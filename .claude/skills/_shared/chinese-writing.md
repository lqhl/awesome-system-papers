# 中文写作与术语解释契约

本契约适用于 skills 生成或改写的中文正文、标题、表格、摘要、对话答案和日志。默认读者是具备系统与机器学习基础的技术研究者；不假设熟悉当前论文或细分方向，但也不把常用系统术语当作入门教材逐一展开。

用户、AGENTS.md 或具体 skill 的更严格规则优先。论文标题、系统名、文件名、代码标识和 wikilink target 保持原样。

## 术语决策

写作前在内部统一术语表达，但不默认把术语清单输出到正文。

1. **系统领域常用缩写直接使用**：GPU、CPU、TPU、NPU、HBM、DRAM、SSD、NUMA、PCIe、NVLink、RDMA、NIC、API、KV cache、MoE、LLM、SLO、P50/P95/P99、TTFT、TPOT、OOM、DP/TP/PP/EP、I/O、LRU、CUDA、ROCm 等无需写中文名或英文全称。只有缩写在当前语境有歧义时才解释。
2. **系统、模型、基准、API、指标、变量和代码标识保留正式拼写**：首次出现只需用中文说明其在本文中的角色，不要机械展开名称。例如：“vLLM 是实验使用的推理引擎”，无需翻译 vLLM。
3. **论文自创缩写、少见领域术语和本文新抽象解释一次**：用一句自然中文说明它是什么、解决什么问题或为何影响结论。只有确有帮助时补英文原名。
4. **普通概念用中文完成叙述**：workload、baseline、artifact 等普通英文词优先写成工作负载、基线、研究产物；不要用英文密度营造专业感。
5. **同一概念全篇只用一种表达**：不要在“键值缓存”“KV 缓存”“KV cache”之间轮换；本仓库默认使用 `KV cache`。

`阅读提示` 只用于长篇、跨领域文档中至少四个非标准术语同时阻碍理解的情况，最多五条。不得把 GPU、NUMA、MoE、PCIe 等常用缩写列入阅读提示。短文和普通 wiki 页在首次使用非标准术语时行内解释。

## 可读性

- 先交代读者理解当前判断所需的背景，再引入抽象、机制和证据。不要让术语表、证据等级或实验参数先于问题出现。
- 普通叙述用中文完成语法关系，但允许自然使用常用缩写、系统名和指标。
- 每段只承担一个主要判断：问题是什么、为何重要、设计如何回应、证据覆盖到哪里。
- 将论文直接证据、综合推断和待验证假设分开写，不把来源中的英文名词串直接复制进综合文本。
- 表格单元格也是正文；同样遵守术语与可读性规则。

## 不翻译的内容

- frontmatter key、枚举值、英文 tags、文件名、wikilink target 和 URL。
- 论文英文原题、正式系统名、模型名、组件名、API、代码和公式。
- 单位、变量、通用指标与上述常用系统缩写。
- 标准 Markdown 外链的正式论文或产品名。

## 成稿语义审计

写入文件或发出答案前：

1. 检查是否为常用缩写做了冗余的“中文名（英文全称，缩写）”展开；若是，改为直接使用缩写。
2. 检查每个非标准缩写和新抽象是否在首次出现时用中文说明了角色。
3. 检查英文串词、斜线堆叠、英文普通概念标题和表格单元格。
4. 检查背景是否先于机制，直接证据、综合判断与假设是否分开。
5. 对写入 wiki 的文件运行定向 `wiki-lint --language-only`。`language_warnings=0` 不能替代前四项人工审计。

## 正反例

- 反例：“图形处理器（graphics processing unit，GPU）通过外围组件互连高速总线（Peripheral Component Interconnect Express，PCIe）读取键值缓存。”
- 改写：“GPU 通过 PCIe 读取 KV cache。”
- 反例：“agent-native quant research system 从 hypothesis 到 paper/live gate 都有 artifact。”
- 改写：“面向智能体的量化研究系统将研究假设、代码、实验结果和发布关口组织为可审计的研究产物。”
- 反例：“HandoffLease”
- 改写：“HandoffLease 是运行时发布的可撤销交接提示，包含目标模型、截止时间和状态版本。”
