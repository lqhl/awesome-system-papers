# IntAttention: A Fully Integer Attention Pipeline for Efficient Edge Inference

**作者**：Wanli Zhong, Haibo Feng, Zirui Zhou, Hanyang Peng, Shiqi Yu
**会议**：MLSys 2026
**链接**：https://proceedings.mlsys.org/paper_files/paper/2026
**源文件**：[[c20ad4d76fe97759aa27a0c99bff6710.pdf]]

---

## 1. 背景

Transformer 模型(LLM、ViT、多模态)正快速从云端迁移到手机、嵌入式开发板等边缘设备。Gemma3-270M、QuestA 等小模型证明了在端侧部署有意义的推理能力是可行的,但端侧推理的核心约束变成了 **latency 与 energy budget**,而不是云端的吞吐与扩展性。

attention 在长上下文场景下复杂度为 O(L²),在 prefill(决定 TTFT)阶段是主要开销。为了在没有高并行 FP 单元的边缘 CPU 上跑得动,业界已经走向 INT8 量化:商品 ARM CPU 普遍提供 NEON/dot-product/I8MM 等高效整数路径,而对 BF16/FP16/FP8/FP4 的支持要么缺失要么不省电。SageAttention 系列已经证明 QK⊤ 和 PV 两个 GEMM 用 INT8 量化基本无精度损失。

但当 GEMM 被加速到 INT8 之后,**softmax 与其前后的 dequantize/requantize 反而成了主要瓶颈**:在边缘 CPU 上这一段可以占 attention 总延迟的 57%–65%(论文 Figure 2)。如何把 softmax 也整数化、消除数据类型转换,是端侧 attention 推理进一步加速的关键。

---

## 2. 要解决的问题

围绕「INT8 GEMM + FP softmax」混合精度路径,现有工作各有局限,没有一个方案同时满足端侧部署的三个核心需求:

1. **dequant → softmax → requant 的 detour 拖慢整体**。INT32 logits 必须 dequant 到 FP32 才能跑 exp 和 division,概率再 requant 回 UINT8/INT8 喂给 PV GEMM。这条路径上的 exp 在边缘 CPU 上往往展开成几十条 FP 指令,而归一化的 row-wise division 同样昂贵。
2. **现有加速 softmax 的方案都需要某种妥协**:
   - 硬件协同设计(Softermax、ConSmax)需要专用加速器,商品 SoC 不能用;
   - LUT 近似(EXAQ、TurboAttention)消除了 exp,但归一化(rowSum + division)仍留在浮点,数据流仍是混合精度;
   - 整数化 softmax(I-BERT、I-ViT、I-LLM)虽然走纯整数路径,但需要 QAT/校准/微调才能恢复精度,无法 plug-and-play。
3. **缺少在通用 ARM CPU 上即插即用的纯整数 attention**。论文目标:不改模型、不重训、不依赖专用硬件,只用 add/mul/shift/lookup 这些基础整数指令,完整替换 attention 中包括 softmax 在内的所有阶段。

## 3. 洞察与设计

**关键洞察**:softmax 中 exp(·) 函数在数值上具有强稀疏性 —— 经过 row-wise max-subtraction 后,每行只有少量大值真正贡献到归一化分母,绝大多数元素的 exp(·) 值已经接近零。这意味着 (i) exp 的有效输入域可以被 clip 到一个紧凑区间 [0, c],并且 (ii) 在这个有界区间上,一个分辨率适中的查表就能精确刻画 exp 曲线 —— 既不需要 EXAQ 那样昂贵的 per-tensor 动态统计,也不需要每元素跑完整 exp 计算。

基于这个洞察,论文提出 **IndexSoftmax**:一个完全在整数域执行的 softmax 替代算子,由三个紧耦合的机制组成(见 Figure 3 的 pipeline):

1. **Sparsity-aware 整数域 clipping**。对 INT32 logits Â 做 Δ̂ = rowMax(Â) − Â(变成非负距离),再通过整数门限 c_int = round(c·√d / (s_Q·s_K)) 裁剪 Δ̂′ = min(Δ̂, c_int)。整个过程不离开整数域。clip 阈值 c 是从浮点域门限通过 QK⊤ 的量化 scale 反推出来的,保证「整数比较」与「浮点 exp 输入比较」在量化语义上等价。
2. **LUT 指数近似**。预先计算 2^b 个 entry 的查找表 LUT[i] = exp(−c·i/(2^b−1))(末位置零),把 clip 后的整数距离通过线性映射变成索引,gather 出 exp 的 UINT8 近似值。论文选择固定超参 (b, c) = (5, 6.6),即 32-entry UINT8 LUT,只占 32 字节。
3. **整数域归一化**。归一化也留在整数域:用 32-bit accumulator 算 rowSum,然后 P̂ = ⌊255·Ê / rowSum(Ê)⌉ 做 fixed-point scaling,直接产出 UINT8 概率矩阵。

**两个非显然的设计选择**:
- **UINT8 而非 INT8 存概率**:概率矩阵 P 天然在 [0, 1] 范围,signed INT8 的对称范围浪费了一半动态范围,小概率值被严重失真。改用 unsigned ×255 后,cosine similarity 从 0.9966 提升到 0.9991,RMSE 减半。
- **m − A 的符号约定**:不是经典 softmax 的 A − m,而是 m − A,使所有 exp 输入非负 ∈ [0, c],与 LUT 的索引范围天然对齐。

**与其他 LUT 方案的对比**(Figure 5):EXAQ 用 INT3 表(8 entries,32 字节)依赖动态 clipping;IndexSoftmax 在同样 32 字节预算下塞进 32 entries(UINT8),分辨率 4× 提升,且无需任何全局统计 —— 边缘 CPU 上跑全局 reduction 的开销恰恰是 EXAQ 的痛点。

## 4. 实现细节

- **Pipeline 形态**:Q̂K̂⊤ → INT32 logits → IndexSoftmax → UINT8 P̂ → P̂V̂ → INT32 → s_V dequant 得到输出 O。从 QK⊤ 出口到 PV 入口完全是整数,**没有任何 FP32 操作出现在 runtime path**(Figure 1b)。
- **量化方案**:Q/K/V 三者用 per-tensor symmetric INT8 量化,zero point 固定为 0,scale = max(|X|)/127。论文同时给出了 per-channel/per-block 量化下的扩展公式:每组 g 用各自的 c_int^(g),但 LUT 本身可以全组共享,因为连续域 bound c 和分辨率 b 都是固定的。
- **LUT 构造**:浮点表 LUT[i] = exp(−c·i/(2^b−1)),量化为 LÛT = ⌊255 × LUT⌉ 存为 UINT8。固定超参 (b, c) = (5, 6.6),全模型/全任务通用,无需 per-model 调参。
- **Runtime 操作**:每元素只需 clipping(整数 min)→ 索引计算(乘法+移位)→ LUT gather → rowSum 累加 → fixed-point division。所有指令都能在 ARM NEON SIMD 下并行,没有需要全局 sync 的 reduction。
- **硬件**:在 Rockchip RK3588S2(NEON + dot-product)和 Apple M2(NEON + dot-product + I8MM)两块 ARMv8 SoC 上实现,8 线程,基于 Arm Compute Library (ACL) v52.4.0。

## 5. 实验结果

**模型**:语言模型 LLaMA-3.2-1B / OPT-1.3B / Qwen3-1.7B,视觉模型 DeiT-B-224 / ViT-L-P16-384 / CaiT-L-M48-448。
**数据集**:WikiText、HellaSwag、LAMBADA、PIQA、WinoGrande、ARC-C/E(语言);ImageNet-1K(视觉)。
**对比 pipeline**:FP32、FP16、INT8 Quant-Only、IntAttention,以 FP16 为基线归一化。

**端到端速度**(Figure 6/7):
| 平台 | vs FP16 | vs Quant-Only |
|---|---|---|
| RK3588S2 | 2.1× – 3.7× | 1.6× – 2.0× |
| Apple M2 | 2.4× – 2.8× | 1.9× – 2.4× |

在 RK3588S2 上,IntAttention 在 16K 序列长度跑到 964 GFLOP/s,而 FP16 只有 345 GFLOP/s,Quant-Only 也只有 402 GFLOP/s。

**能耗**(Figure 8):RK3588S2 上 IntAttention 每次 attention 迭代只用 39.18% 的 FP16 能耗(节省 61%),比 Quant-Only 还低 37%。

**精度**(Table 1/2):
- LLaMA-3.2-1B WikiText PPL:FP16 12.66 → Quant-Only 13.70 → IntAttention 13.07,平均 6 任务 acc:59.76% → 59.56% → 59.92%(略超基线)。
- OPT-1.3B:IntAttention 平均 acc 与 FP16 持平(54.00% vs 54.00%)。
- Qwen3-1.7B:对量化最敏感,但 IntAttention(PPL 27.75)比 Quant-Only(PPL 32.95)显著缩小了与 FP16(23.01)的差距。
- 视觉模型在 DeiT-B/ViT-L/CaiT-L 上 Top-1 平均 84.51%(IntAttention) vs 84.51%(FP16),基本无损。

**Softmax 算子消融**(Table 3/4):同样 32 字节 LUT 预算下,IndexSoftmax 比 EXAQ INT3 平均高 1.4% 准确率,在 Qwen3 上 PPL 从 29.00(EXAQ INT3)降到 22.36(IndexSoftmax),甚至略好于 FP16(23.01)。EXAQ INT2 显著退化。

**P 矩阵量化消融**(Table 5):对照 FP16,UINT8 量化 cosine similarity 0.9991,RMSE 0.0012;INT8 分别为 0.9966 和 0.0024,UINT8 明显更优。

**延迟分布**(Figure 2):INT8 Quant-Only 中 dequant→softmax→requant 占 57%–65%,换上 IndexSoftmax 后降到 14%–22%,瓶颈回到 GEMM。

**超参敏感性**(Figure 9):b ≥ 4 且 c ∈ [5.5, 7.7] 是稳定平台;c ≈ 6.6 是跨模态最优脊线。

## 6. 批判性分析

1. **「3.7×」的最大加速比是峰值,不是均值**。3.7× 来自 RK3588S2 上某个特定序列长度的对比;Apple M2 上最高只有 2.8×。论文 abstract 用「up to 3.7×」是合理的,但 figure 6 显示 1K 序列长度时 IntAttention/Quant-Only ≈ 1.85×,不同 L 下加速比抖动较大。读者应理解这是「最佳情形」而不是平均。

2. **「Softmax 占 65% 延迟」前提依赖弱基线**。这个比例是在「INT8 GEMM + FP32 softmax + dequant/requant」的 naive 实现下测的。如果对照对象是 FlashAttention 风格的 fused softmax-GEMM kernel(把 dequant 与 GEMM tile 内联,避免来回写内存),65% 这个数字会显著缩水。论文没有跟一个 fused 的 INT8 baseline 比较,这是一个明显缺口。

3. **LUT-only 方案对 Qwen3 仍有显著精度损失**。Qwen3 PPL 从 23.01(FP16)涨到 27.75(IntAttention),约 +21% 退化。论文承认这部分主要来自 Q/K/V 的量化(而非 softmax),但 Qwen3 这个量级的退化在生产场景下可能不可接受 —— 论文没有展示如果叠加 SageAttention 的 outlier smoothing 能否真正补回这个差距,「正交可叠加」目前只是声称。

4. **能耗测量缺失方法学细节**。「61% 能耗节省」具体测量方法(片上功耗 sensor? 外部 USB power meter?)、采样窗口、预热协议都没有交代,在 RK3588S2 这种带 big.LITTLE 调度的 SoC 上,能耗测量很容易被频率抖动污染。

5. **固定超参 (b=5, c=6.6) 的泛化性可能被高估**。整个超参 sweep 仅在 LLaMA-3.2-1B/WikiText 和 DeiT-B/ImageNet 两个 (model, dataset) 组合上做,跨任务的稳定性结论建立在很窄的样本上。Qwen3 这种对量化更敏感的模型,理想 (b, c) 是否仍是 (5, 6.6) 没有正面回答。

6. **未与最新整数 softmax 工作对比**。I-LLM (2024) 的 DI-ClippedSoftmax 也声称端到端整数,但论文只在 Background 提到一笔,没有放进实验对比。如果 I-LLM + 校准能拿到接近 IntAttention 的精度且不需 plug-and-play 这一点的限制,「first plug-and-play 整数 attention」的差异化价值就需要更细致地论证。

7. **CodeRelease 时间未明**。abstract 末尾「Code will be released in later version」 —— 在边缘 CPU 上的 INT8 SIMD kernel 很难凭论文复现,代码不开源会显著限制其影响力和可信度。

## 7. AI Infra / MLSys 视角

**对 AI 系统研究者的启发**:

1. **「LUT-as-activation」是一个被低估的边缘推理工具**。GPU 时代我们习惯了 polynomial approximation + Tensor Core,但在边缘 CPU 上,「32 字节 LUT + gather」的能量/延迟 profile 可能优于任何多项式近似。这个思路可以延伸到 GELU、SiLU、Softplus 等其他 activation,甚至 LayerNorm 的 1/√x。
2. **Pipeline 完全整数化的「次级瓶颈」会暴露**。论文有一个非常诚实的发现:把 softmax 也整数化之后,延迟瓶颈回到了 QK/PV GEMM。这意味着对边缘 attention 的下一步优化应该投资在 INT4 GEMM kernel 和 sparsity-aware GEMM,而不是继续抠 softmax。
3. **UINT8 vs INT8 选择**:这是一个常被忽视的细节 —— 任何天然分布在 [0, +) 的 tensor(probability、ReLU 输出、attention sink)用 unsigned 表示都能多 1 bit 动态范围。这点在 KV cache 压缩、low-bit FFN 中也值得复用。
4. **整数域 sparsity 的潜力**:论文用整数比较实现了 attention 的「软 top-k」效果。如果把 c_int 从全局门限改成动态 per-row(轻量化的 EXAQ 思想 + 不需要 FP 统计的整数估计器),可能进一步压缩 LUT entries 不变前提下的精度。

**可跟进的研究问题**:

- **LUT 复用 + 多算子融合**:能否在 ARM SIMD 内 fuse「IndexSoftmax + PV GEMM」到一个 tile 内,把 P̂ 留在 register 而不写回 L2,直接输入 PV 的 dot-product 累加?这可能再省 30%+ 的内存带宽。
- **整数化 Online Softmax**:FlashAttention 的核心是 online softmax(随 K block 滚动更新 max & sum)。把 IndexSoftmax 的整数路径嵌进 online softmax,使 attention 在边缘 CPU 上也能避免 O(L²) 的中间矩阵物化,这是一个明显的 future work,论文没有覆盖。
- **从 attention 拓展到 MoE routing**:MoE 的 router softmax 也是「少量大值主导 + 大量小值可截断」的稀疏分布,IndexSoftmax 直接复用应该开箱即用。
- **边缘设备 prefill / decode 分离调度**:IntAttention 只在 prefill(L 大,attention 占主导)阶段优势明显;decode(L 增长但每步只算一行)的 attention 延迟主导项不同。需要在 PD 分离的 server-edge 协同框架中精细评估其适用域。

**最有价值的切入点**:把这个 LUT-based 整数 softmax 反向移植到 GPU 上 INT4 attention 的 P 矩阵阶段,与 SageAttention3 的 FP4 路径对比,看能否在「INT4 QK + INT8 P + INT4 PV」配置下打破现在 SageAttention 系列在 P 上仍依赖 FP 的一致瓶颈。这是一个跨硬件迁移整数化设计思想的好题目。

## 8. 总结

IntAttention 是第一个 plug-and-play、零重训、纯整数的 attention 流水线,目标场景是商品 ARM 边缘 CPU。核心贡献是 IndexSoftmax —— 一个 32 字节 UINT8 LUT + 整数 clipping + 整数归一化的 softmax 替代算子,把传统 INT8 量化 attention 中占 60% 延迟的 dequant→softmax→requant 路径压缩到 14%–22%,在 RK3588S2 上端到端最高加速 3.7×、节能 61%,且语言/视觉模型精度基本无损。主要局限在于:加速比在不同序列长度下抖动较大、未与 fused INT8 baseline 对比、对 Qwen3 这类量化敏感模型仍有 ~21% PPL 退化、代码未开源。这篇工作对边缘端 LLM 推理是实用且影响大的,对云端 GPU 推理则更多是设计思想上的启发。
