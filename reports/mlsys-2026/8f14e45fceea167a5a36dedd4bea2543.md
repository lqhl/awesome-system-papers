# SuperInfer: SLO-Aware Rotary Scheduling and Memory Management for LLM Inference on Superchips

**作者**:Jiahuan Yu, Mingtao Hu, Zichao Lin, Minjia Zhang
**会议**:MLSys 2026
**链接**:https://proceedings.mlsys.org/paper_files/paper/2026
**源文件**:[[8f14e45fceea167a5a36dedd4bea2543.pdf]]

---

## 1. 背景

大语言模型(LLM)在线推理服务对延迟 SLO 越来越敏感,业界广泛使用两个关键指标:**TTFT**(Time-To-First-Token,首 token 时延)和 **TBT**(Time-Between-Tokens,token 间时延)。LLM 推理在自回归生成过程中每个请求都会不断累积 KV cache,当请求到达率(RPS)升高时,GPU HBM 会迅速被 KV cache 耗尽,导致 head-of-line (HOL) blocking 和大量 SLO 违约。

为了突破显存瓶颈,社区一直在探索 KV cache / 参数 offloading 到 CPU 内存的思路(FlexGen、NEO、CachedAttention、NanoFlow、Pie 等),但这些系统几乎都假设 PCIe 互连,单向带宽只有 32-64GB/s。随着 NVIDIA GH200、AMD MI300A 等 **Superchip** 架构的出现,GPU 与 CPU 通过 NVLink-C2C 等一致性互连紧耦合,理论带宽提升到 900GB/s 量级,比 PCIe 高一个数量级。这种硬件变革为 offloading 打开了新的设计空间,但现有软件栈能否用满这条链路尚无定论。

---

## 2. 要解决的问题

论文要解决的是在 GH200 这类紧耦合 Superchip 上构建**同时满足 TTFT 和 TBT SLO** 的高性能 LLM 推理系统,具体细化为三个子问题:

1. **SLO-unaware 的静态 offloading 策略无法平衡 TTFT / TBT**。生产框架常见的 Waiting-First (WF) 和 Swapped-First (SF) 两种静态策略:WF 优先新请求导致 TBT 恶化,SF 优先恢复被换出请求会退化到 FCFS,均不能同时优化两个 SLO(§3.1, Fig. 1)。
2. **PCIe 带宽根本不足**。即使调度策略完美,offloading 的响应性受限于 swap 带宽。PCIe Gen5x16 的带宽不足以及时清理积压的 waiting 队列,还会在 swapped 队列里引入新的 HOL blocking(§3.2, Fig. 2-3)。
3. **GH200 上软件栈无法榨干 NVLink-C2C 带宽**。作者测得 vLLM 的 offloading 在 GH200 上仅跑到 ~10GB/s,不到理论峰值(~200GB/s DRAM 受限上限)的 5%(§3.3, Fig. 4-5)。换句话说,即便有好硬件,当前软件也不能把 SLO-aware offloading 做出来。

## 3. 洞察与设计

**关键洞察**:

- **洞察 1**(调度侧):GH200 的紧耦合内存层次可以把 LLM 推理栈类比成 OS — 请求是线程,HBM 是片上缓存,DRAM 是主存,KV cache 是线程数据。既然 OS 用 CFS/EEVDF 这类抢占式、时间片轮转调度器管理大量线程,LLM 推理也应该把"抢占"从 OOM 时的最后兜底手段升级为**由 SLO 进度主动驱动的 rotation**。
- **洞察 2**(数据布局侧):vLLM 的 NVLink-C2C 带宽被打到 10GB/s 不是硬件的锅,而是 PagedAttention 的 layer-first 布局让每个 KV segment 只有 64KB(Qwen2.5-32B),每次要独立 `cudaMemcpyAsync`;而 NVLink-C2C 只有在传输 ≥8MB 时才能跑进高带宽区间,小传输下 kernel launch overhead 甚至大于实际拷贝时间。
- **洞察 3**(全双工侧):NVLink-C2C 物理上支持 450+450GB/s 双向并发,但 Grace DRAM 是半双工的(总共 384GB/s),所以软件层需要打破 D2H / H2D 间的数据依赖才能真正跑双向;而现有系统(vLLM、SGLang)都是串行 swap-in/out。

**系统设计**。基于上述洞察,SuperInfer 由两个协同设计的组件组成(Fig. 6):

### 3.1 RotaSched:OS 风格的主动轮转调度器

- **rotary state**:在传统 waiting / running 两个状态之外,引入第三个瞬态 rotary,表示"KV cache 已 swap 到 DRAM 等待下一轮切回 HBM 继续推理"的请求。它让 LLM 推理呈现出类似 OS 时间片轮转的结构,但切片节拍由 SLO 进度而非固定 quanta 决定。
- **Virtual Lag Time (VLT)**:参考 EEVDF 的 lag 概念,为 rotary / waiting / running 三类请求各自定义一条分段函数(公式 1):
  - rotary:$\alpha \cdot \mathrm{ReLU}(t_{\mathrm{now}} - t_{\mathrm{last}} - \beta_B S_B)$,反映距离 TBT SLO 的余量
  - waiting:$\mathrm{ReLU}(t_{\mathrm{now}} - t_{\mathrm{arr}} - \beta_F S_F)$,反映距离 TTFT SLO 的余量
  - running:$-(t_{\mathrm{now}} - t_{\mathrm{run}})$,负值,越小说明已经占用 GPU 越久
  - 其中 $\alpha$ 控制 TBT / TTFT 敏感度比,$\beta_B, \beta_F$ 是容忍系数
- **Largest-VLT-First (LVF)**:每次引擎迭代:① 若 HBM 容得下所有请求则 fallback 到 FCFS;② 所有请求按 VLT 降序排序;③ 从头部选 rotary / waiting 请求填入 transfer budget $B_{\mathrm{xfer}}$ + 空闲 HBM 块;④ 从尾部抢占 running 请求腾出空间。VLT 最高者(最"拖延")优先执行,VLT 最低者(最"超前")优先换出。

### 3.2 DuplexKV:高效 KV cache 轮转引擎

- **Block-first layout**:把 PagedAttention 原本的 layer-first 虚拟张量 $(N_L, N_B, S_{\mathrm{seg}})$ 转置为 block-first,使同一 block 内 $N_L$ 个 layer 的 segment 在物理内存上连续。以 Qwen2.5-32B 为例,单次连续区间从 64KB 提升到 4MB,把传输推进到 NVLink-C2C 的高带宽区段。作者同时改造 PagedAttention kernel 的 stride 计算以兼容新布局。
- **Batched kernel**:把原本每 segment 一次 `cudaMemcpyAsync` 的数千次 launch 合并成一次 `cudaMemcpyBatchAsync`,消除 launch 开销主导带宽的问题。
- **Eager block rotation**(Fig. 13):把每个 block 标成 dirty(正在写入)或 synced(已写满)。DRAM 后台提前 copy synced block,当请求真正被抢占时,只需 swap-out 最后一个 dirty block,HBM 中 synced block 直接丢弃。这样 swap-in 目标块与 swap-out 源块不会碰撞,彻底消除 D2H / H2D 间的数据竞争,实现全双工并发传输。
- **Cross-iteration pipeline**(Fig. 15):迭代 $t$ 内 GPU 执行迭代 $t{-}1$ 准备好的 batch,同时 CPU 侧调度器 + DuplexKV 为迭代 $t{+}1$ 准备批次,把 transfer + schedule 时间藏到计算后面。

## 4. 实现细节

- 在 **vLLM v0.6.6.post1** 之上基于 Python + C++ 实现,替换了 scheduler 和 KV cache 管理器。
- **Block table** 维护每个 block 的状态(dirty / synced)和驻留位置(HBM / DRAM),是 RotaSched 与 DuplexKV 的桥梁(Fig. 6 中的 Block Table)。
- **PagedAttention kernel 改造**:原始 block 间 stride 为 $(j-i) \cdot S_{\mathrm{seg}}$,block-first 布局下变为 $(j-i) \cdot N_L \cdot S_{\mathrm{seg}}$,kernel 支持新 stride 但保留 paging 抽象。
- **评测超参**:$\alpha = 3$、$\beta_B = 0$、$\beta_F = 0.5$、$B_{\mathrm{xfer}} = 2400$ blocks,TTFT SLO = 5s、TBT SLO = 100ms,DRAM 给 offload 用 400GB。
- 论文没有披露代码行数,但描述上是 vLLM 的深度改造,不是 plug-in。

## 5. 实验结果

**硬件**:NVIDIA GH200(144GB HBM + 480GB DRAM)。
**模型 / 数据**:LLaMA-3-8B、Qwen2.5-32B、Mixtral-8x7B;ShareGPT、LMSYS-Chat-1M;Poisson 到达。
**基线**:vLLM v0.6.6.post1、LightLLM、LTR、NEO(NEO 不支持 MoE 所以 Mixtral 上缺)。

### 5.1 端到端 SLO 达成率(Fig. 16)

- 在所有 3 模型 × 2 数据集上,SuperInfer 的 **TTFT SLO 达成率全面胜出**,多数高 RPS 点逼近 100%,最高相对提升 **74.7%**。
- **TBT SLO 达成率与 vLLM 相当或更好**,没有像 LTR 那样牺牲 TBT 换 TTFT。LTR 的 TTFT 在高负载下虽仅次于 SuperInfer,但 TBT 经常跌破 25%。

### 5.2 消融(Fig. 17)

| 配置 | TTFT 说明 | TBT 说明 |
|---|---|---|
| vLLM (FCFS) | 差 | 参考线 |
| SuperInfer w/o DuplexKV (L, $B_{\mathrm{xfer}}=300$) | 显著改善 TTFT | TBT 与 vLLM 相当 |
| SuperInfer w/o DuplexKV (H, $B_{\mathrm{xfer}}=2400$) | TTFT 好 | **TBT 严重恶化**(transfer 跑不动,压住执行) |
| SuperInfer(RotaSched + DuplexKV) | 最佳 TTFT | TBT 不降 |

结论:RotaSched 独立即可提升 TTFT;没有 DuplexKV 直接拉大 $B_{\mathrm{xfer}}$ 反而伤 TBT;两者缺一不可。

### 5.3 DuplexKV 带宽(Table 1,传 16GB Qwen2.5-32B KV)

| 方法 | D2H (GB/s) | H2D (GB/s) | E2E 时间 (ms) |
|---|---|---|---|
| Naive(64KB segment) | 10.75 (U) | 9.86 (U) | 1556.15 |
| MS(merged segment → 4MB) | 80.05 (U) | 133.51 (U) | 159.87 |
| MS + MK(batched kernel) | 238.95 (U) | 269.69 (U) | 63.14 |
| **DuplexKV**(+ eager rotation) | 180.99 (B) | 179.37 (B) | **46.80** |
| Ideal(Grace DRAM 半双工上限) | 192.00 (B) | 192.00 (B) | 41.66 |

Naive 到 DuplexKV,E2E 时间缩短 **33 倍**,只比理论 ideal 慢 1.12 倍。

### 5.4 VLT 参数扫描(Fig. 18-20)

- $\alpha$ 增大 → TBT 改善但 TTFT 变差,$\alpha=3$ 是 sweet spot
- $\beta_F$ 大于 2 后 TTFT 急剧恶化
- $\beta_B < 0$ 可换取最好的 P99 TBT

### 5.5 吞吐(Fig. 22)

SuperInfer 与 vLLM 吞吐相当,高 RPS 下最多有 **29.2%** 提升,因为快速轮转给 prefill 带来了更多 batching 机会,chunked prefill 得以发挥。

### 5.6 UM 对照(Appendix D)

开启 GH200 Unified Memory 后 vLLM TBT 严重劣化。原因是 GH200 的 UM 不是 page-fault 驱动,而是 access-counter 驱动的懒迁移,短生命周期的 KV cache block 还没迁上来请求就结束了,GPU 一直在通过 900GB/s C2C 跨越去读 384GB/s 的 DRAM — 形成 "bandwidth cliff"。这说明 UM 不是 offloading 的替代方案,主动管理是必要的。

## 6. 批判性分析

1. **只在 GH200 单机上评测**,没有 MI300A、多节点或弱一点的 Grace Blackwell 数据。论文核心主张是 Superchip 类架构的普适方法,但 "block-first layout 的最优 segment 大小"、"eager rotation 的 dirty/synced 阈值" 都可能与具体 DRAM 子系统带宽相关,在其他平台上结论能否迁移存疑。

2. **与 Pie / Select-N 的比较被刻意回避**。Pie 是明确针对 GH200 offloading 的 paper,论文以"缺少公开代码"为由排除。考虑到 Pie 的 on-the-fly memory allocation 在 SLO 维度也有设计,完全不比是说服力不足的。

3. **超参 $\alpha, \beta_B, \beta_F$ 的鲁棒性存疑**。Fig. 18-20 显示三参数对 P99 尾延迟非常敏感,$\alpha$ 略偏都会使某一 SLO 显著劣化。论文没有给出自适应调参的策略,默认值也是在 ShareGPT + Qwen2.5-32B 上调出来的,切换 workload 可能需要重新 tuning,这跟"SLO-aware"的卖点有轻微张力。

4. **TTFT SLO = 5s 偏宽松**。在交互式场景(聊天、Copilot)这个门槛可以,但同期不少工作设到 1s 甚至 500ms;在紧 SLO 下 SuperInfer 的优势是否还能保持 74% 并不清楚。

5. **rotary 状态的 KV cache 一致性被轻描淡写**。eager rotation 把 synced block 在 HBM 标记为"可丢"并把 DRAM 当权威副本,但如果后续又重新 swap-in,Attention kernel 必须准确区分"HBM 中残留旧副本"和"DRAM 中最新副本",论文正文没有讨论这种读写竞争的验证或一致性协议,只在 block table 画图里示意。

6. **VLT 公式的合理性偏工程直觉**。Running 请求 VLT 为负且只与执行时间线性相关,意味着无论是否临近生成完成都会被 preempt 掉,可能在尾部阶段打断本应很快结束的请求,反而放大整体 latency;论文没有针对这种边界场景的 microbenchmark。

7. **throughput 29.2% 的提升归因含糊**。作者归因于 "长请求不再霸占 HBM,prefill 有更多 batching 机会",但同一张 Fig. 22 里低 RPS 也有少量提升,说明改动带来的 overhead 并非纯粹靠调度红利;没有隔离 DuplexKV 带来的传输效率提升与 scheduling 带来的 batching 收益。

## 7. AI Infra / MLSys 视角

这篇论文对 AI Infra 研究的启发主要有三层:

1. **"OS ↔ LLM serving" 这个类比值得被继续推进**。把 request 视为线程、KV cache 视为线程 stack/heap、Superchip 两级内存视为 cache / main memory,立即可以把 OS 领域几十年的调度/内存管理思想迁移过来。VLT 借用 EEVDF 是一个起点,后续可以继续借鉴 MLFQ(Multi-Level Feedback Queue)处理长尾请求、NUMA-aware scheduler 处理多 GPU Superchip,甚至引入 work-stealing 处理混合 prefill/decode。
2. **Layout × Interconnect 的 co-design 是 Superchip 软件栈的共性痛点**。Block-first 布局这种表面上"换个 stride"的改动能把带宽打上去 20 倍,意味着 PagedAttention 这类为 PCIe 时代优化的抽象,在 C2C / NVLink 时代可能要整体重写。可以沿着这个方向思考:不仅 KV cache,参数 offload、MoE expert migration、RLHF trajectories 是否都该抛弃 "layer × small segment"?
3. **"eager 化" 以打破数据依赖的思路可迁移性很强**。核心技巧是把一次粗粒度的 swap 拆成 token-粒度的后台拷贝,提前消费带宽、让前台关键路径最短。类似思路可以应用到:
   - **MoE expert fetch**:expert 一旦被命中就 eager 预取下一层/下一 token 可能用到的 expert
   - **推测解码**:speculative 产生的 KV 后台 eager sync,一旦接受就零延迟 commit
   - **分布式训练**:optimizer state offload 到 CPU 时 eager rotate 已经稳定的参数 shard

**值得跟进的 future work**:

- 把 VLT 拓展到 multi-SLO / priority tier(把 TTFT、TBT、请求优先级一起建模成约束优化),看是否能产生更好的 closed-form 策略
- 探索 block-first 布局对 attention kernel 性能的影响(cache line、TMA load pattern)是否有二阶收益
- 在 B200 / Grace Blackwell / MI300A 上复现以验证方法的架构无关性
- RotaSched 的抢占决策是否能借助 length prediction(LTR 的思路)进一步减少错误抢占

**最有价值的切入点**:把 SuperInfer 与 speculative decoding、disaggregated prefill/decode 架构做融合。当前方法假设 prefill/decode 共用 GPU,disaggregated 场景下 RotaSched 的 rotate 会变成跨机器的 KV migration,eager rotation 的价值还会更大,这是一个离"把 SLO-aware offloading 推向生产"最近的方向。

---

## 8. 总结

SuperInfer 是第一个为 GH200 类 Superchip 架构专门设计的 SLO-aware LLM 推理系统,核心贡献是:(1) 用 OS 抢占式调度(EEVDF)启发的 VLT + LVF 策略把 LLM 请求抢占从"OOM 兜底"升格为"SLO 主动轮转";(2) 用 block-first 布局 + batched memcpy + eager block rotation 打破 PagedAttention 和 C2C 的软件 mismatch,把 NVLink-C2C 带宽利用率从 5% 提升到接近理论峰值。在 GH200 上对 3 个主流模型 × 2 个数据集的评测显示 TTFT SLO 达成率最高提升 74.7%,TBT 与吞吐不降反升。局限在于只在 GH200 上评测、与 Pie 等紧密相关工作未直接对比、VLT 超参对 workload 相对敏感;但 "OS-inspired 调度 + 布局-互连协同设计" 的方法论对下一代 AI Infra 栈有较强的借鉴价值。
