# SuperInfer: SLO-Aware Rotary Scheduling and Memory Management for LLM Inference on Superchips

**作者**：Jiahuan Yu, Mingtao Hu, Zichao Lin, Minjia Zhang（University of Illinois Urbana-Champaign）
**会议**：MLSys 2026
**链接**：[arXiv:2601.09302](https://arxiv.org/abs/2601.09302)

---

## 一、背景

LLM 推理服务面临严格的延迟 SLO（Service Level Objectives）要求，核心指标包括 Time-To-First-Token（TTFT）和 Time-Between-Tokens（TBT）。随着请求速率增加，每个请求维护的 KV cache 持续增长，迅速耗尽 GPU 显存，导致严重的 head-of-line（HOL）阻塞和 SLO 违规。

现有的 KV cache offloading 方案主要基于 PCIe 架构，带宽仅 32-64 GB/s，无法在高请求速率下支撑快速的 swap-in/swap-out，严重限制了 offloading 的响应性。与此同时，以 NVIDIA GH200 为代表的 Superchip 架构通过 NVLink-C2C 提供了高达 900 GB/s 的双向带宽，比 PCIe 高出一个数量级，为解决这一瓶颈提供了硬件基础。

---

## 二、要解决的问题

1. **SLO-unaware offloading**：现有系统采用静态的 offloading 策略（如 Waiting-First 或 Swapped-First），无法同时兼顾 TTFT 和 TBT。WF 策略有利于新请求但恶化 TBT，SF 策略保护 TBT 但退化为 FCFS 行为。

2. **PCIe 带宽瓶颈**：PCIe Gen5 x16 单向带宽仅约 64 GB/s，导致 offloading 响应迟缓——等待队列中的请求积压清除缓慢，swap 队列中的请求恢复同样缓慢，产生新的 HOL 阻塞。

3. **NVLink-C2C 利用率极低**：尽管 GH200 提供了高带宽互连，但现有 LLM serving 栈（如 vLLM）在 GH200 上仅实现约 10 GB/s 的有效 offloading 带宽（不到理论峰值的 5%）。根本原因在于 PagedAttention 将 KV cache 分散为大量小的非连续 segment（如 64KB），每次传输都需要独立的 cudaMemcpyAsync kernel launch，launch 开销远大于实际传输时间。

---

## 三、洞察与设计

**关键洞察**：GH200 上的 LLM serving 栈与操作系统在 CPU 上的结构高度类似——请求对应线程，Hopper HBM 对应 on-chip cache，Grace DRAM 对应主存，KV cache 对应线程数据。因此可以借鉴 OS 的 preemptive time-slicing 调度思想，将 GPU 显存从「静态分配」转变为「动态调度」，基于 SLO 进度主动轮转请求，而非被动等待 OOM 再做 preemption。同时，NVLink-C2C 的带宽瓶颈不在硬件而在软件——大量小粒度非连续传输是根因，通过数据布局变换和 batch 传输可以充分利用 C2C 带宽。

### RotaSched：OS-inspired 旋转调度器

- 引入 **rotary state**（旋转态）：请求在 GPU 执行暂停后，KV cache 被 swap 到 CPU，等待下次轮转。三态模型：waiting → running ↔ rotary。
- 定义 **Virtual Lag Time (VLT)** 度量请求偏离 SLO 进度的程度：
  - Running 请求：VLT 为负值，运行越久越小（越"超前"）
  - Waiting/Rotary 请求：等待超出容忍度后 VLT 变为正值并持续增大（越"滞后"）
  - 参数 α 控制 TBT/TTFT 敏感度比例，βB/βF 为延迟容忍系数
- **Largest-VLT-First (LVF) 调度**：每个 engine iteration 执行四步——① 竞争检测（显存够则 FCFS）→ ② 按 VLT 降序排序 → ③ 优先调度 VLT 最高的请求 → ④ 从 VLT 最低的 running 请求开始 preempt 以腾出显存

### DuplexKV：全双工 KV cache 旋转引擎

- **Eager block rotation**：利用 KV cache 增量生成特性——已写满的 block 不会再被修改，可以提前同步到 CPU，避免 swap-in 和 swap-out 的 HBM block 数据竞争，实现 D2H 和 H2D 在独立 CUDA stream 上并行执行
- **Block-first layout transformation**：将 PagedAttention 的 layer-first 布局重组为 block-first 布局，使同一 block 所有 layer 的 KV cache 连续存放，单次传输大小从 64KB 提升到 4MB+，进入 C2C 高效传输区间
- **Cross-iteration pipeline**：将传输与模型计算重叠，隐藏传输延迟

---

## 四、实现细节

- 基于 vLLM 实现，修改了调度器和内存管理模块
- Block table 扩展：每个请求的每个 KV block 同时记录 HBM 和 DRAM 地址，支持双副本管理
- Eager rotation 通过标记 block 状态（dirty/synced）实现：dirty block 仍在写入中，synced block 已完全写满可安全传输
- Layout transformation：将 (NL, NB, Sseg) 的 layer-first 3D 虚拟张量重组为 block-first，使每个 block 的所有 layer 数据连续，segment 大小从 P×C 变为 NL×P×C
- 传输采用 batched kernel launch，将多个 block 的传输合并为少量大传输
- Pipeline 设计：iteration i 的 D2H/H2D 传输与 iteration i+1 的模型计算重叠

## 五、实验结果

**平台**：NVIDIA GH200（Hopper GPU + Grace CPU，NVLink-C2C 900GB/s 双向）

**模型**：LLaMA-3-8B、Qwen2.5-32B、Mixtral-8x7B

**数据集**：ShareGPT、LMSYS-Chat-1M

**基线**：vLLM（FCFS/SJF/SRTF/preemptive offloading）、SGLang、LightLLM

| 指标 | 结果 |
|------|------|
| TTFT SLO attainment | 比 SOTA 提升最高 74.7% |
| TBT SLO attainment | 保持可比或更优 |
| 吞吐量 | 可比或略优于 vLLM，高请求率下提升最高 29.2% |
| C2C 有效带宽 | 从 vLLM 的 ~10 GB/s 提升到接近硬件上限（~200 GB/s） |

- 低请求率下（显存充足），SuperInfer 退化为 FCFS，与基线性能一致
- Transfer budget Bxfer 越大，延迟改善越显著，验证了高 swap 带宽对 SLO-aware offloading 的必要性
- GH200 的 Unified Memory（硬件管理）不适用于 LLM serving：GPU 访问 CPU 内存走 C2C 带宽仅 384 GB/s 远低于 HBM 的 4 TB/s，且硬件 access counter 驱动的页迁移对 KV cache 的短时访问模式无效

## 六、批判性分析

1. **硬件平台单一性**：所有实验仅在 NVIDIA GH200 上进行。论文声称系统面向"Superchips"（标题和摘要均为复数形式），但 AMD MI300A 等其他 tightly-coupled 架构未做任何验证。GH200 的 Grace DRAM 半双工特性（总共 ~384 GB/s）是系统设计的重要约束，直接影响 eager block rotation 和 pipeline 策略，这些设计在不同架构上是否仍然有效存疑。

2. **VLT 参数敏感性分析不足**：α、βB、βF 三个超参数直接影响调度行为，但论文仅在附录中简单提及 α=2, βB=βF=0.5 的默认设置，缺乏系统的参数敏感性分析。在不同模型规模、请求分布、SLO 严格程度下，这些参数是否需要重新调优？是否存在鲁棒的默认配置？

3. **排序开销被忽略**：LVF 每个 iteration 对所有请求按 VLT 排序。论文未讨论当并发请求数极大时（例如数千），排序本身的计算开销是否成为瓶颈。虽然排序在 CPU 上执行，但在高请求率下可能影响 scheduling 延迟。

4. **Layout transformation 的开销**：Block-first layout 需要在 GPU 上执行数据重组。论文提到利用 GPU SMEM 进行转换，但未量化该操作的计算和内存开销，特别是在高并发场景下多个请求同时需要 layout transformation 时。

5. **基线公平性**：与 vLLM 的比较使用了 FCFS、SJF、SRTF 等调度策略，但这些都是 vLLM 内置的简单策略。论文的核心贡献之一是 SLO-aware scheduling，但未与 SOLA、Sarathi-Serve 等同样做 SLO-aware scheduling 的系统在同一硬件上直接对比。与 LightLLM 的对比也因 LightLLM 未针对 GH200 优化而不完全公平。

6. **单 GPU 实验**：所有实验均为单 GH200 节点。在实际部署中，tensor parallelism 和 pipeline parallelism 会改变 KV cache 的分布和通信模式，SuperInfer 的设计能否扩展到多 GPU/多节点场景未知。

---

## 七、AI Infra / MLSys 视角

1. **Superchip 作为 LLM serving 新范式**：本文首次系统性地揭示了现有 LLM serving 栈在 Superchip 上的软件瓶颈——PagedAttention 的碎片化内存布局和 kernel launch 开销导致 C2C 带宽利用率不到 5%。这一发现对所有基于 Superchip 的 AI 系统开发都有重要参考价值，说明高性能互连需要配套的软件栈重新设计。

2. **OS-LLM serving 类比的可迁移性**：将 LLM 请求调度类比为 OS 线程调度（HBM 作为 cache，DRAM 作为 main memory）是一个有价值的思维框架。这一类比可以进一步延伸到 distributed serving 场景：多 GPU 间的请求迁移类似于 NUMA 调度，远程 KV cache 访问类似于 remote memory access，可以借鉴更多 OS/体系结构领域的经验。

3. **值得跟进的方向**：
   - **多 Superchip 协同调度**：SuperInfer 目前仅针对单 GH200，如何在多个 GH200 之间进行跨节点的 SLO-aware 请求迁移和 KV cache 协同管理是自然的延伸
   - **Speculative decoding + Superchip offloading**：speculative decoding 产生的 draft tokens KV cache 可能很快被丢弃，eager rotation 策略需要适配这一新模式
   - **异构 Superchip 集群**：未来集群可能混合 GH200、MI300A 等不同 tightly-coupled 架构，统一的 offloading 抽象层和自适应调度器值得探索
   - **Disaggregated serving + Superchip**：prefill 和 decode 分离架构下，Superchip 的 CPU-GPU 协同如何与 prefill-decode disaggregation 配合优化

4. **实用启发**：DuplexKV 的 block-first layout transformation 思路不仅适用于 offloading，对任何涉及 KV cache 跨设备传输的场景（如 KV cache migration、prefix caching 跨节点共享）都有借鉴意义——传输效率的瓶颈往往不在链路带宽而在数据布局。

---

## 八、总结

SuperInfer 是首个针对 Superchip（GH200）设计的 SLO-aware LLM 推理服务系统，通过 OS-inspired 的 RotaSched 旋转调度器和 DuplexKV 全双工传输引擎，将 NVLink-C2C 的有效利用率从不到 5% 提升到接近硬件上限，在高请求率下实现了 TTFT SLO attainment 最高 74.7% 的提升。其核心贡献在于揭示了现有 serving 栈在 Superchip 上的软件瓶颈，并提出了调度与内存管理协同设计的解决方案。主要局限在于仅验证了单 GH200 场景，参数敏感性和多 GPU 扩展性有待进一步研究。
