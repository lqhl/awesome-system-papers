## 1. 背景

Transformer 架构已成为 LLM、视觉、多模态系统的主干,而注意力机制在其中承担着主要的计算负担 —— 自注意力分数在序列长度上呈平方级增长。随着长上下文推理、代码库建模、高分辨率视频处理等新能力不断涌现,进一步提升注意力效率是一条持续被挖掘的主线。FlashAttention 系列正是沿着这条主线演进:FA1 通过 tiling + kernel fusion 消除 GMEM 中间读写、FA2 沿 sequence length 并行化提升 SM 占用率、FA3 在 Hopper H100 上引入 warp specialization 和 FP8。

然而,近两年加速器演进呈现明显的**非对称(asymmetric)特征**:tensor core 的峰值算力翻倍增长,而 shared memory 带宽、exponential unit 等辅助功能单元的吞吐几乎不变。NVIDIA Blackwell B200 把 BF16 tensor core 吞吐推到 2.25 PFLOPS(相较 Hopper 的 1 PFLOPS 翻倍),但 MUFU 指数单元仍然只有 16 ops/clock/SM、SMEM 读带宽仍然是 128 bytes/clock/SM。与此同时 Blackwell 引入了 tensor memory (TMEM, 256 KB/SM)、更大的 128×128 MMA tile、完全异步的 MMA 写 TMEM、2-CTA MMA 模式等新特性。FA3 这一代针对 Hopper 的假设(累加器驻留 register、64×128 tile、warp 内 shuffle 做 softmax)在 Blackwell 上既无法直接迁移(Hopper MMA 指令不向前兼容),也无法充分利用新能力。

---

## 2. 要解决的问题

FlashAttention-4 的核心问题是:**在非对称扩张的 Blackwell GPU 上,如何通过算法–kernel 协同设计把注意力算子推到硬件极限**。具体拆解为:

1. **瓶颈漂移**:原本 matmul-bound 的注意力在 Blackwell 上被 exp 单元和 SMEM 带宽反超 —— roofline 分析显示,对典型 tile (128³),MMA compute 与 exp unit 持平、SMEM 稍低;对更大 tile (256×128²),exp 单元和 SMEM 都会成为关键路径。
2. **Pipeline 重新设计**:TMEM 把累加器搬出寄存器,不但缓解了寄存器压力、使得更大 tile 成为可能,也允许更激进的 MMA/softmax 重叠模式 —— 而 FA3 的 register-resident pipeline 无法复用这些自由度。
3. **Backward pass 更复杂**:5 个 MMA + 2 个 elementwise + dQ 的全局 atomic 累加,SMEM 流量比 MMA 多 30%,是当前主要瓶颈。
4. **训练可复现性**:dQ 的 inter-CTA reduction 使 backward 具有不确定性,给 RL 等场景的 debug 和对齐造成困扰。
5. **工程生产力**:传统 C++ 模板 metaprogramming 编译一次要 45–55 秒,迭代慢、门槛高,限制了注意力变体(block-sparse、FlexAttention)的研发节奏。

## 3. 洞察与设计

**关键洞察**:Blackwell 上 tensor core 算力相对其他硬件单元(SMEM、MUFU、FMA)急剧失衡,意味着"每条路径都塞满 MMA"已不再是最优目标 —— 要让 kernel 真正跑满 MMA,就必须用**异步 MMA + TMEM 作为并行媒介**把 softmax、rescaling、reduction 等非 matmul 操作搬到与 MMA 平行的硬件单元上执行。这其中有两个更细的观察:(1) FMA 单元是空闲的,可以用多项式近似把一部分 exp 从 MUFU 分流到 FMA,等价地把 exp throughput 翻倍;(2) FA 的 online softmax rescaling 中,只有 running max 真正变大时才需要 rescale,大多数 block 的 rescale 是不必要的。

基于上述洞察,FA-4 分别为 forward 和 backward 设计了新的 pipeline:

**Forward pass**:
- **新 ping-pong schedule**:每个 threadblock 计算两个输出 tile(High 和 Low),当一个 tile 跑 tensor core 时另一个算 softmax。利用 Blackwell 的 fully-async MMA 和 TMEM,softmax 所需的输入/输出都走 TMEM,不占用寄存器,允许用整整 128 线程的 warpgroup 处理一行(免去 warp-shuffle 求 rowmax)。
- **Correction warpgroup**:因为 P 经由 TMEM 而不是 register file 传递,可以把 output rescaling 拆成独立的 correction warpgroup,让它脱离关键路径。
- **TMEM 分区**:S 和 P 共享同一块 TMEM 区,允许流水线启动时立刻并行计算两个 S tile;剩余的 TMEM 用来传递 rescale 统计量。
- **指数函数软件模拟**:用 Cody-Waite 范围约简 + Horner 多项式 + IEEE-754 指数位操作实现 $2^x$,一部分 exp 跑在 FMA 上,另一部分仍然走 MUFU.EX2。degree-3 多项式在 BF16 量化后与硬件 exp 几乎不可区分(BF16 量化误差 ~$3.9\times10^{-3}$,多项式误差小一个量级)。实际部署时只对 10–25% 的 entry 做 FMA 仿真,兼顾 throughput 和寄存器压力。
- **条件 rescaling**:只有 $m_j - m_{j-1} > \tau$ (典型 $\tau=\log_2 256 = 8$) 时才 rescale,并在最后归一化阶段用 final max 纠正所有累积偏差 —— 这样 99%+ 的 block 都可以跳过 vector-multiply 型 rescale。

**Backward pass**:
- **基于 TMEM 的 pipeline 重构**:FA-3 因为累加器在寄存器中,compute graph 几乎被串行化成 S→dP→dV→dQ→dK;FA-4 把 S 和 P 共享一个 TMEM 块、dP/dS/dQ 共享另一个,允许 dQ(previous iter)和 dK(previous iter)的 MMA 与当前 iter 的 softmax 重叠,实现至少两条 MMA 并发。
- **2-CTA MMA for backward**:以 $M=256, N=K=128$ 的 tile 形状让一对 CTA 协作完成一个 MMA,每个 CTA 只载入并暂存一半的 operand B,把 SMEM traffic 近乎减半 —— SMEM 时间从 3328 cycle 降到 2688 cycle,对比 MMA 的 2560 cycle,从"超出 30%"压缩到"超出 5%"。
- **dQ 的 DSMEM 重排**:2-CTA 模式只切分 output 的 M 维而不切分 reduction 维 N,与 dQ MMA 沿 N 做 reduction 天然冲突。解决方法是通过 distributed shared memory 在同 cluster 的两个 CTA 间交换一半 dS,使每个 CTA 持有自己的 $M/2$ 行 + 完整 2N reduction。副产品:每个 CTA 现在只写 dQ 的一半,全局 atomic 数量减半。
- **Deterministic 模式**:用 semaphore lock 串行化 inter-CTA reductions,配合"最短处理时间优先(SPT)"的 CTA 调度(causal 场景下按 query block 降序 reduce)几乎消除了 lock 上的 stall。
- **调度**:LPT(longest-processing-time first)调度针对 causal masking 和 varlen 两类负载不均场景,结合 batch/head 轴的 L2 cache-friendly swizzling。对 causal,按 mblocks 倒序处理使得 SM 先啃硬骨头;对 varlen,用预处理 kernel 按 per-worktile execution time 排序 batch。

## 4. 实现细节

FlashAttention-4 完全用 **CuTe-DSL** (Python embedded DSL) 实现,不含 CUDA C++ 代码。CuTe-DSL 编译器把 Python 源码降到 PTX,再由 ptxas 生成 SASS。设计上与 CUTLASS C++ 同构,保留低层 GPU 表达力,并提供 inline PTX escape hatch,未被 CuTe-DSL 暴露的指令可以直接嵌 PTX。

关键实现工程要点:
- **Tile shape**:forward 典型使用 $M=256$(两 tile ping-pong 各 128 query tokens),$N=d=128$;backward 2-CTA 版本 $M=256, N=K=128$,dQ 特殊为 $M=128$ with doubled reduction $2N=256$。
- **Warp 组织**:forward 有两个 softmax warpgroup(每个 128 线程,各处理一行)、一个 correction warpgroup、一个 producer warpgroup 负责 TMA + MMA 驱动。
- **Register 压力管理**:BF16 input 下一行需 128 reg,output 64 reg;通过**分段存储 P**(前 3/4 立即写 + 触发 MMA,最后 1/4 单独写)缓解 spill。
- **Exp 仿真**:Sollya 计算多项式系数,degree 可选 3–5;通过"forcing fractional bits into mantissa"的 bit-trick 求 ⌊x⌋,再用 IEEE-754 exponent 位拼装回去。
- **dQ atomic**:deterministic 模式下用 memory fence + semaphore;非 deterministic 模式下依赖 hardware atomic;2-CTA 让 atomic 数目自然减半。
- **编译性能**:JIT 单 kernel 编译 forward 2.5s、backward 1.4s,相对 FA-3 的 55s/45s 快 22–32 倍。典型 FA2/FA3 要预编译数百个 kernel 变体,FA-4 几乎没有这个成本。

代码已开源:`https://github.com/Dao-AILab/flash-attention/tree/main/flash_attn/cute`。

## 5. 实验结果

**硬件和软件**:B100 180GB SXM6 (1000W)、CUDA 13.1、PyTorch 2.10.0、CuTe-DSL 4.4.1、Triton 3.6、FlashAttention 2.8.3;对比 cuDNN 9.13 及 9.19.1.2。5 次 warmup + 10 次平均。BF16 为主,head dim 64/128 和 (192, 128)(用于 DeepSeek V3)。

**Forward (非 causal,head dim 128,seq=32K)**:

| 实现 | TFLOPS |
|---|---|
| FA2 | 432 |
| Triton 3.6 | 703 |
| Gluon 3.6 | 1250 |
| cuDNN 9.13 | 1517 |
| cuDNN 9.19.1.2 | 1613 |
| **FA4** | **1613** |

FA-4 对 Triton 最高 2.7×,对 cuDNN 9.13 最高 1.3×,绝对值 ~1600 TFLOPS,约是 B200 理论峰值 2.25 PFLOPS 的 71%。论文特别指出 cuDNN 9.13 之后的版本已经吸收了 FA-4 的多项技术,导致与最新 cuDNN 接近。

**Backward (非 causal,head dim 128,seq=32K)**:

| 实现 | TFLOPS |
|---|---|
| FA2 | 386 |
| cuDNN 9.13 | 1107 |
| cuDNN 9.19.1.2 | 1274 |
| **FA4** | **1412** |

Backward 上 FA-4 对 cuDNN 9.19 保持 ~10% 领先,对 FA2 有 3.5× 以上加速。

**Deterministic backward (causal, head dim 128)**:调度策略对比(TFLOPS):

| Seq | Naive | LPT | Reverse-mblock LPT | SPT |
|---|---|---|---|---|
| 1K | 250 | 440 | 450 | 470 |
| 8K | 350 | 720 | 790 | 920 |
| 32K | 540 | 760 | 830 | 950 |

SPT 调度达到非 deterministic backward 75% 的速度,是朴素调度的 ~1.8×。

**编译时间**:FA4 的 forward kernel JIT 2.5s vs FA3 的 55s,加速 22×;backward 1.4s vs 45s,加速 32×。

## 6. 批判性分析

- **Roofline 结论对 tile 选择敏感**。Section 3.1.1 的结论(exp unit 和 MMA 并列瓶颈)是在 $M=N=d=128$ 或 $M=256, N=d=128$ 特定配置下得到的。实际 head dim 64 或 192 时 non-matmul 和 MMA 的比例都会变,论文没有展示不同 head dim 下的 roofline 重新分析,也没有说明软件模拟 exp 的 10–25% 比例是如何随 tile 重新调整的 —— 这些超参看起来都是经验 tune 出来的。
- **BF16 only**。论文的核心实验全部是 BF16,对 FP8/FP4 低精度模式没有任何数据。现实 LLM 推理越来越多在 FP8 上运行(SageAttention3 已在 Blackwell 消费卡上做 FP4),FA-4 对这些路径的适配尚未验证,论文在这个赛道上并没有推进。
- **"1.3× 相对 cuDNN"的时效性堪忧**。论文明确承认 cuDNN 9.14+ 已经吸收 FA-4 的技术,最新版与 FA-4 的差距被抹平;而 FA-4 相对 Triton/Gluon 的优势本质上是"vendor-tuned vs 通用编译器"的比较,不完全反映算法价值。比较对象里缺少 xformers 的 flash-attention 适配、vLLM 中的 FA backend、SageAttention 系列等 state-of-the-art 基线。
- **短序列(1K/2K)优势有限**。图 4/6 中 FA-4 对 cuDNN 9.19 在短序列下基本持平甚至略低 —— 论文宣称"medium and long sequences"上领先,但没有深入分析短序列 regime 的开销(比如 JIT warmup、grid launch overhead 对小问题的放大)。
- **Deterministic backward 仍有 25% 损失**。在 RL/alignment 场景下 25% 的 throughput 折扣并不小,论文也没有讨论有没有进一步 pipeline 化 semaphore lock 的空间,或者替代方案(比如基于 tree reduction 的确定性累加)。
- **CuTe-DSL 的发展风险被轻描淡写**。把整个 kernel 押在一个 NVIDIA 自家、尚在演进的 DSL 上,意味着团队要承担 DSL 上游 breakage、PTX 版本跳跃、非 NVIDIA 硬件无法复用的代价。论文声称"isomorphic to CUTLASS C++"并用 PTX escape hatch 弥补缺失功能,但这本身就是一个"DSL 还不够成熟"的侧写。
- **论文结构偏工程速写**。Algorithm 章节多处用自然语言 + roofline 表格混杂描述,缺少完整的伪代码;对于想复现的读者,最终只能回到开源代码看 —— 这是整个 FA 系列论文的共同问题,但在 FA-4 这一代尤其突出(更多硬件细节、更多异步资源分区)。

## 7. AI Infra / MLSys 视角

FA-4 是 MLSys 社区近两年最具参考价值的 kernel 工程工作之一,对 AI Infra 研究者的启发主要在三个方向:

1. **非对称扩张(asymmetric scaling)是新常态,roofline 要定期重画**。过去几年,AI kernel 设计的默认假设是"matmul bound"—— 所有优化都围绕把 tensor core 喂满。但 Blackwell 的数据显示,这个前提正在被打破。对 attention 是 exp + SMEM,对 MoE 可能是 all-to-all collectives,对 KV-cache reuse 可能是 L2 bandwidth。值得跟进的 future work:把 FA-4 的 roofline 方法系统化成 Infra 里的"kernel audit" SOP,在每一代新硬件上重新评估哪些算子是 matmul-bound、哪些已经被辅助单元卡住。
2. **用 FMA 模拟专用单元 = 新的 unit-level scaling 技巧**。把 exp 拆到 FMA 上跑是一个极具推广潜力的思路。以类似手法可以考虑:LayerNorm/RMSNorm 的 rsqrt 能否部分分流到 FMA? sigmoid/gelu 的 exp 能否共享同一套多项式?rotary embedding 的 sin/cos 能否用软件 ladder 近似?一旦确立"non-matmul 单元是瓶颈",这类技巧会大量出现,有可能成为下一代 kernel 通用优化范式。
3. **TMEM/2-CTA 模式重塑 kernel pipeline 的 design space**。2-CTA + DSMEM 把原本必须 per-CTA 自持的 operand 拆到一对 CTA 之间,这是一个比 warp specialization 更粗粒度的协作模型,在 MoE expert routing、prefill attention 的长序列融合、甚至跨 SM 的 collective gather/scatter 里都可能有新位置。Future work:为 2-CTA + DSMEM 抽象出一套编程模型(类似 CUTLASS Hopper 的 warp specialization 抽象),让更多算子能够以较低门槛受益。
4. **Deterministic 训练的 kernel 层系统化**。FA-4 给 RL 场景提供 deterministic backward,这和 RLHF/RLVR 的可复现调试需求正在汇合。值得跟进:把 FA-4 的 semaphore + SPT 调度模式抽成通用的 deterministic reduction 组件,嵌入到 PyTorch 分布式和 vLLM 训练后端,让"deterministic training"不再是需要用户显式开关的特性。
5. **Python-embedded DSL 的代表案例**。FA-4 以 CuTe-DSL 打破了"C++ 模板才是高性能 kernel 唯一路径"的偏见 —— 20–30× 的编译时间提速对 kernel 研究员意味着可以实验数十倍以上的变体。对 AI Infra 团队,这个数据点可以用来重新评估内部 kernel 仓库是否该迁移到 Python DSL(CuTe-DSL / Triton / Gluon / ThunderKittens),以及如何在 CI 流水线里对这类 DSL 做 regression 测试。

如果要基于这篇论文做延伸工作,最有价值的切入点是:**把 FA-4 的 roofline + partial-emulation 方法论扩展到推理时最吃 throughput 的其他算子(RMSNorm fused with attention, MoE dispatch, decode 阶段的 mini-KV-cache)**,在 Blackwell 上系统识别并打通 exp 单元、SMEM、L2 这些非对称瓶颈;这比单纯继续打磨 attention kernel 本身更有杠杆。

## 8. 总结

FlashAttention-4 将 FA 系列带入 Blackwell 时代,把 tensor core 算力翻倍但辅助单元几乎没动的"非对称扩张"困境作为首要 target,通过 (1) 基于 TMEM 的全异步 MMA pipeline + ping-pong、(2) 多项式近似把一部分 exp 分流到 FMA、(3) 条件 rescaling 跳过大多数 softmax renormalize、(4) 2-CTA + DSMEM 重排减半 backward 的 SMEM 流量和全局 atomic、(5) LPT/SPT 调度 + deterministic backward 这五条主线,把 B200 BF16 的 attention kernel 推到 1613 TFLOPS(71% 理论峰值),相对 Triton 最高 2.7×、相对 cuDNN 9.13 最高 1.3×。工程侧使用 CuTe-DSL 把单 kernel 编译时间压到 2 秒级,极大加速 kernel 变体研发。适用场景是 Blackwell 数据中心 GPU 上的 BF16/FP16 attention(含长序列、causal、varlen、MQA/GQA、DeepSeek 式非对称 head dim);主要局限是 BF16-only、短序列优势有限、部分优化已被 cuDNN 追回,且论文以工程描述为主缺少完整伪代码。
