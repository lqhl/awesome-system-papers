## 1. 背景

差分隐私(DP)深度学习能够给模型提供形式化的隐私保证,使得攻击者难以从训练数据中抽取敏感信息。近年来,社区观察到 DP 训练也遵循「更大模型更好性能」的规律:RoBERTa-base → RoBERTa-large 把 GLUE 上的 DP 准确率从 83% 推到 86%;GPT2-small → GPT2-large 把 E2E 的 DP BLEU 从 61 提到 64。因此把 DP 训练规模扩展到与非 DP 大模型(GPT3-175B、LLaMA-63B)同等级别已经成为一个迫切的工程与研究问题。

在单 GPU 可容纳的模型(< 1B 参数)上,BK(Book-Keeping)算法配合 mixed ghost norm trick 已经把 DP 训练开销压到非 DP 的 1.03× - 1.08×,几乎无痛。但一旦模型超出单卡显存,需要做参数分片时,现有的 DP 分布式方案就明显掉队:DP-DDP 因为要缓存 per-sample gradient 比非 DP 慢 2 - 9×,而且根本放不下超大模型;DP-PipeP(He et al., 2022)能做到只微调 GPT3-175B 的 0.1% 参数,但被 pipeline bubble 拖慢;而非 DP 侧最先进的 ZeRO(Rajbhandari et al., 2020)—— 它通过分片 optimizer states / gradients / parameters 把基础 DataP 的 16Ψ 内存降到 16Ψ/N —— 却一直没有 DP 版本,因为 ZeRO 用的 tensor hook 与 DP 库常用的 modular hook 不兼容,且 per-sample gradient、gradient book-keeping 与参数分片之间存在多重冲突。

---

## 2. 要解决的问题

论文的目标是把 DP 深度学习从「单卡 / 小模型」时代推进到「ZeRO 级别的多节点百亿参数」时代,并要求新系统同时满足:

- **速度**:相对非 DP ZeRO 的训练吞吐不显著下降(≥ 95%),不能像 DP-DDP 那样慢 2–9×
- **显存**:多 GPU 条件下达到和非 DP ZeRO 几乎相同的 per-GPU 内存占用,支持 100B 级规模
- **通信**:保持 ZeRO 随 GPU 数近线性/超线性扩展的通信行为,不能因 DP 而退化
- **mixed-precision**:首次在 DP 大模型训练里支持 fp16/bf16,否则显存和通信量都会翻倍
- **通用性**:覆盖 ResNet / ViT / GPT 各类架构,同时兼容 DeepSpeed 和 FSDP 两大实现
- **一致性**:保持 DP 数学定义不变,隐私预算与单卡 DP 等价

核心技术障碍是:(I) DP 库用 module hook、ZeRO 库用 tensor hook,两套机制会生成多余 hook 并互相抢占计算;(II) BK 算法需要把 output gradient 留在本地做二次反传,但 ZeRO3 会把所有 model states 都分片;(III) 标准 mixed-precision 的 loss scaling 与 per-sample clipping 会彼此"双重缩放",要么溢出要么过度收缩。

## 3. 洞察与设计

**关键洞察**:DP 只改变反向传播(在反向里加一次 per-sample clipping factor 和 Gaussian noise),而 ZeRO 的分布式效率收益主要来源于模型状态分片和通信调度,这两部分与「算哪种梯度」完全正交。只要让 DP back-propagation 自身的速度/内存开销接近标准反传(借助 mixed ghost norm + BK 在单卡上早已验证),DP-ZeRO 的整体效率就自动等同于标准 ZeRO —— 尤其在多节点、通信成为瓶颈的场景下,DP 的那点额外计算会被通信时间完全掩盖。

基于这个观察,作者系统性地把 DP-ZeRO 拆成几块设计:

- **算法层**:保留 ZeRO 的「forward 前 all-gather 参数 → backward 前再 all-gather → backward 后 reduce-scatter 梯度 → 本地更新」骨架,只在 backward 里把 parameter gradient 的生成过程替换为 `DP grad = a⊤·diag(C₁,...,C_B)·∂L/∂s + σN(0,I)`,如图 3 所示,clipping factor 与 Gaussian noise 完全本地化,不引入新的跨 GPU 通信。
- **数学分片 vs 硬件分片分离**:论文明确区分 DP 的「mathematical gradient partition」(决定 clipping 粒度/精度,如 all-layer 还是 layer-wise)与 ZeRO 的「hardware gradient partition」(决定把 gradient tensor 放在哪张卡上,不影响数学结果),从而保证 DP 精度与 ZeRO 分片可以自由组合。推荐 layer-wise clipping 因其显存更省。
- **hook 融合**:选择 layer-wise clipping 后,DP 所需的 module hook 可以被并入到 ZeRO 的 tensor hook 生命周期中,避免算一次「非私有梯度」白费,也避免 BK 的 output gradient 在 ZeRO3 被错误分片(详见 Appendix E)。
- **mixed-precision 的 DP 化**:正是 per-sample clipping factor `Cᵢ = R/‖gᵢ‖` 已经承担了「把梯度归一化到某一量级」的作用,所以在 DP 路径下 **不能再使用 loss scaling**。论文论证了四种排列组合,最终推荐 `1→3→4→6`(静态 S=1,跳过 scale up 与 scale down),并建议优先用 bf16:bf16 的动态范围等同 fp32,解决 fp16 的 underflow,又不会像 fp16 那样在 loss scaling 后发生溢出。
- **与 PEFT / LoRA 正交**:当 Ψ_train ≪ Ψ_model(例如 PEFT 0.1% 参数),通信和 back-propagation 开销都按 Ψ_train 缩减,DP-ZeRO 的相对与绝对速度均提升;Remark 4.1 据此在单节点上训练了 ViT-10B full-parameter 和 ViT-22B PEFT。

## 4. 实现细节

- **代码骨架**:在 Amazon 的 FastDP 基础上扩展,把它既接入 DeepSpeed(默认)又接入 PyTorch FSDP。暴露的用户接口极简,一行代码即可启用:`privacy_engine = PrivacyEngine(model, batch_size=256, sample_size=50000, epochs=3, target_epsilon=3)`。
- **两种实现路径**(见 Appendix E):
  - *With hooks*:直接 register module hook + tensor hook,工程量小但在 ZeRO2/3 下只能支持 layer-wise clipping(因为 ZeRO3 的分片会吃掉 BK 需要保存的 output gradient);
  - *Without hooks*:按 Appendix A 的公式直接手写每类 layer 的 DP 反传(需要对 linear、embedding、conv、norm 等都写一次,可以下沉到 C++/CUDA 以进一步融合算子)。论文发布的代码库覆盖两条路径,用户通过 PrivacyEngine 选择。
- **per-sample gradient norm**:沿用 BK 的 mixed ghost norm——根据 `‖aᵢ⊤·∂L/∂sᵢ‖² = vec(∂L/∂sᵢ·∂L/∂sᵢ⊤) · vec(aᵢ·aᵢ⊤)` 的代数等价式,在每层挑选两种计算方式中更便宜的一种,从而免去 per-sample gradient 的实例化。
- **bias 处理**:bias 的梯度是 `1⊤·∂L/∂sᵢ`,不是矩阵乘积,因此 bias 的 per-sample gradient 直接实例化,不走 ghost norm。
- **gradient accumulation 下的噪声**:DP-ZeRO 不区分 micro-batch,噪声 σ·N(0,I) 在每个 micro-batch 上均匀添加。若跨 N_d 卡用相同随机种子,单 batch 噪声量为 `σ/√N_d`;否则为 `σ/N_d`。这是它与 Opacus 0.x 的主要语义差异。
- **实验硬件**:A100 40GB(大部分实验)与 A100 80GB(Figure 8 的 100B 级实验),最多扩到 32 节点、256 GPU,启用 activation check-pointing 与 MiCS(ZeRO3 变体)。

## 5. 实验结果

作者评估五个维度:架构通用性、效率、可扩展性、与不同 ZeRO 实现的兼容性、与 PEFT/低内存 optimizer 的协同。默认配置:AdamW、mixed-precision、layer-wise clipping、B=4。

**通用性与单节点效率(ViT-Gigantic 1.8B / ResNet152 / GPT2-XL 1.5B)**
- DP-ZeRO1 在 ViT / GPT 上的吞吐相对标准 ZeRO 达 81%–84%(full precision 83%、mixed precision 85%);
- layer-wise clipping 与 all-layer clipping 速度相同,但显存分别相当于标准 ZeRO 的 ~100% 和 113%(full precision) / ~107%(mixed precision)。

**ZeRO 三阶段(ViT-Gigantic,Figure 7)**

| 阶段 | DP-ZeRO 相对标准 ZeRO 吞吐 |
|------|---|
| ViT-ZeRO1 | 81% / 83%(full / mixed) |
| ViT-ZeRO2 | 89% / 84% |
| ViT-ZeRO3 | 94% / 95% |
| ViT-FSDP(ZeRO3) | 98% / 97% |
| GPT-ZeRO1 | 82% / 83% |
| GPT-ZeRO2 | 84% / 83% |

可见 ZeRO stage 越靠后,通信占比越大,DP 额外计算越被掩盖,相对差距缩小;在 4 节点配置下 ZeRO1/2 也能达到 > 95%。

**可扩展性(ZeRO3,Figure 8)**
- **固定 26B 模型、16 → 128 GPUs**:DP-ZeRO 相对标准 ZeRO 吞吐 > 95%,且随 GPU 数 super-linear 扩展(与标准 ZeRO 同趋势);
- **固定 GPU 数、7B → 100B 参数**:DP 与非 DP 吞吐曲线几乎重合,total training time 对参数量 ~线性。GPT-100B 在 256× A100 上可完成训练,这是首个百亿级 DP 模型。

**轻量训练(Figure 6)**
- 低内存 optimizer:把 Adam 替换成 SGD,ViT-5B 的显存从 ~32 GB/GPU 降到 ~25 GB/GPU;PEFT 把它进一步压到 ~11 GB/GPU,速度对应 > 2× 提升。
- PEFT 收益:DP-ZeRO 在 PEFT 下比 full fine-tuning 快约 2×,而单 GPU 仅 ≤ 1.5×,说明分布式场景更吃 PEFT 带来的通信红利。

**mixed-precision 正确性(Figure 4 / Table 3)**
- ViT-large 在 CIFAR100、ε=2。loss scaling=fp32/1 时 DP 训练可达 ~83% 准确率;scaling 升到 10 时降到 78%,100 时跌到 ~18%,1000 时几乎崩盘。标准训练则对 scaling 不敏感。实验证明 DP 路径必须关闭 loss scaling。

**DP 规模破纪录**(Figure 1):从以往工作的 < 1B 推进到 ViT-10B、ViT-Gigantic、GPT-100B 等,首次在 DP 下训完 full GPT2-XL。

## 6. 批判性分析

- **与 DP-PipeP 的对比是空的**。论文承认 He et al. (2022) 的 DP-PipeP 代码与实验细节未公开,因而直接跳过对比,只给出"既然 ZeRO 比 PipeP 强,DP-ZeRO 比 DP-PipeP 也强"的推论。但这个推论成立的前提是 DP 把 PipeP 的 bubble 损失线性继承;在只微调 0.1% 参数、bubble 其实可以被很多 micro-batch 吸收的 PEFT 设定下,DP-PipeP 未必弱。论文没有做严格基准,"DP-ZeRO 是 SOTA"的主张缺少最强对手实测。
- **效率指标主要看系统吞吐,对 DP 训练的端到端质量(accuracy × privacy budget)几乎不报**。文中给出的唯一 accuracy 曲线是 CIFAR100 上关于 loss scaling 的 sanity check,完全没有在 GPT-100B / ViT-10B 这些"被首次 DP 训成"的旗舰模型上报告下游任务准确率或 ε。读者无法判断这些训练是否产出了有用的模型,还是只是"能跑完一个 step"。
- **隐私会计粒度隐藏了一个 trade-off**。Appendix E.3 指出当 N_d 卡共享同一 seed 时单卡噪声是 `σ/√N_d`,否则是 `σ/N_d`。前者在数学上等价于单卡 DP,后者则会使总噪声变小,进而降低隐私保护强度。这对终端用户并不透明,一个粗心的集群配置可能让实际隐私预算远高于声称的 ε。
- **mixed-precision 诊断其实是"fp16 不推荐"**。Table 3 列出的四条 DP mixed-precision 方案中只有一条是 usable(bf16 + 不 loss scaling)。fp16 在 DP 路径下要么溢出要么过缩,这意味着用户要享受 mixed-precision 的显存/通信红利实际上被绑定到 Ampere+ 的 bf16 硬件上;论文没有讨论 V100 这种仍然主流但只有 fp16 的场景该怎么办。
- **DP-ZeRO1 vs DP-ZeRO3 的相对效率倒置源于基线慢,不是 DP 自身变快**。Figure 7 显示 DP-ZeRO3 的相对效率"更高",但绝对吞吐其实比 ZeRO1 低一半以上(ViT-ZeRO3 约 30 samples/s vs ZeRO1 约 100 samples/s)。论文的行文容易让人误读为"DP-ZeRO3 最好",实际只是通信开销把非 DP 和 DP 的差距都拉平了。
- **"一行代码就能用"的声明低估了工程负担**。PrivacyEngine 需要与 DeepSpeed/FSDP 深度集成才能工作,Appendix E 显示 layer-wise clipping 是 DP-ZeRO2/3 的硬性要求,否则无法运行。这些约束(不允许 all-layer clipping、必须重写 backward hook 顺序)并未在一行代码的 API 中暴露,属于隐性假设。

## 7. AI Infra / MLSys 视角

对 AI Infra / MLSys 研究者,这篇论文值得关注的点:

- **"DP 只改 backward,所以与大部分分布式策略正交"是个可迁移的分析框架**。在做 quantization-aware training、activation compression、gradient sparsification 等「只修改 backward 某一阶段」的工作时,可以直接复用论文的 speedup 分解公式(3),用来估计在不同通信/计算占比下新 backward 的端到端影响。特别是多节点场景下"只要 backward 开销不超过 forward+comm,整体就几乎不亏"这一结论,对 low-precision / compressed gradient 的系统设计都适用。
- **mixed-precision 与 per-sample 缩放的冲突值得泛化思考**。论文揭示了"两个 normalization 层串联会互相对冲"的普适问题。类似的情形在 grad accumulation + FSDP 的 fp16 训练、LoRA + DP 训练、federated learning + secure aggregation 里都可能出现。作者给出的方法论——画一张"信号量级表"(Table 3)逐步追踪每个 tensor 的 dynamic range——是一个可复用的 debugging 技巧,推荐纳入 AI Infra 团队的工具箱。
- **可跟进的 future work**:
  1. **Operator-level DP fusion**:论文在 E.2 暗示 "rewriting backward at CUDA kernel level" 是未开采金矿。把 `vec(aa⊤) · vec(∂L∂L⊤)` 直接融合进 cuBLAS GEMM epilogue,或者结合 FlashAttention 风格的 tiling 去掉中间 B×T×T 矩阵实例化,是工程价值很高的 MLSys 方向。
  2. **DP + Tensor Parallelism / Sequence Parallelism**:论文只处理了 ZeRO(分数据、分 state),对真正跨 GPU 切 layer 内部的 TP 和 Megatron-LM 风格 SP 只在 Section 5 一句话带过。将 `C_i = R/‖g_i‖` 的全局性质与 TP 的 row/column partition 协调(需要跨 GPU 求全 gradient 范数)是一个值得独立撰写的后续工作。
  3. **privacy accountant for ZeRO3 async all-gather**:ZeRO3 每次 iter 把参数 all-gather 到不同 GPU,DP 语义下这会带来细粒度的 data-access pattern,是否影响 membership inference 或 worst-case ε,目前没人分析过。
  4. **大模型 DP 下游质量的系统评估**:与其追更大的 model,不如在 7B / 13B / 26B 上跑通 DP fine-tuning → 下游 benchmark 的完整 pipeline,把"ε / accuracy / throughput" 做成可复现的三维曲面,给社区一个真正 useful 的 scaling law。
- **切入点建议**:如果要基于此论文做延伸,最低风险/高回报的点是 **把 DP backward 写成一个独立的 CUDA kernel,然后作为 DeepSpeed 的 custom op 插入**——这既能验证论文 Section 5 的"engineering improvement" 主张,又能给 DP 训练带来可能 30%+ 的额外加速,且其结果对整个社区立即可用。

## 8. 总结

DP-ZeRO 首次把 DP 优化与 SOTA 分布式训练方案 ZeRO 完整打通,在 256 GPU 上训成 GPT-100B 这类此前 DP 社区从未触及的规模,同时达到标准 ZeRO 95% 以上的吞吐。它的核心贡献有三:(1) 把 DP 的数学分片与 ZeRO 的硬件分片解耦,让 layer-wise clipping + BK + ghost norm 稳定地工作在分片环境中;(2) 系统地厘清了 DP 与 mixed-precision 的交互,证明 loss scaling 必须关闭且推荐 bf16;(3) 开源一个与 DeepSpeed/FSDP 兼容、一行代码启用的 PrivacyEngine。局限在于对模型下游质量评估几乎为零、与 DP-PipeP 等最强对手的对比缺位、fp16 兼容性较差、相对效率优势在低通信场景会退化。对于想把 DP 引入大模型训练的团队,它提供了迄今为止最实用的工程基础;对 AI Infra 研究者,它给出了"DP 正交于分布式骨架"的第一个完整验证。
