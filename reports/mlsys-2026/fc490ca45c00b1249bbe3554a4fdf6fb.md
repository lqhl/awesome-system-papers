# MorphServe: Efficient and Workload-Aware LLM Serving via Runtime Quantized Layer Swapping and KV Cache Resizing

**链接**:https://proceedings.mlsys.org/paper_files/paper/2026

## 1. 背景

LLM 在线推理服务(vLLM、Orca 等)通常用 PagedAttention、连续批处理等技术优化吞吐,但**默认假定模型精度固定、负载平稳**。然而,Microsoft Azure LLM 服务和 BurstGPT 等真实生产 trace 表明,LLM 工作负载具有强烈的**突发性和非平稳性**:请求到达率与上下文长度都剧烈波动,短时的流量尖峰会导致显存耗尽与队列堆积,从而触发 TTFT(time-to-first-token)和 TPOT(time-per-output-token)的 SLO 违约。

业界常见两类应对方案各有代价:

- **静态超配 GPU**:能扛过最坏情况,但低负载时利用率极低,边缘场景甚至无法弹性扩缩。
- **静态量化/剪枝/低秩近似**(AWQ、GPTQ、LLM-Pruner、LoRA 等):能压缩资源占用,但**带来不可逆的精度损失**,即使在低负载、本可全精度推理时也持续付出质量代价。

KV cache 压缩与驱逐(PyramidKV、SnapKV、AdaKV 等)是另一个维度的尝试,但多依赖固定启发式,无法跟随负载变化,且与 GQA、MLA 等现代注意力变体兼容性较差。

## 2. 要解决的问题

如何让一个 LLM 服务系统**在负载维度上弹性可调**,使精度与延迟的权衡能随实时压力沿 Pareto 前沿移动:

1. **静态精度无法兼顾**:全精度服务在突发流量下违约,静态量化在低负载时无谓地牺牲质量。
2. **缺乏运行时机制**:现有混合精度/早退/层跳过工作(PMPD、MARLIN、LayerSkip、FlexiDepth)往往需要离线决策或架构改造,不能基于实时负载在线调整。
3. **KVC 弹性缺失**:静态预分配的 KVC 容量在峰值时不足、空闲时浪费,且现有 KVC 压缩方案与 PagedAttention/GQA 集成困难。
4. **状态保留的难度**:在不打断进行中请求的前提下,在 token 级别切换层精度并扩缩 KVC,需要避免模型重 prefill、避免 GPU 内存指针重映射、避免对解码流的阻塞。

## 3. 洞察与设计

**关键洞察**:

1. **量化对不同 transformer 层的影响是近似可加的**(论文用 Llama 2 7B 在 WikiText 实测,无论已量化几层,继续量化 layer 19/24 带来的 perplexity 增量基本恒定 ≈ 0.0035 / 0.0020,Appendix Table 7)。这一性质使得"按重要性排序、贪心地逐层切换"成为可行策略。
2. **不同层对最终输出的敏感度差异巨大**:有的层切到 INT4 几乎没有质量损失,有的层换掉就明显退化。可以通过离线 profiling(Layer Importance Score)给出固定的优先级序列,运行时无需重新计算。
3. **量化释放的显存可以复用为 KVC 容量**:FP16 → INT4 一层节省 ~75% 权重内存(7B 模型一层从 ~0.4 GB 缩到 ~0.1 GB),恰好可以补齐突发流量下的 KVC 缺口。
4. **token 级粒度足够细**:在一个请求的解码过程中临时切换若干层的精度,只让"加压窗口内"生成的 token 略受影响,前后 token 仍是全精度,精度损失被局部化。
5. **PCIe 与解码可以重叠**:一层 INT4 ~4 ms、FP16 ~16 ms 的 H2D 传输,可以用独立 CUDA stream 与正在进行的解码完全重叠,做到几乎零阻塞。

**设计概览**(见 Fig 2 架构图):

MorphServe 由三个组件构成反馈控制环路:

- **Serving Monitor**:采集 GPU 显存利用率、请求队列深度、吞吐、TTFT/TPOT 等运行时指标,做短窗口平滑后用于检测饱和征兆。
- **Morphing Controller**:全局 GPU 显存管理器,当指标超过用户阈值(例如 KVC > 85%、队列等待 > 100 ms)时,决定调用 LayerSwapper 或 KVResizer 并向具体 worker 下发指令。
- **Morphing Executor**:每个 worker 上的本地执行器,负责实际的层替换和 KVC 块增减。所有动作走异步 CUDA stream + 预分配 buffer,与解码流并行。

两个核心机制:

**LayerSwapper(动态层切换)**

- 离线 profiling 计算每层的 Layer Importance Score:`LIS = α₁·LTS + α₂·LRS + β·MDS`,其中 LTS(层输入输出 cosine sim)和 LRS(原层与量化层输出 cosine sim)是与输入无关的局部指标,MDS 是给定当前已量化层集合 Q 后再换 p 层带来的端到端 cosine sim 变化。论文采用 α₁=α₂=0.25, β=0.5,贪心地按 LIS 降序构造层切换序列。一次性离线执行,32 层模型 < 15 分钟。
- 运行时所有变体(FP16、INT8、INT4)都预加载到 pinned CPU 内存,GPU 上保留全精度副本,所有 GEMM kernel 提前编译好。
- 切换时用 `cudaMemcpyAsync` 在原始地址上原地覆盖,无需指针重映射;动作走单独的 CUDA stream,与解码完全重叠;一次 INT4 替换包括传输 + 重建约 6 ms。
- 注意力状态和解码进度不动:替换的是权重,KV cache 已计算的 token 表示保持原样,因此**不需要 re-prefill**。

**KVResizer(弹性 KVC 扩缩)**

- 在 PagedAttention 之上扩展了块级别的按需分配/回收能力,通过内存映射实现,无需 kernel 重编译。
- 当 Monitor 检测到 KVC 不够给新请求 prefill 或继续 decoding 时,先触发 LayerSwapper 释放权重显存,再把空出来的物理块挂到 KV cache pool 中。压力消退后两者都回滚:KVC 块释放,层恢复 FP16。
- 解决两类问题:(a) prefill 阶段队列因无 KV 块而堆积,导致 TTFT 飙升;(b) decoding 阶段因显存满而 preempt,触发 swap-out 或重计算,导致 TPOT 长尾。

**Token 级渐进适配 + 状态保持**:不同于以往压缩"作用于整个请求"的做法,MorphServe 在单个请求内可以前 1K token 用 FP16、中间 1K 用 W4、再切回 FP16,论文 Table 1 实测各种切换 pattern 的 F1/Rouge-L 都被框定在 FP16 上界与 W4 下界之间,质量可控。

## 4. 实现细节

- **代码量**:约 2,200 行 Python + 500 行 C++/CUDA,基于 SwiftLLM(一个复刻 vLLM 性能、组件更轻量的推理框架)。
- **权重布局**:所有精度变体(FP16、W8、W4、可选 W3)预加载到 pinned CPU 连续内存,GPU 上每层有固定地址区域,通过追踪指针表执行原地拷贝。kernel 用 dummy 数据预编译,避免运行时编译延迟。
- **KV cache 扩展**:在 PagedAttention 上加了块级动态注册机制,支持运行时 attach/detach 物理块,所有 attention kernel 接受动态 block table。
- **CUDA stream 隔离**:morphing 和 decoding 分别在独立 stream,通过 event 同步,确保 H2D 拷贝、KVC 重映射不阻塞 token 生成。
- **profiling 算法**(Algorithm 1):双层循环。外层 32 次(L 层),内层对每个未量化层 j 临时量化、跑校准集、算 MDS,再合成 LIS,选 argmax 加入 Q。整体一次性、可并行,~15 分钟/模型。
- **量化算法无关性**:论文对 AWQ 与 uniform INT4 都做了实验,效果一致,说明 MorphServe 是一个调度框架,不依赖特定量化方法。
- **未实现的部分**:仅做权重精度切换,activation 与 KV 的量化、子模块(attention / MLP 分别)的更细粒度切换、SSD → host 流式加载等都列在 future work。

## 5. 实验结果

**评测设置**:Vicuna 7B v1.5、Llama 2 7B、Llama 3 8B、CodeLlama 34B 四个模型;Azure LLM Inference 与 BurstGPT 两个真实 trace(各取 72s 片段并按 1.75× / 4.75× 下采样匹配硬件);GovReport、Multi-News(长文摘要)、QMSum(query 摘要)、DuReader(阅读理解)四个数据集。7B/8B 在 NVIDIA L4 (24 GB),34B 在 A100 (80 GB)。基线:FP16(质量上界)与 INT4 静态量化(性能上界,用 AWQ kernel)。MorphServe 报两个模式:accuracy mode(保守,优先质量)和 performance mode(激进,优先吞吐)。

**主结果**(Fig 4):

| 指标 | MorphServe vs FP16 | MorphServe vs INT4(静态 AWQ) |
|---|---|---|
| P95 TTFT | 减少 2.2×–3.9×(accuracy mode);3.4×–19.5×(perf mode) | 性能差距很小,但质量明显更好 |
| 平均 SLO 违约率 | 减少 92.45% | — |
| F1/Rouge-L 退化 | accuracy mode 仅 0.11%–2.18%,perf mode 0.51%–3.82% | 静态量化退化 2.34%–9.47%;MorphServe 减少退化最多 88.85% |
| 显存利用率 | — | 提升 29.29% |

**KVC 弹性**(Fig 5):FP16 基线在峰值时 KVC 满,触发排队/preempt/swap;静态量化即使有空闲显存也固定不用;MorphServe 在突发期最多扩容 32.97% 超过 FP16 上限,排队延迟最多减少 3.8×。

**吞吐**(Fig 6):MorphServe 在 DuReader 上把饱和点向后推,峰值吞吐比 FP16 高 1.6×–1.83×。

**TPOT 长尾**(Fig 7):平均 TPOT 与 FP16 持平,P95/P99 减少最多 1.06×/1.23×;perf mode 平均 TPOT 还能再降 1.11×–1.17×。runtime overhead 可忽略。

**消融**:

- **量化算法无关**(Table 2):MorphServe 在 AWQ 与 uniform INT4 上同时把准确率退化降 83.57% / 74.67%,P95 TTFT 比 FP16 低 77%+。
- **LIS 跨数据集泛化**(Table 3):用 WikiText-2 校准的 LIS 在 C4 上仍优于 front-to-back / back-to-front / random 顺序。
- **混合精度质量边界**(Table 1):BookSum 6K/2K 长文本下,各种 FP16/W4 token 切换组合的 F1 都在 [W4, FP16] 区间内,可控。
- **量化独立性验证**(Appendix Table 7):layer 19、24 的增量 perplexity 在已量化 0–16 层的所有设置下基本恒定,直接支撑了贪心 ranking 的合理性。
- **LIS 顺序消融**(Table 6):有趣的是 Front-to-Back 在多数模型上几乎和 LIS 持平,论文承认并把 Front-to-Back 作为没有 profiling 时的默认 fallback。

## 6. 批判性分析

1. **LIS 的实证收益小于其复杂度暗示的程度**。Table 6 显示 Front-to-Back 与 LIS 在所有 4 个模型、所有量化层数下 perplexity 差距通常 < 0.01,在 CodeLlama 34B 上几乎完全重合。论文也坦承"Front-to-Back remains highly competitive… MorphServe adopts Front-to-Back as the default"。这相当于自己承认 LIS 这条复杂的离线 profiling pipeline(LTS + LRS + MDS、贪心搜索)在工程上**收益边际**——核心系统价值其实来自切换+扩 KVC 这套机制本身,而不是切谁先切谁后。这削弱了文章 Section 4.2 整节的必要性。

2. **饱和点和 SLO 指标对实验配置非常敏感**。trace 被人为下采样 1.75× / 4.75× 来匹配 24 GB / 80 GB 的小硬件,trace 片段只取 72 秒,而 P95 TTFT 在饱和前/后差异巨大(图 6 显示 FP16 一旦过饱和点 TTFT 直线飙升)。"P95 TTFT 减少 2.2×–3.9×"这类数字本质是"是否进入饱和区"的二元差异,而 MorphServe 的优化恰好把饱和点向后推。换更大显存或更长 trace,优势可能急剧收窄。文章未报告"远低于饱和点"和"远高于饱和点"两个极端区间的对比。

3. **MorphServe vs INT4 的延迟可比性存疑**。Table 2 显示 INT4 静态的 P95 TTFT(1.17 s)比 MorphServe(1.24 s)还稍低,Table 8 的 Vicuna 上甚至差出近 2×(0.41 s vs 0.73 s)。换言之,MorphServe 的"延迟优势"主要相对 FP16,相对 INT4 静态其实是劣势,只是用更好的精度换回来的。文章的 marketing 一直强调"vs FP16",对 INT4 的优势单纯是质量。

4. **没有比较先进的动态/混合精度基线**。MorphServe 的核心定位是"工作负载感知的动态混合精度",但实验只与 FP16 和静态 AWQ INT4 比,没有跟 PMPD(prompt-aware mixed precision)、MARLIN、LayerSkip、FlexiDepth 等同方向工作做端到端对比。这些方法在 Section 2 都被提到,但只在 motivation 段轻飘飘地说"prioritize hardware efficiency but overlook runtime workload variability",没有数据支撑。

5. **2× 内存代价被淡化**。MorphServe 需要在 host 内存里同时存 FP16 + INT8 + INT4(可能 + INT3)三/四份权重,论文称"under 2×"。对单 7B 还能接受,但放大到 70B / MoE 级别(几百 GB),host 内存从几百 GB 一下升到 1 TB 以上,云上是显著成本。Limitation 里只用一句话带过("future work may stream from SSD"),并没有量化。

6. **profiling 中 MDS 的"假设量化层效果可加"在数学上其实并非严格成立**。Appendix B.1 测了 layer 19 和 layer 24 单独的边际效应稳定,但没有跨多对、跨 layer 间隔近(如 layer 5 vs layer 6)的情形,可加性结论的支撑面较薄。

7. **触发阈值是手工设的**(KVC > 85%、queue > 100 ms),没有自适应/学习方案,在不同流量分布下需要重新调参,论文没讨论 robustness。

## 7. AI Infra / MLSys 视角

这篇论文对做 LLM 服务系统的研究者很有借鉴价值,**核心可迁移的设计哲学是"运行时弹性"**:把以往离线决定的资源/精度配置,变成与负载耦合的反馈控制问题。具体几个值得跟进的方向:

1. **把"层级 morphing"扩展到更细粒度**。论文目前在 transformer layer 边界切换,自然延伸是 attention vs MLP 分开切(MLP 占 65%+ 参数,质量影响也不一样)、甚至 expert 级别(MoE 模型每个 expert 独立选精度,负载 + 路由统计直接驱动)。这是非常具体的、技术上可实现的下一步。

2. **预测式 morphing 取代反应式 morphing**。论文坦承自己只反应不预测,这正好留出了一个研究空间:用轻量时间序列模型(甚至简单 EWMA)预测下一个 5–10 秒的 token throughput,提前几百毫秒触发 swap,把 H2D 时间彻底隐藏。结合 trace 的可预测周期性(BurstGPT 有明显的日内规律),收益空间显著。

3. **把 KVResizer 与现代 KV 压缩方法组合**。文章自己提到"compatible with KV cache compression",但没做实验。一个 follow-up:MorphServe + PyramidKV / SnapKV 组合,既动态扩 KVC,又对长尾 token 用 importance-based 驱逐,可以再多挤一档容量。

4. **PD 分离架构下的 morphing**。Splitwise / DistServe 这类 prefill-decode 分离的部署里,prefill 实例显存 / 算力压力模式与 decode 实例完全不同,可以让两类实例分别拥有不同的 morphing 策略(prefill 主要扩 KVC 减队列,decode 主要降权重精度避免 preempt)。这是与最新 serving 架构的直接结合点。

5. **Activation / KV quantization 的同步切换**(论文 Future Work 里也提了)。INT4 weight 已经接近极限,结合 W4A8KV4(QServe)做运行时 dynamic switch 的 kernel 复杂度高、calibration 依赖更强,但理论上能再提供 ~30% memory headroom。

6. **离线 profiling 指标的廉价化**。现在 LIS 跑 32 层模型要 15 分钟、跑 70B 模型可能 1 小时+。如果能用 LLM-internals(如 attention sink、layer activation norm)做 zero-shot ranking,profiling 可以免做。论文 Table 6 Front-to-Back ≈ LIS 也佐证:layer 重要性可能有简单的结构性 prior 可用。

**值得复用的工程模式**:把"resource pool → 反馈监控 → 异步 reconfiguration"这套控制环路,作为 LLM serving 系统的通用基础设施。这个抽象不只用于精度切换,也可以管理 LoRA adapter 的换入换出(类似 dLoRA)、speculative decoding draft model 的开关、batch size / chunked prefill 阈值的动态调整。

## 8. 总结

MorphServe 提出了一个简单但实用的运行时弹性 LLM 服务框架,通过 LayerSwapper(token 级层精度切换)和 KVResizer(弹性 KVC 块挂载/释放)的协同,实现负载感知的混合精度推理:在低负载时保持 FP16 质量,在突发流量下用最少的层数、最少的 token 受影响来扛住饱和。实验在 4 个模型 × 2 个 trace × 4 个数据集上显示 P95 TTFT 减少 2.2×–3.9×、SLO 违约减少 92.45%,精度损失可控在 3% 以内。系统适合云端中小规模(7B–34B)的 LLM 在线服务,主要局限是 ~2× 的 host 内存放大、profiling 收益边际、与同类动态混合精度方法缺乏直接对比;最具借鉴价值的不是 LIS 算法本身,而是"反馈控制 + 异步原地权重切换 + KV 块动态注册"这套通用工程模式。
