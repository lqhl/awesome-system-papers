# MorphServe: Efficient and Workload-Aware LLM Serving via Runtime Quantized Layer Swapping and KV Cache Resizing

**作者**：Zhaoyuan Su, Zeyu Zhang, Tingfeng Lan, Zirui Wang, Haiying Shen, Juncheng Yang (Harvard), Yue Cheng — University of Virginia
**会议**：MLSys 2026
**链接**：[arXiv](https://arxiv.org/abs/2506.00260)
**源文件**：[[fc490ca45c00b1249bbe3554a4fdf6fb.pdf]]

---

## 一、背景

LLM 推理服务面临动态突发负载的核心挑战。vLLM、Orca 等主流框架通过 PagedAttention 和 continuous batching 优化吞吐，但均假设固定精度和稳定负载。现实中，Azure LLM 和 BurstGPT 的生产 traces 显示请求到达率和 token 量存在剧烈波动——短暂的流量尖峰即可导致 GPU 显存耗尽、排队延迟激增，引发 SLO 违规（TTFT 超标）。

与此同时，静态量化（如 AWQ、GPTQ）虽降低了资源占用，但引入不可逆的精度退化，即使在低负载时也无法恢复全精度推理。KV cache 压缩/驱逐方法依赖固定启发式，与 GQA、MLA 等新型注意力机制不兼容，且无法根据运行时状态自适应调整。

---

## 二、要解决的问题

1. **全精度服务的脆弱性**：达到饱和点后，TTFT 急剧飙升，出现大量 SLO 违规，但在低负载期间资源被浪费
2. **静态量化的刚性**：全时段施加精度损失，低负载时本可全精度服务却仍承受 2.34%–9.47% 的 F1 退化
3. **KV cache 管理的静态性**：PagedAttention 预分配固定 KVC 容量，高负载时触发请求抢占和 KVC swap，低负载时又浪费显存
4. **缺乏运行时自适应**：现有系统无法在推理过程中根据实时负载动态调整模型精度和 KVC 容量

## 三、洞察与设计

**关键洞察**：Transformer 各层对量化的敏感度近似独立且可叠加——量化某一层引入的额外 perplexity 在不同量化组合下保持近乎恒定。这意味着可以通过离线 profiling 建立一个固定的层替换优先级序列，在运行时按此顺序逐层替换，而无需在线重新计算决策。

基于此洞察，MorphServe 设计了一个反馈驱动的控制回路，包含三个核心组件：

- **Serving Monitor**：采集 GPU 显存利用率、队列深度、TTFT/TPOT 延迟等指标，滑动窗口平滑后检测负载变化
- **Morphing Controller**：全局 GPU 显存管理器，当指标超过阈值（如 KVC 显存 >85%、排队延迟 >100ms）时，决定触发层替换和/或 KVC 扩容
- **Morphing Executor**：驻留在每个 worker 上，执行两个互补机制：
  - **LayerSwapper**：按离线 profiling 的 Layer Importance Score (LIS) 序列，异步将低影响力的 FP16 层替换为预量化版本（INT8/INT4/INT3），压力消退后恢复全精度
  - **KVResizer**：将层量化释放的显存（如 FP16→INT4 释放 75%）弹性分配为新的 KVC blocks，支持更多请求的 prefill 和 decoding

关键设计决策：
- **Token 级自适应**：在单个请求的 decoding 过程中可临时替换部分层，早期 token 全精度、后期 token 混合精度，压力消退后恢复
- **状态保持的 morphing**：层替换不中断 attention 状态或 decoding 进度，无需模型重载或 re-prefill
- **异步执行**：层替换在独立 CUDA stream 上进行，与 decoding 重叠，开销可忽略

## 四、实现细节

**Layer Importance Score (LIS)**：离线 profiling 时，对每层计算三个基于 cosine similarity 的敏感度指标：
- Layer Transformation Sensitivity (LTS)：层输入输出的 cosine similarity，衡量层变换强度
- Layer Replacement Sensitivity (LRS)：全精度层与量化层输出的 cosine similarity，衡量替换失真
- Model Degradation Sensitivity (MDS)：在当前已替换层集合 Q 下，再替换候选层后模型输出的 cosine similarity

三者加权组合：`LIS_p = 0.25·LTS_p + 0.25·LRS_p + 0.5·MDS_p`，采用贪心策略逐步选择 LIS 最高的层加入替换序列。32 层模型 profiling 耗时 <15 分钟。

**模型预加载**：所有精度变体（FP16/INT8/INT4/INT3）预加载到 pinned CPU memory，推理 kernel 预编译消除运行时编译延迟。GPU 上预分配连续显存区域，层替换通过 `cudaMemcpyAsync` in-place 拷贝，无需指针重映射。

**层替换延迟**：Llama 2 7B 上，INT4 层约 0.4→0.1GB，PCIe Gen4 传输约 4ms（INT4）/16ms（FP16），完整替换含重建约 6ms，完全与 decoding 重叠。

**KVResizer**：扩展 PagedAttention 支持 block 级动态分配/释放，通过 memory mapping 实现无需 kernel 重编译。所有 resize 操作在独立 CUDA stream 上异步执行。

**代码规模**：基于 SwiftLLM 实现，新增约 2,200 行 Python + 500 行 C++/CUDA。

## 五、实验结果

**实验设置**：
- 模型：Vicuna 7B v1.5、Llama 2 7B、Llama 3 8B、CodeLlama 34B
- 硬件：7B/8B 模型用 NVIDIA L4 (24GB)，34B 用 A100 (80GB)
- Traces：Azure LLM Inference (72s, 4.75× downscale)、BurstGPT (72s, 1.75× downscale)
- 数据集：GovReport、Multi-News、QMSum、DuReader
- 量化方法：AWQ INT4

| 指标 | MorphServe vs FP16 | MorphServe vs 静态 INT4 |
|------|-------------------|----------------------|
| SLO 违规率 | 降低 92.45% | — |
| P95 TTFT | 降低 2.2×–3.9×（accuracy mode） | — |
| 吞吐量 | 提升 1.6×–1.83× | — |
| F1/Rouge-L 退化 | 0.11%–2.18%（accuracy mode） | 减少退化最高 88.85% |
| KVC 显存利用率 | — | 提升 29.29% |
| KVC 容量扩展 | 超出 FP16 上限 32.97% | — |
| 排队延迟 | 降低最高 3.8× | — |
| P99 TPOT | 降低最高 1.23× | — |

**Perplexity（Llama 2 7B, WikiText-2）**：全 FP16 为 5.47，LIS 策略量化 16/32 层分别为 5.52/5.60，优于 Front-to-Back、Back-to-Front 和 Random 策略。

**跨量化方法泛化**：AWQ 和 Uniform INT4 均有效，F1 退化分别降低 83.57% 和 74.67%。

## 六、批判性分析

1. **实验规模有限**：所有端到端实验在单 GPU 上进行（L4 24GB / A100 80GB），72 秒 trace 片段且做了 1.75×–4.75× downscale。论文声称"naturally scales to distributed serving"但未提供任何多 GPU 实验验证。实际多节点部署中，Morphing Controller 的全局协调、跨节点通信开销、以及不同 worker 上层替换状态不一致等问题均未被讨论。

2. **CPU 内存开销被轻描淡写**：需要在 CPU pinned memory 中存储所有精度变体（FP16 + INT8 + INT4 + INT3），对于 Llama 2 7B 这意味着约 2× 模型大小的额外 CPU 内存。论文仅用一句话带过"typically under 2× and is well accommodated by modern clusters"，但在 edge 场景（论文声称的目标之一）这一开销并不小。

3. **Trace 代表性存疑**：仅 72 秒的 trace 片段，且经过大幅 downscale 以适配硬件。这种人为缩放后的负载模式是否仍能反映真实生产环境的突发特性值得质疑。论文提到"MorphServe is effective across the full traces"但未给出完整 trace 的结果。

4. **精度评估不够充分**：仅使用 F1 和 Rouge-L 评估生成质量，这两个指标对摘要任务有效，但对于对话、推理、代码生成等更广泛的 LLM 使用场景，混合精度推理可能带来更微妙的质量退化（如逻辑一致性、事实准确性），论文未涉及。

5. **与更强基线缺乏对比**：仅对比全精度 FP16 和静态 INT4，未与近期的动态推理方法（如 LayerSkip、FlexiDepth、PMPD）做端到端对比。虽然论文在 related work 中讨论了这些方法，但以"objectives differ"为由回避了直接比较。

6. **LIS 的 front-to-back 默认策略暴露了 profiling 价值有限**：Table 6 显示 Front-to-Back 策略与 LIS profiling 在大多数配置下 perplexity 差异极小（如 Llama 2 7B 量化 16 层：5.54 vs 5.52），论文自己也承认"Front-to-Back remains highly competitive"并将其作为默认策略。这削弱了 LIS 这一核心技术贡献的实际价值。

## 七、AI Infra / MLSys 视角

**启发与借鉴价值**：
- **运行时 morphing 的范式**：MorphServe 提出的"在推理过程中动态调整模型精度"思路，为 LLM serving 系统引入了一个新的自由度。这一范式可推广到其他维度的运行时自适应——如动态调整 batch size、sequence length 限制、甚至模型并行策略。
- **层量化独立性假设**的验证（Table 7）为混合精度推理的理论基础提供了实验支撑，可被其他混合精度系统借用。

**可迁移的技术**：
- 异步 CUDA stream 层替换 + pinned memory 预加载的工程模式，可复用于 LoRA adapter 热切换、speculative decoding 中 draft model 的动态替换等场景
- KVResizer 的弹性 KVC block 管理思路可与 KV cache 量化（如 KV4）、分层 KV cache（如 LayerKV）结合

**值得跟进的方向**：
1. **预测式 morphing**：论文当前为反应式（reactive），集成轻量负载预测（如基于历史 trace 的时序预测）可实现 proactive morphing，提前在流量尖峰到来前完成层替换
2. **Activation + KV 量化的联合 morphing**：论文仅做 weight-only 量化，将 activation 量化和 KV cache 量化纳入 morphing 框架可释放更大的显存空间
3. **多模型/多 LoRA 场景**：在多租户服务中，不同模型/adapter 可以共享 morphing 策略，实现跨模型的显存弹性调度

---

## 八、总结

MorphServe 提出了一种负载感知的 LLM 推理框架，通过运行时量化层替换（LayerSwapper）和弹性 KV cache 扩缩容（KVResizer）两个异步机制，在高负载时动态降低模型精度以释放显存、扩展 KVC 容量，低负载时恢复全精度。在单 GPU 实验中效果显著（SLO 违规降低 92.45%、精度退化 <2.18%），但多 GPU 扩展性、CPU 内存开销、以及 LIS profiling 相对简单启发式的增量价值仍需进一步验证。
