# FarSkip-Collective: Unhobbling Blocking Communication in Mixture of Experts Models

**作者**：Yonatan Dukler, Guihong Li, Deval Shah, Vikram Appia, Emad Barsoum
**单位**：Advanced Micro Devices Inc. (AMD)
**会议**：MLSys 2026
**链接**：https://proceedings.mlsys.org/paper_files/paper/2026
**源文件**：[[698d51a19d8a121ce581499d7b701668.pdf]]

---

## 1. 背景

Mixture-of-Experts (MoE) 已成为当前主流大模型的事实架构（DeepSeek-V3、Llama-4、Qwen-3、Kimi-K2 等），通过稀疏激活把参数规模扩展到数百 B 乃至 T 级别。由于单卡显存有限，MoE 的训练和推理严重依赖分布式执行 —— 典型并行策略 Tensor Parallelism（TP）把 MLP/Attention 沿维度切分后以 all-reduce 汇合，Expert Parallelism（EP）把专家按 rank 切分并通过 all-to-all 的 Dispatch / Combine 做 token 路由。

分布式执行中这些通信集合是阻塞的（blocking）：下一阶段的计算必须等通信返回结果后才能开始，在通信期间加速器空转，形成 exposed idle。随着硬件算力提升（MI325X、H100）和模型稀疏度上升，通信占端到端时间的比例持续扩大，尤其在 wide-EP（32+ ranks）和多节点场景下已成为首要瓶颈。

文献里已有两类思路：operator 分解加 fine-grained 调度（AsyncTP、DeepSpeed），以及更激进的架构级改动 —— 用"outdated"或"partial"的输入激活替代完整输入以解除依赖（Ladder-Residual、Kraken 等）。但后一类方案之前只在 dense + TP 场景上、且仅部分层上验证过，没人证明它可以扩展到 100B+ 参数的 SOTA MoE 全层改造。本文即回答这个问题。

---

## 2. 要解决的问题

1. **MoE 特有的阻塞通信**：每层至少有三处 blocking 位点 —— attention 后的 TP/CP all-reduce、MoE Dispatch 和 MoE Combine。Dispatch/Combine 因依赖 router 输出，天然处于 critical path 上，无法简单 pipeline。
2. **现有架构改造只在 dense + TP 上验证过小模型**：Ladder-Residual、Kraken、Lamprecht et al. 等工作要么仅做部分层改造，要么只覆盖 dense 模型，未证明「全层改造 + 100B+ MoE」可行。架构级改动在小模型上有效不等于在前沿模型上有效。
3. **即便逻辑上解除了依赖，实际重叠非易事**：PyTorch / JAX 不会自动 overlap computation 与 async communication，autograd 图在反向传播时还会强制同步。需要在框架层给出可被下游复用（不依赖低层 kernel 重写）的通用实现。
4. **架构改动后如何低成本恢复精度**：从头预训练大型 MoE 不现实，必须找到 ≤10B tokens 量级的 recovery recipe。

---

## 3. 洞察与设计

**关键洞察**：在现代 Transformer 的残差主干下，第 k 层 sub-block 的输入由先前所有 sub-block 的 residual 累加构成，即便把当前层的 communicated output 推迟到再下一层 residual（"far-skip"）而不是作为直接输入，第 k+1 层仍能访问 (k-1)/k 比例的历史信息。在足够大的模型里，这种"丢一个 block"的扰动对能力的冲击可以通过少量 distillation 恢复。换言之，**残差连接为 communication hiding 留下了一条几乎免费的信息旁路**。

基于此，作者把原本的计算图

$$o_k = f_1(o_0) + f_2(o_1) + \dots + f_k(o_{k-1})$$

改造为

$$o_k = o_0 + f_1(o_0) + f_2(o_1^*) + \dots + f_k(o_{k-1}^*)$$

其中 $o_k^*$ 有两种选项：
- **outdated**：$o_k^* = o_{k-1}$，直接用上一层的 residual，完全跳过当前 sub-block 的 communicated 部分
- **partial**：$o_k^* = o_{k-1} + f_k^*(o_{k-1}^*)$，使用那些在 communication 开始前就已 ready 的 partial 结果（比如 TP 中每 rank 自己的 $\text{MLP}^i(A)$）

MoE 层里作者采用混合策略：
- attention 入口使用 **partial**：`attn-in_k = o_{k-2} + attn-out_{k-1} + shared-exp-out_{k-1}`（缺失的是 routed-expert 的 Combine 输出）
- MoE 入口使用 **outdated**：`mlp-in_k = o_{k-1}`

由此，Combine 的 all-to-all 可以与下一层的 shared-expert + attention 重叠，Dispatch 的 all-to-all 可以与 attention 本体（core-attention + output projection）重叠。论文 Figure 1（架构对比）和 Figure 2（算子时序）直观展示了两侧差异及 overlap window。

**FarSkip-Collective Self-Distillation (FCSD)** 是配套的精度恢复配方：以原模型为 teacher，用 KL 知识蒸馏在 SFT 数据上继续训练 ≤10B tokens，MBPP+ 早停防止 KL 训练后期的梯度不稳定（teacher–student 接近时偶现大梯度）。作者做了一组消融：KL 比 SFT 显著好，加 intermediate L2 loss 反而更差，embedding 冻结影响甚微。

## 4. 实现细节

### 训练（Megatron-LM）

作者沿用 DeepSeek-V3 风格的 MoE+MLA+EP+no-TP-on-attention 配置。核心工程点：

1. **拆分 attention 为两段**：(a) MLA 的 Q/K/V 准备，(b) core-attention + output projection。Dispatch 的 async 启动点放在 (a) 和 (b) 之间，使 (b) 与 Dispatch 通信重叠。
2. **Forward 执行顺序**：attn(a) → sync 上一轮 Combine → gating/router → 启动 Dispatch（async-op）→ attn(b) → sync Dispatch + routed experts → 启动 Combine（async-op）→ shared experts。
3. **Backward 的两项 trick** —— 这是工程最难的部分：
   - **Stateful async all-to-all autograd function**：在 forward 创建的 async handle dict 中预留 backward key，当 backward 触发时，自定义 autograd function 填入 backward 通信 handle；再通过 backward hook 挂到通信输入的 tensor node 上，在处理前强制同步。
   - **劫持 autograd Sequence Number**：torch.autograd 对同时 ready 的节点用 Sequence Number 排序。作者通过重新分配 Sequence Number，把通信输入节点的优先级降低，让 sub-block 的 backward 计算先跑，从而在反向也创造出 overlap window。

实测 DS-V2 Lite (16B) + EP8 在 1×MI325X 机器上取得 87.6% (fwd) / 89.0% (bwd) 的 all-to-all 重叠率，端到端训练加速 1.11×。

### 推理（vLLM + SGLang）

vLLM / SGLang 的 MoE 实现不是 all-to-all 风格，而是把激活复制到所有 rank，只切 expert 权重，然后在 MLP 末尾做 all-reduce。因此 FarSkip 在推理端针对的是：
- MoE 层的 all-reduce 改为 async-op，延迟到下一次 MoE 计算前再 sync
- attention 的 RowParallelLinear 输出 all-reduce 改为 async-op，延迟到下一 attention 层前再 sync
- 针对 MLA 的 prefill / decode 两套 fused kernel 分别处理
- 使用 graph-compatible API（PyNCCL）与 HIP/CUDA Graphs 集成

all-reduce overlap 率：Llama-4 Scout 95.3%，DeepSeek-V2 97.6%。Llama-4 Scout TTFT 加速 12.2% – 18.5%。

整体设计刻意停留在 PyTorch API 层而不是 Triton / 手写 kernel，以便在 AMD HIP 和 NVIDIA CUDA 两边通用。

### 推理侧

- vLLM 上 Llama-4 Scout (109B) / DeepSeek-V2 (235B) prefill TTFT 加速 12.2–18.5% / 8.2–16.8%（1×MI300X 8GPU，EP=8 + TP=8，FP8，BS=2，L=512/1024/2048）。
- SGLang 上 DeepSeek-V3 (671B) TP=8 + EP=8 prefill 最高 1.34× TTFT 加速。
- 单节点大 MoE 的 decode 阶段受 memory-bandwidth 支配、通信占比小，FarSkip 收益有限；但 TP=16 + EP=16 的 2 节点 wide-EP + BS=1024 decode 场景下 Time-Between-Tokens 有稳定加速。

### 预训练（Appendix A）

从头预训练 16B DeepSeek-V2-Lite 50B tokens，FarSkip 训练 loss 2.205 vs regular 2.187，评估集平均 54.7 vs 54.4，无统计学差异 —— 说明架构本身并不"弱"。

## 6. 批判性分析

1. **"1% 差距"的口径遮蔽了若干显著退化**。摘要和结论反复强调 Llama-4 Scout 平均掉点 < 1%，但 MMLU 从 80.0 降到 75.9（−4.1），Qwen-3-30B MoE 的 MMLU 从 80.2 降到 74.0（−6.2）、MBPP+ 从 84.4 降到 74.4（−10.0）。MMLU 对学术知识敏感、MBPP+ 对分布偏移敏感，这些是 distillation 难以补偿的"硬"能力。平均到 11 个 benchmark 会被 PIQA / ARC-E / HS 这类接近饱和的任务稀释，建议读者关注子任务差异。
2. **10B tokens 的 distillation 不是小数字**。虽然相对 pretrain from scratch 便宜 100–1000 倍，但 10B tokens × 100B 参数的 fwd+bwd 仍需几天集群时间。论文多次淡化了这一成本，尤其在 "efficient recipe" 的措辞上。对于不掌握 instruction-tuning pipeline 的团队，这是非平凡门槛。
3. **vLLM / SGLang 推理侧的适用范围被模糊表述**。论文强调 FarSkip 在推理侧能 overlap，但 vLLM / SGLang 当前用的是 activation-replicated + all-reduce 的 MLP 切分方式，不是真正的 EP Dispatch/Combine。因此推理侧成果实质上是"TP all-reduce overlap"，与训练侧的 EP all-to-all 是不同问题。把它们合写成一个故事，读者容易高估方法适用性。
4. **"永远有至少两处 all-to-all 不能 overlap"这一硬约束未充分讨论**。作者自己承认 forward 最后一次 Dispatch 和 backward 第一次 all-to-all 没有下游计算可 hide；这意味着 88.4% 是实现上能达到的上限而非理论上限，当 EP 规模进一步放大、单次通信超过一层计算时，收益会被边界项反噬。论文没有给出模型 `T_comm / T_layer` 何时转为 bottleneck 的 break-even 分析。
5. **MBPP+ 做早停指标过于 ad-hoc**。用一个评估集监控蒸馏训练稳定性，本身就把测试集信息泄露进训练决策；更稳的选择应当是留出 held-out 生成集或困惑度监控。论文的"patience 20 × 1000 steps"设置也缺乏敏感性分析。
6. **实验硬件局限在 AMD 生态**。MI325X / MI300X、ROCm、400 Gbps，与 H100 NVLink + IB 的行为曲线不同 —— NVIDIA 上 NCCL all-to-all 的有效带宽与 SM 占用特征不同，是否能复现 88%+ overlap 是开放问题。另外 vLLM 主线长期优化以 CUDA 为主，FarSkip 对 HIP graph 的依赖让结果不易独立验证。
7. **"架构等价"的不对称性**。论文一直把 FarSkip 说成 "connectivity modification"，但 FarSkip 实际上改变了模型的计算图语义：layer k 看到的不再是 layer k−1 的完整输出。文本里说"层 k 仍能看到 (k−1)/k 的历史信息"，但这是按 block 数做的平均描述，对于那些强依赖最近一层 refinement 的 circuit（比如某些 attention head 专门跟进前一层 MoE 的输出），损失并不均匀 —— MMLU 偏弱可能与此相关。

## 7. AI Infra / MLSys 视角

这是一篇典型的 **"model-system co-design"** 论文，与 Ladder-Residual、Kraken、AsyncTP 属于同一谱系：**通过轻度破坏前后层的数据依赖，换取通信 overlap 的天窗**。它值得 AI Infra 研究者关注的点：

1. **"partial + outdated 的混用"是可复用模板**。在 attention 用 partial（本 rank 已算好的 shared 部分可用）、在 MoE 用 outdated（等 routed Combine 完成代价太高）是细粒度的权衡。这个模式可以直接迁移到：
   - **Pipeline Parallelism**：把 stage 间的 activation 传递做成 outdated，让下一 stage 先跑上一 micro-batch 的下一 block
   - **CP / SP 的 sequence all-gather**：长序列 attention 的 KV all-gather 如果 outdate 一层，可和当前层 FFN 重叠
   - **Wide-EP decoding 的 KV expert 查找**：large batch 下 gating + dispatch 可以 outdate 到上一个 decode step
2. **Autograd Sequence Number 劫持**是一个鲜见的 PyTorch 框架层技巧。大多数 overlap 工作走 custom `autograd.Function` 路线，本文不用重写 backward 就实现了 topo 重排。**这套 recipe 可以复制到任何"forward 有 overlap 窗口但 backward 默认被 autograd 按 Sequence Number 阻塞"的场景**（例如 FSDP 的 all-gather / reduce-scatter 在 backward 的调度优化）。
3. **Distillation 作为"架构迁移"工具的效率边界**。10B tokens 能恢复 100B+ MoE 的 99% 能力，是个值得做更多 ablation 的信号 —— 如果类似的 "perturb model, re-distill" 可以跨越更多架构修改（稀疏 attention、低秩化、量化 aware fine-tune），可能会成为一类通用技术。值得跟进的研究问题：
   - 何时 self-distillation 能恢复？何时必须 pretrain from scratch？
   - distillation token 数与扰动"强度"之间有无 scaling law？
4. **未解决的跟进方向**：
   - **Multi-block far-skip**：作者把这个留成 future work —— 当 `T_comm > T_layer` 时需要跨两层甚至三层 far-skip，信息损失如何界定？是否需要 routing-aware 的动态选择？
   - **与 kernel-level intra-device overlap 结合**：NanoFlow、FlashInfer 在单卡内做 compute/ memory overlap，FarSkip 做跨卡 overlap，两者理论上正交，叠加收益值得测量
   - **Router-aware far-skip**：MoE 的 token 经过 router 后负载不均，能否按 token 是否 "active 专家全在本 rank" 动态决定 far-skip 策略？
5. **对小团队的操作建议**：想复现或扩展该工作最低成本的切入是"Qwen-3-30B + FCSD + MegatronLM EP8 single-node"；训练成本在 10B tokens × 30B ≈ 数百 GPU-hours。小实验室可以把焦点放在 **distillation recipe 的样本效率** 或 **partial/outdated 切换的理论分析**，不必重做 109B 规模。

---

## 8. 总结

FarSkip-Collective 把 MoE 模型的残差连接改造为"far-skip"结构 —— attention 用 partial 激活、MoE 用 outdated 激活 —— 从而解除 Dispatch / Combine / attention-后 all-reduce 在计算图上的阻塞依赖，配合 FCSD self-distillation 和 MegatronLM + vLLM + SGLang 的工程化实现，在 16B–109B MoE 上以 ≤10B tokens 的 distillation 成本恢复 97.5%–99% 的下游能力，并取得 88% 级别的 all-to-all 重叠率、1.04–1.22× 训练端到端加速以及 18.5% 的 TTFT 加速。论文的主要贡献在于**首次证明"partial/outdated connectivity"方案能扩展到全层改造 + SOTA MoE + 100B 规模**，并给出了不依赖低层 kernel 的框架级实现模板；主要局限在于某些知识密集型 benchmark（MMLU）的硬退化、实验硬件仅限 AMD 生态、以及推理侧成果其实针对 TP all-reduce 而非真正的 EP all-to-all。对 AI Infra 研究者而言，更大的价值是它示范了一条通用路径：**让模型架构为通信重叠让步一点点，再用 distillation 把能力补回来**，这套思想可以复制到 PP、CP、wide-EP decoding 等更多并行场景。
