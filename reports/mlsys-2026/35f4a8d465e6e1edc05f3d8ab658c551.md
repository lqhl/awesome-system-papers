## 一、背景

随着半导体行业对高性能硬件的需求持续增长，Register Transfer Level (RTL) 设计自动化成为加速芯片开发流程的关键环节。LLM 在通用编程任务上表现出色，但在 Hardware Description Language (HDL) 生成方面面临独特挑战：HDL 在预训练语料中占比极低，导致 LLM 的参数化知识严重不足；HDL 需要描述并发硬件行为、满足时序约束、遵守综合要求，这些领域特定语义远超通用编程语言的复杂度。

现有方法分为三类：(1) prompt engineering（如 ParaHDL、AoT），受限于 LLM 本身有限的 HDL 知识；(2) fine-tuning（如 RTLCoder、ChipSeek-R1），需要高昂的数据整理和训练成本；(3) multi-agent 架构（如 MAGE、CoopetitiveV），但存在噪声传播和推理空间受限两大根本缺陷。

---

## 二、要解决的问题

现有 multi-agent HDL 生成框架存在两个关键缺陷：

1. **噪声传播（Noise Propagation）**：线性流水线（如 MAGE）中错误逐层累积，标准 MoA 的逐层聚合也无法避免低质量输出对后续层的污染。缺乏有效的质量过滤机制，系统知识库容易被错误信息腐蚀。

2. **推理空间受限（Constrained Reasoning Space）**：无论是刚性流水线还是无结构辩论式架构，都无法系统地探索 HDL 的广阔设计空间，容易过早收敛到局部最优。所有 agent 都在同一推理路径上操作，缺乏多样化的求解策略。

---

## 三、洞察与设计

**关键洞察**：LLM 对 C++ 和 Python 等高资源语言拥有远比 HDL 丰富的参数化知识，将 specification-to-HDL 的直接翻译分解为 specification → 高级语言代码 → HDL 的两阶段过程，可以充分利用 LLM 在高级语言上的流畅性来弥补其 HDL 知识的不足，同时通过不同中间表示引入结构化多样性。

基于这一洞察，VERIMOA 提出两个协同创新：

**1. Quality-Guided Caching 机制**

- 维护一个全局缓存，存储所有层所有 agent 的中间 HDL 输出及其质量分数
- 后续层的 agent 通过 TopN 操作从全局缓存中选取质量最高的 HDL 代码作为参考，而非仅依赖前一层输出
- 打破了标准 MoA 的级联依赖，从数学上保证质量的单调非递减（最小质量和平均质量均不下降）
- 质量评估采用分层策略：通过仿真验证的满分、语法正确但功能错误的加权扣分、语法错误的规则打分

**2. Multi-Path Generation 策略**

- 每层包含三类 agent：Base agent（直接生成 HDL）、C++ agent、Python agent
- C++ 和 Python agent 执行两阶段生成：Stage 1 从 specification 生成中间语言代码并经语法验证和自修复；Stage 2 将中间代码翻译为 HDL
- 中间代码也有独立的全局缓存和质量评估，质量分数由其生成的 HDL 质量决定
- 三条路径产生结构性差异：Base agent 侧重硬件惯用写法，C++ agent 强调位级控制，Python agent 利用高级表达能力

**整体架构**：L 层 MoA，每层 M 个并行 agent，前 L-1 层为 proposer 层，最后一层为 aggregator。可选地集成 simulator-based self-refinement。

## 四、实现细节

- **仿真器**：使用 Icarus Verilog (iverilog) 进行语法和功能验证
- **质量评估（Algorithm 1）**：三级评估路径——完全正确得满分；语法正确但功能错误按严重性（逻辑错误、综合问题、风格问题）分级扣分；语法错误按模块结构、逻辑关键字、格式化规则打分
- **默认配置**：4 层 proposer + 1 层 aggregator，每层 6 个并行 agent（2 Base + 2 C++ + 2 Python）
- **采样参数**：temperature=0.8，top_p=0.95
- **每个问题采样 10 次**（n=10），用于计算 pass@k 指标
- **中间代码处理**：C++ 和 Python 中间代码经语法检查脚本验证后，由 agent 根据反馈自修复，再翻译为 HDL
- **Agent 配置跨层一致**：所有 proposer 层的 agent 配置相同（A_{i,j} = A_{i',j}）
- 代码开源于 GitHub

## 五、实验结果

### 实验设置

- **Benchmark**：VerilogEval 2.0（156 个问题，覆盖组合和时序电路）和 RTLLM 2.0（50 个复杂实际设计任务）
- **评估指标**：Pass@1, Pass@3, Pass@5

### 与非训练方法对比（Table 1）

| 模型 | 方法 | VerilogEval 2.0 Pass@1 | RTLLM 2.0 Pass@1 |
|---|---|---|---|
| Qwen2.5-7B | Direct | 22.90% | 18.99% |
| Qwen2.5-7B | VeriMaAS | 32.81% | 40.33% |
| Qwen2.5-7B | VERIMOA | **56.44%** (+33.54) | **52.07%** (+33.08) |
| Qwen2.5-Coder-32B | Direct | 46.93% | 40.40% |
| Qwen2.5-Coder-32B | VeriMaAS | 56.67% | 55.82% |
| Qwen2.5-Coder-32B | VERIMOA | **73.31%** (+26.38) | **65.49%** (+25.09) |
| GPT-4o | Direct | 64.74% | 52.48% |
| GPT-4o | VeriMaAS | 71.34% | 61.70% |
| GPT-4o | VERIMOA | **84.97%** (+20.23) | **69.17%** (+16.69) |

- VERIMOA + Qwen2.5-7B (56.44%) 超过 VeriMaAS + Qwen2.5-32B (53.57%)，小模型可超越大模型

### 与 Fine-Tuned 模型对比（Table 2）

| 模型 | VerilogEval 2.0 Pass@1 |
|---|---|
| VeriRL-CodeQwen2.5 (7B, fine-tuned) | 66.28% |
| Qwen2.5-Coder-14B + VERIMOA | **66.86%** |
| Qwen2.5-Coder-32B + VERIMOA | **73.31%** |

- 无需训练即可匹配甚至超越 fine-tuned 模型

### Ablation Study

- Q-Cache 是最关键组件：为 Qwen2.5-7B 带来 +11.93 点提升（MoA 28.86% → 40.79%）
- Two-stage 单独加入 MoA 仅提升 +2.60，但叠加 Q-Cache 后提升 +11.27（40.79% → 52.06%），说明 Q-Cache 是 Two-stage 发挥作用的前提
- 宽度（并行多样性）比深度更重要：12 agent 下，2 层×6 宽 (48.5%) > 3 层×4 宽 (47.6%) > 4 层×3 宽 (46.4%)

## 六、批判性分析

1. **计算成本未充分讨论**：4 层 × 6 agent，每层还有两阶段生成和自修复循环，一个问题的总 LLM 调用次数远超直接生成。论文未报告端到端延迟、token 消耗或成本对比，仅以 Pass@1 作为评估维度，回避了实用性问题。对于声称"training-free"的方法，推理成本可能远超一次 fine-tuning 的摊销成本。

2. **"单调质量保证"的理论价值有限**：Equations (14)-(15) 的证明仅依赖于"从更大集合中 TopN 选择不会降低质量"这一平凡事实，本质上是缓存池单调增大的直接推论，并非框架设计带来的质量提升保证。真正关键的问题——每一层是否能生成比已缓存内容更好的新候选——未被证明。

3. **Benchmark 覆盖面窄**：VerilogEval 2.0 和 RTLLM 2.0 规模较小（156 + 50 个问题），且以相对简单的模块级设计为主。论文未展示在大规模、系统级 RTL 设计上的表现，而这才是实际芯片开发的核心场景。

4. **中间表示的有效性缺乏深入分析**：C++ 和 Python 作为中间表示的选择缺乏系统性比较（为何不是 SystemC？Chisel？）。论文未分析哪类电路更适合哪种中间路径，也未给出中间代码到 HDL 翻译的错误类型分布。

5. **Ablation 设计存在混淆**：在比较 Q-Cache 和 Two-stage 的贡献时，Two-stage 本身引入了更多 agent（额外的 C++/Python agent），因此其增益中混入了 agent 数量增加的因素，与纯方法贡献难以分离。

6. **质量评估器的局限性**：Algorithm 1 依赖 testbench 驱动的仿真验证，这要求每个问题都有完整的 golden testbench。在实际 RTL 开发中，testbench 本身的编写是主要工程负担，论文未讨论这一前提假设的实际可行性。

---

## 七、AI Infra / MLSys 视角

1. **Multi-Agent 质量控制的通用范式**：Quality-Guided Caching 的思路——维护全局候选池、按质量排序选择参考——可以直接迁移到 AI Infra 中的其他多 agent 代码生成场景，如 kernel 优化（自动生成 CUDA kernel）、编译器 pass 探索等。关键是定义合适的质量评估函数。

2. **中间表示策略对 LLM-based 编译器的启发**：利用 LLM 在高资源语言上的优势作为中间跳板，这一思路可以应用于 AI 编译器领域——例如用 LLM 先生成 PyTorch/JAX 级别的算子描述，再翻译为 Triton/CUDA kernel，可能比直接生成低级代码更可靠。

3. **值得跟进的方向**：
   - 将 VERIMOA 的框架扩展到 AI 加速器的 HLS (High-Level Synthesis) 流程，用 C++/Python 到 HLS 指令的翻译替代 HDL 生成
   - 探索质量评估器的自动化构建——能否用 LLM 自动生成 testbench，形成自举式的质量反馈闭环
   - 将 width > depth 的经验发现应用于 AI Infra 中的 MoA 搜索策略（如并行探索多种量化方案、多种 operator fusion 策略）

---

## 八、总结

VERIMOA 提出了一个 training-free 的 Mixture-of-Agents 框架用于 HDL 代码生成，通过 quality-guided caching（全局缓存 + 质量排序选择）和 multi-path generation（利用 C++/Python 作为中间表示）两个协同机制，在 VerilogEval 2.0 和 RTLLM 2.0 上实现了 15-30% 的 Pass@1 提升，使小模型（7B）超越大模型（32B）的直接生成，14B 模型匹配 7B fine-tuned 模型。主要局限在于推理计算成本高昂（多层多 agent 多阶段）、benchmark 规模和复杂度有限、以及依赖完整 testbench 的质量评估前提在实际场景中的可行性存疑。
