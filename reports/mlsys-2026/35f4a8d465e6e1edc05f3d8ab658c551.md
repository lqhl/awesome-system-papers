# VeriMoA: A Mixture-of-Agents Framework for Spec-to-HDL Generation

**作者**：Heng Ping, Arijit Bhattacharjee, Peiyu Zhang, Shixuan Li, Wei Yang, Anzhe Cheng, Xiaole Zhang, Jesse Thomason, Ali Jannesari, Nesreen Ahmed, Paul Bogdan

## 1. 背景

随着半导体产业对高性能硬件的需求不断增长,寄存器传输级(RTL)设计自动化成为加速芯片开发流程的关键环节。自然语言规约自动生成 Hardware Description Language(HDL,如 Verilog)可以显著缩短设计周期。大语言模型(LLM)在通用代码生成上已展现出较强能力,因此近两年涌现出大量"LLM for RTL/HDL"方向的工作,大致可分为三条技术路线:

1. **Prompt engineering**:如 ParaHDL、AoT,用任务特化的 prompt 模板或 Chain-of-Thought 激发 LLM 已有的 HDL 知识,训练成本低但受限于模型本身 parametric knowledge。
2. **Fine-tuning / RL**:如 RTLCoder、AutoVCoder、VeriSeek、ChipSeek-R1,在 HDL 数据集上做 SFT 或 RL,精度更高但数据收集和训练开销显著。
3. **Multi-agent / system-level framework**:如 MAGE(线性 pipeline)、CoopetitiveV(多智能体辩论),用训练免费的协作架构来弥补单一 LLM 的推理短板。

本文(VeriMoA)属于第三条线,在 Mixture-of-Agents(MoA, Wang et al. 2024)范式之上改造出一套专门用于 HDL 生成的框架。

---

## 2. 要解决的问题

LLM 做 HDL 生成的本质困难在于两点:一是 HDL(Verilog/VHDL)在预训练语料中占比很小,模型 parametric knowledge 稀薄;二是 HDL 语义特殊(并发行为、时序约束、综合要求),与通用编程语言的思维模式不匹配。

在此背景下,已有的多智能体框架暴露出两个深层缺陷:

1. **噪声传播(noise susceptibility)**。无论是 MAGE 式的线性 pipeline 还是 CoopetitiveV 式的无结构辩论,都缺乏一个系统性的机制过滤低质量中间结果。一旦某一阶段产出了错误的 HDL,下游 agent 只能基于这份"被污染的输入"继续迭代,错误会沿层级级联放大。即便是标准 MoA 的 layer-wise aggregation,也只是部分缓解,并未真正切断级联依赖——每层仍只能看到上一层的输出。
2. **推理空间受限(constrained reasoning space)**。现有方法都是"spec → HDL"的单通道直译,缺乏多条异构推理路径。脆弱的线性结构和混乱的辩论结构都难以系统性地探索 HDL 庞大的设计空间,容易过早收敛到局部最优。

论文的目标:在不额外训练的前提下,同时解决这两个缺陷。

## 3. 洞察与设计

**关键洞察**:

- **洞察一(质量维度)**:MoA 中"每层只看上一层"的刚性依赖是噪声传播的根本原因。如果把所有历史中间结果与其质量分数一起 cache,让更深的 agent 直接按质量挑选参考,就能从架构上保证深层拿到的参考始终 ≥ 浅层,从而打破级联依赖、实现 monotonic knowledge accumulation。
- **洞察二(多样性维度)**:LLM 在 C++ 和 Python 上的 parametric knowledge 远比 HDL 充足,而硬件行为(控制流、数据结构、bit-level 操作)在这些高级语言中也能较好地表达。因此"spec → C++/Python → HDL"的两阶段生成比"spec → HDL"直译更能发挥 LLM 的强项,同时不同中间语言天然引入了推理路径的异构性。
- **洞察三(来自 MoA 性能分解)**:已有实证研究(Li et al. 2025)把 MoA 性能拟合成 $t = \alpha q + \beta d + \gamma$,其中 $\alpha > \beta$,即 proposer 质量对最终性能的贡献大于多样性。因此应当优先强化质量(quality-guided caching),再叠加多样性(multi-path generation)。

**核心设计**(参见 Figure 1 的架构图):

VeriMoA 由 L 层组成,前 L-1 层为 proposer 层,第 L 层为 aggregator。每个 proposer 层并行部署 M 个 agent,agent 有三种类型:Base agent(直接 spec→HDL)、C++ agent(spec→C++→HDL)、Python agent(spec→Python→HDL)。

**(1) Quality-guided caching**。所有 agent 产出的 HDL 都经过质量评估器 Q 打分后存入全局 cache $\mathcal{C} = \{(H_{i,j}, q_{i,j})\}$。质量评估(Algorithm 1)是一个分层打分策略:

- 语法+功能都通过 → $q_\text{perfect}$
- 语法通过但功能失败 → 基础分减去 severe/moderate/minor 三级错误罚分(逻辑错误 > 综合问题 > 风格问题)
- 语法都过不去 → 用规则打分(检查 module/IO 结构、逻辑关键字、格式)做 fallback

从第 2 层起,每个 agent 的 prompt 被增广为 $\mathcal{P}_{i,j} = \mathcal{D} \oplus \mathcal{H}_i^{(n)}$,其中 $\mathcal{H}_i^{(n)} = \text{TopN}(\mathcal{C}_{<i}, n)$ 是来自**所有**之前层的 top-n 高质量 HDL。论文通过 TopN 操作的单调性给出了质量的 monotonic guarantee:

$$\min_{H \in \mathcal{H}_{i+1}^{(n)}} q(H) \geq \min_{H \in \mathcal{H}_i^{(n)}} q(H)$$

平均质量同理非递减。

**(2) Multi-path generation with intermediate representations**。C++ 和 Python agent 把生成拆成两阶段:

- Stage 1: `spec → intermediate code`,先生成 C++/Python 版本的参考实现,做 syntax check 与 self-refine。中间代码也存入对应的 cache $\mathcal{C}_\mathcal{L}$,按"它最终生成 HDL 的质量"反向打分(task-aligned evaluation)。
- Stage 2: `intermediate code + top-n HDL references → HDL`,以精化后的高级代码作为 scaffold 生成 Verilog。

**(3) Optional simulator-based self-refinement**。在 aggregator 层(或任意 proposer 层)可选地引入仿真反馈的 self-refine 环节,进一步打磨最终 HDL。

三种 agent 类型在同一层并行运行、产物共同进入 cache,既保证每层内部的多样性,又通过 cache 让多样性成果在层间保留。

## 4. 实现细节

- **仿真器**:Icarus Verilog(iverilog),轻量、易集成,用作质量评估器的 SyntaxTest/FunctionTest 执行器。
- **LLM 后端**:Qwen2.5 系列(7B / Coder-7B / 14B / Coder-14B / 32B / Coder-32B)、GPT-4o / 4o-mini。采样参数 `temperature=0.8, top_p=0.95`,与 VerilogEval 2.0 保持一致。
- **框架配置**:默认 4 层 proposer + 1 层 aggregator,每层 6 个并行 agent(Base/Cpp/Python 混合),与标准 MoA 配置对齐。
- **质量分数**:Algorithm 1 定义了 $q_\text{perfect}$、$\alpha_\text{severe/moderate/minor}$、$\beta_\text{structure/logic/format}$ 等超参,具体数值论文未给出。
- **TopN/TopK 选择**:HDL cache 取 top-n(n 未明说,代码开源:`https://github.com/hping666/HDL_Generation`),中间代码 cache 取 top-k,分别作为 prompt 补充。
- **Self-refine**:Stage 1 对中间代码做基于 syntax check 的 refine;Stage 2 可选基于仿真反馈的 HDL refine。
- **评测**:Pass@1/3/5,按 `pass@k = E[1 - C(n-c, k)/C(n, k)]`,n=10(per-problem 采样 10 次),benchmark 为 VerilogEval 2.0(156 problems)和 RTLLM 2.0(50 tasks)。

## 5. 实验结果

**RQ1 — 主结果**(Table 1,VerilogEval 2.0 Pass@1,与 non-training baseline 比较):

| LLM | Direct | CoT | HDLCoRe | VeriMaAS | VeriMoA | Δ vs VeriMaAS |
|---|---|---|---|---|---|---|
| Qwen2.5-7B | 22.90 | 26.87 | 30.92 | 32.81 | **56.44** | +23.63 |
| Qwen2.5-Coder-7B | 33.91 | 36.74 | 40.67 | 44.73 | **60.96** | +16.23 |
| Qwen2.5-14B | 39.26 | 41.24 | 45.18 | 48.97 | **65.27** | +16.30 |
| Qwen2.5-Coder-14B | 39.74 | 43.81 | 46.82 | 50.96 | **66.86** | +15.90 |
| Qwen2.5-32B | 46.85 | 48.72 | 51.75 | 53.57 | **71.85** | +18.28 |
| Qwen2.5-Coder-32B | 46.93 | 48.65 | 51.28 | 56.67 | **73.31** | +16.64 |
| GPT-4o-mini | 48.97 | 52.20 | 53.50 | 57.24 | **72.43** | +15.19 |
| GPT-4o | 64.74 | 66.38 | 69.60 | 71.34 | **84.97** | +13.63 |

关键观察:VeriMoA 带来的提升在小模型上最显著(+23 到 +33 Pass@1);Qwen2.5-7B + VeriMoA (56.44%) 甚至超过 VeriMaAS + Qwen2.5-32B (53.57%),即 "7B + 好架构"胜过"32B + 弱架构"。RTLLM 2.0 上呈现相同的趋势,VeriMoA 对 VeriMaAS 有 7–12 点 Pass@1 提升。

**与 fine-tune 模型的对比**(Table 2):Qwen2.5-Coder-32B + VeriMoA 在 VerilogEval 2.0 上达到 73.31% Pass@1,超越所有 fine-tuned 基线(最强为 VeriRL-CodeQwen2.5-7B 的 66.28%)。Coder-14B + VeriMoA 的 66.86% 也已与最强 7B fine-tune 模型持平。

**RQ2 — 消融**(Figure 2):以 Qwen2.5-7B 为例,

- Base: 22.9% → MoA: 28.9% (+6.0)
- MoA + Two-stage: 31.5% (+2.6 over MoA)
- MoA + Q-Cache: 40.9% (+12.0 over MoA)
- MoA + Q-Cache + Two-stage: 52.1% (+11.2 over Q-Cache)
- 全配 + SR: 56.4%

Q-Cache 是主要贡献,且只有在 Q-Cache 存在时 Two-stage 才能发挥完整效益(单独加 Two-stage 仅 +2.6,加在 Q-Cache 之上 +11.2)。这一规律在 8 个 LLM backbone 上一致。

**RQ3 — 参数敏感性**(Figure 3,Qwen2.5-7B 热力图):layer depth × layer width。

- Depth=1 或 Width=1 → 25.5%–39.8%,性能低
- Depth ≥ 3 且 Width ≥ 4 → 47.6%–56.4%
- 等总 agent 数时,加宽度收益大于加深度:12 agents 下,2层×6宽 (48.5%) > 3层×4宽 (47.6%) > 4层×3宽 (46.4%)

**RQ4 — 质量/多样性演化**(Figure 4,LIFObuffer 任务,10 trials 均值):

- 标准 MoA:质量 0.49→0.48(停滞),多样性高 (3.98–5.61),Pass Rate 0%
- MoA + Two-stage:质量 0.55→0.61,Pass Rate 10%
- MoA + Q-Cache:质量 0.50→0.82(单调上升),多样性中等 (3.74–3.97),Pass Rate 50%
- MoA + Q-Cache + Two-stage:质量 0.54→0.93,多样性 4.06–4.84,Pass Rate 80%

数据直接支撑"质量为主、多样性为辅"的设计哲学。

## 6. 批判性分析

- **"Monotonic quality guarantee"只是 top-n 选择的恒等式,不是算法贡献**。论文公式 (14)(15) 的证明本质上是"从更大集合里选 top-n 的最小值/均值不会更差"——这是 TopN 操作的平凡性质,并不需要复杂机制就能达成。真正决定系统性能的是 *top-n 的绝对值*能否随层数提升,而这取决于(a)质量评估器的准确度,(b)agent 是否真的能基于高质量参考产出更好的 HDL。论文给了 Figure 4 LIFObuffer 的实验观察(0.54→0.93),但只展示了一个任务,缺乏更广泛的 quality-over-depth 曲线统计。
- **质量评估器依赖 testbench,但这恰恰意味着"训练-评测数据泄漏风险"**。Algorithm 1 的 `FunctionTest(H, T, S)` 直接用 golden testbench T 打分——也就是说在生成阶段就用了评测目标做反馈。这并非 fine-tuning 那种权重层面的泄漏,但架构上把 oracle 信号嵌入了生成循环,本质是一种"testbench-guided search"。与之对比,fine-tune 的 VeriRL 在训练时用 testbench,推理时不用;VeriMoA 则在推理时也持续调用 testbench。因此 73.31% vs VeriRL 66.28% 的比较并不完全公平——如果评估场景里 testbench 不可得(真实设计早期常常如此),VeriMoA 只能退化到 syntax + 规则 fallback 路径。论文未单独报告"无 testbench 模式"的性能。
- **计算成本完全没报告**。默认配置 4 层 × 6 agents = 24 个 proposer agent,加上 aggregator、两阶段(C++/Python 中间代码生成和 refine)、每层做仿真打分,单个 HDL 问题的 token 消耗和 wall-clock 时间比 Direct 高出 1–2 个数量级(粗估 20–50×)。论文只字未提 cost-performance tradeoff,也没给"同 budget 下 VeriMoA vs 单模型 N 次采样"的 Best-of-N 基线。很可能 Qwen2.5-7B 直接采 50 次取 best 也能接近 VeriMoA 的数字,但这个对照缺失。
- **"小模型 + VeriMoA 超过大模型 + VeriMaAS"的叙事有混淆变量**。Qwen2.5-7B + VeriMoA (56.44%) > VeriMaAS + 32B (53.57%) 的比较中,VeriMaAS 是否也用了 testbench 反馈、采样次数是否可比,论文没讲清。更公平的对照应当是"Qwen2.5-7B + VeriMoA vs Qwen2.5-32B + VeriMoA",但这组数据(65.27% vs 71.85%)显示相同框架下大模型仍明显更强,提示框架增益与模型规模并不冲突。
- **Width > Depth 的结论与单调质量论互相打架**。RQ3 里 2层×6宽 的 48.5% 超过 4层×3宽 的 46.4%;但论文理论分析的重点是"深度越深质量越高(monotonic)"。如果深度真的带来稳定质量积累,4 层应当明显胜出,至少在同宽下是这样。实验显示 4层×6宽(56.4%)相比 3层×6宽(53.2%)的边际收益已经很小(+3.2),说明质量的 monotonic 其实很快饱和。这与理论部分"layer 越深质量越好"的叙述存在张力。
- **Figure 4 只挑了一个任务(LIFObuffer)来展示质量演化**,无法排除"cherry-picking"。论文缺一张跨数据集的平均质量曲线。
- **Intermediate code 的 task-aligned 打分存在循环依赖**。中间代码 C++/Python 的质量分 $q_{i,j}^\mathcal{L} = q(H_{i,j}^\mathcal{L})$ 用的是它"生成出的 HDL 的质量",也就是说要先走完 Stage 2 才能给 Stage 1 打分。这使得第一层的 C++/Python agent 需要额外的调用开销,也让 cache 的增长速度加倍——但论文没有讨论这部分额外成本。
- **Qwen2.5-Coder-14B + VeriMoA 在 RTLLM 2.0 的 Pass@5 (66.22%) 比 7B + VeriMoA (66.24%) 还略低**,这一反常点在论文中未解释,也未触发对"框架是否对某些模型 plateau"的讨论。

## 7. AI Infra / MLSys 视角

这篇论文属于典型的"LLM agent 框架 + 领域应用"工作,对 AI Infra / MLSys 研究者的借鉴价值主要在**系统层的 agent orchestration 范式**上,而不在 HDL 领域本身:

1. **"Global cache + quality-guided routing"是一种可复用的 agent 架构模式**。把每个 agent 调用的中间结果都持久化到 cache,按质量分排序后供后续 agent 选择,本质上把 agent pipeline 从"DAG 拓扑依赖"解耦为"数据池 + 动态选择"。这个模式可以直接迁移到其他 multi-step 推理场景:代码修复、SQL 生成、定理证明、多跳 RAG,只要下游任务能给出可执行的 quality oracle(编译器、测试用例、形式验证器、BLEU)。对 AI Infra 从业者而言,这给了一个具象的 agent framework 抽象,比"prompt chain"更 system-friendly。

2. **"高资源语言做中间表示"是对 LLM knowledge gap 的通用补救策略**。LLM 对 CUDA kernel、OpenCL、MLIR、TVM DSL、SQL 方言、XLA HLO 这类 low-resource 语言的 parametric knowledge 都很薄,同样的"先用 C++/Python 打草稿、再翻译到目标 DSL"的两阶段模式完全可以借鉴。一个具体的 MLSys 研究方向:**spec → Python → Triton/CUDA kernel**,用 PyTorch-eager 作为 reference implementation,Triton 作为目标,quality oracle 用 numerical equivalence + benchmarking。这类比 VeriMoA 更贴近 AI Infra 的生产需求(自动生成高效算子)。

3. **Quality oracle 设计的启示**。Algorithm 1 的分层打分策略(perfect / partial / syntax-fail)对 AI Infra 里"用 LLM 生成系统代码"的质量评估很有参考意义:在 binary pass/fail 之外引入 severity-weighted penalty,能让 cache 在早期层次也积累出有区分度的 partial credit 信号,避免"大部分初始样本都是 0 分、选择无意义"的冷启动问题。这个思路在 LLM-assisted kernel tuning、配置搜索、pipeline placement 等场景下都适用。

4. **潜在的后续工作方向**:
   - **Cost-aware agent framework**:给 VeriMoA 加上 cost budget,把 "第 i 层是否再调用 agent"做成学习或 bandit 问题,在同 token 预算下对比 Best-of-N sampling。这是当前 multi-agent 研究普遍缺的一块。
   - **Agent specialization via cache routing**:把 Base/C++/Python 泛化为"根据 cache 中当前主要错误模式动态选择特化 agent",例如见到时序错误调用"时序 agent",见到宽度 mismatch 调用"类型 agent"。
   - **扩展到 ML kernel 生成**:用完全相同的架构做 Triton kernel、TVM schedule、Halide program 的自动生成,quality oracle 用 correctness + throughput。
   - **理论层面**:论文给的 monotonic guarantee 过于平凡,更有价值的问题是"在 quality estimator 有噪声的情况下,top-n 选择与真正最优 solution 的 gap 如何刻画"——这是一个典型的 noisy ranking / best-arm identification 问题,可以用 bandit 理论给出更有信息量的 bound。

对小 lab 来说最具性价比的切入点是第 2 和第 3 条:在 kernel/DSL 生成场景复刻 VeriMoA 的架构,核心代码量不大(一个 cache + 一个 scheduler + 几个 prompt 模板),配上 PyTorch-Triton 这种天然带 oracle 的 benchmark,很容易做出有说服力的数字。

## 8. 总结

VeriMoA 在 Mixture-of-Agents 范式之上加入两项关键机制——**quality-guided global caching** 和 **multi-path (C++/Python) intermediate representations**——将 spec-to-HDL 生成的 Pass@1 在 8 个 LLM backbone 上提升 15–30 点,让 7B 级小模型匹敌 32B 级大模型,让无训练框架超越 fine-tuned 专用模型。核心贡献是把"多 agent 如何不被噪声淹没、如何避免推理空间坍缩"这两个在 multi-agent 领域普遍存在的问题,用一个干净的"cache + 质量打分 + 多路径"结构回答了。

适用场景:任何带有**可执行 quality oracle**(testbench、编译器、numerical check)的代码/程序生成任务——HDL 只是其中一个典型 instance,迁移到 kernel DSL、SQL、定理证明都顺理成章。

主要局限:(1) 推理阶段重度依赖 golden testbench,在 testbench 不可得的真实早期设计场景下优势会大幅缩水;(2) 计算成本是 Direct 的 20–50×,论文未报告 cost-performance tradeoff,也未给 Best-of-N 对照;(3) 理论"单调质量保证"部分是 TopN 操作的平凡性质,真正影响效果的是 quality estimator 准确度,这方面的实证支持偏弱。整体而言这是一篇工程上扎实、叙事清晰、但理论深度和 cost 透明度有提升空间的应用研究论文。
