# Hawkeye: Reproducing GPU-Level Non-Determinism

**作者**：Erez Badash (Pearl Research Labs), Dan Boneh (Stanford University), Ilan Komargodski (Pearl Research Labs), Megha Srivastava (Stanford University)
**会议**：MLSys 2026
**链接**：[GitHub](https://github.com/badasherez/gpu-simulator)

---

## 一、背景

随着大语言模型和深度学习的快速发展，ML-as-a-Service 成为主流模式——用户将模型训练和推理任务外包给云服务商（如 AWS SageMaker、Google Vertex AI、Azure ML）。然而，用户无法验证服务商是否忠实执行了约定的计算：服务商可能偷工减料（减少训练步数）、替换为更小的模型，甚至植入后门。

可验证机器学习（Verifiable ML）旨在解决这一信任问题，但其核心前提是计算的确定性——给定相同输入，必须产生相同输出。然而 GPU 上的浮点运算天然具有非确定性：浮点加法的非结合性、Tensor Core 内部未公开的累加顺序、舍入策略和 subnormal 数处理方式等，都导致同一计算在不同 GPU（甚至同一 GPU 的不同执行）上可能产生不同的 bit-level 结果。

---

## 二、要解决的问题

1. **GPU Tensor Core 的数值行为不透明**：NVIDIA Tensor Core 是 ML 工作负载的核心计算单元，但其内部累加顺序、舍入模式、中间精度等实现细节未被完整文档化，导致无法在 CPU 上精确复现其计算结果。

2. **现有可验证 ML 方案代价高昂**：
   - 强制确定性执行（禁用非确定性特性）会带来显著性能下降；
   - 基于舍入决策记录的方案（如 Srivastava et al., 2024）存储开销巨大；
   - 基于密码学的验证方案（ZK-SNARKs 等）需要计算是确定性的，无法直接应用于非确定性 GPU 计算。

3. **启发式容差方法不可靠**：现有一些方法假设不同硬件间的数值差异"足够小"可以忽略，但缺乏形式化保证，在对抗性场景下可能被恶意利用。

---

## 三、洞察与设计

**关键洞察**：虽然 NVIDIA Tensor Core 的内部实现未公开文档，但其数值行为是确定性的——对于给定的架构和精度类型，Tensor Core 的累加顺序、内部精度、舍入模式等都是固定的硬件逻辑，可以通过精心设计的探测测试逆向工程出来，从而在 CPU 上实现 bit-exact 复现。

Hawkeye 的核心设计是一套系统化的 **黑盒探测测试（targeted tests）**，通过构造特殊矩阵输入来逐项揭示 Tensor Core 的内部数值行为：

1. **Summation Dependency and Order Test**：通过穷举搜索计算中性子组（computationally neutral subgroups），恢复 Tensor Core 的累加层次结构。例如发现 Ampere 采用两阶段累加（前 8 个乘积 + 累加器先汇总，再与后 8 个乘积汇总），而 Hopper 采用单阶段 16 路累加。

2. **Internal Precision Detection Test**：通过构造两项相消为零的乘积对，然后引入一个极小项，逐步减小其指数来探测内部累加器的有效精度位数（Ampere FP16 为 24-bit，Hopper 为 25-bit）。

3. **Rounding Mode Detection Test**：通过四组精心设计的测试，排除各种舍入模式，最终确定 Tensor Core 在对齐移位和最终输出时均使用 towards zero（截断）舍入。

4. **Normalization Stage Detection Test**：确定乘积结果在送入累加器前是否进行归一化（发现不归一化，直接传递原始 significand）。

5. **Subnormal Behavior Detection Test**：确定 subnormal 输入的乘积是否被重新归一化（发现不会，保留降低精度的 significand）。

将所有测试结果编码为软件模拟器，即可在 CPU 上精确复现 Tensor Core 的矩阵乘法行为。

## 四、实现细节

- **探测内核**：使用内联 PTX 汇编编写 CUDA kernel，直接调用硬件 MMA 指令（`wmma.mma_sync` → `HMMA` SASS 指令），操作 16×16 tile 粒度的矩阵乘累加。

- **Ampere FP16 恢复的计算流水线**（Algorithm 12-14）：
  - **乘法阶段**：两个 FP16 输入相乘，mantissa 左移 3 位扩展到内部精度（≈FP32），不进行中间归一化。
  - **分组累加阶段**：以 towards zero 截断方式对齐指数，先将累加器 C 和前 8 个乘积求和为 G₁，再将 G₁ 与后 8 个乘积求和为 G₂。
  - **输出阶段**：最终结果归一化并截断到 FP32 精度输出。

- **架构差异**：
  - Ampere：两阶段累加（8+8），24-bit 内部精度
  - Hopper：单阶段 16 路累加，25-bit 内部精度
  - Lovelace：与 Ampere 结构一致

- **BF16 特殊处理**：由于 BF16 指数范围更大，需额外处理中间值超出 FP32 范围的情况（临时允许溢出，最终饱和到 ±∞）以及 sub-normal 乘积（最小有效贡献对应指数 2⁻¹⁵⁶）。

- **精度覆盖**：FP16、BF16、FP8 (E4M3)，分别在 Ampere、Hopper、Lovelace 架构上测试。

- **代码开源**：https://github.com/badasherez/gpu-simulator

## 五、实验结果

### Bit-exact 复现率

在所有测试的架构和精度组合上，对 **100,000 个随机生成的 16×16 tile 矩阵乘法**进行验证，实现了 **100% bit-exact 复现**。

### CPU 模拟性能

| 精度 | 架构 | 4096×4096 MatMul 时间 (秒) | 标准差 (秒) |
|------|------|---|---|
| FP16 | Ampere | 50.8 | 3.2 |
| FP16 | Hopper | 47.2 | 2.5 |
| BF16 | Ampere | 52.5 | 2.9 |
| BF16 | Hopper | 48.2 | 2.6 |
| FP8 | Hopper | 40.6 | 0.6 |

（Apple M4 Pro CPU 上测量，10 次独立运行取平均值）

## 六、批判性分析

1. **仅验证了 16×16 tile 级别的矩阵乘法**：实际 ML 工作负载中，cuBLAS/cuDNN 对大矩阵的分块、调度、融合策略同样引入非确定性，Hawkeye 完全未涉及这一层。论文承认需要"additional reverse engineering of implementation details beyond the scope of this work"，但这恰恰是端到端可验证 ML 的核心难题，而非边角问题。

2. **未展示端到端 ML 任务验证**：论文全文没有在任何实际的训练或推理场景上验证 Hawkeye 的有效性。100% 的 16×16 tile 复现率并不意味着能复现一次完整的 transformer forward pass，因为 softmax、LayerNorm、attention mask 等非 MatMul 操作同样存在非确定性。

3. **测试用例的覆盖面有限**：100,000 个随机 16×16 矩阵是否足以覆盖所有 corner case？论文未讨论输入空间的覆盖率，也未尝试针对性的对抗性测试（如全部 subnormal、极端指数差异等边界输入）。

4. **CPU 模拟性能问题被低估**：4096×4096 矩阵乘法需要约 50 秒，而 GPU 上通常在毫秒级完成。对于一次完整的 LLM 推理（包含数千次 MatMul），审计时间可能需要数小时乃至数天。论文以"审计只需执行一次，慢一点可以接受"轻描淡写，但忽略了审计频率和实时性需求。

5. **逆向工程方法的脆弱性**：Hawkeye 的正确性完全依赖于"GPU 硬件行为在同一架构内完全一致"这一假设。如果 NVIDIA 在同一架构的不同 stepping/revision 中微调了数值行为（在工程实践中并非罕见），Hawkeye 的模拟器就会失效。论文未讨论这一风险。

6. **仅覆盖 NVIDIA GPU**：AMD、Intel、Google TPU 等加速器完全未涉及，对于通用可验证 ML 的适用性有限。

## 七、AI Infra / MLSys 视角

1. **对可验证推理服务的启发**：随着 LLM 推理服务成为核心基础设施，"服务商是否真的跑了约定的模型"是一个日益重要的信任问题。Hawkeye 提供了一种不修改 GPU kernel、不引入运行时开销的事后审计路径——虽然目前只到 tile 级别，但方向值得关注。

2. **Tensor Core 内部行为的系统化文档**：论文的核心贡献——揭示 Ampere/Hopper/Lovelace 在 FP16/BF16/FP8 下的累加结构、内部精度、舍入模式——对于理解和优化混合精度训练中的数值稳定性问题有直接参考价值。例如，知道 Ampere 使用截断舍入而非最近偶数舍入，有助于解释某些训练中观察到的 loss spike。

3. **可迁移的逆向工程方法论**：Hawkeye 的五类探测测试（计算中性子组、精度边界探测、舍入模式鉴别等）是通用的黑盒硬件行为分析框架，可以迁移到其他加速器（如 TPU 的 systolic array、AMD CDNA 的 matrix core）的数值行为研究。

4. **值得跟进的方向**：
   - 将 tile 级别的模拟器扩展到 cuBLAS 级别的完整 GEMM，需要逆向 tiling/scheduling 策略；
   - 基于 Hawkeye 的精确模拟器构建高效的密码学证明（ZK-SNARKs for MatMul），消除可验证 ML 的最后一个确定性障碍；
   - 利用 Hawkeye 揭示的内部精度信息优化量化训练策略——例如，既然 Tensor Core 内部累加使用 24-bit（而非完整 FP32），那么基于 FP32 累加假设设计的量化方案可能过于保守。

---

## 八、总结

Hawkeye 通过一套系统化的黑盒探测测试，逆向工程了 NVIDIA Tensor Core 在多种架构（Ampere、Hopper、Lovelace）和精度（FP16、BF16、FP8）下的矩阵乘累加数值行为，包括累加顺序、内部精度、舍入模式和 subnormal 处理方式，并据此构建了 CPU 端模拟器，在 100,000 个随机 16×16 tile 上实现了 100% bit-exact 复现。该工作为可验证 ML 的核心难题——GPU 非确定性——提供了一条可行的解决路径，但目前仅覆盖了 tile 级矩阵乘法，距离端到端的训练/推理验证还有较大的工程和研究鸿沟。
