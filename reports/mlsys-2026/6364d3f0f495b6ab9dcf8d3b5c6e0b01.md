# OSWorld-Human: Benchmarking the Efficiency of Computer-Use Agents

**作者**：Reyna Abhyankar, Qi Qi, Yiying Zhang（University of California, San Diego; Gensee AI, Inc.）
**会议**：MLSys 2026（1st Workshop on Computer-Use Agents at ICML）
**链接**：[arXiv:2506.16042](https://arxiv.org/abs/2506.16042)
**源文件**：[[6364d3f0f495b6ab9dcf8d3b5c6e0b01.pdf]]

---

## 一、背景

计算机使用代理（Computer-Use Agents, CUAs）是利用生成式 AI 模型自主控制计算机系统执行任务的智能体，具备通过 GUI 和 CLI 操作桌面应用的能力。随着 LLM 和 VLM 能力的快速提升，CUA 在准确率上取得了显著进展——商业产品如 OpenAI Operator、Anthropic Claude Computer Use、Google Project Mariner，以及开源项目如 UI-TARS、Agent S2、InfantAgent 等，都在 OSWorld 等基准测试上表现出色。

然而，当前研究几乎完全聚焦于**准确率**提升，忽视了一个关键的实用性瓶颈：**延迟**。一个人类用户几分钟内完成的任务（如更改文档行间距），CUA 可能需要十几分钟，这严重限制了其在实时交互场景中的可用性。

---

## 二、要解决的问题

1. **延迟过高**：CUA 完成任务的端到端延迟远超人类（数十分钟 vs 数分钟），导致实际不可用。
2. **缺乏延迟分析**：现有研究未系统研究 CUA 延迟的来源和分布，无法指导优化方向。
3. **缺少效率基准**：OSWorld 等 benchmark 仅评估任务完成率，没有衡量路径效率的人类参考标准——无法量化"agent 多走了多少弯路"。
4. **评估指标不完善**：现有准确率指标无法同时反映成功率和执行效率。

---

## 三、洞察与设计

**关键洞察**：CUA 的延迟主要来源于 LLM/VLM 调用（规划和反思），而非动作执行或截图，且随着步数增加，每步的 prompt 因包含完整历史而线性增长，导致后续步骤的延迟可达初始步骤的 3 倍。同时，即使最优秀的 agent 也比人类所需步数多 1.4–2.7 倍，说明大量步骤可以被避免。

基于这一洞察，作者提出两条优化方向：
1. **减少每步 LLM 调用延迟**：规划和反思占总延迟的 75%–94%，是优化的核心目标。
2. **减少总步数**：通过动作分组（action grouping）等方式，将多个可连续执行的操作合并为一步，减少 LLM 调用次数。

**OSWorld-Human 数据集构建**：
- 对 OSWorld 全部 369 个任务手动标注人类最优轨迹（ground-truth trajectory）
- 提供两种粒度：单动作轨迹（single-action）和分组动作轨迹（grouped-action）
- 分组规则：在同一视觉观测下可连续执行的动作归为一组

**Weighted Efficiency Score (WES) 指标**：
- WES⁺：成功任务按效率加权（t_exp / t_actual），范围 [0, 1]，越高越好
- WES⁻：失败任务按消耗步数占比惩罚（-t_actual / S），范围 [-1, 0]，越接近 0 越好
- 综合反映 agent 的准确率和路径效率

---

## 四、实现细节

**延迟分析实验**：
- 使用 Agent S2 框架，以 GPT-4.1 作为规划/反思/检索模型，UI-TARS-7B-DPO 作为 grounding 模型
- Grounding 模型托管在单张 NVIDIA A6000 GPU 上，使用 SGLang 推理引擎
- 在 OSWorld 37 个任务子集上收集详细的逐步时间和 token 跟踪数据

**步骤分类**：每步分为信息检索（retrieval）、步骤规划（planning）、动作定位（grounding）、动作执行（action）、截图（screenshot）、反思（reflection）六个阶段。

**感知方式对比**：对比了截图（SS）、Accessibility Tree（A11y）、Set-of-Marks（SoM）三种感知方式对延迟和步数的影响。

**OSWorld-Human 构建**：
- 两位计算机科学研究生两轮标注 + 交叉验证
- 在 OSWorld 虚拟机环境中实际执行验证每条轨迹
- 避免使用脚本等非普通用户手段，但允许键盘快捷键

---

## 五、实验结果

### 延迟分析（Agent S2, 37 任务子集）

| 阶段 | 占总延迟比例 |
|------|------------|
| 规划 + 反思 | 75%–94% |
| Grounding | 3.1%–6.1% |
| 检索 | 0.7%–8.9% |
| 截图 + 动作执行 | < 5% |

- 后期步骤的 LLM 调用延迟可达早期的 **3 倍**，因 prompt 包含完整历史记录
- 加入 A11y Tree 大幅增加延迟（树生成 3–26 秒 + 每步额外数千 token）
- Set-of-Marks 整体能减少步数，但效果因应用而异

### WES 评估（16 个 CUA，全部 369 任务）

| 系统 | 最大步数 | OSWorld 原始准确率 | Single WES⁺ | Grouped WES⁺ | WES⁻ |
|------|---------|-------------------|------------|--------------|------|
| Agent S2 w/ Gemini 2.5 | 50 | 41.4% | 28.2% | 17.4% | -0.26 |
| UI-TARS-1.5 | 100 | 42.5% | 23.7% | 14.3% | -0.22 |
| Agent S2 w/ Claude 3.7 | 50 | 34.5% | 20.0% | 11.4% | -0.42 |
| InfantAgent | 50 | 35.3% | 13.3% | 8.2% | -0.22 |
| UI-TARS-72B-DPO | 50 | 24.6% | 15.6% | 10.6% | -0.16 |

- 最好的 agent（OSWorld 42.5%）在 grouped WES⁺ 上仅 17.4%，效率大幅下降
- 领先 agent 的步数是人类的 **1.4–2.7 倍**

## 六、批判性分析

1. **延迟分析的代表性存疑**：仅用 Agent S2 一个系统、37 个任务（10% 子集）进行延迟分析，虽然论文声称架构具有代表性，但不同系统的 prompt 策略、历史压缩方式、模型选择差异显著，结论的泛化性有待验证。

2. **人类轨迹的"最优"定义模糊**：论文声称标注"最小人类感知步数"，但由两位研究生完成，存在主观性。不同操作习惯、快捷键熟练度会显著影响步数。此外，"grouped action"的分组标准（同一截图下可执行）过于理想化——人类实际操作中也需要视觉确认中间状态。

3. **WES 指标设计的局限**：WES⁺ 将效率简单定义为步数比，但不同步骤的复杂度差异巨大。一个"聪明但慢"的步骤（如一步完成复杂操作）与多个简单步骤在 WES 中被等价对待。WES⁻ 对不同 S 值的 agent 使用不同基数，跨系统比较的公平性存疑。

4. **忽视延迟优化的已有方法**：论文未讨论 prompt 压缩、KV cache 优化、历史摘要等已有的减少 LLM 调用延迟的技术方案，也未进行任何消融实验验证这些方向的潜力。

5. **"感知方式"实验设计不充分**：每应用仅采样一个任务比较 SS/A11y/SoM，样本量过小，结论（"A11y 增加延迟但有时减少步数"）缺乏统计显著性。

6. **论文定位偏低**：本质上是一个 benchmark + 初步分析，核心贡献是人工标注的轨迹数据集和一个新指标。缺乏任何优化方案的探索或验证，实际推动领域发展的力度有限。

## 七、AI Infra / MLSys 视角

1. **LLM 推理延迟是 CUA 的核心瓶颈**：规划和反思的 LLM 调用占 75%–94% 的延迟，且因 prompt 包含完整历史而随步数线性增长。这直接指向几个 AI Infra 方向：
   - **增量 prefill / prompt caching**：CUA 的 prompt 在步间高度重叠（仅新增一步的截图和反思），非常适合 KV cache 复用（如 SGLang RadixAttention、vLLM prefix caching）。论文未做此优化，潜在收益显著。
   - **长上下文推理优化**：CUA prompt 在 50 步后可达 14K+ token，是长上下文推理的典型场景，稀疏注意力、prompt 压缩等技术可直接应用。

2. **多模型协同的推理调度**：CUA 系统典型地使用大模型（规划/反思）+ 小模型（grounding）的组合，大模型是瓶颈。这提示了异构模型 serving 的调度优化空间——如何在同一推理集群中高效协调不同规模模型的请求。

3. **Token 效率优化**：论文数据显示 prompt token 是延迟的主要驱动力。探索视觉 token 压缩（减少截图的 token 开销）、历史摘要（用摘要替代完整历史）等方向，可以在不显著牺牲准确率的前提下大幅降低延迟。

4. **可操作的 future work**：
   - 在 Agent S2 等框架中集成 prompt caching，量化端到端延迟降低
   - 设计自适应历史窗口策略（滑动窗口 vs 摘要），平衡准确率与延迟
   - 将 action grouping 从人工标注扩展为模型自动预测，训练"多动作输出"的规划模型

---

## 八、总结

本文首次系统研究了计算机使用代理的延迟问题，通过对 Agent S2 的详细逐步分析揭示了 LLM 调用（规划和反思）是端到端延迟的绝对主因（75%–94%），且 prompt 历史积累导致后期步骤延迟急剧增长。作者构建了 OSWorld-Human 数据集（369 个任务的人类最优轨迹）和 WES 效率指标，评估 16 个 CUA 发现最优 agent 仍比人类多走 1.4–2.7 倍步数。论文的核心价值在于明确了 CUA 延迟的来源和量化了效率差距，但缺乏优化方案的探索，更多是一个问题诊断和 benchmark 贡献。
