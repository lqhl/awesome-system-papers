# MixLLM: LLM Quantization with Global Mixed-precision between Output-features and Highly-efficient System Design

**作者**：Zhen Zheng, Xiaonan Song, Chuanjie Liu
**单位**：Microsoft

**链接**：https://proceedings.mlsys.org/paper_files/paper/2026
**源文件**：[[2723d092b63885e0d7c260cc007e8b9d.pdf]]

---

## 1. 背景

大语言模型(LLM)推理面临显著的内存占用与计算成本压力,量化(quantization)是当前最主流的压缩方案。后训练量化(PTQ)按目标的不同可分为三类:

- **Weight-only**:仅量化权重(如 GPTQ、AWQ),主要解决小批量 decoding 阶段的 memory-wall 问题。但 4-bit 权重在 Llama 3 等高信息密度模型上精度损失明显;且当 batch 较大时,反量化开销反而拖慢 MatMul,SOTA W4A16 kernel 在 batch 512、hidden 4096 配置下只能达到 float16 的 83% 性能。
- **Weight-activation**:同时量化权重和激活(SmoothQuant、QuaRot、QoQ),可以利用低位 Tensor Core 提升计算吞吐。但激活通常比权重更难量化,精度损失更大;同时 group-wise 反量化会引入额外的 I2F(int-to-float)开销。
- **Outlier separation / mixed-precision**:对高显著性元素保留高精度。Atom 等 SOTA mixed-precision 方案采用 input-feature 维度上的混精,且每层局部决定 outlier,系统效率与精度都未达到理想点。

作者把"精度 — 内存占用 — 系统效率"概括为"effectiveness triangle",并指出现有方案都只覆盖了其中两条边。

---

## 2. 要解决的问题

如何在以下三个维度同时取得 SOTA?

1. **精度**:在 4-bit 量级下,weight-only 与 weight-activation 方法都仍然与 float16 baseline 有可见差距(典型 PPL 抬升 0.5+),特别是在 Llama 3 系列等信息密度高的新模型上。
2. **内存**:推理服务希望权重尽可能小,但保留过多 outlier(SpQR、SqueezeLLM 用 fp16 存储 outlier)会破坏存储紧凑性,且产生稀疏 MatMul 的低效问题。
3. **系统效率**:在 continuous batching / chunked-prefill 下,LLM MatMul 趋于 compute-bound,需要让低位计算真正命中 int8 Tensor Core(624 TOPS),而不是因为反量化路径回退到 SIMT Core(19.5 TFLOPS)的反量化操作上。

具体子问题包括:(a) 如何识别哪些权重元素值得保留高精度;(b) 在 group-wise + asymmetric 配置下如何用上 int8 Tensor Core(QoQ 走两步量化,Atom 干脆放弃 asymmetric);(c) 如何把 SIMT Core 的 I2F 开销降到与 Tensor Core MatMul 重叠后接近为零。

## 3. 洞察与设计

**关键洞察**:

1. **不同 output channel 对模型最终 loss 的贡献差异极大,且这种差异只能在"全局"视角下识别**。在 Llama 3.1 8B 中,全局取 top 10% 显著性 channel 后,v_proj 平均有 71.22% 的 channel 落入 top 10%,而 gate_proj 只有 0.73%(Tab.4)。任何"每层固定百分比"的局部策略都会错配。
2. **混精在 output-feature 维度上是 disjoint sub-problem**:不同 output channel 的 MatMul 结果天然独立,可以拆成两个不同 bit-width 的子 MatMul 并行,再 fused scatter 拼回。这一性质让混精的 system 实现比 input-feature 维度上的 Atom 更友好。
3. **MatMul 计算强度对权重位宽更敏感**:给定 M=512,N=K=4096,把权重从 8-bit 降到 4-bit 可让 compute intensity 上升 80%,而把激活从 8-bit 降到 4-bit 只贡献 5.88%。因此激活 8-bit + 权重 4-bit 是更好的"系统/精度"折中点。
4. **存在一段 int32 的连续区间,其位模式可被解释为对应 float32 值**(Fig.3)。利用 0x4b400000 作为 bias,可以把昂贵的 I2F 指令替换为两条 add/sub,并把 int 减法 fuse 进 Tensor Core 的 mma 累加器。

**核心设计**:

- **Output-feature 维度的全局混精**(Fig.1 左半):离线阶段按 salience 全局排序所有 linear 层的 output channel,前 N 个用 8-bit、其余用 4-bit。两类权重做 memory-interleave 预打包,生成两个独立的子权重张量。
- **Global precision search**:用一阶 + 近似二阶(Fisher 信息矩阵代替 Hessian)的 Taylor 展开估计每个 channel 量化前后的 loss 距离 \(S_c = |g^T(c_q - c_0) + \frac{1}{2}(g^T(c_q - c_0))^2|\)。与多数现有工作不同,本文**保留一阶项**,因为对预训练好的模型 g 很小、二阶项是一阶项平方的一半,一阶项实际可能更显著。
- **量化配置 sweet spot**:8-bit symmetric 激活 + 4-bit asymmetric 权重,group_size = 128。对称 8-bit 提供精度,asymmetric 4-bit 拟合非对称分布,group-wise 控制 chunk scale。
- **Two-step dequantization**:在 W4A8 的 \((W_q - z) \cdot s_w \cdot A_q \cdot s_a\) 中,先做 \((W_q - z)\) 这一步整数减法(int8 不溢出),用 int8 Tensor Core 算 \((W_q - z) A_q\),最后才乘 \(s_a s_w\)。这样既保留了 asymmetric 的精度收益,又能命中 int8 Tensor Core。
- **Fast I2F**:利用 0x4b400000 偏置把 I2F 转化为"先在累加器初始化时加上 bias_int → MMA 累加 → 末尾减去 bias_fp",即"消失的 I2F"。在 A100 上单 MatMul 提速 20+ TOPS。
- **End-to-end software pipeline**(Fig.4):引入 quantization group tile,叠加在 warp tile / block tile 之上;register 上维护两个 buffer,一个 group 级累加(可 apply per-group scale),一个 global 级累加。把 G2S(global→shared)、S2R(shared→register)、SIMT 反量化、Tensor Core MMA 充分流水化。

## 4. 实现细节

- **预打包**:权重在 ahead-of-time 阶段按内存交错(memory-interleave)布局,运行时无 permutation 开销。4-bit 与 8-bit 子张量分别打包。
- **两子问题并行**:用 CUDA Graph 同时调度两个不同 bit-width 的 MatMul kernel;通过 fused epilogue scatter 把结果按 channel index 写回同一输出张量,几乎零额外开销。
- **vsub4 矢量减法**:每条指令完成 4 个 int8 的 \(W_q - z\) 减法。
- **Salience 搜索算法**(Algorithm 1):一次性扫所有层、对每个 channel 计算 \(S\) 然后全局排序,前 N 给 8-bit。本文证明 one-pass 与 progressive iterative search 在结果上几乎相同,但耗时少 4 倍以上(7B/8B 7 分钟 vs 30 分钟)。
- **整体集成**:GPTQ 与 clip search 可以独立作用在 4-bit 与 8-bit 两个 disjoint 子问题上,作为正交优化叠加。
- **平台**:NVIDIA A100 (80G),CUDA 12.1,PyTorch 2.4.1,transformers 4.45.2。

## 5. 实验结果

**模型/数据集**:Llama 3.1 8B/70B、Llama 3.2 1B、Qwen2.5 0.5B/1.5B/7B/32B、Mistral 7B v0.3。Calibration 用 wikitext2(MixLLM/GPTQ)128 样本 × 2048 token。

**Perplexity (Tab.1)** —— 节选 wikitext2 / c4:

| 方法 | Llama 3.1 8B | Llama 3.1 70B | Mistral 7B v0.3 |
|---|---|---|---|
| float16 | 6.24 / 8.95 | 2.81 / 6.68 | 5.32 / 7.84 |
| RTN W4A16 | 6.82 / 9.72 | 3.55 / 7.43 | 5.51 / 8.04 |
| GPTQ W4A16 | 6.52 / 9.55 | Abn / Abn | 5.49 / 8.19 |
| AWQ W4A16 | 6.65 / 9.48 | 3.28 / 6.96 | 5.44 / 7.98 |
| SmoothQuant W8A8 | 6.34 / 9.08 | 2.92 / 6.77 | 5.35 / 7.88 |
| QoQ W4A8 | 6.64 / 9.49 | 3.49 / 7.07 | 5.44 / 7.98 |
| QuaRot W4A4 | 8.34 / 11.95 | 6.16 / 9.91 | 5.83 / 8.50 |
| **MixLLM W4.4A8 (p10)** | **6.42 / 9.33** | **3.02 / 6.83** | **5.36 / 7.93** |
| MixLLM W8A8 (p100) | 6.25 / 8.97 | 2.81 / 6.68 | 5.32 / 7.84 |

W4.4A8 在仅多 10% 比特预算下,把 Llama 3.1 70B 的 PPL 抬升从 SOTA 的 ~0.5 压到 < 0.2。W8A8 几乎无损。

**Downstream tasks (Tab.3,3 个 7B 量级模型平均)**:MixLLM W4.4A8 在 MMLU-Pro 上 34.53,优于 QoQ W4A8 (32.84)、QuaRot W4A8 (33.60),平均提升 0.93;BBH 48.17 vs QoQ 45.78。

**System (Fig.5,A100,in/out=4096/4096)**:

| 配置 | vs FP16 平均加速 | vs W4A16 SOTA 平均加速 | vs QoQ |
|---|---|---|---|
| MixLLM W4A8 | 1.90× | 1.26× | 0.99× |
| MixLLM W8A8 | 2.75× | 1.78× | 1.39× |

**Ablation (Fig.6)**:从 RTN W4A4 PPL=744 起步,逐项叠加得到收益最大的几步是:(a) 激活转 8-bit + 权重对称 → 9.867;(b) 权重 asymmetric + group128 → 6.937;(c) 加 10% 8-bit (diagonal Fisher) → 6.830;(d) 升级到 blocked Fisher + 一阶项 → 6.496;(e) GPTQ + clip 微调到 6.420。

**搜索开销 (Tab.5)**:7B/8B 单 A100 7 min;70B 4×A100 55 min。

## 6. 批判性分析

**值得审视的点**:

- **大 batch 下系统优势衰减**。Fig.5 上 token≥256 时 MixLLM W4.4A8 相对 W4A16 几乎只剩持平,W8A8 也回落到 ~1.5× 量级。论文摘要里"SOTA system efficiency"的口号主要由 token<32 区间撑起,与生产推理服务希望的高吞吐场景并不完全对齐。
- **与 QoQ 在系统侧实质打平**。表里 MixLLM W4A8 vs QoQ W4A8 是 0.99× 加速,W8A8 vs QoQ 1.39× 在意料之中(后者就不是 W8A8)。论文用"better accuracy than QoQ"为系统持平兜底,但严格说 W4A8 这一档没有 system 上的胜出。
- **calibration 数据集选择不一致**。MixLLM/GPTQ 用 wikitext2,AWQ/SmoothQuant/QoQ 用 pile,理由是"to enable their better performance",但同时 MixLLM 用 wikitext2 校准、又在 wikitext2 上汇报 PPL,存在 data-dependent 优势嫌疑。C4 上的相对优势更小且对 SmoothQuant 在多个 7B 模型上反而轻度落后(Mistral 7B v0.3:MixLLM W4.4A8 c4 7.93 vs SmoothQuant 7.88)。
- **Salience 估计的近似链条很长**。Hessian → Fisher → 把 cross-sample expectation 拆成 per-sample squared dot product。论文承认"second order factor 是 first order 平方的一半,所以 first order 可能更大",但没给出 first order 占主导比例的实证;ablation 里"+ blocked Fisher and 1st order"一步只把 PPL 从 6.830 降到 6.496,说明这套高阶推导的真实贡献其实有限,大头还是"10% 8-bit + group-wise"本身。
- **70B 模型上 70B 用 4 卡顺序 device_map**,Search 55 min;但论文没说明在 H100 / B200 上的搜索成本与 kernel 加速曲线,A100 单平台数据让"SOTA"覆盖面不够强。
- **MixLLM W4A8 (p0) 在 Llama 3.2 1B 上 PPL 10.36,反而比 RTN W4A16(11.72) 低、和 GPTQ 接近**,这说明"8-bit 激活 + group-wise weight"才是最大功劳,output-feature 混精 (10%→W4.4A8) 边际收益约 0.31 PPL —— 论文标题强调的"global mixed-precision between output features"在小模型上贡献并不突出。
- **缺失 KV cache 量化对比**:为公平把 QoQ/QuaRot 的 KV 量化关掉,但在真实部署中 KV cache 占内存比重大,关掉后比较不能直接外推到端到端推理收益。
- **没有端到端推理(整模型 throughput / latency)实验**,所有 system 数据都是 single linear layer microbenchmark。这正是论文 6 节里批判 weight-only 方案"用微基准代表端到端"时担心的同类问题。

## 7. AI Infra / MLSys 视角

**对 AI Infra 的启发**:

1. **结构化混精的可工程化模式**。Output-feature 维度天然是 disjoint sub-problem,这一点对 attention / FFN 层都成立,且能与 GPTQ、clip search、rotation 等已有 PTQ 技术正交叠加。可以把"全局重要性 + 结构化混精"当作通用 building block 移植到其他场景:KV cache 混精、MoE expert 混精、稀疏 attention head 混精。
2. **Two-step dequantization 范式**。现代低位 kernel 设计在面对"asymmetric + group-wise"时常常被迫放弃 Tensor Core,本文的"先做整数减法再做 MMA、最后 epilogue 乘 scale"是值得复用的招式。同样的拆解可以推广到 W4A4(若能找到合适的 int8 →int4 bridge)。
3. **Fast I2F via bias trick**。利用 IEEE 754 的位模式重叠把 I2F 替换为加法 + 减法,这一招对所有需要"频繁 int↔float 转换"的低位推理 kernel 都适用,例如 FP4/FP6 dequant、稀疏 indexing kernel 中的 indices→float 映射等。
4. **量化决策的"compute intensity 公式驱动"**。\(I = 2MNK / (MK B_{act} + KN B_{weight})\) 这种简洁推导适合做架构权衡时的快速估算,值得在 design doc 阶段常态化使用。

**可跟进的 future work**:

- **从 PTQ 推到 QAT / pre-train aware**:全局 salience 是 training 后的事后估计,如果在 pre-training 末期就让模型适应"output channel 级别的混精",salience 分布是否会更均匀,从而进一步压缩 8-bit 占比?
- **混精 + KV cache + speculative decoding 联合优化**:本文刻意关掉了 KV 量化,但 W4.4A8 + W4-KV / W2-KV 是产品落地必须 co-design 的;以及与 speculative decoding draft model 的混精搭配。
- **Hopper / Blackwell 上的重做**:H100 的 FP8 Tensor Core 与 TMA、B200 的 MX 数据类型,会让"two-step dequant"的最优拆点完全不同。把 MixLLM 的 pipeline 在 sm_90a / sm_100 上重新走一遍是清晰的工程问题。
- **混精搜索的廉价化**:70B 55 min 的开销对快速迭代仍然偏高,能否用一个小 proxy 模型或 layer-wise 重要性的可迁移 prior 把 search cost 降到 < 5 min,且不损失精度?
- **大 batch 体制下的 kernel 调优**:Fig.5 token≥256 后优势消失,值得专门为 prefill / chunked-prefill 大 MatMul 设计另一套 tile schedule(更大的 block tile、更深的 software pipeline 级数)。

---

## 8. 总结

MixLLM 在 output-feature 维度上做"全局显著性 + 结构化混精"的 PTQ,在仅多 10% bit-width 的预算下把 Llama 3.1 70B 的 PPL 抬升从 SOTA 的 0.5 量级压到 0.2 以内,在三类 7B 模型 MMLU-Pro 上平均提升 0.93。系统侧通过 two-step dequantization、fast I2F bias trick 和 group-tile 软件流水,在 A100 上让 W4A8 / W8A8 / W4.4A8 kernel 与 QoQ 持平且全面超越 W4A16 SOTA。论文的核心贡献是"output-feature 混精的 disjoint 性质 + 全局 salience 排序"这一干净抽象,以及一套可以让 group-wise asymmetric 量化命中 int8 Tensor Core 的 kernel 工程模板。主要局限在大 batch 下系统优势衰减、缺乏端到端推理实验、与 QoQ 系统持平,适用场景偏向"对精度极敏感、batch 不大"的生产部署。
