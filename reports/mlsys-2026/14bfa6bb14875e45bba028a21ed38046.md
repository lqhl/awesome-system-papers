# SpecDiff-2: Scaling Diffusion Drafter Alignment for Faster Speculative Decoding

**会议**：MLSys 2026
**链接**：[arXiv:2511.00600](https://arxiv.org/abs/2511.00600)

---

## 一、背景

大语言模型（LLM）的推理加速已成为关键研究方向。随着 test-time compute scaling（如 chain-of-thought 推理）的兴起，模型在推理阶段需要生成更长的 token 序列，导致 wall-time latency 显著增加。Speculative decoding 是目前最主流的无损加速方案，通过小模型 draft、大模型 verify 的方式实现并行化。然而，现有方法受限于两个根本瓶颈：（1）draft 阶段的自回归依赖限制了并行性；（2）draft 模型与 verify 模型之间的分布不对齐导致大量 token 被拒绝。

---

## 二、要解决的问题

1. **Draft 阶段的串行瓶颈**：传统 AR drafter（如 EAGLE/EAGLE-2）逐 token 生成 draft，draft 延迟与序列长度线性增长，限制了加速上限。
2. **Drafter-verifier 对齐不足**：Diffusion 模型作为 drafter 虽然解决了并行性问题，但其学习的是 token 序列的联合分布（joint distribution），而 AR verifier 评估的是逐位置的条件概率（prefix-conditional next-token posterior），两者在 token 级别上存在根本性的分布差异（miscalibration），导致接受率低。
3. **现有对齐方法不适用于 diffusion drafter**：基于知识蒸馏的 AR drafter 对齐方法（如 DistillSpec）仅优化窗口第一个位置的对齐，无法捕获 diffusion drafter 在整个 draft 窗口内的位置依赖性差异。

---

## 三、洞察与设计

**关键洞察**：Diffusion drafter 的 position-wise acceptance rate 在不同位置上差异显著——AR 风格的蒸馏方法只在靠近 prefix 的早期位置获得较好对齐，后续位置快速退化。因此，必须在整个 draft 窗口上优化对齐，而非仅优化单一位置。同时，diffusion 模型一次 denoising 即可生成所有位置的 marginal 分布，从中可以以几乎零成本采样多条 draft 路径，这为 test-time 选择最优 draft 提供了天然优势。

基于此洞察，SpecDiff-2 提出两个互补的对齐机制：

### 1. Train-time：Streak-distillation
- 不同于传统蒸馏只优化 `α₁(s)`（第一个位置的接受率），streak-distillation 直接优化 `TokensDraft(γ, s)`——即整个 draft 窗口的期望接受 token 数（product-of-accepts 形式）
- 通过 greedy acceptance 代理构造可微目标，使用 verifier P 的 teacher trajectory 作为参考路径，对 diffusion drafter 做梯度上升
- 实验证实 streak-distillation 在后端位置（距 prefix 远的位置）的接受率比 AR-distillation 高 3.2 倍

### 2. Test-time：Self-selection acceptance
- 利用 diffusion 模型的并行特性：一次 denoising 生成 marginals `{q_j}` 后，以近乎零成本独立采样 K 条 draft
- 用 verifier 对 K 条 draft 打分（基于 streak objective 的等价形式），选择期望 throughput 最高的 xmax
- 通过 tree-style attention 高效计算所有 K 条 draft 的 verifier 分数
- 采用 greedy-acceptance 规则验证：`Pr(accept xᵢ) = P(xᵢ|s)`，不需要 drafter 概率，天然支持跨 tokenizer

## 四、实现细节

- **Diffusion drafter**：采用预训练的 masked discrete diffusion language model（MDM），包括 DiffuCoder-7B（Qwen2 tokenizer）和 DiffuLLaMA-7B（LLaMA-2 tokenizer）
- **Denoising 步数**：固定为 T=1（单步 denoising），因为 7B 规模的 drafter 足够强，额外步数收益递减但延迟线性增长
- **Draft 窗口**：DiffuCoder 使用 γ=32，DiffuLLaMA 使用 γ=16
- **Drafter 温度**：T=1.5 作为 self-selection 的最优温度，平衡 draft 质量与多样性
- **Self-selection 并行数**：K=1~8，K 条 draft 的采样与排序可通过 tree-style attention 并行完成
- **Streak-distillation 训练**：≤75 GPU-hours（A100），约 60k gradient steps，在 reasoning corpus 上微调
- **Verifier 模型**：Qwen2.5-72B-Instruct、LLaMA-2-70B-Chat（以及 14B/13B 消融实验）
- **Greedy-acceptance 规则**：验证时仅使用 verifier 概率，不依赖 drafter 概率分布，支持跨 tokenizer 场景

## 六、批判性分析

1. **Drafter 规模的公平性问题**：SpecDiff-2 使用 7B diffusion drafter，而 EAGLE/EAGLE-2 的 drafter 仅约 1B 参数。论文声称 diffusion drafter 的并行特性使得延迟可控，但在 14B verifier 消融实验中已显示 7B drafter "certainly too large to behave as optimal drafters"，DiffuLLaMA 在小 verifier 上甚至无法一致超越 EAGLE-2。这说明 speed-up 优势部分来自 drafter 参数量的代差（7× 更大），而非纯粹的方法论优势。

2. **EAGLE-3 缺失**：论文承认 "the results from the original EAGLE-3 work were not reproducible in our environment"，因此跳过了这个最强 AR baseline。这使得 "state-of-the-art" 的声称缺乏完整支撑——EAGLE-3 同样引入了 training-time 对齐和 test-time tree 优化。

3. **GPQA 场景的收益显著下降**：在 open-ended QA（GPQA）上，SpecDiff-2 的优势大幅收窄（Qwen2.5-72B T=1 时仅 2.65× vs EAGLE-2 的 2.52×），论文将此归因于 "semantic diversity"，但未深入分析。这暗示 diffusion drafter 在分布宽泛的生成任务上对齐效果有限。

4. **Greedy-acceptance 的理论代价被淡化**：论文引入的 greedy-acceptance 规则 `Pr(accept xᵢ) = P(xᵢ|s)` 是一个不同于标准 speculative decoding 接受规则的变体。虽然论文声称仍是 lossless 的（附录有证明），但相较于标准规则，greedy-acceptance 在 drafter 质量较好时可能会拒绝更多 token（因为它不考虑 min(1, p/q) 中 q 较小的情况）。论文没有对比两种 acceptance 规则的实际差异。

5. **Self-selection 的额外 verifier 计算开销**：K 条 draft 都需要 verifier 评估（通过 tree attention），这意味着 verifier 的计算量随 K 增加。论文强调 "negligible sequential overhead"，但实际 FLOPs 和显存开销并非可忽略，尤其在 K=8 时。

6. **评估数据集偏窄**：仅使用 Math-500、HumanEval、GPQA 三个数据集，缺乏对长文本生成、对话、摘要等常见推理场景的评估。

## 七、AI Infra / MLSys 视角

1. **Diffusion model 作为 LLM 推理加速组件的可行性**：SpecDiff-2 首次证明了 diffusion drafter + AR verifier 的异构推理架构可以大幅超越同构 AR drafter 方案。这为推理系统设计开辟了新维度——drafter 不必与 verifier 共享架构范式。

2. **"Acceleration-compute" scaling 概念**：论文提出加速计算量（alignment training + test-time selection）作为一个独立的 scaling axis，与 model scaling 和 data scaling 并列。这对 AI Infra 系统的资源分配策略有启发：在固定 wall-time 预算下，投入更多计算在 drafter 对齐上可以单调提升推理效果。

3. **跨 tokenizer 支持**：Greedy-acceptance 不依赖 drafter 概率，天然支持不同 tokenizer 的 drafter-verifier 组合。这对推理系统中模型复用和混合部署有实际价值。

4. **值得跟进的方向**：
   - **Diffusion drafter 的最优规模 scaling law**：论文指出 7B drafter 在 14B verifier 上已过大，但最优 drafter 规模与 verifier 规模的关系尚未建立
   - **专用硬件 kernel**：缺乏 semi-autoregressive inference 的高效 kernel 和 diffusion draft 场景的 KV cache 支持
   - **多 drafter ensemble**：K 个不同 drafter 分别专注于不同子分布（代码、数学、自然语言），test-time 选择最优——这可以与 MoE 推理系统结合
   - **与 continuous batching 系统的集成**：diffusion drafter 的 batch 特性与 vLLM 等系统的 continuous batching 如何协同是工程落地的关键问题

---

## 八、总结

SpecDiff-2 首次为 diffusion drafter 的 speculative decoding 提出了系统化的对齐方案，通过 train-time 的 streak-distillation（优化整个 draft 窗口的期望接受 streak）和 test-time 的 self-selection acceptance（利用 diffusion 并行采样多条 draft 并选优），在 Math-500、HumanEval 等结构化推理任务上实现了最高 5.5× 的无损加速，平均超越 EAGLE-2 约 30-55%。其核心优势在于 diffusion 模型的天然并行性与针对性的窗口级对齐优化。主要局限在于 drafter 规模较大（7B vs EAGLE 的 ~1B）导致在小 verifier 和开放式生成场景下优势收窄，且缺乏与 EAGLE-3 的完整对比。
