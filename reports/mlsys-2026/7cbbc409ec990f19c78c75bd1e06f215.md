## 1. 背景

大语言模型(LLM)推理效率是当下 AI infra 的关键瓶颈。主流的自回归(AR)Transformer 模型在训练时可通过 teacher forcing 并行,但推理时必须严格逐 token 生成,形成难以摆脱的序列依赖;同时 AR 模型只能单向注意上文,在文本 infilling、编辑、全局规划等任务上存在天然短板。

作为替代范式,**Diffusion Language Models (DLMs)** 借鉴图像/音频/视频生成中的 diffusion 思想,从全 MASK 序列出发通过若干步去噪迭代生成文本,理论上每一步可以并行更新所有位置,具备打破 AR 序列依赖的潜力。闭源的 Gemini Diffusion、Mercury 等已报出相对 AR 最高 10× 的吞吐优势,但开源 DLM(LLaDA、Dream 等)在实际推理中仍远慢于同尺寸 AR 模型,主要卡在两个根本性问题上:

1. **双向注意力与 KV cache 不兼容**:DLM 每步都在对整个序列做 full bidirectional attention,导致标准 KV cache 机制失效,每步都需重新计算所有位置的 K/V
2. **采样步数极多**:为保证生成质量,DLM 通常需要与目标长度 $L_g$ 相当的去噪步数(例如 $L_g = 256$ 就需要 256 步),每步又都是 $O(L^2)$ 注意力,累计开销远超 AR

学界已有若干加速路径:一条是 approximate caching(dLLM-Cache、dKV-Cache)和 block-wise causal 微调(D2F、Fast-dLLM v2)处理 KV cache 问题;另一条是 parallel sampling(Fast-dLLM、entropy-bounded unmasking)减少步数。但两条路径鲜有工作同时打通。而在视觉 diffusion 领域,**consistency models** 已经成功把去噪步数压缩到 few-step 甚至 one-step,这一思想尚未被系统地迁移到离散的语言 diffusion 场景。

---

## 2. 要解决的问题

作者定位要同时攻克开源 DLM 推理的两大核心瓶颈:

- **去噪步数过多**:现有 DLM 在高质量模式下要求 $N = L_g$ 的采样步数,远高于 AR 生成所需步数
- **KV cache 失效**:bidirectional attention 让每步都要重算全序列 K/V,即便步数减少,单步成本也高
- **现有加速工作不完整**:training-free 方法(dLLM-Cache、Fast-dLLM)多只处理一个维度,而训练型方法(D2F)主要针对 KV cache,没有把 consistency 思想引入 DLM 来系统性减少步数

核心研究问题:**能否通过一次 post-training 同时解决步数过多与 KV cache 不兼容两个问题,并在数学与代码推理任务上保持精度?**

---

## 3. 洞察与设计

**关键洞察**:

1. **Consistency 目标能够跨离散 token 轨迹泛化**:虽然 consistency models 最初定义在连续 ODE 轨迹上,但 DLM 逐步 unmask 的过程同样构成一条"去噪轨迹",相邻状态之间的预测应当自洽。如果训练目标让模型在"信息较少的中间状态 $y$"与"block 完成态 $y^\star$"上产生一致的预测,模型就能学会跳过中间步、一次性敲定多个 token
2. **Block-causal mask 并不必然损失 DLM 的局部 bidirectional 能力**:关键的 infill/editing 操作发生在当前正在解码的 block 内,只要 block 内部保持双向注意力、block 之间做 causal 因果化,就能在保留 DLM 语义优势的同时获得精确 KV caching
3. **双向 teacher → 块因果 student 的自蒸馏是可行的**:teacher 与 student 同规模同架构,仅 attention mask 不同,可以通过 LoRA 少量微调就完成结构迁移

基于上述洞察,CDLM 的核心设计如下:

**(a) 三目标联合训练**:

- $\mathcal{L}_{\text{Distillation}}$:对 $y$ 与 $y^\star$ 之间"新被 unmask"的 token 位置,让 student 的分布与 teacher 存储的 logits(由保存的 hidden state 重建)做 forward-KL 对齐。这是"多 token finalization"最关键的监督信号
- $\mathcal{L}_{\text{Consistency}}$:对 $y$ 与 $y^\star$ 中仍然 masked 的位置,让 student 自己在两个状态下的预测分布一致(使用 stop-gradient target),鼓励跨步稳定的"跳跃式"去噪
- $\mathcal{L}_{\text{DLM}}$:保留标准 masked-denoising 目标,防止 distillation 过度偏科导致 mask prediction 能力退化

**(b) Block-wise causal attention mask**:student 的注意力被约束为:prompt → 之前完成的所有 block → 当前 block 内全双向。完成的 block 之间是严格 causal 的,于是 **每个 block 一旦完成就可以把 KV 写入 cache,后续 block 重用**,并支持遇到 `<endoftext>` 的 block-level 早停。

**(c) Offline trajectory + hidden-state buffer**:teacher 按 block-wise 解码(每步完成 1 token),把每个 token 被 finalized 时的 last hidden state 写入 $L_g \times d$ 的缓冲区,后续 student 训练时直接从 hidden state + shared lm_head 重建 teacher 的 logits,存储成本比直接存 logits 少约 30×(因 $d \ll |V|$)。此外用 $\tau \in \{0.0, 0.5\}$ 两种温度产生多条轨迹增加多样性,$\tau = 1.0$ 因推理链不稳定被舍弃。

**(d) 推理**:block-causal mask + KV cache + 每步在当前 block 内把置信度超过 $\tau_{\text{conf}} = 0.9$ 的所有 token 一次性 finalize。刻意不引入 inter-block parallelism 等额外启发式,保持方案简洁。

## 4. 实现细节

- **基座**:Dream-7B-Instruct 与 LLaDA-8B-Instruct,两者覆盖了当前开源 DLM 的两种代表实现
- **微调方式**:LoRA(Dream rank=32,LLaDA rank=64),作用于 attention 与 MLP 模块;生成长度 $L_g = 256$,block size $B = 32$,总步数 $N = L_g$
- **数据**:Bespoke-Stratos-17k 的过滤子集,控制 prompt 长度 ≤ 512,共约 7.5k 条;LLaDA 额外加入 DParallel 7.5k 数学风格 prompts(共 ~15k 条)。Ground-truth 答案由 Qwen2.5-7B 生成
- **训练成本**:4× A100(80GB),Dream 8 小时,LLaDA 16 小时,epoch = 16(best @ 12),有效 batch size = 64,AdamW + 5% warmup constant LR
- **损失权重**:Dream $(w_{\text{distill}}, w_{\text{cons}}, w_{\text{dlm}}) = (1.0, 0.5, 0.01)$,LLaDA $(1.0, 0.5, 0.1)$
- **数据存储**:每 shard 25–30 GiB 承载 15k 样本的 hidden-state buffer,单服务器可容纳
- **推理配置**:$B = 32$,$\tau_{\text{conf}} = 0.9$,greedy(temperature=0)

## 5. 实验结果

### 5.1 Dream-7B-Instruct 主结果

| GSM8K-CoT | Dream baseline | 4.1 | 23.5 s | 256 | 79.1 |
| GSM8K-CoT | Fast-dLLM (Par.+D.C.) | 36.6 | 2.5 s | 60.8 | 77.3 |
| GSM8K-CoT | **CDLM-Dream** | **51.7 (12.6×)** | **2.1 s (11.2×)** | **44.1 (5.8×)** | **78.8** |

| HumanEval-Instruct | Dream baseline | 15.4 | 13.4 s | 256 | 48.2 |

### 5.3 核心发现

- **步数大幅压缩**:Dream 5.2–7.7×,LLaDA 3.4–7.9×,且精度普遍保持甚至提升(HumanEval 48.2→50.0, 37.8→40.2;MBPP 51.8→53.0)
- **延迟优势**:14.5× 峰值加速出现在 MBPP-Instruct 上,其中 step reduction 与 block-wise KV cache 两者叠加贡献
- **超越 AR baseline**:TPS 上 CDLM-Dream 相对 Qwen2.5-7B 在 GSM8K-CoT 1.2×,MBPP 1.1×;CDLM-LLaDA 相对 LLaMA-3.1-8B 在 HumanEval 达到 4.2×
- **消融 — 简单截断步数不可行**:直接把 Dream 基座截到 48 步,GSM8K-CoT 得分从 79.1 跌到 41.8,证明了 consistency 训练的必要性
- **消融 — 三目标缺一不可**:只用 consistency 完全崩溃(GSM8K 6.9);distillation 是主锚点;加入 consistency 和小权重 DLM 能同步提升精度与收敛速度
- **系统分析**:Arithmetic Intensity 分析表明 block-wise DLM 介于 memory-bound 的 AR 与 compute-saturated 的 vanilla DLM 之间。A100 的 ridge point ≈ 153 FLOP/Byte,$B = 32$ 时在 bs ≈ 8 处越过 ridge,小 batch 下的 compute 利用率最佳

## 6. 批判性分析

**MATH 基准的严重退化被轻描淡写**。Dream 在 MATH 上从 38.0 掉到 32.4(−5.6 分),作者归因于"训练数据量小"与"生成预算只 256 token 不够长链推理"。但这两个解释恰好揭示了 CDLM 训练配方的脆弱性:15k 样本、$L_g = 256$ 的 offline trajectory 是本方法最吃训练成本的地方,而要修正需要扩数据、扩长度,成本可能成倍上涨。作者把问题推给 future work,但没给出已有方案下的 cost-quality Pareto 曲线。

**TPS 受生成长度强烈干扰,指标存在"偷工"嫌疑**。HumanEval-Instruct 上 CDLM-Dream 的 TPS 反而不如 Fast-dLLM,作者解释为"生成长度从 200 缩到 97,pass@1 反而更高"。但这也意味着 CDLM 在没有显式 budget awareness 的情况下倾向于提前截断,这在 MBPP-Instruct 上表现为 74.3 → 长于 baseline 49.5 的反向案例,暴露了生成长度是 CDLM 的一个不稳定变量,直接影响 throughput 数字的可比性。相同条件下更合适的指标应当是 **latency-per-correct-answer** 或 **token cost at fixed accuracy**。

**Baseline 覆盖并不完整**。D2F 这个最直接的对手被以"它基于 Dream-7B-Base、$L_g = 512$"的理由跳过,但 CDLM 也是 training-based 方法,对标 D2F 本应在对等训练预算下做严格比较。FastdLLM v2(同样 block-diffusion 训练法)没出现在主表里。这让"training-based 类别第一名"的论断缺乏直接支撑。

**生成质量是否真的"持平"值得怀疑**。多处分数提升(HumanEval 48.2→50.0, MBPP 51.8→53.0)的绝对变化其实小于基准本身的随机波动(pass@1 在 164 个 HumanEval 任务上 2 分差异 ≈ 3 题)。作者用 greedy(temp=0)评估单次结果,没有多 seed/多采样做统计显著性检验,在 MBPP 因 sampling 随机性更高,这类结论尤其脆弱。

**"Teacher ceiling"被自我坦承但未量化**。作者承认 CDLM 不可能超越 teacher,但在 MBPP-Instruct 上 CDLM-LLaDA (38.4) 比 teacher (40.8) 低 2.4 分,说明蒸馏过程本身也损失精度;论文未给出"理想 oracle teacher"下的上界,也未对 KL 散度收敛曲线做分析,无法判断 student 是否已逼近 teacher 或仍有余量。

**"Block-causal 不影响 DLM 优势"的主张缺乏 infilling 证据**。CDLM 以"保留 block 内 bidirectional 注意力"为卖点,但论文通篇只评估了 math/coding 这类天然左到右的任务,没有做任何 infilling、editing 或 global planning 实验。block causality 对这些任务的影响完全没有被评估,这恰恰是 DLM 相对 AR 的最大差异点。

**数据选择上的 hidden dependency**。Dream 和 LLaDA 的 ground-truth 都由 Qwen2.5-7B 提供,这意味着整个训练链路间接继承了 Qwen2.5 的能力上限,且两个基座"共同向 Qwen 对齐"可能造成同质化。论文没有对比如果用不同 answer generator 训练会发生什么,这是一个潜在的公平性问题。

## 7. AI Infra / MLSys 视角

这篇论文对 AI infra 研究者有几个非常具体的启发:

**(1) DLM 是一个被低估的 inference 研究新阵地**。AR 推理优化(continuous batching、paged attention、speculative decoding)已经卷到接近天花板,而 DLM 刚刚起步,存在大量 system-level 机会:KV 管理、跨 block 调度、inter-block parallelism、batching 策略、speculative sampling 都有重新设计的空间。5.4 节的 arithmetic intensity 分析已经明确指出,block-wise DLM 在小 batch 场景下的 compute 利用率显著优于 AR,这对 single-user chatbot / edge inference 场景是直接可用的结论。

**(2) Block-causal + KV cache 的设计可直接迁移到其他 non-AR 架构**。State Space Models(Mamba)、Linear Attention、MoE 混合等变体都可以借鉴"block 内全连接、block 间 causal"的 mask 策略获得 exact caching 能力。这比当前很多 approximate caching 方案(periodic refresh、stale KV)更干净,没有精度损失。

**(3) Hidden-state buffer 取代 logits 存储是一个通用蒸馏技巧**。30× 存储节约对大规模蒸馏 pipeline 非常可观,特别是当 vocabulary 在扩大(tokenizer 到 150k–200k 的趋势)。适用于任何 same-family 自蒸馏场景,不局限于 DLM。

**(4) Consistency modeling 作为 inference 加速 primitive 的潜力被低估**。论文最后一句话点明的方向 **CDLM 作为 speculative decoding 的 drafter** 极具价值:AR verifier + diffusion drafter 是非常自然的组合 — DLM 每步并行出多 token 本就契合 speculative decoding 的"draft N accept K"模式。未来工作可以对齐:
   - **具体研究问题 1**:CDLM drafter + AR verifier 的 acceptance rate 曲线是什么样?与 Medusa / EAGLE 相比在长链推理上是否更优?
   - **具体研究问题 2**:drafter 的 block 大小与 verifier 的验证窗口如何联合调优?draft block 大 → 一次性验证更多 token,但被拒的代价也更大
   - **具体研究问题 3**:能否用 CDLM 的 confidence score 做 adaptive draft length,让高信心 block 提交更多 token,低信心 block 收敛到 single-token draft?

**(5) 最有价值的延伸方向**:**on-policy 蒸馏的 DLM 版本**。论文自己承认 offline trajectory 是主要瓶颈,但也指出 DLM 采样慢让 on-policy 几乎不可行。这就是一个经典的 "system enables algorithm" 问题 — 如果先做好 CDLM 本身的加速,就能让后续的 on-policy 蒸馏循环变得可行,形成 **自举式加速**。这是一个典型的 AI infra × algorithm co-design 方向,适合做后续论文。

**(6) Roofline 分析方法论值得借鉴**。Table/Figure 9 的 AI 与 ridge point 对比图式是一个判断新生成范式"有没有希望"的简洁工具,可以作为未来评估新 LLM inference 架构(reading model、recurrent fill)的 baseline 方法论。

## 8. 总结

CDLM 通过一次 LoRA 微调,把 consistency modeling 引入 diffusion language models,同时解决了 DLM 推理的两大瓶颈:**步数过多**(用 distillation + consistency 双目标把 step 减少 3.4–7.9×)和 **KV cache 不兼容**(用 block-wise causal mask 获得 exact caching)。在数学与代码基准上端到端延迟降低 3.6–14.5×,throughput 最高超过同尺寸 AR 模型 4.2×,同时精度总体持平。方法简洁、成本可控(4×A100 训练 8–16 小时)、代码开源,使其成为目前 open-source DLM 加速方案的强基线。

主要局限在于依赖 offline 静态轨迹导致数据敏感、未评估 infilling/editing 等 DLM 原生优势场景、MATH 类长链推理出现可观退化,且与最直接竞争者 D2F、FastdLLM v2 的严格对比缺失。但作为把 consistency 引入 language diffusion 的首个系统工作,它给 AI infra 社区开辟了一个很有前景的加速新赛道,尤其与 speculative decoding 的结合潜力值得立即跟进。
