## 一、背景

Diffusion Language Models (DLMs) 是一种有前景的文本生成范式，通过从全 mask 序列出发迭代去噪来并行生成文本，区别于自回归模型逐 token 生成的方式。闭源 DLM（如 Google DeepMind 在代码生成领域的工作）已报告相比自回归模型可达 10× 的吞吐提升。然而，开源 DLM 在推理效率上仍显著落后，主要受限于两个瓶颈：(1) 双向注意力机制导致无法使用标准 KV cache；(2) 高质量生成需要大量 refinement steps（通常与序列长度成正比）。

在视觉领域，Consistency Models 已成功将扩散模型的去噪步骤减少到少步甚至单步生成。这一技术的核心是训练模型在概率流 ODE 轨迹上的相邻去噪状态之间产生一致性预测。虽然该方法最初针对连续数据设计，但已有工作开始将其适配到离散语言建模场景。

---

## 二、要解决的问题

当前开源 DLM 的推理效率问题可分解为两个正交瓶颈：

1. **KV cache 不兼容**：标准 DLM 使用全双向注意力，每个去噪步都需要重新计算整个序列的注意力矩阵（O(L²) 复杂度），无法复用前序步骤的 KV cache，导致推理计算量巨大。
2. **refinement 步数过多**：高质量生成通常需要与序列长度相当的去噪步数（如 256 步生成 256 个 token），每步只确定一个 token，导致推理延迟极高。

现有的推理加速方法要么只解决其中一个瓶颈（如 dLLM-Cache 仅做 KV cache 近似，Fast-dLLM 仅做步数减少），要么依赖 inference-time heuristic 而非训练层面的改进。缺少一种同时解决两个瓶颈的训练方法。

---

## 三、洞察与设计

**关键洞察**：DLM 的 block-wise 解码轨迹上存在 temporal consistency 特性——同一 block 内不同去噪阶段的预测分布应当一致，可以通过 consistency 训练将多步 refinement 压缩为少步"跳跃"，同时将双向注意力教师的知识蒸馏到 block-causal 学生中，实现 KV cache 兼容性与步数减少的联合优化。

基于这一洞察，CDLM 的设计方案包含三个核心组件：

**1. Block-wise Causal Attention**：将学生模型的注意力 mask 从全双向改为 block-wise causal——每个 block 内保留双向注意力（支持 infilling），但 block 之间强制因果依赖。这使得已完成 block 的 KV 可以被精确缓存复用，同时支持 early stopping。

**2. Consistency-guided Distillation 训练**：联合优化三个损失函数：
- **Distillation Loss**：从双向教师的 hidden states 重构 logits，通过 forward KL 将教师的多 token finalization 信号传递给 block-causal 学生
- **Consistency Loss**：强制学生在当前状态 y 和其 block-completion 状态 y⋆ 之间的 masked 位置产生一致预测，鼓励稳定的多步跳跃
- **DLM Loss**：辅助的 masked denoising 目标，保留模型的 mask 预测能力

**3. 离线轨迹收集**：用双向教师模型在训练 prompt 上运行完整的 block-wise 解码，记录每个 token 被 finalize 时的 hidden states，构建训练数据集。

## 四、实现细节

**轨迹收集**：
- 固定生成长度 L_g=256，block size B=32
- 每步 finalize 当前 block 内置信度最高的 1 个 token
- 记录 finalization 时刻的 last hidden states 到 buffer H（用于白盒蒸馏）
- 用多个 temperature 对每个 prompt 生成多条轨迹做数据增强

**训练配置**：
- 使用 LoRA 对 attention 和 MLP 模块进行微调
- 训练数据：~7.5k prompt（来自 Bespoke-Stratos-17k 过滤），LLaDA 额外增加 7.5k 数学 prompt
- 损失权重：w_distill=1.0, w_cons=0.5, w_dlm=0.01（Dream）/ 0.1（LLaDA）
- 训练时长：Dream 约 8 小时，LLaDA 约 16 小时，4×A100 80GB
- Stop-gradient 用于 consistency loss 的 target（参考 Song et al., 2023）

**推理策略**：
- Block-wise 解码 + KV cache
- 每步在当前 block 的 masked 位置中，将所有置信度 > τ_conf=0.9 的 token 同时 finalize（confidence-thresholded parallel finalization）
- 支持 early stopping：当某 block 内生成 \<endoftext\> 时终止

## 五、实验结果

**实验平台**：4×NVIDIA A100 (80GB)，batch size 1，data parallelism

**目标模型**：Dream-7B-Instruct 和 LLaDA-8B-Instruct

**基准任务**：GSM8K、GSM8K-CoT、MATH、HumanEval、MBPP-Instruct

### CDLM-Dream 主要结果

| 基准 | 方法 | TPS | 延迟 (s) | 步数 | 准确率 |
|------|------|-----|----------|------|--------|
| GSM8K-CoT | Dream 原始 | 4.1 (×1.0) | 23.5 (×1.0) | 256 | 79.1 |
| GSM8K-CoT | CDLM-Dream | 51.7 (×12.6) | 2.1 (×11.2) | 44.1 | 78.8 |
| MBPP-Instruct | Dream 原始 | 2.3 (×1.0) | 21.7 (×1.0) | 256 | 51.8 |
| MBPP-Instruct | CDLM-Dream | 48.1 (×20.9) | 1.5 (×14.5) | 33.2 | 53.0 |
| HumanEval-Instruct | Dream 原始 | 15.4 (×1.0) | 13.4 (×1.0) | 256 | 48.2 |
| HumanEval-Instruct | CDLM-Dream | 43.3 (×2.8) | 2.2 (×6.1) | 49.6 | 50.0 |

### CDLM-LLaDA 主要结果

| 基准 | 方法 | TPS | 延迟 (s) | 步数 | 准确率 |
|------|------|-----|----------|------|--------|
| GSM8K | LLaDA 原始 | 8.2 (×1.0) | 28.3 (×1.0) | 256 | 77.1 |
| GSM8K | CDLM-LLaDA | 54.3 (×6.6) | 3.3 (×8.6) | 57.7 | 73.9 |
| HumanEval | LLaDA 原始 | 7.4 (×1.0) | 11.3 (×1.0) | 256 | 37.8 |
| HumanEval | CDLM-LLaDA | 50.9 (×6.9) | 1.9 (×5.9) | 32.3 | 40.2 |

**关键发现**：
- CDLM 在所有基准上都实现了最大的延迟降低（3.6×–14.5×）
- 步数减少 3.4×–7.9×，同时保持竞争力的准确率
- CDLM 的吞吐量超过了同等规模的自回归模型（Dream vs Qwen2.5-7B，LLaDA vs Llama-3.1-8B）
- 朴素地截断步数会导致准确率大幅下降（Dream 在 48 步时 GSM8K 从 79.1 降至 41.8），而 CDLM 在类似步数下维持 78.8

## 六、批判性分析

1. **准确率下降被轻描淡写**：论文在 MATH 上的准确率从 38.0 降到 32.4（-5.6 点），在 GSM8K (LLaDA) 上从 77.1 降到 73.9（-3.2 点），但文中将其归因于"训练数据有限"和"生成长度预算不够"。实际上这暗示 consistency 训练本身可能与复杂推理任务存在根本冲突——多 token 并行 finalize 的独立性假设在需要严格推理链的场景下可能不成立。

2. **与自回归模型的准确率差距巨大**：虽然论文重点比较 TPS，但 CDLM-LLaDA 在 HumanEval 上仅 40.2 vs AR 的 60.4，MBPP 上 38.4 vs AR 的 50.2。DLM 本身的准确率远逊于 AR 模型，加速一个低准确率系统的实际价值需要更审慎评估。

3. **训练数据规模太小且领域狭窄**：仅 7.5k–15k prompt，几乎全部来自数学/代码领域。论文声称这是通用加速方法，但缺乏在更广泛任务（如开放域对话、长文本生成、摘要）上的验证。

4. **生成长度固定为 256 的限制**：所有实验都在 L_g=256 下进行，这是一个相当短的长度限制。论文没有验证在更长生成（512、1024+）上的表现，而实际应用中长输出场景很常见。

5. **TPS 指标的公平性问题**：CDLM-Dream 在 HumanEval 上的 TPS 低于 Fast-dLLM，论文解释为"生成长度更短"。但生成长度的差异本身就反映了模型行为的不一致——block-causal 学生可能因为缺乏全局 budget awareness 而过早终止。

6. **Arithmetic Intensity 分析偏理论化**：Roofline 分析假设忽略了 prefill 成本和 OOM 约束，且仅在理论层面讨论，没有给出实测的 GPU 利用率或实际 FLOPS 数据来验证理论预测。

## 七、AI Infra / MLSys 视角

**对 AI 系统研究的启发**：

1. **DLM 推理系统优化的蓝图**：CDLM 清晰地分解了 DLM 推理的两个正交瓶颈（KV cache 不兼容 + 步数过多），并通过训练层面的架构修改（block-causal mask）而非推理层面的 hack 来解决 KV cache 问题。这种"通过微调改变模型的推理友好性"的思路值得在其他非标准架构（如 Mixture-of-Experts 的 routing、SSM 模型的 state 管理）上借鉴。

2. **Block-wise 解码的 Arithmetic Intensity 分析**：论文提供了 AR、vanilla DLM、block-wise DLM 在不同 batch size 下的 AI 对比分析，揭示 block-wise DLM 处于 AR（memory-bound）和 vanilla DLM（compute-bound）之间的平衡点。这一框架可以指导推理引擎的 batch scheduling 策略——在低 batch 场景下 block-wise DLM 的硬件利用率显著优于 AR。

3. **可迁移的技术点**：
   - Consistency distillation 从大教师蒸馏到 block-causal 学生的流程，可以应用于 speculative decoding 的 draft model 训练
   - Confidence-thresholded parallel finalization 可以作为一种通用的动态 token budget 策略
   - 离线轨迹收集 + hidden state 缓存的训练管道设计具有工程参考价值

**值得跟进的方向**：
- 在更强的 DLM backbone（如 SDAR 30B → 8B 蒸馏）上验证 CDLM 的 scaling 效果
- 探索 online trajectory collection 替代当前的 offline 方式，减少分布偏移
- 将 block-wise causal + consistency training 与 inference-time 的 inter-block parallelism 结合，进一步压缩延迟
- 研究 variable block size 的可能性，让模型根据内容复杂度自适应调整 block 大小

---

## 八、总结

CDLM 通过将 consistency modeling 引入 Diffusion Language Models，同时解决了 DLM 推理中 KV cache 不兼容和 refinement 步数过多两大瓶颈。其核心方法是：用 block-wise causal attention 微调实现精确 KV cache，用 consistency-guided distillation 实现多 token 并行 finalize。在数学和代码任务上实现了 3.6×–14.5× 的延迟降低，同时基本保持准确率。主要局限在于训练数据规模小且领域单一，生成长度受限于 256 token，且 DLM 本身的准确率仍与自回归模型存在显著差距。方法的实际价值依赖于更强 DLM 基座的出现。
