# Accelerating Sparse Attention for Visual Generative Models with Dual-Balanced Sequence Parallelism

## 1. 背景

Diffusion Transformer (DiT) 已成为图像和视频生成的主流架构,代表模型包括 Wan2.1-T2V-14B、CogVideoX1.5-5B、HunyuanVideo 等。DiT 在多步 denoising 过程中反复调用 Transformer 主干预测噪声,其中 self-attention 随 token 数呈平方复杂度增长。对于高分辨率长视频(如 81 帧 1280P)而言,一个 transformer layer 的序列长度可达 7 万以上 token,attention 占端到端延迟的 50% 以上。

为缓解 attention 的开销,**block-wise sparse attention**(PAROAttention、SpargeAttn、Sparse VideoGen 等)在注意力掩码上按块跳过低权重区域,同时保持 GPU SM 连续访存、块内可复用 dense kernel 实现,是目前视觉生成中最实用的稀疏模式之一。即便如此,在单张 A800 上用 Wan2.1-T2V-14B + PAROAttention 生成一条视频仍需 15 分钟以上,远未达到可用水平。

与此同时,**Sequence Parallelism (SP)** 被认为是扩展 DiT 推理的首选策略:DiT 权重小、激活大,划分激活比划分权重更合理;而且 attention/linear 计算密度高,即便拆分到多 GPU,每张卡仍有足够负载打满算力。SP 有三种主流形式:

- **Ulysses**:沿 head 维切分,attention 前后用两次 All-to-All 重排激活
- **Ring Attention**:沿 sequence 维切分 Q/K/V,通过 ring P2P 环形传 K,V,天然支持计算/通信重叠
- **USP (Unified SP)**:将 GPU 划分为正交的 Ulysses 组和 Ring 组,hybrid 组合 $U_x R_y$

---

## 2. 要解决的问题

**当 block-wise sparse attention 与 SP 结合时,三种 SP 方法都会产生严重的 workload imbalance,使得从单卡扩到 8 卡只能拿到约 6× 的加速(理想值 8×)。** 不平衡来自两个正交层级:

![](../../markdowns/mlsys-2026/d3d9446802a44259755d38e6d163e820/images/8f1da26bbb8fbf55005471dee368b8e3d3eb1a33cb0c98b7e62db687dceac329.jpg)

- **Head-level imbalance**:不同 head 的稀疏率差异巨大,Ulysses 按 head 分配时,某张 GPU 分到的 dense block 总数可能显著大于另一张 GPU
- **Block-level imbalance**:sparse mask 中 dense block 的分布是不规则的;Ring Attention 按 Q chunk 切分后,每次 ring 迭代中各 GPU 所处理 (Q chunk, K/V chunk) 区域的 dense block 数也不均等

作者用 sparse imbalance ratio $\rho_s$(最忙 GPU 的工作量 / 平均工作量)量化这个现象,在真实负载(8×A800 + Wan2.1-T2V-14B / CogVideoX1.5-5B × PAROAttention / SpargeAttn)上测得 $\rho_s$ 区间 1.159–1.513,即存在最高 50% 的潜在加速空间。此外,还有三个具体挑战:
1. **双层级耦合**:head 和 block 两层不平衡互相影响,联合优化的搜索空间爆炸
2. **重平衡开销**:重排需要 intra-GPU indexing 与 inter-GPU 数据交换,过大开销会抵消收益
3. **策略动态性**:sparse 模式在不同 denoising step / transformer layer 间变化,固定的 $U_xR_y$ 策略很难始终最优

---

## 3. 洞察与设计

**关键洞察**:尽管 head-level 与 block-level 两层不平衡在原始问题中是耦合的,但**每一层单独做 greedy 分区就已经能把 $\rho_s$ 压到接近 1(head-level ≤1.10,block-level ≤1.05)**。这意味着不需要做代价高昂的联合搜索,而可以把"双层联合优化"近似分解为两个顺序子问题:先做 head-level 分区,再在"head 侧近似完全均衡"的假设下做 block-level 分区。

![](../../markdowns/mlsys-2026/d3d9446802a44259755d38e6d163e820/images/8729907e5d3d4210e29bf3903b9f488f9813c6fcc095b9a1a752392ce6a848c3.jpg)

基于这个洞察,作者提出 **db-SP**,整体包含两个部分:

### 3.1 Dual-Balanced Partitioning

**Head-level partitioning**(对应 Ulysses 维度):
1. 统计每个 head 的 dense block 总数
2. 按降序排序
3. 遍历时贪心地把当前 head 分给"累积块数最少"的 GPU
4. 重用机制:相邻 denoising step 的 mask 高度相似,引入阈值 $P_s$(默认 1.10),若当前 $\rho_s < P_s$ 直接复用上一步的方案,仅在 50 步中约 5 步重算

**Block-level partitioning**(对应 Ring Attention 维度):

![](../../markdowns/mlsys-2026/d3d9446802a44259755d38e6d163e820/images/1f519413e0bcf1bcb9b1a655ae330090b8f9af237c25a454a1172fd9a407b360.jpg)

1. 先按 head 求和消去 head 维度(利用上一阶段 head 侧已经均衡的假设)
2. 对 Q 块(按行)和 KV 块(按列)分别做 greedy 切分,使 $|\mathcal{G}| \times |\mathcal{G}|$ 个(Q chunk, KV chunk)组合的 dense block 数尽量均匀
3. 引入 **reward factor $R_b$** 的 *biased* greedy:在比较时把"原 GPU"的累计计数减去 $R_b \times$ 当前块的 KV 块数,鼓励 Q/KV 留在本地 GPU,减少 inter-GPU 数据交换。$R_b$ 越大越偏向本地(通信少但 $\rho_s$ 稍差),越小越偏向严格均衡(通信多)

分解后的完整算法(Alg. 1)先执行 head-level greedy,再在 head 均衡假设下执行 block-level biased greedy,输出三份 plan:head_partitioning_plan、q_partitioning_plan、kv_partitioning_plan。

### 3.2 Sparsity-Aware Parallel Strategy Selection

对于 $|\mathcal{G}| = 2^k$ 张 GPU 存在 $k+1$ 种 $U_x R_y$ 组合(如 8 GPU 时有 U8R1/U4R2/U2R4/U1R8)。作者推导了 multi-GPU attention 的延迟模型:

$$\mathcal{L}(s,p) = \mathcal{L}^{\text{all2all}}(x) + \big[\max(\mathcal{L}^{\text{comp}}(s), \mathcal{L}^{\text{p2p}}(y))(y-1) + \mathcal{L}^{\text{comp}}(s)\big] \times \rho_s(s,p)$$

其中 $\mathcal{L}^{\text{comp}}$ 随稀疏度线性缩放,$\rho_s$ 乘性地反映不平衡带来的延迟放大。运行时每层 attention 都按当前 sparse pattern 预测三到四种策略的延迟,选最低延迟者执行。

**支持策略动态切换的关键优化**:SP 本身不切分权重,因此切换策略无需 reload 模型,只需要切换通信域。db-SP 在初始化时就把所有 $\log_2(|\mathcal{G}|)+1$ 组通信 group **预构建好**,运行时零切换开销。

## 4. 实现细节

- **代码基线**:基于 USP 开源代码,替换 attention backend 为 PAROAttention(静态 mask)或 SpargeAttn(动态 mask)
- **前端集成**:接入主流 DiT 推理引擎 xDiT 和 ParaAttention,支持端到端推理
- **数据操作**:intra-GPU 重排用 PyTorch `index_select`,inter-GPU 交换用 NCCL 的 `all_to_all`
- **离线拟合**:$\mathcal{L}^{\text{all2all}}(x)$、$\mathcal{L}^{\text{p2p}}(y)$、$\mathcal{L}^{\text{dense}}$、$\mathcal{L}^{\text{launch}}$ 通过 dense attention profiling 数据离线拟合
- **block size**:与底层 sparse kernel 对齐,PAROAttention 通常为 64,BurstEngine 为了均衡退化到 32,导致单算力下降

## 5. 实验结果

**测试平台**:8×A800 80GB SXM4(NVLink 8 代)、8×H800 80GB
**模型/任务**:Wan2.1-T2V-14B(81 帧 1280P,75.6K tokens)、CogVideoX1.5-5B(161 帧 1280P,85.7K tokens),50 denoising steps
**稀疏方案**:PAROAttention(sparsity 0.414 和 0.683 两档)、SpargeAttn
**基线**:Ulysses (U8R1)、USP (U4R2/U2R4)、Ring Attention (U1R8)、BurstEngine

**主结果(Fig. 8)**:

![](../../markdowns/mlsys-2026/d3d9446802a44259755d38e6d163e820/images/8cea9616f6af6646dcf223dd7c0ca666a95c524ae7b16b5c062c7170ad753fb0.jpg)

| 维度 | 8 GPU | 4 GPU |
|---|---|---|
| Wan2.1 端到端加速 | 1.12–1.26× | 1.10–1.15× |
| CogVideoX1.5 端到端加速 | 1.16–1.42× | 1.10–1.15× |
| Wan2.1 attention 加速 | 1.22–1.42× (vs Ring) | 1.26–1.38× (vs Ulysses) |
| 平均 attention speedup | 1.40× | — |
| 平均端到端 speedup | 1.25× | — |

**关键观察**:
- BurstEngine 在视觉生成场景下反而比普通基线更慢,原因是它为均衡需要退化到小 tile(32),attention kernel 本身慢 1.25×,得不偿失
- 基线之间(Ulysses/USP/Ring)在不做重平衡时表现相近,而一旦 workload balance 做好,不同策略的差距被放大出来 —— 这正是动态策略选择的价值
- **Sparse imbalance ratio 越大,db-SP 的加速越显著**,实验(Fig. 9)显示 attention speedup 与 $\rho_s$ 近线性关系

**动态策略选择收益**:相比固定策略,动态切换贡献额外 1.02–1.27× 端到端加速

**开销分析**:
- Head-level 分区(仅 intra-GPU 重排)开销 < 1%
- Block-level 分区需 inter-GPU 交换,但可与前置 sort/index 计算重叠,总体 < 5% 端到端延迟
- 阈值 $P_s = 1.10$ 下,50 denoising step 中仅需 5 次重新分区

## 6. 批判性分析

这篇论文工程完成度高,但有几处需谨慎解读:

1. **"端到端加速 1.25× 平均" vs "attention 加速 1.40×" 的错位**:作者 headline 强调 1.40× attention 加速,但端到端只有 1.25×(Fig. 8 中 CogVideoX1.5 的 1.42× 是个别最优值)。这是因为 attention 只占端到端的约 50%,Amdahl 天花板已经限定了可达收益。读者需要明确 db-SP 并非把整个 DiT 推理加速 1.4 倍。

2. **BurstEngine 基线对比偏不公平**:BurstEngine 原本是为长上下文 LLM 训练设计的,block size 默认小(32);论文用它当 baseline 时未探索调大 block size 或放宽精度约束。把它直接拉过来当"最强 sparse-aware SP 基线"并宣布 db-SP 大幅领先,说服力有限。真正的对照应该是最新的 **DSV**(§2.4.2 提到,但没纳入端到端对比)—— DSV 同样做 sparsity-aware context parallelism,只是针对训练场景。

3. **两层级真的"各自独立近似完美"吗?** §4.2.3 用"head-level 和 block-level 各自都能压到 $\rho_s \approx 1$"来支撑分解成两个子问题的合理性。但这个前提只在 Fig. 9 里用"合成 mask"做了 microbench,真实 mask 上 head-level 分完之后 block-level 的实际 $\rho_s$ 会不会退化,只有 Fig. 11(默认配置下)的一条曲线支撑,缺乏系统性对比。

4. **延迟模型的拟合质量未披露**:§4.3 的 Eq. 4 是策略选择的核心,但 $\mathcal{L}^{\text{dense}}$、$\mathcal{L}^{\text{p2p}}$ 的实际拟合误差是多少?在极端稀疏(sparsity > 0.8)或少 GPU 情况下预测是否仍然准?论文没给 calibration curve,导致读者对动态选择 1.02–1.27× 的加速来源只能将信将疑。

5. **Reward factor $R_b$ 缺少自适应机制**:Fig. 12 显示 $R_b$ 与 $\rho_s$/通信开销之间是 U 型 trade-off,但论文只描述"存在 trade-off",没有给出如何自动挑选 $R_b$ 的算法。实际部署中,不同网络、不同 sparse 模式可能需要不同 $R_b$,这块工作被作者轻描淡写了。

6. **只覆盖 NVLink 全互联的 single-node 场景**:所有实验都在单机 8 GPU 且全 NVLink,没有讨论跨节点 IB/RoCE 下 ring P2P 与 all-to-all 相对成本发生翻转时,策略选择模型是否还 hold。

7. **生成质量未做定量核对**:db-SP 声称是"精准不变"的纯调度优化,但稀疏方法本身(PAROAttention / SpargeAttn)会影响质量;论文只报延迟不报 VBench/CLIPScore,读者无法确认 1.25× 是在等质量下取得的。

## 7. AI Infra / MLSys 视角

这篇工作对 AI 系统研究者有几个有价值的启发:

1. **"高阶分解"作为一种通用 load balance 方法论**:稀疏 attention 的 head/block 不平衡与 MoE 的 token/expert 不平衡、KV cache 的 sequence/head 不平衡在结构上非常像 —— 都是"多维 irregular workload 分摊到多 GPU"。db-SP 证明当每一维 greedy 单独已经接近最优时,顺序分解比联合搜索更工程可行。可以直接迁移到 **MoE expert-to-GPU 路由 × sequence packing 的联合优化**,或者 **KV cache paging × prefix sharing 的资源分配**。

2. **"策略选择"比"单策略优化"更值得研究**:作者发现 Ulysses / Ring / USP 在不做 balance 时差异很小,但 balance 之后差异被放大。这意味着**"好的调度器 + 动态策略选择"可能比"发明新并行原语"收益更大**。类似思路可以用于 LLM serving:相同 batch 用 prefix cache vs dynamic prefill vs chunked prefill,静态选择一个 suboptimal,运行时选择一个 near-optimal。

3. **可迁移到 LLM 推理的 block-sparse KV 剪枝**:未来 LLM 推理若采用 MInference / SparQ / H2O 这类 block-wise sparse KV 访问方式,在 TP + SP hybrid 并行下也会遇到完全同构的 head/block imbalance 问题。db-SP 的 greedy + reusing + reward biasing 框架可以几乎直接复用,只需把 denoising step 换成 decode step。

4. **值得跟进的 future work 方向**:
   - **异构通信拓扑下的策略选择**:扩展 Eq. 4 的延迟模型到跨节点 IB,研究在带宽阶梯化的网络下 biased greedy 的 $R_b$ 应如何自适应
   - **联合 quantization 的调度**:SageAttention2 提供 INT4/FP8 kernel,不同 head 量化精度不同会再引入一层 imbalance,db-SP 框架可以扩展为"head × block × quant-level"三维均衡
   - **训练场景回迁**:db-SP 目前只针对推理,DSV 做训练;合并两者,让 DSV 的 sparsity-aware context parallelism 也吸收 db-SP 的 dual-level greedy + reward biasing,可能在大模型视频生成训练上带来更大收益
   - **自动选取 $R_b / P_s$**:用 online bandit / small regressor 在运行时根据实测 $\rho_s$ 和通信延迟调参,替代现在的人工超参

5. **对小实验室的可操作切入点**:这篇论文没开源 DSV 的对比实验数据,也没做跨节点实验 —— 对只有 2–4 卡的小实验室,"把 db-SP 放到 PCIe / 低带宽环境里看崩在哪儿"本身就是一篇工程 paper 级的问题。此外,db-SP 的核心开销统计缺少 GPU trace(Nsight),可以做一个细粒度的 kernel-level breakdown 并提出进一步优化(如重叠 sort 与 KV 传输)。

---

## 8. 总结

db-SP 针对"block-wise sparse attention × sequence parallelism"场景下的严重 workload imbalance 问题,提出 **head-level 与 block-level 分层 greedy 分区 + 稀疏感知的动态策略选择** 的组合拳。核心贡献在于:(1) 形式化定义 sparse imbalance ratio $\rho_s$,量化损失;(2) 通过"每层单独 greedy 已近最优"的洞察,把双层联合优化分解为两个顺序子问题;(3) 引入 reusing threshold 和 reward factor 两个轻量机制有效控制重平衡开销在 5% 内;(4) 借助 SP 不切分权重的特性,实现 runtime 零开销策略切换。在 8×A800 / 8×H800 上 Wan2.1 和 CogVideoX1.5 的端到端推理分别取得平均 1.25× 加速和 1.40× attention 加速。

**适用场景**:长序列视觉生成(> 70K token)、block-wise sparse attention 方案、NVLink 全互联 multi-GPU 单机环境。**主要局限**:仅覆盖推理、仅覆盖单机、reward factor 无自适应、未验证生成质量不变性、基线对比略有不公平。对 AI Infra 研究者而言,其"分层 greedy + 动态策略选择"的设计范式比具体数字更值得借鉴。
