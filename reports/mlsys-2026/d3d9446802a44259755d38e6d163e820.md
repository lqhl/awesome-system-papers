# Accelerating Sparse Attention for Visual Generative Models with Dual-Balanced Sequence Parallelism

## 一、背景

Diffusion Transformer（DiT）已成为图像和视频生成的主流架构，其核心的 attention 计算随 token 数量呈二次增长，在多帧视频生成任务中占据超过 50% 的端到端延迟。Block-wise sparse attention 是一种有效的加速手段，能在维持生成质量的同时减少计算量。然而，即使使用了 sparse attention，单 GPU 上的生成延迟仍然过高（例如 Wan2.1-T2V-14B 在 A800 上超过 15 分钟/视频），因此需要 sequence parallelism（SP）将工作负载分摊到多 GPU 上。

现有的 SP 方法包括 Ulysses（按 attention head 维度分区）、Ring Attention（按序列维度分区）和 USP（两者的混合）。这些方法在 dense attention 下工作良好，但在 sparse attention 场景下会引入严重的工作负载不均衡。

---

## 二、要解决的问题

将 sequence parallelism 应用于 block-wise sparse attention 时，存在**双层工作负载不均衡**问题：

1. **Head-level 不均衡**（Ulysses 方式）：不同 attention head 的稀疏模式差异显著，分配到不同 GPU 的 head 对应的 dense block 数量差距很大。
2. **Block-level 不均衡**（Ring Attention 方式）：sparse mask 中 dense block 的分布不规则，导致不同 GPU 在每次迭代中处理的 block 数量不均。

作者定义了 sparse imbalance ratio（ρ_s）来量化这种不均衡，实测 ρ_s 在 1.159–1.513 之间，意味着最繁忙 GPU 的工作量比平均值高出 16%–51%，造成大量 GPU 空等。

此外，解决不均衡还面临三个具体挑战：
- 两层不均衡相互耦合，联合优化搜索空间大
- 工作负载再均衡引入数据重排和 GPU 间交换开销
- Sparse pattern 随 denoising step 和 layer 动态变化，需要运行时策略选择

---

## 三、洞察与设计

**关键洞察**：Head-level 和 block-level 的 greedy partitioning 各自都能独立达到近乎完美的均衡（ρ_s ≤ 1.1 和 ρ_s ≤ 1.05），因此可以将联合优化问题解耦为两个顺序子问题，而不需要昂贵的联合搜索。

基于此洞察，db-SP 的设计包含三个核心组件：

### 1. Dual-Balanced Partitioning

- **Head-level partitioning**：对所有 head 按 dense block 数量降序排列，用 greedy 算法将 head 分配到 GPU（每次放到当前负载最小的 GPU），实现 Ulysses 维度的均衡。利用相邻 denoising step 间 sparse mask 的相似性，设定阈值 P_s 复用上一步的分区方案，减少分区执行次数（50 步中仅需 5 次重新分区）。
- **Block-level partitioning**：将 Q 和 K/V 的 block 分别按对应 dense block 数量降序排列，greedy 分配到 GPU/iteration。引入 reward factor R_b，对留在原始 GPU 的 block 给予偏置奖励，减少 GPU 间数据交换量。

### 2. 解耦策略

先执行 head-level partitioning，然后在假设 head 层已完美均衡的前提下执行 block-level partitioning。由于各层独立达到高均衡度，解耦后的结果接近联合最优。

### 3. Sparsity-Aware Parallel Strategy Selection

不同 layer 和 denoising step 的 sparse pattern 不同，最优并行策略（UxRy 的 degree 选择）也不同。db-SP 通过延迟预测公式，在运行时对每个 attention 计算动态选择最优策略。预先构建所有可能的通信组（共 log₂(|G|)+1 种），消除策略切换开销。

---

## 四、实现细节

- 基于 USP 开源代码实现，后端集成 PAROAttention（静态 mask）和 SpargeAttn（动态 mask）的 sparse attention kernel
- 已集成到 xDiT 和 ParaAttention 推理引擎
- Intra-GPU 数据重排用 `index_select` 实现，inter-GPU 交换用 NCCL 的 `all_to_all` 实现
- 延迟预测模型：$L(s,p) = L_{\text{all2all}}(x) + L_{\text{attn}}(s,p)$，其中 attention 延迟考虑了 Ring Attention 的计算-通信 overlap 和 ρ_s 的影响，参数通过 dense attention profiling 离线拟合
- Head-level partitioning 复用阈值 P_s = 1.10 时，50 步 denoising 只需 5 次重新分区
- Block-level partitioning 的 GPU 间通信可与前序计算（排序、索引）overlap，开销控制在端到端延迟的 5% 以内

## 五、实验结果

**实验平台**：8×A800 80GB SXM4 和 8×H800 80GB，NVLink 互联；CUDA 12.1 + PyTorch 2.5.1 + NCCL 2.21.5

**模型与任务**：

| 模型 | 视频规格 | Token 数 |
|------|---------|---------|
| Wan2.1-T2V-14B | 81 帧 1280P，50 步 | 21 帧 × 3600 tokens/帧 |
| CogVideoX1.5-5B | 161 帧 1280P，50 步 | 21 帧 × 4080 tokens/帧 |

**主要结果（8 GPU）**：

| 指标 | Wan2.1 | CogVideoX1.5 |
|------|--------|---------------|
| 端到端加速比 | 1.12×–1.26× | 1.16×–1.42× |
| Attention 加速比（vs Ulysses） | 平均 1.38× | 平均 1.38× |
| Attention 加速比（vs Ring Attention） | 平均 1.42× | 平均 1.42× |

**4 GPU 结果**：端到端加速 1.10×–1.15×（两个模型均如此），不均衡在 GPU 数量更多时更显著。

**Partitioning 效果**：
- Head-level partitioning 后 ρ_s ≤ 1.1
- Block-level partitioning 后 ρ_s ≤ 1.05
- 动态策略选择额外带来 1.02×–1.27× 端到端加速

**开销**：Head-level reordering < 1% 端到端延迟；block-level 含通信 overlap 后 < 5%。

**Baseline 对比**：BurstEngine 因分块后 attention kernel tile size 缩小（64→32），kernel 性能退化 1.25×，反而不如不做均衡的 baseline。

## 六、批判性分析

1. **加速比受限于 attention 占比**：端到端加速 1.25× 对应的 attention 加速为 1.40×，说明 attention 之外的部分（linear layers、通信等）未被优化。随着 sparse attention 进一步提高稀疏度，attention 占比下降，db-SP 的端到端收益会递减。

2. **4 GPU 场景收益有限**：4 GPU 下端到端加速仅 1.10×–1.15×，对于中小规模部署场景吸引力不大。论文主要展示 8 GPU 结果，但未探索更大规模（16/32 GPU）下不均衡是否进一步恶化以及 db-SP 的可扩展性。

3. **SpargeAttn 仅支持 Ulysses**：由于 SpargeAttn kernel 实现限制，论文在 SpargeAttn 场景下只能评估 Ulysses 维度的均衡，无法验证 block-level partitioning 和策略选择的效果。这限制了结论的普适性。

4. **延迟预测模型的简化假设**：Eq. 4 假设 computation 和 P2P 通信完美 overlap，实际中 overlap 效率受 GPU 负载、NVLink 带宽争用等因素影响。论文未报告预测误差。

5. **Reward factor 的手动调参**：R_b 需要人工选择（论文测试了 0–10 范围），缺乏自适应机制。不同硬件和模型配置下最优 R_b 可能不同。

6. **仅评估两个模型**：Wan2.1 和 CogVideoX1.5 都是视频生成模型，未评估图像生成（如 FLUX、SD3）或其他使用 sparse attention 的场景。

---

## 七、AI Infra / MLSys 视角

1. **工作负载均衡是 sparse + parallel 的通用问题**：db-SP 揭示的 dual-level imbalance 不仅限于 DiT 推理。在 LLM 的 sparse attention（如 MInference）、MoE 的 expert parallelism 等场景中，都存在类似的不均衡问题。Greedy partitioning + 解耦优化的思路可以迁移。

2. **动态策略选择的范式值得借鉴**：db-SP 在运行时根据 workload 特征动态切换并行策略，且通过预构建通信组消除切换开销。这种 "预备多种策略 + 运行时选择" 的模式对 LLM serving 中的动态 batch/sequence 调度也有启发。

3. **可延伸的研究方向**：
   - 将 db-SP 扩展到 DiT **训练**场景（DSV 已初步探索，但 head-level 均衡未被考虑）
   - 结合 quantization（SageAttention）和 caching 技术与 db-SP 的联合优化
   - 探索更大规模（16/32/64 GPU）下的可扩展性，以及跨节点场景下通信开销的影响
   - 将 dual-balanced 思路应用于 MoE 模型的 expert parallelism 不均衡问题

4. **最有价值的切入点**：在 LLM long-context inference 中，dynamic sparse attention（如 MInference、StreamingLLM）与 sequence parallelism 的结合同样面临不均衡问题，db-SP 的方法可以直接迁移验证。

---

## 八、总结

db-SP 针对 block-wise sparse attention 与 sequence parallelism 结合时的双层工作负载不均衡问题，提出了 head-level 和 block-level 两级 greedy partitioning 方案，并通过解耦优化、mask 复用、biased greedy 算法和动态策略选择来最小化开销。在 Wan2.1 和 CogVideoX1.5 两个视频生成模型上，db-SP 实现了平均 1.25× 端到端加速和 1.40× attention 加速。其主要局限在于收益受 attention 占比约束、仅验证了 8 GPU 规模、以及部分 sparse kernel 的兼容性限制。
