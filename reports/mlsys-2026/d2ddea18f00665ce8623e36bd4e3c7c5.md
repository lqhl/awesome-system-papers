# PLayer-FL: A Principled Approach to Personalized Layer-wise Cross-Silo Federated Learning

## 1. 背景

联邦学习(Federated Learning, FL)允许多家机构在不交换原始数据的前提下协同训练模型。最经典的算法 FedAvg 通过加权平均各客户端权重得到一个全局模型,但当各客户端数据非独立同分布(non-IID)时,本地优化方向相互冲突,平均后的全局模型容易落在局部最优解之外,性能显著下降。这在医疗等典型的 cross-silo 场景尤其严重 —— 各医院/中心人群结构、采集协议、操作流程都不同。

为缓解这一问题,personalized FL 让每个客户端拥有自己的模型,只在与全局模型保持一定一致性的前提下做局部调整。其中 **partial FL** 是一种结构上简单的思路:只联邦"前几层",后几层只在本地训练。这背后的洞察来自表示学习——浅层学到的是更通用的特征(纹理、边缘等),深层学到的是任务/数据集相关的特征。然而既有 partial FL 方法(FedPer, FedBABU, FedRep 等)依赖 **架构特定、人工预设** 的层划分规则,难以泛化到不同模型(尤其是 CNN 之外的架构)。

---

## 2. 要解决的问题

围绕 partial FL 的核心痛点是 **"哪些层应该被联邦"是被预先硬编码的,缺少跨架构、跨任务的通用判定准则**。具体可拆为三点:

1. **缺乏统一指标**:目前没有一个轻量、跨 FCN/CNN/Transformer 都能用的层级分指标来识别"该不该联邦此层"。
2. **划分时机过晚或过依赖完整训练**:许多自适应方法需要训练到收敛后才能做层级划分,代价高。
3. **公平性与参与激励不足**:既有 personalized FL 在平均性能可能不错,但对每个客户端是否都比 local-only 好(参与激励)、收益是否均匀(公平性)缺乏保证 —— 这在 cross-silo 场景非常关键,因为客户端往往有足够数据自己训练,如果联邦不能稳定带来收益就没人愿意加入。

---

## 3. 洞察与设计

**关键洞察**:作者借用模型剪枝中的"参数重要性"思路,观察到一个层在联邦中"是否值得 share"可以通过一阶近似 $(\theta_p \nabla \theta_p)^2$ 来度量,且 **这种层级 pattern 在第一个 epoch 训练后就稳定显现**。具体而言,在非 IID 数据上独立训练的同初始化模型,其层级泛化能力(以 gradient variance、Hessian eigenvalue sum、CKA 表征相似度衡量)会出现一致的 pattern:浅层处于平坦的 loss 面上、跨客户端表征相似;深层突然陡峭、表征分化 —— 这个"转折点"早期就能识别。

**Federation Sensitivity 指标**:论文将层 $l$ 的联邦敏感度定义为前 $l$ 层参数重要性(归一化后)之和:

$$\mathcal{F}_l(\Theta) = \sum_{k=1}^{l} \frac{1}{n_k} \sum_{p=1}^{n_k} (\theta_p \nabla \theta_p)^2$$

相对参数重要性的两个改动:(1) 按层参数数 $n_k$ 归一化,确保不同大小的层可比;(2) 累计前序层贡献,反映"联邦第 $l$ 层就必须联邦前面所有层"的约束。这个指标重用了 SGD 已经计算的 weight 与 gradient,几乎零额外成本。

**PLayer-FL 算法**(Algorithm 1-3):
1. 所有客户端跑一个 epoch 的 local update,各自计算每层的 federation sensitivity。
2. 服务端聚合各客户端的 sensitivity 数组,找出第一个使相对增长 $\mathcal{F}_{p+1}/\mathcal{F}_p > t$ 的层 $p$ —— 即"敏感度突变点"。
3. 后续按 FedAvg 的方式只联邦前 $p$ 层,后面的层各自本地训练(但前向/反向都参与,每轮都更新)。

阈值 $t$ 控制激进度,但实验显示在很大范围内 transition point 都稳定。整体复杂度与 FedAvg 同阶 —— 多出的 CALCULATEFEDSENSITIVITY 是 $O(P)$、LAYERSPLIT 是 $O(L)$,均只跑一次。

---

## 4. 实现细节

- **何时计算 sensitivity**:仅在第 1 个 epoch 后做一次。客户端无需上传 sensitivity 数组本身的 raw 梯度,只上传聚合后的层级标量;隐私开销可控。
- **federated 与 local 的更新方式**:每一轮 client 端同时更新所有层(包括 local 层),但只上传 federated 层给 server 聚合;新一轮下发时 federated 层覆盖、local 层保留。学习率默认两部分共享,可分别设置。
- **正交性**:作者强调这是一个"决定层划分"的策略,可与 FedProx、Ditto 等 personalized 算法叠加。
- **架构覆盖**:在 7 个数据集上分别用 3-5 层 CNN(图像)、4 层 FCN(表格)、Transformer 风格 stack(NLP)训练,Table A.2 给出了识别出的 transition point —— 例如 5×Conv-2×FC 的 CIFAR-10 模型识别为 Conv5,Transformer 识别为第一个投影层 FC1Projection,体现了跨架构通用性。
- **训练栈**:除 pFedMe 用其原生优化器外,其余算法均用 AdamW;每个数据集用 grid search 选学习率;在单台 Tesla V100 16GB 节点上跑实验。

## 5. 实验结果

**评测设置**:
- **数据集**(7 个):FashionMNIST、EMNIST、CIFAR-10(标签 Dirichlet 划分,α=0.5);ISIC-2019、Fed-Heart-Disease(医院自然划分);Sent-140(用户划分,Top-15);MIMIC-III(按 admitting diagnosis 划分)。覆盖图像、表格、NLP 三种模态。
- **基线**(11 个):分三类 —— 标准(Local、FedAvg);personalized(FedProx、pFedMe、Ditto、LocalAdaptation);partial FL(FedBABU、FedLP、FedLAMA、pFedLA)。
- **指标**:Macro-F1(主指标,处理类别不平衡)、accuracy、test loss、fairness(各客户端性能方差)、incentivization(超过 local 与 FedAvg 的客户端占比)。多数据集结论用 Friedman rank test 验证。

**主要结果**(Table 1, Macro-F1 均秩):

| 算法         | 平均秩 | 备注                         |
|--------------|--------|------------------------------|
| **PLayer-FL** | **2.6** | 7 个数据集上整体最佳         |
| FedBABU      | 4.1    | 最强 partial FL 基线         |
| pFedMe       | 5.3    |                              |
| FedAvg / Ditto | 6.0  |                              |
| Local        | 6.9    | cross-silo 下 local 仍很强   |
| FedLP        | 6.7    |                              |
| FedLAMA      | 10.1   |                              |
| pFedLA       | 11.4   | 在多个图像任务上几乎崩溃     |

PLayer-FL 在 FMNIST(79.3 F1)、Sent-140(59.6)上拿到最高分,在其他任务上虽非第一,但秩稳定靠前;Friedman p < 5×10⁻³。

**公平性与激励**(Table 2):PLayer-FL 在 fairness 平均秩 3.8、incentivization 平均秩 3.4,均为 11 种算法中最佳。值得注意的对照实验是 PLayer-FL-Random(随机选 transition point),在 F1 平均秩仅 6.1、incentivization 4.8 —— 这说明性能优势确实来自 sensitivity 指标的"找对位置",而不是单纯多了一些 local 层。

**关键现象**:
- 在 cross-silo 高度 non-IID 场景下,Local 训练本身就是相当强的基线(各客户端数据量足),很多 personalized FL 算法甚至打不过 Local。PLayer-FL 在 7 个任务里几乎都不比 Local 差。
- pFedLA(基于 hypernetwork 的层级聚合)在小数据集上完全过拟合(EMNIST 仅 7.1 F1),反衬出 PLayer-FL "结构简单 + 数据驱动" 的鲁棒性。

## 6. 批判性分析

1. **Federation sensitivity 与最终性能的因果链不完整**。论文证明该指标与 gradient variance、CKA 相似度等"已知泛化性指标"高度相关,然后跳到"用它选 transition point 就能获得最佳 partial FL 性能"。但中间缺一步:**为什么"敏感度突增的位置"恰好是最优联邦边界**?如果突增很缓和或出现多个"次峰",阈值 $t$ 的鲁棒性还成立吗?Figure 4 只展示了"突增很显著"的几个网络,Sent-140 和 Heart 这种结构非典型的网络中阈值敏感性没有正面分析。

2. **transition point 仅由 1 个 epoch 决定的风险**。整个方法的"第一 epoch 即可定型"是一个极强的假设。如果第 1 个 epoch 学习率不合适、batch size 噪声大,sensitivity 可能不稳定。论文未做学习率/batch size 对 transition point 的 ablation,而 Table A.3 显示 PLayer-FL 在不同数据集上需要专门调学习率才能达到最佳效果 —— 这削弱了"零额外开销、即开即用"的卖点。

3. **公平性指标其实掩盖了部分客户端被牺牲**。Fairness 用方差衡量,意味着"所有人都很差"也可以得到很好的 fairness 分数。在 EMNIST 上 PLayer-FL 只拿到 62.2 F1(低于 FedBABU 的 66.1),Incentivization 0%(无人受益于联邦),却仍是 fairness 第三名。需要更严格的"Pareto improvement"指标来辅助判断。

4. **基线超参公平性存疑**。Table A.3 显示 PLayer-FL 在每个数据集都有专属调过的学习率,但其他算法(尤其 pFedLA)是否也用了相同力度的 grid search?pFedLA 在多任务上崩到接近随机(EMNIST 7.1 F1, CIFAR 10.5 F1)颇为反常 —— 这可能不是算法本身的问题,而是配置不当。论文用"对手很弱"作为衬托值得警惕。

5. **隐私分析缺失**。每个客户端要把 layer-wise sensitivity 上传给服务端,虽然是聚合标量,但其值反映了本地数据的梯度结构,可能泄露分布信息。论文完全没讨论这一点。

6. **未与最近 LoRA/adapter 类 personalized FL 比较**。Adapter 思路也能实现"主干共享 + 个性化外挂",在 LLM 时代尤其相关。论文比较的最新基线(pFedLA, pFedHR)都是 2022-2024,没有覆盖 adapter 路线。

7. **作者承认缺乏理论保证**,但更深一层的问题是:Federation sensitivity 的定义直接照搬剪枝中"零化参数"的近似,而联邦聚合的扰动方向与"参数置零"在几何上并不等价。论文用了"both are perturbations"做模糊比拟,严谨性不足。

## 7. AI Infra / MLSys 视角

虽然论文落点在医疗 cross-silo FL,但其中几个思路对 AI Infra 研究者很有启发:

1. **"用第一个 epoch 的局部信号决策长期结构"是一个可迁移的范式**。在 LLM 训练/推理基础设施里,我们经常需要预先决定:哪几层做 KV cache offload、哪几层做 quantization、哪些 expert 做 host placement。PLayer-FL 给的启示是 —— 不要等收敛、不要 grid search、用一阶梯度信号在 warmup 阶段就做决策,代价为零。可以借鉴 federation sensitivity 设计 "offload sensitivity"、"quantization sensitivity" 等度量。

2. **跨架构通用的层级度量是稀缺品**。在 MoE、Transformer、Mamba 等多元化架构并存的今天,大多数系统优化(如 layer-wise sparsity、layer-wise pipeline cut)依然基于人工启发式。一个能跨 CNN/Transformer 都给出一致结构信号的指标(本文 federation sensitivity 在 Conv 网络与 Transformer 上都能给出有意义的转折点)是可被复用的工具。

3. **partial FL 与 LoRA-based personalized fine-tuning 的桥接**。可顺着这个方向延伸:能否用 federation sensitivity 决定 **LoRA 应该挂在哪些层**?在多 tenant LLM serving 中,每个 tenant 有自己的私有数据,联邦微调时如果能精准识别哪些层适合 LoRA 共享、哪些层 per-tenant,既能减少通信、又能减少 personalize 模型的存储。

4. **Cross-silo 场景在 LLM 推理基础设施里也开始重要**。多家医院/银行联合做 RAG / fine-tune,不能交换数据但需要共建模型;这类场景下 PLayer-FL 这种轻量 partial FL 比训练 hypernetwork 的 pFedLA 更工程友好,值得作为 baseline。

5. **可操作的 future work 切入点**:
   - 把 federation sensitivity 推广到"layer-wise compression sensitivity",用于 LLM 后训练阶段的混合精度量化
   - 在 DiLoCo / async FL 场景下检验:第一个本地 step(而非 epoch)的 sensitivity 是否仍稳定?
   - 与梯度压缩、Top-K sparsification 结合:既然只有部分层联邦,这些层是否还可以进一步稀疏化?

---

## 8. 总结

PLayer-FL 提出了一个轻量、跨架构通用的 federation sensitivity 指标,基于一阶 weight×gradient 近似在第 1 个训练 epoch 后即可识别"该联邦到第几层"的转折点,把原本依赖人工启发式的 partial FL 升级为有原则的方法。在 7 个 cross-silo benchmark 上(图像/表格/NLP),PLayer-FL 在 Macro-F1 平均秩、fairness 与 incentivization 三项上都拿到最佳,且与 FedAvg 同阶复杂度。主要适用场景是数据高度 non-IID、客户端数量不多但本地数据充足的 cross-silo 设置(典型如医疗联邦学习)。局限在于缺少理论保证、对超参敏感、未覆盖 LLM/adapter 路线、隐私分析缺失,但工程上易于落地、可与其他 personalized FL 方法叠加,作为这一子领域的强基线值得跟进。
