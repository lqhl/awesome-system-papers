# HetRL: Efficient Reinforcement Learning for LLMs in Heterogeneous Environments

**作者**：Yongjun He, Shuai Zhang, Jiading Gai, Xiyuan Zhang, Boran Han, Bernie Wang, Huzefa Rangwala, George Karypis
**会议**：MLSys 2026
**链接**：[MLSys 2026 Proceedings](https://proceedings.mlsys.org/paper_files/paper/2026)
**源文件**：[[7f39f8317fbdb1988ef4c628eba02591.pdf]]

---

## 1. 背景

LLM post-training 中,RL(PPO、GRPO 等)已经成为提升推理能力和对齐人类价值观的主流技术。但 RL 训练的算力需求随着模型尺寸快速膨胀,目前主流的 RL 训练系统(verl、OpenRLHF、NeMo-Aligner 等)都假设运行在单一 region 内的同构高端 GPU 集群(全是 H100 或全是 A100)+ 高带宽 NVLink/IB 网络上。

与此同时,由于 NVIDIA 频繁推出新一代 GPU,大量中端 / 上一代 GPU(L40S、L4、A100 等)在各 region 散落且利用率低下。多项研究已经指出,跨地理区域聚合这些异构 GPU 资源,总算力和总显存远超单 region 内可获得的同构高端 GPU 集群。在 LLM 训练 / 推理场景,已经有 Metis、HexGen-2、Helix、ThunderServe、Sailor、StreamRL 等工作探讨过异构 GPU + 异构网络下的部署优化。本文把这条路径延伸到 RL post-training。

---

## 2. 要解决的问题

把异构 GPU + 异构网络用于 RL 训练面临两类困难:

1. **现有 RL 训练系统几乎不考虑异构性**。verl、OpenRLHF 等假设同构 GPU + 同构高带宽网络。最相关的 StreamRL 把 GPU 分成两组 —— 一组跑 actor generation,另一组跑剩余任务 —— 但仍要求每组内部同构、且位于同一 data center,无法处理细粒度异构。

2. **直接套用 LLM 训练 / 推理的异构调度算法不可行**。RL workflow 远比单模型推理 / 训练复杂:典型 PPO 涉及 4 个模型(actor、critic、reward、reference)+ 6 个任务(actor generation、3 个 inference、actor/critic training)+ 复杂数据依赖。verl 的同构调度算法已经要枚举数百万到数十亿个 plan,耗时数百到数千秒;若把 Metis、HexGen-2 等异构调度算法分别套到每个模型 / 任务上,搜索时间还要再放大 1000–10000 倍,根本不可扩展。

需要的是一个能联合优化 (a) 模型 / 任务的 colocation 与并行,(b) 模型内并行(TP/PP/DP),(c) tasklet 到异构设备的细粒度分配 的统一调度算法,且能在合理时间内收敛。

## 3. 洞察与设计

**关键洞察**:RL 调度问题的搜索空间虽然指数级巨大,但具有天然的层次结构 —— task grouping、coarse GPU 分组、tasklet 到 device 的精细映射处于不同抽象层。把它分解成 5 层 coarse-to-fine 决策后,每一层的候选数量都可控,并且较粗层的 cost 模型评估足以指导哪些较细层的方向值得继续探索。基于这一观察,可以用 **nested successive halving (SHA)** 在两个最粗的层早早砍掉无前途分支,把搜索预算集中到有希望的子树上。

基于上述洞察,作者把问题形式化为 **constrained joint optimization**:寻找最优的 partitioning 策略 ρ 与 assignment 策略 σ,最小化 RL workflow 单 iteration 执行时间,约束包括每个 task 的 tasklet 数不超过 GPU 数、所有 tasklet 必须被分配,以及每个 device 的显存上限。论文证明该问题是 NP-hard(规约自 balanced graph partitioning 或 knapsack)。

**Multi-level Search Framework**(对应 Figure 1):

| Level | 决策 | 角色 |
|------|------|------|
| 1 | Task grouping(把 6 个 task 分到 disjoint group) | 实例化 ρ |
| 2 | Coarse-grained GPU assignment(决定每个 GPU group 的 GPU 数,不指定具体设备) | 实例化 σ |
| 3 | Medium-grained GPU assignment(把 task group 分配到具体 GPU) | 实例化 σ |
| 4 | Intra-model parallelization(决定每个 task 的 TP/PP/DP degree) | 实例化 ρ |
| 5 | Fine-grained GPU assignment(把 tasklet 分配到具体 GPU) | 实例化 σ |

**Search 策略**:Level 1–2 用 **nested SHA**,把任务组合 / GPU 组合视为 multi-armed bandit 的 arm,用 cost model 估计的执行时间作为损失;每轮淘汰一半 arm 并把剩余预算翻倍。Level 3–5 用 **带 two-level swap 的遗传算法**:在 Level 3 跨 task group 交换 GPU,在 Level 5 跨 tasklet group 交换 GPU,用变异 + 交换生成新候选后用 cost model 评估并替换最差个体。

**Cost Model**(详见 Appendix B,核心公式在 Section 3.3):

- 端到端 cost 按 RL 算法形态不同(synchronous PPO/GRPO、asynchronous PPO/GRPO)有不同的组合方式;Φ(·) 用 `max + (1-η)·(sum - max)` 参数化任务并行度
- 单任务 cost 按 generation / inference / training 区分 —— generation 额外考虑 HBM bandwidth(decoding 是 memory-bound),training 额外考虑 DP 通信和 pipeline bubble
- 通信 cost 按异构网络建模:对每条 ring,取所有 edge 上 `α + 数据量/β` 的最大值,再在所有可行 ring 上取最小

## 4. 实现细节

HetRL 在 verl 上构建,新增约 3k 行代码(Figure 2),包含四个组件:

- **Profiler**:收集异构环境信息 —— 各 GPU 的 TFLOPs / 显存容量 / HBM 带宽,跨节点延迟与带宽
- **Scheduler**:执行多层级搜索框架,产出 execution plan
- **Execution Engine**:基于 verl 扩展,支持细粒度资源分配。底层训练用 Megatron-LM,推理 / generation 用 vLLM
- **Load Balancer**:三种策略
  1. Actor rollout 阶段调整 DP group 内各 GPU 的 local batch size(用 cost model 估计)
  2. 其他任务(序列长度已知)把长序列样本分给更强 GPU
  3. 调整 PP stage 的 layer 分布,实现 layer-level 负载均衡

底层依赖 AWS OFI NCCL 和 AWS EFA 做跨节点通信。

## 5. 实验结果

**硬件**:64 GPU 测试床 —— 24×A100(40 GB,312 TFLOPS FP16)+ 24×L40S(48 GB,366 TFLOPS)+ 16×L4(24 GB,121 TFLOPS)。通过测量 10 个真实 region(AWS US/EU)的延迟与带宽并施加到测试床上,模拟四种网络场景:

| 场景 | 描述 |
|------|------|
| 1 Single-Region | 标准云内部署,无延迟控制 |
| 2 Multi-Region-Hybrid | Ohio + Virginia,跨 region 10 ms / 5 Gbps,部分边缘 GPU 限带 1 Gbps |
| 3 Multi-Country | 8 个欧洲 region,5–30 ms / 1.9–5.0 Gbps |
| 4 Multi-Continent | 欧美 8 个 region,5–60 ms / 0.9–5.0 Gbps |

**模型 / 算法**:Qwen 4B / 8B / 14B,PPO 与 GRPO 的同步 / 异步两个版本,GSM8k 数据集,prompt+response 各 1024 tokens,global batch 1024,8 responses per prompt。

**Baseline**:verl(同构 SoTA)和 StreamRL(作者基于 verl 复现的异步异构 SoTA)。

**端到端吞吐**(Figure 3,对比 verl):

| 场景 | Sync 加速 | Async 加速(vs verl-Async) |
|------|-----------|----------------------------|
| Single-Region | 1.51–2.05× | 1.10–1.31× |
| Multi-Region-Hybrid | 3.01–4.99× | 4.07–9.17× |
| Multi-Country | 1.40–3.07× | 1.71–4.0× |
| Multi-Continent | 2.24–5.46× | 4.38–10.76× |

跨 region 网络越复杂,HetRL 相对优势越大。

**调度算法效果**(Figure 4):对比 verl 调度、HetRL(simple,关闭 SHA + GA 只在模型内 swap)、HetRL 完整版本。HetRL 在所有四个场景下都比 simple 版本和 verl 收敛得更快、找到的 plan 估计 cost 更低,验证 SHA + two-level swap 的有效性。

**Load balancing**(Figure 5):同步 RL 下,Single-Region 场景吞吐提升最多 12%,Cross-Region 场景最多 18%(略低于 Metis 的 19–22%)。异步 RL 下提升不明显,因为瓶颈被 generation/training 之间的资源调度主导。

**GPU 组合影响**(Figure 6):用全部异构 GPU 比仅用 24×A100 提升 1.57–2.0×;HetRL 全部 GPU 与 verl 在限定同构 GPU 上的对比加速 1.57–4.33×。

总搜索 / 训练消耗 20,000 GPU-hours。

## 6. 批判性分析

1. **基线选择存在偏差**。论文承认 StreamRL 没有开源、由作者基于 verl 复现,但没有说明复现质量如何验证。在 Multi-Region-Hybrid 异步场景下 StreamRL 的吞吐居然比 verl-Async 还低 4–9 倍(对比 HetRL 的 9.17× 加速 ≈ HetRL/verl,而 HetRL/StreamRL 仅 1.11–1.27×)—— 说明 verl-Async 在异构环境下的"原生表现"非常差,把 verl-Async 当成 baseline 算出的 9.17× 加速比里有相当一部分来自 verl 调度算法在异构环境下的崩溃,而不是 HetRL 自身的设计胜利。如果只看 HetRL 与一个真正面向异构的 baseline(StreamRL)对比,加速比通常只有 1.1–3.7×。

2. **搜索成本未被透明披露**。Figure 4 用 "iterations" 衡量收敛速度,但每个 iteration 实际多少秒、HetRL 完整搜索一次需要多少分钟 / 小时,论文里没有给绝对数。"几百到几千秒"的同构搜索时间在前文是被作为问题的;HetRL 自己的 wall-clock 搜索开销 vs 单 iteration RL 训练时间的比例,直接决定其实用性,却未量化。

3. **Cost model 误差未评估**。SHA 砍 arm 的依据是 cost model 估值,作者把多达 30+ 个估算公式塞到 Appendix B,但全文没有 cost model 估计值 vs 实测时间的相关性分析(R²、MAPE 之类)。Figure 4 的 y 轴是 "Estimated Cost",不是真实执行时间,可能存在 Goodhart's law:HetRL 在 estimated cost 上 dominate,不一定在真实 wall-clock 上同样 dominate。

4. **测试床规模有限**。最多 64 GPU、3 种 GPU 型号、最大 14B 模型,但 RL post-training 真正紧迫的需求是 70B+(Llama 3、DeepSeek-V3 等)。模型一旦上 70B,actor 模型 / KV cache 可能放不下任何单张 L4 / L40S,intra-model parallelization 就被强制约束,SHA + GA 的搜索空间结构可能完全不同,论文没有讨论这一 scaling 行为。

5. **GRPO 与 PPO 加速差异未深入解释**。论文只说"GRPO 没有 critic 所以 gap 不同",但 GRPO 加速大多比 PPO 小,这可能反映 HetRL 主要在协调 critic 模型相关任务上发力 —— 而行业未来方向(DeepSeek-R1 等)正逐步抛弃 critic,HetRL 的 headroom 可能在收窄。

6. **正确性未验证**。论文坦承没有研究跨异构 GPU 数据交换可能带来的精度问题对收敛的影响,也没有给训练曲线 / 模型质量对比 —— 只比 throughput。理论上跨 region 的 mixed-precision 路径若引入 BF16/FP16 累积误差,policy 可能漂移,这是把 RL 部署到异构环境的硬约束之一。

7. **跨 region RL 训练的真实部署约束未触及**。跨 region 通信受云厂商 egress 计费、带宽配额、合规边界(GDPR、数据主权)限制,论文 Section 6 只说"不做 cost-efficiency 比较",但这是工业部署能否成立的关键。

## 7. AI Infra / MLSys 视角

这篇论文对 AI Infra 研究有几个值得借鉴的角度:

- **Multi-level search 框架的可推广性**。把"模型 colocation → coarse 资源分配 → fine 资源分配"分层 + 用 SHA 做层间预算分配,这一模式对所有需要联合优化"任务图 + 设备图"的系统问题都适用 —— 比如 multi-tenant LLM serving、agentic workflow 调度、RAG pipeline 上的 placement。SHA 的 "halving + budget doubling" 思想从 hyperparameter tuning(Hyperband)迁移到系统调度的 cost-model 评估,是相对新颖的 cross-pollination。

- **RL workflow 作为新的工作负载**。现有 ML 系统研究主要把 LLM 训练 / 推理当作 single-model 问题,但 agentic / RL 时代会有越来越多 multi-model multi-task workflow(actor + critic + reward + tools + verifier),这类调度问题在异构 / 弹性环境下还是空白。HetRL 是一个 reference design,但还有大量方向没解决:async RL 下 staleness vs throughput 的 Pareto 边界、speculative rollout、per-iteration 弹性扩缩。

- **可跟进的 future work**:
  1. **Cost model 自标定**:自动从前几个 iteration 的实测时间 fit cost model 参数,缩小 estimated vs real 的 gap,让 SHA 决策更可靠
  2. **70B+ 大模型场景**:研究 actor 模型本身需要跨节点切分时,multi-level framework 如何与 Megatron 的 3D parallel 复合,以及 KV cache 的跨异构 GPU placement
  3. **Agent 训练的扩展**:RLHF 之外,更复杂的 agentic RL(tool use、self-play、长 trajectory)有更多 model + tool 角色,cost model 和 task 抽象需要重新设计
  4. **跨 region 数据 / 权重移动的最小化**:Resharding cost(C_reshard)在论文里被简单建模,实际跨 region 移动 actor 权重 GB 级数据耗时巨大,值得有专门的 weight broadcast / 局部更新研究
  5. **混合精度跨 region 收敛性**:实证跨 GPU 代际(A100 BF16 vs L4 FP16)对 RL 收敛精度的影响,如果有显著漂移,如何用 gradient 校正或 critic 重置缓解

- **最有价值的延伸切入点**:把 HetRL 的多层调度 + SHA 思路与 disaggregated serving 结合,做 **agentic workflow 的统一调度器** —— Agent 一次推理涉及 LLM(decoding,memory-bound)+ tool calls(network/IO-bound)+ embedding/retrieval(throughput-bound),把它们 colocate 到合适的异构资源上,可能是 next-gen Agent serving 系统的核心问题。

---

## 8. 总结

HetRL 是第一个面向异构 GPU + 异构网络的 RL post-training 系统,核心贡献是把 RL 调度形式化为约束联合优化问题并设计了 multi-level search + nested SHA + 双层 swap GA 的可扩展求解框架,在 verl 上工程化为完整系统。在 64-GPU 三型号 + 模拟跨 region 网络的测试床上,相对 verl 最高 9.17× 吞吐提升、平均 3.17×。论文最适合的场景是有大量散落中端 GPU 想合并成 RL 训练资源池的团队;主要局限是模型规模(只测到 14B)、cost model 精度未做误差分析、不评估精度对收敛的影响,以及跨 region 部署的 cost-efficiency / 合规问题被刻意排除。
