# HetRL: Efficient Reinforcement Learning for LLMs in Heterogeneous Environments

## 一、背景

随着 LLM 规模持续增长，强化学习（RL）已成为提升 LLM 推理能力和价值对齐的主流后训练技术（PPO、GRPO 等）。当前 RL 训练依赖单一集群中大量同构高端 GPU 和高带宽网络，但现实中高端 GPU 严重短缺，而大量中端或上一代 GPU 分布在全球各数据中心处于闲置状态。如何利用这些异构 GPU 和异构网络进行高效 RL 训练，是一个具有实际意义的问题。

与单模型训练/推理不同，RL 工作流涉及多个模型（actor、critic、reference、reward）和多种任务（generation、inference、training），计算和数据依赖关系复杂，这使得异构环境下的调度问题远比单模型场景困难。

---

## 二、要解决的问题

1. **现有 RL 训练系统仅为同构环境设计**：verl、OpenRLHF、DeepSpeed-Chat 等 SoTA 系统的调度算法不考虑硬件异构性，在异构 GPU 和网络上无法实现高效部署。

2. **直接套用异构感知算法不可行**：已有的异构感知 LLM 训练/推理调度算法（DTFM、Metis、Helix、ThunderServe 等）针对单模型/单任务，搜索一个模型的近优方案就需要数百到数千秒。RL 工作流涉及多个模型和任务的联合优化，简单组合导致搜索空间爆炸，既不实际也不可扩展。

3. **StreamRL 的局限**：StreamRL 虽然支持跨数据中心的异构部署，但要求同一组内 GPU 必须同构且位于同一数据中心，无法处理真正的细粒度异构环境。

4. **搜索空间复杂度极高**：需要联合优化任务分组、GPU 分配、模型内并行策略、以及 tasklet 到具体 GPU 的映射，这是一个 NP-hard 的受约束联合优化问题。

---

## 三、洞察与设计

**关键洞察**：RL 工作流中不同任务（generation、inference、training）具有截然不同的计算、内存和通信特征——generation 是内存带宽瓶颈需要 KV cache，training 是计算瓶颈需要梯度和优化器状态——这种异构性恰好与硬件的异构性形成匹配机会：将不同特征的任务分配到不同能力的 GPU 上，可以比同构部署更高效地利用资源。

基于此洞察，HetRL 的核心设计包括：

**多级搜索框架（Multi-Level Search Framework）**：将 NP-hard 的联合优化问题分解为 5 个层级：
- Level 1：任务分组（Task Grouping）——将 RL 任务划分为不相交的组
- Level 2：粗粒度 GPU 分配——确定每组的 GPU 数量
- Level 3：中粒度 GPU 分配——将具体 GPU 分配给任务组
- Level 4：模型内并行化——确定每个任务的 TP/PP/DP 策略
- Level 5：细粒度 GPU 分配——将 tasklet 映射到具体 GPU

**嵌套 Successive Halving（SHA）**：在 Level 1 和 Level 2 使用嵌套 SHA 进行预算分配，逐步淘汰不佳方案，将更多搜索预算分配给有前途的候选。

**遗传算法 + 双层交换（GA with Two-Level Swaps）**：在 Level 3-5 使用 GA 搜索，交换操作同时在任务组间（Level 3）和 tasklet 间（Level 5）进行，打破了先前工作仅在单模型内交换的局限。

**代价模型（Cost Model）**：基于设备和网络属性，对 TP/PP/DP 通信、计算、pipeline bubble、HBM 带宽等进行分析建模，快速估算执行时间。

---

## 四、实现细节

- 基于 verl 构建，新增约 3000 行代码，包含 scheduler、profiler 和支持细粒度资源分配与负载均衡的 execution engine
- 使用 Megatron-LM 作为训练引擎，vLLM 作为推理引擎
- Profiler 自动收集硬件信息（计算能力、内存容量、HBM 带宽、节点间延迟和带宽）
- 负载均衡策略分两类：
  - **数据级**：根据 GPU 能力调整 DP 组内的 local batch size，将长序列样本分配给强 GPU
  - **层级**：根据代价模型调整 pipeline 各阶段的层数分配
- 代价模型详细建模了 transformer 各组件的计算、TP/PP/DP 通信、pipeline bubble、decoding HBM 带宽等开销
- 支持同步和异步 PPO/GRPO 四种模式
- NP-hard 性证明通过归约到 balanced graph partitioning 和 knapsack 问题

## 五、实验结果

**硬件环境**：64 GPU 测试平台（24×A100、24×L40S、16×L4），模拟 4 种网络场景（单区域、混合多区域、多国、多洲）

**模型与算法**：Qwen-4B/8B/14B，PPO 和 GRPO（同步+异步），GSM8k 数据集

| 场景 | vs verl-Sync | vs verl-Async | vs StreamRL-Async |
|------|-------------|---------------|-------------------|
| Single-Region | 1.51∼2.05× | 1.10∼1.31× | 1.10∼1.31× |
| Multi-Region-Hybrid | 3.01∼4.99× | 4.07∼9.17× | 1.11∼1.27× |
| Multi-Country | 1.40∼3.07× | 1.71∼4.00× | 1.19∼1.50× |
| Multi-Continent | 2.24∼5.46× | 4.38∼10.76× | 2.25∼3.72× |

**关键发现**：
- 平均 3.17× throughput 提升，最高 9.17×
- 负载均衡在单区域带来最高 12% 提升，跨区域最高 18%
- 调度算法收敛速度显著优于 verl 调度器和简化版 HetRL
- 利用异构 GPU 比仅用有限同构 A100 可获得 1.09∼1.77× 加速
- 总评估消耗约 20,000 GPU-hours

## 六、批判性分析

1. **硬件多样性有限**：仅测试 NVIDIA 三款 GPU（A100、L40S、L4），且都是 Ada/Ampere 架构。未涉及 H100、AMD MI300X 等其他硬件，也未测试不同网络栈（仅 AWS EFA/OFI NCCL）。在真实异构环境中，硬件多样性远超论文设置。

2. **网络异构是模拟的**：并非真正的跨地域部署，而是在单一测试平台上通过延迟/带宽控制模拟不同区域的网络特征。这回避了真实跨地域部署中的诸多工程问题（网络抖动、路由变化、故障恢复）。

3. **9.17× 的最大加速数字需要审慎解读**：这是在最极端的 Multi-Region-Hybrid 场景下、异步模式、特定 workload 的结果。同场景下 vs StreamRL 仅 1.11∼1.27×。论文标题和摘要突出 "up to 9.17×" 容易产生误导。

4. **回避了收敛性问题**：论文明确承认保持 RL 算法不变、仅评估 throughput，不调查异构 GPU 间数据交换可能带来的精度问题。对于异步 RL 训练，data staleness 对最终模型质量的影响也未讨论。

5. **搜索开销未充分量化**：虽然论文展示了收敛曲线，但未报告调度搜索本身的绝对时间开销。对于需要频繁调整的弹性场景，调度开销可能成为瓶颈。

6. **成本效率分析缺失**：论文以"GPU 定价波动"为由完全回避了成本分析。但这恰恰是使用异构 GPU 最重要的决策因素——如果异构部署虽然 throughput 更高，但总成本也更高（因为需要更多低端 GPU），其实际价值就需要重新评估。

7. **所有模型使用相同大小**：实验中 RL workflow 的 actor/critic/reference/reward 均使用相同大小的 LLM，但实际中 reward 和 critic 模型通常比 actor 小得多。这一简化可能低估了真正异构 workload 下 HetRL 的优势（或暴露新问题）。

## 七、AI Infra / MLSys 视角

**启发价值**：
- HetRL 首次系统性地处理了多模型、多任务 RL 工作流在异构环境下的调度问题，其多级搜索框架的 decomposition 思路可以推广到其他复杂的多阶段 AI 工作流（如 MoE 训练、多模态训练等）
- 嵌套 SHA + GA 的组合搜索策略在大搜索空间中实现了高效探索，这一范式对自动并行化系统设计有借鉴意义

**可迁移的技术**：
- 代价模型的分层建模方式（component → task → end-to-end）可用于其他异构部署场景
- 双层交换的遗传算法打破了"只在单模型内优化"的局限，适用于任何多阶段 pipeline

**值得跟进的方向**：
1. **弹性调度与容错**：论文未处理 GPU 故障和动态资源变化，而跨地域异构环境中这恰恰是核心挑战。如何在 HetRL 框架中实现轻量级重调度？
2. **异构 GPU 上的混合精度策略**：不同 GPU 的 FP16/BF16/FP8 支持不同，如何在异构环境中利用不同精度能力？
3. **与 Spot/Preemptible 实例结合**：异构 GPU 的重要来源是 spot 市场，HetRL 的调度需要处理实例中断
4. **推理-训练混合调度**：将 RL 训练中的推理任务与在线 serving 共享 GPU 资源，进一步提高利用率

**最有价值的切入点**：将 HetRL 的多级搜索框架与 Sailor 等弹性训练系统结合，研究资源动态变化下的在线重调度问题——这是异构环境实际落地最大的障碍。

---

## 八、总结

HetRL 是首个面向异构 GPU 和网络环境的 LLM RL 训练系统，将调度问题形式化为受约束联合优化，通过多级搜索框架分解搜索空间，结合嵌套 SHA 和遗传算法高效搜索近优执行计划。在 64 GPU 测试平台上，HetRL 在多种 workload 和网络场景下平均获得 3.17× 的 throughput 提升（最高 9.17×）。系统主要适用于拥有大量分散异构 GPU 资源的组织进行 LLM 后训练。主要局限在于硬件多样性有限、网络环境为模拟、缺少成本效率和模型收敛性分析。
