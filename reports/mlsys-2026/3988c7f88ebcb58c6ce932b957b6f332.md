# ProToken: Token-Level Attribution for Federated Large Language Models

**作者**：Waris Gill, Ahmad Humayun, Ali Anwar, Muhammad Ali Gulzar
**会议**：MLSys 2026
**链接**：https://proceedings.mlsys.org/paper_files/paper/2026
**源文件**：[[3988c7f88ebcb58c6ce932b957b6f332.pdf]]

---

## 1. 背景

联邦学习（Federated Learning, FL）允许多个持有私有数据的组织在不交换原始数据的前提下协同训练模型，已经成为隐私敏感场景下训练机器学习模型的主流范式。近几年 FL 也被拓展到 LLM 微调：FederatedScope-LLM、FedBPT、FedBiOT 等框架允许多家医疗机构、金融机构在自有私有数据上联合微调同一个 LLM。

但联邦训练出来的 LLM 一旦部署到真实应用，就出现一个传统 FL 研究没解决的问题：当全局模型生成某条响应时，**究竟是哪家客户端的数据推动了这条输出**？这个问题在经典图像分类 FL（TraceFL、FedDebug 等）里已经有 neuron provenance 类方案，但自回归文本生成 + transformer 架构 + billion 级参数量让这类方法全部不再适用。

---

## 2. 要解决的问题

给定全局联邦 LLM $G$ 和它对一条 prompt 生成的响应 $\mathbf{y}$，输出一个归因向量 $\mathcal{P} \in \mathbb{R}^K$，其中 $\mathcal{P}(i)$ 量化第 $i$ 个客户端对该响应的贡献度，$\hat{i} = \arg\max_i P_i$ 即为"主要责任客户端"。解决此问题同时服务于四类应用：

1. **恶意客户端定位**：当全局 LLM 出现后门触发、拒答、事实错误时，精确定位是哪家机构的数据污染所致
2. **贡献度公平奖励**：按真实贡献分配联邦协作收益
3. **可解释性 / 可审计性**：给医生、监管机构、合规团队提供可追溯的模型行为来源
4. **智能 client selection**：基于历史贡献做更智能的轮次参与策略

三大技术挑战：

1. **自回归带来的级联依赖**：每个 token 依赖所有之前生成的 token，客户端的影响随序列传播并相互混淆，无法独立归因
2. **计算不可行**：若朴素地追踪每一层每一神经元——1B 参数 × 5 客户端 × 100 token ≈ 5 × 10¹¹ 次计算
3. **噪声活化**：客户端的某些神经元可能对所有 token 都强烈激活（例如医学领域神经元对 "the" 也激活），若不加权会让归因被无关活化稀释

此外还有一个**根本性评估难题**：LLM 的输出可能来自客户端贡献，也可能来自基座模型预训练知识，没有 ground truth 就无法验证归因是否正确。

## 3. 洞察与设计

**关键洞察**：作者基于三条核心观察构建方法论：

1. **FL 聚合在参数层面是线性的**：FedAvg/FedProx 都满足 $\theta_{\text{global}} = \sum_i \rho_i \theta_i$，因此对任何输入 $h$ 可以分解为 $\theta_{\text{global}}^\top h = \sum_i \rho_i (\theta_i^\top h)$，即每个神经元的激活前输出等于各客户端同位置神经元输出的加权和——这一线性分解在激活函数前对每个神经元都严格成立，是 provenance 可追踪的数学基础
2. **Transformer 后几层集中存放任务特定知识**：早期层负责语法、低级语义；后期层负责高层概念和任务知识。因此只监测最后 N 个 block 里的 self-attention Output Projection + MLP 最后一层，就能覆盖客户端对生成 token 的主要贡献，避免全参数追踪
3. **Token 对应的 logit 相对于某层激活的梯度可作为相关性权重**：对每个输出 token $x_j$，gradient $\mathbf{g}_{x_j}^\ell = \partial \text{logit}_{x_j} / \partial \mathbf{h}_G^\ell$ 直接指示了该层各维度对 token 预测的影响力，梯度小的维度无论激活多大都无关，可以自动过滤

**核心设计**：ProToken 的工作流由一个外层 token 循环（Algorithm 1）和一个内层每客户端归因循环（Algorithm 2）组成：

- **Step 1**：全局模型 $G$ 正常自回归生成 token $x_j$，记录选定层集合 $\mathcal{L}$（最后 N 个 block 的 Output Projection + 最终 MLP 层）的输入 `inputℓ_G` 和激活 `hℓ_G`
- **Step 2**：对每个 token，反传计算 $\mathbf{g}_{x_j}^\ell$
- **Step 3**：对每个客户端 $i$，把 $\text{input}^\ell_G$ 注入客户端模型 $C_i$ 的对应层（用客户端权重 $\theta_i^\ell$ 重新前传），得到客户端特定激活 $\mathbf{h}_i^\ell$
- **Step 4**：客户端在该 token 该层的 provenance score 为内积 $\mathcal{P}_{i,x_j}^\ell = \langle \mathbf{h}_i^\ell, \mathbf{g}_{x_j}^\ell \rangle$——活化 × 梯度 = 相关性加权的客户端贡献
- **Step 5**：跨选定层求和 → 跨生成序列所有 token 求和 → softmax 归一化得到每客户端概率 $P_i$，取 $\arg\max$ 得责任客户端

整个计算只依赖模型权重、激活、梯度，不需要访问任何客户端原始数据，兼容 FL 隐私约束。

## 4. 实现细节

- **框架集成**：基于 Flower 做 FL 编排，HuggingFace Transformers 做模型处理
- **聚合策略**：FedAvg，AdamW 优化器（lr=5e-5, weight_decay=0.001），per-device batch size 32
- **层选择**：实测显示最后 3 层即可达到 100% 归因准确率，可线性 trade off 开销与覆盖范围
- **归因在生成时并发进行**：Algorithm 1 的外循环跟生成循环对齐，每生成一个 token 立即做归因，不需要保存整个序列再一次性归因
- **Ground truth 构造**（关键评估贡献）：借用 backdoor injection 作为"可验证标签"——在指定客户端训练集注入触发短语 `!!!BadMagic!!!` → 固定 sentinel 响应 `"I'm sorry, but as an AI assistant, I cannot follow the given instruction."`。推理时只要 sentinel 响应出现，就 100% 来自这些 trigger 客户端，提供无歧义归因标签。作者明确声明 backdoor 仅用于评估，不用于攻防研究
- **模型规模**：Gemma-3-270M, SmolLM2-360M, Llama-3.2-1B, Qwen2.5-0.5B 四种 270M–1B 小模型，代表联邦部署的实际算力约束
- **硬件**：2 块 NVIDIA H200 + 1 块 A100，每客户端 2 CPU + 1 GPU

## 5. 实验结果

**实验规模**：16 configurations = 4 模型 × 4 领域（医疗/金融/数学/代码）× 10 轮 × 6 客户端（其中 2 个注入后门），再加上 55 客户端扩展性实验（25 恶意 + 30 良性，10 轮随机采样/轮，15 轮训练）。

**RQ1 跨架构 × 跨领域准确率**：

| 指标 | 结果 |
|---|---|
| 16 configurations 平均归因准确率 | **98.62%** |
| 准确率范围 | 40%–100% |
| Gemma / SmolLM 多数场景 | 100% |
| Llama / Qwen 更大模型 | >92.5% |
| 收敛速度 | 1–2 轮联邦训练即稳定 |

Figure 3 的 box plot 显示，责任客户端（clients 0-1）和非责任客户端（clients 2-5）的 log-scale 贡献概率在所有 16 个子图中完全不重叠，Gemma 上差距可达 10⁶ 量级——这是近乎二值化的归因信号，而非模糊的概率估计。

**RQ2 Gradient Weighting Ablation**：

| 条件 | 平均准确率（per-layer 平均） | 范围 |
|---|---|---|
| 启用 gradient weighting | **66.34%** | 55.0%–83.33% |
| 仅用激活幅值 | 35.71% | 22.94%–56.20% |
| 相对提升 | **1.86×** | — |

关键是：即使关掉梯度加权，单凭激活也能达到 22%–56%（说明激活本身带有弱信号），但不足以达到可靠归因；梯度加权把信号放大到能做生产级决策的水平。

**RQ3 计算效率**：监控层数从 3 增加到几乎全部时，Gemma-3-270M 的开销从 1.10s 到 1.42s（29% 增量），最深模型最高到 1.87s，**线性可调**且所有层数设定下都能保持 100% 准确率——证实 provenance 信号集中在后几层，监控少量层即可。

**RQ4 扩展性**：从 6 客户端扩到 55 客户端（9.2× 增长，25 恶意），Gemma 准确率 92.00%，Qwen 95.24%。相对 6 客户端基线的 98.62%，仅轻微下降，且责任/非责任组的概率分布仍然清晰分离。

## 6. 批判性分析

1. **"可验证 ground truth" 方法论漏洞**：作者用 backdoor injection 做 ground truth 的理由是「只有后门客户端能产生 sentinel 响应」，但 backdoor 信号本身是**极度强烈且刻意设计的集中信号**——单一短语 → 固定完整句子，这使得归因难度被显著低估。真实世界的"客户端贡献"分布得多得多（医疗客户端可能贡献了 10% 的医学术语偏好，不对应任何可识别的 sentinel）。论文全部准确率数字都建立在 backdoor 评估之上，98.62% 并不等于"ProToken 能在真实细粒度贡献归因上达到 98.62%"。作者仅在一句话里承认这是 proxy，但全篇结论仍直接表述为"attribution accuracy"。
2. **评估仅限 270M–1B 小模型**：论文强调"联邦部署受算力约束所以选小模型是合理的"，但目前 FL + LLM 的研究前沿已经推到 7B–70B。小模型的后几层足够识别 backdoor 不代表大模型的后几层对细粒度贡献也能识别——大模型的知识分布更深、更分散，后 N 层假设的泛化性存疑。
3. **层选择假设过于宽松**："Output Projection + 最后 MLP 层" 是 hypothesis（作者原文用 "We hypothesize" 和 "We posit"），没有提供对比实验：如果改监控中间层、或只监控 attention、或只监控 MLP，会不会同样达到 100%？Figure 5 只变了"监控多少层"但没变"监控哪些层"，层选择的必要性论证不充分。
4. **归一化的 softmax 破坏了信号幅度**：原始 $\mathcal{P}_{i,\mathbf{y}}$ 做 softmax 后，只要责任客户端比其他人大，就会被放大到接近 1。这让 "probability 的清晰分离" 变成 softmax 的几何效果而非归因本身的强度指标。Figure 3 用 log-scale 看到的 10⁶ 差距很可能只是 softmax 对数几率的放大。
5. **未对比 FedAvg 以外的聚合**：公式 3 的线性分解假设 $\theta_{\text{global}} = \sum_i \rho_i \theta_i$ 对 FedAvg/FedProx 成立，但对 FedNova、FedOpt、FedAdam 等自适应优化器方案，聚合不严格是参数线性组合。论文只在 FedAvg 上做了评估，对现代 FL 优化器的适用性未知。
6. **前向传播开销被低估**：Algorithm 2 对每个 token、每个客户端都要前传一次选定层，55 客户端 × 100 token ≈ 5500 次子网前传。Figure 5 报的 1.1–1.9s 是 6 客户端场景，55 客户端时应线性放大到 10s+ 级别，但论文没给出此关键数字。
7. **"preserves FL privacy" 的说法值得推敲**：ProToken 需要客户端把自己的 $\theta_i$ 持续暴露给执行归因的那一方（通常是服务器）才能做子网前传。即便原始数据没泄露，客户端的完整更新权重本身就可能通过 model inversion / membership inference 攻击还原部分数据——FL 领域这是已有大量文献的风险。作者仅在一句话里声明"只操作 updates/activations/gradients"就算满足隐私。

## 7. AI Infra / MLSys 视角

对 AI 系统研究者来说，ProToken 核心价值**不是 FL provenance**本身，而是它隐含的几个可迁移 idea：

1. **"聚合线性性 + 层选择 + 梯度加权" 三件套是通用的 attribution 骨架**：这个组合可以迁移到任何"输出由多个可加权组件共同生成"的 LLM 系统。典型场景：
   - **MoE 模型的专家贡献归因**：MoE 的 gating weight 是显式的 $\rho_i$，可以用同样的 gradient × expert activation 做 per-token 专家归因，帮助调试"为什么这个 token 路由到了专家 X"、"哪些专家对幻觉负责"
   - **模型合并 (Model Merging / SLERP / TIES)**：当多个 fine-tuned 模型合并时，用户想知道输出来自哪个源模型——这本质上与 ProToken 的 FL 设置同构
   - **LoRA Adapter 组合**：多个 LoRA adapter 叠加推理时，哪个 adapter 对具体输出负责？ProToken 框架几乎零改动可以套用
2. **"监控最后 N 层"的结论给 KV cache / activation 存储策略启发**：如果知识集中在后 N 层，那么推理时是否只有后 N 层的 activation 值得长期保存用于后续分析？对 debug pipeline、对 RAG + LLM 的混合归因、对在线模型回溯都有借鉴价值
3. **生成时 per-token 反传的成本与可行性**：ProToken 在 generation time 做每 token 反传以得到 gradient，这与 recent steering / activation patching 研究是同族技术。论文实测 Gemma-270M 上 100 token 归因只增加 ~1s 开销，说明 **"生成时同步计算 gradient-based 分析"在小模型 + 窄层选择下是工业可行的**——这对生产级 interpretability tooling 是重要信号
4. **Ground truth 构造方法值得 ML systems evaluation 圈借鉴**：用 backdoor / trigger 作为"可验证的人工信号"来测归因方法是个实用 trick，可以泛化到"测 RAG 是否真的用了某份文档"（把特定 token 注入文档）、"测 memory system 是否真的调用了某条记忆"等场景

**具体可跟进的研究方向**：

- **把 ProToken 搬到 MoE 上做专家级归因**：用 DeepSeek-MoE、Mixtral 做实验，量化每个 expert 对 hallucination token 的贡献。这是小实验室可做的 focused work，核心改动是把 $\rho_i$ 从 FL 聚合权重换成 MoE routing 权重
- **细粒度（非 backdoor）贡献归因的评估框架**：为 ProToken 类方法建立一个更接近真实世界的 benchmark——例如按领域切分数据、用 influence function 做 oracle、跨 client 数据冗余度测 robust 性
- **gradient-free 变体**：gradient 需要反传，对超大模型开销大。能否用 forward-only 近似（例如 log-linear 扰动、Jacobian 采样）替代梯度同时保持 1.86× 提升？
- **把层选择从 "hypothesis" 变成 "learned"**：用少量带标签的归因样本训练一个元层选择器，预测该 prompt 需要监控哪些层。对不同 prompt 自适应切换层集合，可能在大模型上解锁新效率

---

## 8. 总结

ProToken 是首个面向联邦 LLM 的 token-level provenance 归因方法，用 "FL 聚合线性分解 + 最后 N 层选择 + gradient × activation 相关性加权" 三个关键设计把原本 500B 次计算的 naive 归因压缩到秒级，在 16 个模型/领域配置上达到 98.62% backdoor 归因准确率、从 6 客户端扩到 55 客户端后仍保持 92%+。核心贡献是打通了 FL provenance 从分类模型到生成模型的理论与实现路径，并贡献了一套基于 backdoor injection 的可验证归因评估框架。主要局限在于：评估全部依赖 backdoor proxy，不等于真实细粒度贡献归因能力；仅在 ≤1B 模型上测试，对大模型泛化性未验；层选择基于未经对比实验的假设；"隐私保护"依赖客户端持续暴露完整权重，对 model inversion 风险讨论不足。方法论本身（聚合线性 + 层选择 + 梯度加权）对 MoE 归因、模型合并归因、LoRA 组合归因等相邻场景有直接迁移价值，值得 AI infra 研究者关注。
