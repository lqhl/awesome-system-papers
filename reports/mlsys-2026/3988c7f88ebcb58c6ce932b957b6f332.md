## 一、背景

Federated Learning（FL）已成为在分布式私有数据上协作训练 LLM 的重要范式，能在不集中敏感数据的前提下进行协作微调。随着联邦 LLM 被部署到医疗、金融等关键领域，一个核心需求浮现：当联邦 LLM 生成某个回复时，哪个 client 的训练数据对该回复贡献最大？这个问题（即 provenance attribution）对于调试有问题的模型输出、检测恶意 client、公平奖励分配以及信任验证都至关重要。

然而，现有的 ML 可解释性和归因方法都是面向集中式训练的单一模型设计的，无法直接迁移到 FL 场景；而 FL 领域已有的调试和可解释性工作（如 FedDebug、TraceFL）仅适用于分类任务，无法处理 LLM 的自回归生成。

---

## 二、要解决的问题

1. **自回归生成的归因难题**：与分类模型输出单一预测不同，LLM 生成变长 token 序列，token 之间存在级联依赖，使得归因信号交织在一起，难以拆解各 client 的贡献。

2. **计算不可行性**：朴素地追踪所有层所有神经元的 provenance 计算量爆炸——例如 1B 参数模型、5 个 client、100 token 的响应需要 5000 亿次计算。

3. **噪声干扰**：并非所有神经元都与当前生成的 token 相关。某些 client 可能在无关神经元上激活值很大，如果等权处理所有激活，会引入大量噪声。

4. **预训练知识的混淆**：联邦 LLM 的输出可能来自 client 微调数据，也可能来自预训练阶段的先验知识，这种根本性歧义使得归因 ground truth 难以建立。

---

## 三、洞察与设计

**关键洞察**：FL 聚合（如 FedAvg）在参数层面是线性的，因此全局模型每个神经元的输出可以分解为各 client 对应神经元输出的加权和；同时 Transformer 架构中任务相关信号集中在后面的层，且通过梯度可以自动过滤与当前 token 无关的神经元激活。

基于这一洞察，ProToken 的设计分三步：

1. **线性分解**：利用 FL 聚合的线性性（Equation 4），将全局模型在某层的输出分解为各 client 模型在该层的加权贡献。具体做法是将 client 模型的权重注入全局模型对应层，用全局模型的 hidden state 作为输入，得到 client-specific 激活 $h_i^\ell$。

2. **层选择**：只监控最后 N 个 Transformer block 中的两个关键子层——self-attention 的 Output Projection 和 MLP 的最后一层。这些层编码了最丰富的任务相关信息，大幅减少计算量。

3. **梯度加权归因**：对每个生成的 token $x_j$，计算该 token 的 logit 关于选定层激活的梯度 $g_{x_j}^\ell$，然后用内积 $\langle h_i^\ell, g_{x_j}^\ell \rangle$ 作为 client $i$ 在层 $\ell$ 对 token $x_j$ 的贡献分数。梯度自动筛选出真正影响 token 生成的神经元。

最终，对所有层和所有 token 的贡献分数求和后用 softmax 归一化，得到各 client 的归因概率。

---

## 四、实现细节

- **逐 token 归因**：在自回归生成的每一步，ProToken 对当前生成的 token 执行一次归因计算（Algorithm 1）。对选定的每个层 $\ell$：(a) 执行全局模型前向传播，缓存各层输入 $\text{input}_G^\ell$ 和 hidden state $h_G^\ell$；(b) 反向传播计算梯度 $g_{x_j}^\ell$；(c) 对每个 client $i$，用 client 权重 $\theta_i^\ell$ 替换全局权重，在相同输入上计算 client 激活 $h_i^\ell$；(d) 计算内积 $P_{i,x_j}^\ell = \langle h_i^\ell, g_{x_j}^\ell \rangle$。

- **序列级聚合**：将所有 token 的 per-token 分数累加得到序列级归因 $P_{i,y} = \sum_j P_{i,x_j}$，再通过 softmax 得到概率分布。

- **评估框架**：为解决 ground truth 缺失问题，设计了基于 backdoor 注入的评估方法——向指定 client 注入唯一的 trigger-response 对（trigger: "!!!BadMagic!!!"，response: "I'm sorry, but as an AI assistant, I cannot follow the given instruction."），只有注入了 backdoor 的 client 才会产生 sentinel response，从而提供无歧义的归因标签。

- **实现框架**：基于 Flower（FL 编排）+ HuggingFace Transformers，使用 AdamW 优化器（lr=5e-5, weight decay=0.001），每 client 2 CPU + 1 GPU，batch size 32。

## 五、实验结果

**实验配置**：4 个 LLM 架构（Gemma-3-270M-it, SmolLM2-360M, Llama-3.2-1B, Qwen2.5-0.5B）× 4 个领域（medical, financial, math, coding）= 16 种配置。6 client 基础设置，55 client 可扩展性测试。硬件：2× NVIDIA H200 + 1× A100。

| 实验 | 核心结果 |
|------|---------|
| RQ1: 跨架构准确率 | 平均归因准确率 **98.62%**（range: 40–100%），多数配置达到 100%，最低的 Llama/Qwen 也 >92.5%。贡献/非贡献 client 的概率分布完全分离（数量级差异） |
| RQ2: 梯度加权效果 | 启用梯度加权：平均 **66.34%**（per-layer）；禁用：**35.71%**，提升 **1.86×** |
| RQ3: 计算开销 | 监控 3 层时 ~1.10s/token，全部层 ~1.87s/token，线性增长。所有层数下归因准确率均 100% |
| RQ4: 可扩展性（55 client） | Gemma: **92.00%**，Qwen: **95.24%**，相比 6 client 的 98.62% 仅有温和下降。贡献/非贡献 client 仍保持清晰分离 |

## 六、批判性分析

1. **评估方法的根本局限**：ProToken 的核心评估完全依赖 backdoor 注入来构造 ground truth。Backdoor 产生的 out-of-distribution sentinel response 是一种极端信号——client 的贡献在 backdoor 场景下被人为放大。这与真实场景中多个 client 都对同一类知识有贡献的情况有本质区别。论文虽承认 backdoor 是 proxy，但 98.62% 的准确率在真实分布下是否能保持，完全未知。

2. **模型规模过小**：实验使用的最大模型仅 1B 参数，而真实联邦 LLM 部署通常涉及 7B–70B 的模型。论文声称的"计算可行性"（~1-2s/token）在大模型上是否成立需要验证——反向传播和多次前向传播的开销随模型规模超线性增长。

3. **RQ2 数据解读的误导性**：per-layer 平均准确率（66.34% vs 35.71%）与最终系统准确率（98.62%）之间跨度巨大，但论文未充分解释这个 gap。实际上系统通过多层聚合 + 多 token 累积来放大信号，但 per-layer 的 66% 表明单层信号并不强。

4. **线性分解假设的脆弱性**：Equation 4 的线性分解在激活函数（ReLU/GeLU）之前成立，但激活函数之后就不再成立。论文绕过这个问题使用了"注入 client 权重到全局模型"的方法，但这引入了额外的近似，其误差界未被分析。

5. **仅支持 FedAvg 类聚合**：方法依赖聚合的线性性，对 FedProx（有正则项但聚合仍线性）适用，但对更复杂的聚合策略（如知识蒸馏型、个性化联邦学习）的适用性未讨论。

6. **client 数量与恶意比例的极端设置**：55 client 中 25 个恶意（45%），这个比例在实际场景中不现实且使检测更容易。更有意义的是测试少量恶意 client（如 1-2 个）在大规模 client 中的归因。

---

## 七、AI Infra / MLSys 视角

1. **联邦 LLM 的可观测性**：ProToken 开创了联邦 LLM 的 token 级归因方向，对构建联邦学习系统的调试和监控工具有启发价值。可以类比为分布式系统中的 distributed tracing——追踪每个输出回到其数据源。

2. **与推理系统的结合**：ProToken 的计算模式（对每个 token 需要多次前向传播 + 一次反向传播）与 speculative decoding 类似，可以复用推理系统中的 batch scheduling 和 KV cache 管理技术来加速。

3. **值得跟进的方向**：
   - **离线归因**：当前方法是在线逐 token 归因，开销大。能否设计离线批量归因方法，在生成完成后一次性分析整个序列？
   - **大模型验证**：在 7B+ 模型上验证方法的有效性和计算开销，尤其是 LoRA/QLoRA 等参数高效微调下的联邦场景。
   - **超越 backdoor 的评估**：设计更接近真实场景的评估方法，如让不同 client 训练不同领域数据，测试模型在特定领域问题上能否正确归因到对应 client。

---

## 八、总结

ProToken 首次解决了联邦 LLM 中的 token 级归因问题，利用 FL 聚合的线性性、Transformer 层级结构和梯度加权三个技术手段，实现了计算可行的 per-token provenance tracking。在 16 种配置下达到 98.62% 平均归因准确率，55 client 规模下仍保持 >92% 准确率。主要局限在于评估完全依赖 backdoor 注入这一极端场景，且实验模型规模偏小（最大 1B），与实际联邦 LLM 部署场景存在差距。
