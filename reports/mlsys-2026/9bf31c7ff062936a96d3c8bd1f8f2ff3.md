# EARTHSIGHT: A Distributed Framework for Low-Latency Satellite Intelligence

## 一、背景

低轨道（LEO）纳卫星星座（如 Planet Dove、Spire LEMUR）已实现对地球表面的高分辨率、近每日覆盖成像，广泛应用于灾害响应、环境监测、城市规划和军事情报等场景。然而当前地球观测系统的瓶颈已从数据获取转向数据分析——每天覆盖 2 亿平方公里的影像需要及时处理。传统管线将所有影像先下行至地面站再分析，因下行窗口短（10-15 分钟）、带宽有限，导致数小时到数天的延迟，严重影响时间敏感型任务（如灾害搜救、冲突区态势感知）。

近年来 Orbital Edge Computing（OEC）方兴未艾，在卫星上执行 ML 推理来优先排序或丢弃低价值影像。但已有系统（如 SERVAL、KODAN）将每颗卫星视为独立计算节点，忽略星座级协调，且只支持单任务推理，导致多任务间存在大量冗余计算。

---

## 二、要解决的问题

1. **孤立计算，缺乏全局协调**：已有 OEC 系统不考虑星座整体的下行竞争和带宽分配，无法在多颗卫星间最优分配有限的通信机会
2. **单任务推理导致冗余**：同一影像可能服务于多个应用（如船舶检测 + 类型分类 + 非法捕鱼识别），分别运行独立模型造成计算和能耗浪费
3. **严苛的星载资源约束**：纳卫星功耗预算 1-5W，使用抗辐射低功耗处理器（远落后于地面加速器），无法在下一个下行窗口前完成所有影像的推理
4. **静态 filter 执行策略低效**：已有系统按固定执行时间排序 filter，未利用 filter 选择性和任务逻辑关系来实现早期拒绝

## 三、洞察与设计

**关键洞察**：卫星影像分析本质上是一个地面-轨道间的分布式决策问题——地面站拥有全局上下文（用户查询、历史分布、星座传输预测），轨道端拥有实时资源状态（功率、推理结果），两者的协同可以比任一端独立决策获得更优的影像优先级排序。

基于此洞察，EARTHSIGHT 设计了三个核心组件：

### 1. Multi-Task 星载推理
采用共享 backbone + 轻量 task-specific head 架构（EfficientNet backbone + MLP head）。按领域（海洋、陆地等）对任务分组，组内共享 backbone 特征提取，避免跨任务冗余计算。分类任务 memory 节省 55.7%，精度损失 < 0.5%。

### 2. 地面站 Query Scheduler
- **查询驱动框架**：用户提交带 AOI（兴趣区域）和优先级的查询，用逻辑表达式描述筛选条件（如 "cloud-free AND ship present AND ship is military"）
- **Look-ahead 仿真**：预测下行窗口时间、可传输数据量，计算每颗卫星的优先级阈值 p* 和目标拒绝率 r_reject
- **Schedule 生成**：为每个计划拍摄位置构造 DNF 公式，编码影像满足优先级阈值的条件；利用唯一公式压缩（~25× 压缩比），通过 1 字节索引的查找表传输

### 3. 轨道端自适应 Filter 排序
- **动态置信度阈值**：上界 α 根据功率余量和拒绝率动态调整，下界 β 固定（避免漏掉重要影像）
- **Utility-driven 贪心排序**：将 filter 排序建模为 Stochastic Boolean Function Evaluation (SBFE) 问题（NP-hard），使用贪心启发式——每步选择 utility 最高的 filter，utility 综合考虑通过概率、真阳率、执行时间和逻辑影响力
- **流水线 CPU-xPU 执行**：当 xPU 执行当前 filter 时，CPU 预加载下一个最可能的 filter，投机性地预取备选 filter 以隐藏 misprediction 延迟

## 四、实现细节

- **模型架构**：EfficientNet-B0/B1/B2 作为 backbone，MLP 作为 prediction head。按任务领域分组共享 backbone（如海洋相关任务共享一个 backbone），避免异构领域合并导致的欠拟合和超出内存限制
- **硬件平台**：Google Coral Edge TPU（4 TOPS INT8, 2W peak）和 NVIDIA Jetson AGX Orin Nano GPU（40 TOPS INT8, 7-15W）
- **仿真框架**：基于 SERVAL 开源仿真器扩展，使用 SGP4 算法传播轨道，模拟 PlanetScope Dove 星座（153 颗卫星、14 个地面站），48 小时连续仿真
- **Schedule 压缩**：将 6 小时内 ~16,000 个 DNF 公式压缩为 < 256 个唯一公式，使用 1 字节索引查找表
- **DNF 公式求值**：使用 Disjunctive Normal Form 表示查询条件，每个 term 是 filter 结果的 conjunction，公式整体是 terms 的 disjunction。confidence 计算基于未评估 filter 的先验通过概率
- **功率管理**：太阳能电池板供电，目标维持 70% 最大电量；α 阈值随功率下降而放松，减少计算以保护电池寿命

## 五、实验结果

### 实验场景
三个真实应用场景：自然灾害监测、情报监控、城市综合观测

### 端到端延迟（P90 tail latency，首次地面接触到影像交付）

| 场景 | 平台 | Baseline (SERVAL) | EARTHSIGHT MT |
|------|------|-------------------|---------------|
| Intelligence | Coral | 47 min | 21 min |
| Urban Observation | Coral | 51 min | 21 min |
| Natural Disaster | Coral | 较低改善 | 与 baseline 接近 |

### 影像优先级排序时间

| 平台 | 方法 | 平均时间 | 加速比 |
|------|------|----------|--------|
| Jetson | Baseline | 2.46s | 1× |
| Jetson | EARTHSIGHT MT | 1.33s | 1.85× |
| Coral | Baseline | 7.82s | 1× |
| Coral | EARTHSIGHT MT | 4.15s | 1.88× |

### 功耗（前 6 小时生成功率消耗占比）

| 方法 | TPU | GPU |
|------|-----|-----|
| Baseline | 27.95% | 171.96% |
| EARTHSIGHT MT | 8.91% | 61.49% |

Baseline 在 GPU 上消耗功率超过生成量（171.96%），意味着电池会耗尽。

### 贪心 vs. 精确解
在 2,473 个合成公式上，EARTHSIGHT 贪心策略相对精确解的 mean 误差仅 7.5%，median 完全一致。

### Ablation：动态 vs. 静态阈值

| α 策略 | Mean Latency | P90 Latency |
|--------|-------------|-------------|
| Dynamic | 7.0s | 20.0s |
| Static 0.2 | 11.9s | 44.7s |
| Static 0.3 | 7.6s | 21.1s |

## 六、批判性分析

1. **Natural Disaster 场景改善有限，但这恰恰是最需要低延迟的场景**：论文坦承在灾害监测场景下 EARTHSIGHT 相对 baseline 改善不大（因为灾害事件稀少、模型简单，baseline 已能处理大部分帧）。但论文选择将此解读为"baseline 足够好"，而非反思系统在低负载时的过度设计。真正的灾害响应需要在事件突发时的极端尖峰负载下表现良好，而非平均情况。

2. **仿真而非真实部署**：虽然使用了真实硬件的推理时间和功耗数据，但整体评估基于仿真。卫星实际运行中的热管理、辐射导致的 bit flip、通信中断等问题未被考虑。论文未讨论 EARTHSIGHT 的鲁棒性和容错机制。

3. **Baseline GPU 功耗 171.96% 的不公平性**：Baseline（SERVAL）在 GPU 上消耗功率超过太阳能生成量，这意味着 baseline 在 GPU 上根本无法持续运行。用一个不可行的 baseline 作为比较基准，放大了 EARTHSIGHT 的优势。公平的比较应在 baseline 也能正常工作的配置下进行。

4. **贪心策略的 7.5% 误差仅在 ≤15 filter 的缩减公式上测试**：实际场景可能有 60 个 filter，而精确解在 60 filter 时需要一天计算时间。论文无法评估贪心策略在大规模公式上的实际误差，7.5% 的数字可能严重低估真实误差。

5. **Multi-task 模型的跨域评估不足**：论文按领域分组共享 backbone，但未充分评估当新任务不属于现有分组时的扩展性。新 head 的上行和部署流程被描述为轻量级，但缺乏定量评估。

6. **查询模型假设较强**：系统假设用户查询可以被精确表达为 AOI + 逻辑公式 + 优先级的形式，且 filter 的先验成功概率可从历史数据准确估计。对于突发性、前所未见的事件（如新型灾害），先验概率可能严重失准。

## 七、AI Infra / MLSys 视角

1. **分布式推理的 ground-orbit 范式**：EARTHSIGHT 将全局调度（计算密集但不受资源约束）放在地面站，将自适应执行（轻量但需实时响应）放在边缘端。这种 "global planner + local executor" 的设计模式对 AI Infra 中的异构集群推理调度有借鉴意义——中央调度器提供全局 hint，各节点根据本地负载自适应调整。

2. **Utility-driven 早期退出**：filter 排序本质上是一种推理时的动态计算分配——对低价值输入尽早终止计算。这与 LLM 推理中的 speculative decoding、early exit transformer 有共通之处。将"输入的预期价值"纳入调度决策是一个值得在 LLM serving 中探索的方向。

3. **Multi-task inference 在边缘部署的实践**：shared backbone + task heads 的架构在服务器端已广泛使用，但本文展示了在 2W TPU 上的实际部署效果（memory 节省 55.7%，精度损失 < 0.5%），为 edge AI 场景（手机、IoT 设备）的多任务推理提供了实证参考。

4. **可操作的 future work 方向**：
   - 将 SBFE 的贪心优化替换为 learned policy（强化学习学习 filter 执行策略），可能在大规模公式上获得更好的近似
   - 探索 mixed-precision / 可变停止点推理，在精度-延迟-功耗三维 trade-off 上做更细粒度的控制
   - 将 inter-satellite link（ISL）引入决策框架，卫星之间直接共享推理结果，减少对地面站的依赖

---

## 八、总结

EARTHSIGHT 将卫星影像分析重新定义为地面-轨道间的分布式决策问题，通过地面站全局查询调度、星载 multi-task 推理和自适应 filter 排序三个组件的协同，实现了高优先级影像 P90 尾延迟从 51 分钟降至 21 分钟（相对 SERVAL），每图计算时间减少 1.85-1.9×，功耗大幅降低。系统适用于多任务、多用户的星座级卫星观测场景。主要局限在于评估基于仿真而非真实在轨部署，自然灾害等低负载场景改善有限，贪心调度策略在大规模 filter 下的近似质量未被充分验证。
