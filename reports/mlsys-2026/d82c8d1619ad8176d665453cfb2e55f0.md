# BLASST: Dynamic Blocked Attention Sparsity via Softmax Thresholding

**作者**：Jiayi Yuan, Cameron Shinn, Kai Xu, Jingze Cui, George Klimiashvili, Guangxuan Xiao, Perkz Zheng, Bo Li, Yuxin Zhou, Zhouhai Ye, Weijie You, Tian Zheng, Dominic Brown, Pengbo Wang, Richard Cai, Julien Demouth, John D. Owens, Xia Hu, Song Han, Timmy Liu, Huizi Mao

## 1. 背景

大语言模型(LLM)对长上下文推理的需求迅速增长:代码库级补全、长文档问答、多轮对话等场景都要求模型支持 32K/128K 甚至 1M tokens 的输入。但 attention 机制本身是 $O(n^2)$ 复杂度,序列越长,KV 矩阵和 softmax 的 HBM 访问与计算开销就越主导整个推理延迟。

FlashAttention 及其后续(FA2/FA3)通过 tiling + kernel fusion 在 HBM 带宽利用率上做到了接近硬件极限,但它依然**计算完整 attention 矩阵**,并没有触碰二次复杂度本身。要进一步加速,就需要在算法层面利用 attention 分布的稀疏性:大多数 token 对某个 query 的贡献确实接近零。

---

## 2. 要解决的问题

现有稀疏 attention 方法有三类根本性缺陷:

- **预计算开销吞噬理论加速**:MInference、XAttention 需要先跑一遍代理计算(如 anti-diagonal 打分)来筛选重要块,FlexPrefill 依赖 compiler-supported 的调度,这些开销经常把理论上的 FLOPs 节省吃掉。
- **静态稀疏模式不够灵活**:StreamingLLM 等固定 sink + local window 的方案无需预计算,但对不同任务、不同上下文长度的最优稀疏模式差异极大,一刀切会损失精度。
- **代理分数不准**:用累积 attention 权重、QK 相似度等"代理"来判定重要性,经常漏掉关键 token 交互,导致精度陡降。
- **prefill 和 decode 割裂**:大多数方法只优化一个阶段,导致端到端管线难以同时拿到压缩收益。

BLASST 的目标是**一次性解决这四个问题**:无预计算、无代理分数、精度稳定、prefill + decode 统一加速。

---

## 3. 洞察与设计

**关键洞察**:在 FlashAttention 的 block-wise online softmax 中,running maximum $m_i^{(j)}$ 已经在每一步更新。若一个 block 的 local maximum $\tilde{m}_i^{(j)}$ 比当前 running max 小很多,那么该 block 所有元素经过 $\exp(S - m)$ 归一化后都趋近于 0,对最终 output 的贡献可忽略。换句话说,**判断一个 block 是否可跳过所需的全部统计量,online softmax 已经顺手算出来了,不需要额外代理**。

作者把这个观察压缩成一个极简的跳过条件:

$$\tilde{m}_i^{(j)} - m_i^{(j)} < \ln(\lambda) \quad \Rightarrow \quad \text{skip block}$$

一旦判定跳过,就一次性省掉三种开销:

1. **CUDA core 开销**:跳过 `MUFU.EX2`(exp)、`FMUL`、`FADD` 等指令,以及 rowsum 归一化。
2. **Tensor core 开销**:跳过 $\tilde{P}_{ij} V_j$ 的 MMA,这是 prefill 阶段最重的一笔。
3. **HBM 带宽**:跳过 $V_j$ 从 HBM 到 SRAM 的 TMA load,这是 decode 阶段的关键瓶颈。

三步近似的推导很清晰:理想情况下应比较每个 $S_{ij}$ 与全局最大值,但全局最大值计算昂贵,因此用 running max 做代理;再进一步,把 token 级比较替换为 block 级比较(用 block local max),换来每 block 只需一次比较的极低开销。

**阈值校准 λ = a / L**:实验发现在同一模型上,达到固定稀疏度 S 所需的阈值 λ 与上下文长度 L 成反比。这里的直觉是 attention 行归一化后总和为 1,序列越长每个 token 的平均分数越小,所需阈值也相应缩小。校准过程很简单:在若干上下文长度采样,找到命中目标稀疏度的 $\lambda_{\text{best}}$,然后对 $(1/L, \lambda_{\text{best}})$ 做线性回归,得到模型特定常数 a。

**稀疏感知训练(可选扩展)**:fine-tune 阶段在前向就用 BLASST 剪枝,反向时被跳过的 block 天然没有梯度,这等价于让模型主动把重要信息集中到高分 block 里,进一步推动 accuracy-sparsity 帕累托前沿。

## 4. 实现细节

BLASST 集成在 NVIDIA 的 flashinfer 框架中,分别为 prefill 和 decode 写了专门的 CUDA kernel,目标平台是 Hopper(H200)和 Blackwell(B200)。

**跳过决策的低开销实现**(对应 Algorithm 1 line 7):
- 每个 thread 根据比较结果设置 predicate。
- `VOTE` 指令做 warp 内一致性投票。
- 每个 warp 由一个 thread 发射 `ATOMIC` 写共享内存,协调整个 softmax warpgroup 对该 block 的跳过决定。

这些额外指令全部隐藏在现有 FlashAttention kernel 的已有气泡中,因此 0% 稀疏度下 overhead 只有 0.98–0.99×(论文自己承认的 tiny slowdown)。

**Prefill kernel(compute-bound 优化)**:
- 同时跳过 softmax 和 BMM2(P × V),释放 CUDA core 与 Tensor core。
- 保留 V 块的 HBM load,因为 prefetch pipeline 受益于可预测的访存模式,且条件加载的延迟可能超过节省。
- Figure 3 显示 4 次 loop 中跳过 2 次,总 schedule 从 18 时间单位压缩到 14 单位。

**Decode kernel(memory-bound 优化)**:
- 主要跳过 V 块的 TMA load 和 BMM2,因为 decode 下 HBM 带宽是瓶颈。
- Figure 4 显示连续跳过 3 个 loop 的 V load 后,剩余 V load 的 outstanding 时间从 30 降到 23 单位。
- 对于 MLA 这种即使 decode 也 compute-bound 的 attention 变体,额外再跳 softmax。

**兼容性**:MHA / GQA / MQA / MLA 都支持,sliding window attention 也兼容。

## 5. 实验结果

**模型与数据集**:Llama-3.1-8B-Instruct、Qwen3-8B-Instruct,以及 DeepSeek-R1 distilled Llama-3.1-8B。评测覆盖 RULER(4K–128K)、LongBench v2、MATH500、AIME 2024、GPQA、LiveCodeBench、RepoQA(最长 200K)。

**端到端精度**(Table 1 节选):

| 模型 | 稀疏度 | RULER-32K | LongBench | MATH500 | AIME 2024 | GPQA |
|---|---|---|---|---|---|---|
| Llama-3.1-8B (Dense) | 0% | 92.33 | 31.40 | 73.40 | 46.66 | 46.71 |
| Llama-3.1-8B (BLASST) | ~75% | 91.67 | 31.80 | 73.89 | 46.01 | 45.95 |
| Qwen3-8B (Dense) | 0% | 91.90 | 33.60 | 95.87 | 75.00 | 61.21 |
| Qwen3-8B (BLASST) | ~75% | 92.11 | 34.40 | 96.07 | 75.33 | 61.51 |

在 ~75% 稀疏度下精度几乎不掉,Qwen3-8B 上甚至略有提升。

**Prefill 基线对比(Llama-3.1-8B, RULER 平均)**:

| Method | RULER 平均 | LongBench Overall |
|---|---|---|
| Dense | 93.21 | 31.4 |
| FlexPrefill | 87.72 | 25.7 |
| MInference | 84.15 | 31.2 |
| XAttention | 92.44 | 30.6 |
| **BLASST (~50%)** | **92.87** | **31.8** |

BLASST 在 prefill 阶段显著优于代理分数方法。

**Decode 基线对比(Qwen3-8B)**:

| Method | RULER-32K | LongBench | MATH500 | AIME 2024 | LiveCodeBench | GPQA |
|---|---|---|---|---|---|---|
| Dense | 91.90 | 33.60 | 95.87 | 75.00 | 53.83 | 61.21 |
| Quest | 56.23 | 30.30 | 94.18 | 71.50 | 52.17 | 60.12 |
| RocketKV | 87.89 | 30.60 | 95.88 | 73.54 | 53.10 | 60.50 |
| **BLASST (~50%)** | **91.55** | **33.90** | **96.23** | **76.50** | **54.15** | **61.51** |

**GPU kernel 加速(B200 / H200)**:

| 平台 / 阶段 | Sparsity | Speedup |
|---|---|---|
| B200 Prefill | 50.67% | 1.24× |
| B200 Prefill | 73.47% | 1.41× |
| B200 Prefill | 80.35% | 1.49× |
| B200 Decode | 46.68% | 1.25× |
| B200 Decode | 73.15% | 1.48× |
| B200 Decode | 91.99% | 1.79× |
| H200 Prefill | 74.7% | **1.62×** |

**校准有效性**(Table 5):fixed threshold $\lambda = 10^{-3}$ 在 4K→64K 上实际稀疏度从 23% 漂到 75%(偏离目标 50% 达 ±25%),而 $\lambda = a/L$ 能把各长度稀疏度全部稳定在 47%–54% 区间,平均偏差 1.2%。

**稀疏感知训练(Figure 6)**:在 50%–75% 稀疏区间,fine-tune 过的模型比 post-training 应用稀疏的精度降幅降低最多 1.7×。

**正交性(Table 6)**:BLASST 可与 XAttention(prefill)、RocketKV(KV 压缩)叠加使用,组合后精度降幅 ≤0.62 分。

**超长序列(Table 7, RepoQA 200K)**:prefill 稀疏度 57.5% + decode 稀疏度 40.8%,精度仅从 0.850 降到 0.838。

## 6. 批判性分析

- **"稀疏反超 dense"的解释不严谨**:Qwen3-8B 在 MATH500 从 95.87 提到 96.23、AIME 从 75.00 提到 76.50,作者用"隐式去噪"和"过滤冗余推理步骤"来解释。这些差异在推理任务的采样方差(T=0.6, top-p=0.95, 10–20 samples, majority voting)下完全可能是噪声。严谨做法应当报告置信区间或多 seed 复现,但论文并未给出。
- **Quest 基线结果异常**:Table 3 中 Quest 在 RULER-32K 只有 56.23 分,而 Dense 是 91.90,差 36 分。这个量级的掉点远超 Quest 论文自报数字,暗示要么配置不合理、要么 KV eviction 类方法不适合 RULER 的 needle-in-haystack 模式。拿"最弱配置"对比会美化 BLASST 的相对优势,这种 apples-to-oranges(KV 剪枝 vs attention 剪枝)比较可读性值得打折。
- **Block 级决策的粒度风险被轻描淡写**:跳过整块意味着 block 里任何单个高分 token 也一起被丢。Figure 7 已经显示 layer/head 间稀疏度差异极大(有些几乎全稠密,有些近乎完全稀疏),但 BLASST 并未为这种异质性设计自适应阈值,而是全模型共用一个 λ(只随 L 变),实际效果依赖"头间自然平均"这个假设。
- **0% sparsity 仍有 1%–2% 的 overhead**:论文说"no significant degradation",但 0.98–0.99× 意味着 short-context、dense-attention 场景接入 BLASST 是轻微负收益。在 batched serving 里并非所有请求都长上下文。
- **校准并非真"无训练"**:虽然算法本身训练无关,但部署前需要在每个模型、每个目标稀疏度上跑 ~1000 条 RULER 样本标定 a。切换模型时要重算,这部分成本论文没列入对比。
- **λ = a / L 的"理论依据"是直觉而非证明**:作者只说"注意力行归一化后平均分更低",但没有给出严格的下界或概率分布刻画。在 attention sink 或极不均衡分布下,这个线性关系能否继续成立缺乏证据。
- **稀疏感知训练破坏了 training-free 卖点**:论文在 Section 5.5 承认 fine-tune 能把帕累托前沿再推一档。这意味着要想在 >75% 稀疏度不掉精度,实际还是要训。宣传"drop-in"时需要注意边界。
- **Tile row reordering 的 gain 仅在 FWE 上出现**:Figure 8 显示 VT 上无差异、FWE 上有改善,作者承认"dataset-dependent"。这个正面性质被当作未来可扩展性讲,但落到当前版本就是随机效果。

## 7. AI Infra / MLSys 视角

BLASST 本身就是一篇典型的 MLSys 论文,对 AI 基础设施有直接借鉴价值:

- **"算法 + kernel co-design"的范本**:跳过决策的全部信号来自 online softmax 已经算出的量,本质上是在 kernel 内部"免费"挤出信息。这种"不要设计新代理,用已有的中间状态"的思路,值得推广到 MoE routing、speculative decoding 的 draft 选择、投机采样中的 rejection logic 等场景。
- **阶段分治的硬件映射**:prefill 跳 compute、decode 跳 memory,这个区分比"全局稀疏率"重要得多。未来在设计稀疏方案时,应当从硬件瓶颈(roofline)出发倒推算法形态,而不是先选一个稀疏模式再兼容硬件。
- **Layer/head 级自适应是明确的 future work**:Figure 7 显示不同层/头稀疏度差异巨大。可研究方向包括:(a) 给每层每头学出独立的 λ,(b) 结合 retrieval head 理论(Wu et al., 2024)决定哪些头走 dense,(c) per-batch 或 per-query 动态调整。
- **block-local max 的改进空间**:当前块内只用 max,可以考虑 max + second-max、或者 max + running sum 的联合判定,进一步压稀疏度而不损精度。
- **与量化、投机解码的组合**:BLASST 跳过 V load 的决定只看 Q K 统计,和 FP8/INT4 KV 量化是正交的。把 BLASST + FP8 KV + speculative decoding 堆起来,在长上下文 serving 上可能叠加出 3–5× 的端到端加速,这是值得做的系统集成工作。
- **硬件 feature 建议**:block-level predicated MMA 目前只能靠 warp vote + shared memory atomic 模拟,未来 SM 架构若直接支持 per-tile predicate,开销会更低。这类 skip-aware tensor core 是可以向硬件厂商提出的具体需求。
- **对 serving 框架的启发**:BLASST 的稀疏度随上下文长度线性增长(通过 λ = a/L 的校准),serving 调度器可以据此在长短请求混批时更准确地估算剩余计算量,改善 token-level fair scheduling。

---

## 8. 总结

BLASST 用一个简到近乎 trivial 的观察把稀疏 attention 推进了一步:online softmax 算出的 running max 已经足够判断一个 block 是否值得算,无需任何代理。配合精心设计的 prefill/decode kernel、λ = a/L 的自动校准和可选的稀疏感知微调,在 Llama-3.1-8B / Qwen3-8B 上实现了 ~75% 稀疏度几乎无损精度,以及 H200 上 1.62× prefill 和 1.48× decode 的实测加速。方法的真正价值在于它是**可叠加的基础构件**:和 XAttention、RocketKV 正交,可以塞进任何 FlashAttention-based 推理栈。主要局限是(1)block 级粒度在 head 间异质性下略显粗糙;(2)精度超 75% 稀疏仍需微调;(3)对 KV eviction 类基线的比较不够公平。整体而言,这是一份工程完成度高、思想清晰的 MLSys 论文,属于"看一眼就能上生产"的那类工作。
