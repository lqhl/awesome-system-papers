## 一、背景

随着大语言模型（LLM）对长上下文推理能力的需求增长（128K 乃至 1M tokens），标准 attention 机制的 O(n²) 计算和内存复杂度成为部署瓶颈。FlashAttention 系列通过 tiling 和 kernel fusion 优化了内存带宽利用率，但仍计算完整的 attention 矩阵，未改变二次复杂度的本质。

现有的稀疏 attention 方法试图只计算部分 attention 矩阵来降低开销，但面临三个关键限制：(1) 需要昂贵的预计算来确定稀疏模式（如 MInference、XAttention），往往抵消了理论加速；(2) 依赖代理重要性分数（accumulated attention weights、query-key similarity）而非真实 softmax 值，可能遗漏关键 token 交互；(3) 大多只优化 prefill 或 decode 其中一个阶段，缺乏端到端加速方案。

---

## 二、要解决的问题

1. **预计算开销**：动态稀疏方法（MInference、XAttention、FlexPrefill）需要额外的 pass 来计算重要性分数或排序 block，这些开销可能完全抵消稀疏带来的加速
2. **代理分数不准确**：基于代理评分的方法无法精确反映 softmax 归一化后的真实贡献，导致错误地剪枝重要 block
3. **Prefill/Decode 分离优化**：现有方法通常只针对 prefill（compute-bound）或 decode（memory-bound）其中一个阶段，无法提供统一的长上下文推理加速方案
4. **阈值不自适应**：固定阈值在不同上下文长度下产生差异极大的稀疏率（4K 时 23%，64K 时 75%），使生产部署不可靠

---

## 三、洞察与设计

**关键洞察**：在 FlashAttention 的 block-wise online softmax 计算过程中，running maximum 已经被跟踪维护。如果某个 block 的局部最大值 m̃ᵢ⁽ʲ⁾ 显著低于当前 running maximum m_i⁽ʲ⁾（差值超过 ln(λ)），那么该 block 经过指数化和归一化后对最终输出的贡献将接近于零——这意味着可以直接复用 FlashAttention 已有的统计量来做剪枝决策，无需任何额外预计算或代理分数。

基于此洞察，BLASST 的设计如下：

- **剪枝规则**：在 FlashAttention 的 block 遍历中，每个 block 计算完 QKᵀ 后检查 m̃ᵢ⁽ʲ⁾ − mᵢ⁽ʲ⁾ < ln(λ)，满足条件则跳过三项开销：(1) softmax 的 exp 计算（CUDA cores），(2) P̃V 矩阵乘（Tensor cores），(3) V block 从 HBM 加载（内存带宽）
- **自适应阈值校准**：发现最优阈值与上下文长度成反比 λ = a/L（因为 softmax 行归一化使得更长序列的平均分数更低）。通过在多个上下文长度上搜索目标稀疏率对应的阈值，再做线性回归拟合 a，实现跨序列长度的稳定稀疏控制
- **Sparsity-aware training**：在 fine-tuning 时直接使用 BLASST 的稀疏 attention 做前向传播，被跳过的 block 自然不接收梯度，鼓励模型将重要信息集中在高分 attention block 中，从而推进 accuracy-sparsity Pareto 前沿

## 四、实现细节

**Prefill kernel（compute-bound 优化）**：
- 流水线调度跨 Tensor Cores（MMA）和 CUDA cores（softmax/correction）
- 跳过 block 时省略 softmax（EX2 指令）和 BMM2（attention-value 乘法），但仍加载 V block（因为 prefill 不是内存带宽瓶颈，且跳过条件 V 加载的延迟反而更大）
- 跳过计算释放的执行单元使后续操作提前调度，压缩整体时间线

**Decode kernel（memory-bound 优化）**：
- 核心是跳过 V block 从 HBM 到 SRAM 的加载，直接减少内存流量
- 对 MLA（Multi-head Latent Attention）等即使在 decode 也 compute-bound 的变体，额外跳过 softmax 计算
- TMA pipeline 中 skip V load 后其他 pipeline stage 的 load 更快完成

**Skip decision 实现**：
- 每个 thread 做阈值比较设置 predicate
- VOTE 指令在 warp 内达成共识
- 单个 ATOMIC 指令写入 shared memory 在 warp group 间协调
- 这些指令被隐藏在已有操作后面，几乎零额外延迟

**校准过程**：在 RULER 数据集上采样约 1000 条序列，覆盖 4K-64K 上下文长度，grid search 找到各长度下达到目标稀疏率的最佳 λ，然后在 (1/L, λ) 上做线性回归拟合 a。

**集成**：基于 flashinfer 框架实现，支持 MHA、GQA、MQA、MLA 所有 attention 变体，以及 sliding window attention。

## 五、实验结果

**模型**：Llama-3.1-8B-Instruct、Qwen3-8B-Instruct、Qwen3-Coder-30B
**GPU**：NVIDIA H200 (Hopper)、B200 (Blackwell)
**基线**：FlashAttention-3 BF16、MInference、FlexPrefill、XAttention、Quest、RocketKV

### 准确率（Table 1, ~75% sparsity）

| 模型 | RULER-32K | LongBench | MATH500 | AIME2024 | GPQA |
|------|-----------|-----------|---------|----------|------|
| Llama-3.1-8B Dense | 92.33 | 31.40 | 73.40 | 46.66 | 46.71 |
| Llama-3.1-8B ~75% | 91.67 | 31.80 | 73.89 | 46.01 | 45.95 |
| Qwen3-8B Dense | 91.90 | 33.60 | 95.87 | 75.00 | 61.21 |
| Qwen3-8B ~50% | 92.08 | 35.10 | 96.23 | 76.50 | 61.56 |

### Kernel 加速（Blackwell B200）

| 稀疏率 | Prefill 加速 | Decode 加速 |
|--------|-------------|-------------|
| ~50% | 1.24× | 1.25× |
| ~73% | 1.41× | 1.48× |
| ~80% | 1.49× | 1.64× |

| 方法 | 4K | 8K | 16K | 32K | 64K |

## 六、批判性分析

1. **加速比与稀疏率不成正比**：74.7% 稀疏率仅获得 1.62× 加速（理想上限约 3.9×），实际加速效率约 42%。论文将此归因于 QKᵀ 仍需全量计算（用于做 skip 判断），但未量化 QKᵀ 占总时间的比例，读者难以判断还有多少优化空间

2. **评估模型规模偏小**：核心实验在 8B 模型上进行，仅有 RepoQA 用了 30B（且是 MoE 模型 Qwen3-Coder-30B-A3B）。在 70B+ 密集模型上的效果未验证——更大模型的 attention 分布可能不同，稀疏率和准确率的 trade-off 可能改变

3. **"偶尔超越 dense baseline" 的解释较投机**：论文将 BLASST ~50% sparsity 下 MATH500/AIME2024 分数提升解释为"隐式去噪"和"过滤冗余推理步骤"，但未设计对照实验验证该假设。这种小幅波动更可能来自采样方差（reasoning 任务用了 temperature=0.6 多次采样取 best-of-N）

4. **Sparsity-aware training 评估不充分**：仅在 RULER 上展示了 accuracy-sparsity 曲线，未报告 reasoning 任务的结果。训练成本（数据量、epochs、额外时间）也未报告

5. **校准需要额外数据和计算**：虽然声称"automated"，但校准需要在多个上下文长度上运行 ~1000 条序列来拟合 λ=a/L。这个过程对每个新模型都需要重新做，且 a 是否在不同任务/domain 上保持稳定未被充分验证

6. **Running maximum 的顺序敏感性**：block 的遍历顺序影响 running maximum 的积累速度，从而影响 skip 决策质量。虽然 ablation（tile row reordering）显示影响不大，但只在两个 RULER 子任务上验证，且仅在 8K 上下文。在 attention 模式更复杂的真实任务上是否稳健存疑

## 七、AI Infra / MLSys 视角

**启发与借鉴**：
- BLASST 的核心思路——复用已有计算中间结果做动态剪枝决策——是一个优雅的设计范式。这种"zero-overhead decision making"思路可推广到其他计算密集的 kernel 中，例如 MoE 的 expert routing、speculative decoding 的 verification
- Prefill 和 decode 用不同的优化策略（compute-bound vs memory-bound）反映了对硬件瓶颈的精准理解，这种分阶段优化的方法论值得在其他系统设计中借鉴

**可迁移的技术**：
- λ=a/L 的阈值校准公式简洁实用，类似的"一个超参数适配多种部署场景"的校准方法可应用于 KV cache eviction、speculative decoding 的 draft length 选择等
- 与 XAttention（prefill）和 RocketKV（decode）的正交组合表明，BLASST 可作为现有推理优化 pipeline 中的一个即插即用模块

**值得跟进的方向**：
1. **与 KV cache compression 联合优化**：BLASST 跳过的 block 对应的 KV cache 理论上可以更激进地压缩或驱逐，实现 compute + memory 的双重节约
2. **Hardware-aware block size 自适应**：当前使用固定 block size，但不同 GPU（Hopper vs Blackwell）和不同 head dim 下最优 block size 不同，动态选择可进一步提升加速比
3. **长思维链推理场景**：论文提到 decode 阶段 73% sparsity 仅损失很少准确率——对 DeepSeek-R1 这类长推理模型，decode 阶段的 attention 稀疏潜力值得深入挖掘
4. **Sparsity pattern 分析用于模型理解**：Figure 7 展示的 layer/head 级别稀疏率异质性是理解模型 attention 行为的有价值信号，可用于指导结构化剪枝或 head pruning

---

## 八、总结

BLASST 提出了一种零预计算开销的动态稀疏 attention 方法，通过复用 FlashAttention online softmax 中已有的 running maximum 统计量做 block 级剪枝决策，在 prefill 和 decode 两个阶段均实现了显著加速（74.7% 稀疏率下 prefill 1.62×、73.2% 稀疏率下 decode 1.48×），同时保持了接近 dense baseline 的准确率。其自适应阈值校准（λ=a/L）和 sparsity-aware training 进一步增强了部署灵活性。该方法适用于所有 attention 变体（MHA/GQA/MQA/MLA），可与现有稀疏方法正交组合，是长上下文 LLM 推理加速的实用方案。主要局限在于实际加速比受限于 QKᵀ 仍需全量计算、评估模型规模偏小、以及校准过程的模型特异性。
