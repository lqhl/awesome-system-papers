# Learning from Less: Measuring the Effectiveness of RLVR in Low Data and Compute Regimes

**作者**:Justin Bauer, Thomas Walshe, Derek Pham, Harit Vishwakarma, Armin Parchami, Frederic Sala, Paroma Varma
**会议**:MLSys 2026
**链接**:https://proceedings.mlsys.org/paper_files/paper/2026
**源文件**:[[7f1de29e6da19d22b51c68001e7e0e54.pdf]]

---

## 1. 背景

近年来,Reinforcement Learning with Verifiable Rewards (RLVR) 已经成为推动 LLM 推理能力的重要后训练方法。DeepSeek R1、GPT-o3、Claude Sonnet 4.5 等 SOTA 模型都在数学、代码等有明确可验证答案的任务上借助 RLVR 产生了 emergent 推理与自我纠错能力。

主流 RLVR 研究的一个隐含假设是:高质量标注数据与算力都充足。例如 DeepMath-103K 动辄 10 万条样本,ScaleRL 等工作重点研究的是"如何在更多算力下 scaling"。然而在现实工业场景或新领域迁移中,标注数据和 GPU 预算都经常是稀缺资源,这些"充裕场景"下得到的 scaling law 未必可直接套用。本文关注的核心问题是:**当训练数据和算力都受限时,模型性能如何演化,以及数据的哪些属性真正影响泛化?**

---

## 2. 要解决的问题

已有的 scaling 工作主要在两个方向:
1. **模型 / 算力 scaling**:Kaplan、Hoffmann、ScaleRL、Tan et al. 都沿着"更大模型、更多 steps"的轴线刻画性能,没有控制数据组成。
2. **数据选择启发式**:LIMR、Shen et al. 等证明"小而精"可以胜过"大而杂",但没有系统研究数据规模与难度分布的交互。

作者认为现有工作的不足包括:
- 大多数 RLVR scaling law 来自单一领域(尤其是数学),泛化到其他推理任务的有效性未知
- 在"低数据 + 低算力"这种工业常态下,缺少系统的经验刻画
- 数据难度(easy / medium / hard)的配比如何影响样本效率,尚无定量结论
- 训练 token budget、reward 设计等系统约束与数据组成的交互被忽视

本文希望通过可程序化控制复杂度的数据集,在 SLM (4B) + LoRA 的低成本 setup 上,把这些关系打开。

---

## 3. 洞察与设计

**关键洞察**:当模型规模、算力、训练步数都被钉死之后,RLVR 的收益不再由"样本总量"主导,而由**样本难度分布**主导 —— 易题的同质样本只能给出低幅度、同质化的 advantage 信号,而掺入 medium/hard 样本后,即使总量不变,GRPO 组内的 reward 方差扩大,等价于每个 optimization step 获得的有效信息增加;同时 easy 部分又为 rollout 提供足够多的正样本以稳定训练。这个"难度多样性 substitute 数据量"的假设,是本文所有设计与实验的前提。

**整体设计**:作者搭建了一个封闭可控的实验工厂:

1. **三个 procedurally-generated 数据集**,覆盖不同推理模态:
   - **Counting Problems**:对整数序列做 filter + transform + count/sum/bitwise 等聚合,通过操作树深度 (1–7 步) 控制难度
   - **Graph Reasoning**:在 5–25 节点图上做 min-vertex-cover、max-clique、Hamiltonian path、图直径等经典图论任务,由 GPT-4o 做答案归一化后走 networkx 程序化验证
   - **Spatial Reasoning**:2D 网格 + 粒子的移动/旋转序列,询问绝对/相对的位置与朝向。absolute vs relative 对应空间认知里的 allocentric vs egocentric 二分
2. **多模型校准的难度分层**:用 10 个前沿 LLM (GPT-5、Claude 4.5、Gemini 2.5、Grok-3、Llama-4、Qwen3 等) 跑一次评估,按答对率划成 Easy (67–100%) / Medium (34–66%) / Hard (0–33%)。这一步把难度从"人类直觉"锚定到"当前模型能力边界",是使"data composition × model capability"的比较有意义的关键工程细节。
3. **六种训练配置 × 三个数据集 = 18 组实验**:Easy-only {100, 200, 500} 和 Mixed (Easy/Medium/Hard 各约 1/3) {100, 200, 500}。训练/测试严格 disjoint。

**训练配置**:统一 Qwen3-4B + LoRA (rank 64, α 16, target 所有 linear layer, 仅训 ~100M 参数) + GRPO + 4× A100 80GB。Counting/Graph 300 steps,Spatial 1000 steps。Reward 分任务定制:Counting 用 correctness + format + reasoning-length 惩罚的多分量 reward;Graph 给"格式正确但答错"部分分;Spatial 严格 binary。

## 4. 实现细节

**Reward 工程**(论文中较有信息量的一部分):

| 数据集 | Reward 范围 | 核心成分 |
|---|---|---|
| Counting | [−0.4, +1.1] | 答对 +1.0 / 格式 "Answer: X" +0.1 / 推理超过 5 步每多 1 步 −0.1(最多 −0.3) |
| Graph | [−0.2, +1.1] | 答对 +1.0 / JSON 格式 +0.1;格式正确但答错给 0.1;无结构输出 −0.2 |
| Spatial | {0, 1} | 严格 exact-match;浮点数匹配到 3 位小数 |

三个 reward 的"密度"显著不同,Spatial 的 binary 设计在训练曲线上会制造离散的 reward 台阶(这也解释了 Figure 2c 为何看起来是阶梯状改进)。

**训练超参**(Table 1 摘录):
- Counting: batch=2×4 GPU=8; Graph/Spatial: batch=1×4=4
- generations per prompt K=8 (Counting/Graph) / K=5 (Spatial);T=1.0
- max prompt 4096,max completion 2048
- AdamW + gradient clip 1.0 + cosine LR 5e-5 + 10% warmup
- 每 50 步在训练分布的 10% held-out 上做验证;测试用 greedy (T=0)
- 单次训练 5–12 小时

**Graph 任务的 token budget 陷阱**:Mixed 组的图平均 14.9 节点 vs Easy 的 12.6 节点,导致 mixed 下 67–73% 的 rollout 是 extraction failed (没在 2048 tokens 内产出可解析的 JSON),reward 被格式惩罚拖到负值。这也是后文"harder instances 受 token budget 约束"论点的主要证据。

## 5. 实验结果

**聚合测试准确率**(Table 2,mean test accuracy %,baseline 为未 fine-tune 的 Qwen3-4B):

| Samples | Counting Easy | Counting Mixed | Graph Easy | Graph Mixed | Spatial Easy | Spatial Mixed |
|---|---|---|---|---|---|---|
| 0 (base) | 31.3 | 31.3 | 29.4 | 29.4 | 26.1 | 26.1 |
| 100 | 21.9 | **44.2** | **33.3** | 29.1 | 49.9 | **56.6** |
| 200 | 40.0 | 43.4 | 32.9 | 32.7 | **56.7** | 54.3 |
| 500 | 44.2 | 35.5 | **36.5** | 34.0 | 53.1 | 55.7 |

**关键观察**:

1. **Counting**:Mixed-100 的 44.2% ≈ Easy-500 的 44.2%,也就是 **5× sample efficiency**。Mixed 组反而随样本量增加而下降(100→500 从 44.2 降到 35.5),违反传统 SFT scaling law 的单调改进预期。作者归因为:500 样本 / 300 步的 per-sample optimization update 太少,验证曲线到 step 300 还在上升,尚未收敛。

2. **Counting 训练不稳定性**:Easy-100 在 step 150 达到 0.89 val reward 后崩到 0.59,同时段 gradient norm 飙到 baseline 的 850× (Figure 4)。而样本量相同的 Mixed-100 全程稳定,作者据此提出"**难度多样性可以替代数据量来稳定 RLVR**"。

3. **Counting 跨难度泛化**(Figure 3a):
   - Easy-trained:在 easy 题上单调 scaling(从 0.530 到 0.931),但 hard 题上最多只到 0.134
   - Mixed-trained:跨难度更均衡(easy 0.934 / medium 0.589 / hard 0.125 @ 100 样本),Easy 题表现甚至和 Easy-500 相当

4. **Graph**:主要被 token budget 卡住,两种训练方式都难以泛化到 medium/hard。Easy-500 表现最好 (36.5%),但绝对收益有限。Mixed-100 甚至低于 baseline (29.1% vs 29.4%)。

5. **Spatial**(Figure 6):relative queries (RO, RL) 基线最差 (7.55% / 12.50%),fine-tuning 改进最显著。Mixed 训练对 RO 尤其有益(升到 67.50%),作者认为是 mixed set 含有更多该类 query 的结果。

**统一规律**(论文 Section 4.2 总结):
- 训练集组成可胜过数据量:Counting 和 Spatial 都有 5× 样本效率现象
- 固定预算下"加数据"常常无效:三个数据集都出现 inverted-U 或 diminishing-returns
- 硬样本可能被 token 上限卡住,使 reward signal 被抑制(Graph 是最典型的 victim)

**鲁棒性说明**:因算力限制,未做 multi-seed 重复,仅靠 18 组配置的定性一致性来作为鲁棒性证据,明确把结论定位为"low data/compute regime 下的经验观察,generate hypotheses rather than definitive causal claims"。

## 6. 批判性分析

论文的核心贡献("Mixed-100 ≈ Easy-500")确实是个值得关注的现象,但在以下几个点上存在可质疑之处:

1. **"5× sample efficiency"的统计基础薄弱**:全部 18 组实验都是**单 seed**。对于 Counting Mixed 从 44.2 → 35.5 这种"随 N 下降"的反常现象,作者自己也承认训练到 step 300 尚未收敛。那这究竟是"数据太多所以稀释 update",还是"训练步数不够"?两者在当前实验下无法区分。若是后者,那么"加数据不如 diversity"的结论可能在增加 steps 后消失。

2. **难度分层的自循环风险**:难度标签是由 10 个 LLM 的答对率决定的,而 Qwen3-4B 本身就是其中之一。这意味着"Mixed"集的 hard 样本,对 Qwen3-4B 而言很可能是**本来就无希望答对**的样本。如果 Mixed 的收益主要来自 easy+medium 部分,而 hard 部分基本是噪声,那么更合理的 baseline 应该是"Easy+Medium mixed",而不是"Easy+Medium+Hard"。论文没有做这个消融。

3. **Counting 反常 scaling 的解释不完整**:作者用"更多数据 / 更少 per-sample update"解释 Mixed-500 下降。但在相同 300 步、相同 batch 下,Easy-500 反而表现最好 (44.2%),明显优于 Easy-100 (21.9%) —— 这与"数据多 = update 少 = 性能差"的叙述直接矛盾。更可能的解释是 Mixed-500 中 hard 样本占比高,产生大量不完整/错误 rollout,噪声 reward 污染了 policy gradient。但论文没有给出这样的机制分析。

4. **Graph 结果其实是 negative result**:无论哪种配置,fine-tuning 相对 baseline 的收益都 ≤ 7 个百分点(29.4→36.5),medium/hard 上甚至普遍低于 baseline(从 Figure 3b 的 mean reward 接近 0 可见)。把 Graph 放进"data composition scaling law"的叙事里,其实稀释了 Counting / Spatial 上真正有意义的信号。作者也诚实地承认这是 token budget 问题,但如果 max_completion=2048 根本跑不通 task,那这个 domain 就不适合用来做 data scaling 的经验。

5. **缺少 full fine-tune 对照**:LoRA rank 64 虽然引用了 Schulman 博客说"RL 上 LoRA ≈ full FT",但这个结论主要在数学任务上得到验证。空间/图推理任务上 LoRA 是否仍然无损,未验证。"5× sample efficiency"在 full FT 下是否成立,未知。

6. **泛化声明偏乐观**:abstract 里说"models trained on lower complexity tasks can generalize to higher complexity tasks",但 Figure 3a 显示 Easy-trained 在 hard 问题上的 reward 是 0.052→0.134,几乎接近随机。这更像"性能略有不为零"而非"泛化",措辞过于强势。

7. **reward 函数是 post-hoc tuning 的产物**:论文明确说"we tried several formulations and report the ones that performed best" —— 这意味着 reward 设计本身经过了人工筛选,且不同数据集 reward 设计差异很大 (Counting 多分量 / Graph 格式 bonus / Spatial binary)。跨数据集结论的可比性被削弱。

## 7. AI Infra / MLSys 视角

本文对 AI Infra 从业者的直接启发:

1. **训练预算规划需要把"数据 × 算力 × token 上限"同时纳入优化变量**。现在业界做 RLHF / RLVR pipeline 时,常见默认值是"先堆数据,再调 step"。本文的 Counting 结果表明,在 GPU 小时数固定的预算下,200–500 样本的易题可能还不如 100 样本的 mixed。这对模型精调的 DevOps 有直接意义:**数据筛选管线应该把难度分布暴露为一流 knob**,而不是只有"样本总数"和"step 数"两个旋钮。

2. **程序化数据生成器 + 多模型校准是一个可复用的基础设施范式**。大多数团队在新领域做 RLVR 时,标注数据是瓶颈。本文方法:
   - 先用模板生成足够多候选题目
   - 用前沿 LLM 集体答题,自动打上难度 tier
   - 根据 tier 配比采样训练集

   这套流程几乎完全自动化,非常适合做成 AI Infra 平台上的一个 component,配合 Bases / FM Ops 做统一的"数据工厂 as a service"。延伸方向:把 curriculum 生成和 RL training 串成 closed loop,每次 rollout 后根据 reward 分布动态调整下一轮数据配比。

3. **Graph 的 token budget 陷阱暴露了 RLVR 训练的一个系统层瓶颈**:verbose reasoning + 固定 max_completion 会产生大量被扣分的 truncated rollout,这些 rollout 反而拖累优化。对推理系统的启发:
   - **自适应 max_length**:根据当前任务预测合理输出长度,而不是一刀切。可以用 PagedAttention 的思路按样本分配 KV cache 额度
   - **token-aware reward shaping**:把输出长度相关的奖惩从"reasoning step 数"升级为"与该样本难度匹配的目标长度的差距"
   - **early termination with partial credit**:对超长 rollout 给部分奖励,避免 gradient 完全被 extraction failure dominate

4. **GRPO 的 group-size 选择**:本文 K=8 (Counting/Graph)、K=5 (Spatial)。group size 决定 advantage baseline 的方差,与样本难度分布紧密相关。一个值得做的实验是:在 Mixed 数据集上,每个 group 内强制包含 easy/medium/hard 各 1 条,看 advantage 的 group-relative signal 是否更稳定 —— 这其实是把"数据多样性替代样本量"的洞察直接下沉到 RL algorithm 层面。

5. **可跟进的具体研究问题**:
   - **RLVR budget-aware scaling law**:形式化 (N_samples, N_steps, max_tokens, reward_sparsity) 的四维帕累托面
   - **Auto-curriculum for RLVR**:把"难度分层"做成在线决策,根据 rollout 的 reward 分布自适应调整下一批 batch 的难度组成
   - **LoRA rank × RL**:把本文 rank=64 的设置在 rank∈{8, 32, 128, 256, full} 上做消融,验证 Schulman 博客的"LoRA 无损"在非数学领域是否成立
   - **从 4B 到 70B 的可迁移性**:作者自己承认 5× 结论可能不能外推。但这正是值得做的后续实验:在 7B / 14B / 70B 上跑同样 18 组配置,看效应量如何随模型 scale 衰减

**最有价值的切入点**:把 procedural data generation + multi-model difficulty calibration 工程化,做成一个可以支持任意新领域冷启动 RLVR 的平台。这比单纯发表新 benchmark 有更长期的复利价值,与大厂"一键 fine-tune"类产品路径天然契合。

## 8. 总结

这篇论文在一个被主流 RL scaling 研究忽视的区间(低数据 + 低算力 SLM RLVR)做了一次诚实的经验刻画。核心贡献是:(1) 贡献了三个 procedurally-generated、难度可控、可自动验证的推理数据集;(2) 给出了"Mixed-100 ≈ Easy-500"的 5× 样本效率观察,以及 mixed 数据对训练稳定性的替代作用;(3) 指出在固定预算下,数据组成可能比数据量更关键,且硬样本可能被 token budget 约束抑制。

局限同样明显:单 seed、单一 4B 模型 + LoRA、三套不同的 reward、Graph 数据实验接近 negative result、难度分层存在对自己 base model 的自循环风险,以及"scaling law"的措辞对这个实验规模而言略显夸张。作者对这些 caveat 的自我声明是比较清楚的(论文明确定位为"generate hypotheses rather than definitive causal claims")。

适用场景:在工业界新领域冷启动 RLVR、预算受限的 SLM 精调、教学与研究中的 procedural benchmark 工具链。不适合直接套用的场景:大模型 SOTA 训练、需要严格 scaling law 保证的工业部署。
