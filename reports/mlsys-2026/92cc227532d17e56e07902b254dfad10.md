# SkipKV: Selective Skipping of KV Generation and Storage for Efficient Inference with Large Reasoning Models

**作者**：Jiayi Tian (UC Santa Barbara), Seyedarmin Azizi (USC), Yequan Zhao (UCSB), Erfan Baghaei Potraghloo (USC), Sean McPherson (Intel Labs), Sharath Nittur Sridhar (Intel Labs), Zhengyang Wang (UCSB), Zheng Zhang (UCSB), Massoud Pedram (USC), Souvik Kundu (Intel Labs)

**链接**：arXiv:2512.09370

## 一、背景

大型推理模型（Large Reasoning Models, LRMs），如 DeepSeek-R1，通过冗长的 Chain-of-Thought（CoT）过程进行复杂推理。这种长推理链导致 KV cache 线性增长，产生巨大的内存开销。例如，DeepSeek-R1-Distill-Llama-8B 解决一个复杂数学问题可能生成超过 32K token；在 batch size 为 10 时，KV cache 内存约为模型权重的 2.5 倍。KV cache 的持续增长不仅消耗大量内存，还影响 decode 阶段的吞吐量，成为 LRM 部署的关键瓶颈。

现有 KV cache 压缩方法（如 H2O、SnapKV、R-KV）主要针对 long-context prefill 场景设计，在 CoT 推理任务中效果不佳。

---

## 二、要解决的问题

作者通过三个关键观察揭示了现有 token 级 KV eviction 方法的根本缺陷：

1. **Multi-batch 解码精度大幅下降**：由于 batch 内不同样本 prefill 长度差异大，padding token 占用了有效 KV 预算，导致 H2O 和 R-KV 在 multi-batch 设置下精度严重退化。

2. **KV eviction 反而导致生成更长的推理链**：token 级 eviction 造成上下文信息丢失，模型为了补偿会重新推导、重复验证，产生比无压缩时更长的输出。

3. **Token 级 eviction 造成碎片化删除，引发 overthinking**：R-KV 等方法常常从关键数学计算步骤中移除数字 token，或保留最终答案的碎片 token，迫使模型反复重新验证部分结果，生成冗余的非执行思维（non-execution thoughts）。

---

## 三、洞察与设计

**关键洞察**：CoT 推理的冗余存在于句子（sentence）级别而非 token 级别——错误推理的输出中包含显著更多的高相似度句子（1.7× 于正确输出）和非执行思维（2.6× 于正确输出），这意味着以句子为粒度的语义感知 eviction 能更好地在保持推理连贯性的同时去除冗余。

基于此洞察，SkipKV 包含三个核心组件：

### 1. Sentence-level KV Storage Skipping（句子级 KV 存储跳过）

- 用 last-layer hidden state 的均值作为句子的 embedding（避免额外 sentence transformer 开销）
- 计算 Pairwise Sentence Similarity (PSS)，相似度超过阈值 τ（0.95~0.99）的早期句子标记为冗余
- 设计 Cumulative Score 综合 token importance、token redundancy 和 sentence similarity 三个维度，其中 sentence similarity 分数（≥0.95）远高于 token 级分数（~0.1），确保高冗余句子优先被驱逐
- 引入 Cache Range Monitoring Logic，维护 generation space 到 cache space 的索引映射，确保句子级别的一致驱逐

### 2. Adaptive Steering（自适应引导生成跳过）

- 构建 steering vector：用 MATH 训练集的 execution 和 non-execution 思维的隐藏状态差的均值
- 将 steering vector 注入特定层的 hidden states：$H_k \leftarrow H_k + \alpha_t \cdot V$
- 与 SEAL 不同，SkipKV 动态调整 steering 强度：$\alpha_t = \alpha_0 + N_o \cdot \gamma$，其中 $N_o$ 是已生成的 non-execution 思维计数，使得模型越发散越强力纠正

### 3. Batch Grouping（批次分组）

- 按 prefill 长度排序后重新分批，减小 batch 内 prefill 长度差异
- 大幅降低 padding token 数量，提高有效 KV 预算

---

## 四、实现细节

- **压缩频率**：每 128 个 decoding step 压缩并更新 KV cache
- **Score 权重**：attention-redundancy trade-off factor σ = 0.1
- **Steering vector 注入层**：R1-Qwen-7B 和 R1-Llama-8B 在第 20 层，R1-Qwen-14B 在第 35 层
- **Steering 参数**：初始 α₀ = 1 或 1.25，增量因子 γ = 0.02
- **句子分割**：基于换行和标点模式（`\n`、`.\n`、`)\n` 等）
- **Non-execution 检测**：简化为关键词匹配（"Wait"、"Alternatively"、"again"）
- **Sentence embedding**：直接用 last-layer hidden state 在句子 token 范围内取均值，无需外部模型
- 所有实验在单张 NVIDIA A100 (40GB) 上运行

## 五、实验结果

### 模型与数据集

- 模型：DeepSeek-R1-Distill-Qwen-7B/14B、R1-Distill-Llama-8B
- 数据集：AIME-24、MATH-500、LiveCodeBench、GSM8K

### 精度对比（vs H2O、R-KV、FullKV，multi-batch，pass@1）

## 六、批判性分析

1. **Non-execution 检测过于简化**：仅依赖三个关键词（"Wait"、"Alternatively"、"again"）检测 non-execution 思维，远不足以覆盖真实推理中的各种反思和验证模式。这个简化的合理性和鲁棒性未被充分验证。

2. **Steering vector 的泛化性存疑**：Steering vector 仅从 MATH 训练集的 500 个样本构建，但被应用于 AIME-24、LiveCodeBench 等不同领域的推理任务。数学推理和代码生成的"execution vs non-execution"语义可能有本质差异，论文未讨论 steering vector 的跨任务迁移性。

3. **句子相似度阈值敏感性分析不足**：τ 在 0.95~0.99 之间选择，但不同模型、不同任务上应如何设置缺乏系统的消融实验。

4. **实验基线不够全面**：仅对比了 H2O、R-KV 和 SEAL，缺少与 ThinkV（同期工作，也针对推理模型的 KV 压缩）的直接对比。

5. **SkipKV 有时精度超过 FullKV**：如 R1-Qwen-7B 在 AIME-24 上 SkipKV（20% budget）达到 50% 精度而 FullKV 仅 46.7%。作者将此归功于减少了冗余推理，但这也可能是小样本（AIME-24 仅 30 题）的统计波动，论文未提供置信区间。

6. **128 步固定压缩间隔的合理性**：每 128 步压缩一次是固定参数，但不同任务和推理阶段的句子长度和冗余程度差异很大。为什么不根据实际冗余水平自适应调整压缩频率？

7. **仅验证了 DeepSeek-R1 蒸馏模型**：所有实验在 7B-14B 的蒸馏模型上进行，对更大规模的原生推理模型（如 R1-671B）的适用性未知。

---

## 七、AI Infra / MLSys 视角

1. **句子级 KV 管理的范式启发**：现有推理引擎（vLLM、TensorRT-LLM）的 KV cache 管理都在 token 级别操作。SkipKV 提出的句子级视角——维护 generation space 到 cache space 的映射、以语义单元为粒度管理缓存——值得推理引擎探索，可以作为 PagedAttention 之上的更高层抽象。

2. **自适应 steering 与系统调度的结合**：Steering 强度根据 non-execution 思维计数动态调整的思路可以扩展到系统层面：将推理效率（token/answer 比率）作为运行时信号，动态调整计算资源分配、batch 调度策略等。

3. **Batch grouping 的实际部署价值**：按 prefill 长度排序分批是一个简单但有效的工程优化，可直接应用于 continuous batching 场景。但论文假设所有请求同时到达（offline），在线 serving 场景需要额外的 buffering 和 scheduling 策略。

4. **可操作的研究方向**：
   - 将 sentence-level eviction 集成到 vLLM 等推理引擎中，研究与 PagedAttention 和 chunked prefill 的兼容性
   - 探索 adaptive steering 在 speculative decoding 中的应用：steering 减少冗余生成可能提高 draft model 的接受率
   - 研究 KV eviction 策略的在线学习：根据当前请求的推理模式动态调整 τ 和 σ 参数

---

## 八、总结

SkipKV 是一个面向大型推理模型的 training-free KV cache 压缩框架，通过句子级冗余检测跳过 KV 存储、自适应 steering 抑制冗余生成、以及 batch grouping 提高有效 KV 预算三个机制协同工作。在 multi-batch 设置下，SkipKV 相比 R-KV 实现最高 26.7% 的精度提升和 1.6× 的生成长度缩减，吞吐量较 FullKV 提升 9.6×。其核心价值在于将 KV eviction 从 token 级提升到句子级语义粒度，但在 non-execution 检测的鲁棒性、steering vector 的跨任务泛化性以及大规模模型的适用性方面仍有待进一步验证。
