# SkipKV: Selective Skipping of KV Generation and Storage for Efficient Inference with Large Reasoning Models

**作者**：Jiayi Tian, Seyedarmin Azizi, Yequan Zhao, Erfan Baghaei Potraghloo, Sean McPherson, Sharath Nittur Sridhar, Zhengyang Wang, Zheng Zhang, Massoud Pedram, Souvik Kundu

## 1. 背景

大型推理模型（Large Reasoning Models, LRMs）如 DeepSeek-R1 系列通过长链式思考（chain-of-thought, CoT）在数学推理、代码生成等复杂任务上取得了显著突破。然而,这种冗长的推理过程直接导致推理阶段生成的 token 数量线性膨胀,进而使 KV cache 的显存占用成为部署瓶颈。举例来说,一个 8B 参数的 R1-Distill 模型在求解一道数学题时可能生成超过 32K tokens,当 batch size 为 10 时,KV cache 的显存占用可达模型权重的约 2.5 倍。

为缓解 KV 显存压力,学术界提出了两类主流方法:**KV 驱逐（eviction）** 和 **KV 量化**。本文聚焦于前者,代表工作包括:

- **H2O**（Zhang et al., 2023）：基于累积注意力得分保留"重击（heavy-hitter）"token
- **SnapKV**（Li et al., 2024）：在 prefill 阶段一次性压缩 KV cache
- **Quest**：将 FullKV 保留在全局内存,按 query 相关性拉取 chunk 到本地
- **R-KV**（Cai et al., 2025）：当前的 SoTA,提出 redundancy-aware token 得分,在单 batch 下能达到 >80% 压缩率

这些方法均在 prefill 长上下文场景表现良好,但在 CoT 推理场景下存在严重缺陷,这也是本文要解决的核心问题。

## 2. 要解决的问题

作者首先通过一系列 motivation 实验,系统揭示了现有 token 级 KV 驱逐方法在 LRM 推理场景下的三大失败模式:

1. **多 batch decoding 下准确率严重下降**：R-KV 和 H2O 在 batch-size=1 时尚能维持精度,但一旦 batch-size 增大到 10,准确率显著掉落。根因是不同样本 prefill 长度差异大(MATH-500 数据集批内 prefill 长度差可超 400 tokens),batch 内需要大量 padding tokens 对齐,这些 padding 挤占了有限的 KV 预算,使得"有效 KV 预算"被严重腐蚀;同时 padding 还扭曲了注意力分布,让 token 级重要性估计失稳。

2. **压缩后生成序列反而更长**：在固定 KV 预算下,带 R-KV 压缩的模型生成的 token 数量跨所有预算档位都**超过**了 FullKV 基线。这是反直觉的——本想节省显存却反而增加了 forward pass 次数,压缩收益被生成延长所抵消。

3. **token 级驱逐会产生碎片化保留**：R-KV 基于 token 级冗余评分,经常保留最终答案"6 + 9i"中的碎片 token(例如 `+ 2i`、`(, 9)`),或者从关键计算步骤中抽走数字(例如 `6+12i-3i` 中的 `6`、`12`)。模型看到这些碎片后会反复自我验证和重新推导,陷入 overthinking,生成"等等,让我再检查一遍……"式的冗余发散,使 CoT 变得臃肿。

此外,作者通过 sentence 级统计发现:错误回答中**高相似度句子比例** 比正确回答高 1.7×(R1-Qwen-7B 错误样本达 78.8%,正确样本 51.3%),**非执行性思考（non-execution thoughts）** 比例高 2.6×。这说明失败的推理轨迹本质上就是在反复打转,也佐证了"如果能抑制这种重复,就能同时提升精度和效率"的假设。

## 3. 洞察与设计

**关键洞察**：LRM 的推理轨迹具有天然的句子级语义结构——真正有害的冗余是**整句 / 整段**的语义重复(例如"Wait, let me double-check" 式的 non-execution 思考),而不是孤立 token 的冗余。基于句子粒度对 KV 进行驱逐,能同时(1)保留推理链的语义连贯性,避免模型因碎片保留而产生 overthinking;(2)从根源上移除导致推理失败的重复性思维片段。此外,redundant sentence 的相似度得分(≥0.95)天然比 token 级得分(∼0.1)高一个数量级,这让两种信号可以在同一评分公式中和谐共存,而无需复杂调参。

基于这一洞察,SkipKV 提出了**句子感知的选择性 KV 驱逐与生成抑制框架**,由三大组件构成:

![SkipKV Overview](../../markdowns/mlsys-2026/92cc227532d17e56e07902b254dfad10/images/40cf974be088e388cfa11d5737a9177f0c71695e671cd35bd57e11695afd33e2.jpg)

### 3.1 句子级评分驱逐 KV 存储（§4.1）

- **句子嵌入的廉价获取**：不另外跑 sentence transformer,直接复用模型最后一层 hidden state,对句子范围内的 hidden 取均值作为句向量 `v_i = mean(H[k]_{b_i:e_i})`
- **PSS (Pairwise Sentence Similarity)**：`PSS(v_i, v_j) = v_iᵀ v_j`;阈值 τ(默认 0.95–0.99)以上的句对中,较早的句子 i 被加入冗余集 𝒫
- **融合评分公式**：

  ```
  I_final = σ·I_α - (1-σ)·R - λ_{i,j}   (若 i ∈ 𝒫)
          = σ·I_α - (1-σ)·R              (否则)
  ```

  其中 `I_α` 是 SnapKV 风格的注意力重要性,`R` 是 R-KV 风格的 token 冗余,`λ_{i,j}` 是句子冗余得分。由于 `λ_{i,j}` 量级远大于 token 级分数,冗余句内的 token 会被优先驱逐。
- **生成空间–缓存空间的 mapping Φ**：为了在多轮压缩中持续追踪句子范围,引入一套查找表 𝒯 和 range monitoring 机制,分 pre-eviction(初始化 / 追加新句)和 post-eviction(按存活 token 索引重映射)两阶段更新(见 Eq. 9–11)。

### 3.2 自适应 steering 抑制 KV 生成（§4.2）

受 SEAL（Chen et al., 2025）启发,先用 MATH 训练集的 500 个样本构造 steering vector `V = H̄_E − H̄_O`（执行型 vs 非执行型思考的 hidden state 差），在第 k 层注入 `H_k ← H_k + α_t · V`。与 SEAL 使用固定 α 不同,SkipKV 动态调整 steering 强度:

```
α_t ← α_0 + γ · N_o
```

其中 `N_o` 是当前累计的非执行思考数。模型越倾向于"等等,让我再检查一遍",steering 强度就越大,抑制效果越强,形成负反馈闭环。

### 3.3 Batch Grouping 提升有效 KV 预算（§4.3）

这是一个简洁而有效的工程优化:**按 prefill 长度对样本排序**,然后顺次打包成固定 batch。batch 内最大 prefill 与最小 prefill 的差距被压到最小,padding token 数量随之骤降,有效 KV 预算 `B′ = B − Δ_pad` 逼近名义预算 B。以 MATH-500 为例,KV budget=768 时,平均有效预算从 630 (21%) 提升到 759 (25%)。

## 4. 实现细节

**算法流程**（Algorithm 1 + 2）:

- **压缩周期 Δ_t = 128 个 decoding step**:每 128 步触发一次句子评分 + KV 驱逐。
- **句子分割**:依据 newline 集合 𝒟 = `{"\n", ".\n", ")\n", "\n\n", …}` 和非执行关键词集合 𝒩 = `{"wait", "Alternatively", "again"}`,在生成过程中在线标注"Execution" vs "Others"(非执行)。
- **steering 插入层**:R1-Qwen-7B 和 R1-Llama-8B 选第 20 层,R1-Qwen-14B 选第 35 层;`α_0 ∈ {1, 1.25}`,`γ = 0.02`。
- **token 重要性 trade-off**:`σ = 0.1`(即偏向冗余信号而非注意力信号,与 R-KV 一致)。
- **GQA 适配**:token 重要性矩阵按 key-value head 做 maxpool 聚合,再 softmax 归一化。
- **padding-aware 冗余得分**:在 Eq. 5 中用 attention mask M 对 key 做归一化前的 mask 乘法,降低 padding token 对冗余计算的污染。
- **实测环境**:单卡 A100-40GB,配合 FlashAttention-2。

**算法 1 的关键是 range monitoring**:每次 eviction 后,原有的句子边界 `(b_i, e_i)` 在新 cache 空间下会错位。作者用 Eq. 11 扫描存活 token 索引集 P,把 `b_i` 重置为"不早于原始 start 的最早存活索引",`e_i` 重置为"不晚于原始 end 的最晚存活索引",若句子所有 token 都被驱逐则整条 range 丢弃。

## 5. 实验结果

**评测模型**:DeepSeek-R1-Distill-Qwen-7B / 14B / Llama-8B
**评测数据集**:AIME-24、MATH-500、GSM8K、LiveCodeBench
**Baselines**:FullKV、H2O、R-KV、SEAL

### 5.1 精度对比

![Accuracy across budgets](../../markdowns/mlsys-2026/92cc227532d17e56e07902b254dfad10/images/bc502c0d9e45147dcf36134fd474a7ed436a46201e00067e7902a742dbf9b594.jpg)

在所有模型 × 数据集 × KV 预算档位上,SkipKV 精度全面优于 H2O 和 R-KV,且经常**接近或超过 FullKV**:

- AIME-24 + R1-Qwen-14B:仅用 15% KV budget 就达到与 FullKV 相当的 60% 精度(6.7× 显存压缩),在 41% 预算下甚至**超越** FullKV 10 个百分点(65% vs 60%)
- LiveCodeBench + R1-Qwen-7B:2× 压缩下精度比 FullKV 提升 5.2%
- MATH-500 上 SkipKV 曲线几乎贴着 FullKV

### 5.2 生成长度对比

![Token length](../../markdowns/mlsys-2026/92cc227532d17e56e07902b254dfad10/images/6ee92f8c32e7d0886d0b5c87430c4b445536dfef18a4d24ca1cfd69e5da662c4.jpg)

生成长度的对比最具视觉冲击力——H2O 和 R-KV 的曲线**全部位于 FullKV 之上**(压缩反而变长),而 SkipKV 曲线**全部位于 FullKV 之下**。相较 R-KV,SkipKV 在 R1-Qwen-7B / 14B / Llama-8B 上分别可减少最高 32% / 39% / 48% 生成 token,转化为 1.5–2× 的 decoding 延迟降低。

## 6. 批判性分析

虽然 SkipKV 的实验结果很出彩,但仔细审视仍有若干值得质疑的地方:

1. **"超越 FullKV"的结论需要审慎解读**。论文在 AIME-24 上展示 41% KV budget 下精度反超 FullKV 10 个百分点,并将其归因于"压缩后生成更简洁"。然而 AIME-24 只有 30 道题,10 个百分点意味着 **3 道题**的差异,考虑到 pass@1 的采样方差(论文没报告多 seed 均值和方差),这类反超很可能在统计噪声范围内。作者 3×30 = 90 个点的测试规模下,5% 的置信区间至少在 ±5%,需要更多 seed 验证才能支撑"超越 FullKV"的叙事。

2. **steering vector 的领域依赖性被轻描淡写**。Steering vector 是用 MATH 训练集 500 个样本构造的,作者直接把这个向量用到代码生成(LiveCodeBench)上并报告了正向结果。但代码生成中的"非执行思考"模式(调试、类型推断)与数学推理的"Wait / Alternatively"模式结构截然不同,steering 向量的迁移性缺少分析——是 vector 本身迁移好,还是因为 γ=0.02 本来就足够保守所以没翻车?论文没有提供"换领域时 steering vector 是否需要重构"的消融。

3. **非执行关键词集 𝒩 过于朴素**。𝒩 = {"wait", "Alternatively", "again"} 只有 3 个英文关键词。这种硬编码列表在跨模型(中文 R1 变体)、跨数据集(竞赛题以外的场景)时会不会失效?论文对关键词选择没有鲁棒性实验,也没讨论如何自动扩展 𝒩。

4. **句子切分依赖 punctuation pattern,对无标点长推理脆弱**。DeepSeek-R1 风格的推理偶尔会生成没有充分标点的长段落,这时句子边界无法正确识别,整个框架的前提就会失效。作者没有报告"句子长度分布对方法敏感度"的分析。

5. **Batch Grouping 的公平性值得商榷**。Batch Grouping 本质上改变了推理服务的调度策略——线上服务通常是 streaming 请求,不可能等齐一批再按 prefill 长度排序。论文实验默认是离线 batch evaluation 场景,而 Table 1 的 throughput 数据也是在离线假设下得出。**在线服务场景下 Batch Grouping 基本不可用**,那去掉这一项后 SkipKV 相对 R-KV 的优势会缩水到什么程度?论文应该单独报告 "+ Sentence Scoring + Adaptive Steering" 配置在 online 场景的表现。

6. **压缩开销未被严格评估**。每 128 步做一次 PSS 计算、range mapping 更新、final score 排序,这些操作在 GPU 上也是有成本的——尤其是 range monitoring 的 index remap(Eq. 11)在长生成下 n(句子数)可能达到几百,对 GPU 不友好。Table 1 报告的是端到端 throughput,没有细分"计算 PSS 花了多少 ms"。这使得"SkipKV 比 R-KV 快 1.7×"的说法无法定位到真正的瓶颈。

7. **未讨论与 KV 量化(KIVI、GEAR)正交组合的可行性**。论文把量化定义为"正交方向"后就不再展开,但一个完整的推理系统通常需要 eviction + quantization 叠加使用,SkipKV 的句子结构假设在 2-bit 量化后是否仍成立,是工业界落地时的关键问题,论文回避了这个问题。

## 7. AI Infra / MLSys 视角

本文对 AI Infra / MLSys 研究者非常有借鉴价值,可以从以下几个维度展开:

### 7.1 语义粒度压缩的范式启示

KV cache 压缩社区过去过度聚焦于 token 粒度,本文把粒度向语义层次(句子、段落)抬升,是一个**有启发价值的范式迁移**。这个思路可延伸到:

- **段落 / 推理步骤级别的压缩**:对于 Agent 场景下的多轮对话历史,能否以"一次工具调用 + 其响应"为单位做语义驱逐?
- **跨 turn 的 KV 复用**:Agent 多轮中重复访问同一文档,能否用 embedding 识别"语义重复段"并做 deduplication?
- **多模态场景的 KV 压缩**:视觉-语言模型的 KV 中,图像 token 往往是整张图作为语义单元,天然比单 token 更适合粗粒度驱逐。

### 7.2 Padding-aware 的系统优化

"有效 KV 预算 = 名义预算 − padding 腐蚀"的视角很有洞察力。Batch Grouping 给出的启示是:**推理服务的调度层和 KV 压缩算法必须协同设计**。在 continuous batching(vLLM / SGLang)框架下,padding 通过 paged attention 已经被大幅缓解,但不同 sequence 的 KV 预算仍会动态竞争。可以研究:

- **Paged KV + sentence-level eviction 的协同**:能否在 vLLM 的 block manager 里,以 sentence 为单位申请 / 释放 block?
- **KV 预算的公平调度**:当多个 request 共享 KV pool 时,如何按"推理复杂度"动态分配预算(简单题少分配,复杂题多分配)?
- **Speculative decoding 与 sentence eviction 的结合**:draft model 生成的候选序列中被 reject 的部分,其 KV 显然是浪费的,能否触发一次"强制 eviction"?

### 7.3 Adaptive Steering 的闭环控制视角

SkipKV 的 `α_t ← α_0 + γ · N_o` 本质上是一个**最朴素的 PID 控制器的 P 项**。LRM 推理是一个动态过程,steering 强度应该是闭环的而不是开环的,这个思路有进一步研究空间:

- **PID 扩展**:加入 I 项(累积非执行比例)和 D 项(非执行比例的变化速度)是否能更平滑地控制 steering?
- **基于 reward model 的在线 steering**:用一个轻量 reward model 实时打分推理质量,替代"数关键词"的启发式?
- **跨层 steering**:当前只在一层注入 V,能否在多层协同注入,达到更精细的推理风格控制?

### 7.4 值得跟进的 future work

1. **Online serving 版 SkipKV**:去掉 Batch Grouping 依赖,设计适配 continuous batching 的句子级压缩机制。
2. **无训练的 steering vector 自动发现**:不依赖标注的 execution / non-execution 样本,用自监督方式从模型自身的 hidden state 聚类中提取 steering 方向。
3. **与 speculative decoding 结合**:SkipKV 大幅缩短生成长度,而 speculative decoding 大幅加速每个 token 的生成,两者乘积效应在 LRM serving 上或许能做出量级级的吞吐提升。
4. **面向 RL post-training 的启示**:如果 LRM 经常生成冗余的 non-execution thoughts,能否在 RLHF / RLVR 的 reward 中加入"简洁性"惩罚,从训练阶段就解决这个问题?这将与本文的推理期方法形成互补。

### 7.5 最有价值的切入点

我认为最有可操作性的延伸工作是**面向 Agent 的 KV 压缩**。当前 Agent 系统(Claude Code、ChatGPT Agent)的上下文普遍包含大量重复的工具调用历史,这种重复的语义粒度比数学推理中的"等等让我再检查"还要粗——几乎是段落级甚至整条消息级。把 SkipKV 的句子相似度替换为消息 / 工具调用相似度,结合历史重要性(某个工具的输出被后续步骤引用了多少次),应该能在 Agent 长上下文推理中做出更大幅度的压缩。这个方向的优势是:(1)Agent 场景商业价值大;(2)数据集易于构建(SWE-bench 等已经提供了丰富的 Agent trajectory);(3)和本文的方法路径高度一致,工程风险可控。

---

## 8. 总结

SkipKV 通过将 KV cache 压缩的粒度从 token 上移到句子,并辅以自适应 steering 抑制 non-execution 思考,以及 batch grouping 消除 padding 腐蚀,在 LRM 推理场景下同时取得了"更高精度、更短生成、更大吞吐"的三重收益——相比 SoTA R-KV 最高 26.7% 精度提升、1.6× 更短生成和 1.7× 更高吞吐,相比 FullKV 达到 6.7× 显存压缩和 9.6× 吞吐。方法的适用场景是需要大批量部署的数学 / 代码推理服务,主要局限是 Batch Grouping 在 online serving 下不适用、steering vector 的跨领域迁移性不足、句子切分依赖硬编码的标点 / 关键词规则,这些都为后续研究留下了空间。
