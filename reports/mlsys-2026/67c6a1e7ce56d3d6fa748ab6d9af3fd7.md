## 1. 背景

大语言模型(LLM)的解码阶段是典型的 memory-bound 问题:延迟由权重和 KV cache 的加载时间主导,而非计算时间。自回归(AR)模型每步只能产出一个 token,无法充分利用 GPU 的计算密度,尤其在小 batch size 下 MFU 极低。扩散语言模型(dLM,如 LLaDA、Dream、Block Diffusion)提供了一条并行解码的路径,但存在经典的「并行度 vs. 质量」矛盾:每步解码越多 token,token 独立性假设带来的 sequence-level 不一致越严重,质量下降越明显。

另一条提速路线是 speculative decoding:用小模型快速 draft、大模型 verify。然而 draft 模型容量受限,draft 过程本身是串行的,且 draft 与 verify 无法同时进行,最大可获得的加速比有上限。EAGLE 系列、DeepSeek-V3 MTP、Apple MTP 等通过挂载额外的 draft head 改进了这一点,但仍未真正打破「draft 串行」和「draft 容量不足」两个根本约束。

作者提出本文的出发点:能否把扩散的并行能力和 AR 的质量保证**融合在同一个模型的同一次前向里**,用好 GPU 在 memory-bound 区段的「免费」 compute 余量?

---

## 2. 要解决的问题

现有并行解码方案在三个维度无法同时满足需求:

1. **质量**:多 token 并行解码引入 token 独立性假设,使扩散模型的生成质量显著下降(例如 Dream-7B 在 GSM8K 上从 1 token/step 增加到 2 token/step 时掉 10%)。
2. **draft 容量**:speculative decoding 的 drafter 必须小才有速度收益,但小模型草稿质量差导致 acceptance rate 低、实际吞吐受损。现有 MTP/EAGLE 方案让 drafter 复用 base model hidden state,但 drafter 本身仍然只能自回归地产出 token,无法充分利用计算密度。
3. **draft-verify 串行**:即使 drafter 再快,draft 阶段与 verify 阶段在时间轴上是先后关系,端到端延迟并未真正压低。

此外,扩散模型由于双向注意力,**无法精确 KV-cache**,这让 dLM 在工程落地时又额外吃亏(Fast-dLLM、d-KV Cache 只能做近似缓存)。

TiDAR 要解决的核心问题:在**一次** forward pass 中同时完成「draft 多个未来 token」+「对上一步 draft 的 token 做 AR rejection sampling」,并保持精确 KV cache,从而在 GPU memory-bound 区段内把免费算力吃满。

---

## 3. 洞察与设计

**关键洞察**:在 GPU memory-bound 解码场景下,单步前向的延迟主要被权重加载和 KV cache 读取占据,把序列长度从 1 加到几十甚至上百个 token slot,延迟曲线几乎是平的(论文 Figure 1 在 H100 上实测 Qwen3-32B,token slots 从 1 增加到 ~100 时延迟基本不变)。这意味着在单次前向里**可以免费塞入数十个 mask token 做扩散 drafting,不增加延迟**——作者称之为 "free token slots"。只要把 draft 和 verify 塞进同一次前向,前者来自扩散分支的 marginal distribution,后者来自 AR 分支的 chain-factorized joint distribution,就能同时拿到扩散的并行度和 AR 的质量。

基于这一洞察,TiDAR 的设计如下:

- **双模态 backbone**:训练时把序列长度翻倍——原 clean 序列 + 追加的 mask 序列。用一个混合注意力掩码让 clean token 之间走 causal attention(AR 目标、NTP loss),让 mask token 对 prefix 走 causal、对同 block 内部走 bidirectional(扩散目标、mask prediction loss)。两种 loss 在同一次前向中同时计算、加权求和。
- **全掩码(full-mask)训练策略**:与 Block Diffusion/SBD 的随机 mask 不同,TiDAR 在扩散段把所有位置都置为 mask。好处:① 扩散 loss 信号更密集;② AR loss 与 Diff loss 的 token 数完全一致,加权平衡简单(作者直接用 α=1);③ 让 inference 时「一步扩散 drafting」与训练分布一致。
- **并行 draft + sample 的前向布局**(Figure 2):每一步前向的输入序列被划成三段:
  1. **Prefix tokens**:已确认的 token,复用上一步的 KV cache,走 causal attention。
  2. **Tokens drafted from last step**:上一步 draft 出来的候选 token,本步走 causal attention,用其 AR logits 对它们做 rejection sampling(与 speculative decoding 相同的 modified rejection strategy)。
  3. **Tokens pre-drafted for next step**:本步就要为下一步准备 draft。关键技巧是:由于 rejection sampling 的接受长度未知,作者对**每一个可能的前缀接受长度**都并行预生成一组 draft(用 bidirectional 注意力),等本步确定了接受长度后,再选对应的那组 proposal 交给下一步。
- **精确 KV cache**:causal 部分(prefix + drafted tokens)的 KV cache 可以完整保存,若 drafted tokens 被拒绝则 evict 对应位置,无需任何重算。这是相比 Block Diffusion / Fast-dLLM 的一个工程硬优势。
- **预初始化 attention mask + 切片复用**:训练/推理 mask 尺寸固定,用 Flex Attention 预 allocate `(max_seq_len + block_size)²` 的 mask,每步按 prefix 长度切片,避免重复构建稀疏掩码。

整体上,TiDAR 把 speculative decoding 中「小 drafter + 大 verifier」替换为「同一个大模型的扩散分支 draft + AR 分支 verify」,且两者在一次 forward 内完成,draft 容量 = base model 本身。

## 4. 实现细节

- **模型初始化**:从 AR checkpoint 继续预训练(continual pretrain),1.5B 基于 Qwen2.5-1.5B,8B 基于 Qwen3-8B。
- **训练数据/算力**:1.5B 模型 50B tokens,8B 模型 150B tokens。global batch size 2M tokens,seq length 4096,BF16。8B 开梯度检查点。优化器为 distributed Adam,cosine schedule(lr_max=1e-5,lr_min=3e-6,1% warmup)。
- **训练框架**:基于 Megatron-LM + Torchtitan 二次开发。
- **训练目标**(公式 5):
  $$\mathcal{L}_{TiDAR} = \frac{1}{1+\alpha}\left(\sum_i \frac{\alpha}{S-1}\mathcal{L}_{AR}(x_i, x_{i+1}) + \sum_i \frac{1}{S-1}\mathcal{L}_{Diff}([\text{mask}], x_i)\right)$$
  默认 α = 1。
- **关键数据结构**:双倍长度的输入序列 `[x_1, ..., x_S, m, m, ..., m]`;训练 mask 是 `(2S, 2S)` 的 block-structured 矩阵(Figure 3 左)。
- **推理超参**:几乎无需调节——block size(draft 长度)可以零样本调整(4/8/16 都能跑)。sampling 时可选「Trust AR」或「Trust Diff」(通过混合 logits 前的加权系数 β 控制)。
- **验证鉴别**:采用与经典 speculative decoding 相同的 modified rejection sampling,质量等价于从 AR 分布采样(但不等价于 base AR 模型的精确输出——见下文批判)。

## 5. 实验结果

**生成任务(Coding + Math,Table 2)**:

| Model | Size | HumanEval | MBPP | GSM8K | Minerva Math | Avg | T/NFE |
|---|---|---|---|---|---|---|---|
| Qwen2.5 (AR baseline) | 1.5B | 35.98% | 43.60% | 54.74% | 26.40% | 41.64% | 1.0 |
| Qwen3 | 1.7B | 48.17% | 55.80% | 66.72% | 29.74% | 52.22% | 1.0 |
| Block Diff | 1.5B* | 39.02% | 34.00% | 52.99% | 21.56% | 38.41% | — |
| **TiDAR** | **1.5B*** | **43.29%** | **41.40%** | **53.90%** | **25.48%** | **44.03%** | **7.45** |
| Qwen3 (AR baseline) | 8B | 64.63% | 69.40% | 81.80% | 52.94% | 68.09% | 1.0 |
| LLaDA | 8B | 32.32% | 40.80% | 70.96% | 27.30% | 41.78% | — |
| Dream | 7B | 54.88% | 56.80% | 77.18% | 39.60% | 58.74% | — |
| **TiDAR (Trust AR)** | **8B** | **55.49%** | **65.40%** | **79.83%** | **50.58%** | **63.90%** | **8.23** |
| **TiDAR (Trust Diff)** | **8B** | **57.93%** | **65.40%** | **80.44%** | **51.64%** | **65.31%** | **8.25** |

**端到端吞吐(Figure 4)**:
- TiDAR 1.5B: 相对 Qwen2.5-1.5B 吞吐 **4.71×**(平均 avg 图中 7.35×),质量几乎无损。
- TiDAR 8B: 相对 Qwen3-8B 吞吐 **5.91×**(平均图中 8.36×),质量有少量损失。
- 对比 EAGLE-3 (AngelSlim / Tengyunw 权重): TiDAR 8B 的吞吐加速远高于 EAGLE-3 的 3.5~4.5×,且 T/NFE 和 T/NFE→T/s 转化率都更高。

**Likelihood 任务(Table 3)**:TiDAR 可直接用 AR causal mask 计算 likelihood(传统 dLM 要用 Monte Carlo 128 步,非常慢),结果在 MMLU/ARC/Hellaswag/PIQA/Winogrande 上均与 AR baseline 可比,8B 平均 75.40% 超过 Qwen3-8B 的 74.25%。

**消融实验**:
- **Full-mask vs Random-mask**(Table 5):全掩码策略在 HumanEval 提升 ~6%,MBPP 提升 ~3%,T/NFE 也更高。
- **Decoding 策略对比**(Table 4):TiDAR (16 drafts) 在 T/NFE=6.97 时 HumanEval=41.16%,显著好于 confidence-based decoding(类似 T/NFE 下只有 22~28%)。
- **Trust AR vs Trust Diff**(Figure 6):两者在不同 α 下性能接近,说明 AR 与 Diff 预测收敛到一致,最终质量由 AR rejection sampling 保证。

**硬件**:全部在单张 NVIDIA H100 上、batch size = 1 测试,使用 PyTorch + Flex Attention,无自定义 kernel。

## 6. 批判性分析

1. **「close the quality gap with AR models」的措辞存在选择性**:1.5B TiDAR 的 avg 44.03% 确实超过其初始化点 Qwen2.5-1.5B (41.64%),但远低于同规模 Qwen3-1.7B (52.22%)。换句话说,作者证明的是「用 Qwen2.5 权重做 CPT 后得到的 TiDAR 1.5B 不差于 Qwen2.5 1.5B」,而非「TiDAR 跟上了当前最强 1.5B 级 AR」。读者容易被 abstract 中的「close the quality gap」误导。

2. **训练成本被完全回避**:TiDAR 需要 50B(1.5B)/150B(8B) tokens 的继续预训练,且序列长度**翻倍**——单步训练 FLOPs 约为同规模 AR 模型的 2×。作者通篇只报 inference 效率,没有给训练成本 vs. 加速收益的综合评估。对资源有限的小团队,这条线的可复现性要打问号。

3. **「beat speculative decoding」的对比不公平**:文中对比的是 EAGLE-3 公开权重(AngelSlim / Tengyunw 社区训出的),而 TiDAR 是作者自己用 150B tokens CPT 出来的。更公平的比较应该是「用同样 150B tokens 训 EAGLE-3 draft head」。作者虽然承认「speculative decoding 可以严格复刻 base model 分布而 TiDAR 不能」,但这是在小字里带过的根本性差异——对需要 output-level 一致性的场景(例如复现实验、数值稳定性要求高的应用),TiDAR 不是 drop-in 替代。

4. **batch size = 1 是最有利于 TiDAR 的配置**:"free token slots" 概念依赖于 memory-bound regime。一旦 batch 上来(典型推理服务 BS > 8),系统进入 compute-bound regime,额外 token slot 不再免费。作者在 Limitations 里只说「可以调整 block length 来适配」,却没有给任何 large batch 的实测数据,这在一篇吞吐导向的系统文章里是显著缺失。

5. **pre-draft proposal 的扩张成本被低估**:为了并行,每一步对**每一种可能的 acceptance 长度**都预生成一组 proposal(Figure 2 里的 Proposal 1/2/3)。block size=16 时意味着一次 forward 要同时算 16 组 proposal 的 mask token,这对 attention mask 大小和内存带宽是有成本的。论文给出了 T/s 的最终加速比,但没分解「免费 slot 具体用到什么密度、proposal 复用率如何」。如果真的有 ~100 个 free slot(Figure 1),剩余空间能否让 block size 进一步扩大?作者没讨论边界。

6. **评测面较窄**:TiDAR 只在 coding + math + knowledge(单选题)上评测,没有开放式生成(summarization、对话)。扩散 drafting 在长 free-form 文本上是否仍然保持高 acceptance rate?这与 GSM8K/HumanEval 这种短、结构化输出很不同。

7. **训练 loss 平衡用 α=1 而非调优**:作者说「well-trained 下两边 logit 会一致,所以 β 不敏感」——但 Figure 6 的平稳曲线是在作者选定的 α 区间下得到的,α 取极端值时的鲁棒性未讨论。

8. **`Figure 1` 的「free slot 上限」测的是 Qwen3-32B**,而 TiDAR 实际跑的是 1.5B 和 8B 模型。小模型 memory-bound 区段更短,"free" 边界会提前被打破。以 32B 的曲线背书 1.5B/8B 的 free slot 设计,理论外推不够严谨。

## 7. AI Infra / MLSys 视角

这是一篇典型的 MLSys 交叉工作,对 AI Infra 研究有几个直接启发:

1. **"Free token slots" 是可迁移的系统视角**:把 memory-bound 区段的 compute 余量视为可以被 prefill、draft、speculation 等并发任务「免费」消耗的资源,这个框架比只看 T/s 更有指导性。AI Infra 的 serving 引擎(vLLM、SGLang、TensorRT-LLM)可以借此重新设计 batch 组装策略——例如,在 decode batch 未达 compute-bound 之前,自动 fill in 其他请求的 prefill chunk 或 speculative draft,而不是等 batch 满。

2. **同模型自投机(self-speculation)是 EAGLE/MTP 路线的自然终点**:TiDAR 的思路本质是「既然 drafter 要和 base 共享 hidden state,不如直接让 base 自己 draft」。未来 speculative serving 可能会走向「单模型 + 结构化 mask + 一次 forward」,这会简化 serving 栈(不再需要两个模型的 KV cache 协同、不需要单独的 drafter checkpoint)。值得跟进的方向:在 vLLM 或 SGLang 中实现 TiDAR 风格的自投机调度器。

3. **精确 KV cache + 块级扩散是 dLM 落地的关键补丁**:此前 dLM 工程化最大的拦路虎就是双向注意力阻碍 KV cache。TiDAR 通过让 prefix 始终 causal 解决了这一点。如果小团队想做 diffusion-based serving,这个设计模板比 Fast-dLLM 的近似 cache 更可靠。

4. **可延伸的研究问题**:
   - **Multi-step TiDAR**:当前只做 1-step 扩散 drafting,是否可以让 draft 阶段内部多步 refine(类似 denoising chain),在更大 block 下维持 acceptance rate?
   - **large-batch 场景的 block size 自适应**:在 compute-bound regime 下应该如何动态调整 draft length?可以从 LLM serving 的 continuous batching 视角研究。
   - **与 tree-based verification 组合**:TiDAR 目前走线性 acceptance(draft 一串 token),能否与 Medusa/EAGLE-2 的 tree draft 组合,在一次 forward 里并行探索多条分支?
   - **kernel 协同**:Flex Attention 已经给了 30% 以上的加速,但文章明确说还有自定义 kernel 的空间。可做的工作:为 TiDAR 特定的「causal + 块级 bidirectional」mask 写 fused attention kernel,进一步挤压 8B 模型的延迟。

5. **对小团队有价值的切入点**:若无力做 150B tokens CPT,可以关注**用 TiDAR 风格的结构化 mask 做 post-training/LoRA 适配**(把已有 AR 模型在少量 data 上接个扩散 head),评估最小 CPT 预算下能拿多少加速比。这是原论文未覆盖的场景,也是最容易出高性价比结果的位置。

---

## 8. 总结

TiDAR 通过「扩散分支并行 draft + AR 分支逐 token rejection sampling」的混合架构,配合精心设计的双向/因果混合注意力掩码,在单次前向内同时完成多 token 的 draft 与 verify,把 GPU memory-bound 区段的 compute 余量(free token slots)兑换成 4.71~5.91× 的端到端吞吐加速,首次在 batch size=1 场景下超过 EAGLE-3 级别的 speculative decoding。核心贡献是**用一个模型、一次前向、精确 KV cache**的架构让扩散并行性与 AR 质量真正共存。主要局限是训练成本显著(翻倍序列长度 + 50~150B CPT)、large batch 场景未验证、且与 base AR 模型的 output-level 严格一致性不再保证。适合对延迟极度敏感、可接受小幅分布偏移的 serving 场景。
