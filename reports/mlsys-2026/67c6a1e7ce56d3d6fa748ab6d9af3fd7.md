## 一、背景

大语言模型（LLM）的推理效率是当前 AI 系统面临的核心挑战之一。Autoregressive（AR）模型在生成质量上占据主导地位，其因果结构与语言建模天然对齐，但解码过程是 memory-bound 的——每一步只生成一个 token，无法充分利用 GPU 的计算密度，尤其在小 batch size 场景下。

Diffusion language models（dLMs）提供了并行生成多个 token 的可能性，理论上可以利用 GPU 的空闲计算资源。然而，现有 dLMs（如 Dream、LLaDA）面临一个根本性矛盾：并行解码越多 token，生成质量越差。这源于 token 间的独立性假设——并行解码的 token 从边际分布独立采样，破坏了序列级的连贯性。

另一条加速路线是 speculative decoding，用小模型草拟 token、大模型验证。但小草拟模型的容量有限导致接受率低，且草拟和验证是串行的，无法充分利用计算资源。

---

## 二、要解决的问题

1. **AR 模型计算利用率低**：解码阶段 memory-bound，每步只产出一个 token，GPU 计算密度远未饱和。论文通过 profiling 发现在一定范围内增加 token slots 几乎不增加延迟（"free token slots"），这些计算资源被浪费了。

2. **Diffusion LLM 的质量-并行度矛盾**：并行解码多个 token 引入 token 独立性假设，导致生成质量显著下降。Dream-7B 在 GSM8K 上从 1 token/step 增加到 2 token/step 就下降 10% 准确率。

3. **Speculative decoding 的效率瓶颈**：草拟模型容量低、草拟过程串行、草拟与验证分离——这三个因素共同限制了加速上限。

---

## 三、洞察与设计

**关键洞察**：GPU 在 memory-bound 区间存在大量"free token slots"——在单次 forward pass 中额外携带若干 token 几乎不增加延迟。如果能在这些免费 slots 中同时完成 diffusion 并行草拟和 AR 验证采样，就能在不牺牲质量的前提下大幅提升吞吐。

基于这一洞察，TiDAR 设计了一种序列级混合架构：

**架构核心**：在单次 forward pass 中，将输入序列划分为三个部分——(1) prefix tokens（使用 exact KV cache），(2) 上一步草拟的 tokens（用 AR causal attention 做 rejection sampling 验证），(3) 为下一步预草拟的 mask tokens（用 bidirectional attention 做 one-step diffusion 草拟）。

**Attention Mask 设计**：通过精心设计的 structured attention mask 实现双模式共存——prefix 部分使用 causal attention（支持 AR 模式的链式因式分解联合分布），diffusion 部分使用 block-causal + bidirectional attention（支持边际分布的并行预测）。训练时序列长度翻倍（原始 + 附加 mask tokens），AR loss 和 diffusion loss 在同一样本上同时计算。

**并行自投机生成**：每一步同时进行两件事——(1) 对上一步的草拟 token 做 AR rejection sampling，(2) 基于所有可能的接受前缀结果，预草拟下一步的候选 token。无论接受多少 token，都能直接选取对应的预草拟方案，消除了草拟-验证的串行开销。

**全 Mask 训练策略**：diffusion 部分在训练时将所有 token 设为 mask（而非传统的随机 mask），带来三重好处：(1) diffusion loss 更密集，(2) 与 AR loss 的平衡更简单（loss 项数一致），(3) 推理时只需 one-step diffusion 草拟，无需多步去噪。

## 四、实现细节

- **模型初始化**：从现有 AR 模型（Qwen2.5 1.5B、Qwen3 4B、Qwen3 8B）做 continual pretraining
- **训练规模**：1.5B 模型用 50B tokens，8B 模型用 150B tokens，在 NVIDIA H100 上训练
- **训练配置**：global batch size 2M tokens（DDP），max sequence length 4096，cosine scheduling（max_lr=1e-5, min_lr=3e-6），BFloat16 精度，Distributed Adam 优化器
- **训练框架**：修改版 Megatron-LM + Torchtitan 支持
- **Block size**：1.5B 模型测试了 4、8、16 三种 block size；8B 模型使用 block size 16
- **损失函数**：$\mathcal{L}_{TiDAR} = \frac{1}{1+\alpha}(\alpha \cdot \mathcal{L}_{AR} + \mathcal{L}_{Diff})$，默认 $\alpha=1$（等权）
- **KV Cache**：支持 exact KV cache，forward 中 causal attention 部分的 KV cache 保留，rejection 失败的 token 对应的 cache 被驱逐
- **Attention Mask 优化**：预初始化固定大小的 block attention mask，每步通过 slice 复用，配合 Flex Attention 无需重新计算
- **Logits 融合**：采样时可混合 AR 和 diffusion 的 logits：$\text{argmax}\{\beta \cdot logits_{AR} + (1-\beta) \cdot logits_{Diff}\}$

## 五、实验结果

**实验平台**：单张 NVIDIA H100 GPU，batch size=1，native PyTorch + Flex Attention

### 生成任务（Coding & Math）

| 模型 | 规模 | HumanEval | MBPP | GSM8K | Avg | T/NFE |
|---|---|---|---|---|---|---|
| Qwen2.5 | 1.5B | 35.98% | 43.60% | 54.74% | 41.64% | 1.00 |
| Block Diff | 1.5B | 39.02% | 34.00% | 52.99% | 38.41% | - |
| TiDAR | 1.5B | 43.29% | 41.40% | 53.90% | 44.03% | 7.45 |
| Qwen3 | 8B | 64.63% | 69.40% | 81.80% | 68.09% | 1.00 |
| Dream | 7B | 54.88% | 56.80% | 77.18% | 58.74% | 1.00 |
| LLaDA | 8B | 32.32% | 40.80% | 70.96% | 41.78% | 1.00 |
| TiDAR (Trust Diff) | 8B | 57.93% | 65.40% | 80.44% | 65.31% | 8.25 |

### 吞吐加速

| 模型 | 相对 AR 吞吐加速 |
|---|---|
| TiDAR 1.5B | 4.71× |
| TiDAR 8B | 5.91× |

- TiDAR 首次在吞吐上超越 speculative decoding（EAGLE-3），且接受率（T/NFE）和转化率（T/NFE → T/s）均更高
- 在 likelihood 任务（MMLU、ARC、HellaSwag 等）上，TiDAR 8B 达到 75.40% 平均准确率，甚至略超 Qwen3 8B 的 74.25%

### 消融实验关键发现

- **全 Mask vs 随机 Mask**：全 Mask 策略在质量和效率上均有显著提升（Avg 从 45.68% → 48.94%，T/NFE 从 5.22 → 5.49）
- **Trust AR vs Trust Diff**：模型训练良好时两者差异很小，说明质量由 AR rejection sampling 保证
- **不同 block size**：block size 增大带来更高 T/NFE（4→8→16 对应 3.47→5.49→6.97），质量基本稳定

## 六、批判性分析

1. **仅评估 batch size=1 场景**：论文所有效率实验都在 batch size=1 下进行。实际生产环境中 serving 通常使用较大 batch size，此时 GPU 已处于 compute-bound 区域，"free token slots" 的前提不再成立。论文在 Limitations 中仅简要提及可以调整 block length，但未提供任何大 batch size 下的实验数据。

2. **训练成本不对称比较**：TiDAR 需要从 AR 模型做 continual pretraining（1.5B 用 50B tokens，8B 用 150B tokens），训练序列长度翻倍。与直接使用 AR 模型 + EAGLE-3（后者几乎零训练成本或仅需少量微调）相比，这一训练开销被低估了。

3. **8B 模型质量仍有差距**：与基座 Qwen3 8B 相比，TiDAR 8B 在 HumanEval（57.93% vs 64.63%）和 MBPP（65.40% vs 69.40%）上有明显差距。论文将此归因于"需要更多训练数据"，但这只是推测，没有提供缩放实验验证。

4. **与 EAGLE-3 的比较不完全公平**：EAGLE-3 使用的是 Qwen3-8B Instruct 模型的第三方权重（因缺少 base 模型权重），而 TiDAR 使用 base 模型。Instruct 模型的输出分布更集中，可能影响 speculative decoding 的接受率。

5. **缺少端到端应用级评估**：所有评估都是短序列的 benchmark（最长 512 tokens 生成），缺少长文本生成、对话、RAG 等实际场景的评估。长序列场景下 KV cache 管理和 rejection 带来的重计算可能显著影响实际加速比。

## 七、AI Infra / MLSys 视角

**对 AI 系统研究的启发**：

1. **"Free token slots" 是重要的系统级洞察**：论文对 H100 上不同 prefix length 和 token slots 的 latency profiling（Figure 1）清晰展示了 memory-bound 区间的计算浪费。这一洞察不仅适用于文本生成，也可迁移到多模态生成、推理中间步骤并行化等场景。

2. **单模型 draft-verify 消除了通信开销**：相比传统 speculative decoding 需要两个模型（或额外的 draft head），TiDAR 在单次 forward 中完成草拟和验证，消除了模型间的数据传输和同步开销，这对 serving 系统的调度设计有重要参考价值。

3. **Attention mask 作为架构控制原语**：TiDAR 通过精心设计的 attention mask 在单个 Transformer 中实现了 causal 和 bidirectional 双模式。这种"通过 mask 编程行为"的思路可以推广到更多混合推理模式的设计。

**值得跟进的方向**：

- **大 batch size 和连续批处理（continuous batching）下的 TiDAR serving**：如何在请求级别动态调整 block size，以及如何与 PagedAttention 等 KV cache 管理方案集成
- **与 MoE 架构的结合**：diffusion 部分和 AR 部分可能激活不同的 expert，探索是否能进一步提升计算效率
- **长上下文场景的 context parallelism**：论文指出训练时序列翻倍是长上下文的瓶颈，设计 TiDAR 专用的 context parallelism 策略是有价值的工程研究方向

---

## 八、总结

TiDAR 提出了一种序列级混合架构，在单次 forward pass 中通过 structured attention mask 同时完成 diffusion 并行草拟和 AR rejection sampling 验证，利用 GPU memory-bound 区间的"free token slots"实现近乎免费的并行计算。在 1.5B 和 8B 规模上分别实现了 4.71× 和 5.91× 的吞吐加速，同时保持与 AR 模型接近的生成质量，首次在实测吞吐上超越 speculative decoding。主要局限在于仅验证了 batch size=1 场景、训练需要额外成本、以及大模型上仍存在一定质量差距。
