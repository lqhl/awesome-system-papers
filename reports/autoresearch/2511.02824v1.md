# Kosmos: An AI Scientist for Autonomous Discovery

**作者**：Ludovico Mitchener*, Angela Yiu*, Benjamin Chang* 等（Edison Scientific, University of Oxford, UCL, Washington University, MIT, Stanford, Future House 等多机构）
**会议**：arXiv 预印本（2025年11月）
**链接**：[arXiv:2511.02824](https://arxiv.org/abs/2511.02824)
**源文件**：[[2511.02824v1.pdf]]

---

## 一、背景

数据驱动的科学发现需要迭代执行文献检索、假设生成和数据分析。大语言模型（LLM）agent 在编程和跨学科推理方面表现出色，使得自动化科学研究成为可能。已有系统如 Robin（Edison Scientific 此前的工作）、Sakana 的 AI Scientist、Google 的 AI co-scientist、Virtual Lab 等，均在特定维度上推动了自动化研究，但都存在明显的局限：要么只能执行有限步骤后就失去一致性（coherence），要么局限于特定领域（如机器学习），要么不执行实际的数据分析。如何让 AI 系统在长时间运行中保持研究方向的连贯性，同时跨领域执行数据分析和文献综述，是一个未解决的核心挑战。

---

## 二、要解决的问题

1. **Agent 上下文丧失**：现有 AI 研究系统在执行少量步骤后就会失去连贯性，无法进行深入、持续的研究探索
2. **Agent 间信息共享不足**：数据分析 agent 和文献检索 agent 之间缺乏有效的信息共享机制，导致发现孤立、无法形成连贯叙事
3. **规模受限**：已有系统的代码生成量和论文阅读量有限（如 Robin 约 4,310 行代码），无法支撑数月级别的研究工作量
4. **可追溯性不足**：AI 系统产出的科学报告中，声明的来源不可追溯，难以进行独立验证

---

## 三、洞察与设计

**关键洞察**：通过引入一个结构化的 world model 来管理大量并行 agent 的输出信息，可以在上百次 agent rollout 之间保持上下文连贯性，使系统能够在单次运行中完成相当于数月的研究工作量。

### 系统架构

Kosmos 由三个核心组件构成：

1. **Data Analysis Agent**：通用数据分析 agent，编写和执行 Jupyter notebook 进行统计分析、可视化和假设检验
2. **Literature Search Agent**：文献检索 agent，阅读和综合完整论文
3. **Structured World Model**：结构化世界模型，作为两个 agent 之间的共享知识库

### 工作流程

每个 discovery cycle 中，Kosmos：
- 最多同时启动 10 个并行的文献检索和数据分析任务
- 任务完成后，将输出摘要更新到 world model
- 查询 world model 以提出下一轮的任务
- 运行可达 20 个 cycle（约 12 小时）
- 最终将发现综合为 3-4 篇科学报告

每条报告中的声明都引用了生成它的代码（Jupyter notebook trajectory）或文献来源，确保完全可追溯。

---

## 四、实现细节

- **LLM 基础**：所有运行使用 Claude Sonnet 4 作为数据分析 agent 的底层模型；部分控制实验使用 Sonnet 4.5
- **Agent 基础设施**：基于 Edison Scientific 的两个通用 agent（data analysis agent 和 literature search agent）
- **运行规模**：平均每次运行执行约 166 个 data analysis agent rollout（生成约 42,000 行代码）和 36 个 literature review agent rollout（阅读约 1,500 篇论文），相比 Robin 代码量提升 9.8 倍
- **World model 管理**：每个 cycle 结束后更新 world model，包含发现的摘要和下一步建议；world model 使 agent 能在 200+ rollout 间保持连贯
- **报告生成**：当 Kosmos 认为研究目标已完成时，自动综合关键发现生成科学报告，每条声明附带代码或文献引用

## 五、实验结果

### 准确性评估

从 3 篇代表性报告中提取 102 条声明，由独立专家科学家评估：

| 声明类型 | 准确率 | 样本量 |
|---------|-------|-------|
| Data Analysis | 85.5% | 55 |
| Literature Review | 82.1% | 28 |
| Interpretation（综合推理） | 57.9% | 19 |
| **总体** | **79.4%** | **102** |

### 研究时间等效评估

| 评估方式 | 等效专家时间 |
|---------|------------|
| 任务量估算（15分钟/论文 + 2小时/notebook） | 4.1 个月（n=6, σ=0.85） |
| 学术团队独立评估（20 cycle 运行） | 6.14 个月（n=7, σ=2.49） |

### 七项科学发现

论文展示了 Kosmos 在 6 个领域的 7 项发现：

| 发现 | 领域 | 类型 | 验证结果 |
|------|------|------|---------|
| 1. 低温神经保护中的核苷酸代谢 | 代谢组学 | 复现未发表发现 | R²=0.998（与原始分析） |
| 2. 钙钛矿太阳能电池中退火湿度的决定性作用 | 材料科学 | 复现预印本发现 | 验证了线性关系 J_sc vs DMF SPP |
| 3. 神经网络连接的对数正态分布 | 连接组学 | 独立推理复现 | μ 值 Pearson r=0.77/0.46 |
| 4. SOD2 驱动人类心肌纤维化 | 统计遗传学 | 新方法支持已有发现 | β 效应量 R²=0.9983（vs 人工） |
| 5. T2D 保护性变体对 SSR1 的顺式调控 | 统计遗传学 | 新方法支持已有发现 | 独立 E2G 和 TWAS 数据验证 |
| 6. AD 中疾病事件的时序排序 | 蛋白质组学 | 独立开发新分析方法 | Davies test p=0.017，bootstrap 验证 |
| 7. 衰老中内嗅皮层易损性机制 | 转录组学 | 人类研究者未发现的新发现 | 独立数据集和 AD 临床数据验证 |

### 可扩展性

学术合作者报告：
- 有价值发现的数量随 Kosmos cycle 数线性增长（测试至 20 cycles）
- 等效专家研究时间从 cycle 5 到 cycle 20 大致翻倍
- Cycle 20 的发现具有中等到高度的推理深度，以及中等到完全的新颖性

## 六、批判性分析

1. **Interpretation 准确率堪忧**：综合推理类声明仅 57.9% 准确，这意味着 Kosmos 在将数据分析结果上升为科学结论时，近一半是错误的。论文将此轻描淡写为"倾向于将统计显著性与科学价值混淆"，但这实际上是一个根本性问题——科学发现的核心价值恰在于解释而非计算

2. **评估样本量过小且存在选择偏差**：102 条声明来自仅 3 篇"代表性"报告，7 项发现均经过精心挑选。论文未报告 Kosmos 总共进行了多少次运行、产出了多少发现、其中多少被丢弃。这种只展示最佳结果的做法使得整体性能评估缺乏可信度

3. **等效时间估算方法存在严重偏差**：将 agent rollout 数量乘以人类完成同等任务的时间来估算"等效专家时间"，忽略了一个根本区别——人类科学家不会盲目执行 166 个分析 trajectory，而是会有针对性地设计实验。42,000 行代码中有多少是冗余或无用的分析？

4. **"新发现"的验证标准不一致**：Discovery 7（内嗅皮层易损性机制）被称为"人类研究者未发现的新发现"，但验证是由提供数据的同一团队（Bourdenx/Foiani 等）进行的，存在确认偏差。且该发现依赖 PS 暴露作为"eat-me"信号的已知机制，Kosmos 的贡献更多是将已知机制应用到特定数据集

5. **Colocalization 分析失败被轻描淡写**：Discovery 4 中 colocalization 分析因技术问题完全失败（p 值存储为 0、列名冲突等），Kosmos 直接跳过该步骤转向 fine-mapping。论文将此描述为"灵活性"，但实际上这意味着系统无法可靠地执行标准生物信息学流程

6. **缺乏成本分析**：运行 12 小时、200+ agent rollout、42,000 行代码、1,500 篇论文——对应的 LLM API 成本完全未提及。对于评估实际应用价值而言，成本效益比至关重要

7. **World model 的具体实现未公开**：作为论文声称的核心创新，structured world model 的具体数据结构、更新策略、信息检索机制等关键实现细节几乎完全缺失

## 七、AI Infra / MLSys 视角

### 可借鉴的设计思路

1. **Structured world model 作为 agent 间通信机制**：这是一种比简单的 context window 共享或 message passing 更有结构的方案。在多 agent 系统中，用一个持续更新的知识库来管理上下文，可以有效解决长程一致性问题。这对 AI Infra 中的多阶段 pipeline 编排（如训练-评估-部署流水线）有直接启发

2. **Agent rollout 的规模化调度**：Kosmos 在单次运行中管理 200+ agent rollout，涉及并行调度、资源分配、错误恢复等系统工程挑战。这与分布式训练中的任务调度问题有相似性

3. **代码生成的可追溯性设计**：每条声明引用对应的 Jupyter notebook trajectory，这种 provenance tracking 机制对 MLOps 中的实验管理和模型谱系追踪有借鉴意义

### 值得跟进的方向

1. **World model 的高效存储和检索**：随着 cycle 数增加，world model 的规模如何管理？是否可以借鉴向量数据库或 KV cache 优化技术来加速检索？
2. **Agent rollout 的智能剪枝**：42,000 行代码中有大量冗余分析。如何在运行时判断哪些 trajectory 值得继续、哪些应及早终止？这类似于推理时的 speculative decoding 或 early exit 策略
3. **Multi-agent 系统的资源效率**：当前系统使用 Claude Sonnet 4 作为底层模型，对于不同复杂度的子任务（数据清洗 vs 假设推理），是否可以用不同规模的模型来优化成本？这与 MoE 或 cascade serving 的思路相通

---

## 八、总结

Kosmos 是一个面向数据驱动科学发现的 AI 系统，通过引入 structured world model 在数据分析 agent 和文献检索 agent 之间共享上下文，实现了在单次运行中协调 200+ agent rollout、生成 42,000 行代码、阅读 1,500 篇论文的能力。论文展示了 7 项跨领域发现，从复现已有工作到提出新的生物学机制。系统的核心价值在于大规模无偏数据探索能力，但在综合推理准确性（57.9%）、world model 实现细节透明度、以及发现筛选效率方面存在明显不足。Kosmos 代表了 AI 自动化研究从"单任务辅助"向"端到端长程研究"的重要一步，但距离真正替代科学家的判断力仍有本质差距。
