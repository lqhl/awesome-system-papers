# The AI Scientist-v2: Workshop-Level Automated Scientific Discovery via Agentic Tree Search

**作者**：Yutaro Yamada*, Robert Tjarko Lange*, Cong Lu*（共同一作），Shengran Hu, Chris Lu, Jakob Foerster, Jeff Clune, David Ha（Sakana AI, University of British Columbia, Vector Institute, FLAIR/University of Oxford, Canada CIFAR AI Chair）
**会议**：arXiv preprint, April 2025
**链接**：[arXiv](https://arxiv.org/abs/2504.08066)
**源文件**：[[2504.08066v1.pdf]]

---

## 一、背景

AI 驱动的自动化科学发现是近年来的热门方向。从早期的 Robot Scientist 到近期的 LLM-based 系统，研究者一直在探索如何让 AI 自主完成从假设生成、实验设计与执行、数据分析到论文撰写的完整科研流程。Sakana AI 此前推出的 The AI Scientist-v1 (Lu et al., 2024) 是首个端到端自动化科学发现系统，但存在两大核心限制：（1）严重依赖人工编写的代码模板，每个新领域都需要人工准备 baseline 代码；（2）实验过程采用线性、浅层的假设检验方式，无法深入探索复杂假设空间。

---

## 二、要解决的问题

1. **模板依赖**：v1 需要人工为每个研究主题编写代码模板作为起点，严重限制了系统的自主性和跨领域泛化能力。
2. **实验探索深度不足**：v1 采用严格线性的实验流程（每次代码修改直接基于前一次实验），导致短视的实验策略，无法像人类科学家那样进行开放式假设生成和迭代式假设精炼。
3. **可视化质量缺乏反馈**：v1 没有利用 Vision-Language Model 对生成的图表进行质量把控，导致论文中的图表可能存在标签缺失、图例不清等问题。

---

## 三、洞察与设计

**关键洞察**：科学实验天然具有多阶段、渐进式的结构（从初步可行性验证到超参调优、核心实验、消融实验），这种结构化过程可以用树搜索来建模——每个实验节点要么被 debug（修复错误），要么被 refine（改进性能），从而在代码空间中进行系统性探索，而非线性推进。

基于这一洞察，AI Scientist-v2 设计了以下核心组件：

### Experiment Progress Manager（实验进度管理器）

将科研实验划分为四个阶段：
- **Stage 1 - Preliminary Investigation**：建立最小可工作原型，验证初步可行性
- **Stage 2 - Hyperparameter Tuning**：优化关键超参数，建立稳健的实验 baseline
- **Stage 3 - Research Agenda Execution**：系统性执行核心研究计划
- **Stage 4 - Ablation Studies**：消融实验，评估各组件的重要性

每个阶段结束时，LLM evaluator 选出最佳节点作为下一阶段的起点。

### Parallelized Agentic Tree Search（并行化代理树搜索）

每个实验节点包含：实验脚本、高层计划描述、执行错误信息（如有）、性能指标、LLM 反馈、可视化脚本、VLM 对图表的反馈、节点状态（buggy/non-buggy）。

搜索过程中：
- 以预定概率选择 buggy 节点进行 debug，或选择 non-buggy 节点进行 refine
- Non-buggy 节点使用 best-first search，由 LLM 根据性能指标和图表质量评估
- 多节点并行扩展，大幅加速探索

引入专用节点类型：Hyperparameter nodes、Ablation nodes、Replication nodes（不同随机种子重复实验）、Aggregation nodes（汇总结果生成统计图表）。

### 更通用的 Idea Generation

不再基于现有代码库提出增量修改，而是从更高抽象层次进行开放式思考，集成 Semantic Scholar 文献检索工具在 idea 生成阶段评估新颖性。

### VLM Reviewer

在实验阶段和论文撰写阶段双重集成 VLM：
- 实验阶段：对生成的图表提供即时反馈，标记问题节点
- 论文阶段：检查图表与 caption 的一致性、视觉清晰度、重复图表等

---

## 四、实现细节

- **模型配置**：代码生成使用 Claude 3.5 Sonnet (v2)（max tokens 8192, temperature 0.5）；LLM/VLM 反馈使用 GPT-4o；论文撰写使用 o1 进行 reflection
- **树搜索超参数**：Debug 概率 1.0，最大 debug 深度 3，单节点最长运行时间 1 小时；四阶段节点分配分别为 21/12/12/12
- **数据集加载**：统一通过 Hugging Face Hub 的 `datasets.load_dataset` 加载
- **论文撰写**：从 v1 的 Aider-based 迭代写作改为单次生成 + reasoning model（o1）反射的两阶段方式
- **端到端耗时**：单篇论文生成通常需要数小时到最长 15 小时（设定的 runtime 上限）
- **代码已开源**：https://github.com/SakanaAI/AI-Scientist-v2

## 五、实验结果

### 评估方法

将 3 篇完全由 AI Scientist-v2 自主生成的论文提交到 ICLR 2025 的 "I Can't Believe It's Not Better" (ICBINB) workshop（共 43 篇投稿）。审稿人事先被告知可能存在 AI 生成的投稿，但不知道具体是哪些。

### 审稿结果

| 论文 | 主题 | 审稿分数 | 结果 |
|------|------|----------|------|
| Compositional Regularization | 组合正则化对 LSTM 泛化的影响（负面结果） | 6, 7, 6（均分 6.33） | 达到接收阈值（top 45%） |
| Label Noise on Model Calibration | 标签噪声对深度学习模型校准的影响 | 未达标 | 未接收 |
| Pest Detection using Deep Learning | 深度学习害虫检测的现实挑战 | 未达标 | 未接收 |

### 关键发现

- 被接收论文的均分 6.33 超过了 workshop 人类投稿的平均接收阈值，这是首次完全 AI 生成的论文通过同行评审
- 审稿人评价该论文在报告负面结果方面做得好，但指出缺乏直觉解释、仅测试 LSTM 架构、实验范围局限于合成数据
- 作者团队内部评估发现额外问题：数据集训练集和测试集约 57% 重叠、术语混淆（embedding states vs hidden states）、部分图表 caption 不准确

### v1 vs v2 对比

| 特性 | AI Scientist-v1 | AI Scientist-v2 |
|------|-----------------|-----------------|
| 代码基础 | 需要特定主题模板 | 通用，无需模板 |
| 实验方式 | 线性执行 | 树搜索 |
| 并行实验 | 不支持 | 支持 |
| VLM Reviewer | 无 | 有 |
| 评估方式 | 未提交评审 | Workshop 级别接收 |

## 六、批判性分析

1. **评估规模与说服力不足**：仅提交 3 篇论文到一个 workshop（接收率 60-80%），其中 1 篇达到阈值。这个样本量远不足以证明系统的"能力"——在高接收率的 workshop 中，随机质量的工作也有相当概率被接收。作者自己也承认三篇均未达到 main conference 水平。

2. **人工干预被淡化**：虽然声称"fully autonomous"，但流程中存在多处人工介入：（a）从 ~40 个 AI 生成 idea 中人工选择 3 个；（b）每个 idea 用不同随机种子运行多次，人工选择最佳 manuscript；（c）第二批 idea 的 prompt 被人工修改为聚焦特定应用领域。这些选择步骤对最终结果有显著影响，将其描述为"meta-selection"而非"human intervention"有掩饰之嫌。

3. **被接收论文本身质量堪忧**：作者自己的 code review 发现训练集与测试集 57% 重叠——这是一个可能使所有实验结论无效的致命问题。此外还有 caption 错误、术语混淆等问题。一篇存在数据泄露的论文通过了 peer review，这更说明 workshop review 的门槛问题，而非 AI 系统的能力。

4. **缺乏系统性 ablation**：对 AI Scientist-v2 自身各组件（树搜索 vs 线性、VLM feedback、Experiment Progress Manager）没有进行消融实验。无法判断哪些改进真正有效、各贡献多大。

5. **成本与效率分析缺失**：每篇论文需要数小时到 15 小时的 API 调用（Claude 3.5 Sonnet + GPT-4o + o1），但论文未报告 API 成本。考虑到三篇中仅一篇勉强达到 workshop 水平，cost-effectiveness 存疑。

6. **实验领域局限**：所有实验均限于 ML 领域（合成数据集上的简单模型），且依赖 Hugging Face 数据集。对于需要专业设备、大规模计算或非 ML 领域的科研，系统的适用性未被验证。

7. **伦理叙事过于乐观**：论文在 conclusion 中预言"AI will likely generate papers that match or exceed human quality"，但从当前仅 workshop-level 且存在数据泄露问题的结果来看，这一预测缺乏足够支撑。同时，对 AI 生成论文可能造成的审稿负担增加、学术诚信风险等讨论流于表面。

## 七、AI Infra / MLSys 视角

1. **Agentic Tree Search 的基础设施挑战**：AI Scientist-v2 的并行树搜索需要同时管理多个 LLM agent、Python 执行环境和 GPU 资源。这对 agent 调度、资源隔离、状态管理提出了实际的系统挑战——如何高效地在多节点间分配计算资源、管理实验状态的 checkpoint 与回滚，是一个值得研究的 MLSys 问题。

2. **Multi-Agent 协调模式的参考价值**：Experiment Progress Manager 管理四阶段流程、LLM evaluator 选择最佳节点、VLM reviewer 提供视觉反馈——这种多 agent 协调模式（manager + worker + evaluator + critic）可以迁移到其他 AI 基础设施场景，如自动化 ML pipeline 调优、AutoML 系统。

3. **长时间运行 Agent 的可靠性**：单次 paper 生成需要数小时到 15 小时，涉及大量 API 调用和代码执行。如何保证长时间运行的 agent workflow 的容错性（API 超时、代码执行崩溃、上下文窗口溢出）是实际部署中的关键问题。

4. **可跟进方向**：
   - **自动化实验管理系统**：将 Experiment Progress Manager 的阶段化管理 + 树搜索思路应用到通用 ML 实验管理（如 MLflow + LLM agent），实现更智能的超参搜索和实验规划
   - **Agent Sandbox 基础设施**：为代码生成 agent 构建安全、隔离、可复现的执行环境，支持 checkpoint/rollback，这是 AI Scientist 类系统大规模部署的前提

---

## 八、总结

AI Scientist-v2 是 Sakana AI 对全自动科学发现系统的重要迭代，通过引入 Experiment Progress Manager + 并行化代理树搜索消除了对人工代码模板的依赖，并通过 VLM 反馈提升图表和论文质量。其核心里程碑是首次让 AI 完全自主生成的论文通过了 ICLR workshop 的同行评审（均分 6.33/10）。然而，这一成就需要在正确语境下理解：workshop 接收率本身较高（60-80%），被接收论文存在数据泄露等严重问题，且流程中仍有显著的人工选择步骤。系统目前仅在 ML 领域的简单任务上验证，距离"自主产生 conference-level 高质量研究"仍有相当距离。尽管如此，其树搜索驱动的实验探索框架和多 agent 协调架构为未来 AI-assisted research 系统提供了有价值的设计参考。
