# SAND: A New Programming Abstraction for Video-based Deep Learning

## 论文基本信息

- **标题**: SAND: A New Programming Abstraction for Video-based Deep Learning
- **作者**: Juncheol Ye, Seungkook Lee, Hwijoon Lim, Jihyuk Lee, Uitaek Hong, Youngjin Kwon, and Dongsu Han
- **会议**: SOSP 2025
- **Session**: ML and FPGA
- **PDF**: 3731569.3764847.pdf

## 研究背景

视频理解（Video-based Deep Learning）是计算机视觉领域的重要研究方向，广泛应用于视频监控、自动驾驶、体育分析、内容推荐等场景。现代视频理解系统通常由多个神经网络组件构成：视频帧的预处理（解码、resize、归一化）、特征提取（2D/3D CNN 或 Vision Transformer）、时序建模（3D 卷积、Transformer 或 RNN）、以及下游任务头（分类、检测、跟踪等）。

然而，当前的视频理解系统在系统设计上存在三个深层问题：

**预处理瓶颈**。视频解码和预处理占端到端推理延迟的 60-95%，远超神经网络推理本身的时间。这一问题在 CPU-GPU 异构环境中尤为突出，因为视频解码是 CPU 密集型操作，而神经网络推理需要 GPU 资源，两者往往相互竞争。

**视频冗余问题**。视频数据在时间和空间维度上存在大量冗余：连续帧之间的像素变化很小，场景中的背景区域变化更小。但现有系统通常将每一帧都作为独立输入处理，没有利用这些冗余信息来减少计算。

**缺乏统一抽象**。现有的视频理解系统通常将预处理和神经网络作为两个独立系统分别管理，由用户手动调度它们之间的数据流和资源分配。这导致系统难以在全局层面进行优化，也无法灵活适应不同的硬件配置。

## 要解决的问题

如何设计一个统一的编程抽象，使开发者能够高效地表达视频理解流水线，同时让系统在运行时自动处理预处理-推理协同优化、跨帧冗余利用和异构硬件调度？

SAND 的核心贡献是提出 **SAND abstraction**（Streaming And Data-dependent Abstraction），它将视频理解流水线表达为两个层次：**strips**（空间上的分片）和 **inter-strip 依赖图**（分片之间的数据依赖关系），从而将预处理、神经网络推理和跨帧优化统一在一个框架下。

## 核心贡献

1. **SAND 抽象**：一种新的视频理解编程抽象，将流水线表示为 strip（空间分片）+ inter-strip 依赖图，同时覆盖预处理和神经网络推理两个阶段。

2. **Inter-strip 并行化**：利用 strip-level 依赖图，在多个 strips 之间自动发现和利用并行性，使预处理和推理能够在 strip 粒度上重叠执行。

3. **Strip 缓存机制**：通过缓存和复用跨帧不变的 strip 计算结果（如背景区域的特征），显著减少冗余计算。

4. **异构硬件感知的 Cost Model**：构建了一个考虑 CPU/GPU 特性、内存带宽和数据传输开销的 cost model，用于指导 strip 划分和调度决策。

5. **端到端系统实现**：在 PyTorch + FFmpeg 基础上实现了 SAND runtime，并提供了 Python API，显著降低了开发者的使用门槛。

## 主要研究方法

**Strip 抽象**。SAND 将输入视频帧在空间维度上划分为多个 strips（水平或垂直分片）。每个 strip 是独立的处理单元，可以并行地在 CPU（预处理）和 GPU（推理）上执行。

```
Frame N
+----------+----------+----------+
| Strip 0  | Strip 1  | Strip 2  |   ← GPU inference strips
+----------+----------+----------+
| Preproc  | Preproc  | Preproc |   ← CPU preprocessing strips
+----------+----------+----------+
```

**Inter-strip 依赖图（Inter-strip Dependency Graph,ISD）**。当一个 strip 的处理需要其他 strip 的输出作为输入时（例如光流计算、跨区域注意力），ISD 图记录了这些跨 strip 依赖关系。SAND 调度器根据 ISD 图确定哪些 strips 可以并行执行、哪些必须串行等待。

**Strip Caching**。SAND 的缓存机制基于一个关键观察：视频中的背景区域（通常是帧的大面积区域）在连续帧之间变化极小。因此，当一个 strip 的输入与上一帧的对应 strip 高度相似（通过特征相似度度量）时，可以直接复用上一帧的预处理结果或神经网络输出，而无需重新计算。

**Heterogeneity-aware Cost Model**。SAND 的 cost model 将执行时间建模为：
```
T_total = max(T_cpu, T_gpu) + T_transfer
```
其中 T_cpu 是 CPU 预处理时间，T_gpu 是 GPU 推理时间，T_transfer 是 CPU-GPU 数据传输时间。模型通过离线 profiling 和在线自适应调整来选择最优的 strip 数量和划分策略。

## 设计与实现

SAND 的系统架构包含三层：

```
[User Code: Video Understanding Pipeline]
                  ↓
+------------------------------------------+
|          SAND API Layer                  |  (Python, declares strips + ISD)
+------------------------------------------+
                  ↓
+------------------------------------------+
|      SAND Runtime (Scheduler)            |  (strip scheduling, caching)
+------------------------------------------+
         ↓                        ↓
+------------------+       +------------------+
|  CPU Workers     |       |  GPU Workers     |
|  (FFmpeg/NumPy)  |       |  (PyTorch NN)    |
+------------------+       +------------------+
```

**API 层**。开发者使用 SAND API 声明 pipeline：将视频帧划分为 strips，指定每个 strip 的预处理函数和神经网络模型，以及 strip 之间的依赖关系（ISD）。

**Runtime 层**。SAND runtime 负责：
- **调度**：根据 ISD 图和 cost model，将 strips 分配给 CPU/GPU workers，并行启动
- **缓存管理**：维护 strip 缓存池，决定何时复用缓存、何时重新计算
- **资源协调**：管理 CPU-GPU 间的数据传输流水线，最小化空闲等待

**Worker 层**。CPU worker 运行基于 FFmpeg 的视频解码和 NumPy 的预处理；GPU worker 运行 PyTorch 神经网络模型。

SAND 采用了 **strip-pipelining** 策略：当 GPU 在处理第 N 帧的 strip 0 时，CPU 已经在并行处理第 N+1 帧的 strip 0（或第 N 帧的 strip 1）。这种流水线重叠显著降低了端到端延迟。

## 主要实验结果

SAND 在 4 种视频理解任务上进行了评估：

| 任务 | 模型 | 数据集 | 加速比（vs baseline） |
|------|------|--------|-------------------|
| 动作识别 | SlowFast + SlowOnly | Something-Something V2 | 8.7x |
| 视频分类 | TimeSformer | Kinetics-400 | 6.3x |
| 视频目标检测 | VideoSwin + SORT | YouTube-VIS | 5.1x |
| 视频字幕 | VideoClip + GPT | MSR-VTT | 4.2x |

**Baseline** 定义为使用独立预处理（串行 CPU decode + GPU inference，无 strip 划分）的方法。

**关键数据**：
- **Per-frame latency**：SAND 将单帧平均延迟降低 6-11x（具体取决于视频分辨率和模型）
- **预处理占比**：从 60-95% 降至 15-35%
- **Strip caching 命中率**：对中等运动场景视频达到 78%，高运动场景达到 45%
- **能效**：GPU 利用率从 baseline 的 40-60% 提升至 80-90%

## 潜在问题 / 局限性

1. **Caching 策略的鲁棒性依赖场景特性**。Strip caching 效果高度依赖于视频内容——高运动场景（camera motion, fast action）的缓存命中率显著下降（论文报告 45% vs 78%）。对于以动作为核心的视频理解任务（如体育赛事分析），SAND 的缓存收益可能大打折扣。论文未提供针对不同运动强度视频的细粒度分析。

2. **ISD 图需要手动标注**。Inter-strip 依赖图需要开发者显式声明 strip 之间的依赖关系，这实际上增加了编程负担。虽然论文声称 ISD 的声明比完整的流水线代码更简单，但这仍然是一个需要用户介入的额外步骤，与"统一抽象"的初衷存在张力。

3. **跨 strip 边界的神经网络处理**。当神经网络操作（如卷积、attention）作用于 strip 边界时，strip 划分可能导致边界效应（boundary effects）——即被截断的特征导致模型精度下降。论文提到通过 overlapping strips 来缓解，但未给出具体的精度损失数据。

4. **与现有框架的集成成本**。SAND 建立在 PyTorch + FFmpeg 之上，需要用户将现有流水线重写为 SAND API。这个迁移成本对于大型代码库可能是显著的。论文未讨论与 DeepStream、TVM 等现有视频推理框架的集成可能性。

5. **实验设置的透明度**。论文中关于实验硬件配置（CPU/GPU 型号、内存带宽）的描述不够详细，限制了结果的可重复性和跨平台泛化性评估。

## 未来工作

1. **自适应 strip 划分**：当前 strip 数量由 cost model 预先决定，未来可以引入运行时自适应调整——根据当前帧的内容复杂度动态选择 strip 粒度。

2. **扩展到多 GPU 场景**：当前 SAND 仅考虑单 GPU，未来可扩展到多 GPU 节点，支持跨 GPU 的 strip 分配和通信优化。

3. **结合视频压缩知识**：利用 H.264/H.265 编码中的运动向量（motion vectors）和 GOP（Group of Pictures）结构来指导 strip 缓存决策，可能比基于特征相似度的缓存更高效。

4. **端到端可微分优化**：将 strip 划分和缓存策略纳入端到端优化框架，由神经网络自动学习最优的 strip 配置。

## 个人评注

SAND 的核心贡献是对视频理解系统中的"预处理瓶颈"问题提出了一个系统级的解决方案。Strip 抽象将一个复杂问题分解为可并行处理的空间单元，同时通过缓存机制利用了视频数据固有的冗余性。这个思路在概念上不复杂，但在系统实现上需要精细的工程工作——特别是 strip 调度和 CPU-GPU 流水线协同。

从技术深度看，论文的主要创新在于 ISD 图的依赖建模和 strip-level 缓存策略。不过，这些技术在本质上与流处理系统中的 task scheduling 和 state management 有相通之处。SAND 更像是在视频理解场景中应用了已有的流处理优化思想，而非提出了全新的系统原语。

总体而言，SAND 对于视频理解系统的性能优化有实质性的参考价值，但其设计决策主要针对"视频帧之间的冗余"这一特定领域知识，通用性有待进一步验证。
