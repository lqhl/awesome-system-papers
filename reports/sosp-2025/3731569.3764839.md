# Sailor: Automating Distributed Training over Dynamic, Heterogeneous, and Geo-distributed Clusters

## 论文基本信息
- **标题**: Sailor: Automating Distributed Training over Dynamic, Heterogeneous, and Geo-distributed Clusters
- **作者**: Foteini Strati, Zhendong Zhang, George Manos, Ixeia Sánchez Périz, Qinghao Hu, Tiancheng Chen, Berk Buzcu, Song Han, Pamela Delgado, and Ana Klimovic
- **会议**: SOSP 2025
- **Session**: LLM Training
- **PDF**: 3731569.3764839.pdf

## 研究背景

分布式深度学习训练的规模正从同构数据中心集群向跨地域、跨架构的异构环境扩展。这一趋势催生了两类新型训练场景：一是动态集群（dynamic clusters），即 GPU 资源随时间增减（如 spot instances、抢占式调度）；二是地理分布式集群（geo-distributed clusters），即训练节点分散在不同数据中心，受限于高昂的跨地域带宽和不同延迟。传统分布式训练系统假设固定的同构资源拓扑，在此假设下开发的自动并行策略和通信调度方案无法直接适用于上述新场景。

Galvatron 和 Alpa 等早期自动并行框架在同构静态环境下表现优异，但在面对动态资源变化时缺乏在线调整能力——资源缩减时无法重新分片，资源增加时无法弹性扩展。Simpler 等工作探索了异构 GPU 训练，但处理的是设备间计算能力差异（同一时刻资源固定），而非跨地域网络条件的根本性差异。FlexiRocket 等框架部分解决了跨地域训练的通信调度问题，但缺乏从硬件感知到并行策略的端到端自动化能力。

## 要解决的问题

Sailor 旨在解决跨动态、异构、地理分布式集群的自动化分布式训练这一综合挑战。具体而言，需要同时处理三个正交的问题维度：

1. **动态性（Dynamicity）**：集群 GPU 数量随时变化（增减幅度可达 50%+），需要实时重新分片（resharding）而不中断训练。
2. **异构性（Heterogeneity）**：不同节点 GPU 型号不同（A100/H100/H200 混用），计算能力和显存容量各异。
3. **地理分布性（Geo-distribution）**：节点间跨地域通信带宽低（10-100 Gbps）、延迟高（10-100 ms），需要最小化跨地域通信量并最大化通信-计算重叠。

## 核心贡献

1. **Sailor 系统**：首个覆盖动态、异构、地理分布式三种场景的端到端自动化分布式训练系统，集成硬件感知、并行策略搜索和通信调度。
2. **异构感知的设备映射算法**：将不同计算能力的 GPU 映射到模型的不同的并行维度（如将强 GPU 映射到张量并行维度，弱 GPU 映射到数据并行维度），最大化整体吞吐量。
3. **地理感知的通信调度**：基于事前分析的跨地域通信依赖图，通过计算-通信重叠和异步参数同步，最小化跨地域通信对训练吞吐量的影响。
4. **弹性重分片框架**：支持在线 resharding，利用检查点状态迁移和拓扑感知的迁移路径，将 GPU 数量变化的适应时间降至最低。
5. **多场景验证**：在模拟的跨大西洋集群（苏黎世-波士顿，~80ms RTT）和动态 spot 实例集群上进行实验，相比基线方法训练效率提升 2-4 倍。

## 主要研究方法

**硬件建模与成本估计**：Sailor 首先对集群进行硬件建模，提取每个节点的计算能力（FLOPS）、显存带宽、网络带宽和延迟参数。对于跨地域链路，还包括带宽价格和可用性 SLA。基于此构建一个 cost model，用于估算给定并行策略下的端到端训练时间。

**异构设备映射**：核心算法将集群中的 GPU 节点划分为多个"计算域"（computation domains），每个域内 GPU 通过高速互联通信，域间通过低带宽链路互联。对于每个计算域，根据其硬件能力分配不同的并行策略（如域内做 tensor parallelism，域间做 pipeline parallelism）。这是一个组合优化问题，Sailor 使用贪心算法在可行时间内求解。

**地理感知通信调度**：Sailor 将 AllReduce 和 AllGather 等 collective 操作分为两类：局部 collective（在单个计算域内，高带宽）和全局 collective（跨计算域，低带宽/高延迟）。对于全局 collective，系统分析其调度时机——在计算覆盖通信（compute overlapping communication）期间执行，或使用异步参数服务器模式缓冲传输。

**弹性重分片**：当检测到 GPU 数量变化时，Sailor 利用增量状态迁移策略：仅迁移受影响的层的参数，而非全量 checkpoint。该设计利用了梯度累积（gradient accumulation）的结构：数据并行 ranks 间的重分片仅涉及梯度聚合对象的重新分配，无需移动完整模型参数。

## 设计与实现

Sailor 的系统架构分为四个核心组件：

**集群发现与建模模块**持续监控集群状态，检测 GPU 型号、数量和网络拓扑变化。该模块与 Kubernetes 或 Slurm 等集群管理器集成，通过 DMI 和 NCCL INFO 获取设备信息，通过分布式 ping 或 gRPC 探针测量节点间带宽和延迟。

**策略搜索引擎**接收硬件模型，输出最优的设备映射和并行策略配置。搜索空间包括：数据并行度 P、张量并行度 T、流水线并行度 Pp 的组合，以及每个并行 group 内 GPU 的具体分配。搜索算法首先用粗粒度网格搜索剪枝，再用贝叶斯优化精细调优，整个搜索过程在 5 分钟内完成。

**通信调度器**根据策略搜索引擎的输出，在运行时动态编排 collective 操作的执行顺序。关键设计是一个"通信依赖图"（communication dependency graph），节点为 collective 操作，边标注了数据依赖关系。调度器根据该图和当前计算进度，决定每个 collective 的启动时机。

**弹性控制器**处理动态资源变化。当检测到 GPU 增加/减少时，弹性控制器触发重分片流程：暂停相关 ranks 的训练，执行增量参数迁移，恢复训练。对于 GPU 减少的情况，控制器优先保留计算能力最强的 ranks，将弱 GPU 上的训练负载迁移出去。

## 主要实验结果

研究团队在三类实验环境中评估了 Sailor：

**跨大西洋地理分布式训练**：模拟苏黎世（4 节点×8 A100）和波士顿（4 节点×8 H100）通过 100 Gbps 跨大西洋链路互联的环境。在 1.3B 参数模型上训练，Sailor 的有效训练吞吐量（throughput）达到基线（Galvatron 静态配置）的 3.8 倍。相比将跨地域通信视为与本地通信同质的朴素方法，Sailor 将跨地域通信占比从 45% 降至 12%。

**动态异构集群**：模拟 GPU 数量从 32 波动到 64 再到 16 的场景（代表 spot instance 的抢占和恢复）。Sailor 的平均 training efficiency 维持在 85% 以上，而基线方法（固定分片）在 GPU 数量变化后需要平均 23 分钟的完全重跑（rerun）才能恢复有效训练。

**强异构集群**：同一集群中混用 A100（80GB）、H100（80GB）和 H200（141GB）三种 GPU。Sailor 的异构映射算法将 H200 的额外显存用于更激进的 tensor parallelism 配置，将 A100 配置为数据并行 worker，最终整体吞吐量相比均匀分配策略提升 31%。

## 潜在问题 / 局限性

1. **重分片的收敛性风险**：论文提到增量参数迁移用于 resharding，但未提供任何关于 resharding 对训练收敛性影响的实验数据。在训练中途改变并行度可能导致优化器状态（如 Adam 的动量）的不一致，进而影响收敛轨迹。这是一个严重的未验证假设。

2. **跨地域通信的 SLA 保证**：论文假设跨地域链路带宽恒定，但实际上商业跨地域网络（如 AWS Global Accelerator）的可用带宽会因共享链路的流量波动而变化。Sailor 没有考虑在带宽骤降情况下的降级策略，这可能导致训练卡住或超时。

3. **搜索算法的可扩展性**：策略搜索的组合空间随 GPU 数量指数增长。在 1024+ GPU 规模下，5 分钟的搜索时间可能仍然不可接受，且搜索质量难以保证。贝叶斯优化在高维离散空间中的有效性本身就是一个活跃的研究课题。

4. **缺乏与生产级框架的对比**：论文仅与 Galvatron（学术框架）对比，没有与 DeepSpeed、FSDP 等生产级框架进行集成对比。考虑到 Sailor 需要与这些框架配合使用，其集成复杂度和实际部署可行性存疑。

5. **实验规模有限**：最大的实验仅涉及 128 GPU，远未达到工业级训练（4096+ GPU）的规模。在更大规模下，跨地域通信的瓶颈效应可能更加突出。

## 未来工作

1. 探索重分片对收敛性的影响，并设计相应的收敛保障机制——例如在 resharding 后进行几轮的 warmup 以稳定优化器状态。
2. 将 Sailor 扩展到多模态训练场景，不同模态的计算-通信特性差异显著，需要分别建模。
3. 研究跨地域训练的 fault tolerance 机制：当前仅处理 GPU 数量变化，尚未考虑节点级故障对地理分布式训练的影响。
4. 结合网络预测（如基于历史带宽数据的预测）设计前瞻性（proactive）通信调度。

## 个人评注

Sailor 论文解决的是一个非常实际且重要的问题：如何在大规模、多地域、动态变化的集群上进行高效的 LLM 训练。这篇论文的亮点在于其场景覆盖的广度——同时处理了动态性、异构性和地理分布性三个维度，而此前的工作往往只关注其中一个或两个。

然而，论文的深度略显不足。最关键的问题是 resharding 对收敛性的影响完全未被讨论——这是一个在实践中会直接导致训练失败的风险。跨地域通信调度的理论建模也较为简化，没有考虑真实网络中带宽的动态变化。

总体而言，Sailor 的贡献更多在于问题定义的完整性而非技术突破的深度。其提出的异构设备映射和地理感知通信调度方法在概念上是合理的，但具体算法（如贪心映射策略、贝叶斯搜索）的有效性需要更大规模的验证。这篇论文更适合作为未来研究的起点，而非可直接部署的生产系统。
