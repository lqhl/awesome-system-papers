# IC-Cache: Efficient Large Language Model Serving via In-context Caching

**作者**：Yifan Yu (UIUC), Yu Gan (Google), Nikhil Sarda (Google), Lillian Tsai (Google), Jiaming Shen (Google), Yanqi Zhou (Google), Arvind Krishnamurthy (Google & UW), Fan Lai (UIUC), Henry M. Levy (Google & UW), David E. Culler (Google)

## 一、背景

LLM 在 chatbot、代码生成、数学推理等应用中取得巨大成功，日处理百万级用户请求。然而，服务大规模 LLM 面临严峻的质量-延迟-成本三角矛盾：更大的模型（如 DeepSeek-R1 的 671B 参数）带来更好的质量，但推理成本和延迟也成倍增长（如 ChatGPT-4o 与 3.5 之间 10× 的 token 价格差异）。同时，真实场景中请求负载呈突发性波动，峰值负载可达低谷的 25 倍，这使得 SLO 保证和资源规划极为困难。

现有优化工作主要集中在提升单请求的系统吞吐（并行化、GPU 利用率、内存效率）和降低延迟（请求调度），但忽略了一个互补的机会：利用请求之间的语义相似性。

---

## 二、要解决的问题

1. **语义缓存质量差**：分析显示超过 70% 的 LLM 请求与历史请求存在高语义相似性（cosine > 0.8），但直接复用相似请求的响应（semantic caching）会导致 win rate 从 50% 暴跌至 18%，因为微小的上下文差异即可产生离题回复。

2. **大小模型之间的质量鸿沟**：小模型（如 Qwen-7B）成本低、延迟低，但质量明显逊于大模型（如 DeepSeek-R1）。简单地将请求路由到小模型会损害用户体验。

3. **动态负载下的路由困难**：请求分布、模型性能和负载模式持续变化，静态的分类器式路由无法适应这些动态性。

---

## 三、洞察与设计

**关键洞察**：历史请求-响应对不应被当作可直接复用的缓存条目，而应被当作 in-context examples 注入到新请求的 prompt 中，利用 in-context learning 能力让小模型模仿大模型的推理轨迹和回答模式，从而实现小模型的"实时能力增强"（live capability augmentation）——小模型不仅能模仿大模型的回答结构，还能复现其组合推理能力。

基于这一洞察，IC-Cache 的核心架构包含三个组件：

1. **Example Selector（两阶段选择）**：第一阶段用 embedding 相似性从缓存中快速筛选候选（利用 K-Means 聚类加速，K = √N），第二阶段用轻量级 proxy model（如 TinyBERT，仅 < 0.2% 的目标模型大小）估计每个 example 对最终响应的端到端 helpfulness。此外引入动态 utility threshold 控制 example 数量，避免过多 example 导致的上下文膨胀。

2. **Request Router（MAB-based 路由）**：将路由建模为 contextual multi-armed bandit 问题，输入为请求内容+选出的 examples，每个 arm 对应一个候选模型。路由器通过 EMA 跟踪系统负载，在负载过高时用 tanh 函数计算 corrective bias 偏向小模型，实现质量-效率的自适应平衡。通过选择性地仅在路由器不确定时收集反馈，降低数据采集成本。

3. **Example Manager（缓存管理）**：采用 cost-aware replay 机制，离线重放请求以获取更高质量的响应替换原有 example；使用带衰减因子的 moving average 跟踪 example utility，淘汰过时或低质量条目。

---

## 四、实现细节

- **集成方式**：IC-Cache 作为现有 serving 框架（HuggingFace Runtime、vLLM、LangChain）的补充层，仅需几行代码改动即可接入。
- **Proxy Model**：第二阶段使用 TinyBERT，参数量不到目标 LLM 的 0.2%，异步更新，利用在线收集的用户反馈（thumbs-up/down、偏好对比）训练。
- **聚类索引**：离线对 example pool 做 K-Means 聚类，在线查询时先找最近 centroid 再在簇内搜索，总比较次数最优为 2√N。
- **负载感知**：EMA 跟踪 serving load，超过阈值时 tanh bias 推动路由偏向小模型；bias 持续过大可作为 auto-scaling 信号。
- **隐私支持**：支持 DP（差分隐私）合成 example pool，质量仅轻微下降但仍优于无 IC-Cache 的基线。
- **实验集群**：16 × NVIDIA A100 GPU，请求到达模式采用 Microsoft 真实 LLM serving trace。

## 五、实验结果

**模型配置**：
- 闭源：Gemini-1.5-Pro vs. Gemini-1.5-Flash
- 开源：DeepSeek-R1 vs. Qwen2.5-7B；Gemma-2-27B vs. Gemma-2-2B

**Baselines**：w/o IC-Cache（vanilla vLLM）、RouteLLM、LongRAG、Semantic Caching

| 指标 | IC-Cache 表现 |
|------|--------------|
| 吞吐提升 | 1.4–5.9× |
| 延迟降低 | TTFT 降低 28–71%（P50 降低 75–83% vs 大模型） |
| 响应质量 | 与大模型持平或超越（部分数据集上 2B 模型 win rate > 50% 击败 27B） |
| vs RouteLLM | 相同吞吐下 win rate 高 4–16%；相同质量下吞吐高 2.3× |
| vs Semantic Caching | 质量提升最高 28%，或等质量下效率提升 4.1× |
| vs SFT | IC-Cache 在 in-domain 和 out-of-domain 任务上均优于 SFT |
| vs RAG | IC-Cache 单独优于 RAG；IC-Cache + RAG 组合效果最佳（win rate 62.4%） |
| Example Cache 开销 | 近饱和性能仅需 ~2K–12K examples（< 20MB 明文） |
| 选择器开销 | 两阶段选择引入 < 1% 额外开销 |

## 六、批判性分析

1. **评测偏向 LLM-as-a-judge**：所有质量评估均使用 LLM 自动打分（DeepSeek-R1 评 Gemini、Gemini-Pro 评其他），尽管论文声称与人类偏好强相关，但 autorater 本身的 bias 和不稳定性未被充分讨论。七分制打分下 [-0.3, 0.3] 视为 tie 的阈值选择也缺乏严格论证。

2. **Example 来自大模型的前提假设**：IC-Cache 的核心逻辑依赖于用大模型的历史响应来增强小模型。这假设系统已经部署了大模型并积累了足够的历史数据。在冷启动或纯小模型部署场景下，IC-Cache 的价值大打折扣，但论文对此讨论不足。

3. **实验设置的代表性**：实验使用的数据集（MS MARCO、Natural Questions、Alpaca 等）以事实性问答和简单对话为主，对于复杂的多轮对话、长文档处理、tool use 等真实 LLM 应用场景的适用性未经验证。

4. **Proxy Model 的泛化性**：TinyBERT 作为 utility 估计器，其训练依赖在线反馈数据。论文未深入讨论在请求分布剧烈变化时 proxy model 的适应速度，以及新领域请求涌入时的性能退化问题。

5. **In-context example 的 context window 占用**：论文承认 example 会增加 input length，但主要评估场景中 example 数量相对有限（~5 个）。当需要更多 example 或原始请求本身较长时，context window 争抢问题可能更严重，尤其对于小模型（context window 本身就有限）。

6. **吞吐提升的归因**：1.4–5.9× 的吞吐提升范围跨度很大，主要来自于将请求从大模型 offload 到小模型。这本质上是模型路由的收益，而非 in-context caching 独有的贡献。Figure 16 的 ablation 也显示 router 的作用占比很大。

## 七、AI Infra / MLSys 视角

1. **对 LLM serving 架构的启发**：IC-Cache 提出了一种介于 prefix caching 和 model routing 之间的新范式——利用历史响应进行实时能力增强。这种思路可以扩展到更复杂的场景，如 multi-tenant serving 中不同用户群体共享高质量 example pool，或 agent 系统中跨 agent 的经验共享。

2. **与 KV Cache 优化的结合点**：IC-Cache 的 example 注入本质上增加了 prefill 长度。结合 prefix-aware scheduling（如 RadixAttention）和 KV cache reuse 技术，可以对常用 example 的 KV cache 进行跨请求复用，进一步降低 prefill 开销。这是一个值得探索的系统优化方向。

3. **Speculative decoding 的互补性**：IC-Cache 用小模型 + example 替代大模型，而 speculative decoding 用小模型加速大模型。两者可以组合：在 IC-Cache 判定需路由到大模型的请求上，用 speculative decoding 进一步降低延迟。

4. **可操作的 future work**：
   - 将 IC-Cache 扩展到 multi-turn conversation 场景，研究如何选择和管理对话级别的 example
   - 探索 example selection 与 prompt compression 技术的结合，在保留 example utility 的同时减少 token 消耗
   - 研究 IC-Cache 在 MoE 模型场景下的适用性——expert routing 与 request routing 的协同优化

---

## 八、总结

IC-Cache 提出了一种新颖的 LLM serving 优化思路：将历史请求-响应对作为 in-context examples 注入新请求，实现小模型对大模型推理能力的实时模仿，从而在不损失响应质量的前提下大幅提升吞吐（1.4–5.9×）并降低延迟（28–71%）。系统通过两阶段 example 选择、MAB-based 路由和 cost-aware 缓存管理实现端到端优化。其核心价值在于提供了一种轻量级、无需模型重训练的能力增强路径，但其效果依赖于大模型历史数据的可用性，且在复杂应用场景下的泛化能力仍需进一步验证。
