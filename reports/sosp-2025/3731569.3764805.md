## 一、背景

远程内存系统（remote memory systems）通过将不常访问的数据存放在网络可达的远端内存节点，扩展服务器的内存容量，从而提升多应用场景下的内存利用率和应用性能。这类系统的典型实现是 swap-based 方案：借助 Linux swap 子系统，应用程序无需修改即可透明地访问远端内存，常访问的数据驻留在本地 DRAM（作为 cache），miss 时通过 RDMA over RoCE 从远端拉取。

在多用户共享场景下，多个应用竞争两类关键资源：**本地 DRAM cache 容量**和**访问远端内存的网络带宽**。如何在多应用之间公平分配这两类资源，是保障系统性能和公平性的核心问题。

---

## 二、要解决的问题

### 2.1 Cache 与 Bandwidth 的复杂相互依赖

与传统计算、内存、磁盘等彼此独立的资源不同，远程内存系统中的 cache 和带宽存在复杂的**互依赖关系**：更大的 cache 可以降低 miss rate，从而减少所需带宽；更多的带宽则可以支持更多并发网络请求，降低对大 cache 的需求。因此，同一个吞吐量目标可以通过 `<大 cache, 小带宽>` 或 `<小 cache, 大带宽>` 等多种分配组合来实现。

### 2.2 应用需求难以先验确定

这种相互依赖关系是应用特定且工作负载依赖的，无法在部署前预知。带宽敏感型应用（如 STREAM）和 cache 敏感型应用（如 Memcached）对资源的偏好截然不同，且同一应用在不同工作负载下需求也会变化。

### 2.3 现有方案的局限

经典多资源公平分配方案（如 DRF）假设：① 各资源相互独立；② 应用的资源需求是一个先验已知的固定值。在远程内存场景下，这两个假设均不成立：应用无法知道自己的最优分配，被迫请求尽可能多的每类资源，导致 DRF 退化为静态均分，性能次优。硬件辅助方案（如基于 Intel CAT 的 LLC 分区）则依赖硬件改造，违反了 swap-based 系统的透明性要求。

## 三、核心设计

Spirit 是一个用于远程内存系统中多用户**公平资源分配**的框架，包含两大组件：

### 3.1 公平性重新定义

Spirit 将公平性目标重新定义为**性能公平性**（performance fairness），而非传统的资源份额公平性：
- **Sharing Incentive**：每个应用通过共享获得的性能不低于独占其静态公平份额（`C/N, B/N`）时的性能。
- **Envy-freeness**：任何应用不希望换取其他应用的资源分配。
- **Pareto-efficiency**：无法在不降低某应用性能的情况下提升另一应用的性能。

### 3.2 Symbiosis：基于拍卖的分配算法

Symbiosis 从微观经济学的 CEEI（Competitive Equilibrium from Equal Incomes）理论中汲取灵感，通过拍卖机制让应用"交易"资源：

1. **初始化**：每个应用获得等量 credits，cache 和带宽资源价格各设为 0.5（归一化）。
2. **竞价轮次**：每个应用根据当前资源价格和自身性能函数 `f_i(c, b)` 在预算约束下最大化性能出价。
3. **价格调整**：若某类资源总需求超出供应，则提高其价格，降低另一类价格，直到两类资源均被完全分配（清算）。
4. **收敛保证**：采用二分搜索确定均衡价格，保证收敛，最终分配满足三条公平性属性。

关键思路：cache 敏感型应用用 credits 购买更多 cache，带宽敏感型应用购买更多带宽，价格机制自动驱动资源从低价值用途流向高价值用途，实现互利交换。

### 3.3 运行时性能依赖估计

由于不依赖用户申报需求，Spirit 运行时自主估计每个应用的 `f_i(c, b)`：

- **硬件采样**：利用 Intel PEBS 对 LLC miss（`MEM_LOAD_RETIRED.L3_MISS`）进行采样（每 25 次访问采 1 次），建立内存访问频率直方图。
- **Power-law 回归**：利用 cache 条目访问频率服从幂律分布的规律，拟合函数 `g(x) = α₁(1+x/α₂)^α₃ + α₄`，通过两阶段梯度下降确定参数：第一阶段拟合访问直方图，第二阶段用实测 miss rate 校正。
- **Miss Ratio Curve (MRC) 估计**：基于 `g(x)` 计算目标 cache 大小下的 miss ratio，进而推算目标分配下的相对性能（slowdown 因子）。
- **局部准确性优化**：搜索范围限定在当前分配的 ±5ε 邻域内，确保估计误差 <10%。

## 四、实现细节

- **部署方式**：每个应用运行于独立 Docker 容器，通过 cgroups 实现资源隔离。
- **Cache 限制**：通过 `docker update` 设置容器内存上限（`cgroup memory.limit_in_bytes`）。
- **带宽限制**：通过 cgroup 的 `io.max` 限制 swap 块设备的 I/O 带宽。
- **页面置换**：使用 Linux 6.8 的 multi-generation LRU（mglru）进行更精确的 LRU 近似。
- **性能监控**：通过 Linux `perf` 工具采集 PEBS 事件；通过 `sysfs`（`memory.stat`、`memory.swap.current`、`/io.stat`）获取 swap 带宽和内存使用量。
- **分配周期**：30 秒为一个分配 epoch（兼顾响应速度和稳定性）。
- **代码规模**：系统以 Linux 内核模块和用户态 allocator 实现，开源于 https://github.com/yale-nova/spirit。

## 五、实验结果

**实验平台**：模拟 Amazon m5a.8xlarge EC2 实例（32 vCPU，128 GB 内存，7.5 Gbps 网络），基于 Intel Xeon 6252N 服务器，4 台远程内存节点，RDMA 延迟约 5μs，本地 DRAM cache 限制为 10~20 GB（约为工作集的 20%）。

**应用负载**（Table 1）：

| 应用 | 类型 | 内存占用 |
|------|------|---------|
| STREAM | 带宽敏感 | 16 GB |
| Memcached (Meta KVS) | cache 敏感 | 8 GB |
| DLRM | 计算密集 | 32 GB |
| SocialNetwork (DeathStarBench) | cache 敏感 | 15 GB |

**对比方案**：uDRF（用户申报需求的 DRF）、Harvest（PARTIES 改编）、Trade（直接 1:1 资源互换）、Ideal（离线最优）。

**主要结果**（24 应用实例，10 GB cache）：

| 应用 | Spirit vs uDRF（吞吐量） | Spirit vs uDRF（P99 延迟） |
|------|------------------------|--------------------------|
| Stream | +21.6% | — |
| Meta KVS | +5.9%~6.1% | -16.8%（降低） |
| Social Network | +5.9%~6.1% | -6.1%（降低） |
| DLRM | 无变化（计算密集） | — |

- Spirit 性能接近 Ideal，远优于 Harvest（因短期性能波动导致错误决策）和 Trade（虽性能高但违反公平性）。
- 资源充裕（20 GB cache）时，Spirit 增益降至约 7.6%（交换价值降低）；资源过度稀缺时各方案均崩溃。
- **Symbiosis 可扩展性**：24 个应用收敛 <1 秒，1000 个应用平均 <20 秒，CPU 占用 <3.3% 单核。
- **动态适应**：当应用的资源偏好在运行时切换（带宽敏感 ↔ cache 敏感），Spirit 约 5 分钟内检测并重新收敛。

## 六、批判性分析

**1. 实验规模有限**：全部实验在模拟 AWS 单实例规格的私有集群上完成（因无法获取公有云资源），最多 9 台机器，24 个应用实例。这一规模难以代表真实生产部署，论文对此的解释（"模拟 m5a.8xlarge"）较为牵强——"模拟"主要是通过参数配置，而非真实云环境的噪声和多租户干扰。

**2. 基线不公平的潜在问题**：uDRF 要求应用上报需求，在需求未知的情况下被迫请求所有资源，从而退化为均等分配。论文将其作为主要基线是合理的，但同时也意味着 Spirit 的提升部分来自于一个刻意设置的弱基线。Ideal 方案则依赖离线全量性能剖析——实际中完全不可行，作为上界参考价值有限。

**3. 单一性能指标的局限**：Spirit 使用 LLC miss rate（via PEBS）作为性能代理指标。对于 DLRM 等计算密集型应用，LLC miss 与端到端性能相关性弱，系统对此应用无法优化（论文也承认 DLRM 不受影响）。但若工作负载中计算密集型应用占比高，Spirit 的收益将大幅缩水。

**4. Monotonicity 假设存疑**：论文假设性能函数 `f_i` 对 cache 和带宽均单调递增，并以此为回归估计的基础。这一假设在大多数 LRU/LFU 场景下成立，但对于非 LRU 置换策略（如 2Q、ARC）或存在 Belady 异常的场景，单调性不保证。论文将此列为 future work，但未量化违反单调性时的降级行为。

**5. 30 秒 epoch 的配置敏感性**：实验表明 epoch 过短（<20s）或过长（>60s）均会导致性能退化，但"30 秒"这一选择依赖特定负载特性，通用性存疑。对于短生命周期容器或高频变化的工作负载，此参数可能需要重新调整。

**6. 策略证明与实际场景的差距**：论文证明 Symbiosis 在完整的 `f_i` 信息下满足公平性属性，但实际中依赖估计的 `f_i`，估计误差（Fig. 4 显示相距较远时误差可达 50%+）可能导致分配偏离理论保证。论文通过限制搜索范围缓解此问题，但并未严格量化估计误差对公平性属性的影响。

## 七、AI Infra / MLSys 视角

Spirit 的核心问题虽然聚焦于远程内存系统，但其设计思路对 AI Infra 有多个层面的借鉴价值：

**1. 异构资源的联合公平分配**：AI 训练/推理集群中同样存在多类相互依赖的资源（GPU 显存、NVLink 带宽、PCIe 带宽、CPU 内存、存储 I/O），传统资源调度器（如 Kubernetes）通常对这些资源独立建模。Spirit 的 Symbiosis 算法提供了一种将相互依赖资源联合建模并进行公平分配的可操作框架，可迁移到多租户 GPU 集群的资源调度。

**2. KV Cache 与带宽的权衡**：LLM 推理中 KV cache 的分配（显存大小）与 PCIe/NVLink 带宽（KV cache 迁移、disaggregated prefill-decode）之间存在类似的权衡关系。Spirit 的框架或许可以直接指导 disaggregated LLM serving 系统（如 Mooncake、DistServe）中的 cache 与传输带宽联合调度。

**3. 运行时性能估计的轻量化方法**：Spirit 采用 PEBS 硬件采样 + 幂律回归估计 MRC 的思路，规避了精确 reuse distance 计算的高开销。类似的思路可以用于 GPU 显存访问模式的建模（利用 NVIDIA NVLink/PCIe 监控工具），为显存换出（tensor offloading）或显存池化提供更准确的决策依据。

**可操作的 future work 方向**：
- 将 Symbiosis 扩展到 GPU 显存 + NVLink 带宽的联合分配，用于多租户 LLM 推理集群的公平调度。
- 在 CXL memory pooling 场景下验证 Spirit 框架，CXL 的低延迟特性会改变 γ 参数（本地/远端访问延迟比），影响性能估计模型。
- 探索将 MRC 估计与注意力机制的 working set 预测结合，用于 LLM KV cache 驱逐策略的优化。

---

## 八、总结

Spirit 针对 swap-based 多用户远程内存系统中 cache 与带宽互依赖导致的公平分配难题，提出了基于微观经济拍卖理论的 Symbiosis 算法，并通过 Intel PEBS 硬件采样与回归估计实现了运行时透明的性能依赖建模，在不修改应用或硬件的前提下实现了 Pareto-optimal、envy-free 且 sharing-incentive 的资源分配。实验表明在 24 应用实例下相比静态 DRF 最高提升 21.6% 吞吐量、降低 16.8% P99 延迟。局限在于：规模较小的实验环境、对单调性的强假设、以及分配 epoch 对负载特性的敏感性。
