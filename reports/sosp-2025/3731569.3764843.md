## 一、背景

Mixture-of-Experts（MoE）大语言模型通过稀疏激活机制在保持模型容量的同时大幅降低计算量，代表作如 DeepSeek-V3/R1（671B 参数）已经展现出 state-of-the-art 性能。MoE 模型天然适合两种部署场景：大规模云端（高并发，充分利用 GPU 集群）和本地部署（低并发，稀疏激活降低内存访问开销）。

对于本地部署，GPU 显存不足以容纳整个模型，CPU/GPU 混合推理成为一种有前景的方案：将 attention 等高计算密度模块放在 GPU 上，将 routed experts 卸载到 CPU/DRAM 上执行。先前工作 Fiddler 率先提出了这种基于算术密度的分区策略。然而，将这一方法应用于 671B 级别的大型 MoE 模型时，系统吞吐量极低（prefill 70 token/s，decode 4.68 token/s），GPU 利用率不到 30%，CPU 成为主要瓶颈。

---

## 二、要解决的问题

1. **Prefill 阶段 CPU 计算利用率不足**：MoE 的 prefill 阶段需要同时处理数千 token，对 CPU 产生大量矩阵乘法负载。现有实现仅使用通用 SIMD 指令（如 AVX-512），未能有效利用 Intel AMX 等高级 CPU 扩展。即使 PyTorch 通过 oneDNN 集成了 AMX kernel，实测性能仅达理论峰值的 7%，原因在于内存布局不佳导致 cache 效率低下。

2. **Decode 阶段 CPU-GPU 同步开销过大**：Decode 阶段每步只处理少量 token，单层 CPU/GPU kernel 执行时间极短（几毫秒甚至更少），导致同步开销占比极高。Fiddler 每个 decoded token 触发超过 7000 次 CUDA kernel launch，launch overhead 占 GPU 执行时间的 73%。Llama.cpp 通过 operator fusion 将其降至 21%，但仍然显著。此外，跨 NUMA 节点的内存访问效率低下进一步拖累性能。

3. **CPU 和 GPU 并行度不足**：在混合推理中，MoE 层（CPU）和 attention 层（GPU）的严格顺序依赖导致硬件资源大量闲置。DeepSeek-V3 的 shared experts 仅占 GPU 执行时间的 18%，CPU/GPU overlap 空间有限。

## 三、洞察与设计

**关键洞察**：现代 Transformer 模型由于 residual connection 的存在，对中间计算的延迟具有天然鲁棒性——部分 routed experts 的输出可以被推迟到下一层合并，而不会显著影响模型精度。这一特性使得打破 MoE 层与 attention 层之间的严格顺序依赖成为可能，从而释放 CPU-GPU 并行执行的空间。

基于以上洞察，KTransformers 提出三层优化：

### 1. Arithmetic Intensity-Aware Hybrid Inference Kernel
根据任务的算术密度（ARI）动态选择指令集：
- **高 ARI（prefill 阶段）**：使用专门为 AMX 设计的 kernel，配合 AMX tiling-aware 内存布局——预处理权重矩阵为 AMX tile 兼容的子矩阵，64 字节对齐，block-wise 量化（Int4/Int8），消除推理时的 transpose/reshape 开销
- **低 ARI（decode 阶段）**：切换到轻量级 AVX-512 kernel，避免 AMX 处理完整 tile 带来的额外开销
- 还实现了 Fused MoE Operator（Gate+Up 融合、跨 expert batch 化）和 dynamic task scheduling 解决 prefill 阶段负载不均衡问题

### 2. Asynchronous CPU-GPU Task Scheduling
将整个 decode phase 封装进单个 CUDA Graph 实例，利用 CUDA-based spinning 替代传统 CPU 端同步，消除 kernel launch overhead。与现有方案每层/每 batch size 需要独立 CUDA Graph 不同，KTransformers 用一个 graph 覆盖所有动态 tensor shape。

### 3. Expert Deferral
将每层 MoE 中的部分 routed experts（deferred experts）延迟到下一层的 attention 计算期间执行，在 layer k+2 合并结果。这样 CPU 执行 deferred experts 可以与 GPU 执行 attention 完全重叠，将 CPU 利用率从 ~75% 提升到接近 100%。

### 4. NUMA-Aware Tensor Parallelism
按 NUMA 拓扑分配 expert 权重和计算任务，避免跨 socket 内存访问。采用 tensor parallel 而非 expert parallel，确保每个 NUMA 节点只访问本地内存。

## 四、实现细节

- **代码规模**：11,000 行 C++ 扩展（性能关键组件）+ 2,000 行 Python 集成代码
- **接口兼容**：作为 HuggingFace Transformers 的 drop-in replacement，通过 module injection 机制替换默认 PyTorch 模块
- **AMX Kernel 执行流程**：
  1. 权重矩阵按列分区为 task，动态调度到线程
  2. 每个 task 按行分块，精确匹配 L2 cache 容量
  3. 每个块包含 AMX tile 大小的子矩阵
  4. Input 从 L3 cache 加载，权重从 DRAM 加载到 L2
  5. Tile 级 AMX 指令执行乘累加，中间结果缓冲在 L1
- **量化支持**：对称 group-wise 线性量化（Int8/Int4），scale factor 独立存储以保持对齐；Int4 packed 到 Int8 大小块中，用 SIMD intrinsics 解包
- **Expert Deferral 参数选择**：目标是刚好饱和 CPU 利用率，同时保证至少 2 个 immediate experts 以维持行为稳定性。DeepSeek-V3 BF16 defer 3 experts，Int4 defer 6 experts
- **GPU 端**：集成 FlashInfer attention 和 Marlin 量化 kernel
- **开源**：https://github.com/kvcache-ai/ktransformers

## 五、实验结果

**硬件平台**：双路 Intel Xeon 8452Y（每路 36 核，1TB DDR5，intra-socket 220 GB/s，cross-socket 125 GB/s），搭配 NVIDIA A100 40GB 或 RTX 4080 16GB，PCIe 4.0 连接。

**模型**：DeepSeek-V3-0324（671B）、DeepSeek-V2.5-1210（236B）、Qwen2-57B-A14B

**基线**：Fiddler（PyTorch-based）、Llama.cpp（C++-based，扩展了 expert-level offloading）

### 端到端性能

| 指标 | vs Fiddler | vs Llama.cpp |
|------|-----------|-------------|
| Prefill 加速 | 4.62–19.74× | — |
| Decode 加速（无 Expert Deferral） | 2.42–4.09× | 1.25–1.76× |
| Decode 加速（含 Expert Deferral） | — | 1.66–2.56× |

### 微基准测试

| 组件 | 加速比 |
|------|--------|
| AMX kernel vs PyTorch oneDNN | 3.98×（单路 CPU，峰值 21.3 TFLOPS） |
| CUDA Graph 优化 | decode 阶段 1.23× |
| Expert Deferral | 额外 up to 1.45× |

### Expert Deferral 精度影响

| 模型 | HumanEval | MBPP | GSM8K | StrategyQA |
|------|-----------|------|-------|------------|
| DS-3 (8+0) → (2+6) | 83.0 → 83.0 | 71.2 → 70.2 | 94.8 → 95.2 | 83.0 → 82.9 |
| DS-2 (6+0) → (2+4) | 80.5 → 82.5 | 67.6 → 66.8 | 93.3 → 92.8 | 79.7 → 80.4 |
| QW-2 (8+0) → (4+4) | 65.7 → 67.4 | 52.4 → 53.4 | 84.7 → 83.4 | 83.6 → 82.5 |

在 LiveBench 上，Expert Deferral（6 experts deferred）平均精度下降仅 0.5%，而 Expert Skipping 同等条件下下降 13.3%。

### 性能分解（BF16，以 Fiddler 为基线）

- Prefill：AMX kernel 贡献最大（~3.14×），dynamic scheduling 贡献 ~1.83×，NUMA-aware ~1.22×
- Decode：AVX-512 kernel ~2.22×，NUMA-aware ~1.63×，CUDA Graph ~1.23×

## 六、批判性分析

1. **实验只测了 batch size = 1**：这是论文自己限定的"本地部署"场景，但完全回避了 batch size > 1 时系统表现如何。当 batch size 稍微增大（哪怕 2-4），ARI 变化会改变 AMX/AVX-512 的最优选择点，Expert Deferral 的 accuracy trade-off 也可能不同。论文没有讨论这一边界。

2. **Expert Deferral 的精度评估不够深入**：虽然在几个标准 benchmark 上精度下降 <0.5%，但这些 benchmark 都是短 context 任务。对于长文档理解、multi-turn 对话等场景，deferred expert 的累积误差是否会放大？论文未涉及。LiveBench 的细分结果显示 Language 和 Data Analysis 类别下降较多（部分超过 1%），但论文只强调了平均值。

3. **硬件绑定过强**：核心优化高度依赖 Intel AMX（Sapphire Rapids 及以后）和特定的 NUMA 拓扑。对于 AMD EPYC（有类似的 AVX-512 但无 AMX）、Apple Silicon、ARM 服务器等平台的适用性，论文仅在设计层面提及"可扩展"但无实验验证。

4. **与 weight offloading 方案的比较不完整**：论文只比较了 computation offloading（Fiddler 系）和 Llama.cpp，未与 ProMoE、MoE-Infinity、Expert Flow 等 2024 年的新工作进行端到端对比，虽然在 related work 中提到了这些系统。

5. **CUDA Graph 的 VRAM overhead 讨论不足**：论文提到将整个 decode phase 封装进单个 CUDA Graph，但没有报告这带来了多少额外的 VRAM 占用。在 RTX 4080 16GB 这种 VRAM 受限的场景下，这个 overhead 可能很关键。

6. **Expert Deferral 与 Expert Skipping 的对比存在公平性问题**：Expert Skipping 直接丢弃低分 experts，而 Expert Deferral 只是延迟一层。二者在概念上差异巨大（一个是近似，一个是精确计算的延迟合并），对比的意义更多是展示 Deferral 的优势，而非公平对标。

## 七、AI Infra / MLSys 视角

1. **Computation offloading 范式的系统化**：KTransformers 证明了在本地部署场景下，computation offloading 远优于 weight offloading（受 PCIe 带宽限制）。这一思路可以推广到更多异构计算场景——不只是 CPU/GPU，还有 NPU/GPU、多级缓存系统等。

2. **Expert Deferral 的通用性值得探索**：利用 residual connection 的鲁棒性来打破层间依赖、提升并行度，这一 insight 不限于 MoE 推理。它可能适用于：
   - 分布式推理中跨节点的 pipeline 重叠
   - Speculative decoding 中 draft model 与 verification 的重叠
   - 训练中 gradient 的异步聚合

3. **AMX/SME 等新指令集的 AI workload 适配**：论文揭示了 PyTorch + oneDNN 的 AMX 利用率仅 7%，这说明上层框架对新硬件指令的适配严重不足。这对 AI compiler（如 TVM、Triton）是一个明确的改进方向——需要 tiling-aware memory layout 的自动生成。

4. **可跟进的研究方向**：
   - **Dynamic Expert Deferral**：根据 token 的实际路由结果动态决定 defer 数量，而非使用固定配置
   - **Multi-GPU + CPU 混合**：将 KTransformers 的思路扩展到多 GPU 场景，某些 experts 在 CPU 上、某些在不同 GPU 上
   - **Training-time deferral-aware fine-tuning**：如果知道推理时会使用 Expert Deferral，可以在训练/微调阶段引入类似的 regularization，进一步减少精度损失

---

## 八、总结

KTransformers 是一个针对 MoE 模型 CPU/GPU 混合推理的高性能系统，通过 AMX-specialized kernel（充分利用现代 CPU 矩阵加速指令）、异步 CUDA Graph 调度（消除 kernel launch overhead）、NUMA-aware tensor parallelism（避免跨 socket 内存访问）以及创新的 Expert Deferral 机制（利用 residual connection 的鲁棒性实现更充分的 CPU-GPU 重叠），在单 GPU + 双路 CPU 的本地环境下实现了 671B DeepSeek-V3 的实用推理。系统相比 Fiddler 和 Llama.cpp 分别获得 4.62–19.74× prefill 和 1.66–4.90× decode 加速，且 Expert Deferral 的精度损失控制在 0.5% 以内。主要局限在于硬件绑定（Intel AMX）较强、仅验证了 batch size = 1 场景，以及长 context 下 Expert Deferral 的精度影响尚不明确。
