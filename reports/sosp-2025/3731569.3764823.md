## 一、背景

LLM 推理服务的核心瓶颈之一是 GPU 显存容量——更大的 batch size 意味着更高的吞吐量，而 batch size 直接受限于 KV cache 的显存占用。PagedAttention 是当前最广泛使用的 KV cache 内存管理算法，它将显存划分为固定大小的 page，按 token 数量动态分配给请求。

PagedAttention 的设计基于早期 Transformer 的两个同质性假设：(1) 所有 token 和所有 layer 的 embedding 大小相同，因此 page 大小固定；(2) 所有 layer 使用 full attention，因此每层需要相同数量的 page。然而，最新的 LLM 架构正在变得越来越异构——Gemma-3 混合了 full attention 和 sliding window attention，Hymba/Jamba 混合了 Mamba 层和 attention 层，VLM 的 vision embedding 和 KV cache 大小不同，speculative decoding 同时运行大小两个模型——这些都打破了 PagedAttention 的同质性假设。

---

## 二、要解决的问题

1. **内存碎片化**：异构模型中不同 layer 类型的 embedding 大小不同（如 Llama 3.2 Vision 的 text token KV cache 是 image token 的 4 倍），PagedAttention 只能按最大类型分配，导致严重的内存浪费（Llama 3.2 Vision 在 MMMU-pro 数据集上浪费 79.6%，Gemma-3 浪费 73.6%）。传统的 Buddy allocator 等通用分配器同样会产生不可用的碎片。

2. **Prefix caching 策略失效**：不同 attention 机制对 prefix caching 的需求截然不同——full attention 需要缓存所有 prefix token，sliding window 只需缓存窗口内的 token，Mamba 只需缓存最后一个 token 的 state。(a) 不同层的 cache hit 条件不同，但整体 hit rate 受最差层约束，需要跨层平衡；(b) 为高效 attention 层只缓存 active token 可以增大 batch size，但会降低 cache hit rate，两者之间存在 trade-off。

---

## 三、洞察与设计

**关键洞察**：现代异构 LLM 中，不同层的内存行为（可能的分配大小和 page 访问模式）可以从模型结构中提前确定——embedding 大小是编译期已知的常量，attention 机制的 token 依赖模式也是固定的。因此，可以将这些行为建模为 layer property，在此基础上实现高级的内存管理。

基于这一洞察，Jenga 提出了 **layer property 抽象接口**，包含三个属性：
- `page_size()`：该层每个 token 的 KV cache 大小
- `active_pages(request, length)`：给定请求长度下生成下一个 token 所需的 page 集合
- `possible_prefix(is_hit)`：给定 cache 状态下所有合法的 prefix hit 长度

在此抽象之上，Jenga 构建了两大核心组件：

**LCM Allocator（两级内存分配器）**：底层使用大小为所有 embedding size 的最小公倍数（LCM）的大 page，上层由每种 layer type 的定制分配器将大 page 切分为对应大小的小 page。由于现代 LLM 的 embedding 大小通常是 2 的幂次的倍数，LCM 通常接近最大 embedding size（如 Gemma-3-27B 的 LCM 为 8320KB vs 最大 1664KB），碎片极小。不同 layer type 共享大 page pool，可根据运行时 workload 动态交换内存。

**Customizable Prefix Caching**：针对每种 attention 机制定制 eviction、cache hit 策略：
- Eviction：用 LRU 策略，但只更新 active page 的 last access time（sliding window 层只更新窗口内 token），使窗口外 token 自然获得更高的 eviction 优先级，同时跨层使用统一时间戳保持平衡。
- Cache Hit：通过 `possible_prefix` 接口为每种层定制 hit 规则，取所有层的交集作为最终 hit prefix。
- Common Page Pool：单独维护一个不可被 evict 的 page pool，缓存高概率复用的 prefix page（基于相邻请求的 common prefix 预测），解决 batch size 与 cache hit rate 的 trade-off。

## 四、实现细节

- 基于 vLLM 实现，约 4,000 行 Python 代码，对用户透明，无需为新模型做额外配置。
- **内存布局**：采用 page-layer partition（先分 page 再分 layer），而非 PagedAttention 的 layer-page partition。每层的内存仍可用 `KV_cache_start_ptr`、`page_size_exec`、`pageid_exec` 三个参数表示，复用现有 PagedAttention kernel，无需修改 attention kernel 代码。
- **小 page 分配器**：每种 layer type 维护自己的小 page 分配器，当小 page 耗尽时向 LCM 分配器申请大 page 并切分；当大 page 内所有小 page 释放后，归还给 LCM 分配器。尽量将同一请求的小 page 分配在同一大 page 内以减少内部碎片。
- **Common prefix 预测**：利用 Mooncake 真实 trace 的观察——若两个短间隔到达的请求共享 prefix，则该 prefix 有 81% 概率被后续请求复用。预测方法为取新请求与"GPU 能同时容纳"的最近请求的最长公共前缀。
- **Common page pool 大小确定**：通过模拟 token 调度并用线性回归模型（公式 2）估算前向传播时间，搜索使总执行时间最短的 pool 大小。实践中约 1000 个 page 即足够。
- **VLM Vision Embedding Cache**：支持 allocate-on-demand 模式下 chunked prefill 时按需释放已消费的 vision embedding；支持 fully-allocated 模式下复用 KV cache 内存空间存储 vision embedding，实现零额外内存开销。
- 支持的 layer type：full attention、sliding window attention、Mamba (SSM)、Llama 4 local attention、cross attention（VLM）、PyramidKV（动态 token dropping）。

## 五、实验结果

**平台**：NVIDIA H100 80GB GPU / NVIDIA L4 24GB GPU

**端到端吞吐量**（vs vLLM v0.8.3）：

| 模型 | H100 加速比 | L4 加速比 |
|------|------------|----------|
| Llama 3.2 Vision 11B | 1.71× | 2.16× |
| Gemma-3 12B | 1.39× | 1.56× |
| Ministral 8B | 1.73× | 2.07× |
| Llama 4 109B (8×H100) | 1.39× | OOM |
| Jamba-1.5 52B (4×H100) | 1.62× | OOM |
| Character.ai 70B | 1.50× | — |
| PyramidKV 70B | 1.00× | 1.00× |
| Llama 3.1 (full attn baseline) | 1.00× | 1.00× |

- H100 平均加速 1.46×，L4 平均加速 1.65×
- 对纯 full attention 模型（Llama 3.1）无额外开销
- 低请求率下延迟仅增 4.2%，高请求率下 E2E 延迟降低最高 1.90×，TTFT 降低最高 23.40×

**最大上下文长度**（Llama 4 109B）：

| 配置 | vLLM | Jenga |
|------|------|-------|
| 8×H100 | 1.3M | 5.2M |
| 8×H200 | 3.7M | 14.7M |

Jenga 在 8×H200 上支持完整 10M+ 上下文，vLLM 仅 3.7M。

**内存利用率**：vLLM 平均浪费 38.2% KV cache 内存，Jenga 仅浪费 0.04%。

**Decode batch size**（Ministral 长文档 QA）：Jenga 平均 batch size 5.39 vs vLLM 2.63 / SGLang 2.74 / TGI 2.50（约 1.95× 提升）。

**Prefix caching**（Gemma-3，arXiv-QA）：cache hit rate 从 2.4%（full attention 策略）提升到 34.6%（Jenga 完整方案）。

**VLM vision embedding cache**：吞吐提升 1.34×–3.53×，延迟降低 20%–78%。

**Speculative decoding**：异构模型平均 1.58× 吞吐提升。

## 六、批判性分析

1. **实验模型选择偏向异构场景**：论文的核心卖点是处理异构性，因此实验中选择的模型天然对 Jenga 有利。在 PyramidKV 和 Llama 3.1（同质模型）上加速比为 1.00×，说明 Jenga 的收益完全来自异构性——但论文没有讨论异构模型在实际部署中的占比和趋势的量化数据。

2. **Common prefix 预测的泛化性存疑**：81% 的 prefix 复用概率来自 Mooncake 的单一 trace，论文未验证该统计规律在其他真实 workload（如 agent 场景、多轮对话）中是否成立。如果请求的 prefix 分布更加离散，common page pool 机制的收益可能大幅下降。

3. **LCM 方案的可扩展性**：当前模型的 embedding size 碰巧有大量公因子（以 2 的幂为主），使 LCM 接近最大值。论文承认了这一点但未讨论如果未来模型采用更不规则的 embedding size（如素数倍数），LCM 可能爆炸的风险。

4. **缺少与 vAttention/GMLake 的端到端对比**：论文在 related work 中分析了 GPU virtual memory 方案的不足，但没有实验数据支撑——仅是定性论述 2MB 粒度太粗。

5. **Character.ai 模型的不可复现性**：Character.ai 是私有模型，论文基于博客描述自行实现，实验结果无法被第三方验证。

6. **延迟指标的微妙之处**：高负载下 Jenga 的 TPOT（Time Per Output Token）实际更高，因为 batch 更大导致单步计算量增加。论文解释"可以调度相同数量的请求来获得相同 TPOT"，但这回避了实际部署中 batch size 和延迟 SLO 之间的 tension。

## 七、AI Infra / MLSys 视角

1. **Layer property 抽象的通用价值**：Jenga 提出的 `page_size`/`active_pages`/`possible_prefix` 三元组接口，是对异构 LLM 内存行为的优雅抽象。这个接口思路可以迁移到其他系统决策中——如分布式推理的 tensor 分片策略、offloading 决策、甚至训练阶段的 activation checkpointing 策略，都可以利用类似的 layer property 抽象来做 layer-aware 优化。

2. **LCM allocator 对 Slab allocator 的映射**：论文明确指出 LCM allocator 是 slab allocator 的特殊形式。这个映射启发我们：OS 领域成熟的内存管理技术（slab、buddy、NUMA-aware allocation）在 GPU 内存管理中仍有巨大的应用空间，尤其是随着模型异构性增加。

3. **值得跟进的研究方向**：
   - **跨节点的异构 KV cache 管理**：当前 Jenga 是单节点方案，分布式推理（如 disaggregated prefill/decode、pipeline parallelism）中如何协调不同节点的异构 KV cache 分配是自然的扩展。
   - **MoE 模型的内存异构性**：MoE 模型的 expert 层激活 pattern 也带来内存异构性，能否将 layer property 扩展为 expert property？
   - **动态异构性**：PyramidKV 等动态 pruning 方法使每层的实际 KV cache 大小在运行时变化，Jenga 当前对此支持有限（实验中加速比 1.00×），如何高效处理运行时动态变化的异构性是开放问题。

4. **最有价值的切入点**：将 Jenga 的内存管理与 KV cache 的 CPU/disk offloading（如 CachedAttention、CacheGen）结合——异构层的不同 eviction 优先级可以直接指导 offload 策略（如 sliding window 外的 token 优先 offload 而非丢弃），在有限 GPU 显存下实现更长上下文。

---

## 八、总结

Jenga 针对现代异构 LLM 架构的内存管理问题，提出了基于 layer property 抽象的两级 LCM 内存分配器和可定制的 prefix caching 策略。通过消除异构 embedding 的内存碎片（从 38.2% 降至 0.04%）和优化 cache hit rate（从 2.4% 提升至 34.6%），Jenga 在多种异构模型上实现了 1.46×–2.16× 的吞吐提升，并将 Llama 4 的单节点最大上下文从 3.7M 推至 14.7M。其设计优雅、实现轻量（4K 行 Python，复用现有 attention kernel），已在 vLLM 中开源并被工业界部署。主要局限在于收益完全来自模型的异构性程度，对同质模型无额外收益。
