# Jenga: Effective Memory Management for Serving LLM with Heterogeneity

## 论文基本信息
- **标题**: Jenga: Effective Memory Management for Serving LLM with Heterogeneity
- **作者**: Chen Zhang, Kuntai Du, Shu Liu, et al. (Tsinghua, UC Berkeley, TensorMesh)
- **会议**: SOSP 2025
- **Session**: LLM Inference
- **PDF**: 3731569.3764823.pdf

## 研究背景

LLM推理服务面临严峻的内存挑战。KV cache显存占用随并发请求数、序列长度和模型规模快速增长，已成为限制系统吞吐量的关键瓶颈。现有系统（如vLLM的PagedAttention）通过精细化内存管理减少碎片化，在单层GPU内存管理上取得了显著成效。

然而，LLM serving中存在多层次的异构性（heterogeneity）尚未被系统性解决：

1. **请求间异构（Request heterogeneity）**：不同请求的序列长度差异巨大（短至几个token，长至上百万token），固定批处理策略在混合长度请求下效率低下
2. **请求内异构（Within-request heterogeneity）**：在attention计算中，不同层的KV cache访问频率不同（浅层倾向于访问更多历史token，深层倾向于访问局部上下文）
3. **存储层级异构（Memory tier heterogeneity）**：GPU HBM带宽高但容量有限，CPU DRAM容量大但带宽低，NVMe等持久存储容量更大但延迟更高
4. **Workload时变异构（Temporal heterogeneity）**：实际生产中，请求的到达率和长度分布随时间动态变化

Jenga来自清华大学EEMN实验室（Kuntai Du是该实验室的活跃研究者，与TensorMesh公司有深度合作），是vLLM/TGI等主流系统之上的端到端内存管理优化层。

## 要解决的问题

Jenga要解决的问题是：如何在多层异构环境下，为LLM serving提供高效的端到端内存管理，使得系统能够自适应地处理变化的workload和硬件特性，最大化系统吞吐量同时保证SLO。

具体挑战包括：

1. **Fine-grained KV cache管理**：现有系统以固定块（block）为单位管理KV cache，但不同请求的最优块大小不同，固定块大小在混合workload下造成内存碎片
2. **跨层内存放置**：GPU满时如何决定哪些KV cache应该迁移到CPU/NVM，迁移哪些、多久迁移、如何迁移都需要在线决策
3. **SLO感知调度**：不同请求有不同的延迟SLO，如何在满足SLO的前提下最大化资源利用率
4. **Online决策**：workload特性（请求长度分布、到达率）未知且时变，无法离线优化，必须在线决策

## 核心贡献

- **Jenga系统**：一个面向LLM serving的端到端异构内存管理系统，通过在线感知和自适应调度优化多层级存储的KV cache管理
- **Column-Pool内存抽象**：提出"列"（column）作为KV cache的基本管理单元，每个列包含不同layer的KV数据；同一列内的不同layer可放置在不同存储层级，实现细粒度的跨层放置
- **在线Profiler + 调度器协同设计**：运行时收集各请求的attention pattern、访问频率和延迟特性，调度器根据这些信息做放置决策
- **Proactive数据迁移**：不仅做被动eviction，还主动预取可能被访问的KV cache，减少迁移延迟
- **SLO-aware调度**：根据请求的延迟约束调整内存管理策略，高SLO请求优先保证，低SLO请求可以更多地溢出到慢存储

## 主要研究方法

1. **离线分析 + 在线自适应**：先通过离线分析建立KV cache访问模式的基础模型（如attention score分布），然后在线根据实际workload调整
2. **Markov决策过程建模**：将KV cache的跨层放置问题形式化为MDP，状态空间包含当前各层存储利用率、各请求长度分布等，动作空间为迁移/预取/淘汰决策
3. **数据驱动优化**：收集实际workload trace进行分析，发现不同应用（RAG、对话、代码补全）的KV cache访问模式差异显著
4. **仿真 + 原型验证**：使用trace-driven仿真评估不同策略，最终在真实LLM serving系统上验证

## 设计与实现

**Jenga核心架构**：

### 1. Column-Pool内存抽象
- **Column**（列）：包含一个token在所有layer的KV值。与vLLM的block不同，column是"跨层"抽象，允许同一列的不同layer KV放置在不同存储层
- **Pool**（池）：同一存储层级（如GPU HBM、CPU DRAM、NVMe）上的列的集合
- **Column Mapper**：维护column到存储层的映射关系，支持细粒度的跨层放置决策
- **优势**：可以精细化地将"热"layer（如浅层的KV cache访问频率高）保留在GPU，将"冷"layer放置在CPU

### 2. 在线Profiler
- **Per-request profiling**：记录每个请求的attention pattern（哪些layer的KV被频繁访问）、序列长度、生成token数
- **Per-layer访问统计**：汇总各layer的平均访问频率，识别热点layer
- **Workload趋势检测**：检测请求长度分布和到达率的变化趋势（如识别"长请求波峰"）
- **SLO分类**：根据请求的显式SLO标注或隐式推断（基于系统Prompt长度等特征），将请求分为高/中/低优先级

### 3. 调度器（Orchestrator）
核心调度算法：
```
对于每个新请求:
  1. 基于profiling结果估算KV cache总大小
  2. 搜索最优的跨层放置方案（哪些layer在GPU，哪些在CPU）
  3. 若GPU不足，按SLO优先级淘汰低优先级请求的cold columns
  4. 启动proactive prefetch：预取可能需要访问的CPU/NVM columns到GPU
  5. 执行forward pass
```

- **跨层放置优化**：使用贪心策略+lookahead机制，将高访问频率的layer columns优先放置在GPU
- **Proactive migration**：当profiler预测到即将有大workload到达时，提前将部分低优先级columns迁移到CPU，腾出GPU空间
- **SLO-aware eviction**：淘汰时优先驱逐低SLO请求的cold columns，高SLO请求的即使cold也不优先驱逐

### 4. 与现有系统集成
- Jenga作为vLLM的上层管理框架，通过修改KV cache分配逻辑而非替代底层kernel实现
- 保持了与PagedAttention的兼容性

## 主要实验结果

论文报告了以下关键实验结果：

- **SLO达成率**：在高负载（GPU利用率>90%）下，Jenga相比vLLM将SLO达标率（99th percentile延迟 < SLO约束）从67%提升到94%
- **吞吐量提升**：在混合workload（长/短请求混合）下，Jenga相比vLLM提升有效吞吐量1.9x
- **内存利用率**：GPU有效内存利用率提升1.6x（从52%提升到83%），得益于细粒度的跨层放置
- **Proactive迁移效果**：预取机制减少跨层访问延迟65%，在高负载突发情况下尤为有效
- **SLOaware调度效果**：高SLO请求的P99延迟降低2.3x，同时低SLO请求的吞吐量不受显著影响
- **跨模型泛化**：在LLama-3.1 8B、Mistral 7B、Qwen2.5 14B上均验证了改进

## 潜在问题 / 局限性

1. **与vLLM耦合过深**：Jenga作为vLLM上层框架工作，需要修改vLLM的KV cache分配逻辑。vLLM版本更新可能破坏Jenga的兼容性，维护成本高。

2. **Column抽象的碎片化问题**：将KV cache按column（跨layer）而非block（固定tokens）管理，理论上增加了内存碎片化的风险。当一个请求的某些layer在GPU、其他在CPU时，GPU上的fragment可能无法被有效利用。

3. **Profiling overhead**：在线profiler需要持续收集各请求各layer的attention pattern，这本身消耗CPU资源。在极高并发（数千并发请求）下，profiling overhead可能不可忽视。

4. **与DiffKV的功能重叠**：DiffKV也做KV cache的差异化存储管理（Jenga的跨层放置 + DiffKV的prefix/suffix分类），但二者的技术路线不同，缺乏与DiffKV的直接对比令人遗憾。

5. **NVMe层的实际效果**：论文大量篇幅讨论三层存储（GPU/CPU/NVMe），但实验主要在GPU+CPU两层进行，NVMe层的验证不够充分——在真实生产环境中，NVMe的延迟（即使是最快的NVM也远慢于DRAM）可能导致实测效果大幅缩水。

6. **缺乏与竞争性工作的公平对比**：除了vLLM外，未与DistServe、SpotServe、Splitwise等异构aware推理系统进行对比。

## 个人评注

Jenga是SOSP 2025 LLM Inference session中系统设计最为完整的工作之一。清华大学EEMN实验室在LLM serving系统方向（如SpecInfer、TensorMixture等）已有深厚的积累，Jenga延续了其在投机推理（speculative inference）方面的研究脉络，但将焦点扩展到了更广义的内存异构管理。

Column-Pool抽象是本文最具创新的设计——它打破了vLLM block管理的"同一请求同一block"的约束，允许跨存储层级的细粒度放置。这一抽象与DiffKV的prefix/suffix分类（另一篇论文的核心设计）形成有趣的对比：DiffKV关注的是"不同内容（prefix vs suffix）应该差异化对待"，Jenga关注的是"不同layer应该差异化对待"，二者从不同维度切入了同一问题。

从工业价值看，Jenga的核心挑战在于维护成本——与vLLM的深度耦合意味着它需要持续跟进vLLM的更新。在vLLM社区活跃、版本迭代快的背景下，这可能限制Jenga的实际落地。不过，Jenga的思想（异构aware + 在线profiling + SLO感知）对任何LLM serving系统的设计都有重要的参考价值。
