# DiffKV: Differentiated Memory Management for Large Language Models with Parallel KV Compaction

**作者**：Yanqi Zhang*, Yuwei Hu* (Huawei), Runyuan Zhao (Huawei), John C.S. Lui (The Chinese University of Hong Kong), Haibo Chen† (Shanghai Jiao Tong University)

**链接**：https://doi.org/10.1145/3731569.3764810
**源文件**：[[3731569.3764810.pdf]]

---

## 一、背景

LLM 推理的核心瓶颈之一是 KV cache 的显存占用。KV cache 随序列长度和并发请求数线性增长，常占总显存的 90% 以上。随着模型支持更长上下文（如 128K+）以及 thinking model（如 QwQ、DeepSeek-R1）生成超长 chain-of-thought，KV cache 的压缩变得愈发关键。现有压缩技术主要分为两类：pruning（根据 attention score 裁剪不重要 token）和 quantization（将 KV cache 从 FP16 量化到低精度）。然而，这些方法对 key 和 value、不同 token、不同 attention head 采用统一策略，未能充分利用 KV cache 内部的差异性。

---

## 二、要解决的问题

1. **Key 与 Value 同等对待**：现有量化方法对 key 和 value 使用相同精度，忽略了 key 在 attention 计算中（softmax 分母，影响所有 token）比 value（仅影响自身 token 的加权贡献）更关键的事实。

2. **Token 重要性未分层**：pruning 方法直接丢弃不重要 token，量化方法对所有 token 使用统一精度，缺少介于"保留"与"丢弃"之间的中间策略。

3. **静态稀疏性分配**：现有方法对所有 attention head 和所有请求使用固定的内存预算，无法适应不同 head、不同请求之间动态变化的 attention 稀疏性模式。

4. **不规则显存管理的可扩展性**：差异化压缩引入高度不规则的 per-head、per-request 显存分配模式，需要管理数万个异构内存区域，而每步推理时间仅在毫秒量级，内存管理开销可能抵消压缩收益。

---

## 三、洞察与设计

**关键洞察**：KV cache 中存在三个层次的差异性——(1) key 对 attention 输出的影响远大于 value（attention score 跨 7 个数量级，而 value norm 仅跨 2 个数量级）；(2) token 重要性呈高度非均匀分布，可按重要性分层压缩；(3) attention 稀疏性在不同 head 和不同请求间动态变化，需要 per-head、per-request 的自适应内存分配。

基于上述洞察，DiffKV 设计了三层差异化压缩框架：

- **差异化 Key/Value 精度**：key 使用更高精度（如 INT8），value 使用更低精度（如 INT4），组合为 K8V4 或 K4V2。
- **层次化 token 压缩**：根据 attention score 将 token 分为三级——最重要 token 用高精度存储（K8V4），中等重要 token 用低精度（K4V2），最不重要 token 直接裁剪。
- **Per-head 动态稀疏性**：每个 attention head 根据自身稀疏性模式独立决定高/低精度 token 的数量，无需预设固定预算。

压缩策略同时具有**序列长度自适应性**：短序列保留更多高精度 token 以维护质量，长序列更积极地压缩以节省显存。阈值通过将 token 的 significance score 与理论平均值 1/N 比较来确定（参数 αh 和 αl 通过 MATH 数据集离线校准）。

## 四、实现细节

DiffKV 基于 vLLM 实现，包含 4.5K 行 CUDA/C++ 和 9K 行 Python。

**核心数据结构**：

1. **Unified Pages**：GPU 显存被划分为固定大小的 page，每个 page 在分配时动态配置精度。Page 内部包含六个段：量化 key、key 元数据、量化 value、value 元数据、token score、position。不同精度的 page 容纳不同数量的 token。

2. **Circular Free Page List**：所有 Page ID 存储在 GPU 端环形列表中，通过 start/end 指针管理。空闲和已用区域保持连续，使得内存分配和回收可以通过 parallel prefix sum 并行化。

3. **Bidirectional Page Table**：每个 attention head 维护一个双向 page table——高精度 page ID 从左侧增长，低精度 page ID 从右侧增长，减少元数据开销。

**KV Compaction 流程**：
- Prompt 阶段：先保守分配（假设全部高精度），压缩后通过 parallel prefix sum 回收多余 page。
- Generation 阶段：每步最多为每个 head 分配一个新 page，token 可从高精度降级到低精度或被裁剪。

**Custom Attention Kernel**：设计了专用 GPU kernel，支持混合精度 KV cache 的高效 attention 计算。采用定制数据布局 `[F/(Kvec×Kgroup), Ntokens, Kgroup, Kvec]` 确保向量化内存访问的连续性。

**跨平台支持**：DiffKV 也被移植到了华为 Ascend NPU。

## 五、实验结果

**实验平台**：NVIDIA GPU，模型包括 Llama3-8B、Llama3-70B、Qwen2.5-7B、Qwen2.5-32B、QwQ-32B、R1-Distill-Qwen-14B、R1-Distill-Llama-8B。

**基线方法**：vLLM（FP16）、INT4 量化、KIVI（2-bit）、Atom（4-bit）、QAQ、SnapKV、H2O、Quest、DuoAttention。

| 指标 | 结果 |
|------|------|
| KV cache 压缩比 | 2.7× ~ 5.7×（使用 19.3% ~ 36.7% 显存） |
| 精度损失 | 平均仅 0.3%（非 thinking model），thinking model 上也近乎无损 |
| 吞吐提升 | 1.9× ~ 5.4×（QwQ-32B 上达 5.4×） |
| Batch size 提升 | 最高 5.9×（QwQ-32B：2.7 → 15.9） |
| 内存管理开销 | < 0.2%（prompt 阶段）、< 0.9%（generation 阶段） |
| GPU→CPU 内存管理延迟对比 | 降低 3 个数量级 |
| Attention kernel speedup | K8V4 在 4096 序列长度下达 2.8× |
| Ascend NPU | Llama3-8B 吞吐提升 1.7×，QwQ-32B 提升 3.8× |

**Thinking model 表现**（Table 3）：在 AIME24 和 GPQA 等高难度推理基准上，pruning 方法（Quest、SnapKV）准确率降至接近 0%，而 DiffKV 保持与 FP16 相当的准确率。

## 六、批判性分析

1. **参数校准的泛化性存疑**：αh 和 αl 仅在 MATH 训练集上校准，作者声称"MATH 信息密度高，参数应能泛化"，但实际上 Qwen2.5-7B 对 4-bit key 量化敏感，需要禁用低精度量化，说明不同模型架构对压缩策略的敏感性差异大。论文未讨论当模型或任务分布显著偏移时参数是否需要重新校准。

2. **基线比较的公平性**：Atom 和 KIVI 基于 HuggingFace Transformers 实现，而 DiffKV 基于 vLLM 并配备了定制 CUDA kernel。作者承认了这一点，但这意味着吞吐对比中 DiffKV 的部分优势来自工程实现（vLLM + 定制 kernel）而非压缩策略本身。

3. **仅评估了两级量化精度**：论文指出系统可扩展到更多精度级别，但所有实验仅使用了两级（K8V4 + K4V2），更细粒度的层次化压缩是否能带来进一步收益未被验证。

4. **Long-context 评估规模有限**：LongBench 的序列长度相对于当前 128K+ 的上下文窗口仍然较短，未评估超长上下文（如 64K-128K）场景下的表现。

5. **未讨论与 prefix caching 的兼容性**：vLLM 的 prefix caching 是生产环境中的重要优化，论文未讨论差异化压缩如何与之共存（不同请求可能对同一 prefix 的 token 赋予不同重要性）。

6. **Significance score 的计算开销**：论文将计算 attention score 的开销归入"KV Compressor"但未单独量化。在 prompt 阶段需要完整的 attention score 矩阵来评估 token 重要性，这本身可能成为长 prompt 场景的瓶颈。

## 七、AI Infra / MLSys 视角

1. **差异化压缩的思路可迁移**：DiffKV 的核心洞察——KV cache 中 key 比 value 重要——是一个可广泛应用的发现。未来的 KV cache 压缩、offloading、speculation 系统都可以考虑对 key 和 value 使用不同策略。

2. **Parallel KV Compaction 的通用性**：基于 circular free page list + parallel prefix sum 的 GPU 端内存管理技术，可推广到其他需要在 GPU 上进行动态、不规则内存分配的场景（如 speculative decoding 的 token tree 管理）。

3. **Thinking model 的 KV cache 压缩是新的研究方向**：DiffKV 是首个在 thinking model（QwQ、R1-Distill）上评估的 KV cache 压缩系统。Thinking model 生成极长的 CoT，KV cache 压力远超传统 LLM，且错误会在自回归生成中累积传播。这一场景需要更精细的压缩策略。

4. **值得跟进的方向**：
   - 将差异化思路与 KV cache offloading 结合：将高精度 key 保留在 GPU，value 可 offload 到 CPU/SSD
   - 与 GQA/MLA 等新架构的协同优化：不同注意力架构下 key/value 的重要性差异可能不同
   - 训练时引入压缩感知（compression-aware training），使模型天然适应差异化量化
   - 动态精度切换的硬件支持：如果未来 GPU/NPU 原生支持 per-token 混合精度存储和计算，DiffKV 的方法将更高效

---

## 八、总结

DiffKV 通过挖掘 KV cache 中 key/value 精度差异、token 重要性层次和 per-head 动态稀疏性三个层次的差异性，实现了 2.7×-5.7× 的 KV cache 压缩和 1.9×-5.4× 的吞吐提升，且几乎不损失精度。其核心技术贡献是基于 unified page、circular free page list 和 bidirectional page table 的 GPU 端并行 KV compaction 机制，有效解决了差异化压缩带来的不规则内存管理挑战。DiffKV 特别适用于 thinking model 和长序列推理场景，是首个在这类高难度工作负载上证明近乎无损压缩可行性的系统。主要局限在于参数校准依赖离线 profiling，且未验证与 prefix caching 等生产级优化的兼容性。
