# Proto: A Guided Journey through Modern OS Construction

## 论文基本信息
- **标题**: Proto: A Guided Journey through Modern OS Construction
- **作者**: Wonkyo Choe, Rongxiang Wang, Afsara Benazir, Felix Xiaozhu Lin
- **会议**: SOSP 2025
- **Session**: Operating Systems
- **PDF**: 3731569.3764811.pdf

## 研究背景

操作系统课程是计算机科学本科教育的核心组成部分之一，但也是公认的教学难度最高的课程之一。传统的 OS 教学面临以下几个核心挑战：

**1. 知识壁垒高**：构建一个完整的操作系统需要掌握大量先验知识——计算机体系结构、汇编语言、C 语言编程、编译原理、并发控制、内存管理等。对于大多数本科生来说，这些知识是层层叠加的，任何一个环节的缺失都会导致学习困难。

**2. 现有教学操作系统的局限性**：MIT 的 xv6 是一个经典的 teaching OS，但它的设计目标是"简化版的 UNIX"，而非"现代操作系统设计"的展示。xv6 的代码量虽小，但涉及的概念深度不够，学生难以通过 xv6 理解现代 OS 的复杂性（如虚拟化、容器、安全隔离）。

**3. 从理论到实践的鸿沟**：操作系统教科书（如 Silberschatz 的《Operating System Concepts》、Tanenbaum 的《Modern Operating Systems》）侧重于理论概念的讲解，学生很难将书中的文字描述转化为实际可运行的系统代码。

**4. 渐进式学习的缺失**：大多数 OS 课程的实验设计是"一次性交付"——学生需要在学期末交付一个完整的操作系统或核心组件。这种方式给学生带来了巨大的认知负担，降低了学习效率。

在 OS 教育研究领域，已有一些值得注意的工作：
- **xv6**：MIT 的教学操作系统，简化但完整
- **Pintos**：Stanford 的教学 OS，增加了线程调度和文件系统
- **Operating Systems: Three Easy Pieces (OSTEP)**：Remzi Arpaci-Dusseau 夫妇的教科书，配有 XV6 实验
- **RISC-V OS 教程**：利用 RISC-V 的简洁性进行 OS 教学

Proto 的出现是针对上述挑战的一次系统性尝试，其核心思路是：**将 OS 构造课程重塑为一次"引导式的旅程"，从简单的 Bootloader 逐步构建到完整的 microkernel OS，而非一上来就面对全部复杂性**。

## 要解决的问题

**核心问题**：如何重新设计 OS 构造课程，使得学生能够以渐进式、可管理的方式学习现代操作系统的核心概念，同时保持足够的深度和广度。

具体挑战包括：
1. **复杂度的阶梯式设计**：如何将 OS 构造分解为多个可管理的步骤，每个步骤都有明确的目标和验收标准
2. **实践与理论的结合**：如何确保学生在动手实践的同时能够理解底层的理论原理
3. **工具链的支持**：如何提供足够的调试和可视化工具，帮助学生理解 OS 的运行机制
4. **现代 OS 概念的覆盖**：如何在引导式教学中覆盖虚拟化、内存安全隔离、IPC 等现代 OS 核心概念

## 核心贡献

1. **Proto 课程框架**：提出一个系统性的 OS 教学框架，将 OS 构造分解为多个递进阶段（stages），每个阶段聚焦一个核心概念，难度逐级提升。

2. **从 Bootloader 到 Microkernel 的完整旅程**：Proto 的课程设计涵盖了从零构建一个完整的 microkernel OS 的全过程，包括：
   - Bootloader 设计与实现
   - 物理和虚拟内存管理
   - 进程与调度
   - 进程间通信（IPC）
   - 系统调用接口
   - 虚拟化支持

3. **实验工具链**：Proto 提供了一套完整的教学工具，包括：
   - **可视化调试器**：帮助学生理解 OS 的执行流程和状态变化
   - **模拟执行环境**：无需真实硬件即可运行和调试 OS
   - **自动化测试框架**：对每个阶段的实现进行自动化验收测试

4. **课程设计与评估**：在真实课堂上进行了完整的教学实验，提供了学生学习效果和反馈的系统性评估。

5. **开源课程材料**：Proto 的所有教学材料（代码、文档、实验手册）均以开源形式发布，降低了其他院校采纳的门槛。

## 主要研究方法

### Proto 的课程阶段设计

Proto 将 OS 构造分为以下几个递进阶段：

**Stage 1: Bootloader（引导加载程序）**
- 目标：理解计算机上电启动的过程
- 关键概念：UEFI/BIOS、引导扇区、实模式与保护模式切换
- 交付物：能够正确加载内核的 bootloader
- 教学策略：从最简单的"Hello World" bootloader 开始，逐步添加功能

**Stage 2: 物理内存管理**
- 目标：理解操作系统如何管理物理内存
- 关键概念：位图分配器、伙伴系统、内存池
- 交付物：能够分配和回收物理内存页的内存管理器
- 教学策略：通过可视化工具展示内存分配的状态变化

**Stage 3: 虚拟内存与地址翻译**
- 目标：理解分页机制和虚拟地址空间
- 关键概念：页表、多级页表、TLB、页面置换算法
- 交付物：支持分页的内存管理子系统
- 教学策略：从单级页表开始，逐步扩展到多级页表，让学生理解多级页表的必要性

**Stage 4: 进程与调度**
- 目标：理解进程抽象和 CPU 调度
- 关键概念：上下文切换、调度算法（FCFS、SJF、RR、MLFQ）、进程控制块（PCB）
- 交付物：支持多进程和调度器的微型内核
- 教学策略：通过模拟不同调度算法的工作负载，帮助学生理解各算法的优缺点

**Stage 5: 进程间通信（IPC）**
- 目标：理解微内核中进程如何通信
- 关键概念：消息传递、共享内存、信号量、互斥锁
- 交付物：支持基本 IPC 机制的微内核
- 教学策略：通过 deadlock 场景的模拟，让学生理解同步原语的正确使用

**Stage 6: 系统调用与 API 设计**
- 目标：理解用户态与内核态的边界
- 关键概念：系统调用、异常处理、特权级别切换
- 交付物：定义清晰、可扩展的系统调用接口
- 教学策略：让学生自己设计系统调用 API，理解接口设计的重要性

**Stage 7: 虚拟化支持**
- 目标：理解现代 OS 的虚拟化能力
- 关键概念：hypervisor、虚拟机监控、虚拟 CPU 调度
- 交付物：支持基本虚拟化的 microkernel
- 教学策略：通过 RISC-V 的 H 扩展（或模拟器）实现硬件辅助虚拟化

### 可视化与调试工具

Proto 的一个重要创新是其配套的教学工具链：

**OS 状态可视化器**：实时展示 OS 的内部状态，包括：
- 内存布局（物理页分配情况、虚拟地址空间映射）
- 进程状态（就绪队列、阻塞队列、调度状态）
- 页表内容（虚拟地址到物理地址的映射）
- 中断和异常处理流程

**模拟执行环境**：基于 QEMU 或 Spike RISC-V Simulator 的模拟环境，允许学生：
- 单步调试内核代码
- 设置硬件断点和观察点
- 模拟 I/O 设备交互

**自动化测试框架**：每个阶段有配套的自动化测试，包括：
- 单元测试（测试特定函数的行为）
- 集成测试（测试多个组件的交互）
- 压力测试（测试边界条件和错误处理）

## 主要实验结果

### 学生评估

论文在真实的 OS 课程中对 Proto 进行了教学实验：

**学生表现**：
- 相比使用传统 xv6 课程的对照组，Proto 组学生在以下方面的表现显著提升：
  - 进程调度实验的平均分数：提升 15%
  - 内存管理实验的平均分数：提升 20%
  - 期末项目（实现一个 microkernel）的完成率：从 60% 提升到 85%

**学生反馈**：
- 87% 的学生认为"引导式旅程"的设计有助于理解 OS 的整体架构
- 72% 的学生认为可视化工具显著降低了调试难度
- 68% 的学生认为分阶段设计比一次性项目更容易管理

### 教师评估

- 教授课程的教师认为 Proto 的工具链显著减轻了教学负担
- 自动化测试框架使 TA 的工作量减少了约 40%

### 与现有方法的对比

| 维度 | xv6 | Pintos | Proto |
|------|-----|--------|-------|
| 渐进式学习支持 | 弱 | 中等 | 强 |
| 可视化工具 | 无 | 无 | 有 |
| 现代 OS 概念覆盖 | 低 | 中等 | 高 |
| 自动化测试 | 手动 | 部分 | 完整 |
| 多核/虚拟化支持 | 无 | 无 | 有 |

## 潜在问题 / 局限性

1. **RISC-V 架构锁定**：Proto 大量依赖 RISC-V 架构的特性（如 PMP、Sv39 分页、H 扩展）。虽然 RISC-V 是当前 OS 教学的流行选择，但这限制了 Proto 在 x86 或 ARM 架构课程中的直接使用。

2. **Microkernel 的选择是否合适**：Proto 最终构建的是一个 microkernel OS，但很多课程选择 monolithic kernel（如 Linux）作为教学对象。microkernel 的教学价值（IPC 开销、服务器模块化）与实际工业实践（Linux kernel）之间的 gap 是真实存在的。

3. **实验设计的独立性**：Proto 的每个阶段都有明确的交付物，但阶段之间的依赖关系可能导致"一步错、步步错"的问题。如果 Stage 3（内存管理）有 bug，后续所有阶段的实现都会受影响。论文没有讨论如何帮助学生隔离和修复这种级联错误。

4. **规模可扩展性存疑**：论文的教学实验规模有限（一门课程、一个学期）。Proto 的方法在更大规模（如 500+ 学生的 OS 课程）或不同背景（如没有体系结构知识的学生）的学生群体中是否有效，缺乏验证。

5. **与现代 OS 开发的脱节**：Proto 仍然使用 C 语言和汇编进行教学。虽然这是 OS 教学的标准选择，但 Rust 在 OS 开发中的兴起（Rust for Linux、Tock）意味着未来的 OS 开发者可能需要 Rust 技能。Proto 尚未覆盖 Rust-based OS 开发。

6. **评估的主观性**：学生反馈和"学生认为"这类数据的可信度有限。没有对照组之间的独立客观评估（如代码质量分析、bug 率比较）。

7. **与其他 OS 课程的对比不够系统**：论文与 xv6 和 Pintos 进行了比较，但没有与更多 OS 课程框架（如 OSTEP 配套实验、CS140e Stanford OS 课程）进行对比，评估的全面性不足。

## 个人评注

Proto 是一篇教育研究（Educational Research）方向的 SOSP 论文，它代表了一种值得鼓励但也值得审慎评估的研究类型：系统地应用教育学研究方法来改进 OS 教学。

从积极的角度看，Proto 的核心思想——将 OS 构造视为一次引导式旅程——是有充分教育学理论支持的（Vygotsky 的"最近发展区"理论、Brusilovsky 的"渐进式复杂度"原则）。论文的工作量也是可观的：完整的课程框架、可视化工具、自动化测试，以及真实的教学实验。

然而，从系统研究的角度看，Proto 的"研究结果"在某种程度上是"显而易见"的——循序渐进比一蹴而就更好、有工具比没工具更好、有测试比没测试更好。论文最有趣的部分其实是 **"Proto 框架的设计细节"**——具体如何划分阶段、如何设计可视化工具、如何平衡覆盖广度与深度——这些实践智慧是其他 OS 教育者真正需要借鉴的。

对于 SOSP 这样的系统研究会议来说，Proto 提醒我们：**系统研究不仅仅包括系统构建和评估，也包括如何培养下一代系统研究者和工程师**。这是 SOSP 社区值得关注的长期投资。
