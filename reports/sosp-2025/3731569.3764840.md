# Tempo: Compiled Dynamic Deep Learning with Symbolic Dependence Graphs

**作者**：Pedro F. Silvestre, Peter Pietzuch（Imperial College London）
**会议**：SOSP 2025（ACM SIGOPS 31st Symposium on Operating Systems Principles）
**链接**：https://doi.org/10.1145/3731569.3764840
**源文件**：[3731569.3764840.pdf](../../papers/sosp-2025/3731569.3764840.pdf)

---

## 一、背景

深度学习算法的计算常常涉及时间维度上的动态依赖关系（dynamic dependencies）：一个时间步上的 tensor 可能依赖于之前或之后多个时间步的 tensor。例如，LLM 推理中的 causal attention 在每个时间步 t 需要访问所有之前的 key/value 对（依赖模式为 `[0:t+1]`）；强化学习（RL）中的 loss 计算则需要访问未来的 reward（anti-causal 依赖）。

当前 DL 系统在处理这类动态依赖时面临根本性困难：eager 系统（如 PyTorch）能表达动态性但无法做编译优化；graph-based 系统（如 JAX、TensorFlow）能做 ahead-of-time 编译优化，但要求静态的 tensor shape，无法直接表达动态依赖。

---

## 二、要解决的问题

1. **表达力不足**：现有 graph 表示（JAX 的 while 循环、TF 的控制流算子）不能直接表达动态依赖，用户被迫采用 padding+masking（引入计算和内存开销）、逐 shape 编译（编译开销大）、或静态展开循环（图爆炸）等变通方案。

2. **无法做全程序优化**：动态依赖打破了 whole-program compilation 的前提条件，错失代数化简、向量化等优化机会。

3. **调度困难**：future dependency 导致无法用简单的拓扑排序确定执行顺序。

4. **内存管理复杂**：对过去时间步的依赖导致复杂的 tensor 保留/释放/换出决策。在 RL 中，actor-learner 解耦架构将动态依赖粗化为 `[0:T]`，导致冗余计算（forward pass 做两次）、无法并行 acting 和 learning、以及 peak memory 过高。

---

## 三、洞察与设计

**关键洞察**：动态 DL 算法中的 tensor 具有隐含的时间维度（temporal dimensions）。将这些时间维度显式化后，动态依赖就变成了在时间维度上的常规 tensor 索引操作，且这种动态性具有可用符号表达式（symbolic expressions）简洁描述的结构。

基于此洞察，Tempo 的设计包含四个核心组件：

**1. Recurrent Tensors (RTs) 编程模型**：在 tensor 的空间维度之外引入显式的时间维度（如 timestep t、iteration i）。RT 通过符号表达式索引时间维度来声明式地表达动态依赖，例如 `x[0:t+1]` 表示 causal 依赖，`r[t:T]` 表示 anti-causal 依赖。RT 支持自动 domain 推断、domain broadcast 和符号化自动微分（通过对依赖表达式求逆来累积梯度）。

**2. Symbolic Dependence Graph (SDG)**：将 RT 程序转换为 SDG——一种有向图，其中每个算子带有时间域 Ω，边上标注依赖表达式 φ。SDG 上可做：
- **Lifting**：识别并消除 MergeOp 实现的 recurrent pattern（如累加变 cumsum），减少冗余计算
- **Vectorization**：将时间维度铺展为空间维度，增加 SIMD 并行度
- **Tiling**：将动态依赖分解为固定大小的静态 tile，使动态计算变为"动态数量的静态 tile"，实现代码生成
- **Fusion**：合并具有相同域和仅 identity 边的静态 island 为单个 DataflowOp

**3. Polyhedral 调度**：利用多面体模型将 SDG 转化为整数线性规划（ILP），为每个算子的每个时间步找到合法的物理执行时间。调度同时处理内存管理操作（deallocation、GPU/CPU swap、buffer donation），通过在 SDG 中添加带约束的内存管理节点来实现。

**4. 运行时执行**：编译生成命令式 AST（包含 loop、if、execute、deallocate/load/evict 语句），运行时解释执行，同时支持 Torch 和 JAX 作为后端进行 kernel 代码生成。

## 四、实现细节

- 核心代码约 33K Python LoC，开源于 https://github.com/LSDS/Tempo
- 支持 44 种无状态算子（elementwise、reduction、scan、view、indexing 等），用 MergeOp 编码条件分支和状态（如 DNN 参数通过 MergeOp 环路表达迭代更新）
- **Tensor store 策略**：根据 RT 的访问模式选择不同存储方式：
  - Point store：适用于状态传递模式（如 RNN），直接映射 timestep 到物理 tensor
  - Block store：适用于 causal/anti-causal 访问，预分配大小为 T 的 buffer
  - Window store：适用于窗口访问，使用 2 倍窗口大小的循环 buffer，双镜像写入保证连续读取
- **Kernel wrappers**：通过 in-place writes 和 lazy reads 包装避免不必要的拷贝
- 依赖表达式求逆规则：`[t+3]` → `[t-3]`，`[max(0,t-3):t+1]` → `[t:min(t+4,T)]`，`[t:T]` → `[0:t+1]`
- 静态 tiling 中对最后一个不满的 tile 添加 padding 和相应 mask（0 for MatMul/Sum，-∞ for Max）
- Polyhedral 调度使用 isl 库和 Pluto 调度器，编译时间约 18 秒（其中 ILP 求解仅 2 秒，因为 fusion 大幅减少了算子数量）

## 五、实验结果

**实验平台**：AMD EPYC 7402P 24 核 CPU，384GB DDR4，NVIDIA RTX A6000 GPU（48GB），Ubuntu 22.04，CUDA 12.8。

### LLM 解码（Llama-3.2-3B）

| 场景 | 对比系统 | Tempo 加速比 |
|------|---------|-------------|
| Causal attention, B=16, T=16384 | vs JAX | 1.43× |
| Causal attention, B=4, T=32768 | vs JAX | 2× |
| Causal attention, B=4, T=65536 | vs JAX | 2.5× |
| Window attention, B=16, T=16384 | vs JAX | 7× |
| Window attention, B=16 | vs Torch | 最高 3.9× |

- Window attention 下 Tempo 是唯一能自动适配 K/V cache 释放策略的系统，可解码至少 4× 更长的序列
- JAX 的 padding 开销随 T 线性增长；Tempo 通过 tiling 将增长分摊

### RL 训练（PPO / REINFORCE）

| 指标 | 数值 |
|------|------|
| vs RLlib | 最高 54× 加速 |
| vs CleanRL（次快基线） | 平均 2.6× 加速 |
| Peak GPU memory | 最高 16× 降低 |
| 大观测尺寸（3×256×256） | 其他框架 OOM，Tempo 通过 tiling+swapping 正常运行 |

- Tempo 消除了 actor-learner 解耦带来的冗余前向传播，通过缓存 actor activations 复用于 learner
- 对于 n-step TD return，Tempo 自动发现可在延迟 n 步后并行化 acting 和 learning

### 编译可扩展性

- 编译时间约 18 秒，不随模型层数增加而显著变化（利用层间重复结构将模型编码为带 layer 时间维度的小 SDG）

## 六、批判性分析

1. **单 GPU 限制严重**：Tempo 目前仅支持单 GPU 执行。论文在 Discussion 中描述了通过 tiling 实现数据/流水线/模型并行的可能路径，但这纯属未来工作，远非简单扩展。实际 LLM 推理和 RL 训练几乎总是多 GPU 场景，这极大限制了系统的实际适用性。

2. **不支持 FlashAttention 等优化 kernel**：论文承认无法集成 FlashAttention，因其复杂语义阻碍了 Tempo 的变换（vectorization、tiling 等）。这意味着在真实 LLM 推理场景中，Tempo 的 attention 实现性能远不及使用 FlashAttention 的生产系统（如 vLLM、SGLang），而这些正是论文声称要改进的目标。实验中与 naive Torch/JAX 比较并不反映真实竞争格局。

3. **RL 实验的基线选择有偏**：54× 的最大加速比是对比 RLlib（一个以分布式扩展而非单机性能见长的框架），且使用的是极短仿真步长的 toy 环境。CleanRL 作为更公平的基线，Tempo 仅快 2.6×。论文未与 JAX 原生的高性能 RL 实现（如 PureJaxRL）对比。

4. **不支持动态终止**：Tempo 要求时间维度的上界 T 在编译时已知，不支持运行时动态终止（如 LLM 的 EOS token）。这是一个在实际部署中必须解决的问题，但论文仅以"未来工作"一笔带过。

5. **Tiling 策略需人工设定**：静态 tile size 由用户指定，论文自己的实验（Fig.18）显示 tile size 对性能影响显著（可差数倍），但缺乏自动选择机制。

6. **Python AST 解释器的开销**：论文实验中观察到增加 hidden layers 时 Tempo 性能下降更快（Fig.20c），作者归因于 Python 级 AST 解释开销，并建议用 C++ 实现。这说明当前实现在 kernel 执行时间较短时存在显著的调度开销。

## 七、AI Infra / MLSys 视角

**启发与借鉴价值**：

1. **"时间维度显式化"的抽象视角**：将动态依赖视为 tensor 时间维度上的索引操作，这一抽象具有普遍性。当前 KV cache 管理、gradient accumulation、pipeline parallelism 等 AI Infra 问题本质上都是时间维度上的资源调度问题，Tempo 的形式化方法提供了统一分析框架。

2. **SDG 对 KV cache 策略的启示**：vLLM 等系统为每种 attention 类型手工实现 cache 策略，而 Tempo 通过 SDG 的依赖表达式自动推导出 cache 保留/释放策略（causal → 全保留，window → 循环释放）。这一思路可迁移到 serving 系统的 KV cache 管理中，尤其是面对 hybrid attention（混合 causal、window、linear 等）模型时。

3. **Polyhedral model 在 DL 系统中的新用法**：以往 polyhedral model 用于 kernel 级优化（如 Tiramisu、Tensor Comprehensions），Tempo 首次将其用于 whole-program 执行调度和内存管理。这为分布式训练的自动化调度（如 pipeline schedule 生成）提供了新的方法论参考。

**值得跟进的方向**：

- **将 SDG 形式化应用于 serving 系统的自动化 memory planning**：给定 attention pattern 描述，自动生成最优的 KV cache 管理策略和 prefill/decode 调度
- **结合 FlashAttention 的 Tempo 扩展**：如何在保留 SDG 优化能力的同时集成高性能 kernel，可能需要引入"opaque operator"抽象
- **将 tiling + polyhedral scheduling 应用于 RL 训练的 pipeline 化**：Tempo 已展示 n-step TD 的自动 acting-learning 并行化，这可推广到更复杂的 RLHF pipeline（如 PPO 中的 reward model + critic + actor 的交错调度）

---

## 八、总结

Tempo 提出了一种新的 DL 编程和编译系统，通过 recurrent tensor 编程模型将动态依赖显式化为时间维度上的符号索引，构建 symbolic dependence graph 实现全程序优化（lifting、vectorization、tiling、fusion），并利用 polyhedral model 完成执行调度和自动内存管理。在 LLM 解码（vs JAX 最高 7× 加速）和 RL 训练（vs 基线最高 54× 加速、16× 内存降低）上展示了显著效果。但系统目前仅限单 GPU、不支持 FlashAttention 和动态终止，距离生产级部署还有较大差距。其核心贡献在于提出了一个优雅的形式化框架来统一表达和优化动态 DL 计算，对 AI Infra 研究具有方法论参考价值。
