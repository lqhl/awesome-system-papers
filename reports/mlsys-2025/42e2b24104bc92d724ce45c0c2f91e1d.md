# PROTORAIL: A Risk-Cognizant Imitation Agent for Adaptive vCPU Oversubscription in the Cloud

## 一、背景

云服务提供商普遍采用 Oversubscription（超额订阅）策略来提升资源利用率——即向用户分配的虚拟资源总量超过实际物理容量，利用用户不会同时满载的统计规律来减少闲置浪费。vCPU 作为云服务的主要计费单元，其超额订阅策略直接影响收入和用户体验。然而，现有策略大多基于运维经验或静态启发式规则，无法适应负载的动态变化，容易造成灾难性过载或资源浪费。

---

## 二、要解决的问题

1. **收益与风险的矛盾**：激进的超额订阅策略能提高 VM 密度和收益，但会引发节点过载（hot node），导致用户性能下降和赔偿损失；保守策略则造成大量资源闲置。
2. **负载模式的动态性**：不同时间段、不同用户/服务的 CPU 使用模式差异巨大，静态策略无法适应。
3. **策略粒度问题**：超额订阅需要在不同粒度（单 VM、用户、用户组）上制定策略，需求模式随粒度变化。
4. **无法在线训练**：不能在生产云系统上直接进行在线 RL 训练；传统 RL 也难以同时优化收益和风险这两个竞争目标。

---

## 三、洞察与设计

**关键洞察**：不同 VM/服务的 CPU 使用轨迹存在近似对称性（approximate symmetries），即可以被聚类为少数几个等价类（prototypes），每个等价类代表一类典型的负载模式。基于最近原型的策略估计，可以实现对任意粒度的自适应超额订阅。

基于此洞察，PROTORAIL 将超额订阅问题建模为 **Prototypical Imitation Learning** 问题，核心设计包含三个组件：

1. **Prototype Discovery**：从历史 CPU 使用轨迹中学习 K 个原型嵌入，通过三个目标联合优化——代表性（L_rep，最小化轨迹到最近原型的距离）、多样性（L_div，最大化原型间距离）、可解释性（L_int，将原型绑定到真实轨迹实例）。

2. **Imitation Learning over Prototypes**：策略层根据当前轨迹嵌入与各原型的相似度来决定超额订阅率。支持 Behavior Cloning 和 Adversarial IL 两种基础模型。策略等价于一个二次模型，具有单调分段性质，增强了可解释性。

3. **Knowledge-in-the-Loop (KITL)**：通过主动学习框架向领域专家（或 LLM）查询反馈，精炼原型和策略。查询策略基于原型不确定性和动作风险，使用 Advice Potential Gates（指数形式的反馈权重）来调节损失函数，实现去风险化。

---

## 四、实现细节

- **轨迹编码器**：使用序列编码器（LSTM 或 Transformer）将历史使用轨迹映射为嵌入向量 h = f(τ_t)
- **原型层**：维护 K 个原型嵌入 P = {p_1, ..., p_K}，使用 L2 距离度量相似性
- **策略层**：线性层 + sigmoid 激活，输入为轨迹嵌入与各原型的相似度向量
- **KITL 查询框架**：根据原型聚类熵和动作不确定性选择查询点；反馈形式包括 up/down vote、merge/split 原型；反馈通过指数 Advice Potential Gate Φ(x) = e^{-G(F(x))} 缩放损失
- **KITL 配置**：查询频率默认每 10 个训练迭代，不确定性阈值默认 0.8，实际实验中平均仅需 6-8 次查询
- **分配模拟器**：使用 Best-Fit 分配策略模拟 VM 到节点的放置过程

## 六、批判性分析

1. **评估规模有限**：实际部署仅报告了 2 个 region 的观测数据（而非全部 300 个集群），且仅覆盖 Microsoft 内部（1st party）服务，未在面向外部客户的生产环境验证。内部服务的负载模式可能远比真实客户负载简单和可预测。

2. **模拟器与真实系统的 gap**：离线评估依赖简化的 Best-Fit 分配模拟器，而真实云平台的调度和分配策略远更复杂。模拟器可能系统性地低估了过载风险。

3. **基线公平性存疑**：DDPG 直接用于多目标优化表现极差，但未尝试更成熟的多目标 RL 方法（如 constrained RL、Lagrangian 方法）。DAgger 仅使用 20 步人工指导，而 PROTORAIL 的 KITL 在训练过程中持续提供更丰富的反馈，对比不够公平。

4. **KITL 可扩展性未讨论**：每次训练需要 6-8 次人工查询看似不多，但如果需要为不同服务/region/时间段分别训练模型，人工成本可能迅速累积。论文未讨论模型的迁移能力。

5. **机票数据集的说服力不足**：COVID-19 导致数据分布剧变，作者自己也承认 "airline ticket data does not show a clear pattern"。在这样的数据上取得的好结果可能不具有普遍意义。

6. **"0% hot node" 的解读**：Grid-search（最保守策略）也能达到 0% hot node，这说明 0% 风险本身并不难——真正的问题是在低风险下能获得多少收益。PROTORAIL 的 core benefit 相比 grid-search 提升约 9.5%，相比 Moving Average 提升约 7%，改进幅度较为温和。

7. **LLM 作为 κ 的实验不充分**：仅使用 Llama-3.1-70B zero-shot，风险缓解能力仅 46%（vs 人类 100%），便匆匆下结论说 "LLM 还不够好"。未尝试 GPT-4 级别模型或 few-shot/fine-tuned 方案。

---

## 七、AI Infra / MLSys 视角

1. **Prototype-based IL 的通用性**：论文提出的原型发现 + 模仿学习框架不限于超额订阅场景，可推广到任何需要从历史遥测数据中学习自适应资源管理策略的场景，如 GPU 显存分配、推理请求调度、auto-scaling 等。

2. **Human-in-the-loop 去风险化**：KITL 模块提供了一种低成本的人类反馈集成方式（仅需 6-8 次查询），对 AI Infra 中的安全关键决策（如 SLO 保障、故障恢复策略）有借鉴价值。

3. **可探索的 Future Work**：
   - 将 PROTORAIL 应用于 GPU/NPU 超额订阅（如推理场景中的 GPU 显存 overcommit）
   - 用 fine-tuned LLM 替代人类专家作为 KITL 的知识源，降低部署门槛
   - 探索原型的在线自适应更新机制，应对负载分布的长期漂移

4. **局限性启示**：论文仅在内部服务上验证，暗示了对外部多租户、高异质性负载的泛化可能是一个开放问题——这本身是一个有价值的研究方向。

---

## 八、总结

PROTORAIL 提出了一种基于原型的模仿学习框架，通过发现 CPU 使用轨迹中的近似对称模式（prototypes），结合主动知识反馈（KITL）去风险化，实现了云平台 vCPU 超额订阅的自适应策略学习。在 Microsoft 内部云部署中实现了 9.4% 的利用率提升和 0% hot node 率。主要局限在于验证规模有限（仅内部服务、2 个 region）、模拟器与真实系统存在 gap、以及 LLM 替代人类专家的方案尚不成熟。
