## 1. 研究背景与动机

大语言模型（LLM）现已支持极长上下文窗口（如 Gemini、Claude 和 Kimi 支持超过 100 万 tokens 的上下文长度），但注意力机制的二次复杂度导致长上下文推理的 Prefilling 延迟极高。例如，在 100 万 token 的上下文中，ChatGLM3-6B 的注意力计算耗时 1555 秒，占 TTFT（Time-to-First-Token）的 90% 以上，使得实时交互几乎不可行。

现有稀疏注意力方法可分为两类：
1. **静态稀疏模式**（如 LongFormer、BigBird、StreamingLLM）：预设固定稀疏模式，无法捕捉跨 head 和输入的动态稀疏模式，准确性损失较大。
2. **动态稀疏模式**（如 MInference、HyperAttention）：运行时选择重要索引，但要么依赖预定义的固定模式/稀疏度预算，要么粗粒度的选择方法难以维持模型准确性。

## 2. 研究问题与核心挑战

本文揭示了长上下文 LLM 注意力中两个关键特性：

### C#1: 自适应稀疏比率
注意力稀疏度在三个维度上呈现自适应特性：
- **Head 级别**：同一层内不同 head 的稀疏度差异极大（低至 27.4%，高达 99.8%）
- **内容级别**：不同输入提示和上下文长度具有不同稀疏度；上下文越长，稀疏度越高
- **模型级别**：不同模型表现出不同的稀疏度特征

### C#2: 动态稀疏模式
注意力模式在 head、输入和模型架构之间存在显著差异，可归纳为两类主要模式：
- **Column 模式**：捕捉全局上下文信息（如 attention sinks）
- **Slash 模式**：保持规则间隔上下文之间的连接（如局部窗口模式）
- 两者可以组合形成复杂的混合模式

这意味着使用固定稀疏度预算和预定义模式难以达到最优的准确率-效率权衡。

## 3. 主要贡献

1. **Cumulative Residual Attention (CRA) 指标**：提出了一种衡量注意力召回率的鲁棒指标，与模型准确性高度正相关，可用于指导运行时稀疏度选择。
2. **两阶段 Query-Guided 稀疏注意力框架**：第一阶段通过分块采样估计完整注意力分数；第二阶段基于采样分数过滤关键 KV 块。
3. **自适应列+斜向模式选择**：动态识别并选择重要的列和斜向 strips，无需预定义模式。
4. **近无损准确率-效率帕累托前沿**：在 GLM4-9B、YI-9B 和 InternLM2-7B 上均建立了新的准确率-效率帕累托前沿，TTFT 相比 FlashAttention2 最高降低 5.29 倍。

## 4. 核心方法与设计

### 4.1 Cumulative Residual Attention (CRA)

CRA 定义为剪枝后每个 query 剩余注意力概率的最小总和：
$$\text{CRA} = 1 - \max_j \sum_i P_{i,j}$$

实验证明，CRA 与模型准确性存在一致的强正相关关系：随着 CRA 阈值增加，模型准确性单调提升。这一关系在不同 LLM 和任务间保持一致，使得 CRA 成为指导运行时稀疏度选择的可靠指标。

### 4.2 第一阶段：Query-Guided 分块注意力采样

现有方法（如 MInference）仅使用最后一个 query 块来估计注意力分数，这不足以捕捉复杂的列+斜向混合模式。SampleAttention 将 query 序列划分为 $n_{chunk}$ 个等大小的块，对每个块分别进行注意力采样，使估计覆盖整个注意力矩阵。

采样时计算每个 query 块底部与所有 key 之间的注意力分数，然后在块粒度（$blk=128$）上沿列和斜向方向对分数进行归约，得到块级别的分数。

### 4.3 第二阶段：基于分数的 KV 过滤

Naive 联合选择列和斜向 strips 需要评估 $n_{col} \times n_{slash}$ 种组合，计算开销极大。为提高效率，将单一阈值 $\alpha$ 分解为：
- $\alpha_c$：列方向的阈值
- $\alpha_s$：斜向的阈值

分解后的计算复杂度从 $O(n_{col} \times n_{slash})$ 降低到 $O(n_{col} + n_{slash})$。

对于每个采样块，首先沿列和斜向方向累积注意力分数得到块级分数，然后对每个方向分别应用 top-k 选择：选择使累积分数满足阈值的最小 strips 数。最后将各采样块获得的索引沿各自方向扩展并合并为最终的稀疏掩码。

### 4.4 硬件高效实现

与 FlashAttention 的块稀疏变体兼容，利用 FlashAttention 的底层 tiling 机制实现高效的稀疏计算。

## 5. 实验设置

**Backbones**：ChatGLM4-9B（1M 上下文）、YI-9B（200K 上下文）、InternLM2-7B（200K 上下文）

**基准方法**：FullAttention(FlashAttention2)、MInference、BigBird、StreamingLLM、HyperAttention

**任务**：RULER（综合长上下文基准）、LongBench（多任务长上下文）、InfiniteBench（长序列基准）

**评估设置**：仅替换 Prefilling 阶段的完整注意力实现，保持 KV Cache 不压缩、解码阶段使用密集注意力。

## 6. 实验结果

### 6.1 RULER 基准

SampleAttention 在 GLM4-9B、YI-9B 和 InternLM2-7B 上均建立了新的帕累托前沿。相比 MInference：
- 在 GLM4-9B（32K）：准确性相当，但 SampleAttention 提供 1.24×-2.36× 加速，MInference 几乎没有加速
- 在 YI-9B（128K）：SampleAttention 准确性显著优于 MInference，同时保持加速优势
- 最高 TTFT 降低：5.29×（相比 FlashAttention2）

### 6.2 LongBench 和 InfiniteBench

**LongBench（GLM4-9B）**：SampleAttention 总分 1135.93（略高于 FullAttention 1124.04），优于 MInference（1126.22）和其他基线。

**InfiniteBench（GLM4-9B）**：SampleAttention 在多个子任务上表现与 FullAttention 相当或更优，特别是 Code.Debug（28.30 vs 28.30）、PassKey（100 vs 100）、Number KV（49.6 vs 44.0）。

### 6.3 超参数敏感性分析

- CRA 阈值 $\alpha_c$ 和 $\alpha_s$ 在模型和序列长度间需要分别调优
- 采样块数量 $n_{chunk}$：较小的采样数可能无法捕捉完整的稀疏结构，过多则增加开销
- 调优策略：使用 RULER 的子集调优后泛化到其他任务，表现出良好的跨任务适应能力

## 7. 潜在问题与局限性

1. **仅优化 Prefilling 阶段**：Decoding 阶段的 KV Cache 仍然完整存储和访问，未做进一步优化。对于超长输出序列，优化空间可能有限。
2. **超参数调优成本**：$\alpha_c$、$\alpha_s$ 和 $n_{chunk}$ 三个超参数需要离线调优，在新模型/新场景上部署有一定工程成本。
3. **块粒度固定**：使用固定的 128 tokens 块粒度，在不同模型和序列长度上可能存在更优的块大小。
4. **跨架构泛化性**：论文仅测试了三个模型家族，在更不同的架构（如 Mixtral 等 MoE 模型）上的效果未知。
5. **与量化结合**：未探索与 KV Cache 量化（如 W4A8）结合时的性能影响。
6. **采样开销被低估**：两阶段采样过程本身需要额外的计算，该开销未在论文中充分量化。

## 9. 个人评注

SampleAttention 是一项深入分析注意力稀疏性本质规律的工作。其最重要的贡献不在于提出了多么新颖的稀疏模式，而在于揭示了一个关键洞察：注意力稀疏度是自适应的（跨 head、跨内容、跨模型），且存在一个与模型准确性高度相关的指标（CRA）可以指导运行时决策。

两阶段方法的设计体现了很好的工程直觉：
- 第一阶段的分块采样解决了 MInference 单点采样无法捕捉复杂混合模式的问题
- 第二阶段的阈值分解将 $O(n_{col} \times n_{slash})$ 降到 $O(n_{col} + n_{slash})$，是典型的计算复杂度优化

不过，论文对一些关键细节着墨不够：两阶段采样的实际计算开销相对于密集注意力的节省究竟有多大？块粒度 128 是如何选择的？此外，5.29× 的峰值加速是在特定设置下获得的，读者需要关注平均加速水平。

总体而言，这是一篇方法创新和实验验证都比较充分的工作，为长上下文 LLM 推理的稀疏注意力优化提供了新的视角。
