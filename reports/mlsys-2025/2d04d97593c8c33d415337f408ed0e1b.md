# SampleAttention: Near-Lossless Acceleration of Long Context LLM Inference with Adaptive Structured Sparse Attention

**作者**：Qianchao Zhu* (Peking University), Jiangfei Duan* (The Chinese University of Hong Kong), Chang Chen, Xiuhong Li, Siran Liu, Guanyu Feng (Zhipu.AI), Xin Lv (Zhipu.AI), Chuanfu Xiao, Dahua Lin (CUHK), Chao Yang (Peking University)

## 一、背景

大语言模型（LLM）的上下文窗口已扩展至百万 token 级别（如 Gemini、Claude、Kimi），但 vanilla attention 的二次复杂度导致 prefill 阶段的 Time-to-First-Token（TTFT）延迟极高。例如，ChatGLM3-6B 处理 1M token 的 attention 计算需要 1555 秒，占 TTFT 的 90% 以上。这使得长上下文 LLM 的实时交互面临严峻挑战。

已有研究表明 attention score 矩阵具有高度稀疏性（平均稀疏率超过 89.6%），sparse attention 成为加速 prefill 的主要方向。现有方法包括静态稀疏模式（BigBird、LongFormer、StreamingLLM）和动态稀疏方法（MInference、HyperAttention、DSA）。

---

## 二、要解决的问题

现有 sparse attention 方法存在两个核心缺陷：

1. **固定稀疏率（Fixed Sparsity Ratio）**：MInference、DuoAttention 等方法为所有 attention head 预设统一的稀疏预算，但实际稀疏率在不同 head、不同输入内容、不同模型架构之间差异巨大（同一层内最低 27.4%、最高 99.8%）。固定预算无法同时兼顾效率和精度。

2. **静态稀疏模式（Static Sparse Pattern）**：BigBird 等使用预定义的 window/global pattern；MInference 虽然识别了 column 和 slash 两种模式，但将每个 head 离线分类为固定类型（A-shape、Vertical-Slash、Block-Sparse），无法捕获 content-dependent 的模式变化。实际中同一个 head 在不同输入下表现出截然不同的稀疏结构。

---

## 三、洞察与设计

**关键洞察**：Cumulative Residual Attention（CRA）——即稀疏化后每个 query 的剩余 attention 概率之和的最小值——是模型精度的鲁棒指标。CRA 阈值与模型精度之间存在一致的正相关关系，且这种关系跨模型、跨任务稳定成立。因此，可以用 CRA 阈值作为运行时动态决定稀疏率和稀疏模式的统一准则。

进一步的观察：attention 矩阵的重要元素主要集中在 **column stripe**（列条纹，代表全局上下文信息，如 attention sink）和 **slash stripe**（斜条纹，代表局部窗口信息）两种结构化模式中。选择少量关键的 column 和 slash strip 即可精确逼近完整的 CRA。

基于上述洞察，SampleAttention 采用两阶段 query-guided key-value filtering：

- **Stage 1: Query-Guided Chunked Sampling**：将 query 序列等间距划分为 chunk_n 个块，对每个块底部的 query block 计算精确 attention score，然后沿 column 和 slash 方向做 block 级别归约。与 MInference 仅采样最后几个 query 不同，chunked sampling 能捕获 attention 矩阵不同区域的模式变化（如某些 head 上半部分有强 column pattern 但下半部分逐渐消失）。

- **Stage 2: Score-Based Key-Value Filtering**：基于 Stage 1 得到的 block-level score，独立在 column 和 slash 方向上用各自的 CRA 阈值（α_c, α_s）通过 cumulative sum + top-k 选出满足阈值的最小 block 集合。将两个方向的 index 合并为最终的 sparse mask Mˆ，用于 sparse FlashAttention 计算。

这种设计将联合搜索 n_column × n_slash 的复杂度降低为 n_column + n_slash。

---

## 四、实现细节

- **采样开销优化**：Stage 1 中的小算子（bmm、mask_fill、softmax、reduction）通过 operator fusion 减少 IO 开销。
- **Sparse FlashAttention kernel**：基于 FlashAttention2 修改实现自适应结构化 sparse attention kernel，支持 block-level 的 column + slash 混合 mask。
- **Block 粒度**：block size (blk) 设为 128，与 FlashAttention2 的 tile size 对齐。
- **超参数**：三个关键超参——α_c（column CRA 阈值）、α_s（slash CRA 阈值）、chunk_n（采样块数）。通过小规模 RULER 数据集离线自动调优，按序列长度区间分段调参。
- **长序列支持**：序列长度超过 256K 时，将输入分 chunk 并按 head 分区处理 attention，进一步通过 operator fusion 减少中间结果。
- **与 KV cache 压缩正交**：SampleAttention 仅加速 prefill 阶段的 attention 计算，decoding 阶段保留完整 KV cache 和 dense attention，可与 H2O、SnapKV 等 KV cache eviction 方法组合使用。

---

## 五、实验结果

**实验平台**：单张 NVIDIA A100 (80GB)，评估 prefill 阶段 attention 性能。

**模型**：ChatGLM4-9B (1M context)、YI-9B (200K context)、InternLM2-7B (200K context)。

**Benchmark**：RULER（13 个长上下文任务）、LongBench（4K-35K）、InfiniteBench（平均 200K+）。

| 指标 | 结果 |
|------|------|
| 精度保持 | 在所有 benchmark 上一致保持 Full Attention 99%+ 的精度 |
| TTFT 加速 (vs FlashAttention2) | 32K: 1.15×, 64K: 1.60×, 128K: 1.95×, 256K: 2.86×, 512K: 3.94×, 1M: 5.29× |
| vs MInference (RULER) | 在 32K/64K 下 MInference 无加速但精度相当；在 128K 下 SampleAttention 精度和速度均优 |
| LongBench (GLM4-9B) | SampleAttention 1135.93 vs Full Attention 1124.04 vs MInference 1126.22 |
| InfiniteBench | PassKey/Number Retrieval 满分，其他任务与 Full Attention 相当或略优 |

**采样开销**：随序列增长，sampling 占比递减（128K 时约 21.6%，1M 时更低），加速效果在长序列下更显著。

**超参敏感性**：chunk_n=2 通常是精度-效率的最佳平衡点；α_c 和 α_s 设为 0.90-0.95 区间效果较好，不同模型对 column 和 slash 阈值的敏感度不同。

## 六、批判性分析

1. **加速倍数跨度过大**：报告的 speedup 从 1.15×（32K）到 5.29×（1M），但 32K 是实际应用中最常见的长度区间，此时几乎没有加速效果。论文标题和摘要突出 5.29× 的数字，但这只在极端序列长度下才能实现，且此时需要额外的 chunk 分区策略，实际部署场景有限。

2. **单 GPU 实验的局限性**：所有实验在单张 A100 上完成，batch size 固定为 1。实际生产环境中 prefill 通常会跨多 GPU 做 tensor/sequence parallelism，且 batch size > 1，此时 sampling 和 index construction 的开销占比可能不同。论文未讨论多 GPU 或 batched 场景下的表现。

3. **decoding 阶段的兼容性存疑**：论文明确表示 decoding 阶段保留完整 KV cache 和 dense attention，声称与 KV cache eviction 方法"正交可组合"，但未提供任何组合实验。实际上 sparse prefill 选出的 attention pattern 与 decoding 时的 KV cache eviction 策略是否冲突，需要验证。

4. **超参调优的实用性**：需要为每个模型、每个长度区间离线调参，使用 RULER 子集作为调优数据。虽然声称跨任务 robust，但仅在 3 个 benchmark 上验证了交叉泛化性。如果部署到新模型或新版本，需要重新调参，增加了工程负担。

5. **与 MInference 的对比不够公平**：MInference 使用预定义的 fixed ratio，论文指出这是其局限性。但 SampleAttention 也需要离线调优 α_c、α_s、chunk_n，两者的调优成本对比缺失。MInference 在 32K/64K 下"无加速"可能是因为其设置不同，而非方法本质劣势。

6. **精度指标的选择**：使用 "99% of full attention accuracy" 作为 near-lossless 标准（引用 MLPerf），但在某些对精度敏感的任务（如 code completion、math reasoning）上，1% 的精度损失可能是不可接受的。论文在 InfiniteBench 的 Math.Find 任务上精度从 12.17 提升到 16.52，这种波动说明稀疏化的影响可能在特定任务上不稳定。

## 七、AI Infra / MLSys 视角

1. **CRA 作为统一精度指标的启发**：CRA 提供了一种将"稀疏率"和"精度"解耦的思路——不再手工设定固定稀疏率，而是以注意力召回率为目标动态决定稀疏程度。这种思路可以推广到其他需要精度-效率权衡的场景，如 KV cache quantization 的量化位宽选择、speculative decoding 的 draft model 置信度阈值等。

2. **Column + Slash 的结构化稀疏抽象**：将 attention 的稀疏模式抽象为 column（全局关键 token）+ slash（局部窗口）的组合，是对 attention pattern 的简洁有力的建模。这一抽象对设计 attention-aware 的硬件加速器、编译器 sparse tile 调度、以及训练阶段的 structured sparsity 都有参考价值。

3. **Prefill 加速与 disaggregated serving 的结合**：在 prefill-decoding disaggregation 架构（如 DistServe、Splitwise）中，prefill 节点的 TTFT 是关键瓶颈。SampleAttention 可以直接部署在 prefill 节点上。值得探索的方向：将 Stage 1 sampling 的结果（稀疏 pattern）缓存下来，在后续 decoding 阶段或同一 prompt 的多次推理中复用。

4. **可操作的 follow-up 方向**：
   - 将自适应稀疏率的思想应用到 **训练阶段**的 attention 加速，结合梯度信息动态调整训练时的 sparse pattern
   - 将 CRA 指标集成到 **KV cache eviction** 中，替代现有基于 cumulative attention score 的启发式方法（如 H2O），实现 prefill + decoding 全链路的自适应稀疏
   - 在 **多 GPU tensor parallelism** 下探索 per-head 的自适应稀疏率如何与 head-level 并行策略协同

---

## 八、总结

SampleAttention 提出了以 Cumulative Residual Attention（CRA）为指导的自适应 sparse attention 方法，通过两阶段采样-过滤机制在运行时动态确定每个 attention head 的稀疏率和稀疏模式（column + slash），在长上下文 LLM prefill 阶段实现了近无损加速（最高 5.29× vs FlashAttention2）。其核心价值在于将稀疏率从静态超参变为由精度指标动态驱动的运行时决策。主要局限在于短序列加速有限、单 GPU 单 batch 实验不够充分、以及需要为每个模型离线调优超参。
