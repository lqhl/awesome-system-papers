## 一、背景

Mixture-of-Experts (MoE) 模型通过稀疏激活的专家层，在保持计算量不变的前提下大幅扩展模型参数量，成为 LLM 扩展的主流架构之一。然而，MoE 模型面临严峻的内存瓶颈：Mixtral-8×7B 需要约 90GB 内存存放权重（FP16），远超单张 A100 GPU 的 40/80GB 显存；更大的 Arctic MoE（480B 参数）甚至需要接近 1TB 内存。

模型量化是压缩 LLM 权重的主要技术路线。现有方法如 GPTQ 和 AWQ 已经能将 dense LLM 压缩到 INT4 精度而几乎不损失精度。然而，当量化精度进一步降到 3-bit 以下时，MoE 模型会出现显著的精度下降，现有方法难以应对。同时，INT3 量化在硬件层面缺乏高效的 Tensor Core 支持，理论上的压缩收益难以转化为实际的推理加速。

---

## 二、要解决的问题

1. **极端量化下 MoE 精度大幅下降**：INT4 量化对 MoE 模型的精度影响较小，但 INT3 量化导致严重的精度损失（如 Mixtral-8×7B 的 Wikitext2 PPL 从 3.42 升至 4.81）。现有 PTQ 方法无法有效处理这一问题。

2. **标定数据偏差与量化耗时**：GPTQ 等依赖 calibration data 的方法存在过拟合风险，且量化过程需要前向传播，对大规模 MoE 模型计算开销极大（如 GPTQ 对 Mixtral-8×7B 需要 5315 秒）。

3. **INT3 量化缺乏高效硬件支持**：3-bit 不是 2 的幂次，现有数据类型不直接支持 INT3。已有的 INT3 kernel（如 GPTQ 的 GeMV 实现）仅支持 batch size = 1，无法利用 Tensor Core，无法在实际推理中实现加速。

---

## 三、洞察与设计

**关键洞察**：MoE 模型由于其混合 dense-sparse 架构，不同类型的权重矩阵具有截然不同的统计特性——dense 层（attention projections）呈现重尾分布（高 Kurtosis），比 sparse expert 层在极端量化下损失更多信息；而量化主要丢失的是"不显著"的中间值权重（outliers 反而被较好地保留了）。这种异质性意味着可以用少量额外的低秩矩阵针对性地补偿不同层的量化误差。

基于这一观察，MiLo 采用 **Quantize-Then-Compensate** 的两阶段方法：

1. **Calibration-free INT3 量化**：使用 HQQ 对 MoE 模型进行 INT3 量化，不依赖任何标定数据，避免过拟合和高计算开销。

2. **Mixture of Low-Rank Compensators**：对量化残差矩阵 E = W − W_dq 进行低秩近似（SVD），用 UV 矩阵补偿量化损失。关键创新在于"自适应混合"策略：
   - **Layer Discrimination**：给 dense 层（attention）分配更高的 rank，因为它们对所有 token 都活跃，rank 敏感度更高。
   - **Weight Distribution**：根据 Kurtosis 分配 rank——Kurtosis 越高的权重量化误差越大，需要更高 rank。
   - **Expert Frequency**：根据专家激活频率分配 rank——高频专家获得更多 rank。

3. **迭代联合优化**：将问题分解为两个交替优化的子问题——(sp1) 固定 UV 优化量化参数 z；(sp2) 固定量化结果优化 UV。约 10-20 次迭代即可收敛。

4. **低秩矩阵二次量化**：补偿矩阵 U、V 本身可进一步量化为 INT3，仅用 37.5% 的内存（相比 INT8）而几乎不损失精度。

---

## 四、实现细节

**迭代优化算法**：
- 子问题 1 使用 l_{p<1} 范数作为损失函数，通过 Half-Quadratic solver 和广义软阈值算子交替更新辅助变量 M 和 zero-point z。
- 子问题 2 是标准的低秩近似问题，通过截断 SVD（Eckart-Young-Mirsky 定理）直接求解。
- 收敛判据：滑动窗口平均误差变化 < 1e-4，或达到 20 次迭代提前终止。

**INT3 CUDA Kernel 设计**：
- **Zero-bit-waste packing**：每 32 个 INT3 权重打包为 3 个 INT32，完全不浪费任何 bit。
- **MiLo Dequant**：基于二进制操作的高效 INT3→FP16 转换，每次同时转换 2 个 FP16 值（利用 32-bit 寄存器级并行），使用 `__hsub2` 和 `__hfma2` 指令。
- **异步全局权重加载**：利用 NVIDIA Ampere 架构的 `cuda::memcpy_async` API，实现权重加载与计算的重叠。
- **MoE-specific tile shape tuning**：针对不同的 GeMM 尺寸（如 4096×14336 和 14336×4096），支持 (256,64)、(128,128)、(64,256) 三种 tile shape，减少 thread block 间的全局同步开销。

**Rank 策略**：
- Mixtral-8×7B: MiLo-s1 = Dense-512 + Kurtosis-16; MiLo-s2 = Dense-1024 + Kurtosis-32
- DeepSeek-MoE: MiLo-s1 = Dense-800; MiLo-s2 = Dense-1024 + Frequency-32

## 六、批判性分析

1. **评估模型陈旧且规模有限**：仅评估 Mixtral-8×7B 和 DeepSeek-MoE 两个模型，且均非当前 SoTA MoE。论文未在更大规模（如 Mixtral-8×22B、DeepSeek-V2/V3）或更新的 MoE 模型上验证，可扩展性存疑。

2. **与 FP16 基线的差距被淡化**：MiLo-s2 在 Mixtral-8×7B 上 PPL 为 3.9076 vs FP16 的 3.42，仍有 14% 的差距。论文宣称"recover over 87% of accuracy"，但这个恢复率的计算方式（基于 HQQ 而非 FP16）掩盖了与未量化模型的真实差距。

3. **内存节省被高估**：MiLo 的压缩目标是 INT3，但加上 low-rank compensators（INT3 量化后），MiLo-s2 对 Mixtral-8×7B 需要 21GB——而 GPTQ INT4 仅需 18.4GB。如果目标是减少内存，INT4 量化可能是更简单高效的选择。论文未与 INT4 + low-rank compensation 的方案进行公平比较。

4. **自适应 rank 策略依赖先验知识**：Kurtosis 和 expert frequency 的计算需要访问完整权重和数据分布，rank 策略的选择（Dense vs Frequency vs Kurtosis）因模型而异，缺乏自动化的 rank 分配机制。

5. **Kernel 评估不够全面**：所有系统实验仅在 A100 上进行，未在消费级 GPU（如 RTX 4090）或 H100 上测试。INT3 kernel 的设计高度依赖 NVIDIA 特定的硬件特性（Ampere async copy），跨硬件的适用性不明。

6. **缺少生成质量评估**：所有评估均为 PPL 和分类任务准确率，未涉及实际生成质量（如 chatbot 场景）。INT3 量化在长文本生成中的表现可能比这些基准更差。

## 七、AI Infra / MLSys 视角

**启发与借鉴价值**：

1. **Quantize-Then-Compensate 范式**：MiLo 的核心思路——先做极端量化捕获 outliers，再用低秩矩阵补偿中间值信息损失——是一个通用的压缩框架，可以扩展到其他模型架构（dense LLM、vision models）和其他压缩比特数。

2. **利用模型结构异质性做自适应压缩**：MoE 模型的 dense/sparse 层具有不同的量化敏感度，这个观察可以推广到任何混合架构（如 MoE + MLA、Sparse Transformer）。在 AI Infra 中，可以根据层类型动态选择量化策略、内存分配和计算调度。

3. **INT3 Kernel 工程实践**：zero-bit-waste packing、binary manipulation based dequant、async weight loading 的组合为非 2 的幂次量化（如 INT3、INT5、INT6）提供了可复用的 kernel 设计模板。

**值得跟进的方向**：

- **与 KV cache 量化的协同**：MiLo 仅处理 weight-only quantization，若结合 KV cache 量化（如 KIVI），可以进一步压缩推理内存。
- **动态 rank 调整**：根据输入 token 的特征动态调整 compensator 的 rank，类似于 adaptive computation 的思路。
- **与 expert offloading 结合**：在 offloading 场景下，INT3 权重传输量更小，low-rank compensators 可以常驻 GPU 显存，进一步降低 offloading 延迟。
- **扩展到更新的 MoE 架构**：DeepSeek-V3 使用 FP8 训练和 Multi-head Latent Attention，MiLo 的方法是否仍然有效需要验证。

---

## 八、总结

MiLo 提出了一种面向 MoE 模型的"量化 + 低秩补偿"压缩方法：通过 calibration-free 的 INT3 量化结合自适应混合低秩补偿器，在仅增加约 1-4% 内存的前提下大幅恢复极端量化带来的精度损失，并开发了高效的 INT3 Tensor Core kernel 实现实际推理加速（相比 MARLIN INT4 加速 1.2-1.28×）。该方法适用于需要在单 GPU 上部署大型 MoE 模型的场景，但评估仅覆盖两个中等规模模型，且 INT3 + compensator 的内存占用反而高于 INT4 方案，在实际部署中需要权衡压缩比与精度恢复之间的 trade-off。
