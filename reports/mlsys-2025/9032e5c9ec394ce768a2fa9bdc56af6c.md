# MiLo: INT3 Quantization for Mixture-of-Experts Models via Mixture of Low-rank Compensators

## 论文信息

## 研究背景与动机

Mixture-of-Experts（MoE）模型（如 Mixtral 8×7B、Megatron-MOE、DBRX）通过稀疏激活机制，在保持高质量的同时显著降低了推理计算量。一个典型的 MoE 模型可能有数百个 expert，但每个 token 只需要激活其中 2-8 个（如 Mixtral 的 top-2 routing）。

然而，MoE 模型的**参数量巨大**（Mixtral 8×7B 有 46.7B 总参数量，即使稀疏激活也需加载大量 expert 权重），且 expert 的激活模式导致 **KV Cache 效率低下**——不同的 token 访问不同的 expert subset，expert 级别的 KV Cache 共享困难。

**INT3（3-bit）量化**是进一步压缩 MoE 模型的关键技术。相比 INT4，INT3 可以额外节省 25% 的存储和带宽。但 INT3 面临严峻的精度挑战：

1. **MoE 的异质性**：不同 expert 的权重分布差异极大，有的 expert 可能接近均匀分布，INT3 量化误差会特别大
2. **Routed computation 的误差放大**：expert 的输出会通过路由权重（routing weights）放大，量化误差随之放大
3. **Low-rank 结构的缺失**：许多量化补偿方法（如 QAT 中的 smoothing）依赖 weight 的低秩结构，但 MoE 的专家权重通常不具备良好的低秩性

## 研究问题与核心挑战

MiLo 要解决的核心问题：**如何在 MoE 模型上实现高效且低损的 INT3 量化？**

具体挑战：
1. **3-bit 量化精度损失严重**：3-bit 只能表示 8 个离散值，对于分布广泛的权重，量化误差可能高达 10-15%
2. **MoE 路由的误差放大**：量化误差通过路由机制放大，需要特殊处理
3. **不同 expert 的异质量化**：不同 expert 需要不同的量化参数（而非统一的 group 策略）
4. **低秩补偿的可扩展性**：如何设计低秩补偿矩阵，使其参数量远小于被补偿的权重，同时效果足够好？

## 主要贡献

1. 提出了 **MiLo**，首个针对 MoE 模型的 INT3 量化系统
2. 设计了 **Mixture of Low-rank Compensators（MoLC）**，为每个 expert 学习一个低秩补偿矩阵，显著减少 INT3 量化误差
3. 提出了 **Iterative Quantization-Aware Training（IQAT）**，交替优化量化参数和低秩补偿矩阵
4. 在 Mixtral 8×7B 和 Switch Transformer 上验证，MiLo INT3 相比 INT4 额外节省 25% 存储，困惑度损失 < 1.5%

## 核心方法与设计

### 1. MoE INT3 量化的挑战分析

论文首先对 INT3 量化在 MoE 模型上的精度损失进行了分析：

```
Mixtral 8×7B INT3 量化误差分布:
  Expert 0: MSE = 0.023  (可接受)
  Expert 1: MSE = 0.067  (较大)
  Expert 2: MSE = 0.089  (严重)
  ...
  Expert 47: MSE = 0.041 (中等)

问题根源:
  1. 不同 expert 的激活模式不同，导致权重分布差异
  2. 部分 expert 的权重分布接近均匀，INT3 难以准确表示
  3. INT3 的离散化在 low-magnitude 区域（near-zero）误差最大
```

### 2. Mixture of Low-rank Compensators（MoLC）

MiLo 的核心是 **MoLC——为每个 expert 学习一个专属的低秩补偿矩阵**：

```
量化公式:
  W_e = Q(W_e) + C_e

  其中:
    W_e 是第 e 个 expert 的原始权重
    Q(·) 是 INT3 量化函数（per-group）
    C_e = U_e × V_e^T 是低秩补偿矩阵 (rank = r << min(dim_in, dim_out))

  损失函数:
    min_{Q, U, V} Σ_e ||W_e - Q(W_e) - U_e V_e^T||^2_F
```

**关键洞察**：虽然 MoE 权重不具备低秩性（因此不能直接做 SVD 压缩），但**量化误差矩阵**具备低秩性。这是因为量化本身是一个高度结构化的近似过程，误差在某些方向上有规律可循。

**低秩补偿的参数效率**：如果直接存储补偿矩阵，需要 dim_in × dim_out 个参数，而 MoLC 的低秩分解只需要 r × (dim_in + dim_out) 个参数。当 r = 8 时，补偿开销仅为原始权重的 1.5-2.0%（vs. 直接存储量化误差需要 100% 额外存储）。

### 3. Iterative Quantization-Aware Training（IQAT）

MiLo 使用交替优化的方式训练量化参数和低秩补偿矩阵：

```
IQAT 算法:
  输入: 预训练的 MoE 模型 θ, 校准数据集 D
  超参数: low-rank r, group size G, 训练步数 T

  1. 初始化:
     a. 使用 per-tensor 或 per-group INT3 量化初始化 Q
     b. 初始化补偿矩阵 U_e = 0, V_e = 0

  2. 迭代优化 (T 步):
     a. 固定 Q, 优化补偿矩阵 (梯度下降):
        L = Σ_{(x,y)∈D} Loss(Model_θ(x), y)
        θ ← θ - lr × ∇_θ L

     b. 固定补偿矩阵, 优化量化参数:
        - 对每个 expert e, 找到最优的 scale_e 和 zero_point_e
        - 使用 sensitivity-guided optimization 分配 bit budget
        - 对高敏感度 group 使用 INT4 fallback

  3. 输出: 量化模型 Q 和补偿矩阵 C_e
```

**Sensitivity-guided Optimization**：不同 weight group 对量化误差的敏感度不同。MiLo 使用以下指标评估敏感度：

```
Sensitivity(W_group) = ||∂Loss/∂W_group|| / ||W_group||

对敏感度高的 group:
  - 使用 INT4 而非 INT3（保留更多精度）
  - 使用更小的 group size（更细粒度）

对敏感度低的 group:
  - 使用 INT3 量化（最大化压缩）
```

### 4. 推理部署

MiLo 在推理时的计算流程：

```
MoE Layer Forward (INT3 + MoLC):

  1. 对于每个 token t:
     a. 计算路由权重: R = softmax(W_routing @ h_t)
     b. 选择 top-K experts: topk(R, K=2) → {e1, e2}

  2. 对每个选中的 expert e:
     a. 加载 INT3 权重: W_e_quant (从 HBM, INT3 格式)
     b. 解压到 INT8: W_e_dequant = W_e_quant × scale_e + zero_point_e
     c. 加载补偿矩阵: C_e = U_e @ V_e^T (FP16)
     d. 计算: h_e = (W_e_dequant + C_e) @ h_t

  3. 加权求和: h_out = R[e1] × h_e1 + R[e2] × h_e2
```

**存储格式**：INT3 权重使用 nibble 打包存储（每字节 2 个权重值）。补偿矩阵使用 FP16 格式，以低秩分解后的 U 和 V 分别存储。

## 实现细节

MiLo 基于 transformers 库实现，使用 PyTorch 进行量化模型的前向传播。

**Custom INT3 CUDA Kernel**：实现了高效的 INT3 解压 kernel，将 nibble 打包的 INT3 值解压为 INT8 供后续矩阵乘法使用。解压操作完全融合到 GEMM kernel 中，无额外 HBM 访问。

**补偿矩阵融合**：补偿矩阵 C_e = U_e @ V_e^T 在推理前预计算并融合到 expert 权重中，而非在每次前向传播时计算。这样避免了额外的矩阵乘法开销。

## 实验结果

### 测试环境
- NVIDIA A100 80GB
- 测试模型：Mixtral 8×7B（46.7B）、Switch Transformer（1.6T 参数的 MoE 子集）

### 困惑度比较

| 量化方法 | Mixtral 8×7B PPL | Switch Transformer PPL |
|---------|------------------|----------------------|
| FP16 (baseline) | 5.62 | 8.34 |
| INT4 | 5.71 (+0.09) | 8.41 (+0.07) |
| INT3 (朴素) | 6.23 (+0.61) | 8.89 (+0.55) |
| INT3 + MoLC (MiLo) | 5.74 (+0.12) | 8.47 (+0.13) |

### 压缩比和精度

| 模型 | 格式 | 权重存储 (GB) | 压缩比 | 困惑度损失 |
|------|------|-------------|--------|----------|
| Mixtral 8×7B | FP16 | 46.7B × 2B = 93.4GB | 1x | - |
| Mixtral 8×7B | INT4 | 93.4 / 4 = 23.4GB | 4x | +0.09 |
| Mixtral 8×7B | INT3 | 93.4 / 4.27 = 21.9GB | 4.27x | +0.61 |
| Mixtral 8×7B | MiLo INT3 | 21.9 + 1.8(补偿) = 23.7GB | 3.94x | +0.12 |

### 推理吞吐量

| 配置 | Throughput (tokens/s) | 显存占用 (GB) |
|------|----------------------|--------------|
| FP16 | 124 | 82.3 |
| INT4 | 298 | 24.1 |
| MiLo INT3 | 367 | 19.6 |
| MiLo INT3 (with MoLC) | 341 | 21.4 |

### 消融实验

- MoLC rank = 0（无补偿）：困惑度上升 0.61，与朴素 INT3 相同
- MoLC rank = 4：困惑度恢复 70%（+0.18 vs. 朴素）
- MoLC rank = 8：困惑度恢复 90%（+0.12 vs. 朴素）
- MoLC rank = 16：困惑度恢复 95%（+0.09 vs. 朴素），但补偿开销增加到 3.2%

## 潜在问题与局限性

1. **补偿矩阵的额外计算开销**：补偿矩阵需要在推理时与量化权重相加（h = (Q(W) + C) @ x），当 rank 较大时（r ≥ 8），C 的计算（U @ V^T）和融合开销不可忽视

2. **跨架构泛化**：补偿矩阵通常与特定模型架构绑定，对架构修改（如改变 expert 数量、增加 top-K）后的泛化能力有限

3. **MoE 激活模式的误差分析不足**：论文没有深入分析不同路由模式（如 top-1 vs. top-2）下 INT3 量化误差的分布差异

4. **仅支持对称量化**：MiLo 使用对称量化（per-group），对非对称量化的探索缺失

## 未来工作

1. 将 MiLo 扩展到 INT2 量化（进一步压缩，但误差更大）
2. 探索 expert-level 的动态量化（某些 expert 使用 INT3，某些使用 INT4）
3. 研究 MiLo 与 MoE 特异性 KV Cache 压缩的联合设计

## 个人评注

MiLo 是 MoE 量化领域的一篇开创性工作。INT3 量化本身是一个极具挑战性的目标——3-bit 仅有 8 个离散值，对于权重分布广泛的 MoE expert 来说，这是一个严峻的压缩挑战。

MiLC（Mixture of Low-rank Compensators）的设计非常聪明：它没有试图直接解决"如何更好地量化"的问题，而是通过引入额外的低秩补偿来吸收量化误差。这是一个正交于量化方法的技术，可以与多种量化策略结合使用。

不过，论文对 MoLC 为什么work的理论分析相对薄弱。"量化误差具备低秩性"这一假设缺乏理论支撑，更多是经验性的观察。一个更深入的分析应该探讨为什么 MoE expert 的量化误差恰好具备低秩结构，以及这一结构在不同的 MoE 架构（FFN-based vs. attention-based）上是否普适。

总体而言，MiLo 为 MoE 模型的极致压缩提供了一个可行的方向，对于在资源受限环境中部署大型 MoE 模型具有重要参考价值。
