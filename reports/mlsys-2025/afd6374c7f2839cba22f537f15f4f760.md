## 1. 研究背景与动机

移动端设备的 NPU 计算能力持续提升，但 DRAM 带宽的增速远落后于计算密度的增长。以 Phi-3-Medium 为例，INT4 量化后模型约 7GB，逼近智能手机的平均 DRAM 容量——而系统已占用大部分内存，剩余空间对于本地 LLM 部署极为有限。

现有动态稀疏方法（如 DejaVu、LLM in a Flash、PowerInfer）利用 ReLU 激活函数产生的天然零值来实现 MLP 层的稀疏计算，从而减少每次 token 生成时需要加载的参数量。然而，现代 LLM（Llama、Phi-3、Mistral 等）普遍采用 SwiGLU 激活函数替代 ReLU，导致激活向量中几乎没有天然零值。直接沿用 ReLU-LLM 的动态稀疏方法在 SwiGLU 模型上效果严重退化。

针对这一问题，既有的解决方案（如 TurboSparse）需要将 SiLU 替换为 ReLU 并进行大规模微调（通常需要数十亿 token 的微调数据），代价极高。

## 2. 研究问题与核心挑战

### 2.1 SwiGLU 激活的可预测性挑战

论文深入分析了 SwiGLU 架构下动态稀疏方法的局限性。核心发现：

- **稀疏能力有限**：SwiGLU 激活在 MMLU 上只能剪枝约 50% 而不造成 1% 的性能下降，而 ReLU-fied 对应版本可达到 90% 以上。
- **预测器失效**：DejaVu 等方法依赖小型预测器预测零值激活，但在 SwiGLU 模型上表现极差——MMLU 精度在 50% 稀疏度下下降近 10%，远高于 ReLU-fied 版本。论文将这一现象归因于：SwiGLU 激活本身不够稀疏，预测器犯错更容易剪掉重要激活；同时 SwiGLU 中门控组件的交互使激活模式更难预测。
- **单一矩阵稀疏**：GLU pruning 只能稀疏化 MLP 三个大矩阵中的其中一个（up），最多实现 33% 的 MLP 稀疏度。

### 2.2 缓存感知的动态调度

即便稀疏化成功，DRAM 缓存的驱逐策略也至关重要。论文发现，Belady 最优驱逐算法相比简单策略（LRU/LFU）并无显著优势，说明问题在于稀疏掩码本身，而非缓存策略。

## 3. 主要贡献

1. **DejaVu 类方法在 SwiGLU 模型上失效的系统分析**：揭示了预测器方法在非 ReLU 架构上的根本性局限。
2. **Dynamic Input Pruning（DIP）**：一种无需预测器的动态稀疏方法，通过对 MLP 的 up、gate 和 down 三个矩阵同时进行基于 Top-K 的输入剪枝来保留准确性，只需极少的微调。
3. **Cache-Aware Masking（DIP-CA）**：在稀疏掩码生成阶段引入缓存状态感知，重新加权神经元得分以优先选择已在缓存中的权重，从而提升缓存命中率。
4. **LoRA 适配器辅助**：轻量级 LoRA 适配器可进一步恢复稀疏化造成的精度损失，且推理时零开销（因为适配器在列选择之前应用）。

## 4. 核心方法与设计

### 4.1 Dynamic Input Pruning（DIP）

DIP 的核心公式：
- 对 up 和 gate 矩阵：`Wu, Wg = [x_i if i ∈ topK(x)]`，即对输入激活进行 Top-K 剪枝
- 对 down 矩阵：`Wd = [Wd,i if i ∈ topK(]LU(x))]`，即对 GLU 激活的近似结果进行剪枝

关键设计：对 GLU 激活使用 `Wu` 和 `Wg` 而非原始 `Wu` 和 `Wg`，从而在保持准确性的同时稀疏化所有三个 MLP 矩阵。Per-token Top-K 策略（而非 global 或 per-layer threshold）的表现与 per-layer 相当，但能保证每个 token 剪枝数量恒定。

### 4.2 Cache-Aware Masking（DIP-CA）

在 Top-K 选择之前，引入缓存感知重加权：
$$s^{(t)} = \frac{x^{(t)} \odot c^{(t-1)} + \lambda(1 - c^{(t-1)})}{x^{(t)}}$$

其中 $c^{(t-1)}$ 是二值缓存掩码（1 表示已在缓存），$\lambda$ 是惩罚超参数（设为 0.2）。该机制使已被缓存的神经元在竞争中获得优势，同时保证最强激活即使不在缓存也能被选中。

### 4.3 LoRA 辅助恢复

在列选择之前应用 LoRA 适配器：`W[:,i] ← W[:,i] + AB`，其中 A、B 为低秩矩阵。训练时使用知识蒸馏损失（KL 散度匹配原始 logit），推理时零额外开销，因为列选择基于原始矩阵。

## 5. 实验设置

**硬件模拟器**：Apple A18（DRAM I/O 60GB/s，Flash 读取 1GB/s），可配置不同 DRAM 大小和 Flash 速度。

**测试模型**：Phi-3-Medium、Phi-3-Mini、Llama3-8B、Mistral-7B（均为 SwiGLU 架构）。

**基准方法**：GatePruning、UpPruning、DejaVu、CATS（+LoRA）、SparseGPT（unstructured/2:4/4:8）。

**数据集**：SlimPajama（校准），WikiText-2（困惑度），MMLU（5-shot 准确率）。

## 6. 实验结果

### 6.1 准确性（50% MLP 稀疏度）

DIP 在所有模型上显著优于所有基准方法。以 Phi-3-Medium 为例：
- Dense: 4.29 perplexity, 78.14% MMLU
- DIP: 5.52 perplexity, 75.54% MMLU
- DIP+LoRA: 5.01 perplexity, 75.89% MMLU
- CATS+LoRA: 5.54 perplexity, 72.23% MMLU（差距明显）
- DejaVu: 6.15 perplexity, 68.99% MMLU（差距更大）

值得注意的是，在 Llama3-8B 和 Mistral-7B 上，GatePruning 表现极差（MMLU 分别仅 27.23% 和 40.39%），而 DIP 保持 60% 左右的 MMLU 水平。

### 6.2 吞吐量

在 DRAM 仅能容纳约 50% 模型权重的设置下：
- **Phi-3-Medium**：DIP-CA 在 perplexity 损失 0.1 时实现 40% 吞吐量提升和 46% 内存降低；在 perplexity 损失 0.5 时吞吐量提升 93%。
- **所有模型上 DIP-CA 均优于 DIP**，验证了缓存感知机制的有效性。

### 6.3 与量化结合

DIP 应用于 4-bit GPTQ 量化模型后，显著优于单独的剪枝或量化方法——在 4GB DRAM 约束下，BQ4+DIP 的困惑度比 SparseGPT 低 15%。

### 6.4 缓存驱逐策略

DIP-CA + LFU 在所有 perplexity 水平上均优于 DIP + Belady Oracle，表明缓存感知重加权策略比更优的驱逐策略更有效。

## 7. 潜在问题与局限性

1. **模拟环境与真实硬件的差距**：所有实验基于模拟器，缺少在真实 Qualcomm NPU/手机 SoC 上的端到端验证。模拟器的参数（DRAM 带宽、Flash 速度）对结果的真实性至关重要。
2. **仅支持 SwiGLU 架构**：方法针对 SwiGLU MLP 设计，对其他架构（如 GeGLU、SwiGLU 变体）的适用性未知。
3. **Perplexity 作为主要评估指标**：论文主要评估 perplexity 和 MMLU 5-shot 准确率，对下游任务（如代码生成、对话）的端到端影响评估不足。
4. **LoRA 适配器的微调成本被低估**：LoRA 训练需要 1000 步迭代，虽然相对轻量，但在某些部署场景中仍构成工程负担。
5. **仅覆盖 Prefill-Decoding 阶段**：方法聚焦于 token 生成阶段的稀疏化，未探索 Prefill 阶段的潜在稀疏机会。

## 9. 个人评注

这是一篇 Qualcomm AI Research 的工程性论文，特点是扎实、系统性强、针对明确的移动端部署痛点。

论文最有价值的贡献在于揭示了一个被忽视的问题：SwiGLU 架构的动态稀疏性远比 ReLU-LLM 难处理，而 DejaVu 等预测器方法在这一场景下近乎失效。这一观察对于后续工作具有重要的指导意义——不应该简单地将 ReLU-LLM 上的动态稀疏方法移植到 SwiGLU 模型上。

DIP 的设计简洁有效：用简单的 Top-K 剪枝替代复杂的预测器，用 LoRA 蒸馏做精度恢复，用缓存感知重加权弥补驱逐策略的不足。三层叠加形成了一个完整的解决方案，且每一步都有清晰的动机。

但需要指出的是，论文的评估体系存在一定局限性：模拟器环境与真实移动 SoC 存在较大差距（特别是 Flash 读取的并发模式），且仅测试了 perplexity 和 MMLU 两个指标，对于实际部署场景的代表性有限。此外，论文未与 PowerInfer-2（同样是 Qualcomm 的工作）在真实硬件上进行对比，难以判断实际落地价值。

总体而言，对于关注移动端 LLM 部署的研究者和工程师，这篇论文提供了有价值的稀疏化思路，但读者应结合真实硬件验证其有效性。
