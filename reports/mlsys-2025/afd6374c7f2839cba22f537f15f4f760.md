## 一、背景

移动设备的 NPU 算力近年呈指数级增长，但 DRAM 容量和带宽的提升远远跟不上。LLM token 生成阶段以 memory-bound 为主，一个 14B 参数的模型（如 Phi-3-Medium）即使用 INT4 量化也需约 7GB，而智能手机平均 DRAM 容量仅约 8GB，扣除 OS 和应用占用后所剩无几。

此前的动态稀疏方法（DejaVu、LLM in a Flash、PowerInfer 等）利用 ReLU 激活函数产生的天然零值稀疏来跳过不活跃的权重列，从而减少内存访问。但当前主流 LLM（Llama 3、Mistral、Phi-3、Qwen 等）已全面转向 SwiGLU 激活函数，不再产生天然的硬零值稀疏，使得这些方法失效。

---

## 二、要解决的问题

1. **SwiGLU 缺乏天然稀疏性**：ReLU 网络可达 90% 自然稀疏，而 SwiGLU 网络几乎没有硬零值，现有基于零值预测的动态稀疏方法无法直接适用。

2. **预测器在 SwiGLU 上失效**：DejaVu 等方法使用小型预测器来预判哪些激活为零。在 SwiGLU 网络上，需要预测的是激活值大小而非符号，这是一个困难得多的任务。实验显示，相同预测器架构在 SwiGLU 模型上 MMLU 精度下降近 10%，而在 ReLU 模型上几乎无损。

3. **ReLU-fication 代价高昂**：将 SwiGLU 替换为 ReLU 并重新训练（如 TurboSparse）需要数十亿 token 的微调数据，计算成本极高，且可能无法完全恢复原模型精度。

4. **缓存策略与稀疏掩码脱节**：现有方法先确定稀疏掩码、再用缓存策略处理权重加载，两者独立运行，未能利用缓存状态来优化稀疏选择。

---

## 三、洞察与设计

**关键洞察**：虽然 SwiGLU 激活值没有天然硬零值，但其中间激活（GLU output）的幅度分布呈现极端长尾特性——少量神经元激活值比其他高出数个数量级，而第 30 到第 80 百分位的激活值在同一数量级内。这意味着可以在不预测零值的情况下，通过直接对 MLP 输入和中间激活做 magnitude-based top-K 剪枝来实现动态稀疏，且对中等幅度的激活进行重排序（偏向缓存中已有的权重列）不会显著影响输出质量。

### Dynamic Input Pruning (DIP)

核心思路：绕过预测器，直接利用每层 MLP 的输入激活 x 来决定哪些列需要加载：

1. **输入剪枝**：对 MLP 输入 x 做 per-token top-K，保留最大的 K 个维度，仅加载 W_u 和 W_g 对应的列（上游和门控矩阵的列剪枝）
2. **中间剪枝**：用剪枝后的 W̃_u 和 W̃_g 计算近似 GLU 激活，再做一次 top-K，剪枝 W_d 的列
3. **LoRA 补偿**：可选地在稀疏化的 up/gate/down 矩阵上添加轻量 LoRA adapter（rank=32），通过知识蒸馏训练 1000 步，训练后将 adapter 融合回原权重，不增加推理开销

DIP 的优势在于：不需要额外预测器网络、可以同时稀疏化所有三个 MLP 矩阵（最高 66%+ MLP 稀疏度）、仅需极少量微调。

### Cache-Aware Masking (DIP-CA)

在 DIP 基础上引入缓存感知的掩码策略：

$$s(t) = \frac{x(t) \cdot [c(t-1) + \lambda(1-c(t-1))]}{x(t) \cdot \mathbf{1}}$$

其中 c(t-1) 是当前缓存状态的二值掩码，λ ∈ (0,1) 是惩罚因子。对不在缓存中的神经元施加 λ 倍衰减，使 top-K 选择偏向已缓存的列，从而提高缓存命中率。由于中等幅度激活的贡献相近，这种重排序对模型精度影响很小，但能大幅减少 Flash 读取次数。

## 四、实现细节

- **稀疏粒度**：列级稀疏（column sparsity），每个 token 独立选择活跃列
- **阈值策略**：per-token top-K，在所有层上保持固定比例的活跃激活。输入层和中间层的活跃比例根据目标 MLP 稀疏率联合标定（详见 Appendix B.1）
- **LoRA 训练**：rank=32，在 SlimPajama 数据集上用知识蒸馏 loss 训练 1000 步，训练后融合至原权重矩阵
- **缓存管理**：LFU（Least Frequently Used）淘汰策略，λ=0.2 固定用于所有层和模型
- **硬件模拟器**：自研 HW Simulator 模拟 Flash → DRAM → NPU 的数据传输延迟。默认模拟 Apple A18 平台（DRAM I/O 60GB/s，Flash read 1GB/s）。不模拟 NPU 计算时间（token generation 阶段为 memory-bound）
- **量化**：所有吞吐量实验中模型均使用 GPTQ INT4 量化
- **开源**：代码和 HW 模拟器已在 GitHub 公开（Qualcomm-AI-research/dynamic-sparsity）

## 五、实验结果

### 50% MLP 稀疏度下的精度对比

| 方法 | Phi-3-Med PPL↓ | Phi-3-Mini PPL↓ | Llama 8B PPL↓ | Mistral 7B PPL↓ | Phi-3-Med MMLU↑ |
|------|---------|---------|--------|---------|---------|
| Dense | 4.29 | 6.01 | 6.14 | 5.25 | 78.14 |
| GLU Pruning (oracle) | 4.45 | 6.10 | 6.30 | 5.29 | 77.98 |
| DejaVu | 6.15 | 8.76 | 9.43 | 6.24 | 68.99 |
| CATS+LoRA | 5.54 | 7.44 | 16.53 | 9.18 | 72.23 |
| **DIP** | **5.52** | **7.04** | **7.38** | **5.61** | **75.54** |
| **DIP+LoRA** | **5.01** | **6.79** | **7.26** | **5.57** | **75.89** |

DIP 在所有模型上均大幅优于 DejaVu、CATS 和静态剪枝方法，尤其在 Llama 8B 和 Mistral 7B 上优势明显。

### 吞吐量对比（INT4 量化，DRAM ≈ 50% 模型大小）

| 方法 | Phi-3-Med tok/s @+0.5PPL | Mistral 7B tok/s @+0.5PPL |
|------|--------------------------|---------------------------|
| Dense (from Flash) | 0.29 | 0.54 |
| GLU Pruning | 0.45 | 0.87 |
| CATS | 0.47 | 0.77 |
| DIP | 0.50 | 1.23 |
| **DIP-CA** | **0.56** | **1.39** |

Phi-3-Medium 上，DIP-CA 相比 dense 模型实现 **46% 内存减少**和 **40%/55%/93% 吞吐量提升**（分别在 +0.1/+0.2/+0.5 PPL 损失下）。

### 缓存策略对比

DIP-CA + LFU 在所有 perplexity 水平下的吞吐量均超过 DIP + Belady 最优缓存淘汰策略（oracle），表明缓存感知掩码比优化淘汰策略更有效。

### 与量化的互补性

DIP 可叠加在量化之上：BQ4+DIP 优于更激进的 BQ3/BQ2 量化，VQ3+DIP 进一步优于 BQ4+DIP，说明动态稀疏是量化的有效互补手段。

## 六、批判性分析

1. **仅基于模拟器评估，无真实设备数据**：所有吞吐量结果来自自研 HW Simulator，模拟了简化的 Flash→DRAM→NPU 流水线。真实设备上 OS 调度、热节流、内存竞争等因素可能显著影响实际性能。论文未提供任何真机对比验证。

2. **top-K 选择本身的开销被忽略**：DIP 每层需要对输入激活做 top-K 操作，DIP-CA 还需额外的缓存状态查找和分数重算。这些 on-device 计算开销在 memory-bound 假设下被忽略，但在高稀疏度（需要处理的列很少）时，计算可能不再 negligible。

3. **λ=0.2 全模型固定过于简化**：不同层的激活分布特性差异较大（论文自己提到 first/last layer 有更长的尾部），但 λ 参数在所有层、所有模型上均固定为 0.2，可能未达最优。

4. **评估模型规模有限**：仅在 7B-14B 参数模型上验证，缺乏对更大模型（70B+）的评估。更大模型的激活分布特性和稀疏化表现可能有所不同。

5. **仅评估 MLP 稀疏**：论文仅针对 MLP 层做动态稀疏。Attention 层（尤其是 KV cache 相关的内存开销）未被考虑，但在长序列场景下 attention 同样是内存瓶颈。

6. **LoRA 的训练成本被轻描淡写**：虽然称为"lightweight"，但 LoRA 仍需要知识蒸馏训练 1000 步，需要 calibration 数据和 teacher model 推理。对于某些部署场景，这仍是一个非平凡的成本。

## 七、AI Infra / MLSys 视角

1. **移动端 LLM 推理的实用路径**：DIP 提供了一种对现有 SwiGLU 模型几乎"即插即用"的动态稀疏方案（无需重训或替换激活函数），对移动端/边缘端 LLM 部署有直接价值。与量化的正交互补性也很有吸引力。

2. **Cache-aware sparsity 的思想可迁移**：DIP-CA 将缓存状态纳入计算路径选择的思想不局限于移动端。在 GPU 推理中（如多级显存架构、CPU offloading 场景），类似的"让计算适应数据位置"策略值得探索——例如在 vLLM 的 PagedAttention 或 FlexGen 的 offloading 策略中引入 cache-aware 的 token 调度。

3. **值得跟进的研究方向**：
   - 将 DIP 扩展到 Attention 层（动态选择 KV cache 中哪些 head/token 参与计算）
   - 在 GPU offloading 场景（如 DeepSpeed Inference、FlexGen）中验证 cache-aware masking 的效果
   - 探索 DIP 与 speculative decoding 的结合——稀疏模型做 draft，dense 模型做 verify
   - 研究 DIP 在更大规模模型和 MoE 架构上的表现（MoE 的 expert 选择本身就是一种稀疏机制）

4. **最有价值的切入点**：将 cache-aware masking 的核心思想（根据数据局部性动态调整计算路径）应用到 GPU 多级存储层次（HBM/DRAM/SSD）的 LLM serving 系统中，尤其是在长上下文推理中 KV cache 管理的场景。

---

## 八、总结

本文针对 SwiGLU LLM 在内存受限移动设备上的推理问题，提出了 Dynamic Input Pruning (DIP) 方法，通过直接对 MLP 输入和中间激活做 magnitude-based top-K 剪枝实现动态稀疏，无需预测器或昂贵的重训。进一步提出的 Cache-Aware Masking (DIP-CA) 将缓存状态引入稀疏掩码决策，在牺牲极少精度的条件下大幅提升缓存命中率和吞吐量。在 Phi-3-Medium 上实现 46% 内存减少和 40% 吞吐提升（PPL 损失 <0.1）。主要局限在于仅通过模拟器评估、缺乏真机验证，且评估范围限于中等规模模型的 MLP 层。
