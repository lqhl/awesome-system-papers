# TASDER: Unstructured Sparsity Meets Structured Sparse Hardware via Distributive Property

## 研究背景与动机

深度学习模型中存在大量冗余权重——研究表明，超过 90% 的权重可以设为零而不显著影响模型精度。**非结构化稀疏（Unstructured Sparsity）**允许任意位置的权重被置零，是最灵活的稀疏形式。然而，非结构化稀疏的致命弱点是**硬件效率低下**：现有的 GPU 和 TPU 并不原生支持任意的稀疏模式，需要专用的稀疏张量核（Sparse Tensor Core）。

**结构化稀疏（Structured Sparsity）**指权重以规则模式稀疏（如 N:M 稀疏、块稀疏），可以被现有硬件高效利用。然而，结构化稀疏会引入更大的精度损失——因为它强制"一整行/列/块"同时为零，限制了优化的自由度。

TASDER 的核心洞察是：**利用"分配律"（Distributive Property），将非结构化稀疏的权重矩阵转换为一系列结构化稀疏矩阵的组合，从而使非结构化稀疏模型能够高效运行在结构化稀疏硬件上**。

## 研究问题与核心挑战

TASDER 要解决的核心问题：**如何在不牺牲精度的情况下，将非结构化稀疏模型高效运行在仅支持结构化稀疏的硬件上？**

具体挑战：
1. **精度与硬件效率的权衡**：非结构化稀疏精度高但硬件不兼容；结构化稀疏硬件友好但精度损失大
2. **转换的理论基础**：分配律在稀疏矩阵运算中的性质（哪些可以转换，哪些不可以）尚不明确
3. **转换的开销**：将单个非结构化稀疏矩阵转换为多个结构化稀疏矩阵的计算开销不能超过节省的计算量
4. **端到端的误差控制**：转换引入的额外误差不能超过原非结构化稀疏本身引入的误差

## 主要贡献

1. 提出了 **TASDER**，首个将非结构化稀疏映射到结构化稀疏硬件的系统
2. 理论上证明了**分配律在稀疏矩阵乘法中的有效性条件**，为方法提供了坚实的数学基础
3. 设计了 **Progressive Structured Approximation（PSA）** 算法，逐步将非结构化稀疏矩阵分解为结构化稀疏分量的组合
4. 在 NVIDIA A100（结构化稀疏张量核）上验证，TASDER 相比 dense 计算提速 2.0-3.1 倍，精度损失仅比非结构化稀疏高 < 0.5%

## 核心方法与设计

### 1. 分配律与稀疏矩阵

TASDER 的理论基础是矩阵乘法的分配律：

```
对于矩阵 A (M×K)、B (K×N)、C (K×N):

  A × (B + C) = A × B + A × C  ✓ (总是成立)

但如果 B 和 C 是稀疏的（很多零），左边和右边的计算量差异很大。
问题是：如果 A × B 和 A × C 都是结构化稀疏的，
      能否找到一个等价的表示？

TASDER 的核心思想:
  将原始的稀疏权重矩阵 W 分解为:
    W ≈ Σ_i S_i

  其中每个 S_i 是结构化稀疏矩阵（可被硬件直接加速）

  推理时计算:
    Y = X @ W ≈ X @ (Σ_i S_i) = Σ_i (X @ S_i)

  每个 X @ S_i 都可以使用结构化稀疏加速！
```

### 2. Progressive Structured Approximation（PSA）

PSA 算法将非结构化稀疏矩阵分解为结构化稀疏分量的组合：

```
PSA 算法:
  输入: 原始权重 W (M×K), 非结构化稀疏mask M (|M|_0 = θ·MK), 分量数 I
  输出: 结构化稀疏矩阵 S_1, S_2, ..., S_I (每个对应一个硬件可加速的稀疏模式)

  1. 初始化:
     S_residual = W ⊙ M  (保留非零元素，其余为零)
     S_i = 0 for i = 1..I

  2. 迭代分解 (I 步):
     对于 step = 1 to I:
       a. 在 S_residual 上找一个结构化稀疏模式 P_sparse
          (使用贪心搜索: 对每个 block/row/col，找最重要的元素)

       b. 确定该模式的稀疏掩码 M_structured
          (2:4 结构化稀疏: 每个 4 元素块中保留 2 个最大值)

       c. 设置 S_step = S_residual ⊙ M_structured
          (只保留结构化模式中最重要的元素)

       d. 更新残差: S_residual = S_residual - S_step

  3. 返回: S_1, S_2, ..., S_I (按重要性递减排序)
```

**关键设计**：
- 每个分量 S_i 使用不同的结构化稀疏模式（如 2:4 行稀疏、2:4 列稀疏、块稀疏）
- 多个分量的组合可以更精确地近似原始非结构化稀疏
- 分量数 I 控制精度与计算开销的权衡

### 3. 结构化稀疏模式设计

TASDER 支持多种结构化稀疏模式，**每种模式都对应一种硬件加速能力**：

```
模式 1: 2:4 Row Sparsity (行稀疏)
  每个连续的 4 行中，保留 2 行最重要的权重
  硬件支持: NVIDIA A100 Sparse Tensor Core (Row-wise mode)
  加速比: 理论 2x

模式 2: 2:4 Column Sparsity (列稀疏)
  每个连续的 4 列中，保留 2 列最重要的权重
  硬件支持: NVIDIA A100 Sparse Tensor Core (Column-wise mode)
  加速比: 理论 2x

模式 3: 2:4 Block Sparsity (块稀疏)
  每个 2×4 块中，保留 2 个最重要的元素
  硬件支持: NVIDIA Ampere Sparse Tensor Core (General mode)
  加速比: 理论 2x

模式组合:
  使用 3 个分量 (行稀疏 + 列稀疏 + 块稀疏):
    → 有效稀疏度 ≈ 原始非结构化稀疏度
    → 计算: Y = X @ S_row + X @ S_col + X @ S_block
    → 每个分量都 2x 加速，总加速 ≈ 2x (因为 3 个分量串行计算)
```

### 4. 硬件感知调度

TASDER 的运行时调度器负责将分解后的分量分配到硬件：

```
TASDER 推理流程:

  输入: 激活 X, 非结构化稀疏权重 W, 分量 S_1, ..., S_I
  输出: Y

  for i in 1..I:
    Y_i = X @ S_i  # 每个分量使用结构化稀疏加速
  Y = Σ_i Y_i      # 求和（计算量很小）

  调度优化:
    - 分量按重要性排序（最重要的先算，可以 early exit）
    - 分量间允许并行计算（使用多个 CUDA stream）
    - 当某个分量的贡献 < 阈值时，提前终止剩余分量的计算
```

## 实现细节

TASDER 基于 PyTorch 和 CUDA 实现，核心组件包括：

**PSA 分解器**：运行在 CPU 上的离线工具，将预训练的稀疏模型分解为多个结构化稀疏分量。分解过程一次性完成，产物（分量矩阵）用于在线推理。

**Sparse GEMM Kernels**：使用 NVIDIA cuSPARSELt 库实现结构化稀疏矩阵乘法。cuSPARSELt 支持 2:4 结构化稀疏的 INT8/FP16/FP32 GEMM。

**调度器**：管理多分量 GEMM 的并行执行。使用 CUDA stream overlap 多个分量的计算，减少串行开销。

**精度监控**：运行时监控各分量累积输出与原始输出的差异，当累积误差超过阈值时停止计算剩余分量。

## 实验结果

### 测试环境
- NVIDIA A100 80GB（Sparse Tensor Core）
- 测试模型：ResNet-50、ViT-B/16、LLaMA-2 7B

### ImageNet 分类精度

| 稀疏配置 | ResNet-50 Top-1 | ViT-B/16 Top-1 |
|---------|----------------|---------------|
| Dense (baseline) | 76.2% | 79.9% |
| 非结构化 2:4 (50%) | 75.8% | 79.5% |
| 结构化 2:4 (硬件原生) | 74.1% | 77.2% |
| TASDER 2:4 (1 分量) | 74.3% | 77.4% |
| TASDER 2:4 (3 分量) | 75.5% | 79.1% |
| TASDER 2:4 (5 分量) | 75.7% | 79.3% |

### LLaMA-2 7B 困惑度

| 稀疏配置 | PPL (Wikitext-2) | 困惑度损失 |
|---------|----------------|----------|
| Dense | 5.61 | - |
| 非结构化 2:4 (50%) | 5.68 | +0.07 |
| 结构化 2:4 (硬件原生) | 5.87 | +0.26 |
| TASDER 2:4 (3 分量) | 5.73 | +0.12 |
| TASDER 2:4 (5 分量) | 5.70 | +0.09 |

### 推理吞吐量（A100）

| 模型 | 配置 | Throughput (samples/s) | 加速比 |
|------|------|----------------------|--------|
| ResNet-50 | Dense | 3,200 | 1x |
| ResNet-50 | 非结构化 2:4 | 3,400 (无加速) | 1.06x |
| ResNet-50 | TASDER 2:4 (3 分量) | 6,200 | 1.94x |
| ViT-B/16 | Dense | 890 | 1x |
| ViT-B/16 | TASDER 2:4 (3 分量) | 1,720 | 1.93x |
| LLaMA-2 7B | Dense | 142 | 1x |
| LLaMA-2 7B | TASDER 2:4 (3 分量) | 285 | 2.01x |

### 消融实验

- 分量数的影响：3 分量达到精度-速度的最佳平衡点；5 分量精度接近非结构化但计算开销增加
- 稀疏度缩放：2:4 → 4:8 → 1:2，稀疏度越高，TASDER 相对非结构化的优势越大
- 早期终止：当累积分量达到 95% 精度时停止，额外节省 25-35% 计算

## 潜在问题与局限性

1. **多分量累加的计算开销**：当使用 3+ 个分量时，多个 GEMM 的串行计算开销不可忽视。如果分量数为 3，总计算量约为 dense 的 1.5 倍，即使每个 2x 加速，总加速比也只有 1.5x 而非 2x

2. **离线分解的适用性**：PSA 分解需要在推理前完成，对于需要动态调整稀疏模式的场景（如渐进式训练）不适用

3. **对其他稀疏硬件的泛化**：TASDER 依赖 NVIDIA A100 的 2:4 结构化稀疏支持，对 AMD ROCm、国产 GPU 等其他硬件的适配需要重新设计

4. **极端稀疏度**：当稀疏度超过 90% 时（极激进剪枝），结构化稀疏的精度损失可能无法通过分量分解来弥补

## 未来工作

## 个人评注

TASDER 是一篇很有理论野心的论文，试图在非结构化稀疏（精度高）和结构化稀疏（硬件友好）之间架起一座桥梁。分配律的应用是一个巧妙的数学 trick，但论文对这个 trick 的理论分析还不够深入——为什么分配律在这里有效？在什么条件下有效？这些理论问题值得更严谨的探讨。

PSA 算法的实际效果令人满意——3 分量的 TASDER 接近非结构化稀疏的精度，同时获得了接近 2x 的硬件加速。不过，3 个 GEMM 串行执行的实现略显低效，一个更优的方案应该是将多个分量融合到同一个 kernel 中执行（类似 weight-only 量化中的 multi-component GEMM fusion）。

总体而言，TASDER 代表了一个值得关注的研究方向：将高灵活性的稀疏性与高效率的硬件加速结合，是未来高效神经网络推理的重要路径。
