## 一、背景

图神经网络（GNN）在图分析任务中表现优异，已被广泛应用。对于大规模图，mini-batch 训练是标准做法，而 data parallelism 是将 mini-batch 训练扩展到多 GPU 的主流方式。在 data parallel 训练中，每个 GPU 独立采样各自的 micro-batch，独立加载特征并计算梯度。现有系统如 DGL、PyTorch Geometric、AliGraph 均采用这一范式。

然而，data parallel 训练存在严重的冗余问题：不同 GPU 采样的 micro-batch 之间，k-hop 邻居存在大量重叠，导致采样、特征加载和计算三个阶段均出现冗余工作。实验表明，4 GPU 下 data parallelism 相比单一 mini-batch，计算量增加高达 1.2×，特征加载量增加高达 2.5×。

---

## 二、要解决的问题

1. **Data parallel 的冗余开销**：不同 GPU 的 micro-batch 在 k-hop 邻居上大量重叠，同一顶点的特征被多个 GPU 重复加载，隐藏表示被重复计算。
2. **Push-pull parallelism（P3）的局限**：P3 通过将第一层特征按 GPU 分片减少了特征传输，但引入了昂贵的 activation shuffle 开销，尤其在 GAT 等生成大量中间激活的模型上代价显著。
3. **GPU 缓存方案的不足**：Quiver 等系统通过分布式缓存减少加载时间，但未消除计算冗余，且在特征无法完全缓存的大图上效果有限。
4. **朴素 split parallelism 的挑战**：直接在线运行 min-cut 图划分是 NP-hard 问题，计算成本过高；而使用离线全图划分（Edge 方案）不考虑实际采样模式，导致 shuffle 开销和负载不均衡超过了消除冗余的收益。

---

## 三、洞察与设计

**关键洞察**：在随机采样的 mini-batch 中，顶点和边被采样到的概率是可以通过预采样统计估计的；利用这些概率权重对全图进行离线划分，可以在线阶段以常数时间完成 split 分配，同时在概率意义上最小化跨 split 通信并平衡负载。

基于这一洞察，GSplit 提出了 **split parallelism**——一种新的混合并行范式：

- **核心思路**：每次迭代只采样一个 mini-batch（而非每个 GPU 各采一个 micro-batch），然后将其实时划分为不重叠的 splits，每个 split 分配给一个 GPU。每个顶点的采样、加载和计算只由一个 GPU 负责，彻底消除冗余。
- **概率划分算法**：分为离线和在线两部分：
  - **离线**：通过 pre-sampling（运行若干 epoch 的采样）统计每个顶点和边被采样的频率，以此作为权重，运行加权 min-edge-cut 图划分（如 METIS），得到全局划分函数 f_G。
  - **在线**：每次迭代直接用 f_G 将采样到的顶点映射到对应 GPU，是 embarrassingly parallel 的常数时间操作。
- **Layer-centric API**：GSplit 提供 split/shuffle API，隐藏跨 GPU 的数据交换细节，保持与现有单 GPU 优化内核（采样、训练）的兼容性。

---

## 四、实现细节

- **Pre-sampling 阶段**：运行 10 个 epoch 的采样，统计顶点权重 w_V(v) = k_v/N 和边权重 w_E(e) = k_e/N，构建加权图 G_w。
- **图划分**：使用 METIS 对 G_w 进行加权 min-edge-cut 划分，生成全局划分函数 f_G。划分时间：Orkut 14s，Papers100M 78s，Friendster 534s（一次性成本）。
- **在线 split**：`split()` 函数根据 f_G 将 mixed frontier 中的顶点分为 local 和 remote，构建 shuffle index（gather/scatter 索引），用于高效的 sparse all-to-all 通信。
- **采样流程**（Algorithm 1）：逐层从上到下采样，每层先 `sample_layer()` 得到 mixed frontier，再 `split()` 分离 local/remote 顶点并 shuffle。
- **训练流程**（Algorithm 2）：逐层从下到上，每层先 `shuffle()` 交换特征/激活，再用标准 GNN layer 内核计算。反向传播沿相同路径反向进行。
- **缓存一致性**：f_G 同时决定每个 GPU 缓存哪些顶点的输入特征，确保缓存与 split 分配一致。
- **多主机扩展**：主机间使用 data parallelism，主机内使用 split parallelism，通过 NCCL 进行通信。
- 实现基于 DGL，使用相同的采样和训练内核。

## 五、实验结果

**硬件**：AWS EC2 p3.8xlarge（4× V100 16GB，NVLink），p3.16xlarge（8× V100）。

**数据集**：

| 数据集 | 节点数 | 边数 | 特征维度 | 类型 |
|--------|--------|------|----------|------|
| Orkut | 3.1M | 120M | 512 | 无向 |
| Papers100M | 111M | 1.6B | 128 | 有向 |
| Friendster | 65M | 1.9B | 128 | 无向 |

**端到端性能**（4 GPU，默认配置）：

| 图 | 对比系统 | GSplit 加速比（GraphSAGE） | GSplit 加速比（GAT） |
|----|----------|--------------------------|---------------------|
| Orkut | DGL | 4.4× | 3.6× |
| Orkut | Quiver | 1.1× | 1.1× |
| Orkut | P3* | 0.8× | 1.9× |
| Papers100M | DGL | 1.4× | 1.2× |
| Papers100M | Quiver | 1.9× | 1.4× |
| Friendster | DGL | 2.9× | 1.7× |
| Friendster | Quiver | 1.6× | 1.2× |

**总体**：GSplit 比 DGL 快最高 4.4×（平均 2.5×），比 P3* 快最高 4.1×（平均 2.4×），比 Quiver 快最高 1.9×（平均 1.4×）。

**划分算法对比**：GSplit 的概率划分比 Edge 方案端到端快最高 1.7×；跨 split 边比例从 Random 的 ~75% 降至 ~5%（Papers100M）。

**精度**：GSplit 与 DGL 在 Papers100M 上的 GraphSAGE/GAT 训练精度曲线完全吻合，不引入算法偏差。

## 六、批判性分析

1. **基线公平性存疑**：P3 的源码不公开，论文自行实现了 P3*，这可能未能完全复现 P3 的优化（如分布式场景下的通信优化），使得与 P3* 的对比结论可靠性打折扣。

2. **硬件环境较老旧**：实验全部在 V100（2017 年架构）上进行，NVLink 带宽和 GPU 算力远低于当前主流的 A100/H100。在高带宽互联下，shuffle 成本占比会显著降低，data parallel 的冗余加载也可能被更快的 PCIe/NVLink 掩盖，GSplit 的优势幅度可能缩小。

3. **加速比波动大**：在 Orkut+GraphSAGE 场景下 GSplit 甚至比 P3* 慢（0.8×），论文对此解释不够深入。当特征可完全缓存且模型计算量轻时，split parallelism 引入的 shuffle 开销可能无法被消除的冗余所弥补。

4. **Pre-sampling 假设的脆弱性**：概率划分依赖于采样模式的稳定性——pre-sampling 阶段的统计需要反映实际训练中的采样分布。论文假设"足够多 epoch 的 pre-sampling"可保证这一点，但仅用了 10 个 epoch，且未分析当训练中采样分布发生漂移（如因 curriculum learning 或 adaptive sampling）时划分质量的退化。

5. **数据集代表性有限**：仅用 3 个图，且 Orkut 和 Friendster 是合成特征（512/128 维随机向量）。真实场景的特征维度和访问模式可能差异很大。Papers100M 是唯一有真实特征的数据集。

6. **多主机方案退化为混合方案**：在多主机场景下 GSplit 回退到主机间 data parallelism + 主机内 split parallelism，并未完全解决跨主机的冗余问题。论文也承认在低带宽互联下效果受限。

## 七、AI Infra / MLSys 视角

1. **冗余消除的通用思路**：GSplit 的核心思想——通过统计工作负载分布进行概率性优化——可以迁移到其他存在冗余访问的 AI 系统场景。例如，在 Mixture-of-Experts（MoE）训练中，不同 GPU 上的 expert 路由可能导致重复的 token dispatch；在 KV cache 管理中，不同请求对相同 prefix 的重复计算也可以用类似的预分析+划分思路优化。

2. **与 GNN 在推荐系统中的应用契合**：大规模推荐系统广泛使用 GNN（如 PinSage、AliGraph），GSplit 的技术可直接应用于这类生产场景，尤其是在特征加载成为瓶颈的超大图上。

3. **概率划分 vs. 确定性划分的 trade-off**：GSplit 展示了一个重要的系统设计哲学——在动态工作负载下，用概率保证替代确定性保证可以大幅降低运行时开销。这个思路可以应用于动态 batching、请求调度等 LLM serving 场景。

4. **值得跟进的方向**：
   - 在 A100/H100 + NVSwitch 等现代硬件上验证 split parallelism 的收益是否依然显著
   - 将概率划分思想扩展到异构 GNN 训练（如 RGCN）和动态图场景
   - 探索 split parallelism 与 pipeline parallelism 的结合——论文提到 pipelining 是正交技术，但未实际评估

---

## 八、总结

GSplit 提出了 split parallelism，一种面向 mini-batch GNN 训练的新型混合并行范式，通过将每个 mini-batch 实时划分为不重叠的 splits 分配给不同 GPU，彻底消除了 data parallelism 中的冗余采样、加载和计算。其核心贡献是一个基于 pre-sampling 的概率划分算法，将 NP-hard 的在线划分问题转化为 embarrassingly parallel 的常数时间映射，同时在概率意义上最小化通信并平衡负载。系统在 Orkut、Papers100M、Friendster 三个大图上比 DGL 快最高 4.4×，比 Quiver 快最高 1.9×。主要局限在于：当 shuffle 成本主导时优势缩小（如小图+轻模型场景）、实验硬件较老、多主机扩展仍需混合方案。
