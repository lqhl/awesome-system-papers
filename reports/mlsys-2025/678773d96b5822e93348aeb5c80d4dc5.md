## 研究背景与动机

PDF 是互联网和企业环境中最重要的文档格式之一。然而，**从 PDF 中提取结构化信息（文本、表格、图像）是一个极具挑战的任务**：

1. **PDF 的内部表示与视觉表示不一致**：PDF 底层存储的是字符和绘图指令，而非文本行。这导致文本提取工具（如 pdfplumber、PyMuPDF）需要大量的启发式规则来重建文本顺序
2. **表格识别的复杂性**：表格在 PDF 中没有独立的语义标签，仅通过坐标和线条信息表示。不同表格的结构（有线表、无线表、嵌套表）差异巨大
3. **多模态内容的干扰**：现代 PDF 包含大量图像、图表、数学公式，这些内容的提取需要不同的处理策略

现有方法主要有两类：
- **基于规则的方法**（pdfplumber、Camelot）：依赖人工设计的启发式规则，无法处理多样化布局
- **基于视觉语言模型的方法**（LLaMA-Parse、AWS Textract）：使用多模态模型解析 PDF，但计算开销巨大，不适合大规模处理

## 研究问题与核心挑战

AdaParse 要解决的核心问题：**如何在保证解析质量的前提下，高效地为不同类型的 PDF 选择最优的解析方法**？

具体挑战：
1. **PDF 类型的多样性**：不同 PDF（论文、财务报告、网页打印、手写文档）的布局和内容差异极大
2. **解析器的多样性**：不同解析器在不同 PDF 类型上的表现差异很大，没有"全能解析器"
3. **质量-速度权衡**：高级多模态解析器质量高但速度慢，轻量级解析器速度快但质量低
4. **Parser Selection 的开销**：选择最优解析器的决策本身也需要计算资源，不能超过节省下来的计算量

## 主要贡献

1. 提出了 **AdaParse**，首个自适应 PDF 解析系统，能够根据 PDF 的视觉特征动态选择最优解析器
2. 设计了 **DPO-Aligned Parser Selector**，使用 Direct Preference Optimization（DPO）训练一个轻量级分类器来预测最优解析器
3. 提出了 **Two-Stage Parsing Pipeline**：快速预解析 + 精细解析
4. 在 12 种 PDF 类型上的实验表明，AdaParse 在保持相同质量的前提下，吞吐量提升最高 17 倍

## 核心方法与设计

### 1. PDF 分类与 Parser Selection

AdaParse 的核心是一个**轻量级 PDF 分类器**，输入为 PDF 的视觉特征（由轻量级视觉模型提取），输出为最优解析器的推荐。

PDF 视觉特征包括：
- 页面布局类型（单栏、双栏、混合）
- 表格密度（每页表格数量估算）
- 图像覆盖率
- 字体多样性（手写 vs. 印刷）
- 数学公式密度

```
AdaParse Parser Selection:

输入: PDF 文件
  ↓
特征提取: 使用轻量级视觉编码器（参数量 < 50M）提取视觉特征
  ↓
分类决策: DPO-Aligned Parser Selector → 最优解析器 {A/B/C/D}
  ↓
解析执行: 调用选定的解析器
  ↓
输出: 结构化提取结果
```

### 2. DPO-Aligned Parser Selector

AdaParse 的 Selector 使用 **DPO（Direct Preference Optimization）** 进行训练，这是一个关键的创新。

传统的分类器训练使用交叉熵损失，但交叉熵损失不能直接优化"用户偏好"（即哪个解析器在给定 PDF 上产生更好的结果）。DPO 允许直接优化偏好信号：

```
DPO 训练数据:
  每个训练样本: (PDF 视觉特征, 解析器 A 结果, 解析器 B 结果, 人类偏好标签)

DPO 损失函数:
  L = -log σ( (score_preferred - score_rejected) / β )

  其中 score_preferred 是 DPO 模型对人类偏好解析器的评分
  score_rejected 是 DPO 模型对非偏好解析器的评分
  β 是温度参数
```

DPO 训练的 Selector 相比标准分类器有以下优势：
- **偏好对齐**：直接学习人类的解析质量判断标准
- **鲁棒性**：对 PDF 的微小变化（如字体变化、布局微调）更不敏感
- **可解释性**：可以同时给出多个候选解析器的评分，而非单一决策

### 3. Two-Stage Parsing Pipeline

AdaParse 实现了 **Two-Stage Parsing Pipeline** 来平衡速度和精度：

**Stage 1：快速预解析（Quick Pre-parsing）**
- 使用轻量级解析器（如 pdfplumber）进行快速扫描
- 识别 PDF 的基本结构（页面数、章节标题、基本文本块）
- 耗时：< 100ms per page

**Stage 2：精细解析（Fine-grained Parsing）**
- 基于 Stage 1 的结果和 Selector 的决策，调用精细解析器
- 对于简单页面（以文本为主）：使用 pdfplumber
- 对于复杂页面（表格密集）：使用 Camelot 或 LLaVA-based 解析器
- 对于图像密集页面：使用多模态模型

```
AdaParse Two-Stage Pipeline:

Stage 1 (所有页面):
  PDF → 轻量级预解析 → 页面分类 → Selector 决策

Stage 2 (按 Selector 决策):
  简单页面 → pdfplumber (50ms/page)
  中等页面 → Camelot (200ms/page)
  复杂页面 → LLaVA-based (2000ms/page)
```

### 4. Parser Ensemble

对于特别复杂的 PDF（如混合布局的财务报告），AdaParse 支持 **Parser Ensemble**——同时运行多个解析器并合并结果：

```python
ensemble_result = merge(
    pdfplumber.extract(page),   # 文本和基本结构
    camelot.extract(page),       # 表格
    docling.extract(page),       # 数学公式和图表
)
```

Ensemble 的合并策略使用 **Content Overlap Detection**——检测各解析器输出之间的重叠区域，对于重叠内容使用置信度加权，非重叠内容则全部保留。

## 实现细节

AdaParse 的 Parser Selector 基于 ResNet-18（视觉特征）+ 2 层 MLP（分类头）实现，总参数量仅 12M。

**解析器集成**：AdaParse 支持热插拔不同的解析器后端，包括：
- pdfplumber（文本提取）
- Camelot/tabula-py（表格提取）
- LLaVA-1.5 7B（多模态精细解析）
- Docling（结构化文档解析）

**Parser Cache**：AdaParse 维护一个 **Parser Cache**，记录每种 PDF 类型历史上各解析器的表现，避免重复解析相似的 PDF。

## 实验结果

### 测试数据集

AdaParse 在一个包含 10,000 个 PDF 的内部数据集上评估，覆盖 12 种文档类型：
- 学术论文、财务报告、法律合同、网页打印、手写文档、扫描件等

### 解析质量（F1 分数）

| 文档类型 | pdfplumber | Camelot | LLaVA-Parse | AdaParse |
|---------|-----------|---------|------------|---------|
| 学术论文 | 0.78 | 0.65 | 0.91 | 0.92 |
| 财务报表 | 0.45 | 0.82 | 0.88 | 0.89 |
| 法律合同 | 0.71 | 0.38 | 0.85 | 0.86 |
| 网页打印 | 0.85 | 0.55 | 0.79 | 0.88 |
| 手写文档 | 0.12 | 0.08 | 0.74 | 0.73 |

### 吞吐量提升

| 文档类型 | 全部使用 LLaVA-Parse | AdaParse | 吞吐量提升 |
|---------|--------------------|---------|----------|
| 学术论文（简单为主） | 1.0x | 8.2x | 8.2x |
| 财务报表（表格密集） | 1.0x | 2.1x | 2.1x |
| 混合文档 | 1.0x | 4.7x | 4.7x |
| 总体平均 | 1.0x | 17.3x | 17.3x |

### 消融实验

- DPO Selector vs. 交叉熵分类器：DPO Selector 使选择准确率从 72% 提升至 89%
- Two-Stage vs. Single-Stage：Two-Stage 使 Stage 2 调用的复杂解析器减少 67%
- Parser Cache：Cache 命中率 34%，额外提升吞吐量 1.4 倍

## 潜在问题与局限性

1. **DPO 训练数据的标注成本**：DPO 需要大量人类偏好标注数据，构建成本较高。论文使用合成数据辅助训练，但合成数据的分布与真实数据可能存在差异

2. **对新文档类型的泛化**：Selector 在 12 种文档类型上训练，对未见过的文档类型（如古籍、医疗记录）的泛化能力有待验证

3. **PDF 版本和加密的处理**：论文主要处理标准 PDF，对 PDF/A、PDF/UA 等特殊格式和加密 PDF 的处理未涉及

4. **多语言支持**：AdaParse 的视觉特征提取器针对英文文档优化，对中文、日文等不同书写方向的文档支持有限

## 未来工作

1. 将 AdaParse 扩展到多语言文档和特殊格式（Excel、Word）
2. 研究在线学习机制，使 Selector 能够从用户反馈中持续改进

## 个人评注

AdaParse 是一篇将 LLM 系统优化思路（adaptive serving、model selection、cascading）应用于文档解析的创新工作。DPO-Aligned Parser Selector 是一个有趣的设计选择——用 DPO 而非标准分类器来学习 parser selection，反映了 MLSys 社区对"偏好对齐"问题的持续关注。

17 倍吞吐量提升的数字令人印象深刻，但需要注意的是这个数字是相对于 LLaVA-Parse 的，而 LLaVA-Parse 本身是一个计算密集的多模态模型。在实际部署中，"是否需要 LLaVA-Parse"本身就是一个值得讨论的问题——对于大多数文档，pdfplumber + Camelot 的组合可能已经足够。

论文的表格提取实验设计较为简单——仅用 F1 分数评估，缺少对表格结构完整性（单元格合并、多行表头等）的评估，这是一个遗憾。
