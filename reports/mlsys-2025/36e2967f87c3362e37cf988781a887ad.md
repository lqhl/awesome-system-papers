## 1. 研究背景与动机

知识图谱（Knowledge Graph, KG）以（头实体，关系，尾实体）三元组形式表示结构化知识，是问答系统、推荐系统和知识推理的重要基础设施。知识图谱嵌入（KGE）将实体和关系映射到低维向量空间，是 KG 补全和推理的主流方法。

Translation-based KGE 模型（如 TransE、TransR、TransH、TorusE）因简单高效而广泛应用，但其训练过程计算密集且内存开销大。传统实现将三元组存储为密集矩阵，在训练中需要大量细粒度的 gather-scatter 操作，成为性能瓶颈。具体表现为：
- 嵌入梯度的反向计算占 CPU 训练时间的约 40%
- 嵌入梯度计算位列大多数 Translation 模型的前三大 CPU 密集函数之一

然而，现有 KGE 框架（如 TorchKGE、PyKeen）均未利用稀疏矩阵操作进行训练，完全沿用了 PyTorch 的标准 embedding 模块。

## 2. 研究问题与核心挑战

### 2.1 细粒度 Gather-Scatter 操作的开销

以 TransE 为例，传统训练流程对每个 batch 的三元组执行：
1. **Forward**: 从 embedding 表中 gather head、tail、relation 的嵌入向量
2. **Backward**: 将梯度 scatter 回对应的 embedding 行

这些逐个操作产生了大量小粒度的内存访问，远不如批量矩阵运算高效。

### 2.2 不同模型的差异化表示

每种 translation 模型对 translation 的表示方式不同：
- **TransE**：使用单一嵌入空间，head + relation ≈ tail
- **TransR**：在关系特定空间中进行 translation，需要投影矩阵
- **TransH**：在超平面上进行 translation，引入法向量
- **TorusE**：在环形空间中进行 translation

这些差异使得统一的稀疏化框架设计具有挑战性。

## 3. 主要贡献

1. **稀疏化 formulation**：将 translation-based KGE 模型（TransE、TransR、TransH、TorusE）映射为稀疏-密集矩阵乘法（SpMM），通过 incidence matrix 表示实现一次性 gather/scatter。
2. **统一稀疏框架 SpTransX**：支持多种 translation 模型复用同一稀疏计算内核，无需针对每个模型重新设计。
3. **优化实现**：结合 iSpLib（CPU）和 DGL g-SpMM（GPU）的高性能稀疏内核，配合 streaming embedding 机制支持超大规模 KG 训练。
4. **显著的端到端加速**：CPU 上最高 5.3 倍加速，GPU 上最高 4.2 倍加速，同时大幅降低内存占用。

## 4. 核心方法与设计

### 4.1 Incidence Matrix 表示

核心洞察：将 KG 三元组编码为稀疏 incidence matrix，通过一次 SpMM 操作替代多次 gather 操作。

**h-t computation**（head - tail）：
- Incidence matrix $A \in \{-1, 0, 1\}^{M \times N}$，每行对应一个三元组，head 索引为 +1，tail 索引为 -1
- $h - t = A \cdot E$（E 为实体嵌入矩阵）
- 每行恰好包含两个非零元素

**hrt computation**（head + relation - tail）：
- 将实体和关系嵌入 stack 到同一矩阵 $E' \in \mathbb{R}^{(N+R) \times d}$
- Incidence matrix 扩展为 $A' \in \{-1, 0, 1\}^{M \times (N+R)}$，每行包含 head（+1）、relation（+1）和 tail（-1）的系数

### 4.2 TransE 稀疏化

TransE 的 score function: $\| \vec{h} + \vec{r} - \vec{t} \|$
- 直接使用 hrt computation 方法
- score 函数应用 L1/L2 范数后处理

### 4.3 TransR 稀疏化

TransR 在关系特定空间进行 translation：$\mathbf{M}_r \vec{h} + \vec{r} \approx \mathbf{M}_r \vec{t}$

关键代数观察：经过重排后，TransR 的表达式包含 $(h - t)$ 项，因此可复用 h-t computation，只需在投影后执行一次。该性质使 TransR 的稀疏化在计算上几乎与 TransE 等价。

### 4.4 TransH 稀疏化

TransH 引入超平面约束：$\vec{h}_\perp + \vec{d}_r \approx \vec{t}_\perp$，其中 $\vec{h}_\perp = \vec{h} - (\vec{w}_r^\top \vec{h}) \vec{w}_r$

通过代数变换，最终可分解为两个 h-t computation 的组合，天然适配 SpTransX 框架。

### 4.5 TorusE 稀疏化

TorusE 使用环形空间距离，表达式与 TransE 相同但基于模运算。直接使用 hrt computation 方法。

### 4.6 框架架构

```
Dataset → Dataloader → Incidence Matrix Builder → SpTransX Model
                                                      ↓
                                              iSpLib (CPU) / DGL g-SpMM (GPU)
                                                      ↓
                                              Optimized SpMM Kernels
```

支持从磁盘流式加载嵌入（通过 PyTorch memory-mapped tensors），使超大规模 KG 的训练成为可能。

## 5. 实验设置

**硬件**：NERSC Perlmutter，单卡 NVIDIA A100-SXM4 40GB（GPU），AMD EPYC 7763 Milan 64核 512GB DDR4（CPU）。

**数据集**：7 个标准 KG 数据集，涵盖 FB15K、FB15K-237、WN18、WN18RR、FB13、YAGO3-10、BIOKG。

**基准框架**：TorchKGE（最流行的 KGE 训练框架）、DGL-KE、PyTorch Geometric。

**配置**：学习率 0.0004，margin 0.5，200 epochs；batch size 和嵌入维度根据 GPU 内存最大化为原则选择。

## 6. 实验结果

### 6.1 端到端训练时间

以 TransE 在 A100 GPU 上为例（200 epochs 平均时间）：
- **Forward**: SparseTransX 18.2s vs TorchKGE 48.8s（2.68×）
- **Backward**: SparseTransX 17.49s vs TorchKGE 89.51s（5.12×）
- **总 Step**: SparseTransX 0.4s vs TorchKGE 0.45s（1.13×）

反向计算的加速比最高，这是因为 SpMM 将细粒度的梯度 scatter 操作合并为了单一批量操作。

### 6.2 CPU vs GPU 加速

**CPU（A100 相比 TorchKGE）**：
- TransE: 5.3×（Forward: 2.2×，Backward: 5.5×）
- TransH: 4.1×
- TransR: 2.4×
- TorusE: 4.5×

**GPU（A100 相比 TorchKGE）**：
- TransE: 4.2×（Forward: 2.7×，Backward: 5.1×）
- TransH: 3.7×
- TransR: 2.1×
- TorusE: 3.9×

### 6.3 内存占用

SparseTransX 在 GPU 上的峰值内存占用显著低于 TorchKGE。以 TransR 在 FB15K-237 上为例：TorchKGE 在 batch size 32768 时 OOM，而 SparseTransX 可以在相同 batch size 下正常运行。

### 6.4 准确性验证

论文在链接预测任务上验证了稀疏实现与原始实现的数值一致性，结果显示无显著精度损失。

## 7. 潜在问题与局限性

1. **仅支持 Translation-based 模型**：框架目前支持 TransE、TransR、TransH、TorusE，对于 DistMult、ComplEx、RotatE 等非 translation 模型的支持需要额外的 formulation 工作（论文仅在 Appendix D 中简要讨论）。
2. **CPU 实现依赖 iSpLib**：CPU 高性能 SpMM 依赖特定的库（iSpLib），而非通用的 MKL/cuSPARSE，可能增加部署门槛。
3. **单 GPU 局限**：论文明确指出聚焦于单 GPU 稀疏技术，未展示多 GPU 分布式训练的效果（尽管框架声称支持）。
4. **准确性对比不充分**：论文未提供在链接预测标准指标（MRR、Hit@10）上的全面对比，仅验证了数值一致性。
5. **与 GNN 方法的关系未充分讨论**：论文与 GNN 领域的稀疏矩阵应用（PyG、DGL）做了对比，但两者在计算图和优化策略上的差异值得更深入的分析。

## 8. 未来工作

## 9. 个人评注

SparseTransX 是一篇扎实且具有工程价值的论文，其核心贡献是展示了将 KGE 训练中的细粒度 gather/scatter 操作合并为 SpMM 的可行性。论文的核心洞察——h-t 和 hrt computation 可以统一通过 incidence matrix + SpMM 表达——是简洁而优雅的数学重构。

从系统角度看，这项工作体现了 MLSys 社区的一个常见模式：识别出当前实现中的细粒度冗余操作（gather/scatter），通过数学等价变换合并为粗粒度的批量操作（SpMM），从而释放硬件批量计算能力的工程思路。这一思路在 GPU 上的 GEMM 优化中已被充分验证，论文将其延伸到了 KGE 领域。

然而，论文的创新性相对有限——核心技术（SpMM 替换 gather/scatter）是已知技术在 KG 领域的应用。真正的贡献在于完整实现了四种模型的稀疏化 formulation，并构建了可用的开源框架。论文标题中 "Efficient Training" 的定语值得注意：优化的是训练而非推理阶段。

从实践角度看，对于需要频繁重训练知识图谱嵌入的从业者，SpTransX 是一个有价值的工具——尤其在 GPU 内存受限或训练时间敏感的场景下。但对于仅需推理的场景，现有密集实现通常已足够高效，无需引入稀疏化框架的额外复杂度。
