## 一、背景

随着 LLM 应用对长上下文的需求不断增长（few-shot prompting、chain-of-thought、agent 多轮交互等），传统 Transformer 的二次计算复杂度和线性增长的 KV cache 内存成为瓶颈。State Space Models（SSMs，如 Mamba）以线性计算复杂度和固定大小的 recurrent state 提供了更高效的替代方案，但在 recall 和 in-context learning 能力上有所不足。因此，Hybrid LLMs（如 Jamba、Zamba、Nemotron-H）将少量 Attention 层与大量 SSM 层混合（通常 1:6~1:10 比例），在保持模型质量的同时降低推理成本，已在业界广泛部署。

Prefix caching 是 LLM serving 中跨请求复用共享前缀的关键优化，能显著降低 TTFT 和提升吞吐。vLLM、SGLang 等系统已在 Transformer 推理中成功应用此技术。

---

## 二、要解决的问题

Hybrid LLM 的 SSM 层特性使得现有 prefix caching 系统完全失效：

1. **SSM state 的 "all or nothing" 复用**：SSM state 是就地更新的（in-place update），无法像 KV cache 那样通过 tensor slicing 回滚到任意前缀位置。只有精确匹配整个序列的 SSM state 才能被复用，不支持部分前缀匹配。

2. **Cache 利用率极低**：为最大化复用机会，需要对 SSM state 做细粒度 checkpoint（每 x 个 token 保存一次）。但实验表明，block size 为 32 时，KV 的复用率为 25%，而 SSM state 复用率仅 0.4%，差距 65×。大量低价值 SSM state 充斥 cache。

3. **内存消耗爆炸**：SSM state 大小与序列长度无关但本身很大（比单个 token 的 KV 大 10-100×）。细粒度 checkpoint 导致 7B 模型单条 10K token 序列的 cache 占用达 17.4GB，是同规模 Transformer 的 3.3×，迅速耗尽 GPU HBM。

4. **现有 eviction 策略不适用**：LRU 等基于 recency 的策略无法区分不同类型 cache entry 的计算收益差异——KV 的大小与计算节省成正比，而 SSM state 大小固定、与序列长度/计算节省无关。

## 三、洞察与设计

**关键洞察**：尽管未来请求不可预知，但 SSM state 的复用潜力可以通过前缀复用场景的分类学来充分估计——token 冗余分为两类：(1) 纯输入共享前缀（如 system prompt，跨多请求重复出现），和 (2) 输入+输出共享（如对话历史，每轮在末尾追加）。针对这两类场景，只需缓存少量高价值的 SSM state（分支点和最后解码 token 处），而非细粒度全量 checkpoint。此外，Hybrid 模型中不同层类型的 cache entry 在内存/计算收益上存在显著差异，eviction 决策应考虑 FLOP efficiency 而非仅 recency。

### 系统设计

**Marconi** 是首个专为 Hybrid LLM 设计的 prefix caching 系统，核心包含两个策略：

**1. Judicious Admission（审慎准入）**
- 使用 radix tree 记录请求历史，追踪序列重叠关系
- 对于"纯输入"前缀：通过 speculative insertion（在 prefill 前模拟插入）识别分支点，仅在分支点处 checkpoint SSM state
- 对于"输入+输出"前缀：仅缓存最后解码 token 处的 SSM state（对话通常从末尾续写而非中间分叉）
- 每条序列最多准入 2 个 SSM state，大幅减少低价值 entry

**2. FLOP-aware Eviction（计算感知驱逐）**
- 定义 FLOP efficiency = 总计算节省 / 内存占用，衡量 cache entry 的性价比
- 驱逐时综合考虑 recency 和 FLOP efficiency：$S(n) = recency(n) + \alpha \cdot flop\_efficiency(n)$
- SSM layer 的 FLOP efficiency 随序列长度线性增长（长序列 entry 更值得保留），Attention layer 近乎恒定
- α 参数通过 bootstrap 阶段自动调优：积累足够请求后，异步 grid search 选择最优值

**3. 统一管理**
- 在同一 radix tree 中同时管理 KV 和 SSM state，确保每个 cache entry 的所有层 state 一致
- 驱逐中间节点时释放 SSM state，KV 被子节点吸收

## 四、实现细节

- **SSM state checkpoint 获取**：对支持 chunked state passing 的模型（Mamba-2），利用分块 prefill 的中间 state，取倒数第二个 chunk 的 state（可能差几个 token，引入极小误差）；对不支持的模型（Mamba-1、Jamba），执行两遍 prefill
- **Radix tree 管理**：每条边关联 KV 和 SSM state；多子节点的内部节点代表"纯输入"共享前缀（不参与驱逐）；单子节点中间节点可被驱逐
- **Timestamp 更新策略**：cache hit 时仅更新被访问节点的时间戳，不更新祖先节点（因 SSM state 不被祖先复用，祖先 KV 在驱逐时会被子节点吸收）
- **α 自动调优**：启动时 α=0（LRU），首次驱逐后进入 bootstrap 期（5-15× 首次驱逐前请求数），收集完成后多核并行 grid search，通常仅需数秒
- 开源实现：https://github.com/ruipeterpan/marconi，许可证 CC BY-NC

## 五、实验结果

**实验平台**：AWS p4d.24xlarge（8× A100-40GB），96 vCPU，1152GB RAM。模型：7B Hybrid（4 Attention + 24 SSM + 28 MLP layers），以及 Jamba-1.5-Mini（12B active/52B total）。FP16 精度。

**Workloads**：LMSys（长输出）、ShareGPT（短输出）、SWE-Bench（agent 场景，长输入）

### 主要结果

| 指标 | LMSys | ShareGPT | SWE-Bench |
|------|-------|----------|-----------|
| Token hit rate 提升（vs vLLM+） | 4.5× | 7.3× | 34.4× |
| P95 TTFT 降低（vs vanilla） | 36.9% (281.4ms) | 73.2% (106.3ms) | 46.8% (617.0ms) |
| P95 TTFT 降低（vs vLLM+） | 36.1% (275.4ms) | 71.1% (103.3ms) | 46.8% (617.0ms) |
| Token hit rate 提升（vs SGLang+, P95） | 45.6% | 19.0% | 219.7% |

### FLOP-aware Eviction 分析（SWE-Bench）

- SGLang+ 整体 token hit rate 16.4%，Marconi 32.7%（+99.4%）
- 短序列（<7K token）hit rate 降低至多 3.0%，长序列（>7K token）hit rate 提升至多 25.5%
- FLOP 节省整体提升 90.3%
- P5 TTFT 略差 6.3%（绝对值仅 2.1ms），P50/P95 TTFT 分别降低 13.4%/22.0%

### Microbenchmarks

| 维度 | 发现 |
|------|------|
| Cache 竞争度 | 中等竞争（100GB）时收益最大（+68.3%），低竞争时差距缩小 |
| SSM 层比例 | Attention:SSM = 1:8 时 vs vLLM+ 提升 2.6×，纯 Transformer 无差异 |
| SSM state 维度 | d_state 从 16→128，vs vLLM+ 提升从 5.7×→35.4× |
| 请求到达速率 | 更高竞争（更多 session/s）时 Marconi 相对优势增大 |

## 六、批判性分析

1. **仅模拟评估，无真实端到端 serving**：核心实验基于 trace replay 的 cache 模拟器完成，只有 TTFT 数据来自真实 GPU 推理（Jamba-1.5-Mini 部分实验）。token hit rate 到实际延迟/吞吐的转化存在误差——prefill 并非总是 compute-bottlenecked（短序列可能 memory-bound），cache 管理本身的开销（radix tree 操作、speculative insertion、两遍 prefill）未被量化。

2. **α 调优的鲁棒性存疑**：bootstrap 期间的 workload 是否能代表后续 workload 分布？论文假设 workload 分布相对稳定，但实际场景中 workload 可能随时间剧烈变化（如白天 chatbot 流量 → 夜间 batch 任务）。论文未讨论 α 的动态适应性或 workload shift 下的退化情况。

3. **基线设置偏向 Marconi**：vLLM+ 被设定为"每个 token block 都 checkpoint SSM state"——这是最朴素的策略，任何稍有优化的 admission 策略都能轻松超越。SGLang+ 已经使用了 Marconi 的 judicious admission，差距主要来自 FLOP-aware eviction，改进幅度小得多（19-219%）。缺少与通用 cost-aware eviction（如 GDSF）的公平对比。

4. **两遍 prefill 的开销被轻描淡写**：对不支持 chunked state passing 的模型需要做两遍 prefill 来获取中间 SSM state，这本身就是一笔可观的计算开销。论文仅提到"slight drawbacks"但未给出量化数据。

5. **纯输入前缀的冷启动问题**：纯输入类型的共享前缀需要第二次出现时才被识别、第三次出现时才能被复用。对于长尾分布的 system prompt 场景（大量不同 prompt 各出现少数几次），这意味着大部分前缀永远不会被 Marconi 的 SSM cache 命中。

## 七、AI Infra / MLSys 视角

1. **Hybrid LLM serving 的系统性挑战被首次系统化**：本文清晰地分类了 SSM state 的三个核心属性（固定大小、就地更新、体积庞大）及其对 prefix caching 的影响。这个分析框架对设计支持 Hybrid 模型的推理系统有普遍参考价值。

2. **FLOP efficiency 度量值得推广**：将 cache entry 的计算收益归一化到内存占用，这个度量不仅适用于 Hybrid 模型的 prefix caching，也可迁移到任何存在异构 cache entry 的系统场景（如混合精度 KV cache、disaggregated prefill/decode 架构中的 state 管理）。

3. **可跟进的研究方向**：
   - **Disaggregated serving + Hybrid 模型**：Mooncake 等系统将 KV cache 存储与计算分离，但 SSM state 的固定大小特性使得传输/存储策略完全不同，值得专门研究
   - **动态 admission/eviction 策略**：利用 workload 预测（如基于历史请求模式的 learned policy）替代 bootstrap + grid search
   - **跨层 state 压缩**：SSM state 是否存在冗余？能否对低频复用的 state 做量化/压缩以降低内存占用？
   - **Speculative decoding + prefix caching 在 Hybrid 模型中的交互**：speculative decoding 产生的 draft token 对 prefix caching 的影响尚未被探索

4. **趋势对齐**：论文指出 Marconi 在更多 SSM 层、更大 state dimension 时优势更明显，这与 Nemotron-H、Hunyuan-T1 等最新 Hybrid 模型的趋势一致，说明这类优化的重要性会持续增长。

---

## 八、总结

Marconi 是首个面向 Hybrid LLM 的 prefix caching 系统，通过基于前缀复用场景分类的审慎准入策略和 FLOP-aware 驱逐策略，解决了 SSM state 的"大而稀疏"问题。在多种 workload 上实现了 4.5-34.4× 的 token hit rate 提升和最高 71.1% 的 P95 TTFT 降低。系统的适用性随 Hybrid 模型趋势（更多 SSM 层、更大 state dimension）而增强。主要局限在于评估主要基于模拟、α 调优的动态适应性不明确、以及对不支持 chunked state passing 的模型存在两遍 prefill 开销。
