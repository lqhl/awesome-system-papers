## 一、背景

大语言模型（LLM）推理中，tree-structured prefix sharing 越来越普遍。现代 LLM 应用（few-shot learning、document QA、tree of thoughts、multi-chain reasoning 等）天然产生多级前缀共享的查询结构——不同查询共享 system prompt、few-shot examples 等公共前缀。

现有的 LLM serving 系统（如 SGLang）已经利用 radix tree 组织全局 KV cache，使不同查询可以复用共享前缀的 KV cache，从而减少 GPU 显存占用、提升并发吞吐。然而，这些系统在 attention 计算层面仍然沿用传统的 per-query 独立计算模式，并未利用树结构带来的计算优化机会。

Attention 操作在长序列 decoding 中可以占到 GPU 前向时间的 65%（Llama-2-7B, batch=32, seq_len=2048），因此优化 attention kernel 对降低推理延迟至关重要。

---

## 二、要解决的问题

现有系统（SGLang + FlashAttention/FlashInfer）在 radix tree KV cache 共享下存在两个核心计算效率问题：

1. **冗余 HBM 访问**：每个 query 的 attention 由独立的 GPU thread block 处理，共享的 KV cache 被从慢速 global memory 冗余加载多次，无法通过 shared memory 复用。

2. **Tensor core 利用率低**：decoding 阶段每个 query 仅有 1 个 token，attention 退化为 GEMV 操作，无法满足 tensor core 的最小矩阵形状要求。FlashAttention 通过 padding Q 矩阵来使用 tensor core，但有效计算率不到 1%。虽然 batching 可以提升 projection 和 MLP 层的计算密度，但无法直接帮助 attention（因为 query 是分开计算的）。

3. **Context-queries grouping 挑战**：如何在给定的 radix tree 上找到最优的 context-queries 分组方案是一个巨大的搜索空间问题（2^|E| 种可能），不同分组方案在 padding 开销、中间结果开销之间存在复杂的 trade-off。

---

## 三、洞察与设计

**关键洞察**：树结构的 KV cache 共享不仅可以优化内存布局，更可以指导计算优化——将共享同一前缀的多个 query 聚合在一起计算 attention，可以同时实现 shared memory 上的 KV cache 复用（减少 HBM 访问）和将 GEMV 转化为 GEMM（启用 tensor core）。

基于这一洞察，FastTree 包含两大核心组件：

### Tree Structure-Adaptive Runtime Optimization

将最优分组问题形式化为 **binary edge assignment** 问题：给 radix tree 的每条边赋值 0 或 1，1 表示两个连接节点 "concatenate"（拼接 context），0 表示 "split"（分开处理）。通过 edge assignment 生成 virtual tree，再基于 virtual tree 进行 node-centric query aggregation。

**Overhead-guided greedy heuristic**（Algorithm 1）：
- BFS 遍历树，对每条边比较 split（assign 0）和 concatenate（assign 1）的开销
- 开销模型考虑两个因素：(a) **Padding cost**：query 维度和 context 维度的 tile padding 导致的 shared memory 浪费和冗余计算；(b) **Intermediate result cost**：split KV 会引入更多中间结果存储和额外的 reduction 步骤
- 线性时间复杂度，适合运行时在线决策

**GPU-efficient long context splitting**：
- 解决两个 GPU 利用率不足问题：block 数量不够占满所有 SM、长 context 节点导致的 tail effect
- 对超过阈值的长 context 节点进行分割，增加 block 并行度

### Efficient Tree-Structured Attention Kernel

- **单 kernel 处理所有 groups**：不同 context-queries group 分配到不同 block set，避免多次 kernel launch 开销
- **FlashAttention-style group processing**：query 维度跨 block 并行，context 维度 block 内顺序迭代，使用 online softmax 将中间结果保存在 shared memory
- **Multi-phase tiling**：靠近 root 的节点聚合更多 query，使用更大的 tile size 最大化 KV 复用；靠近 leaf 的节点 query 少，使用较小 tile size 提升 SM occupancy

## 四、实现细节

- 基于 **SGLang v0.2.13** 实现，作为 plugin 接入
- Attention kernel 使用 **Triton** 实现（方便原型验证），未使用 Hopper-specific 特性（如 TMA）
- 仅优化 **decoding 阶段**的 attention 操作，prefill 仍使用 FlashInfer kernel
- Cost model 中的经验系数 α、β、γ 通过 profiling H100 硬件确定
- Tile size 根据硬件 shared memory 和 tensor core 的规格固定
- Greedy heuristic 的 CPU 预处理开销可忽略（被 GPU kernel 执行时间掩盖，且 SGLang 对 batch 执行多步 decoding 来摊销调度开销）
- 提供 Docker 环境和复现脚本，代码开源于 GitHub

## 五、实验结果

**实验平台**：NVIDIA H100 GPU (80GB), CUDA 12.2

### Kernel Benchmark

在多种 tree shape 和 GQA ratio (1, 4, 16) 下的 attention kernel 性能对比：

| Baseline | 平均加速比 |
|---|---|
| FlashAttention v2.6.3 | 5.1× |
| SGLang Triton kernels | 9.2× |
| FlashInfer v0.1.6 | 4.2× |
| DeFT | 10.6× |
| Multi-Level Cascade Attention | 2.1× |

- GQA ratio 低时加速比更显著（GQA ratio = 1 时最大），因为 GQA 本身可以缓解 tensor core 利用率问题
- 即使 GQA ratio = 16，FastTree 仍优于 FlashAttention 和 FlashInfer
- Greedy heuristic 在深层复杂树结构上可带来额外 2.2× 加速
- Long context splitting 在特定配置下可带来 1.9× 加速

### End-to-End Performance

模型：Llama-2-7B (GQA=1) 和 Mistral-7B (GQA=4)，batch=128，生成 256 tokens

| Baseline | Llama 平均加速 | Mistral 平均加速 |
|---|---|---|
| SGLang w/ Triton | 2.4× | 3.1× |
| SGLang w/ FlashInfer | 1.6× | 1.9× |

四个 benchmark：Multi-level system prompt、Multiple few-shot learning、Multi-chain reasoning、Multi-document QA。FastTree 在所有场景下均一致优于 baseline，最高 2.2× throughput 提升（vs FlashInfer backend）。

## 六、批判性分析

1. **实验模型规模偏小**：仅在 7B 模型上做了端到端评测（Llama-2-7B 和 Mistral-7B）。在更大模型（70B+）上，attention 在总计算中的占比可能不同（MLP/projection 层更重），实际端到端收益存疑。

2. **仅优化 decoding 阶段**：论文明确承认未优化 prefill 和 mixed prefill-decoding 场景（"except the engineering efforts"）。在实际 serving 中，chunked prefill 和 continuous batching 下 prefill 与 decoding 混合执行是常态，FastTree 的适用范围受限。

3. **Triton 实现 vs CUDA 实现**：FastTree 用 Triton 实现 kernel，而 FlashAttention 和 FlashInfer 是高度优化的 CUDA 实现。论文未讨论如果 FastTree 用 CUDA 实现是否能获得更大收益，也未分析 Triton 本身是否是性能瓶颈。同时未用 Hopper TMA 等硬件特性，留下了较大的优化空间但也意味着当前结果并非该方法的性能上界。

4. **Cost model 的经验系数**：greedy heuristic 依赖 α、β、γ 三个经验系数，这些系数 "based on profiling the underlying hardware"，但论文未讨论这些系数对不同 GPU 架构的泛化性，以及如何自动调优。

5. **Workload 代表性**：四个端到端 benchmark 都是精心构造的 prefix sharing 场景，batch 固定为 128，生成长度固定为 256。实际生产环境中 prefix sharing 的程度、请求到达模式、输出长度分布都更加动态，论文缺乏在真实 trace 上的评估。

6. **与 SGLang 版本绑定**：基于 SGLang v0.2.13 实现，而 SGLang 迭代极快（论文也引用了 v0.4），FastTree 的集成和维护成本未被讨论。

7. **Greedy heuristic 的最优性差距**：论文将问题形式化为优化问题但用 greedy 求解，未分析 greedy 解与最优解之间的近似比或实际差距。

## 七、AI Infra / MLSys 视角

### 启发与借鉴

1. **Memory layout 指导计算优化的范式**：FastTree 的核心思路——利用数据的共享结构来指导 GPU kernel 的计算模式——具有普遍意义。类似的思路可以应用到 speculative decoding（多个 draft token 共享前缀）、beam search、RAG 等场景。

2. **Runtime adaptive kernel selection**：根据运行时的数据结构特征（tree shape）动态选择计算方案的思路，可以迁移到其他需要 workload-adaptive 优化的 AI Infra 场景，如 dynamic batching 策略、MoE routing 等。

3. **Multi-phase tiling**：根据 tree 不同层级选择不同 tile size 的技术，启发了一种更通用的异构 workload kernel fusion 策略。

### 值得跟进的方向

1. **扩展到 prefill 阶段和 mixed batching**：论文明确提到这是工程问题而非根本限制，但 prefill 阶段的 tree-structured attention 优化可能有不同的 trade-off（Q 矩阵更大，tensor core 已经可以有效利用，主要收益来自 KV cache 复用）。

2. **与 PagedAttention v2 / FlashInfer 最新版本的集成**：FastTree 的 tree-aware grouping 策略可以作为通用 scheduling 层集成到更现代的 attention backend 中。

3. **自动化 cost model tuning**：用 auto-tuning 替代手动 profiling 来确定经验系数，使系统能自动适配不同 GPU 架构。

4. **结合 KV cache compression**：当 KV cache 被量化或剪枝后，tree-structured sharing 的收益模型会发生变化，值得研究两者的协同优化。

---

## 八、总结

FastTree 通过将 radix tree KV cache 的内存共享结构延伸到 attention 计算层面，解决了现有 LLM serving 系统中 decoding attention 的冗余内存加载和 tensor core 低利用率问题。其 overhead-guided greedy heuristic 能在线性时间内找到高效的 context-queries 分组方案，配合 tree-structured attention kernel 实现了在 H100 上相比 SGLang+FlashInfer 最高 2.2× 的端到端吞吐提升。主要局限在于仅优化 decoding 阶段、仅在 7B 模型上验证、依赖经验系数、且缺乏真实生产 workload 下的评估。
