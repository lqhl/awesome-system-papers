## 一、背景

大语言模型（LLM）训练对内存需求极高，其中 AdamW 优化器的状态（first moment 和 second moment）占据了大量显存。例如，训练 LLaMA-7B 需要至少 58GB 显存，其中 28GB 用于 AdamW 的优化器状态；GPT-3 (175B) 的优化器状态更是高达 1.4TB。这迫使研究者要么使用更多高端 GPU，要么缩小 batch size，严重限制了训练的可扩展性和吞吐量。

现有的内存高效优化器主要有两条路线：(1) 基于低秩的方法（如 GaLore、Fira），通过 SVD 将梯度投影到低秩空间，但 SVD 计算代价高昂（LLaMA-7B 单次 SVD 更新约需 10 分钟）；(2) 探索优化器状态冗余的方法（如 Adam-mini），按 block 共享 second moment，但仍需保留 full-rank 的 first momentum，且需要针对不同 Transformer 模块仔细选择 block size。

---

## 二、要解决的问题

1. **SVD 计算开销过大**：GaLore 等方法依赖周期性 SVD 更新梯度子空间，O(mn²) 的复杂度在大模型上成为显著瓶颈，严重降低训练吞吐量。
2. **性能与内存的权衡不佳**：Flora 等低秩方法在预训练中与 AdamW 存在明显性能差距；GaLore 需要 1/4 rank 才能保持性能，内存节省有限。
3. **优化器内存仍然可观**：即使是 Adam-mini，也只能节省 second moment 的内存，first moment 仍然是 full-rank，整体内存开销依然不小。
4. **低端 GPU 无法训练大模型**：优化器状态的内存占用使得在消费级 GPU 上从零预训练 LLM 几乎不可能。

---

## 三、洞察与设计

**关键洞察**：AdamW 的 element-wise 学习率自适应规则存在大量冗余——可以将其粗化为 channel-wise 甚至 tensor-wise 的结构化学习率更新，即同一 channel（或整个 tensor）共享一个梯度缩放因子，而不影响甚至能略微提升训练性能。

基于这一洞察，APOLLO 的设计分为三步：

1. **结构化学习率更新**：将 AdamW 重新表述为"自适应学习率的 SGD"——缩放因子 S = G̃_t / G_t，其中 G̃_t = M_t / √V_t。然后将 element-wise 的 S 粗化为 channel-wise 格式：每个 channel j 的缩放因子 s_j = ‖G̃_t[:,j]‖₂ / ‖G_t[:,j]‖₂。实验验证在 LLaMA-130M 上，channel-wise 适应甚至比 element-wise 获得更好的 perplexity（24.43 vs 25.08）。

2. **低秩辅助空间近似（APOLLO）**：将梯度通过随机投影矩阵 P ∈ R^{r×m}（而非 SVD）投影到低秩空间 R_t = P_t G_t，在低秩空间维护 first/second moment（MR_t, VR_t），计算 channel-wise 缩放因子后映射回原始空间。理论上通过 Johnson-Lindenstrauss 引理证明随机投影能以高概率保持缩放因子的近似精度，比值为 √(n/r)。优化器状态从 2mn 降至 2nr。

3. **极致内存版本（APOLLO-Mini）**：将缩放因子进一步粗化为 tensor-wise（整个权重矩阵共享一个缩放因子），使用 rank-1 投影空间。优化器状态降至常数级 2n+2，接近 SGD 的内存开销。通过设置梯度缩放因子 α = √128 补偿 rank-1 带来的尺度差异。

额外引入 Norm-growth Limiter (NL) 来抑制早期训练阶段不稳定梯度导致的 loss spike。

## 四、实现细节

- **随机投影矩阵**：P 的每个元素从 N(0, 1/r) 独立采样，每 T=200 步重新生成（仅需更换随机种子），无需存储投影矩阵本身。
- **算法流程**（Algorithm 1）：
  1. 计算梯度 G_t，随机投影到低秩空间 R_t = P_t G_t
  2. 在低秩空间运行类 AdamW 更新（β₁, β₂ 衰减），获得 MR_t, VR_t
  3. APOLLO：计算 channel-wise 缩放因子 s_j^R = ‖R̃_t[:,j]‖₂ / ‖R_t[:,j]‖₂；APOLLO-Mini：计算 tensor-wise 缩放因子 s^R = ‖R̃_t‖₂ / ‖R_t‖₂
  4. 在原始空间更新权重 W_t = W_{t-1} + η·α·G_t·S - η·λ·W_{t-1}
- **内存开销对比**：APOLLO 优化器状态 2nr + 2，APOLLO-Mini 仅 2n + 2（常数级），而 AdamW 需要 2mn。
- **与量化结合**：集成 INT8 权重量化（Q-GaLore 策略），Q-APOLLO-Mini 在 layer-wise gradient update 下仅需 12GB 即可预训练 LLaMA-7B。
- **理论保证**：通过 JL 引理分别证明了 first moment 和 second moment 在随机投影下的 ℓ₂/ℓ₁ 范数保持性，最终得到缩放因子比值 s_j^R / s_j 的上下界为 √((1±ϵ)·n/r)。

### 系统级收益（8×A100-80GB）

- APOLLO/APOLLO-Mini 支持 4× 更大 batch size（16 vs AdamW 的 4），训练吞吐量约 **3× 提升**
- 端到端训练内存：AdamW 79GB (BS=4) vs APOLLO-Mini 68GB (BS=16)
- 优化器步骤时间（7B）：AdamW 0.173s, APOLLO 0.159s, APOLLO-Mini 0.142s, GaLore 2.874s

### 微调

在 LLaMA-3.2-1B、LLaMA-3-8B、Gemma-7B、Mistral-7B 上的 commonsense reasoning 和 MMLU 任务中，APOLLO 系列与 full-rank AdamW 性能持平或略优，且优化器内存开销极低。

## 六、批判性分析

1. **预训练 perplexity 优于 AdamW 缺乏深层解释**：论文声称 APOLLO 不仅节省内存还能超越 AdamW 的 perplexity，但对"为什么粗化学习率反而更好"只给出了初步讨论（Section 5.5 和 Appendix A.4），承认这是 future work。一个「比 AdamW 更差的近似」理应不会更好——这里可能存在正则化效应（类似 dropout），但论文未能给出令人信服的分析。

2. **训练 token 数量偏少**：主要实验在 C4 上训练 token 量有限（LLaMA-7B 仅约 20B tokens，远低于实际训练 1-2T tokens 的规模）。在更长训练中，channel-wise/tensor-wise 缩放的近似误差是否会累积并放大，论文未充分验证。

3. **下游任务提升不显著**：尽管 perplexity 有明显优势，Tab. 4 中 LLaMA-350M 在 10 个下游任务上的 zero-shot 平均准确率提升非常微小（APOLLO 0.3681 vs AdamW 0.3554），且部分任务上不如 AdamW（如 BoolQ）。这说明 perplexity 改进不一定能转化为有意义的下游收益。

4. **Norm-growth Limiter 的必要性暴露了方法的脆弱性**：channel-wise 学习率在早期训练阶段会出现严重的 loss spike（Fig. 3），必须依赖 NL 技术来稳定。这意味着方法本身对训练早期不稳定的梯度很敏感，在不同架构或训练设置下可能需要额外调参。

5. **理论分析的局限**：JL 引理的 bound 假设 P 在时间步上固定，但实际每 200 步重采样。论文承认这与理论假设不一致，GaLore 也有同样问题，但这使得理论保证的实际意义打了折扣。

6. **Scaling factor α 的设置依赖 heuristic**：APOLLO-Mini 中 α = √128 是"启发式"设置，理论只给出了 √(n/r) 的量级建议。对于不同模型规模和架构，这个值是否需要调整，论文未充分讨论。

7. **与 Adam-mini 的公平比较缺失**：论文在相关工作中批评 Adam-mini 需要人工设计 block 结构，但未在实验中直接对比 Adam-mini 的预训练性能，只在讨论中提到。

## 七、AI Infra / MLSys 视角

1. **降低 LLM 训练的硬件门槛**：APOLLO-Mini 将优化器状态压缩到接近零的水平，结合量化可在 12GB 显存预训练 7B 模型。这对资源受限的研究团队和边缘训练场景有重要意义——未来可以探索在消费级 GPU 集群上的全参数预训练方案。

2. **与分布式训练的协同优化**：优化器状态的大幅缩减直接减少了 ZeRO-style 分布式优化中的通信量。论文已展示 APOLLO-Mini 可用 naive DDP 训练 13B 模型，省去 model sharding 的复杂性。值得深入研究的方向是：APOLLO 与 FSDP/ZeRO-3 结合后能否进一步简化分布式训练栈？

3. **随机投影替代 SVD 的系统友好性**：APOLLO 彻底消除了 SVD 操作（GaLore 的 SVD 在 7B 模型上需 ~10min），仅需随机种子生成投影矩阵。这使其对 GPU kernel 调度和流水线并行更友好，优化器步骤时间甚至低于 AdamW（7B：0.142s vs 0.173s）。

4. **可迁移的 insight**：「element-wise 自适应学习率存在大量冗余，可粗化为结构化更新」这一观察可能对其他自适应优化器（如 LAMB、Adafactor）也适用。此外，结构化缩放因子的思路可迁移到推理侧的量化/压缩场景——例如用 channel-wise scaling 替代 per-element scaling 来降低量化器的开销。

5. **值得跟进的研究问题**：
   - 在超长训练（>1T tokens）和更大模型（70B+）上验证 APOLLO 的稳定性和最终性能
   - 将 APOLLO 集成到 MoE 训练中，研究 expert 级别的结构化学习率更新
   - 探索 APOLLO 与 activation checkpointing、offloading 的端到端内存优化组合

---

## 八、总结

APOLLO 提出了一种基于结构化学习率更新的内存高效优化器，核心思路是将 AdamW 的 element-wise 梯度缩放粗化为 channel-wise（APOLLO）或 tensor-wise（APOLLO-Mini），并通过随机投影在低秩辅助空间中近似计算缩放因子。APOLLO-Mini 将优化器状态压缩到 SGD 级别（近乎为零），同时在 LLaMA 60M-7B 的预训练中反而超越了 AdamW 的 perplexity。系统层面带来 3× 吞吐提升、4× batch size 扩展，并首次实现 12GB 显存预训练 7B 模型。主要局限在于大规模长时间训练的验证不足，以及"为什么近似反而更好"缺乏严格理论解释。
