## 1. 研究背景与动机

大语言模型（LLM）的计算和内存挑战催生了大量优化方法，如量化和稀疏加速。这些优化通常假设高端 GPU 或服务器级 FPGA，具有大容量片外内存和高带宽。然而，低功耗边缘设备（如嵌入式 FPGA）有其独特约束：

1. **低内存带宽**: 边缘设备的片外 DRAM 带宽远低于高端 GPU（如 ZCU102 FPGA 仅 19.2 GB/s）
2. **权重访问瓶颈**: 解码阶段，权重获取延迟成为主导因素
3. **面积和功耗约束**: 边缘设备对芯片面积和功耗有严格要求

**现有方案的局限**:
- **CTA**: 压缩 token 注意力机制，但仍然使用 GEMM 进行 Q+SM(QKT)×V 操作
- **FlightLLM**: 利用混合精度和融合 DSP，但未使用 weight packing

## 2. 研究问题与核心挑战

**核心问题**: 如何在低功耗边缘设备上高效部署 LLM，同时处理内存带宽瓶颈？

**具体挑战**:
1. **权重获取延迟优化**: 在低带宽设备上，权重获取成为解码延迟的主要瓶颈
2. **Q+SM(QKT)×V 操作优化**: 传统的 GEMM 操作在边缘设备上效率不高
3. **Prefill 和 Decode 阶段优化**: 两阶段需要不同的优化策略

## 3. 主要贡献

1. **TPHS（Token-wise Pipelined Hierarchical Softmax）数据流**: 提出一种专为低功耗设备设计的注意力计算数据流
2. **权重打包（Weight Packing）**: 将权重矩阵打包为高位宽向量，减少片外内存访问次数
3. **混合操作模式**: 支持 Prefill 和 Decode 阶段使用不同的操作模式
4. **FPGA 原型验证**: 在 Xilinx ZCU102 FPGA 上验证了方案的有效性
5. **与 prior works 对比**: 相比 CTA 和 FlightLLM，MEADOW 在低带宽场景下表现更优

## 4. 核心方法与设计

### 4.1 内存访问分析

```
Prefill 阶段:
  数据获取: ~50-60%
  计算: ~30-40%
  数据存储: ~10%

Decode 阶段:
  权重获取: ~70-80% (主导因素)
  计算: ~15-20%
  数据存储: ~5%
```

### 4.2 TPHS 数据流

```
Token-wise Pipelined Processing:
  Q Stage → QKT Stage → SM Stage → SMV Stage

并行化:
  Head 1: Q1 → QKT1 → SM1 → SMV1
  Head 2: Q2 → QKT2 → SM2 → SMV2
  ...
```

### 4.3 权重打包

```
原始权重: [w0, w1, w2, ..., w31] (32 个 8-bit 值)
打包后:   [w0:w3, w4:w7, ..., w28:w31] (8 个 32-bit 值)

效果:
  - 4 倍减少片外访问次数
  - 需要 4 倍的片上存储
```

### 4.4 Softmax 模块设计

```
输入: Q (Query) 和 K^T (Key Transpose)
Stage 1: 指数计算 (EXP)
Stage 2: 求和 (Σ)
Stage 3: 除法 (DIV)

使用 PREG (Pipeline Register) 减少组合逻辑延迟
```

### 4.5 操作模式

| 阶段 | Q+SM(QKT)×V | KV, Proj, MLP |
|------|-------------|---------------|
| Prefill | TPHS | GEMM |
| Decode | TPHS | GEMM + Weight Packing |

### 4.6 LUT 优化

使用预计算的指数和除法查找表，减少实时计算开销。

## 6. 潜在问题与局限性

1. **FPGA 特定设计**: 论文的优化针对 Xilinx ZCU102 FPGA 设计，迁移到其他平台需要重新设计。
2. **模型规模限制**: 论文验证的模型规模较小（OPT-125M, OPT-1.3B），对更大模型（如 7B+）的适用性需要验证。
3. **吞吐量 vs 延迟权衡**: TPHS 可能在高吞吐场景下不如 GEMM。

## 7. 未来工作

1. 在更大规模 FPGA 和 ASIC 原型上验证
2. 结合更多优化（如激活压缩）
3. 探索与其他数据流的联合设计

## 8. 个人评注

MEADOW 关注的是 LLM 部署中一个相对小众但重要的场景：低功耗边缘设备。与大多数关注高端 GPU 或服务器的论文不同，边缘设备有其独特的约束和优化机会。

论文的核心贡献在于识别了低功耗设备上的主要瓶颈（权重获取延迟）并设计了相应的解决方案。TPHS 数据流和权重打包是两个有针对性的优化，分别针对注意力和线性层。

不过，论文的验证主要在 FPGA 上进行，与 ASIC 或 GPU 的设计空间有很大差异。FPGA 的可编程性允许更灵活的数据流设计，但也带来了与固定功能硬件不同的性能特征。

MEADOW 与其他边缘 LLM 加速工作（如 EIE、SnapSearch）的比较也值得进一步探索。此外，对于长序列推理（如文档问答、代码补全），MEADOW 的优化策略是否仍然有效也是一个开放问题。

作为系统方向的论文，MEADOW 体现了硬件-软件协同设计的思想：通过深入理解目标硬件的约束，设计针对性的算法和数据流优化。
