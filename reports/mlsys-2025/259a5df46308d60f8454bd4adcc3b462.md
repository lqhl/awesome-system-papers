# MEADOW: Memory-Efficient Dataflow and Data Packing for Low Power Edge LLMs

**作者**：Abhishek Moitra, Arkapravo Ghosh (Yale University), Shrey Agarwal (IIT Roorkee), Aporva Amarnath, Karthik Swaminathan (IBM Research), Priyadarshini Panda (Yale University)

## 一、背景

大语言模型（LLM）的爆发式增长催生了对高效、低功耗硬件部署方案的需求。数据中心级硬件（如 AMD Alveo 系列）依赖高带宽内存（HBM）来处理 LLM 的密集计算，但功耗超过 200W。边缘设备（如 Xilinx ZCU102 FPGA，功耗 <10W）提供了低功耗的替代方案，但缺乏 HBM，片外内存带宽严重受限。现有的 LLM 优化技术（量化、稀疏计算）主要面向 GPU/TPU 等高功耗平台设计，未能充分解决低带宽边缘设备上的内存瓶颈问题。

---

## 二、要解决的问题

1. **Attention 计算中反复的片外内存访问**：标准 GEMM 模式下，Q、QK^T、Softmax、SMxV 等层的中间结果需要反复读写片外 DRAM，在低带宽环境下导致巨大的 prefill 延迟。
2. **权重矩阵加载瓶颈**：Decode 阶段输入仅一个 token，计算和存储开销可忽略，但权重矩阵的加载占据了绝大部分延迟。在带宽受限设备上，这一瓶颈尤为突出。
3. **现有优化方案的局限**：CTA（token 压缩）仅部分减少中间数据传输，FlightLLM（N:M 稀疏）减少计算但未优化权重加载，两者均未从根本上解决片外内存访问问题。

---

## 三、洞察与设计

**关键洞察**：LLM decoder 中 Q+SM(QK^T)xV 层的中间结果在 head 维度上是独立的，可以按 token 并行、按 head 顺序地流水线执行，从而完全消除这些层的片外中间数据读写；同时，量化后的权重矩阵存在极高的冗余（unique chunk 的 reduction ratio 达 10^2 到 10^3 量级），可以通过无损分解大幅减少权重传输量。

基于此洞察，MEADOW 提出两项核心技术：

### Token-Parallel Head-Sequential (TPHS) Dataflow
- 对 Q、QK^T、SM、SMxV 层采用流水线执行：多个 token 并行处理，按 attention head 顺序计算
- 每个 stage（Q → QK^T → SM → SMxV）仅需 T 个时钟周期，中间结果通过片上 pipeline register 直接传递，无需写回片外 DRAM
- KV、Proj、MLP 层仍使用标准 GEMM 模式执行

### Weight Packing
- 将权重矩阵沿内积维度分成大小为 C 的 chunk，提取 unique chunk 构建 Unique Matrix，用 chunk ID 编码原始权重矩阵
- **Packet-specific encoding precision**：不同 packet 根据其最大编码值使用不同位宽，避免低位值浪费高位空间
- **Frequency-aware re-indexing**：高频 chunk 分配低 ID（更少 bit），进一步提升 packing 效率

---

## 四、实现细节

**硬件架构**：MEADOW 采用 tiled 架构，包含：
- 84 个 Parallel MAC PE + 12 个 Broadcasting MAC PE，每个 PE 含 64 个乘法器
- 84 个 Softmax 模块（三级流水线：MAX → EXP → DIV）、8 个 LayerNorm 模块、8 个非线性激活模块
- Weight/Input/Output BRAM 各 1MB，RF 各 4KB
- 片上 NoC 互连，时钟频率 100MHz

**Hybrid PE 设计**：每个 PE 支持 GEMM 和 Pipeline 两种模式。GEMM 模式从 BRAM 读取 input 和 weight；Pipeline 模式从 pipeline register 读取 input，输出直接通过 NoC 传递到下一级。所有 RF 和 pipeline register 采用双缓冲。

**WILU 模块**：Weight Unpacking and Index Look-up 模块，从 Weight BRAM 读取 packed 编码值，通过 Mode-Aware Unpacking (MAU) 模块根据 mode bits 解包不同位宽的编码，再查找 Unique Matrix 获得实际权重值。

**实现规模**：在 Xilinx ZCU102 上使用 150K LUT、845 BRAM、2034 DSP。

## 五、实验结果

**模型与数据集**：OPT-125M 和 OPT-1.3B，SmoothQuant W8A8 量化，LAMBADA 数据集（准确率 60.7% / 69.7%）。

### Prefill 延迟 (TTFT)

| 模型 | DRAM 带宽 | Token 数 | MEADOW vs GEMM |
|------|----------|---------|----------------|
| OPT-125M | 12 Gbps | 64/512 | 1.5×–1.7× 降低 |
| OPT-125M | 1 Gbps | 64/512 | 1.57×–2.5× 降低 |
| OPT-1.3B | 12 Gbps | 64/512 | 1.5×–1.6× 降低 |
| OPT-1.3B | 1 Gbps | 64/512 | 1.55×–2× 降低 |

### Decode 延迟 (TBT)

| 模型 | DRAM 带宽 | Token 位置 | MEADOW vs GEMM |
|------|----------|-----------|----------------|
| OPT-125M | 12 Gbps | 64th/512th | 1.4×–1.46× 降低 |
| OPT-1.3B | 12 Gbps | 64th/512th | 1.4×–1.52× 降低 |

### 与先前工作对比
- 相比 CTA 和 FlightLLM，MEADOW 在 ZCU102 上实现端到端延迟降低 **40%** 以上。

### Weight Packing 效果
- Naive packing：1.4× 延迟降低
- Packet-specific encoding：1.54× 延迟降低
- + Frequency-aware re-indexing：**2.63×** 延迟降低

### ViT 泛化性
- DeiT-S/DeiT-B 模型推理延迟降低 1.5×–1.6×。

## 六、批判性分析

1. **模型规模过小，实用性存疑**：实验仅在 OPT-125M 和 OPT-1.3B 上进行，这两个模型的能力远低于实际应用需求。论文未讨论 MEADOW 能否支持更大模型（即便是 7B 级别），也未分析 weight packing 的 reduction ratio 如何随模型规模变化——更大的模型是否仍有同等冗余程度是一个未验证的假设。

2. **仅与弱基线对比**：CTA 和 FlightLLM 都是 GEMM-based 的优化，本质上是在同一范式内的改进。论文缺少与非 GEMM 架构（如 dataflow 加速器 Eyeriss/NVDLA 风格）、CPU/GPU 边缘方案（如 Qualcomm AI Engine、Apple ANE）的对比，无法判断 FPGA 方案在边缘场景中的真实竞争力。

3. **Weight Packing 的通用性未充分验证**：reduction ratio（10^2–10^3）仅在 OPT 系列的 W8A8 量化下测量。不同量化方式（W4A8、GPTQ、AWQ）、不同模型架构（Llama、Mistral）下的 chunk 冗余程度完全未知。如果模型使用更紧凑的量化，unique chunk 数量可能大幅增加，packing 收益可能急剧下降。

4. **未报告准确率影响**：虽然声称 weight packing 是"lossless"的，但论文仅给出了基础模型的量化准确率（60.7%/69.7%），未给出 MEADOW 部署后的推理准确率数据加以验证。

5. **DRAM 带宽范围设定偏低**：实验使用 1–12 Gbps 的带宽范围，而 ZCU102 的实际 DDR4 带宽可达 ~19.2 GB/s（153.6 Gbps）。论文似乎在人为限制带宽以突出 MEADOW 的优势，但未解释为何实际部署会在如此低的带宽下运行。

6. **面积/资源开销分析缺失**：WILU 模块、双缓冲 RF、NoC 互连引入了额外的硬件开销，但论文未量化这些组件的面积/资源占比，也未讨论 PE 数量缩减后的性能退化曲线。

## 七、AI Infra / MLSys 视角

1. **Weight Packing 思路可迁移到 GPU 推理**：权重矩阵中 chunk 级别的高冗余是一个有趣的观察。虽然 GPU 不需要像 FPGA 那样逐 packet 传输权重，但类似的冗余分析可以启发 GPU 上的权重压缩方案——例如在 KV cache 压缩中寻找 token-level 的冗余模式。

2. **TPHS Dataflow 与 FlashAttention 的互补性**：TPHS 的核心思想是避免中间结果写回外部存储，这与 FlashAttention 在 GPU 上避免中间结果写回 HBM 的思路异曲同工。两者面向不同硬件，但解决的本质问题相同——内存墙。这提示我们在设计新型 AI 加速器时，dataflow-level 的内存访问优化应作为第一优先级考虑。

3. **边缘 LLM 部署的实际价值有限**：OPT-125M/1.3B 在 <10W FPGA 上的部署更多是学术探索。真正有意义的 future work 是：(1) 支持 3B+ 模型在边缘设备上的部署，(2) 结合 speculative decoding 等算法优化，(3) 探索 MEADOW 架构在 ASIC 上的面积/能效优势。

4. **可操作的研究方向**：将 frequency-aware re-indexing 的思想应用到 KV cache 的量化压缩中——对高频出现的 KV pattern 使用更短编码，可能在不损失精度的前提下显著降低 KV cache 的内存占用。

---

## 八、总结

MEADOW 针对低功耗边缘 FPGA 上的 LLM 推理延迟问题，提出了 TPHS 流水线 dataflow（消除 attention 计算的片外中间数据传输）和 Weight Packing（无损压缩权重矩阵传输量）两项互补技术。在 Xilinx ZCU102（<10W）上，相比 GEMM 基线实现 1.5×–2.5× 的延迟降低，相比 CTA/FlightLLM 实现 40% 以上的端到端改善。主要局限在于实验仅覆盖小模型（125M/1.3B），且基线和评估条件的代表性不足，距离实际边缘部署仍有较大差距。
