# MAS-Attention: Memory-Aware Stream Processing for Attention Acceleration on Resource-Constrained Edge Devices

**链接**：Proceedings of the 8th MLSys Conference, Santa Clara, CA, USA, 2025

---

## 一、背景

随着 Foundation Model（如 LLM、ViT、Diffusion Model）在边缘设备上的部署需求日益增长，Attention 机制的二次复杂度成为推理性能的关键瓶颈。在数据中心级 GPU 上，FlashAttention 系列通过多核并行和 SRAM 数据局部性实现了显著加速。然而，边缘端神经加速器（如手机 NPU）的计算核心数量有限、片上缓存紧张，无法直接套用云端的加速方案。

现有边缘端方法（如 TVM、FLAT、oneDNN）主要依赖算子融合（graph fusion）将中间结果保留在片上，减少 DRAM 访问。但这些方法仍然**顺序执行** MatMul 和 Softmax，未充分利用边缘加速器上异构计算单元（MAC unit 和 VEC unit）的并行潜力。

---

## 二、要解决的问题

1. **异构计算单元未被并行利用**：边缘加速器通常配备 MAC（矩阵乘法）和 VEC（向量运算）两类计算单元，但现有 Attention 加速方法将 MatMul 和 Softmax 顺序执行，导致在任意时刻总有一类计算单元处于空闲状态。

2. **片上缓存极其有限**：边缘设备的 on-chip memory 通常只有几 MB，当 sequence length 较长时，中间矩阵 C 和 P 无法完整驻留片上，需要精细的 tiling 和缓存管理。

3. **Tiling 参数搜索空间巨大**：在异构并行执行下，需要同时为 MatMul 和 Softmax 的不同 tiling 粒度找到最优配置，还需要平衡 MAC/VEC 的负载均衡和 I/O 开销。

---

## 三、洞察与设计

**关键洞察**：Attention 计算中的 MatMul（计算密集型，适合 MAC unit）和 Softmax（逐元素运算，适合 VEC unit）天然地映射到不同类型的硬件计算单元上，因此可以将它们作为两个独立的"流"进行流水线并行，而非像现有方法那样顺序执行。

基于此洞察，MAS-Attention 设计了一个**半同步流处理方案**（Semi-synchronous Stream Processing）：

- **流水线结构**：将 Attention 的三个算子（$C_i = Q_i K^T$，$P_i = \text{Softmax}(C_i)$，$O_i = P_i V$）交织成流水线。在 regular round 中，MAC 同时执行 $O_{i-2} = P_{i-2}V$ 和 $C_i = Q_i K^T$，VEC 并行执行 $P_{i-1} = \text{Softmax}(C_{i-1})$。
- **多层 Tiling 方案**：MatMul 使用细粒度子矩阵 tiling，Softmax 使用行粒度 tiling，两者使用不同的 tiling 搜索空间，通过 MCTS + Genetic Algorithm 联合搜索最优 tiling 参数。
- **主动缓存覆写策略**（Proactive Buffer Overwrite）：当片上内存不足时，优先保护 Softmax 中间结果 $P_i$（因为 $P_i$ 仅存在于片上，无法从 DRAM 重新加载），选择性覆写可从 DRAM 重新加载的 K 或 V 矩阵。

---

## 四、实现细节

**流水线调度**：算法分为 warm-up（计算 $C_1$）、regular（三路并行循环）、finalize（排空流水线）三个阶段。数据依赖关系在 round 之间通过同步点管理——MAC 完成 $O_{i-2}$ 后才启动 $C_i$。

**Tiling 搜索**：
- 搜索空间覆盖 B（batch）、H（head）、$N_Q$（query seq）、$N_{K,V}$（key/value seq）四个维度的 tiling factor
- 模拟环境使用 MCTS 生成 tiling factor，GA 优化计算顺序；真实硬件（DaVinci NPU）使用 Grid Search
- 搜索目标为最小化延迟，约 10K 迭代收敛

**缓存覆写机制**：
- 当 VEC 计算 $P_i$ 导致片上内存溢出时，覆写 MAC 正在使用的 V 或 K 矩阵
- MAC 被中断后，待 $P_i$ 完成、VEC 释放缓存空间后，从 DRAM 重新加载被覆写的矩阵并恢复计算
- $P_i$ 不可被覆写，因为它仅存在于片上

**仿真与硬件平台**：
- 仿真：修改版 TileFlow 定义硬件架构，Timeloop + Accelergy 评估延迟和能耗。模拟边缘加速器：3.75 GHz，16nm，2 core（各含 MAC 16×16 PE + VEC 256 PE），L1 cache 5MB，DRAM 6GB / 30GB/s
- 真实硬件：Huawei MatePad Pro 13.2，Kirin 9000 5G SoC，DaVinci NPU（2× Ascend Lite + 1× Ascend Tiny core）

## 五、实验结果

**模拟硬件上的延迟加速**（vs 各基线，几何平均）：

| 基线 | 几何平均加速比 | 最大加速比 |
|------|-------------|-----------|
| Layer-Wise | 5.09× | 8.50× |
| Soft-Pipe | 2.78× | 4.50× |
| FLAT | 1.70× | 2.75× |
| TileFlow | 1.31× | 1.75× |
| FuseMax | 1.27× | 1.47× |

**真实硬件（DaVinci NPU）上的延迟加速**：

| 基线 | 几何平均加速比 | 范围 |
|------|-------------|------|
| Layer-Wise | 2.33× | 1.94×–3.50× |
| Soft-Pipe | 1.73× | 1.35×–2.87× |
| FLAT | 1.42× | 1.30×–1.76× |

**能耗节省**（模拟硬件，几何平均）：

| 基线 | 几何平均节省 |
|------|-------------|
| Layer-Wise | 52.97% |
| Soft-Pipe | 63.07% |
| FLAT | 18.55% |
| TileFlow | 53.16% |
| FuseMax | -11.94%（能耗更高） |

**端到端实验**：在 Stable Diffusion 1.5 UNet（15 个 attention unit，最大 seq_len=4096）上，MAS-Attention 对最大 attention unit 实现 29.4% 延迟降低，端到端模型推理延迟降低 6%。

## 六、批判性分析

1. **仿真环境与真实硬件的差距**：模拟硬件上加速比高达 2.75×（vs FLAT），但真实 DaVinci NPU 上只有 1.30×–1.76×。论文对此差距未做深入分析，仅简单归因于 TileFlow 无法在真实硬件上部署。实际上，真实硬件的调度开销、内存控制器行为、缓存替换策略等可能显著影响性能。

2. **基线公平性存疑**：TileFlow 是根据论文描述自行实现的（"to the best of our knowledge"），FuseMax 被 scale down 到边缘设备且使用手动 tiling 参数。这些基线的实现质量直接影响对比结论的可信度。

3. **能耗对比中 FuseMax 反超**：MAS-Attention 在多数 workload 上能耗高于 FuseMax（几何平均 -11.94%），论文解释为"搜索目标是最小化延迟而非能耗"，但这意味着在实际部署中（电池供电的移动设备），MAS-Attention 的能耗表现可能不如宣称的那样有优势。

4. **序列长度限制**：MAS-Attention 因流水线设计需要同时驻留两个 tile 的中间结果，最大支持 ~1M token（FP16），仅为 FLAT 的一半（~2M token）。在 LLM 长上下文推理场景下，这是一个显著限制。

5. **端到端收益有限**：虽然单 attention layer 加速显著，但端到端 Stable Diffusion 推理仅提升 6%，说明 Attention 在整体推理中的占比并不高（存在 Amdahl 定律效应），论文未量化 Attention 在不同模型中的实际耗时占比。

6. **搜索开销未充分讨论**：MCTS + GA 的离线搜索需要约 10K 迭代才能收敛，论文未报告搜索本身的时间开销。对于每个新的 workload 配置都需要重新搜索，在实际部署中可能不够灵活。

7. **仅覆盖推理场景**：论文明确表示仅支持推理，不支持训练。边缘端训练（如 on-device fine-tuning）的需求日益增长，这限制了方法的适用范围。

---

## 七、AI Infra / MLSys 视角

1. **异构计算单元并行的通用思路**：MAS-Attention 的核心思路——将不同计算特性的算子映射到不同硬件单元并行执行——不局限于边缘端。在数据中心 GPU 上，Tensor Core 和 CUDA Core 也是异构计算单元，FlashAttention-3 已经在 H100 上实现了类似的 MatMul-Softmax overlap。MAS-Attention 的贡献在于将此思路系统化地应用于资源受限的边缘加速器。

2. **对边缘端 LLM 推理的启示**：随着端侧大模型（如 Apple Intelligence、Qualcomm on-device LLM）的发展，Attention 加速是关键环节。MAS-Attention 的 tiling + 缓存覆写方案为设计边缘端 LLM 推理引擎提供了参考。不过，现代端侧 LLM 推理更多受限于 KV cache 的 memory bandwidth，而非 Attention 的计算本身。

3. **值得跟进的方向**：
   - **Prefill vs Decode 分阶段优化**：论文未区分 LLM 推理的 prefill 和 decode 阶段，两者的 Attention 计算模式差异巨大（prefill 是 compute-bound，decode 是 memory-bound），MAS-Attention 的流水线方案可能在 prefill 阶段更有效
   - **与量化/稀疏 Attention 的结合**：MAS-Attention 是 exact attention 加速，结合 INT8/INT4 量化或 sparse attention 可能带来更大的端侧性能提升
   - **多核边缘加速器扩展**：论文的方案针对单核或少核场景，如何扩展到多核 NPU（如 Apple Neural Engine 的 16 core）是一个实际问题

4. **最有价值的切入点**：将 MAC-VEC 异构并行的思路迁移到 GPU 上的 Tensor Core-CUDA Core 协同，特别是在 decode 阶段的 GQA/MQA attention 中，Softmax 和 partial sum reduction 可以 offload 到 CUDA Core 上与 Tensor Core 的 MatMul 并行执行。

---

## 八、总结

MAS-Attention 提出了一种面向资源受限边缘加速器的 Attention 推理加速方案，核心贡献是利用 MAC 和 VEC 异构计算单元的半同步流水线并行来重叠 MatMul 和 Softmax 计算，配合多层 tiling 搜索和主动缓存覆写策略。在模拟硬件上对比 FLAT 实现 1.70× 几何平均加速和 18.55% 能耗节省，在真实 DaVinci NPU 上实现 1.42× 加速。方法的主要局限在于：最大序列长度减半、能耗在部分场景不如 FuseMax、端到端收益有限、仅支持推理且需要离线搜索 tiling 参数。适用于拥有异构计算单元的边缘 NPU 上的 Transformer 推理加速场景。
