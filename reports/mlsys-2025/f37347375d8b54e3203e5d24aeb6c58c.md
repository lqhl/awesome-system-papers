## 1. 研究背景与动机

联邦学习（Federated Learning, FL）系统中，除了模型训练本身，还有大量非训练工作负载，包括：
1. **调度（Scheduling）**: 选择参与每轮训练的客户端
2. **个性化（Personalization）**: 为不同客户端定制模型
3. **聚类（Clustering）**: 对客户端进行分组
4. **调试（Debugging）**: 诊断训练问题
5. **激励（Incentivization）**: 计算客户端贡献度

**关键发现**: 非训练工作负载占总 FL 过程延迟的 11%-98%，且随着参与客户端数量增加而增加。

现有 FL 系统存在以下问题：
1. **存储系统忽视非训练需求**: 现有系统主要优化训练过程，对非训练工作负载的存储需求考虑不足。
2. **元数据管理低效**: 非训练工作负载需要访问大量历史数据，但现有云对象存储和服务器缓存方案效率不高。
3. **缓存策略不匹配**: FL 的迭代特性需要专门设计的缓存策略。

## 2. 研究问题与核心挑战

**核心问题**: 如何设计一个高效存储系统，专门优化 FL 中的非训练工作负载，降低其延迟和成本？

**具体挑战**:
1. **非训练工作负载的多样性**: 不同应用（调度、聚类、调试等）有不同的数据访问模式。
2. **迭代性**: FL 的多轮特性导致数据访问具有可预测的迭代模式。
3. **成本效率**: 云存储和数据传输成本在大规模 FL 中可能非常高。
4. **容错性**: Serverless 函数可能被回收，需要持久化存储保证。

## 3. 主要贡献

1. **FLStore 系统设计**: 提出一个专门为 FL 非训练工作负载设计的存储系统，集成服务器缓存和云对象存储。
2. **工作负载分类与缓存策略映射**: 将非训练工作负载分为五类（评估、聚类、调试、激励、推理），并为每类设计专门的缓存策略。
3. **预测性预取与回填**: 利用 FL 的迭代特性，预测未来轮次的数据需求，提前预取和缓存。
4. **基于生命周期的缓存管理**: 根据数据的生命周期特征（FLIterData、RoundData 等）进行差异化缓存。
5. **容错机制**: 异步备份和恢复机制保证数据在 serverless 函数回收后不丢失。

## 4. 核心方法与设计

### 4.1 系统架构

```
Client Devices
       ↓
FLStore Serverless Cache (λ functions)
       ↓
Persistent Storage (Cloud Object Store)
```

### 4.2 缓存策略分类

| ID | 缓存策略 | 应用场景 |
|----|---------|---------|
| P1 | Individual Client | 评估公平性 |
| P2 | Cluster/Group | 聚类分析 |
| P3 | Round | 调度、调试 |
| P4 | Cross-Round | 激励计算 |
| P5 | Cross-Job | 推理 |

### 4.3 预测性预取

```
当前请求执行 → 预取 Round R_i → 回填 Round R_{i+1}
```

### 4.4 生命周期管理

FLStore 追踪数据的生命周期特征：
- **FLIterData**: 单次 FL 迭代内的数据
- **RoundData**: 单轮训练的数据
- **ClientData**: 单个客户端的数据

### 4.5 故障恢复

使用异步备份机制，在 serverless 函数被回收前将数据持久化到云存储。

## 5. 实验结果

### 5.1 延迟对比

在 EfficientNet、ResNet18、MobileNetV2 等模型上的实验：
- FLStore 相比 ObjStore-Agg 延迟降低 91.3%
- FLStore 相比 Cache-Agg 延迟降低 88.9%

### 5.2 成本分析

在 200 客户端配置下：
- ObjStore-Agg: 基准成本
- Cache-Agg: 降低约 60% 成本
- FLStore: 降低约 92.45% 成本

### 5.3 大规模模型支持

在 ViT-Large 等大规模模型上的实验表明，FLStore 的优势在模型规模增大时更加明显。

### 5.4 缓存策略比较

不同缓存策略（LRU、FIFO、Random、FLStore-adaptive）的对比：
- FLStore 的自适应策略在各种场景下均表现最优

## 6. 潜在问题与局限性

1. **跨云部署**: FLStore 主要针对单一云平台设计，跨云场景下的性能需要验证。
2. **隐私与安全的平衡**: 数据持久化可能带来隐私风险，需要额外的访问控制。
3. **冷启动延迟**: Serverless 函数的冷启动可能影响延迟敏感型应用。

## 8. 个人评注

FLStore 是一篇非常实用的系统论文。联邦学习领域的很多工作都关注算法层面的优化（如 FedAvg 的变体），而 FLStore 关注的是系统层面的基础设施问题——非训练工作负载的存储效率。

论文的核心贡献在于识别了非训练工作负载在 FL 系统中的重要性，并设计了专门化的存储解决方案。预测性预取和基于生命周期的缓存管理是两个有价值的想法，体现了对 FL 应用特性的深入理解。

不过，FLStore 的设计假设了特定的 FL 工作流程，对高度定制化的 FL 系统可能不适用。此外，serverless 架构的选择虽然提供了弹性，但也带来了冷启动延迟等问题，需要在实际部署中权衡。
