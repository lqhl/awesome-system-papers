# Self-Data Distillation for Recovering Quality in Pruned Large Language Models

## 论文信息

- **标题**: Self-Data Distillation for Recovering Quality in Pruned Large Language Models
- **作者**: Vithursan Thangarasa, Ganesh Venkatesh, Mike Lasby, Nish Sinnadurai, Sean Lie (Cerebras Systems、滑铁卢大学)
- **会议**: MLSys 2025
- **链接**: https://proceedings.mlsys.org/paper/2025/File/xxx

## 研究背景与动机

大语言模型（LLM）在自然语言处理领域取得了突破性进展，但其庞大的参数量（从数十亿到数千亿）对部署带来了严峻挑战。**模型压缩（Model Compression）**是解决这一问题的主要技术路线，包括知识蒸馏（KD）、量化（Quantization）、剪枝（Pruning）和因子分解（Factorization）。

**结构化剪枝（Structured Pruning）**是压缩 LLM 的有效方法，它移除整个组件（如整层、整个 attention head、整个 FFN 块）。相比非结构化剪枝，结构化剪枝的硬件兼容性更好，因为移除的是完整的计算单元而非分散的权重。

然而，**剪枝后模型的精度下降严重**——移除 6 个 decoder block（约 19% 的层）的 LLaMA-3.1-8B-Instruct 模型，如果没有微调，准确率从 69.4% 下降到 51.8%（OpenLLM Leaderboard）；即使使用标准的监督微调（SFT），也只能恢复到 56.7%。

**灾难性遗忘（Catastrophic Forgetting）**是精度恢复困难的主要原因——SFT 使用的任务数据集与原始训练分布差异大，导致模型在适应新任务的同时丢失了原有的通用能力。

## 研究问题与核心挑战

Self-Data Distillation 要解决的核心问题：**如何通过自知识蒸馏（self-knowledge distillation）恢复剪枝后 LLM 的模型质量，同时避免灾难性遗忘？**

具体挑战：
1. **剪枝后精度损失的严重性**：结构化剪枝（尤其深度剪枝）会导致推理路径的剧烈变化，精度损失不可忽视
2. **SFT 的灾难性遗忘**：标准 SFT 使用的任务数据分布与预训练分布差异大，导致模型丢失原有能力
3. **蒸馏数据与模型的对齐**：如何生成与原始（未剪枝）模型分布一致的数据？
4. **与推理加速的协同**：剪枝后的模型如何与推理优化（如 Speculative Decoding）结合？

## 主要贡献

1. 提出了 **Self-Data Distillation（自数据蒸馏）**，首个利用原始未剪枝模型生成蒸馏数据集来微调剪枝模型的方法
2. 在 LLaMA-3.1-8B-Instruct 和 Mistral-7B-v0.3-Instruct 上验证，自数据蒸馏相比 SFT 平均准确率提升 8%，在 OpenLLM Leaderboard 上最高恢复 91.2% 的原始质量
3. 提出了 **自数据蒸馏 + 模型合并（Model Merging via SLERP）** 的组合方案，进一步提升剪枝模型质量
4. 验证了自数据蒸馏与 **Speculative Decoding** 的结合，使剪枝模型作为 draft model 时的 token 接受率显著提升

## 核心方法与设计

### 1. 层剪枝算法（Layer Pruning Algorithm）

Self-Data Distillation 使用 **基于 Angular Cosine Distance 的层重要性度量** 来决定哪些层应该被剪枝：

```
Angular Cosine Distance:

  给定层 ` 和层 `+n 的输出向量 h(`)(D) 和 h(`+n)(D):

    d(h(`)(D), h(`+n)(D)) = 1 - cos(h(`)(D), h(`+n)(D))
                          = 1 - (h(`)(D)^T · h(`+n)(D)) / (||h(`)(D)|| · ||h(`+n)(D)||)

  距离越小 → 两层输出越相似 → 这些层越冗余 → 可以剪枝

选择最优剪枝块:

  `* = argmin_{`} d(h(`)(D), h(`+n)(D))

  剪枝块: layers `* to `*+n-1
  重新连接: output(layer `*) → input(layer `*+n)
```

作者发现 **LLM 的中间层冗余度最高**——这与 LoRA、LayerSkip 等工作的发现一致。使用 one-shot 剪枝（即一次性移除多个层，不迭代微调），再通过后续的蒸馏微调恢复质量。

### 2. 自数据蒸馏（Self-Data Distillation）

Self-Data Distillation 的核心思想：**使用原始未剪枝模型 M 生成蒸馏数据集 D'，再用 D' 微调剪枝模型 M'**。

```
传统 SFT（灾难性遗忘的来源）:

  D_sft = { (x_i, y_i) }   ← 使用标准任务数据集（可能偏离原始分布）

  损失: L_SFT = -Σ_i log p_M'(y_i | x_i, c_i)
         ↑ M' 的分布被迫向 D_sft 对齐，偏离 M 的原始分布

自数据蒸馏（Self-Data Distillation）:

  1. 生成蒸馏数据: y˜_i ~ p_M(y_i | x_i, y_i)   ← 用 M 生成 y_i 的"更好版本"
     (rewriting: 让 M 重新生成 y_i，保持语义但改善表达)

  2. 条件选择: y˜_i = y_i if Extract(y˜_i) == y_i else y_i
     (确保蒸馏数据保留正确性，尤其对数学推理等结构化任务)

  3. 微调: L_SelfDistill = -Σ_i log p_M'(y˜_i | x_i)
            ↑ M' 的分布向 M 的分布对齐，而非向外部数据集对齐
```

**关键洞察**：自数据蒸馏通过将蒸馏数据的分布与原始模型的分布对齐，避免了外部数据集引入的分布偏移，从而减轻灾难性遗忘。

### 3. 自数据蒸馏 + 模型合并

论文进一步提出将自数据蒸馏与 **模型合并（Model Merging）** 结合：

```
步骤:
  1. 使用不同数据集对剪枝模型进行多次自数据蒸馏微调:
     - 微调 1: OpenMathInstruct (数学推理)
     - 微调 2: Alpaca (指令遵循)

  2. 使用 SLERP (Spherical Linear Interpolation) 合并两个微调后的模型:

     M_merged = SLERP(M_distilled1, M_distilled2, t=0.5)
              = (sin((1-t)Ω) / sin(Ω)) × M_distilled1
                + (sin(tΩ) / sin(Ω)) × M_distilled2

     其中 Ω 是两个模型参数向量之间的夹角

  3. 结果: M_merged 综合了两个数据集的知识，质量比单一数据集蒸馏更好
```

### 4. 与 Speculative Decoding 的结合

论文探索了自数据蒸馏在 **Speculative Decoding** 中的应用：

```
Speculative Decoding:
  - Draft model (小): M_distilled（自数据蒸馏剪枝模型，更快但精度低）
  - Target model (大): M_70B（原始大模型，精度高但慢）

  流程:
    1. Draft: M_distilled 快速生成 K 个候选 token
    2. Verify: M_70B 并行验证这些 token
    3. Accept: 接受与 M_70B 一致的 token

  自数据蒸馏的作用:
    - 蒸馏后的剪枝模型与原始大模型的分布更接近
    - 因此 token 接受率更高 → 验证步骤减少 → 整体加速更多
```

## 实验结果

### 测试设置

- 模型：LLaMA-3.1-8B-Instruct、Mistral-7B-v0.3-Instruct
- 剪枝块大小：n = 2, 4, 6, 8, 10（每个块 = 1 层）
- 微调数据集：OpenMathInstruct (GSM8k, OpenMath)、Alpaca、Dolly
- 评估基准：OpenLLM Leaderboard v1（MMLU、GSM8k、ARC-C、HellaSwag、TruthfulQA、Winogrande）

### OpenLLM Leaderboard 结果（LLaMA-3.1-8B-Instruct）

| 剪枝配置 | 方法 | 平均分 | 质量恢复率 |
|---------|------|--------|----------|
| Baseline（无剪枝） | NoFT | 69.40 | 100% |
| n=2（剪枝 2 层，节省 5.2%） | NoFT | 66.22 | 95.4% |
| n=2 | SFT | 59.59 | 85.9% |
| n=2 | 自数据蒸馏 | 65.51 | 94.4% |
| n=6（剪枝 6 层，节省 16.3%） | NoFT | 51.82 | 74.7% |
| n=6 | SFT | 56.68 | 81.7% |
| n=6 | 自数据蒸馏 | 63.33 | 91.2% |
| n=10（剪枝 10 层，节省 27.2%） | NoFT | 46.39 | 66.8% |
| n=10 | SFT | 47.58 | 68.6% |
| n=10 | 自数据蒸馏 | 55.91 | 80.6% |

### 自数据蒸馏 + 模型合并结果

| 配置 | 平均分 | 质量恢复率 |
|------|--------|----------|
| n=6 自数据蒸馏（单数据集） | 63.77 | 91.9% |
| n=6 自数据蒸馏 + SLERP（双数据集合并） | 64.75 | 93.3% |

### Speculative Decoding 结果

| Draft Model | 平均接受长度（tokens） | 相对提升 |
|------------|---------------------|---------|
| LLaMA-3.1-8B-Instruct NoFT（无蒸馏） | 2.40 | baseline |
| LLaMA-3.1-8B-Instruct 自数据蒸馏 + SLERP | 3.92 | +63% |

### 消融实验

- 条件选择（Extract 验证）：去掉条件选择时，数学推理任务的准确率下降 12%
- Angular cosine vs. Block Influence：两种层重要性度量效果相当，angular cosine 更高效（只计算最后一个 token）
- 数据集规模：50k 样本达到质量-效率最佳平衡，更大的数据集带来边际递减的提升

## 潜在问题与局限性

1. **蒸馏数据的生成开销**：自数据蒸馏需要用原始未剪枝模型生成蒸馏数据集，生成成本不可忽视。如果目标是压缩单个大模型，生成蒸馏数据的开销可能超过节省

2. **推理加速的间接性**：自数据蒸馏直接优化的是模型质量，而非推理速度。论文的推理加速验证依赖 Speculative Decoding，是一种间接优化

3. **Merge 策略的超参数**：SLERP 的插值参数 t 需要人工调优，最优 t 取决于数据集的互补性，缺乏自动化的 t 选择方法

4. **与其他压缩技术的结合**：论文没有探索自数据蒸馏与量化、知识蒸馏的联合优化——这可能是更大压缩比的方向

## 未来工作

1. 将自数据蒸馏扩展到混合专家模型（MoE）的剪枝
2. 研究自动化的模型合并参数选择
3. 探索自数据蒸馏与 teacher-student 蒸馏的结合
4. 在更大规模模型（如 LLaMA-3 70B）上验证

## 个人评注

Self-Data Distillation 是一篇概念清晰、方法直接的论文。它没有引入复杂的算法或系统设计，而是将"用原始模型生成数据来微调剪枝模型"这一简单想法系统化和实验验证。

论文最值得关注的发现是**自数据蒸馏在高推理难度任务（GSM8k、ARC-C）上的优势远大于简单任务（HellaSwag）**。这说明灾难性遗忘在复杂推理任务上更为严重，而自数据蒸馏通过保持与原始模型分布的一致性，有效地缓解了这个问题。

不过，我认为论文对"自数据蒸馏为什么有效"的理论分析不足。论文反复强调"alignment with original model's distribution"，但缺乏对分布偏移的具体量化分析。此外，"rewriting"过程（用 M 重新生成 y_i）的设计略显粗糙——为什么要 rewrite？直接用 M 生成新数据而不基于 y_i 是否更高效？这些问题值得更深入探讨。

总体而言，自数据蒸馏为结构化剪枝后的模型质量恢复提供了一个简单有效的方案，值得作为后续研究的 baseline。
