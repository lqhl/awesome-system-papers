# Interference-Aware Edge Runtime Prediction with Conformal Matrix Completion

**会议**：MLSys 2025

## 一、背景

边缘计算系统正承担越来越复杂的工作负载，但其硬件高度异构（从微控制器到 x86 服务器），资源极为有限。在边缘环境中，工作负载经常需要共享设备（multi-tenancy），导致工作负载之间产生严重的干扰（interference），实测可达 20× 的运行时间膨胀。准确预测工作负载在异构设备上的运行时间（包括干扰影响）对于资源调度、延迟保障和 QoS 至关重要，但现有方法要么数据效率低，要么需要侵入式的性能分析（instrumentation），在边缘场景中难以实用。

---

## 二、要解决的问题

1. **数据效率问题**：边缘系统中 (workload, platform, interference) 的组合空间指数增长，不可能穷举基准测试所有组合，必须从稀疏观测中泛化预测。
2. **干扰建模困难**：边缘设备的资源争用类型复杂（调度对齐、功耗/时钟频率、蓝牙等应用级通信通道），不像云环境那样可以用 micro-benchmark 量化 CPU/内存/网络等标准资源。
3. **不确定性量化缺失**：实际部署需要的不是"均值预测"而是带概率保证的运行时间上界（runtime bound），现有方法无法提供可证明的不确定性边界。
4. **异构性跨度大**：最快和最慢的平台/工作负载之间运行时间差异跨越数个数量级，朴素的 l₂ loss 会被大数值主导。

---

## 三、洞察与设计

**关键洞察**：工作负载的运行时间可以分解为一系列性能特征的乘积（而非加和），因此在对数空间中建模可以自然地归一化异构性跨度，且能利用中心极限定理使残差分布接近正态。同时，干扰效应可以在工作负载-平台的共享 embedding 空间中被分解为多种"干扰类型"的叠加，每个工作负载对每种干扰类型有"易感性"（susceptibility），每个干扰源对每种类型有"强度"（magnitude）。

基于此洞察，Pitot 系统的设计包含四个关键组件：

1. **Log-Residual Objective**：先用简单模型学习每个 workload 的"难度"和每个 platform 的"速度"作为 baseline（$\log(\bar{C}_{ij}) = \bar{w}_i + \bar{p}_j$），然后在对数空间的残差上训练矩阵分解模型。这使得模型对工作负载的简单缩放具有不变性。

2. **Two-Tower 神经网络矩阵分解**：使用两个 MLP 分别将 workload 特征和 platform 特征映射为 embedding 向量 $w_i, p_j$，通过内积 $w_i^T p_j$ 预测残差。输入特征包括 WebAssembly opcode 执行计数（workload 侧）和 CPU/runtime 信息（platform 侧），外加每个 workload/platform 的可学习参数。

3. **干扰感知预测**：在 embedding 空间中引入低秩"干扰矩阵" $F_j$，将干扰效应建模为 $w_i^T F_j w_k$。通过 SVD 分解可解释为多种干扰类型的叠加。对多个干扰源的情况，在总 magnitude 上施加 leaky ReLU 激活函数，捕捉"干扰阈值"效应。

4. **Conformalized Quantile Regression (CQR)**：训练多个目标分位数的模型，在测试时用 conformal prediction 校准，选择产生最紧边界的分位数，提供带数学保证的运行时间上界。

---

## 四、实现细节

- **模型架构**：workload MLP 和 platform MLP 各 2 个隐藏层、128 单元、GELU 激活。总参数量仅 111,200，workload/platform embedding 网络各占约一半。
- **干扰项**：platform MLP 增加额外输出头生成 $v_s, v_g$ 向量，干扰激活函数使用 leaky ReLU（负斜率 0.1）避免"死"干扰类型。
- **分位数回归**：为降低计算开销，只对 workload embedding 学习多个分位数版本，platform embedding 共享。训练时间增加约 5%。
- **校准池**：按同时运行的工作负载数量分割校准集，保持条件可交换性。
- **训练**：SGD 优化，在 RTX 4090 上训练仅需 12.1 秒，单次推理约 400K FLOPs。
- **数据集**：24 台异构设备（x86, ARM A-class SBC, RISC-V SBC, ARM M-class MCU），249 个 WebAssembly benchmark（Polybench, MiBench, UCSD Cortex Suite, Libsodium, CPython），共 410,970 个数据点，含 53,637 个无干扰观测和 357,333 个带干扰观测，约 80 小时连续采集。
- **Workload 特征**：通过 instrumented interpreter 统计每个 opcode 的执行次数。
- **代码开源**：https://github.com/wiseLabCMU/pitot

## 五、实验结果

### 预测误差（MAPE）

| 方法 | 无干扰 | 有干扰 |
|------|--------|--------|
| Pitot | **5.2%** | **~8%** |
| Neural Network | ~10% | ~15% |
| Attention | ~12% | ~18% |
| Matrix Factorization | >75% | >75% |

- Pitot 比最佳 baseline 平均降低 36% 误差、44% 更紧的不确定性边界。
- 最大改进达 48% 更低误差和 58% 更紧边界。

### 消融实验关键结论

| 组件 | 效果 |
|------|------|
| Log-Residual Objective | 朴素 proportional loss 无法收敛到合理误差，log-residual 显著优于 log objective |
| Side Information | 同时使用 workload + platform 特征效果最佳；platform 特征边际贡献更大 |
| 干扰建模 vs Discard/Ignore | 干扰感知模型在两种评估场景（有/无干扰）上都表现最优 |
| 激活函数 | leaky ReLU 激活带来小但显著的改进 |
| CQR + Quantile Choice | 相比 naive CQR 和 non-quantile 校准，显著提升边界紧致度 |

### 可解释性

t-SNE 可视化显示学到的 workload embedding 按 benchmark suite 自然聚类，验证了模型学到了有意义的性能特征表示。

## 六、批判性分析

1. **数据集局限性**：249 个 benchmark 全部基于 WebAssembly，且主要是计算密集型（compute-bound）。实际边缘工作负载涉及大量 I/O、网络通信和传感器交互，Pitot 在这些场景下的表现完全未知。论文对此仅一笔带过。

2. **假设过强**：要求每个 workload 至少被观测一次（cold-start 问题未解决），且假设 workload 特性不随时间变化。对于动态负载（如数据分析任务随输入数据变化），论文简单地将其视为"不同 workload"，这在实际系统中不可操作——运维人员无法预知 phase shift 何时发生。

3. **干扰模型的可扩展性存疑**：实验中最多只测试了 3 个并发干扰工作负载，但实际边缘系统可能有更多并发任务。多工作负载干扰的组合爆炸问题并未真正解决，只是用激活函数做了近似。

4. **Baseline 选择偏弱**：Matrix Factorization baseline 不使用任何 side information 且 >75% 误差，几乎是稻草人。Neural Network 和 Attention baseline 都是作者自行构造的，缺乏与领域内真正 SOTA 的对比（如 Quasar/Paragon 的实际实现）。

5. **泛化验证不足**：所有实验在同一个 24 设备集群上进行。新增一台未见过的设备类型（如 GPU、FPGA）或新的 benchmark suite 时，性能下降程度未知。

6. **CQR 的实用价值**：overprovisioning margin 在 12%-25% 范围内，对延迟敏感的实时系统来说，这个余量可能仍然太大，而论文未讨论这一问题。

---

## 七、AI Infra / MLSys 视角

1. **异构推理集群调度**：Pitot 的核心思路——用矩阵分解 + side information 在异构设备上预测工作负载性能——可以迁移到 AI 推理服务的异构 GPU/NPU 集群调度。例如预测不同模型在不同 GPU 型号上的推理延迟，以及多模型共享 GPU 时的干扰效应。

2. **Co-location 干扰预测**：大规模推理系统中多个模型共享 GPU 时的干扰（显存争用、SM 竞争、PCIe 带宽）是重要问题。Pitot 的 embedding 空间干扰建模方法（susceptibility × magnitude 分解）提供了一个比 micro-benchmark 更优雅的框架。

3. **轻量级不确定性量化**：Conformalized Quantile Regression 的思路可以用于 LLM serving 的 SLO 保障——预测请求延迟的上界，辅助 admission control 和调度决策。Pitot 仅需 400K FLOPs 推理，足够实时使用。

4. **可跟进方向**：
   - 将 Pitot 扩展到 GPU 推理场景，用模型架构特征（层数、参数量、attention head 数）替代 opcode 计数作为 workload side information
   - 研究 LLM 推理中 prefill/decode 阶段共享 GPU 时的干扰建模
   - 结合 Pitot 的不确定性边界与 SLO-aware scheduler 做端到端优化

---

## 八、总结

Pitot 提出了一种面向异构边缘系统的干扰感知运行时间预测方法，将问题建模为矩阵补全，结合 log-residual objective、two-tower 神经网络矩阵分解、embedding 空间干扰建模和 Conformalized Quantile Regression 四个关键创新，在 24 设备 / 249 benchmark 的 WebAssembly 数据集上实现 5.2% 预测误差，比 baseline 提升约 2×。方法极其轻量（111K 参数，12 秒训练），可解释性好，但在真实边缘工作负载的多样性、设备泛化能力和大规模并发干扰场景下的表现尚待验证。
