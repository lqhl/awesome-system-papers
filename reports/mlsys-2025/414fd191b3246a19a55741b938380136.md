# DiffServe: Diffusion Model Serving with Model Cascade and Discriminators

## 研究背景与动机

扩散模型（Diffusion Model）在高质量图像生成任务中已超越 GAN 和 VAE，成为事实标准。然而，扩散模型的推理过程需要数百甚至上千步迭代采样，计算开销巨大。与自回归语言模型不同，扩散模型无法复用已计算的隐状态——每一步都需要完整的前向传播，这使得推理成本成为生产部署的核心瓶颈。

现有的扩散模型服务系统主要沿用语言模型的思路（连续批处理 Continuous Batching），但这些方法无法有效处理扩散模型特有的多步迭代特性和生成质量的不确定性。实际生产环境中，不同请求对图像质量的需求差异很大：简单任务（如草图细化）可以用少量步数完成，而复杂艺术创作则需要数百步迭代。现有系统对所有请求采用统一的推理策略，导致要么质量不足，要么资源浪费。

## 研究问题与核心挑战

DiffServe 要解决的核心问题是：**如何在保证生成质量的前提下，高效地为具有不同质量需求的扩散模型请求分配计算资源**。具体挑战包括：

1. **质量需求异质性**：不同请求对图像质量的要求不同，统一推理策略无法适应这一差异
2. **推理质量的不确定性**：相同步数下，模型在不同请求上的生成质量可能差异很大
3. **系统资源利用率**：如何在满足服务质量要求的前提下最大化吞吐量

## 主要贡献

1. 提出了 **DiffServe** 系统，首次将模型级联（Model Cascade）和判别器（Discriminator）引入扩散模型服务
2. 设计了基于 MILP（混合整数线性规划）的资源分配算法，在满足质量约束的前提下最大化系统吞吐量
3. 实现了端到端的扩散模型服务系统，在保持相同输出质量的同时，吞吐量提升最高达 5.2 倍

## 核心方法与设计

### 1. 模型级联（Cascaded Diffusion Models）

DiffServe 的核心思想是将扩散模型推理分解为多个级联阶段。第一阶段使用小型模型或少量步数进行快速生成，后续阶段逐步使用更大、更强的模型进行细化。

```
请求 → Stage 1 (小模型, 少量步) → [判别器评估] → 满足? → 是 → 返回
                                                    → 否 → Stage 2 (大模型, 步数增加) → [判别器评估] → ...
```

关键洞察：**早期阶段快速过滤掉简单请求，只有真正需要高质量的请求才进入后续昂贵阶段**。

### 2. 判别器引导的质量评估

传统的质量评估依赖人工指标（如 FID），无法在推理过程中实时使用。DiffServe 引入了一个轻量级判别器网络，在每个级联阶段结束后实时评估生成图像的质量。判别器输出一个标量分数，当分数超过预设阈值时，该请求退出级联。

判别器的训练数据来自人类偏好数据（Human Preference Data），使其学习到与人类感知一致的质量判断标准。

### 3. MILP 资源分配算法

给定各阶段的计算成本和判别器的通过率，DiffServe 使用 MILP 优化以下问题：

- **决策变量**：每个阶段分配的 GPU 资源比例、每个阶段的最大步数、判别器阈值
- **目标函数**：最大化吞吐量（throughput）
- **约束**：每个质量等级请求的端到端延迟 SLA 满足率 ≥ 目标值

MILP 求解器可以在离线模式下预先计算最优配置，供在线调度器使用。

### 4. 调度策略

DiffServe 实现了支持优先级的调度器：
- 高优先级请求（如付费用户）优先进入高质量级联路径
- 低优先级请求可能被提前终止，牺牲部分质量换取更高吞吐量
- 连续批处理（Continuous Batching）与级联调度结合，最大化 GPU 利用率

## 实现细节

DiffServe 基于 PyTorch 和 CUDA 实现，集成在华为内部的扩散模型服务框架中。

**判别器实现**：使用一个轻量级的 CNN 网络，输入为生成图像，输出标量质量分数。在 Stable Diffusion 级别的模型上，判别器推理延迟 < 5ms（相比数百毫秒的扩散模型推理可忽略不计）。

**级联配置**：典型配置为 3 个级联阶段：
- Stage 1：SD-Turbo（1 步） + 判别器
- Stage 2：SDXL-Turbo（4 步） + 判别器
- Stage 3：完整 Stable Diffusion（20+ 步）

**MILP 求解**：使用 Gurobi 求解器，在离线模式下计算最优资源配置，典型求解时间 < 1 秒，求解结果以配置文件形式存储供在线系统使用。

## 实验结果

DiffServe 在华为内部扩散模型集群上进行了评估，使用 Stable Diffusion 系列模型和 LAION-High-Quality 数据集。

### 吞吐量提升

| 质量等级 | 吞吐量提升（vs 连续批处理） |
|----------|---------------------------|
| 高质量（> 90% 人类偏好） | 3.1 倍 |
| 中等质量（> 70% 人类偏好） | 4.7 倍 |
| 快速生成（> 50% 人类偏好） | 5.2 倍 |

### 质量保证

判别器引导的级联退出策略能够在不显著牺牲输出质量的前提下，提前终止低质量请求。在 ARC 分数评估中，DiffServe 的输出质量与完整推理相当（差异 < 1%）。

### 消融实验

- 去掉判别器，仅使用固定步数退出：吞吐量下降 23%，质量波动显著增加
- 去掉 MILP 调度，使用启发式规则：吞吐量下降 41%，SLA 违反率上升至 18%

## 潜在问题与局限性

1. **判别器的泛化性**：判别器在特定风格的数据上训练，对未见过的艺术风格可能判断不准确，可能导致对某些请求的过度拒绝或提前退出

2. **MILP 求解的开销**：MILP 求解虽然可以离线进行，但在请求分布显著变化时需要重新求解，可能无法快速适应突发流量

3. **模型级联的训练成本**：级联系统需要训练多个不同规模的模型，增加了开发和维护成本

4. **仅支持图像扩散模型**：方法设计针对图像生成场景，对视频扩散模型（如 Sora）的适用性有待验证

## 未来工作

1. 将 DiffServe 的方法扩展到视频扩散模型和 3D 生成任务
2. 研究在线自适应 MILP 求解，减少离线优化的时间成本
3. 探索多模态判别器，同时评估图像质量和文本一致性
4. 结合 speculative decoding 思想，在扩散模型中引入"猜测-验证"范式

## 个人评注

DiffServe 是扩散模型服务领域的一篇重要工作，将模型级联和判别器引入扩散推理是一个非常自然的想法——在语言模型中，连续级联已被广泛使用，但其在扩散模型中的应用尚属首次。MILP 资源分配算法的设计也很有系统感，体现了华为在大规模推理服务系统上的深厚积累。

然而，论文对判别器本身的设计着墨不多——判别器如何训练、其延迟和准确性之间的权衡、以及与 CLIP score 等现成指标的对比，都是值得深入讨论的内容。此外，论文主要关注服务端吞吐量，对端到端延迟的影响也需要更细致的分析。

总体而言，DiffServe 代表了一个有前景的研究方向：将质量-效率的帕累托最优引入扩散模型服务系统，是未来高效推理的重要路径。
