# DiffServe: Efficiently Serving Text-to-Image Diffusion Models with Query-Aware Model Scaling

## 一、背景

Text-to-image diffusion model（如 Stable Diffusion、SDXL）已广泛集成到 Adobe Firefly、Midjourney 等交互式内容创作工作流中。随着使用量增长，高效 serving 这些模型变得至关重要——服务提供者需要在满足延迟 SLO 的同时最大化硬件利用率和吞吐量。

Diffusion model serving 面临两个核心挑战：(1) 高质量模型计算开销大，例如 SDXL 比 SDXL-Lightning 质量高 30% 但慢 4.6×；(2) 查询需求随时间剧烈波动，按峰值配置资源会导致低谷时大量浪费。

---

## 二、要解决的问题

1. **模型质量-效率 trade-off 无法动态适配**：现有 serving 系统（如 Clipper、TF Serving）对所有 query 使用同一模型，要么全用重模型（高质量但高延迟），要么全用轻模型（低延迟但低质量），无法根据 query 难度差异化处理。

2. **缺乏有效的 query 难度判别器**：已有的图像质量指标（CLIP Score、PickScore、FID）无法在 per-query 粒度上有效区分 easy/hard query。论文实验表明，基于这些指标的级联判别器甚至不如随机分类器。

3. **级联 serving 的资源分配问题**：model cascade 引入了 confidence threshold、batch size、模型放置等多个耦合参数，需要联合优化以在动态负载下平衡质量和 SLO 违约率。

---

## 三、洞察与设计

**关键洞察**：对于 20-40% 的"easy" query，轻量 diffusion model 生成的图像质量与重量级模型相当甚至更好——这意味着可以构建 model cascade，让 easy query 只经过轻模型即可返回，从而在不损失质量的前提下大幅提升吞吐量。

基于此洞察，DIFFSERVE 设计了一套端到端的 serving 系统：

- **Model Cascade 架构**：query 首先由轻量模型处理，discriminator 评估生成图像质量；若 confidence score 超过阈值则直接返回，否则转发至重量级模型。
- **对抗训练 Discriminator**：采用 EfficientNet-V2 做二分类（real vs. fake），训练集包含真实图像（MS-COCO、DiffusionDB）和两种模型的生成图像。推理时利用 softmax confidence score 判断轻模型输出是否达标。
- **MILP 资源分配**：将 confidence threshold、batch size、设备分配建模为混合整数线性规划（MILP），周期性求解以适配负载波动。目标函数最大化 confidence threshold（即最大化质量），约束包括延迟 SLO、吞吐量需求和设备总量。

系统架构包含 Controller、Load Balancer、Workers 和 Model Repository，Controller 通过收集 runtime statistics 周期性调用 MILP solver（Gurobi，平均 ~10ms）重新分配资源。

---

## 四、实现细节

- **Discriminator**：EfficientNet-V2 架构，推理延迟 ~10ms（A100），远小于 diffusion model 的秒级延迟。训练为 real/fake 二分类任务，用 ground truth 图像（MS-COCO）作为 "real" 样本效果最佳。
- **Queuing delay 估计**：使用 Little's Law（W = L/λ），基于实时队列长度和到达率估计排队延迟，比 Proteus 的 "2x 执行时间" 启发式更准确。
- **Over-provisioning factor λ**：默认 1.05，用指数加权移动平均估计 query demand D。
- **实现规模**：模拟器 ~7K 行 Python 代码；testbed 基于 HuggingFace Diffusers + PyTorch，16 台 A100-80GB GPU，组件间通信使用 gRPC。
- **三组 cascade 配置**：
  - Cascade 1: SD-Turbo (0.1s) + SDv1.5 (1.78s)，SLO=5s
  - Cascade 2: SDXS (0.05s) + SDv1.5 (1.78s)，SLO=5s
  - Cascade 3: SDXL-Lightning (0.5s) + SDXL (6s)，SLO=15s

## 五、实验结果

**实验平台**：16 × NVIDIA A100-80GB GPU cluster；模拟器 + testbed 两种验证方式（模拟器与 testbed 结果差异仅 0.56% FID 和 1.1% SLO violation）。

**数据集**：MS-COCO 2017（Cascade 1-2，512×512）、DiffusionDB（Cascade 3，1024×1024），各取 5K text-image pairs。负载 trace 使用 Microsoft Azure Functions trace。

| 对比系统 | 分配方式 | Query-aware | 备注 |
|---------|---------|------------|------|
| Clipper-Light | 静态 | 否 | 全用轻模型 |
| Clipper-Heavy | 静态 | 否 | 全用重模型，SLO violation 45-75% |
| Proteus | 动态 | 否 | 随机路由 |
| DIFFSERVE-Static | 静态 | 是 | cascade 但按峰值配置 |
| DIFFSERVE | 动态 | 是 | 完整系统 |

**主要结果**：

| 指标 | DIFFSERVE 表现 |
|------|---------------|
| 响应质量（FID）| 比 Proteus 提升 ~20%，比 Clipper-Light 提升 ~23.4% |
| SLO violation 降低 | 比 Clipper-Heavy 降低 19-70%，比 DIFFSERVE-Static 降低 1.2-1.4× |
| Cascade 2 FID 降低 | 6-24% vs. 所有 baseline |
| Cascade 3 FID 降低 | 8-15% vs. 所有 baseline（Clipper-Heavy 除外，但其 SLO violation 高达 68-73%）|
| MILP solver overhead | ~10ms，不在 query 关键路径上 |

**Discriminator 对比**：EfficientNet w GT > ResNet w GT > ViT w GT > EfficientNet w Fake，且均远优于 PickScore/CLIPScore（后两者甚至不如随机分类）。

## 六、批判性分析

1. **FID 作为唯一质量指标的局限**：论文自己指出 FID 是分布级指标而非 per-image 指标，但整个系统评估仍以 FID 为主。一个有趣的现象是混入轻模型输出反而降低了 FID（因为增加了分布多样性），这实际上说明 FID 可能无法真实反映用户感知质量。论文缺少人类评估实验来验证 FID 改善是否对应真实的用户体验提升。

2. **Discriminator 的泛化性未充分验证**：discriminator 在 MS-COCO/DiffusionDB 上训练，但实际 serving 场景中的 query 分布可能与训练集差异很大。论文未讨论 distribution shift 对 discriminator 准确率的影响，也未测试 out-of-distribution prompts。

3. **仅支持两级 cascade**：系统设计局限于 light-heavy 两级，虽然 Discussion 中提到可扩展到多级，但没有实验验证。实际生产中模型选择空间远不止两个。

4. **模型对比的 vintage 问题**：使用的 diffusion model（SDv1.5、SD-Turbo、SDXS）已相对过时，与 SDXL、SD3、FLUX 等新一代模型相比架构差异很大。在更现代的模型上 easy/hard query 的分布特性是否仍然成立，缺乏验证。

5. **模拟器为主的评估**：大部分实验在模拟器上完成，虽然与 testbed 误差小，但模拟器无法捕捉 GPU 内存竞争、context switching、网络抖动等真实系统问题。特别是 gRPC 通信和 discriminator 推理在高并发下的行为未充分压测。

6. **MILP 求解在更大规模下的可行性**：当前 MILP 仅有 4 个变量（x1, x2, b1, b2），~10ms 可解。但若扩展到多级 cascade、异构 GPU、多模型族，变量和约束数量会急剧增长，求解时间可能不再可忽略。

## 七、AI Infra / MLSys 视角

1. **Query-aware routing 的普适性**：DIFFSERVE 的核心思路——根据 query 难度选择不同规模的模型——对 LLM serving 同样适用。论文也引用了 HybridLLM 和 FrugalGPT 等工作。对于 LLM，可以用 perplexity、token 级 uncertainty 或 lightweight classifier 做 query routing，这是一个有价值的 research direction。

2. **Discriminator 设计思路可迁移**：用对抗训练的分类器评估生成质量（而非依赖 CLIP Score 等通用指标）的方法，可以迁移到 LLM serving 中用于评估回答质量，例如训练一个 reward model 的轻量版本作为 router。

3. **MILP 框架用于 serving 资源分配**：将 confidence threshold 与 batch size、设备分配联合优化的 MILP 思路值得借鉴，特别是在 LLM serving 中 KV cache 管理、prefill/decode 分离、speculative decoding 等场景下的资源分配问题。

4. **可跟进的 research direction**：
   - 将 model cascade 扩展到 speculative decoding 场景：小模型 draft + 大模型 verify 本质上也是 cascade，可以引入 query-aware 的 speculation depth 调节。
   - 在多模态生成（video、3D）场景中应用类似的 cascade + adaptive resource allocation 框架。
   - 探索 predictive router（基于 text prompt 直接预测 query difficulty），避免轻模型的冗余计算。

---

## 八、总结

DIFFSERVE 提出了 query-aware model scaling 方法来高效 serve text-to-image diffusion model：通过对抗训练的 EfficientNet discriminator 识别 easy query 并用轻模型快速处理，同时用 MILP 联合优化 confidence threshold、batch size 和设备分配以适配动态负载。系统在三组 cascade 配置上实现了最高 24% 的 FID 改善和 19-70% 的 SLO violation 降低。主要局限在于 FID 评估的有效性、discriminator 的泛化性，以及仅验证了两级 cascade 和较老的模型架构。整体思路对 generative model serving 领域（包括 LLM）有较好的参考价值。
