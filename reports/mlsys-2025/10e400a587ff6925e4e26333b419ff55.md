# Balancing Pipeline Parallelism with Vocabulary Parallelism

## 一、背景

随着 Transformer 大语言模型规模持续增长，Pipeline Parallelism (PP) 因其低通信开销和高算术强度成为大规模训练的核心并行策略之一。近年来，Zero Bubble PP、V-Shape scheduling、BPipe 等工作不断优化 PP 的 bubble 率和内存效率。然而，PP 中存在一个被长期忽视但影响日益严重的问题：vocabulary 层（输入 embedding 层和输出 projection + softmax 层）造成的计算和内存不均衡。

随着模型支持的 vocabulary size 不断增大（如 Gemma 2 9B 的 256k vocabulary），vocabulary 层的计算量和参数量可达 transformer 层的 5 倍以上，这一不均衡问题变得尤为突出。

---

## 二、要解决的问题

在标准 PP 设置中，transformer 层被均匀分配到各 pipeline stage，但输入层固定在第一个 stage、输出层固定在最后一个 stage，导致：

1. **计算不均衡**：最后一个 stage 因承担输出层额外计算而成为瓶颈，其他 stage 出现 pipeline bubble 空闲等待
2. **内存不均衡**：第一个 stage（输入 embedding）和最后一个 stage（输出 projection 权重 + activation）承受显著更高的参数内存和 activation 内存
3. **现有缓解方案的局限**：
   - **Layer redistribution**（DeepSpeed 等）：只能在 layer 粒度调整，无法同时平衡计算和内存（两者 compute-to-memory ratio 不同）；且依赖具体模型配置，灵活性差
   - **Interlaced pipeline**（nnScaler）：用 TP 风格拆分 vocabulary 层，但引入同步 all-reduce 造成额外 bubble（约 11% 性能损失），且 activation memory 增加到 1.5 倍，在大规模场景下直接 OOM

---

## 三、洞察与设计

**关键洞察**：Vocabulary 层的 softmax 计算中的 all-reduce 通信屏障可以通过借鉴 online softmax 的思想进行重排和合并——先用局部 max/sum 计算局部 softmax，再通过轻量级全局校正得到正确结果，从而将通信屏障从 3 个减少到 1 个，使得 vocabulary 层的计算可以被自然地分解为独立的 pipeline pass 并嵌入现有 pipeline schedule 中，仅付出极小的常数 activation memory 开销。

基于这一洞察，作者提出 Vocabulary Parallelism：

1. **Vocabulary 层沿词表维度均匀分区**到所有 pipeline 设备，每个设备持有 V/p 大小的词表分片
2. **Forward 优化（Algorithm 1）**：借鉴 online softmax，先在各设备上用局部 max 和 sum 计算局部 softmax'，再通过一次 all-reduce 获取全局 max 和 sum 进行校正，将通信屏障从 3 个减为 2 个
3. **Backward 优化（Algorithm 2）**：进一步观察到输入梯度的三个 all-reduce/reduce 可以延迟到矩阵乘法完成后合并执行，将通信屏障减为 1 个
4. **通用 schedule 集成方法**：基于 Qi et al. (2024) 的 building block 框架，将 vocabulary pass（S 和 T）插入现有 pipeline schedule 的 building block 中，仅增加 1-2 个 interval 的 lifespan，activation memory 增加量为常数级

---

## 四、实现细节

- 基于开源 **Megatron-LM** 实现 pipeline scheduler 和分区后的 vocabulary 层
- 通信操作（all-reduce、reduce）放在独立 CUDA stream 中，与 transformer 层计算重叠；通过 CUDA MPS 的 `CUDA_DEVICE_MAX_CONNECTIONS` 映射到独立 GPU work queue
- 所有 TP 通信组使用高优先级 stream，避免与 vocabulary 通信重叠时的性能干扰
- Reduce 操作统一实现为 NCCL AllReduce，避免设备间通信量不均衡
- Vocabulary size padding 到 2p 的倍数以改善内存对齐（实测提升约 8%）
- 支持 tied embedding（输入输出共享权重），可节省内存并省去梯度同步的额外 all-reduce
- 通过 profiling forward/backward 时间比来决定 vocabulary pass 的插入位置（实际中该比值接近 2:1，几乎不需要调整）

## 五、实验结果

**实验平台**：最多 32 块 NVIDIA A100 SXM 80GB GPU，4 节点，RoCE RDMA 互联

### 1F1B Schedule 对比（纯 PP）

| 方法 | 相比 Baseline 的吞吐提升 | 说明 |
|------|------------------------|------|
| Redis (Layer Redistribution) | 大 vocab 时下降 8%–33% | 无法处理输出层计算 > 单 stage 的情况 |
| Interlaced | MFU 一致但低于 Vocab | 32 GPU + seq 4096 时 OOM |
| Vocab-1 | +5% 到 +51% | 稳定 MFU，不随 vocab size 变化 |
| Vocab-2 | 略低于 Vocab-1 | 额外计算开销换取更少通信屏障 |

- Vocabulary Parallelism 在 21B 模型上比 Interlaced 方法高 6.7%–8.2% MFU
- 峰值内存：Vocab 方法在 pipeline 设备间均衡分布，Interlaced 需要 1.5x activation memory

### V-Half Schedule 对比

| 配置 | Vocab-1 vs Baseline 吞吐提升 |
|------|------------------------------|
| 16–32 GPU, 32k–256k vocab | +7.2% 到 +143% |
| 内存均衡 | 设备间峰值内存差异 < 2.5 GB（Baseline 差异达 45 GB） |
| 32 GPU + 256k vocab | Baseline OOM，Vocab-1 正常运行 |

### Vocabulary 层 Scaling 效率

| 层 | 8 GPU | 16 GPU | 32 GPU |
|----|-------|--------|--------|
| Output (Vocab-1, seq 4096) | 93.2% | 88.0% | 85.2% |
| Output (Vocab-2, seq 4096) | 88.4% | 83.4% | 79.7% |
| Input (seq 4096) | 27.7% | 15.5% | 8.4% |

输入层 scaling 效率较低，因其需要在所有设备上构建完整输出张量。

## 六、批判性分析

1. **输入层 scaling 效率极低但被轻描淡写**：Input layer 在 32 GPU 时仅 8.4% 的线性 scaling 效率，这意味着输入层的并行化几乎没有实际加速，只是将其均匀分散到各设备上。论文将此放在附录中简单带过，但这对总体吞吐的影响值得更深入讨论。

2. **实验仅使用纯 PP，生产环境泛化性存疑**：作者声称 "结论可泛化到 PP+TP+DP 的生产环境"，但 TP 和 Vocab Parallelism 在通信模式上有潜在冲突（论文自己也提到高优先级 stream 的 workaround），实际组合效果缺乏验证。

3. **仅测试 GPT-like 模型**：没有在实际开源模型（如 Llama 3、Gemma 2）上进行端到端训练验证。使用自定义的 GPT-like 模型配置，无法完全反映真实生产场景中的性能表现。

4. **Vocab-2 收益不明显**：Algorithm 2 相比 Algorithm 1 将通信屏障从 2 减到 1，但实际 MFU 差异很小，有时甚至更低（因为额外计算开销）。论文花了大量篇幅推导 Algorithm 2 但其实际价值有限。

5. **128 microbatch 的设置偏大**：实验固定使用 128 microbatches，这会稀释 bubble 的影响。在更小的 microbatch 数量下（更贴近实际训练场景），bubble 比例更高，Vocabulary Parallelism 的收益可能不同。

## 七、AI Infra / MLSys 视角

1. **直接的实用价值**：随着 vocabulary size 不断增大（多语言模型、多模态模型），vocabulary 层不均衡问题会越来越严重。这篇工作提供了一个干净、通用的解决方案，已开源并基于 Megatron-LM 实现，可直接集成到现有训练框架。

2. **Online softmax 思想的系统化应用**：将 online softmax 的局部计算 + 全局校正思想从 FlashAttention 场景迁移到 pipeline schedule 中，是一个值得借鉴的跨领域技术迁移范例。

3. **多模态 LLM 的直接延伸**：论文在 Future Work 中明确提到，多模态 LLM 的 embedding 层（如 vision encoder 的 projection 层）同样存在不均衡问题。将 Vocabulary Parallelism 扩展到 multimodal embedding 是一个明确且可操作的研究方向。

4. **CUDA kernel fusion 的优化空间**：论文提到当前实现是纯 Python，将 Algorithm 2 的 forward + backward 融合为 CUDA kernel（类似 FlashAttention 避免 softmax 中间结果的 HBM 读写）可以进一步提升性能，尤其在 long-context + large-vocabulary 场景下。

5. **与 Zero Bubble PP 的协同**：本文作者团队（Qi et al.）也是 Zero Bubble PP 的提出者。将 Vocabulary Parallelism 与 zero-bubble schedule 结合，理论上可以同时消除 bubble 和 vocabulary 不均衡，是一个自然的后续方向。

---

## 八、总结

本文针对 Pipeline Parallelism 中长期被忽视的 vocabulary 层不均衡问题，提出 Vocabulary Parallelism：将 vocabulary 层沿词表维度均匀分区到所有 pipeline 设备，借助 online softmax 思想优化通信屏障数量，并通过通用的 building block 框架集成到现有 pipeline schedule 中。方法在不同规模（8–32 GPU）和 vocabulary size（32k–256k）下均表现出稳定的吞吐提升（5%–51%）和显著的峰值内存降低，与 V-Half 结合可实现计算和内存的完全均衡。主要局限在于输入层并行化效率低、缺乏与 TP/DP 组合的实验验证，以及仅在自定义模型上测试。
