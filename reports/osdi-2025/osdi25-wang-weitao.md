## 一、背景

现代数据中心网络的传输层（transport layer）承担着机器间可靠数据传输的职责。当前主流的数据中心传输协议（DCTCP、HPCC、Timely 等）的带宽分配策略相对刚性——在流量竞争时采用公平共享（max-min fair）策略，无法区分不同应用的差异化需求。

随着分布式机器学习训练、Spark/Hadoop、RPC 等应用的兴起，应用对网络带宽的诉求日益多元：DNN 训练中不同 tensor 的传输优先级不同；map-reduce 任务中 straggler 流需要动态提速；多个并发 job 之间存在竞争关系。加权带宽分配（weighted bandwidth allocation）作为一种强大的抽象，可以让应用根据需要灵活调整流之间的带宽比例，但如何在大规模数据中心中高效、精准、敏捷地实现这一目标仍是未解难题。

---

## 二、要解决的问题

加权带宽分配面临三大根本挑战：

**1. 瓶颈识别难**：数据中心网络多跳、多路径，每个流经过的路径由随机哈希决定，各跳竞争的流集合不可预测，且瓶颈跳随时可能变化。

**2. 现有方案的局限**：
- **交换机队列调度方案**（WFQ、WRR 等）：受限于硬件每流队列数量少、权重粒度粗（整数队列映射），难以支持精细化权重；且为新流添加规则需通知所有路径上的交换机，控制平面开销高、灵活性差。
- **逻辑集中式带宽分配器**（如 BandwidthEnforcer、SecondNet）：需要汇聚全网流量信息并集中计算分配方案，通信延迟高，每次流权重变更都需重新计算，在大规模场景下计算时间急剧增长（1 百万流需 31.1 秒），无法满足敏捷性要求。

**3. 三者难以兼顾**：已有方案无法同时达到细粒度（fine granularity）、高敏捷性（high agility）、高可扩展性（high scalability）。

## 三、核心设计

**Söze 的核心洞察**：沿流路径只需一个网络遥测信号——**最大排队延迟（maxQD，max queuing delay）**——即可同时实现以下功能：（1）指示当前链路拥塞程度；（2）作为协调多个流发送方的控制旋钮，引导所有流收敛到加权 max-min 公平分配状态，且无需知道拓扑、路由或其他流的信息。

**数学推导**：将加权分配目标方程分解为两个等价条件：
1. 所有流速率之和等于瓶颈带宽（链路充分利用）
2. 每个流的「速率/权重」比值相等（即加权公平性）

Söze 将这两个条件编码进一个**目标函数（target function）**：每个流独立观察 maxQD 信号，并将自身速率调整至该信号所指示的目标速率。目标函数需满足单调递减性：排队延迟越高，说明链路越拥塞、公平份额越小。具体形式为：

```
target_rate = w_k / (maxQD / p - k/p) * m
```

其中 `p`（排队延迟缩放系数）、`k`（基准排队延迟，保证满利用率）、`m`（收敛速度）为可调参数。

**maxQD INT 信号设计**：在数据包头中携带 maxQD 字段，每个交换机在转发时更新该字段为「当前排队延迟与已记录最大值」的较大者，发送方通过 ACK 包获取该信号。该信号以 O(1) 开销实现了 O(n) 的信息等价传递。

**自适应 MIMD 速率控制算法**：基于 maxQD 信号，每个流独立执行 Multiplicative Increase Multiplicative Decrease（MIMD）：
- 若当前速率低于目标速率 → 乘性增加
- 若当前速率高于目标速率 → 乘性减少

收敛到全局加权 max-min 公平分配的理论可证，且收敛时间仅约 10 个 RTT，与网络规模无关。

**多跳扩展**：在多跳网络中，maxQD 反映的是所有跳中最拥塞的瓶颈跳，Söze 的目标函数天然适配——每个流会在瓶颈跳处收敛到对应的权重份额，非瓶颈跳不影响收敛结果，这已通过形式化证明给出。

## 四、实现细节

**eRPC 测试床集成**：
- 硬件：4 台服务器（配备 DPDK CX-4 NIC）+ Tofino-1 可编程交换机（star 拓扑）
- 在 eRPC 包头中增加 maxQD 字段，交换机附加该信号到每个数据包
- 替换 eRPC 默认的 Timely CC 算法为 Söze，修改约 **1972 行代码**
- 参数默认值：`p=20µs, k=3µs, m=0.25`，链路带宽 25 Gbps

**NS-3 仿真器集成**：
- 自定义交换机以提供最大每跳排队延迟
- maxQD 通过 ACK 包反馈给发送方
- 仿真网络：1024 台服务器 + 320 台交换机，fat-tree 拓扑，100 Gbps 链路，1µs 链路延迟，32 MB 缓冲区

**参数选择原则**：
- `p`：控制 INT 信号粒度，取能保持低震荡的最小值
- `k`：控制基础排队延迟，取能保证 100% 链路利用率的最小值
- `m`：控制收敛速度，需在收敛速度与震荡之间权衡

## 五、实验结果

### 应用场景（eRPC 测试床）

| 场景 | 效果 |
|------|------|
| 关键路径加速 | Job 完成时间从 117s 降至 96s（约 18% 提升） |
| Coflow straggler 缓解 | 动态调权后 straggler 流赶上其他流，整体 coflow 时间缩短 |
| 多 job 共享瓶颈 | 调整权重后 job2 完成时间从 82s 降至 79s，且不影响其他 job 总带宽 |
| Altruistic 调度 | 非关键路径主动让出带宽，job2 完成时间从 60s 降至 50s |
| 最短流优先 | >80% 的流获益，大流 FCT 仅略有增加，无饥饿 |

### TPC-H 基准测试（NS-3 仿真）

- 22 个 job 平均完成时间降低 **0.79×**，最大降低 **0.59×**

### 拥塞控制性能

| 指标 | 对比 |
|------|------|
| Step-in/out 收敛速度 | 优于 Timely（测试床），优于 HPCC（NS-3） |
| RTT | 低于 Timely |
| FCT slowdown（40%/80% load） | 低于 HPCC 和 DCQCN，对短流尤为明显 |

### 微基准测试

| 特性 | 结果 |
|------|------|
| 收敛时间 | ~10 RTT（约 0.3ms），与拓扑规模/流数量无关 |
| 水填充算法（centralized） | 1M 流时耗时 31.1 秒；Söze 始终约 0.3ms |
| 权重精度 | 支持任意连续权重；Multi-Conn 仅支持整数；Physical Queue 受队列数限制 |

## 六、批判性分析

**1. 实验规模较为受限**：eRPC 测试床仅 4 台服务器 + 1 台交换机，star 拓扑，不具备多跳场景的真实复杂性。多跳和大规模场景完全依赖 NS-3 仿真，而仿真对真实网络噪声（NIC 时钟偏差、链路错误、incast 突发）的刻画能力有限。论文对于 fat-tree + ECMP 下多路径 maxQD 汇聚的正确性缺乏实验验证。

**2. 参数敏感性未充分讨论**：`p, k, m` 三个参数在不同工作负载、链路速率下的最优值差异可能很大。论文仅给出了一组默认参数，未分析参数调优对实际部署的影响，现实中不同租户混合场景下的参数鲁棒性存疑。

**3. 加权 max-min 公平的适用假设**：Söze 假设瓶颈在同一跳。当流经历多个同等拥塞的跳时，理论收敛性证明依赖严格的单瓶颈假设，论文虽提到多跳扩展，但未给出强有力的理论或实验验证。

**4. 权重设置由谁负责**：论文展示了多种应用场景下的权重策略（DAG 关键路径长度、流大小倒数等），但这些启发式策略均需要应用层自行实现，最优权重函数的设计问题被轻描淡写地推给了上层应用，缺乏通用性指导。

**5. 与 DCQCN 的对比公平性存疑**：DCQCN 是基于 ECN 的方案，其设计目标和硬件假设与 Söze（依赖 INT）不同，两者的对比在实际数据中心中意义有限——多数生产环境同时部署 RDMA + DCQCN，迁移成本未被讨论。

**6. 多路径/ECMP 场景下 maxQD 的语义**：在 fat-tree + ECMP 下，同一流的不同包可能走不同路径，maxQD 在这种情况下是否还能稳定反映真实瓶颈是一个开放问题，论文未明确说明。

## 七、AI Infra / MLSys 视角

**与 AI 系统的关联**：

Söze 的核心问题——分布式训练/推理中流量的差异化带宽分配——与 AI Infra 高度相关。集合通信（AllReduce、AllGather）中不同 tensor 层的优先级差异，以及流水线并行中 pipeline bubble 期间的带宽利用优化，都是可以直接利用加权带宽分配的场景。

**可借鉴的技术洞察**：

1. **只用一个信号做协调**：Söze 展示了在去中心化系统中，精心设计的单一信号（maxQD）可以替代复杂的全局通信协议。这种「以最小信息量驱动全局收敛」的思想对设计大规模分布式训练的 flow control 有启发意义。

2. **INT 信号重用**：将网络遥测信号从「监控工具」重新定位为「协调机制」，这种思路可延伸至 AI 集群中的网络感知调度（如基于 INT 信号动态调整 AllReduce 的 bucket size 或 chunk 大小）。

3. **DAG 关键路径权重分配**：论文中用 DAG 最长路径距离作为流权重的启发式方法，可以直接应用到分布式训练的 critical path 分析（如 TicTac、Echelon Formation 等工作的延伸）。

**值得跟进的方向**：

- **与 RDMA/RoCE 的集成**：Söze 目前基于 eRPC，在 RDMA 场景（InfiniBand / RoCE）下，IN T 信号采集和 ACK 路径与标准 TCP 不同，如何将 maxQD 机制嫁接到 RDMA transport 是有价值的工程研究。
- **LLM 推理场景的 SLO-aware 权重分配**：对于 prefill/decode 分离部署，两类流量对延迟的敏感程度差异极大，基于 Söze 实现细粒度 SLO-aware 带宽分配是直接的应用场景。
- **与网络感知调度器（Cassini、Themis 等）的结合**：Söze 提供了传输层的加权机制，但权重的最优分配策略需要调度器层的配合，二者协同设计是有价值的未来工作。

---

## 八、总结

Söze 提出了一种轻量级去中心化加权带宽分配系统，其核心创新在于将交换机 INT 中的最大排队延迟（maxQD）从监控信号重新定义为流间协调控制信号，设计了无需拓扑/路由/全局流信息的自适应 MIMD 收敛算法。实验表明，Söze 在支持细粒度（连续权重）、高敏捷性（约 10 RTT 收敛）、高可扩展性（百万流规模下收敛时间恒定）方面均优于现有方案，TPC-H 任务平均完成时间降低 0.79×。主要局限在于实验规模小、多跳真实场景验证不足，以及权重策略需由应用层自行设计。
