# Söze: One Network Telemetry Is All You Need for Per-flow Weighted Bandwidth Allocation at Scale

## 论文基本信息

- **标题**: Söze: One Network Telemetry Is All You Need for Per-flow Weighted Bandwidth Allocation at Scale
- **作者**: Weitao Wang, T. S. Eugene Ng (Rice University)
- **会议**: OSDI 2025
- **链接**: https://www.usenix.org/conference/osdi25/presentation/wang-weitao

## 研究背景与动机

现代数据中心网络中，不同应用对数据传输的性能需求差异巨大且动态变化。传统的传输层协议（如 TCP）提供固定的公平带宽分配策略，无法满足多样化的应用需求。加权带宽分配（Weighted Bandwidth Allocation）是一个强大的抽象，可以根据应用需求精细化分配网络资源——例如，为重要作业提供更高的带宽占比、为延迟敏感作业缩短等待时间。

然而，实现高度敏捷、精确的加权带宽分配在大型云环境中面临根本性挑战：
1. **瓶颈识别困难**: 数据中心网络有多层拓扑，每条流的路径上可能有多个链路，且路由由随机种子决定，难以预测
2. **信息规模巨大**: 需要收集的信息（网络拓扑、链路带宽、每条流的发送方/接收方/路由）规模巨大
3. **全局最优性**: 加权带宽分配需在瓶颈链路处执行才能有效，如何以低成本、快速收敛到全局最优状态极具挑战
4. **粒度与精度矛盾**: 精细粒度的加权分配需要精细粒度的算法，但网络规模使高精度计算成本高昂

## 要解决的核心问题

1. **无需每流、拓扑或路由知识的精确加权带宽分配**: 在只知道流权重的情况下，无需了解网络拓扑和路由信息，即可实现精确的加权 max-min 公平分配
2. **高敏捷性**: 加权分配可在数个 RTT 内完成，允许流的权重即时调整
3. **高可扩展性**: 系统不随网络规模、流的个数或拓扑复杂度而退化
4. **单边网络遥测即可完成协调**: 仅需每条流的路径上有一个网络遥测点（INT 携带的队列延迟），即可完成多流发送方之间的协调

## 主要贡献

1. **理论发现**: 仅需一条流的路径上的一个网络遥测点（队列延迟），无论跳数多少，都可以反映网络共享状态并作为协调多流发送方的信道
2. **去中心化加权 max-min 公平分配框架**: 无需每流、拓扑或路由信息，即可高精度、高敏捷地执行加权带宽分配
3. **基于最大队列延迟的瓶颈识别**: 利用 Lemma 3.3（瓶颈链路属性）——在加权 max-min 公平状态下，每条流的 rate-per-weight 在其瓶颈链路上是所有流中最大的——通过选择 maxQD 信号来识别瓶颈
4. **集成到现有传输层**: 可无缝集成到 TCP 和 eRPC 等现有传输层机制

## 研究方法与设计

### 核心洞察：单边 INT 即为协调信道

关键观察：
1. **队列延迟本身蕴含链路到达速率**: 队列延迟的动态变化由链路到达速率 R 与链路带宽 B 的差值决定（R−B），当链路饱和时队列延迟达到稳态
2. **不同队列延迟代表不同加权公平份额**: 较大的加权公平份额对应较小的队列延迟，存在单调一一映射关系
3. **瓶颈链路上队列延迟最大**: 根据 Lemma 3.3，在加权 max-min 公平状态下，每条流在其瓶颈链路上的 rate-per-weight 是所有流中最大的，因此瓶颈链路上的队列延迟也是该流路径上所有链路中最大的

### 单交换机场景下的去中心化算法（Algorithm 1）

**目标方程**: 加权公平份额 $\frac{B}{w_0 + w_1 + \ldots + w_n}$，流 $k$ 的速率 $r_k = \frac{w_k}{w_0 + w_1 + \ldots + w_n} \cdot B$

**两个等价方程**:
1. $\sum r_i = B$（所有流的到达率之和等于链路带宽）
2. $\frac{r_0}{w_0} = \frac{r_1}{w_1} = \ldots = \frac{r_n}{w_n}$（所有流的 rate-per-weight 相等）

**分布式验证**: 每个流只需验证以上两个方程，无需交换 O(n) 条信息，仅需 O(1) 信息交换。

**收敛算法**:
- 每个流接收路径上的队列延迟信号 $D$
- 计算 rate-per-weight 与目标延迟之间的比例 $ratio = U(\frac{r_k}{w_k}, D)$
- 按 $r_k = r_k \cdot ratio$ 更新发送速率
- 其中 $T^{-1}(D) = p \cdot \frac{w_k}{r_k} + k$，$p$ 为延迟缩放参数，$k$ 为最小延迟

### 多跳网络场景

**瓶颈链路属性（Lemma 3.3）**: 在加权 max-min 公平状态下，每条流在其瓶颈链路上的 rate-per-weight 是所有流中最大的（且不在任何其他饱和链路取得此最大值）。

**maxQD 信号**: 使用每条流路径上所有链路的**最大**队列延迟作为 INT 信号。由于瓶颈链路上的队列延迟最大，maxQD 即为瓶颈链路的队列延迟。

**定理 3.1**: 对于任意网络中的每条流，当且仅当 $0 < m < 2$ 且 $p > \frac{\Delta t \cdot [\ln(\alpha) - \ln(\beta)]}{2}$ 时，Söze 收敛到加权 max-min 公平分配。

### 系统设计

1. **数据包头部携带 maxQD 字段**（2 字节）：数据转发路径上每跳交换机会比较并保留最大队列延迟
2. **ACK 包回传 maxQD**: 接收方主机将 maxQD 附加到 ACK 包头返回发送方
3. **发送方速率控制**: 解析 ACK 包中的 maxQD 数据，计算乘法速率更新比，使用 CWND 或基于速率的拥塞控制

## 关键实现细节

### INT 信号选择
- 仅需队列延迟（queueing delay），这是 commodity 以太网交换机普遍支持的 INT 数据
- 无需可编程交换机，仅需固定功能交换机
- 2 字节字段即可表示队列延迟

### 目标函数设计
- $T^{-1}(D) = p \cdot \frac{w_k}{r_k} + k$
- $k$: 链路饱和时一个流的最小队列延迟
- $p$: 队列延迟缩放参数，用于区分不同流的 rate-per-weight
- $\alpha$, $\beta$: 分别为最高和最低 rate-per-weight 的估计范围

### 策略一致性保证
- 日志系统记录权重更新（时间戳、流 ID、权重值）
- 策略检查器定期汇总验证策略一致性

## 实验结果与分析

### 测试环境
- 仿真：基于 ns-3 的数据中心网络仿真
- 测试床：Mellanox SN2700 交换机 + 配备 ConnectX-5 网卡的服务器

### 关键结果
- **收敛精度**: Söze 的加权分配精度与全局最优解高度一致，误差在 5% 以内
- **TPC-H 作业完成时间**: 改善 0.59×（平均 0.79×）
- **与 eRPC 集成**: 在真实测试床上验证了无缝集成
- **收敛速度**: 约 3-5 个 RTT 即可收敛

## 潜在问题与局限性

1. **仅支持 commodity 以太网交换机**: 需要 INT 支持（队列延迟标签），主要适用于现代数据中心交换机
2. **INT 字段开销**: 2 字节的队列延迟字段增加了每个包的header大小，虽然开销很小但在极端高吞吐场景下可能值得关注
3. **参数调优**: $\alpha$, $\beta$, $p$, $m$ 等参数需要根据网络条件调整，论文未充分讨论自动调优机制
4. **与 ECN 的交互**: INT 队列延迟信号与 ECN 的关系未充分讨论，两者可能在某些场景下冲突
5. **大规模流场景**: 虽然声称高可扩展性，但未提供与数百或数千条流同时运行的相关实验数据

## 未来工作方向

1. 与传输层协议（如 DCTCP、DCQCN）的更紧密集成
2. 动态网络条件下的参数自适应
3. 多租户环境中的安全隔离

## 个人评注

### 优点
1. **理论洞察深刻**: "仅需一条流的路径上的一个网络遥测点即可完成加权分配协调"是一个深刻的理论发现，将 INT 从传统的监控工具转变为协调工具
2. **设计简洁优雅**: 完整的加权 max-min 公平分配系统仅使用队列延迟一个信号，无需复杂的信令或集中控制器
3. **与现有传输层无缝集成**: 作为端点侧修改，可与 TCP/eRPC 等现有协议集成，无需修改网络基础设施
4. ** Lemma 3.3 的关键作用**: 瓶颈链路属性的形式化证明是整个设计的理论基石，使得 maxQD 信号的选择具有严格依据

### 潜在问题
1. **定理 3.1 的条件 $p > \frac{\Delta t \cdot [\ln(\alpha) - \ln(\beta)]}{2}$**: 这个条件依赖于 $\alpha$ 和 $\beta$ 的精确估计，而 $\alpha$ 和 $\beta$ 分别对应最高和最低 rate-per-weight 的范围。如果网络中出现比 $\alpha$ 更高的 rate-per-weight（例如权重极高的流突然加入），系统的收敛性可能无法保证
2. **实验规模相对有限**: 论文主要使用仿真实验（ns-3），测试床实验规模较小（未明确说明），与真实大规模数据中心场景存在差距
3. **与生产环境 DCTCP/DCQCN 的交互**: 真实数据中心通常使用 DCTCP 或 DCQCN 进行拥塞控制，Söze 的队列延迟信号可能与这些机制相互作用，其在生产环境中的稳定性未经充分验证
4. **跨多个瓶颈链路的流**: 对于路径上有多个瓶颈的场景（如负载较重的多条链路），maxQD 信号可能无法准确区分真正的瓶颈，论文未深入讨论这类边界情况
5. **"One Network Telemetry Is All You Need"的标题**: 这个标题类比了 Transformer 的 "Attention Is All You Need"，但实际仅使用了队列延迟一种遥测数据，并非所有 INT 数据都得到了利用，严格来说略有夸大
