# Söze: One Network Telemetry Is All You Need for Per-flow Weighted Bandwidth Allocation at Scale

**作者**：Weitao Wang, T. S. Eugene Ng (Rice University)
**会议**：OSDI 2025
**链接**：https://www.usenix.org/conference/osdi25/presentation/wang-weitao

## 一、背景

现代数据中心网络中，传输层通常采用公平带宽分配策略（如 DCTCP），所有流平等竞争链路带宽。然而，云应用的性能需求日益多样化：分布式训练需要优先传输关键路径上的 tensor，MapReduce 需要优先处理 straggler flow，不同 job 之间也需要差异化的带宽保障。Weighted bandwidth allocation（加权带宽分配）是一种强大的抽象，允许为每个流指定权重，按比例分配带宽资源。

尽管加权分配的价值已被广泛认可，但在大规模数据中心中实现高精度、高敏捷性的加权带宽分配仍是一个开放难题。现有方案要么依赖交换机硬件的 per-flow queue（数量有限、权重粒度粗），要么依赖集中式带宽分配器（通信延迟高、计算开销大）。

---

## 二、要解决的问题

1. **瓶颈识别困难**：数据中心网络多层拓扑、ECMP 随机路由，每个流的瓶颈链路不可预测，而加权分配必须在瓶颈处生效才有意义。
2. **可扩展性不足**：集中式分配器需要收集全网拓扑、流信息并求解全局最优，随网络规模和流数量增长，求解时间急剧上升（10k flows → 1M flows，水填充算法从 1.81ms 增至 31.1s）。
3. **敏捷性差**：每次流到达/离开/权重变更都需要重新计算全局分配，导致控制面延迟高。
4. **粒度受限**：交换机方案受限于物理队列数量（通常仅 4-8 个）和整数权重，无法支持细粒度的权重设定。

---

## 三、洞察与设计

**关键洞察**：对于任意一个流，只需要其路径上的一个网络遥测信号（最大逐跳排队延迟 maxQD），就足以在瓶颈链路上实现加权带宽分配——无需 per-flow 状态、拓扑知识或路由信息。更具体地说，排队延迟不仅能指示拥塞程度，还能被巧妙地重新定义为加权公平份额（weighted fair share）的编码信号，使得每个流发送端可以独立地根据这个信号调整速率。

Söze 的设计分为三个层次：

**单交换机场景**：将加权分配公式 $r_k = \frac{w_k}{\sum w_i} \cdot B$ 拆分为两个等价条件：(1) 所有流速率之和等于链路带宽；(2) 所有流的 rate-per-weight 相等。条件 (1) 由排队延迟的动态天然反映（排队延迟稳定 ↔ 到达率 = 带宽）；条件 (2) 通过设计单调递减的 target function $T(r/w) = p \cdot \frac{\ln(\alpha) - \ln(r/w)}{\ln(\alpha) - \ln(\beta)} + k$，将不同的 weighted fair share 映射到不同的排队延迟值，每个流可以独立比较自己的 rate-per-weight 与遥测信号指示的值，用 MIMD 算法收敛。

**任意网络场景**：利用 weighted max-min fair 的性质——每个流在其瓶颈链路上拥有最大 rate-per-weight，因此瓶颈链路的排队延迟最高。只需在数据包头中维护路径上的最大排队延迟（maxQD），交换机做简单的 compare-and-replace 操作，发送端即可获取瓶颈信号。

**收敛算法**：Algorithm 1 极其简洁——每个流收到 ACK 中的 maxQD 信号后，计算 ratio = $(T^{-1}(D) / (r_k/w_k))^m$，更新速率 $r_k = r_k \cdot ratio$。参数 $m \in (0, 2)$ 控制收敛速度与稳定性的折中。

## 四、实现细节

**eRPC 测试床实现**：在 eRPC 中替换 Timely CC 算法，增加 maxQD 包头字段，使用 Tofino-1 可编程交换机附加遥测信号。修改量约 1972 行代码。参数设定：$p = 20\mu s$，$k = 3\mu s$，$m = 0.25$，带宽 25 Gbps。

**NS-3 仿真实现**：构建 1024 server + 320 switch 的 fat-tree 拓扑，100 Gbps 链路，1μs 链路延迟，32 MB buffer。交换机定制化支持 maxQD 遥测。

**交换机侧**：仅需 compare-and-replace 操作维护 maxQD 字段（2 字节包头），不需要 per-flow 状态，不需要可编程交换机（commodity switch 的 INT 功能即可）。

**参数选择原则**：$p$ 控制 INT 信号粒度（越大排队延迟越高但振荡越小）；$k$ 控制基础排队延迟（太小会导致利用率不满）；$m$ 控制收敛速度（越大收敛越快但振荡越大）。

**应用集成**：通过 API 让应用指定每个连接的权重参数，权重可即时调整，无需与交换机或控制器通信。

## 五、实验结果

### 应用场景（eRPC 测试床）

| 场景 | 效果 |
|------|------|
| 关键路径优先 | Job 完成时间从 117s 降至 96s（权重 2:1） |
| Straggler 缓解 | 动态调整权重使 coflow 中各流同时完成 |
| 资源隔离 | 同瓶颈不同 job 的带宽完美隔离 |
| 利他调度 | Job 2 完成时间从 60s 降至 50s，不影响 Job 1 |
| 最短流优先 | 80%+ 的流受益，大流不会被饿死 |

- 平均 job 完成时间降低 0.79×，最大降低 0.59×

## 六、批判性分析

1. **实验规模与生产差距**：测试床仅 4 台服务器 + 1 个 Tofino 交换机（star topology），NS-3 仿真最大 1024 server。真实数据中心有数万台服务器、复杂多层拓扑和动态路由，论文未验证在这种规模下 maxQD 信号是否仍能准确反映瓶颈。

2. **参数敏感性未充分探讨**：$p$、$k$、$m$ 三个参数的选择对性能影响显著，但论文仅给出定性的"选择原则"和一组固定参数值，缺乏系统的参数敏感性分析。不同工作负载模式下是否需要不同参数？在线自适应调参是否可行？

3. **多瓶颈场景的收敛行为**：论文证明了收敛性，但未深入讨论多瓶颈频繁切换时的瞬态行为。当网络中大量流的瓶颈同时发生变化时，maxQD 信号可能产生振荡，收敛时间可能远超 10 RTTs。

4. **权重确定的实际困难被回避**：论文假设应用能够提供合理的权重设定，但在实际场景中如何从 SLO、deadline 等高层目标映射到具体的流权重是一个非平凡问题。论文引用 NumFabric 但未给出具体集成方案。

5. **与优先级队列的公平比较存疑**：micro-benchmark 中交换机方案仅使用 4 个物理队列，但现代交换机（如 Memory-buffered switches）支持更多队列和更细粒度的调度。WRR + AIMD 基线中 AIMD 参数选择（MD factor = 0.8）是否经过充分调优也不清楚。

6. **安全性/隔离性**：论文依赖应用诚实报告权重，恶意租户可设置极高权重霸占带宽。虽然 §3.4 提到可用日志系统审计，但这是事后补救而非预防机制。

## 七、AI Infra / MLSys 视角

1. **分布式训练通信优化**：论文已提到的 tensor 分层优先级调度（critical path prioritization）与现有工作（TicTac、P3）的思路一致。Söze 提供了一种无需修改交换机配置的轻量级方案，可以在不同 layer 的 gradient 通信之间动态分配带宽优先级，实现 computation-communication overlap 的最大化。

2. **MoE 模型的 All-to-All 通信**：MoE 推理中 expert 负载不均衡导致 All-to-All 通信中部分流是 straggler。Söze 的 coflow straggler mitigation 机制可以直接应用——根据每个 expert 的 token 数量动态调整流权重，使各流同时完成。

3. **多租户 GPU 集群的带宽隔离**：在共享集群中，不同训练任务共享网络时互相干扰是常见问题。Söze 的"权重和不变"特性可以实现 job 级别的带宽隔离，同时允许 job 内部根据通信模式灵活调整。

4. **值得跟进的方向**：
   - 将 Söze 与 NCCL/Gloo 等集合通信库集成，自动从 execution graph 推导流权重
   - 在 disaggregated inference 场景（prefill-decode 分离）中，为不同阶段的 KV cache 传输设置差异化权重
   - 探索 Söze 在 RDMA/RoCE 网络上的实现（论文目前基于 TCP 和 eRPC）

---

## 八、总结

Söze 提出了一种基于单一网络遥测信号（maxQD）的去中心化加权带宽分配方案，核心创新在于将排队延迟从传统的拥塞指示器重新定义为加权公平份额的编码信号，配合极简的 MIMD 收敛算法，在不需要 per-flow 状态、拓扑信息或集中控制器的前提下实现了 weighted max-min fair allocation。系统在细粒度（任意实数权重）、敏捷性（~10 RTTs 收敛）和可扩展性（不随网络规模增长而退化）三个维度上优于现有方案。主要局限在于实验验证规模有限，参数调优缺乏系统指导，且权重的语义映射（从应用目标到流权重）留给了上层系统解决。
