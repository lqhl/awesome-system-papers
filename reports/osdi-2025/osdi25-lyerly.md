# osdi25-lyerly: Skybridge

## 论文基本信息

- **标题**: Skybridge: Bounded Staleness for Distributed Caches
- **作者**: Robert Lyerly, Kevin Doherty, Greg Rogers, John Hugg（Meta Platforms）；Scott Pruett；Nathan Bronson（OpenAI）
- **会议**: OSDI 2025
- **链接**: https://www.usenix.org/conference/osdi25/presentation/lyerly

---

## 研究背景与动机

Meta 的社交产品需要在多个地理区域部署，需要高可用性和低延迟。异步复制提供了最终一致性，但没有**有界延迟保证**——更新可能需要毫秒到数小时才能传播到所有副本。这种无界延迟导致严重的产品问题：
- 用户将某人加入封闭群组，但对方暂时无法参与
- 异步操作读取过期数据导致服务中断
- 开发者构建临时方案（重试循环、分布式锁）来应对不确定性

**目标**：能否在维持异步复制的可扩展性和低延迟优势的同时，为写入可见性提供有意义的界限？

---

## 要解决的核心问题

如何为分布式内存缓存（如 TAO）提供**2 秒有界陈旧度（bounded staleness）**保证，同时：
1. 与现有复制管道互补
2. 避免相关故障
3. 仅占缓存部署规模的 0.54%

---

## 主要贡献

1. **有界陈旧度的实际重要性**：解释为什么开发者需要有界陈旧度而非其他一致性模型
2. **Replication with Gap Detection（RGD）**：新的复制语义，允许数据丢失但可检测，使系统能够专注于实时复制
3. **Skybridge 系统**：带间隙检测的带外复制流，专门针对长尾延迟问题
4. **工程实现细节**：租赁系统（Skylease）、Bloom filter 优化、读写路径设计

---

## 研究方法与设计

### 为什么是有界陈新度而非强一致性

- **线性化/顺序一致性**：在 Meta 规模下引入过多通信和同步开销，无法作为默认设置启用
- **读写一致性（RYW）**：仅对用户自己的写入提供保证，对其他用户/自动化的写入无效；且默认仅在区域内启用
- **有界陈新度**：适合大多数用户的心理模型，同时可扩展启用

### TAO 的现有架构

TAO 是 Meta 的内存图形缓存，使用读/写分层架构：
- 写层处理数据库更新
- 读层提供缓存服务
- Wormhole 发布-订阅系统分发 MySQL 复制流到缓存

**问题**：Wormhole 提供强保证（至少一次、有序传递），但在热 shard 或过载发布者情况下会导致复制延迟。

### 无 Skybridge 的有界陈新度

TAO 原则上可以只用 Wormhole 水印实现简单版本：
- 比较缓存 HLC 与陈新度界限
- 但这会导致**显著的假阳性**：如果 shard 临时超出陈新度界限，TAO 会将所有数据视为过期并进入上游代理模式
- 在读倾斜工作负载中，大多数缓存数据实际上是最新的——因此大多数miss都是假阳性

### 核心设计：Replication with Gap Detection（RGD）

RGD 允许：
1. **复制元数据而非完整数据**：只复制 <key, HLC> 元组，不复制实际数据
2. **允许已知数据丢失**：缓存可以从其他来源填充
3. **允许乱序复制**：使用 CRDT（无冲突复制数据类型）理论

RGD 的关键属性：
- **Gap 检测**：当 RGD 系统缺少某些数据时，必须能够检测到这一点
- **无填充责任**：RGD 系统只负责识别陈旧缓存条目；填充由缓存的正常上游填充机制处理

### Skybridge 架构

```
写入路径：
TAO Writer → Skylease（租赁系统）→ Skybridge 写入路径 → 聚合为写入窗口

复制路径：
Skybridge 写入路径 → Skybridge 复制层（按需拉取）→ 读取路径

读取路径：
TAO 读层 → 检查 Wormhole 水印 → 检查 Skybridge Bloom Filter → getTicket 请求 → 返回 <key, HLC>
```

#### 写入路径与租赁系统

Skylease 合同协议：
- Writer 只有持有有效租赁才能写入 shard
- 租赁由物理时钟派生的时间范围标识
- 租赁提供有界数据完整性保证

**扩展性技术**：
- Delta 压缩（shard 不频繁变化）
- 按需分片
- 批量写入减少共识轮次

#### 读取路径与 Bloom Filter

- TAO 在检测到复制延迟 >1.5 秒时预加载 Skybridge 的 Bloom filter
- Bloom filter 用于避免向 Skybridge 发送请求（如果 filter 指示无写入，则缓存数据可能是新鲜的）
- Bloom filter 无假阴性（有写入时一定报告）但有假阳性（filter 报告有写入时可能没有）

**Trick**：Skybridge 仅发送完整时间窗口的 Bloom filter，因此 TAO 知道何时必须回源

### 性能特性

- Skybridge 规模仅为缓存部署的 **0.54%**
- 2 秒有界陈新度：Skybridge 达到 **99.99998%**，Wormhole 单独为 **99.993%**
- 无需回源的请求：**99.9996%**

---

## 关键设计细节

### 数据完整性检测

对于每个滞后间隔 $I_{\text{lag}}$ 和索引间隔 $I_{\text{index}}$：
Skybridge 有完整数据当且仅当：
1. $I_{\text{lag}} \subseteq I_{\text{index}}$（滞后间隔被写入窗口覆盖）
2. 所有覆盖滞后间隔的索引窗口都标记为 `complete`

这确保了 Skybridge 可以可靠地报告是否有遗漏数据。

### 水印与心跳

- MySQL 每 500ms 注入心跳（HLC）
- TAO 跟踪每 shard 的水印（单调递增）
- 心跳允许下游订阅者区分不活跃 shard 和不健康复制

---

## 潜在问题与局限性

1. **NTP 时钟偏差的假设**：论文提到需要考虑最大 NTP 时钟偏差 $\epsilon$。如果实际时钟偏差超过假设，系统可能静默违反陈新度界限
2. **仅针对有界陈新度**：不支持读写一致性（RYW）等其他一致性语义
3. **写入元数据而非数据的取舍**：这限制了 Skybridge 的适用范围——如果缓存需要更复杂的一致性保证，需要其他机制
4. **Bloom filter 假阳性的间接成本**：虽然无假阴性，但假阳性导致不必要的 Skybridge 查询或回源，论文未量化这些间接成本
5. **Skylease 的强一致性要求**：依赖 Zookeeper/Delos 等强一致共识系统，可能引入延迟

## 个人评注

**优点**：
- RGD 语义是一个优雅的设计——通过限制职责（只复制元数据、不负责填充）实现了专注和高效
- 有界陈新度的选择（2 秒）是在实用性和可行性之间的合理权衡
- 将系统设计为现有 Wormhole 管道的**补充而非替代**是务实的工程决策，降低了部署风险
- 0.54% 存储规模的数字非常有说服力，说明了系统的轻量性

**值得关注的点**：

1. **"99.993% vs 99.99998%"的差距实际影响**：0.008% 的差距在 Meta 规模下意味着什么？论文没有量化这一点。如果 Wormhole 已经做得很好（99.993%），改进到 99.99998% 在实际用户体验上的差异可能微乎其微。需要更多关于实际用户体验改善的证据。

2. **NTP 时钟同步的脆弱性**：论文提到如果最大时钟偏差超过 $\varepsilon$，TAO 可能静默违反有界陈新度。这是一个潜在的系统性风险——时钟同步配置错误或网络分区可能导致静默违规。

3. **99.9996% 无需回源**这个数字比有界陈新度本身更有说服力：说明在绝大多数情况下，Skybridge 可以本地证明数据新鲜，避免了跨区域回源的性能损失。

4. **作者团队背景**：大部分作者来自 Meta，论文反映的是超大规模互联网公司的特定需求。在其他规模或不同工作负载下（如写密集型），类似系统的收益可能不同。

5. **有界陈新度 vs RYW**：论文提到 RYW 和有界陈新度一起构成"令人信服"的语义，但没有讨论两者之间的权衡或可能的冲突。例如，在跨区域 RYW 不可用的场景下，有界陈新度能否完全替代？

6. **系统复杂性与运维**：Skylease（租赁系统）、Skybridge 写入/复制/读取路径、Bloom filter 管理——这是一个复杂的分布式系统。在生产环境中运维和调试这样一个系统需要相当多的工程投资。
