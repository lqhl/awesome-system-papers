# OSDI 2026

> OSDI 2026 的 136 篇论文围绕一个共同问题展开：当硬件、工作负载和部署规模继续异构化，系统如何把原本隐含的资源、状态与正确性边界变成可测量、可调度、可恢复的对象。

## 概览

本届论文的主线不是单一硬件热点，而是“把跨层代价显式化”。[[paper-osdi26-cao|kSTEP]] 控制内核事件与拓扑以重现调度器缺陷；[[paper-osdi26-devsot|Blink]] 直接在函数边界读取 PMU，修正短函数采样失真的诊断；[[paper-osdi26-chen-zhongjie|Xkernel]] 则把内核性能常量变成运行时可调整的机器状态。三者分别处理可复现性、观测精度和调优闭环，说明性能工程正在从“采样后猜测”转向“控制实验条件后测量”。

另一条主线是数据移动。[[paper-osdi26-banakar|OBASE]] 将冷热对象而非整页作为迁移单位，[[paper-osdi26-hu-muyan|VTC]] 消除只改变布局的中间张量搬运，[[paper-osdi26-luo|DirectKV]] 直接让 GPU 读取 pinned CPU memory，[[paper-osdi26-liu-guangda|ECHO]] 则围绕稀疏注意力的 KV cache 做无损预取。它们的收益都依赖更细的布局或访问语义，但适用边界不同：OBASE 受指针结构限制，DirectKV 依赖 GH200，ECHO 的预取本身只贡献最高 4% 的端到端收益。

AI 系统论文普遍把阶段不均衡和资源异构当作一等问题。[[paper-osdi26-du|EcoServe]] 在商用 GPU 集群中折中 prefill/decode 解耦，[[paper-osdi26-wang-yuanqing|DynaRL]] 按动态超图迁移 RL worker，[[paper-osdi26-wu-tianyuan|WEAVE]] 用另一作业的活跃阶段填补 RL 后训练空闲，[[paper-osdi26-hu-weifang|Tessera]] 则在 4,096–12,288 GPU 的 MoE 训练中动态填充流水线气泡。共同证据是固定资源切分会浪费计算，但在线适应的迁移、同步和 SLO 成本必须单独测量。

系统边界也在向运维和正确性扩展。[[paper-osdi26-chen-luofan|Chen-DataPipelines]] 使用 30,000 个生产训练 trace 定位数据管线停顿，[[paper-osdi26-leonhardi|PIMS]] 将维护、故障域和容量缓冲放进统一契约，[[paper-osdi26-lei|AEGIS]] 从 3.5×10^7 GPU-hours 中检测 SDC，[[paper-osdi26-zheng|SDCHUNTER]] 用确定性训练回放定位生产 GPU 缺陷。相比只报告单机吞吐，这些工作把“能否长期运行”作为系统结果的一部分。

## 研究趋势

1. **把隐含资源变成显式状态。** [[paper-osdi26-ahn|DeLFS]] 将全局日志资源拆到核，[[paper-osdi26-hu-kang|SBB]] 将 timer/NIC 通知按核分配，[[paper-osdi26-zhang-jing|vBPF]] 将 eBPF 事件归属到资源命名空间。它们都以减少中心化共享为代价换取扩展性；需要继续测量跨核负载不均衡和状态维护成本。
2. **把慢路径移出关键路径。** [[paper-osdi26-chen-guanyi|CoPilotIO]] 让 CPU 轮询完成队列，[[paper-osdi26-he-yongchao|umap]] 把 DFS 映射和缓存控制放在用户态，[[paper-osdi26-li-tianyu|libDSE]] 允许持久化前继续传递消息。三者的共同限制是慢路径并未消失，只是转移到 CPU、恢复或一致性边界。
3. **在线适应取代静态切分，但适应本身成为新成本。** [[paper-osdi26-wang-yuanqing|DynaRL]]、[[paper-osdi26-yu-chao|RLinf]] 和 [[paper-osdi26-wu-tianyuan|WEAVE]] 把资源随阶段变化重新分配；[[paper-osdi26-yu-shan|Prism]] 和 [[paper-osdi26-du|EcoServe]] 在推理服务中处理模型与请求变化。比较这些路线必须统一迁移时间、SLO 违约和资源碎片指标。
4. **生产证据成为设计的一部分。** [[paper-osdi26-li-suyi|Li-ClusterHeterogeneity]]、[[paper-osdi26-chen-luofan|Chen-DataPipelines]]、[[paper-osdi26-leonhardi|PIMS]] 和 [[paper-osdi26-ren|DiTing]] 使用长期 trace 或生产部署，但生产规模不自动保证因果归因，仍需对照组和回滚数据。

## 共同观察

- **共享状态会在规模上变成主瓶颈。** [[paper-osdi26-ahn|DeLFS]]、[[paper-osdi26-hu-kang|SBB]] 和 [[paper-osdi26-chen-zhongjie|Xkernel]] 分别从文件系统、网络运行时和内核调优验证了中心化状态的扩展代价；但拆分状态会引入复制、迁移或一致性维护。
- **数据移动收益依赖访问语义，而非单纯增加带宽。** [[paper-osdi26-banakar|OBASE]]、[[paper-osdi26-hu-muyan|VTC]] 和 [[paper-osdi26-liu-guangda|ECHO]] 都利用访问或布局结构减少搬运；非仿射访问、动态图变化和预取误判会削弱收益。
- **生产 workload 的长尾会改变最优资源配置。** [[paper-osdi26-chen-luofan|Chen-DataPipelines]]、[[paper-osdi26-wang-yuanqing|DynaRL]]、[[paper-osdi26-li-suyi|Li-ClusterHeterogeneity]] 和 [[paper-osdi26-wu-tianyuan|WEAVE]] 都显示平均利用率不足以解释停顿或浪费，阶段、拓扑和故障状态必须进入调度。

## 互相冲突的假设

- [[paper-osdi26-hu-weifang|Tessera]] 在超大规模训练中依赖 profiling 与运行时动态填充，而 [[paper-osdi26-li-wei|TileLoom]] 依赖可静态描述的拓扑、仿射访问和 buffer 生命周期。需要在动态路由和共享设备干扰下测量两者的模型误差与调度开销。
- [[paper-osdi26-du|EcoServe]] 通过跨实例滚动激活折中阶段隔离，[[paper-osdi26-hwang|Hwang-PipelineParallelism]] 则在单服务流水线中用在线预测减少气泡。前者的关键限制是 KV 传输，后者的关键限制是阶段失衡；统一比较应固定网络带宽并报告 P99 TTFT、TPOT 和 goodput。
- [[paper-osdi26-rosenblum|TimelockDrive]] 把安全边界下沉到物理块检查器，[[paper-osdi26-jiang-yu|USEC]] 把策略边界交给部署者声明的资源。前者牺牲恢复便利性，后者牺牲完整声明时的安全覆盖；需要故障恢复和遗漏资源的端到端测试。

## 值得关注的方向

- **动态资源模型的可迁移校准**：结合 [[paper-osdi26-li-suyi|Li-ClusterHeterogeneity]]、[[paper-osdi26-li-ruihao|PowerSight]] 和 [[paper-osdi26-zhang-zhengtong|DVLA]] 的生产观察，用小规模 trace 重建跨硬件的容量、带宽和功率模型，验证模型漂移下的调度稳定性。
- **面向尾延迟的跨层数据移动预算**：把 [[paper-osdi26-li-nanqinqin|LiteSwitch]]、[[paper-osdi26-luo|DirectKV]]、[[paper-osdi26-xie-zhiqiang|Strata]] 的 CPU、CXL、NVLink 和 SSD 路径放入同一 microbenchmark，测量带宽、并发度和恢复成本的边界。
- **可审计的动态系统调度**：组合 [[paper-osdi26-cao|kSTEP]] 的可重现事件控制、[[paper-osdi26-ren|DiTing]] 的分布式观测和 [[paper-osdi26-zhou-ziming|OpGuard]] 的差异定位，构造能回放一次 SLO 违约的最小 trace，并验证调度决策是否可解释。
