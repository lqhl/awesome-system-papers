# ElasticMoEP2P：多节点 MoE 专家级弹性的归档评估

> 用 P2P RDMA 对热点专家做在线复制、迁移和扩缩仍是实际系统问题，但当前证据只支持已有机制的组合与边界测量，不支持继续投入完整系统实现。

## 阅读提示

- **混合专家模型（Mixture of Experts，MoE）**：每个词元只调用少量专家，但专家权重与词元仍需跨设备放置和传输。
- **专家并行（expert parallelism，EP）**：把专家分散到多张设备，路由决定每个词元访问哪些远端专家。
- **数据并行（data parallelism，DP）**：复制非专家计算路径并处理不同请求批次。
- **进程编号（rank）**：分布式实例中参与通信和持有部分专家状态的执行成员。
- **中央处理器（central processing unit，CPU）与网络接口卡（network interface card，NIC）**：CPU 可代理通信控制，NIC 负责节点间数据传输。
- **专家并行负载均衡器（Expert Parallelism Load Balancer，EPLB）**：根据专家热度复制或重新放置专家的常用策略与实现类别。
- **点到点远程直接内存访问（peer-to-peer remote direct memory access，P2P RDMA）**：设备之间直接传输词元或权重，不要求所有成员共同进入同一个集合通信。
- **GPU 直接远程内存访问（GPUDirect RDMA）**：网卡直接读写 NVIDIA GPU 显存的数据路径，减少主机内存中转。
- **CUDA 与 ROCm**：分别是 NVIDIA 与 AMD 的 GPU 编程和运行时软件栈；跨两者可移植不等于只替换一个内核。
- **服务等级目标（service-level objective，SLO）**：部署承诺满足的延迟、吞吐或可用性边界。
- **有效吞吐（goodput）**：满足既定延迟 SLO 的请求吞吐，而不是全部完成请求的平均吞吐。
- **第 99 百分位（P99）延迟**：99% 请求不超过的延迟，用来观察尾部慢请求。

## 1. 问题真实性与证据边界

### 1.1 真实问题

多节点 MoE 推理存在三类可观察问题：路由偏斜会形成最慢 rank，重平衡会搬运大体积专家权重，固定 EP 成员又使局部故障影响整个实例。[[UEP-OSDI26]] 与 [[UCCL-Tran-OSDI26]] 的 `complete/full-text` 证据说明词元级通信、CPU 代理和跨机架路径碰撞确实影响端到端执行；[[Aegaeon-SOSP25]] 则证明在线状态切换和服务 SLO 是生产问题。

仓库内 CRAFT、LatencyOptimal-MoELB、Libra 与 MoE-Serving-Tax 为 `needs-review/full-text`，可以界定副本预算、搬运成本、执行窗口和阶段税，但关键数字仍需回源。外部 ElasticMoE 与 Expert-as-a-Service 为 `needs-review/full-text`；MoEless、Director、FreeBalance、EasyBalance 与 EEP 只按摘要定位。归档判断依赖的是研究空间拥挤和缺少独立核心机制，不把摘要数字当作强证据。

### 1.2 相邻工作覆盖

- ElasticMoE 公开稿描述分离显存管理与执行进程，以 P2P 搬运、零复制共享和虚拟页重映射调整数据并行与 EP。
- Expert-as-a-Service 公开稿描述独立无状态专家服务、P2P 通信、细粒度扩缩和模拟故障。
- Director 与 FreeBalance 摘要分别描述主动预测迁移，以及把有限迁移藏入路由前计算窗口。
- MoEless 摘要描述无服务器专家扩缩；EasyBalance 摘要描述不改变专家映射的跨层执行。
- EEP 摘要只支撑可变成员与故障修复定位：它声称修复通信可达性、专家覆盖和执行图。本评估不据此推断正常扩缩、并发配置变化、在途词元或原子版本语义。
- UEP 与 UCCL-Tran 已分别提供逐词元 GPUDirect RDMA 路径和软件传输控制，因而“将集合通信替换为 P2P”不能单独构成核心赌注。

## 2. 核心赌注筛选

| 候选赌注 | 证据结果 | 结论 |
|----------|----------|------|
| 热点专家可用 P2P 在线复制与迁移改善静态放置 | ElasticMoE、Director、FreeBalance 与 CRAFT 已覆盖主要机制；外部工作仍需全文复核 | 缺少独立机制 |
| 专家可作为独立弹性单元，避免完整实例扩容 | Expert-as-a-Service 与 MoEless 已给出直接相邻实现 | 抽象空间拥挤 |
| 可变 EP 成员可在局部故障后恢复 | EEP 摘要已直接提出该问题；更强语义尚无完整证据 | 不能从摘要缺项推出新机制 |
| 在线选择复制、迁移或跨层执行 | 统一相图尚缺，但当前只形成评测与控制问题 | 反直觉机制未建立 |

没有候选形成“测量发现—设计回应—结果验证”的新因果链。将复制、迁移、扩缩、P2P 和故障修复放进同一控制器，只会扩大工程范围，不会自动产生新的系统抽象。

## 3. 可保留的测量问题

### 3.1 静态计划的有效期

在代码、对话、推理和工具调用混合的连续请求上，测逐层专家分布变化、静态计划性能衰减和重规划成本。若计划有效期远长于重规划周期，在线迁移的必要性被削弱；若有效期短且搬运能被隐藏，才有继续测量的依据。

### 3.2 路由偏斜在解码中帮还是害

固定模型、批次与拓扑，同时测活跃专家集合、最大 rank 负载、权重读取、P2P 流量和 P99 词元间延迟。MoE-Serving-Tax 的待复核页面报告偏斜可能减少活跃专家；该反例必须回全文并在相同执行栈复现。

### 3.3 复制、迁移与跨层执行的适用相图

在同一轨迹下比较 EPLB/CRAFT 风格静态副本、预测迁移、跨层执行和专家服务扩缩。只有出现跨模型与拓扑稳定的策略反转，且现有成本模型无法解释时，才可能形成新的机制问题。

### 3.4 扩缩与故障修复的状态边界

分别从 ElasticMoE 与 EEP 全文提取权重、路由表、通信成员和执行图状态机，再决定是否存在可比较的共同语义。摘要证据不足以预设配置原子性或在途词元行为。

## 4. 重启与终止门槛

### 4.1 最小复核与测量

最小测量可复用 SGLang 的 EP 路径、EPLB/CRAFT 风格静态放置和 EasyBalance 公开实现，并在 8–32 张 GPU 上采集路由与尾延迟。开始实现新控制器前必须先完成外部关键工作的全文证据卡。

### 4.2 重启条件

该方向只有同时满足以下条件才重启，并使用新名称另建独立提案：

1. 至少三个架构或规模不同的现代 MoE 模型、两类拓扑和四类请求负载出现同一反直觉策略反转。
2. 反转不能由 CRAFT、Director、FreeBalance、EasyBalance、ElasticMoE 或 EEP 的已知机制解释。
3. 请求级 P99 改善越过最小有意义效果（minimum effect size，MES），同时有效吞吐、显存和搬运成本满足部署 SLO。
4. MES 由用户 SLO 与运维价值确定；样本量由独立预实验方差和显著性水平 0.05、功效 0.8 的分析确定，不预填漂亮百分比。
5. 核心论断由 `complete/full-text` 证据支撑；`needs-review/full-text` 必须完成复核，`abstract-only` 不能单独支撑重启。

任一条件不满足，保持归档。只有边界相图而没有新机制时，可单独形成测量产物，不恢复完整系统实现。

## 5. 投稿与转向

当前不投稿。未来若满足重启条件，另建独立提案并根据结果强度重新推导 OSDI、SOSP、NSDI、MLSys 或测量短文的投稿梯度；本页不预占会议叙事。

若静态计划足够稳定、现有策略解释全部反转，或收益只来自单一硬件上的局部优化，则终止该方向。公开轨迹、统一口径和负面结果仍可作为测量资产，但不包装为成熟系统。

## 品味评估

独立批评结果为 **1/5**：

| 维度 | 判断 | 证据 |
|------|------|------|
| 工作负载真实性 | 通过，但证据边界明显 | 大规模 MoE、专家偏斜、权重搬运和 P2P 通信均有公开系统证据；长期多租户逐层解码路由轨迹仍缺失 |
| 反直觉性 | 不通过 | 当前只有“偏斜可能帮助解码”这一待复核反例，尚未导出独立机制；动态复制与预测迁移本身符合直觉 |
| 10 倍突破还是 2 倍优化 | 不通过 | 候选设计主要组合已有副本、迁移、扩缩与通信机制，没有打开可辨认的新设计空间 |
| 不依赖模型代际 | 不通过 | 价值依赖路由偏斜、漂移和专家大小；更强的均衡训练、路由器或模型结构可能显著缩小问题 |
| 抽象贡献 | 不通过 | 专家服务、在线 EP 调整、可变故障成员与 P2P 数据通路均有直接相邻抽象，统一控制器不足以证明新抽象 |

合理终止依据不是问题不存在，而是证据强度与贡献形态不匹配：真实工作负载只证明值得测量，不能把已有机制的组合提升为反直觉核心赌注。继续完整实现会承担高工程成本，却没有清楚的不可替代贡献。

*本归档评估基于 `wiki/proposals/probes/elastic-moe-p2p.md` 的研究版图与证据分析。*
